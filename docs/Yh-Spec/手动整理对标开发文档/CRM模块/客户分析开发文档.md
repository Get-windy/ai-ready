## 3. 页面配置与数据口径

### 3.2 数据源（**唯一的接口调用**）

```ts
async function loadData() {                              // :162-173
  loading.value = true
  try {
    const list = await crmCustomerApi.exportList()        // GET /api/customer/export
    customers.value = Array.isArray(list) ? list : []
  } catch (e) { customers.value = []; console.warn('[客户分析] 客户数据获取失败', e) }
  finally { loading.value = false }
}
onMounted(() => { loadData() })                          // :175-177
```

| 项 | 实情 |
|----|------|
| 端点 | `GET /api/customer/export`（`api/crm.ts:420-422` → `CustomerController.java:78-87`） |
| 入参 | `exportList(params?: { keyword?, customerType?, customerLevel?, status?, salesPersonId? })` —— **本页不传任何参数**（`:165` 无参调用） |
| 返回 | **裸 `List<Customer>`**（无分页、无包装）；`request` 拦截器对裸数组原样返回（`utils/request.ts:198-200`） |
| 过滤 | 后端 `buildQueryWrapper` **显式 `eq(Customer::getDeleted, 0)`**（`CustomerServiceImpl.java:53`）+ MyBatis-Plus 多租户插件注入 `tenant_id` → 本页数据**已排除逻辑删 + 已按租户隔离** ✅（对比：发票页的 JPA 路径两者皆无，见《发票开发文档》§5.11） |
| 排序 | 后端 `orderByDesc(Customer::getCreatedAt)`（`CustomerServiceImpl.java:42`）—— 本页不依赖顺序 |
| 规模风险 | **全量拉取**（无分页、无时间窗）→ 客户数上万时首屏 JSON 与前端聚合变慢（P2） |
| 字段 | `Customer` 实体 47 个字段（`entity/Customer.java`）；本页只读 5 个：`customerSource`、`customerLevel`、`tradeAmount`、`status`、`createdAt` |

### 3.3 统计卡（4 张，`statCards`，`:60-72`）

| # | 标题 | 计算 | 单位/样式 | 行 |
|:-:|------|------|-----------|----|
| 1 | 客户总数 | `list.length` | suffix `家` | `:67` |
| 2 | 正常客户 | `list.filter(c => c.status === 1).length` | suffix `家`、绿色 `#52c41a` | `:62,68` |
| 3 | 本月新增 | `list.filter(c => c.createdAt && dayjs(c.createdAt).format('YYYY-MM') === dayjs().format('YYYY-MM')).length` | suffix `家`、蓝色 `#1677ff` | `:63-64,69` |
| 4 | 累计交易额 | `Σ (Number(c.tradeAmount) || 0)` | precision 2、prefix `¥` | `:65,70` |

> **⚠️ 「正常客户」口径与全模块相反（P0）**：本页用 **`status === 1`**，而 `crm/customer/index.vue` 的列表/看板/筛选/导出全部用 **`status === 0` 判「正常」**（`:391,394,747-748,879-882,1014,1259`），`crm/customer/form.vue` 则用 **`1 = 正常`**（见《客户开发文档》§4.2 #28）。
> `crm_customer.status` 是 `integer`（devdb 实测），**同一张表三处相反语义并存** —— 本页是「1=正常」阵营。**这是全模块 P0，不是本页独有**（详见《CRM模块/README.md》§7）。
> **⚠️ 「累计交易额」含停用客户**（未按 `status` 过滤）→ 与「正常客户」卡口径不同源（P2，可接受但应写明）。
> **⚠️ 「本月新增」依赖 `createdAt`（用对了字段）**：`Customer` 实体时间字段只有 `createdAt`/`updatedAt`（`entity/Customer.java:101,107`），**没有 `createTime`** → 本页读 `createdAt` **正确**；而列表页「创建时间」列 field 是 **`createTime`**（`customer/index.vue:866`）→ **列表该列恒空**（跨页口径不一致，P2，登记在《客户开发文档》）。

### 3.4 客户来源分布（饼图，`sourceOption`，`:75-97`）

| 项 | 值 | 行 |
|----|----|----|
| 聚合 | `new Map<string, number>()`，键 = `c.customerSource ? (SOURCE_TEXT[c.customerSource] \|\| \`来源${c.customerSource}\`) : '未知'` | `:76-82` |
| `series.type` | `pie` | `:89` |
| `radius` / `center` | `['40%','65%']` / `['50%','45%']` | `:90-91` |
| `label` | `'{b} {c}'` | `:92` |
| `tooltip` | `'{b}：{c} 家（{d}%）'` | `:85` |
| `legend` | `{ bottom: 0 }` | `:86` |
| data | `[...counter.entries()].map(([name, value]) => ({ name, value }))` | `:83` |

> **✅ 用 `Map` 而非普通对象做计数表**：正确规避了「原型链键陷阱」（若用 `{}` 计数，`customerSource` 为 `'toString'` 之类的键会命中原型函数）。**本页写法是标准做法，可作模板。**
> **⚠️ 空值归「未知」**：`customerSource` 为 `0`/`null`/`undefined` 都落入「未知」桶（`:78-80`）—— 语义合理（`0` 不是合法来源码）。

### 3.5 客户等级分布（柱状图，`levelOption`，`:100-126`）

| 项 | 值 | 行 |
|----|----|----|

| 值轴 | `type: 'value'`，**`minInterval: 1`**（避免小数刻度 ✅） | `:111` |
| 数据 | `keys.map((k, i) => ({ value: list.filter(c => c.customerLevel === k).length, itemStyle: { color: LEVEL_COLORS[i] } }))` | `:118-121` |
| 柱宽/标签 | `barWidth: 40`、`label: { show: true, position: 'top' }` | `:114-116` |

| `grid` | `{ left: 40, right: 16, top: 24, bottom: 28 }` | `:106` |

> **⚠️ 等级为 `NULL` 的客户不计入任何柱** → 4 根柱之和可能 < 客户总数（P2，与漏斗页「阶段明细之和 ≠ 总数」同源问题）。

### 3.6 近 12 个月新增客户趋势（折线，`trendOption`，`:129-159`）

| 项 | 值 | 行 |
|----|----|----|
| 月份序列 | `for (let i = 11; i >= 0; i--) months.push(dayjs().subtract(i,'month').format('YYYY-MM'))` → **从 11 个月前到本月，共 12 个键** | `:130-133` |
| 归月 | `dayjs(c.createdAt).format('YYYY-MM')`，命中 12 个键才 +1（`counter.has(m)`） | `:135-139` |
| 分类轴显示 | `months.map(m => dayjs(m).format('YY/MM'))` → 如 `26/09` | `:146` |

> **🔴 后果（P1）**：从客户表单录入 `customerSource = 1`（「自主开发」），本页饼图会显示成 **「电话营销」**；录入 2（「转介绍」）显示成 **「网络推广」**，录入 4（「展会」）显示成 **「展会活动」** → **来源分布图对存量数据是错的**。
> **裁定建议**：**以 `crm/customer/form.vue` 的 5 值字典为准**（它是有录入入口的一套），本页 `SOURCE_TEXT` 改为 `1 自主开发 / 2 转介绍 / 3 网络推广 / 4 展会 / 5 其他`；并把这 5 个标签收口为**共享常量**（当前 `SOURCE_TEXT`/`LEVEL_TEXT`/行业字典在 CRM 内已至少 4 处各写一份）。

### 4.3 口径边界（**如实登记，勿当成缺陷忽略**）

| 边界 | 事实 | 影响 |
|------|------|------|
| **只覆盖 4 个等级** | `customerLevel` 不在 1–4（含 `NULL`）的客户不计入任何柱 | 柱状图 4 根之和 ≠ 客户总数 |
| **来源 5 值 + 未知** | 合法值为 1–5，其余（含 `0`/`NULL`）归「未知」 | 饼图分片数可能 > 6 |
| **趋势仅近 12 个月** | 早于 12 个月的不计入 | 与「客户总数」不可加 |
| **累计交易额含停用客户** | 未按 `status` 过滤 | 与「正常客户」卡不同源 |
| **无去重/合并概念** | 直接按 `crm_customer` 行数计 | 同一实体重复建档会重复计数（CRM 客户与 ERP 往来单位未接线，见《CRM模块/README.md》§4） |
| **无金额口径的来源/等级交叉** | 只有「家数」，没有「各来源/各等级的成交额」 | 无法回答「哪类客户更值钱」 |

### 4.4 与其它页面的口径一致性汇总

| 指标 | 本页 | 其它页 | 一致？ |

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 下不存在 `e2e-crm*.cjs`）。落地脚本命名 `tools/e2e-crm.cjs`。
> **前置提醒：`crm_customer` 当前 0 行**（devdb 实测）→ E2E 必须**先造客户数据**（覆盖 `customer_source` 1–5、`customer_level` 1–4、`status` 0/1、`trade_amount` 非 0、`created_at` 分布在近 12 个月内外的多个月份），否则只能断言空态。

### 10.1 接口验收（建议 ≥ 12 项）

1. `GET /api/customer/export` 默认 200，返回**裸数组**，条数与直查 DB（`deleted=0` + 租户）一致。
2. 造 6 个客户（来源 1–5 + 1 个来源为 `NULL`）→ 数组长度 6，`customerSource` 覆盖到位。
3. `export?customerLevel=1` / `status=1` / `customerSource`（⚠️ 后端**不支持** `customerSource` 参数，见 §6.2）逐个验证 —— 应断言 `customerSource` 过滤**当前不支持**。
4. `export?keyword=` 命中 `customer_name`/`customer_code`/`short_name` 三者。
5. `export?salesPersonId=` / `customerType=` 生效（后端支持，本页未传）。
6. `GET /api/customer/statistics` → **断言当前 404**（后端无此端点，登记为本页「无服务端聚合」的依据）。
7. `GET /api/customer/page` 的分页参数是 `pageNum`/`pageSize`（MyBatis-Plus 口径，**与发票页的 `page`/`size` 不同**）→ 断言 `pageSize=1` 时 `records.length===1`。
8. **状态语义断言**：造 `status=1` 与 `status=0` 各一条 → 断言列表页把 `0` 显示为「正常」、分析页把 `1` 计入「正常客户」（**登记两页相反**）。
9. **交易额断言**：造 `trade_amount = 1234.56` → 断言接口能返回该值（验证读路径通），再断言**全仓无写入该列的端点**（登记缺口）。
10. **创建时间断言**：`created_at` 落库后接口返回 `createdAt`；`create_time` 列不被实体映射（断言返回体**无 `createTime` 字段**）。
11. 租户隔离：换租户登录后 `export` 不返回他租户客户。
12. **写库隔离**：所有造数用专用测试客户并在断言后清理。

### 10.2 UI 验收（建议 ≥ 14 项）

## 12. 剩余缺口（不阻塞，如实登记）

1. **`SOURCE_TEXT` 与录入字典不一致（P1）** —— 来源分布图对存量数据是错的（1 自主开发被显示成「电话营销」）。**最高优先，改动最小。**
2. **「正常客户」判据与列表页相反（P0，全模块）** —— 本页 `status===1`，列表页 `0=正常`。
3. **无任何查询条件（P1）** —— 报表无法对比；后端 `export` 已支持 5 个过滤参数。
4. **无下钻（P1）** —— 三图四卡均不可点，客户页筛选条件已就绪。
5. **缺 `ErrorBoundary`（P1）** —— 渲染异常即白屏。
6. **「累计交易额」数据未闭环（P1）** —— `crm_customer.trade_amount` 无写入路径，`/{id}/orders` 是 `List.of()` 桩。
7. **无流失/沉默客户清单（P1）** —— 《客户开发文档》§8 已裁定「应在客户分析页」；可用 `crm_customer_follow_up` 的最近跟进时间立即实现。
8. **缺 CLV / 流失率 / 健康度（P1/P2）** —— **业界建议、本系统未实现**（无数据源，不造假数据）。
9. **字典无接口、各页硬编码（P1/P2）** —— 等级已有 3 套文案、来源已有 2 套；应补枚举接口或共享常量。
10. **全量拉取无分页（P2）** —— 建议后端补 `GET /api/customer/statistics`（按来源/等级/状态分组 + 近 12 个月新增），把聚合从前端移到服务端。
11. **加载失败只有 console（P2）**；无刷新/无导出（P2）。
12. **口径细节（P2）** —— 等级 `NULL` 客户不入柱；趋势全 0 与无客户不可区分；累计交易额含停用客户；「创建时间」字段在两页分裂（`createdAt` vs `createTime`）。
13. **无验收截图资产 / 无模块级 E2E（P2）**。
