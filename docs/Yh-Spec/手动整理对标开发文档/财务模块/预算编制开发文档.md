### 状态（本系统实测）
草稿(draft) → 待审批(submitted) → 已审批(approved) → 执行中(executing) → 已关闭(closed)；已驳回(rejected) 可由编制人修改后重新提交。

| 分组 | 列 |
|------|----|
| 锁定列 | 行号（**表头齿轮 = 列配置唯一入口**，storage-key `budget-plan-table-columns`；工具栏不再放列配置按钮）、操作 |
| 默认显示 | 单据编号、单据状态、编制日期、财政年度、部门、预算总额、已执行、剩余额度、执行率、经手人、打印次数 |
| 默认隐藏 | 批准金额、冻结金额、预算模板、摘要、制单人、审核人、审核时间、审批意见、单据备注、制单时间 |

## 业务规范说明

- **预算编制**：按年度/部门/科目编制预算额度；主表头维护财政年度、部门、编制日期、经手人，明细行维护会计科目与预算金额，「本单金额」= Σ 明细预算金额。
- **审批流**：草稿 →（提交）待审批 →（通过）已审批 /（驳回）已驳回；已驳回可由编制人修改后重新提交；已审批后单据锁定，不可编辑、不可删除。
- **预算执行**：已审批预算经「开始执行」转入《预算执行》跟踪使用 / 剩余，执行中可关闭。
- **快照口径**：明细的「已执行 / 冻结金额 / 剩余额度 / 执行率」在编制阶段初始化为 0 / 0 / 预算金额 / 0，由《预算执行》与控制流程回写，编制侧不直接改这些列。
- **软删除口径**：删除为逻辑删除，单号唯一索引不区分删除状态，因此号段生成必须遍历含软删除的最大单号。

### 业务红线（已实现）
- **单一口径**：预算额度只能经《预算编制》编制并经审批设定；已审批单据禁止编辑、禁止删除。

- **P2 验收**：无桩/无模拟；审批流、下放执行、编制表单需真实数据闭环验证。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
