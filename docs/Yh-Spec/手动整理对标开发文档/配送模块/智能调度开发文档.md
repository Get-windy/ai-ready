## 3. 金标准目标设计

### 3.1 定位重塑：策略台 ≠ 任务列表

| 能力 | 归口 |
|------|------|
| 任务列表 / 手工指派 / 改派 / 取消 | 《调度任务》 |

### 3.2 页面结构（金标准）

`CategoryListLayout` + `Tab`：

1. **策略配置 Tab**：派单规则（最近可用 / 负载均衡 / 评分优先 / 区域分包 / 抢单竞价）的**权重与开关**；配送员约束（在途单上限、载重/容积上限、在线要求、资质要求）；超时升级阈值。落《配送参数》`dms_config`。
2. **调度执行 Tab**：待分配任务 + **一键自动调度**（可先"预览分配结果"再确认），逐单展示"选中配送员 + 命中规则 + 理由"。
3. **效果复盘 Tab**：自动 vs 手工调度占比、平均派单耗时、超时率、承运人负载分布。

- 列表骨架统一 `BillTableList`（序号齿轮列配置）；页面配置 `PageConfigPanel`。

### 3.4 派单策略（业界实践，须落到可配置）

| 策略 | 规则要点 | 工程约束 |
|------|---------|---------|
| 最近可用 | 距取货点最近 + 空闲 | 需实时位置（《实时跟踪》） |
| 负载均衡 | 在途单数/载重/容积最少优先 | **超限不可指派** |
| 评分优先 | 评分 / 准时率 / 完成率加权 | 新配送员冷启动保护 |
| 区域分包 | 按区域/线路绑定固定配送员 | 线路档案（`erp_route`）引用 | ✅ 已落地：`dms_route_rider` 绑定表 + AREA 策略命中（`areaStrict` 严格/偏好两档） |
| 抢单 / 竞价 | 发布到《订单池》由运力自选 | 池生命周期与结算 | ✅ 归口《订单池》，本页只拆分统计 `grabCount` / `bidCount` |

**通用约束**：① 同一任务不重复指派（幂等）；② 指派失败要有明确原因（无人可派/超限/离线）；③ 每次自动调度留**审计**（命中规则、候选人、结果）。

### 7.2 派单算法（可配置）

- **候选池**：`requireOnline=true` 只取「空闲(1)」配送员，否则取非休息配送员。
  - 口径澄清（2026-09-14）：此处的「空闲」= **名下无在途任务**，是**占用**语义；因此任务进入终态（已完成 / 已取消）或改派换人后
    **必须回置空闲**（`TaskService.releaseRiderIfIdle`，单一出口，见《配送模块 README》§8.3）。
    原先「完成」不回置 → 跑完第一单即永久忙碌、不再进池，运力池随完成量单调收缩（已修）。
  - 由此，`requireOnline=false`（“休息中之外均可参与”）是唯一能让**同一配送员同时接多单自动派单**的档位；
    默认档下自动派单是「一次一单」（`dms.dispatch.max.concurrent` 与「负载均衡」权重主要体现在**人工指派**与关闭该开关后）。
- **约束（逐条给出拒绝原因）**：休息中 → 无定位数据 → 任务缺取货点坐标 → **区域分包未绑定线路（严格模式）** → **离线（心跳超阈值）** → 已达并接上限 → 超载重上限 → 超容积上限 → 实名认证与证照（`verifyStatus=1` + `KycService` 有效期）→ 服务围栏。
- **评分**：`距离分(1000/米) × w距离 + 负载分(100/在途) × w负载 + 评分 × w评分`；策略偏好再加权（BALANCED 在途 ×3、SCORE 评分 ×3）；**AREA 下线路绑定的配送员固定加 `100000`（保证绑定者优先不被距离分反超）**。
- **区域分包（AREA，2026-09-13 落地）**：任务按 `dms_task.route_id` 解析线路绑定（一次批量解析，非逐单 N+1）。
  - 偏好档（默认 `areaStrict=false`）：绑定者加权优先，未绑定者作为**备用运力**仍可派（命中规则文案标注「未绑定线路…，备用运力」）。
  - 严格档（`areaStrict=true`）：未绑定线路的配送员直接不可派（候选给出「区域分包：未绑定线路「XX」」；**人工指派同样受此约束**，前后端口径一致）。
  - 任务未指定线路：**降级**为综合评分并在命中规则里注明「区域分包降级：任务未指定配送线路」，不误判为分包拒绝。
- **在线口径（与《实时跟踪》《配送跟踪》《配送员管理》统一）**：`requireOnline=true` 时，`last_report_time` 超过 `dms.tracking.online.minutes`（默认 2 分钟）或**从未上报**即判离线 → 自动派单拒绝并给出「配送员离线（最近上报 N 分钟前 / 从未上报位置）」；候选列表同时返回 `online` / `lastReportTime` 供人工判断（人工指派不做离线硬门控，与既有「离线不参与自动择优」口径一致）。

  （「系统管理 → 开发工具 → 定时任务」，默认**停用**；Redis 锁多实例互斥；逐租户执行；`dryRun` 演练不落库）。
  落地细节与执行器改造（白名单处理器取代反射调用）见《调度任务开发文档》§8.8、《配送模块 README》§8.4。
- **无人可派**：返回「最近候选 + 其拒绝原因」，不再只给一句「无人可派」。
- **诚实兜底**：配送员无定位 / 任务缺取货点坐标时返回**明确原因**而非 NPE（改造前 185 个无定位配送员会把候选接口打成 500）。
