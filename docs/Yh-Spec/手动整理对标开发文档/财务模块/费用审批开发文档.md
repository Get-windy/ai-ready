## 业务规范说明

- **审批流**：费用单提交后按「部门审批中 → 财务审批中 → 总经理审批中 → 审批通过」多级流转，审批人逐级审批，到末级（`currentApprovalLevel >= totalApprovalLevel`）后置为 `APPROVED`。
- **action 语义**：`APPROVE`（通过）/ `REJECT`（驳回）。驳回置为 `REJECTED` 并记录 `rejectReason`；通过且未到末级则 `currentApprovalLevel+1` 并进入下一审批队列。
- **审批记录**：每次操作写 `expense_approval`（申请编号、审批级别、审批人、审批动作、审批意见、审批时间、上一个状态、当前状态），可经 `/records` 追溯。
- **状态机**：`ExpenseStatus`（草稿/已提交/部门审批中/财务审批中/总经理审批中/审批通过/审批拒绝/已支付/已报销/已取消）。
- **待审批范围**：`/pending` 返回 `SUBMITTED / DEPARTMENT_APPROVING / FINANCE_APPROVING / GENERAL_MANAGER_APPROVING` 四种在审状态且未删除的费用单。
- **上游**：费用单（`finance:expense-doc`）在《费用单》页「提交」后进入本页待审批队列。
- **下游**：审批通过后费用单进入《费用支付/报销》环节（`expense_payment` / `expense_reimbursement`）。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 审批单一口径（红线）**：费用审批复用《费用单》状态机与 `expense_approval` 记录表，**严禁另建审批引擎/重复审批状态**；「部门审批中→财务审批中→总经理审批中→审批通过」逐级流转为唯一审批链路。
- **P1 审批→支付/报销下推**：审批通过（APPROVED）后，费用单应真实下推《费用支付/报销》（`expense_payment`/`expense_reimbursement`），保证费用管理闭环。
- **P1 审批人隔离**：`/pending` 按当前登录人 `approverId` 过滤，仅展示本人待办；驳回原因必填并可经 `/records` 追溯。
- **P2 验收**：无桩/无模拟；通过/驳回真实生效（末级置 APPROVED、驳回置 REJECTED 并写 `rejectReason`）；审批记录写入 `expense_approval` 可追溯。
