# 客户概念澄清及重构说明

## 概念澄清

根据业务需求，对CRM模块和ERP模块中的客户概念进行澄清：

### CRM模块的客户
- **定义**：包括潜在客户和实体客户的全部客户
- **范围**：针对客户维护及客户关系处理
- **性质**：即"公海客户"，是所有可能成为客户的客户和已经发生业务往来的实体客户在内的全部公海客户
- **用途**：客户开发、客户关系维护、商机跟进等

### ERP模块的客户（Partner）
- **定义**：特指与企业实际发生业务往来及交易的实体客户
- **范围**：实际的交易对象
- **性质**：在销售订单等实际业务流程中使用的客户
- **用途**：订单处理、交易记录、应收账款等

## 业务逻辑

在销售订单处理中：
1. CRM模块负责客户开发和关系维护
2. ERP模块的Partner实体用于实际的业务交易
3. 销售订单基于实际发生业务往来的实体客户（Partner）进行处理
4. 这种区分确保了业务流程的精确性和数据的准确性

## 技术实现

- 使用PartnerService替代了原来的CustomerService
- 更新了pom.xml依赖，使用erp-partner替代erp-customer
- 修改了getCustomerGradeCode和getCustomerGradeName方法，基于Partner实体获取客户等级信息
- 确保销售订单处理基于实体客户而非整个公海客户群体

## 业务价值

这种概念澄清和实现方式确保了：
1. 销售订单处理的精确性（基于实际业务客户）
2. 客户关系管理与实际交易的分离
3. 数据模型与实际业务流程的一致性
4. 系统架构的合理性
