## 1. 页面概述

### 1.1 一句话说清「模型错位」

| | **ql361 的「系统任务」** | **本系统的「系统任务」** |
|---|---|---|
| 页面性质 | **异步任务的执行台账**（每行 = **一次执行**） | **定时任务的配置清单**（每行 ≈ **一个任务定义**） |
| 行的时间语义 | **任务创建时间 / 任务开始时间 / 任务结束时间**（三个**执行时刻**） | **上次执行**（单个时刻）+ **执行频率**（周期） |
| 结果获取 | ✅ 行内 `下载处理结果` **链接** | ❌ 无（无「结果查看」列） |
| 任务标识 | 任务 ID（如 `17248262`） | 任务编号 |
| 实测数据量 | **共 235 条记录**（12 页 × 20 行） | **0 行**（无表） |
| 后端 | （对标私有） | **零控制器** |
| 表格是否渲染数据 | ✅ 235 条真实数据 | ❌ **恒空**（prop 误用） |

> **结论**：**本系统把「跑过的任务」写成了「会跑的任务」** —— 列名（`执行频率`/`上次执行`）暴露了它其实是**调度配置**的语义，而对标要的是**执行历史**（含开始/结束/结果）。**再加上 prop 误用导致表格恒空**，这一页**两个问题叠加**：① 即使有数据，用户也看不到想看的（执行记录）；② 现在连数据都看不到。

### 1.4 本页不提供的能力（如实登记）

**① 本页「应有」但因 prop 误用而完全失效的能力**：表格恒空、查询/重置无效（与《系统重建》完全同症）。

**② 对标有、本系统完全没有的能力**：

- ❌ **「结果查看」列 + `下载处理结果`**（对标 9 列中的第 9 列，是任务台账的**核心价值**）。
- ❌ **任务状态语义**：对标为 `成功`（实测），本系统**无值域映射**（直接展示原始值）。
- ❌ **任务类型/任务名称的取值口径**：对标实测 `任务类型 = 导出`、`任务名称 = 报表导出` / `商品资料导出`（**类型是粗分类、名称是具体报表名**）。
- ❌ **任务 ID**（对标显示原始数字 ID，如 `17248262`）。
- ❌ **创建人**（对标为 `杨生淮` / `高晓丽`，真实姓名）。
- ❌ **按任务 ID 查询**（对标查询区只有 `任务ID` 一个输入框 + `查询` 按钮）。
- ❌ **`刷新` 按钮**（对标右上角有）。
- ❌ **列配置齿轮**（对标**有**，9 列全可配）。
- ❌ 无失败任务的重试、无任务取消、无执行日志查看、无进度。

**③ 通用能力缺失**：无 `PageConfigPanel`、无 `storage-key`、无 `StandardPagination`、无权限门控、无 `PageContainer(full-height)`。

### 5.1 状态值域

**本系统（查询下拉，`:21-35`）** —— ⚠️ **value 是中文文案本身，不是码值**：

| value | 显示文案 | 行 |
|-------|---------|----|
| `''` | 全部 | `:21-23` |
| `'待执行'` | 待执行 | `:24-26` |
| `'执行中'` | 执行中 | `:27-29` |
| `'已完成'` | 已完成 | `:30-32` |
| `'已失败'` | 已失败 | `:33-35` |

**表格 `status` 列**（`:110`）：**无值域映射**，直接展示后端原始值。
**后端枚举**：**不存在**（无控制器）。

> 🔴 **取值口径分裂（P1，当下无法对证）**：查询下拉用**中文字符串**（`'待执行'` 等 4 态），而表格 `status` 列直接展示原始值。若后端返回**数字码**（`0/1/2/3`），则**下拉选中「已完成」时，`status='已完成'` 传给后端，而列表显示的是 `2`** → **筛选与展示两套口径**。**本页后端不存在，故无法对证**（如实登记）。

**ql361 的值域（实测）**：`任务状态 = 成功`（截图与 `head` 中 235 条的首行与抽样均为 `成功`）。
**对照**：本系统的 4 态（待执行/执行中/已完成/已失败）**在标的上没有可对照的完整值域**（仅取到 `成功` 一态）→ **不对标 ql361 的状态枚举**，应按**本系统自己的异步任务框架**定义（建议 `pending/running/success/failed/partial`，与《系统重建》§7.3 一致）。

### 5.2 流转规则（**目标规格**，本系统未实现）

```
创建任务（pending） ──▶ 开始执行（running） ──┬──▶ 成功（success） ──▶ 结果可下载
                                            ├──▶ 失败（failed）  ──▶ 可重试
                                            └──▶ 部分成功（partial） ──▶ 可重试失败范围
```

| 动作 | 前置校验 | 失败文案 | 副作用 | 证据 |
|------|---------|---------|--------|------|
| 创建任务 | 由**发起方**（导出、重建、同步…）调用 | — | 落 `pending` 行，记 `任务创建时间` | 目标规格 |
| 开始执行 | — | — | `running` + 写 `任务开始时间` | 目标规格 |
| 结束 | — | 失败写原因 | 写 `任务结束时间` + `status` + **产物地址** | 目标规格 |
| **下载处理结果** | 任务 `status=success` 且产物**未过期** | 产物已过期 / 不存在 | 下载文件 | 目标规格（对标有该链接） |
| 重试 | 任务 `status ∈ {failed, partial}` | — | **新起一次执行**（**不得覆盖原记录**） | 业界做法（§8.2） |

> ⚠️ **「重试」的关键设计约束（提前登记）**：**重试必须新增一行（新的执行记录），而不是修改原行** —— 否则「执行历史」被覆盖，台账失去意义。这是对标「每行 = 一次执行」语义的必然推论。
> 本系统《系统重建》的 `partial` 语义（见该文 §7.3）与本页应**共用同一套状态机**。

17. **断言返回字段恰含 9 项**：`taskId`/`taskType`/`taskName`/`status`/`createdByName`/`createTime`/`startTime`/`endTime`/`resultUrl`（**命名须与实施约定一致**）。
18. **断言「创建人」返回的是姓名**（对标实测 `杨生淮`/`高晓丽`），**不是用户 ID**。
19. **断言三个时间列都存在且可空**（`createTime` 必非空；`startTime`/`endTime` 在 `pending` 时为空）。
20. **断言 `status` 取值落在定义的值域内**（不出现定义外的值）。
21. **断言任务类型取值**：造 `task_type='导出'`、`task_name='报表导出'` 与 `'商品资料导出'` → 断言列表正确回显（**复现对标实测取值**）。
22. **断言耗时可由时间列推导**：`endTime - startTime` > 0（对标首行三个时间同为 `17:55:45`，第二行 `15:36:27 → 15:36:30`，**耗时 3 秒**）。
23. **断言列表不返回产物内容**（只返回 `resultUrl`），避免大字段拖慢列表（**性能红线**）。

**D. 结果下载（㉔–㉘）**

24. **成功任务的下载**：`GET /{id}/result` → 200，`Content-Disposition` 含文件名。
25. **未完成任务下载** → 断言 **409/400**（不允许下载未产出结果的任务）。
26. **产物已过期** → 断言 **410/404** 并给出「已过期」的可读提示。
27. **跨租户下载**：用 B 租户 token 下载 A 租户任务的产物 → **断言拒绝**（**越权红线**）。
28. **直链保护**：断言 `resultUrl` **不是永久公开直链**（无鉴权直接访问 → 拒绝）。

**E. 状态与重试（㉙–㉜，目标能力）**

29. **状态机**：造 `pending`/`running`/`success`/`failed`/`partial` 五种任务 → 断言列表状态映射与颜色正确。
30. **失败可读**：`failed` 任务 → 断言返回 `errorMsg` 且非空。
31. **重试**：对 `failed` 任务调重试 → 断言**新起一行任务**，且 **`parentTaskId` 指向原任务**、**原任务行未被修改**（`status`/`endTime` 保持原值）。
32. **幂等**：连续两次对同一 `failed` 任务调重试 → 断言**只创建一个新任务**（或明确返回 409）。

### ② 后端接口清单（方法 + 路径，逐条对源码）

| 方法 | 路径 | 权限码 | 源码 |
|---|---|---|---|
| GET | `/api/set/system-task/page` | `set:system-task:view` | `backend/core/api/core-api/.../scheduler/controller/SystemTaskController.java` |
| GET | `/api/set/system-task/{id}/result` | `set:system-task:download` | 同上 |

要点：

- `/page` 查询条件仅「任务ID」（精确匹配，非数字直接返回空页，不报 500）；**租户可见性手工拼条件**（`scheduled_task_log` 在 `IGNORE_TENANT_TABLES` 中，拦截器不注入）：`tenant_id = 0 / NULL` 为平台级记录（全租户可见），非 0 只对发起方租户可见，平台超管保持全局视野。
- `/{id}/result` **绝不返回假文件**：404（任务不存在 / 非本租户可见 / 文件不存在 / 未产出结果）、409（任务尚未成功完成，含当前状态文案）、410（结果已过期）；跨租户下载一律按「不存在」处理，不泄露他人任务存在性。
- 产物取值：① `result_url`（相对 `storage.local.base-path` 的本地文件，含目录穿越防护，拒绝越界路径）；② `execute_result` 文本（UTF-8 文本文件）。外部 URL **不做服务端代理**（防开放重定向 / SSRF），如实告知。
- 列表**不返回产物内容**，只回鉴权地址 `resultUrl`（避免大字段塞进列表）。
- `SystemTaskVO` 为 9 列契约 + 失败原因；状态归一为闭集字符码（`pending` / `running` / `success` / `failed` / `partial` / `unknown`）。
