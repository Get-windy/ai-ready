## 1. 模块定位与边界

配送模块由**两块**组成，业务上「一次配送动作」与「配送能力体系」分离：

| 分块 | 对标来源 | 本系统菜单 | 内容 |
|------|---------|-----------|------|
| **配发收（配送执行）** | ql361 `配发收` 域（实测 5 页） | 侧边栏「配发收」 | 配送查询、物流发货、发货查询、物流退货收货、采购订货收货 |
| **配送资源（DMS）** | ⚠️ ql361 无对应菜单（本系统新增） | 侧边栏「配送」 | 线路/车辆/骑手/调度/跟踪/配送配置（13 项） |
| **配送主数据** | ql361 `资料 → 配送管理 → 线路`（实测） | 挂在「资料」菜单，业务归配送 | 线路（配送线路档案） |

> **边界铁律**：q l361 的「配发收 → 配送业务」下**只有「配送查询」，没有「配送单」**（2026-09-12 实测确认）。
> 本系统《配送单》属**新增单据**，无对标页，按本系统自主建模（见《配送单开发文档》实现差异说明），**不要臆造 ql361 字段**。

## 4. 域级说明

- **单据编号规则**（实测）：销售订单 `XSDD-`、销售出库单 `XSCKD-`，后缀 `YYYYMMDD-序号`；配送任务编号/收货单据编号规则**待复核**（抓取时点无对应列数据）。本系统《配送单》采用 `PS+YYYYMMDDHHmmss`，待纳入统一号段（见《配送单开发文档》待完善）。
- **入口直达现象**：本域 5 个菜单中 3 个为「直达型」——物流发货 → 订单处理中心 2.拣货/发货；物流退货收货 → 销售退货申请-历史；采购订货收货 → 收货处理。落地时**必须复用目标视图组件**，不得重复造页面（对应通用原则「功能/模块不重复开发」）。
- **状态流转主线**：
  - 销售线：销售订单(XSDD) → 订单处理中心审核 → 拣货/发货（物流发货）→ 销售出库单(XSCKD，已记账) → 配送任务（配送查询：待配送/配送中/已配送）
  - 退货线：销售退货申请（审核）→ 物流退货收货（已收/未收跟踪）→ 销售退货单入库
  - 采购线：采购订单 → 采购订货收货（待收货/部分收货，批量收货）→ 采购入库单
- **配送状态三值**（配送查询实测）：`待配送 / 配送中 / 已配送`。
- **司机与送货员是两个角色**（配送查询实测）：同一配送任务可不同人，列中分设「司机名称」「送货员」，另有隐藏列「司机编号」。
- **收发货双口径**（配送查询实测）：一行任务同时统计正向「配送单量/发货数量/发货金额/订金金额」与回流「退货单量/退货数量/退货金额」，并有「装箱数量 / 配送里程(km) / 体积（m³）/ 重量（kg）」隐藏列。

## 6. 写作与开发原则

- **不重复通用规范**：价格等级 8 字段、客户来源、架构师红线、验收标准统一指向《对标开发技术参考文档》。
- **不发明字段**：字段名必须出自实测弹窗原始列名，禁止凭空补字段；无对标页如实标注「本系统建模」。
- **两类配置严格分开**：查询条件/功能按钮 → 「页面配置」；默认列 + 全量可配置列 → 「数据表格列配置」，不得混写。
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E**：脚本放 `tools/e2e-<模块>.cjs`；**【金标准】启动进程随手关**（详见 `AI_DEVELOPER_RULES.md` 7.3 会话收尾纪律）。
