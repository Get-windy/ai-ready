## 页面概述

移库单用于库内货位之间的库存移动（源货位 → 目标货位），常见于库内整理、补货、货物挪移。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 移库单列表页 | `wh/move-order/index`（list_path 别名 `wms/move`） | 双入口「历史」标签 |
| 新增/编辑移库单表单页 | `wh/move-order/form` | 编辑模式为新增模式加 id |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序。
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结。
- ✅ **当前实现说明**：本页已采用生产级 `CategoryListLayout` + `BillTableList` + `ColumnConfigPanel`/`PageConfigPanel` 实现，已接入**列配置弹窗、页面配置弹窗（查询字段显隐/功能按钮/打印设置）**、打印(F8)、导出。

## 新增编辑移库单表单页配置

### 页面结构（设计值）

`PageContainer` 三段自建面板：**单据头** → **作业明细** → **最近移库单列表**。

### 单据头字段

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 单号 | a-input | 是 | taskNo，前端 `genTaskNo('MV')` 预填，可修改 |
| 移库仓库 | a-select | **是** | warehouseId，`warehouseApi.listAll()`，联动加载货位（change 时重置源/目标货位并重拉） |
| 来源货位 | a-select | 否 | fromLocationId，allow-clear，`locationApi.listByWarehouse(warehouseId)` |
| 目标货位 | a-select | 否 | toLocationId，allow-clear |
| 移库类型 | a-select | 否 | 普通移库 0 / 补货移库 1 / 整理移库 2 |
| 备注 | a-input | 否 | remark |

### 工作流按钮

| 状态 | 按钮 | 动作 |
|------|------|------|
| 任意 | 保存单据 / 保存修改 | `moveApi.save` / `update` |
| 任意 | 新建 | 重置表单 |
| status=0 | 开始移库 | `moveApi.startMove(id, userId, userName)` |
| status=1 | 执行移库（popconfirm） | `moveApi.executeMove(id, userId, userName)` |
| status=0/1 | 取消（popconfirm） | `moveApi.cancelMove(id, reason)` |

### 作业明细表格

明细仅**待移库（status=0）**可编辑，保存为**整体替换**（`moveApi.saveDetails`，先删后插）。新增行时以表头 from/to 货位作为默认值带入。

**编辑态列**：行号、商品（a-select）、规格、单位、移库数量（a-input-number）、源货位（a-select）、目标货位（a-select）、批次号、操作（删除）。

**只读态列**：行号、商品编码、商品名称、规格、单位、移库数量、源货位编码、目标货位编码、批次号、状态。

> 明细保存校验：明细非空、每行必选商品、移库数量 > 0。

### 最近移库单列表（表单页底部）

列：单号、移库类型（文本）、仓库、货位路径（源→目标合并路由）、进度（移/总）、状态、创建时间、操作（载入 / 开始 status=0 / 执行 status=1）。

## 业务规范说明

- 库内货物挪移：移库单记录商品从源货位到目标货位的数量移动，执行后按理应更新货位库存（本单当前**未回写库存**）。
- 移库类型：库内移库 / 补货移库 / 整理移库，决定移库业务归属。
- 明细状态：待移库 0 → 已移库 1；执行移库后明细只读。
- 单号前缀 `MV`，前端 `genTaskNo` 生成（`MV-yyyyMMddHHmmss`），后端 `save` 原样落库；**后端无 next-no / 序列号自动生成**。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），仓储模块无移库页，本页为设计新增。

### 跨模块检查问题（P0→P2 · 本页负责区域）

> 来源：《跨模块关系检查报告.md》。移库单是本批**唯一已接入 `InventoryService.move` 的库内单**（标杆），相对健康；本页负责以下收尾项。

| 级别 | 问题 | 修复要点 | 状态 |
|---|---|---|---|
| P0 | 移库 move 不镜像 `erp_stock`（总量不变，合理） | `move` 仅库位间变动，确保 `wms_inventory` 源/目标行一致，不误镜像总量 | ✅ 已满足：`InventoryService.move` 仅操作 `wms_inventory`（源/目标货位同减同增+库存日志），未调用 `StockService` 镜像总量，源/目标账一致 |

### 最终裁决方案（2026-09-02 · 严格按此执行）

> 与《发货单最终裁决》一致，本页为库内移动标杆，遵循同一库存单一口径红线。

- **P0 库存单一口径（红线）**：库位移动统一经 `InventoryService.move`（源货位扣+目标货位加+`wms_inventory_log`，`FOR UPDATE` 悲观锁并发安全），**严禁绕过引擎**直接改库存（禁止双轨）。
- **P1 盘点差异→移库**：**已实现（2026-09-03 · 事件解耦）**——erp-stock 盘点明细新增「目标货位」(toLocationCode 货位转移差异)，`StockTake.process` 对有目标货位的明细发布 `StocktakeMoveEvent`；wms `StocktakeMoveListener` 监听后调 `MoveService.createMoveFromStocktake` 生成移库单（sourceType=盘点差异，sourceNo=盘点单号，草稿）。未用 HTTP（`/api/wms` 未在鉴权放行列表，服务端调用会 401），改用同容器进程内 Spring 事件解耦。
- **P2 校验**：同货位同批次并发移动由引擎锁保护（`InventoryService.move` 的 `selectForUpdate`）；**批次移动校验**由引擎按 `productId+仓库+源货位+batchNo` 核库存（缺失/不足抛错）；**序列号移动校验**已实现：`executeMove` 对同一移库单内非空 `serialNo` 做唯一性校验（重复抛异常）。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
