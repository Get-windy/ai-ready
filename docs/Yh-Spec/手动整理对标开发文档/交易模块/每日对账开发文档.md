## 页面概述

每日对账是**在线支付渠道路由对账**页：按日期/渠道执行日对账（`POST /api/reconciliation/execute`），对比「我方支付记录」与「渠道侧流水」，产出总/成/差笔数与金额，并对有差异的单据执行「处理差异」（手工调账/忽略差异/重新对账）；同时对待对账日期做查询。（**单入口，无子 Tab，无独立表单**。）

| 页面 | 地址 | 说明 |
|------|------|------|
| 每日对账 | `payment/reconciliation/daily` | 单视图列表页（统计卡片 + 3 查询字段 + 数据表 + 执行对账/处理差异弹窗） |

单入口：交易模块 → 支付管理 → 支付对账。

- 实测实据：数据表列 10、查询字段 3、列/页面配置弹窗 **无**。
- 状态机（`RECON_STATUS_MAP`）：0 待对账 / 1 已对账 / 2 有差异。
- 支付渠道（`PAYMENT_CHANNEL_MAP`）：ALIPAY 支付宝 / WECHAT 微信支付 / UNIONPAY 银联支付 / BANK 银行转账 / CASH 现金/线下。

### 对标页（ql361 在线支付对账单）

## 页面结构（含配置）

每日对账 = 单视图列表页（无子 Tab，无列/页面配置弹窗）。

### 统计卡片（固定 4 项）
已对平（status 1）、有差异（status 2）、处理中（status 3）、差异金额（累计差异金额）。

### 查询条件字段（固定 3）
- 渠道（下拉：全部渠道/支付宝/微信支付/银联支付/银行转账/现金+线下）
- 状态（下拉：全部状态/待对账/已对账/有差异）
- 日期（日期范围：startDate ~ endDate）
- 搜索、重置（按钮）

### 功能按钮 / 行级操作
- 头部按钮：刷新（F5）、**执行对账**（弹窗选对账日期 + 渠道 → `POST /api/reconciliation/execute`）。
- 行级操作：**详情**（抽屉：对账日期/渠道/总笔数/总金额/成功笔数/成功金额/差异笔数/差异金额/状态/对账时间 + 差异明细子表）、**处理差异**（仅 `status===2` 时显示；弹窗选 处理方式 手工调账/忽略差异/重新对账 + 处理备注 → `POST /{id}/handle`）。

### 数据表列（固定 10 列）
对账日期、渠道（Tag）、总笔数、总金额（¥）、成功笔数、成功金额（¥ 绿）、差异笔数、差异金额（¥ 红，>0 显示，否则 -）、状态（Tag）、操作（详情/处理差异）。

## 业务规范说明

- **对账主线**：选日期+渠道 → 执行日对账 `POST /api/reconciliation/execute`（系统拉渠道侧流水比对）→ 产出 总笔/总金额、成功笔/成功金额、差异笔/差异金额 → 更新对账记录状态（待对账/已对账/有差异）。
- **差异处理**：对有差异（status 2）单据执行 手工调账/忽略差异/重新对账（`handleDifference`），完成后状态更新。
- **状态流转**：待对账（0）→ 已对账（1，无差异）/ 有差异（2）；处理差异后 →已对账或重新执行。页面统计卡片另用「处理中（status 3）」区分正在处理的对账，但 `RECON_STATUS_MAP` 枚举仅 0/1/2（见「待完善」）。
- **待对账日期**：`GET /api/reconciliation/pending-dates`（按渠道取待对账日期列表）。
- **金额口径**：总金额=当日渠道路由总流水；成功金额=状态成功；差异金额=「我方」与「渠道侧」不一致的差额（`diffRecords` 明细：我方金额/渠道金额/差异金额/说明）。
- **下游**：差异处理对账、财务核对日结。

## 实现差异说明

**实现文件**：
- 前端：`apps/pc-admin/src/views/payment/reconciliation/daily.vue`
- API：`apps/pc-admin/src/api/payment/index.ts`（`reconciliationApi`）
- 后端：`backend/core/payment/core-payment/.../ReconciliationController.java`（`@RequestMapping("/api/reconciliation")`：`POST /execute`、`GET /page`、`GET /{id}`、`POST /{id}/handle`、`GET /pending-dates`）
- 表：`payment_reconciliation`（V8.10.0__Payment_Center_Tables.sql）

### 页面对齐（当前：`BillTableList`）
- **单视图列表**：当前无子 Tab、无独立表单，符合「单入口对账」定位。
- **查询区（3 字段）**：渠道、状态、日期（范围）；头部另有 刷新、执行对账。
- **数据表列（10 列）**：对账日期、渠道、总笔数、总金额、成功笔数、成功金额、差异笔数、差异金额、状态、操作。
- **统计卡片（4 项）**：已对平/有差异/处理中/差异金额（基于当前页数据实时统计）。
- **弹窗/抽屉**：执行对账、处理差异、（详情含差异明细子表）。
- **行级操作**：详情、处理差异（仅 status 2）。

### 待完善（非阻塞 · 建议对齐金标准）
1. **列/页面配置弹窗**：`BillTableList` → 升级 `CategoryListLayout` + `BillTableList` + `ColumnConfigPanel`/`PageConfigPanel`；补「页面配置-查询条件/功能按钮」与「列配置」弹窗（可参照 ql361 在线支付对账单 10 列列表形态归类）。
2. **状态机不一致**：`RECON_STATUS_MAP` 仅 0/1/2（待对账/已对账/有差异），页面统计用 status 3 表示「处理中」，需统一（补枚举 3 或调整统计口径）。
3. **处理差异参数不一致**：后端 `handleDifference(id, remark)` 只收 `remark`，前端 `handleDifference` 传 `{method, remark}`，`method` 未落到后端（处理方式 手工调账/忽略差异/重新对账 需在后端落库）。
4. **差异明细列**：差异明细子表列（类型/我方金额/渠道金额/差异金额/说明）与后端差异记录结构需核对。
5. **统计口径**：统计卡片改为后端聚合接口（当前为当前页数据实时统计）。
6. **功能按钮**：补 打印(F8)、导出（当前仅 刷新/执行对账 + 行级操作）。
7. **截图**：补本系统浏览器端到端截图。
