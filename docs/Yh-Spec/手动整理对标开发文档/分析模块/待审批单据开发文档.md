## 1. 页面概述

待审批单据是**跨业务域「待审批」状态单据的统一台账**：把销售 / 采购 / 收付款 / 库存 / 费用等各域处于审批中态的单据聚合到同一列表，供审批人在一处完成审核通过 / 驳回。**单入口、单视图**（无页内 Tab）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 待审批单据 | `analytics/pending-approval` | 单视图列表页（跨 13 类单据聚合台账 + 行级/批量审批） |

单入口：分析 → 综合单据 → 待审批单据。

- 页面结构：查询方案 + 时间快捷段 + **三行查询区** + 单据台账表格（首列红色齿轮列配置入口 + 序号线 + 行勾选框 + 固定「操作」列）+ 底部合计行 + 分页条。
- 实测实据（2026-09-15）：共 **6** 条记录、**1/1** 页、每页显示 **22** 行、底部合计 **1,238**。全部为「销售出库单」（`XSCKD-20260915-0xx`），点击左侧「审核」动作处理。
- 多 Tab 判定：实测 JSON `tabs` 为 `{}`（空对象），`.png` 顶部仅一个「待审批单据」页签 → **单视图，无子 Tab**。

## 4. 业务规范

### 统计口径与数据关系

- **数据范围**：全部业务域处于「待审批 / 审批中」状态的单据，一行一单，`金额` = 单据金额原值；底部合计对当前过滤范围求和。
  - 后端实现为 13 个单据分支的 UNION 聚合（`DocQueryService.java` 的 `BRANCHES`，`DocQueryService.java:50-127`），`StatusMode.PENDING` 时每类按其**自身状态枚举**取待审批值，例如销售订单 `status = 1`（`待审核`）、销售出库单 / 销售退货单 `status = 1`（`待审批`）、销售预订单 `status = 1`（`审核中`）、费用申请单 `status IN ('SUBMITTED','DEPARTMENT_APPROVING','FINANCE_APPROVING','GENERAL_MANAGER_APPROVING')`。
  - 单据类型下拉实测默认「全部单据」，可按 13 类之一过滤。
- **账期条件**：带 `≥` 比较符，按单据账期天数过滤（用于筛「账期 ≥ N 天」的超期审批单）。
- **审批动作**：`审核`（行级）/ `审核通过`、`驳回`（批量）。通过 → 单据回到来源业务域继续流转；驳回 → 退回制单人修改后重新提交。
- **组内分工**（综合单据组三页 = 单据生命周期的三个横切状态）：
  待审批单据（审批中）→ 业务草稿（未提交 / 未过账）→ 经营历程（已过账全量流水）。

### 与其他页面关系

- **上游**：各业务域单据的「提交」动作（销售订单表单页提交后进入审核中；采购 / 仓储 / 财务各域单据类推）。
- **下游**：审批通过回写源单据状态；驳回回写并通知制单人。
- **同组页面**：业务草稿、经营历程。

## 5. 实现差异说明

> 本节按当前源码回写（本轮未改动源码）。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/pending-approval/index.vue`（共 107 行）。
- **骨架**：`ARReportPage` 只读报表壳（`index.vue:2-23`，`title="待审批单据"`、`export-file-name="待审批单据"`、`row-key = docTypeCode-docNo`）。`ARReportPage` 为纯报表壳（`components/ARReportPage/ARReportPage.vue`：内联查询表单 `:16-64` + `a-table` `:100-120` + 内置分页 `:234-240` + 内置 CSV 导出 `:340-371`），**不含** `BillDetailTable` / `StandardPagination` / `PageConfigPanel`，**无列配置齿轮、无页面配置弹窗**。
- **查询条件**：`queryFields`（`index.vue:49-54`）= `单据类型`（select，13 项，`DOC_TYPE_OPTIONS` 见 `:33-47`）、`单号`（input）、`往来单位`（input）、`业务日期`（date-range）。**共 4 项**。
- **列定义**：`columns`（`index.vue:57-65`），共 **7 列**：单据类型、单号、业务日期、往来单位、金额、状态、操作人。
- **状态着色**：`statusColor()`（`index.vue:68-75`）；金额格式化 `formatMoney()`（`:77-80`）。
- **数据请求**：`fetcher`（`index.vue:83-85`）→ `docQueryApi.pendingDocsPage`。
- **统计卡片**：`statCards`（`index.vue:87-100`）在 `onLoaded`（`:102-105`）后从响应 `summary` 映射出「待审批总数」+ 逐类型计数卡片 —— **本系统新增，对标无此区域**。
- **行选择**：**禁用**（`ARReportPage` 的 `enableRowSelection` 默认 `false`，`ARReportPage.vue:199`；本页亦未传该 prop）→ 无勾选框、无批量操作。
- **数据来源**：`apps/pc-admin/src/api/analytics.ts` → `docQueryApi.pendingDocsPage`（`analytics.ts:90-92`，`GET /docquery/pending-docs/page`）。
- **后端**：`backend/core/api/core-api/src/main/java/cn/aiedge/docquery/controller/DocQueryController.java:57-73`（`@RequestMapping("/api/docquery")`，`pendingDocs`，附加 `pendingSummary`）；服务层 `docquery/service/DocQueryService.java:144`（`page(..., StatusMode.PENDING, ...)`）、`:210`（`pendingSummary`）。
- **storage-key**：无（未使用列配置 / 页面配置持久化）。

### 剩余缺口

1. **🔴 未达金标准（骨架层）**：本页为 `ARReportPage` 只读壳，未使用 `CategoryListLayout` / `BillDetailTable` / `StandardPagination` / `PageConfigPanel`；无列配置齿轮、无页面配置弹窗。（按本页对标规格，达标线 = 查询区齐全 + 列配置可用 + 分页 + 行级操作，本页仅命中「分页」一项。）
2. **🔴 列配置能力完全缺失**：对标 13 列 / 默认 12 未落地；无表头齿轮、无个人 / 全局配置持久化。
3. **🔴 行级操作缺失**：对标行级「审核」无实现；`columns` 中无「操作」列。
4. **🔴 批量审批缺失**：对标 `审核通过` / `驳回` 无实现（且 `enableRowSelection=false`，连勾选都没有）。
5. **🔴 查询条件不对齐**：对标 12 项（查询方案 / 时间快捷段 / 日期范围 / 单据编号 / 单据类型 / 往来单位 / 经手人 / 部门 / 单据备注 / 账期≥ / 仓库 / 所属区域），本页仅 **4 项**；缺 `所属区域`、`仓库`、`经手人`、`部门`、`单据备注`、`账期(≥)`、查询方案、时间快捷段。
6. **🔴 列结构不对齐**：本页 7 列（单据类型 / 单号 / 业务日期 / 往来单位 / 金额 / 状态 / 操作人）vs 对标 13 列。语义近似仅 4 列（单据类型 / 单据编号(单号) / 往来单位 / 金额）；缺 `单据日期`（本页用 `业务日期`）、`所属区域`、`仓库`、`经手人`、`部门`、`制单人`、`摘要`、`单据备注`、`附件`（9 列）；本页多出 `状态`、`操作人` 两列（对标无）。

8. **列宽 / 对齐**：对标「金额」为右对齐可排序（表头带排序箭头）；本页金额右对齐但无排序交互。
9. **打印：非缺口**：对标本身无「打印(F8)」，本页无打印即对齐。
10. **本系统多出的统计卡片区**：`statCards`（`index.vue:87-100`）为**本系统新增**，对标页无卡片区 —— 属超出对标范围的自加能力，不计入缺口，但亦不构成「对齐」。
11. **无 E2E 脚本**：`tools/` 下**无** `e2e-analytics*.cjs` —— 本页**未跑过** E2E，如实标注。
