## 页面概述

辅助核算余额表是**按核算项（往来单位/供应商/客户/职员/部门）汇总的科目余额**。**复合页**（查询 + 分组表头汇总表格 + 合计行），无分页，单入口。

菜单：财务 → 账簿 → 辅助核算余额表。

### 配置功能说明
- **列配置**：数据表表头内齿轮图标（`.icon-shezhi2`，表头左起「𞸎/谢」列）→ 列配置弹窗（个人配置 / 全局配置），配置列：上级、列名、显示名、显示；支持上移/下移/恢复默认/保存。**12 列全部默认显示，无隐藏列**。
- **页面配置**：无。本页工具栏仅 刷新/打印(F8)/导出/明细对账/查询，无「配置」齿轮，故**无页面配置弹窗**（仅列配置弹窗）。
- ✅ **本系统已实现**：表头 `rowNo` 列内置齿轮（`BillDetailTable` 统一列配置能力）→ 列配置弹窗（个人配置 / 全局配置 两个 Tab，含恢复默认）；分组列在配置弹窗中的列名为「分组名-子列名」（期初余额-借方 …），与对标口径一致；页面无「配置」齿轮、无页面配置弹窗，与对标一致。

## 业务规范说明

- **核算项**：科目挂核算项（应收 1122=客户、应付 2202=供应商、部门/职员费用）；核算项维度可选 往来单位/供应商/客户/职员/部门。
- **取数**：按核算项聚合凭证分录，期初余额（会计月起时点）、本期发生额（起止月间借贷）、本年累计（年初至止月）、期末余额（止月时点）；各段含借方/贷方两方向列。
- **用途**：辅助核算余额（往来单位往来对账、部门费用分析）。

**实现文件**：
- 前端：`views/finance/aux-balance/index.vue`
- API：`api/finance/index.ts` → `auxiliaryBalanceApi.getPage`（`/erp/finance/auxiliary/balance/page`）
- 后端：`erp-finance`
  - `controller/FinanceAuxiliaryController.java`（`GET /api/erp/finance/auxiliary/balance/page`）
  - `service/FinanceAuxiliaryBalanceService.java` + `service/impl/FinanceAuxiliaryBalanceServiceImpl.java`（区间/科目/核算项/分页条件归一化）
  - `mapper/AuxBalanceMapper.java`（纯 SQL 聚合：`finance_voucher_item ⨝ finance_voucher`，仅 `status='posted'`）
  - `dto/AuxBalanceQuery.java` / `AuxBalanceRowDTO.java` / `AuxBalanceSummaryDTO.java` / `AuxBalancePageDTO.java`
- 复用能力：`BillDetailTable`（分组表头 `children` + 表头齿轮列配置）、`BillTableList`、`CategoryListLayout`、`detail-ledger`（明细对账穿透，新增 `settleUnit/settleDept/settleStaff` 入参）

### 取数口径（P0 红线）
| 环节 | 口径 |
|------|------|
| 数据源 | **仅** `finance_voucher_item ⨝ finance_voucher`，`vi.deleted_flag=0 AND v.deleted_flag=0 AND v.status='posted'`（红冲/草稿不计），不读任何余额汇总表 |
| 期初余额 | 会计月(起) 之前全部期间的 `Σ(借−贷)`，按时点方向拆「借方 / 贷方」两列（净额>0 → 借；<0 → 贷） |
| 本期发生额 | `[会计月(起), 会计月(止)]` 区间内 `Σ借` / `Σ贷` |
| 本年累计 | 止月所属会计年度的 1 月至止月 `Σ借` / `Σ贷` |
| 期末余额 | `期初净额 + 本期借 − 本期贷`，按方向拆两列 |
| 余额公式 | 每行与合计行均满足 期初借 − 期初贷 + 本期借 − 本期贷 = 期末借 − 期末贷 |
| 核算项维度 | `PARTNER`=aux_unit（全部）；`CUSTOMER`=aux_unit 且 科目 ∈ 1122/2203；`SUPPLIER`=aux_unit 且 科目 ∈ 2202/1123；`EMPLOYEE`=aux_staff；`DEPT`=aux_dept |
| 核算项编码 | 标量子查询回主数据：`biz_party.party_code` / `sys_dept.dept_code` / `sys_user.username`（`LIMIT 1`，避免一码多名导致行膨胀） |
| 过滤 | 无本期发生额不显示（本期借=贷=0 剔除）；余额为0不显示（期末净额=0 剔除）；科目支持「本级 + 全部下级」范围（`AccountSubjectService#collectCodeWithDescendants`） |
| 合计行 | 全量口径（非当前页）逐列 SUM，与数据行逐列加总一致 |

> **与《科目余额表》的口径边界（勾稽说明）**
> - 《科目余额表》期初 = `finance_ledger` 会计年首期期初（上年结转）+ 本年度起月前凭证净额；
>   本页期初 = **全部年度**起月前凭证净额（纯凭证累计，符合 P0 红线「只读凭证」）。
> - 二者在「上年结转金额 = 上年凭证累计净额」时**完全一致**（当前 dev 库 `finance_ledger` 首期期初为 0，实测勾稽一致）。
> - 仅当 `finance_ledger` 首期期初 ≠ 上年凭证累计净额时（即年结/期初初始化录入了非凭证来源的期初，或跨期结转链未重算）才会出现差额；此时本页的纯凭证累计口径为该科目的真实账面余额，勾稽差异应由《科目余额表》侧承担。
> - 若后续要求两页严格逐分对齐，需把 `finance_ledger` 首期期初按「年初结转」单独合成一行（无核算项维度），属跨页口径统一议题，非本页缺陷。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 核算单一口径（红线）**：辅助核算余额表只读取自凭证核算项聚合，**严禁绕过凭证直改核算项余额**；期初+本借−本贷=期末必须成立。
- **P1 核算项对应**：应收 1122=客户、应付 2202=供应商、部门/职员费用，挂核算项科目必选明细科目。
- **P1 勾稽**：核算项余额合计与科目余额表对应科目余额一致。
- **P2 验收**：无桩/无模拟；余额公式、往来对账、与科目余额勾稽需真实数据闭环验证。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
- 复用清单：`CategoryListLayout` / `BillTableList` / `BillDetailTable`（含分组表头 `children`、表头齿轮列配置）/ `AccountSubjectService#collectCodeWithDescendants`（科目下级范围统一口径）/ `exportCsv`。
