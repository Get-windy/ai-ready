## 1. 页面概述

菜单配置是设置模块的**租户级「菜单显隐」配置台**：以菜单树表格列出菜单，供租户按需增删改菜单项。当前实现**做成了全局菜单树的 CRUD 页**（后端 `/api/menu` 直接操作 `sys_menu`），与本模块 README §1.1 中「设置侧 = 租户改自己菜单显隐」的口径**存在结构性偏差**，详见 §5.4 与 §9。

| 项 | 值 | 证据 |
|----|-----|------|
| 页面 / 组件 | `set/menu-config` / `views/set/menu-config/index.vue`（**362 行**） | `sys_menu.id=80620`；`component=views/set/menu-config/index.vue` |
| 路由挂载 | 由 `router/dynamicRoutes.ts` 按 `component` 动态导入（`:940` 兜底） | 单入口，`display_mode=0`、`list_path=null`（devdb 实测） |
| 外壳 | `ErrorBoundary > PageContainer`（**未传 `full-height`**）+ 裸 `a-table` | `index.vue:2,3,26-33` |
| 后端 | `SysMenuController`（前缀 `/api/menu`，**16 个端点**，逐端点权限注解齐全） | `core/base/core-base/.../base/controller/SysMenuController.java:27` |
| 数据表 | `sys_menu`（**28 列 / 381 行**）、`sys_tenant_menu`（5 列 / **4 行**，本页未使用） | devdb 实测 |
| 权限码 | 前端**零门控**；后端要求 `system:menu:list/create/update/delete/update-status/detail` | 见 §6.3 |

**1.1 与相邻页的分工（本模块最易混的一处）**

| | **菜单配置（本页，80620）** | **菜单管理（系统模块，`6130701`）** |
|---|---|---|
| 归属域 | 设置模块（`client_type = tenant-admin`） | 系统模块（`client_type = system-admin`） |
| 谁可见 | 租户管理员 | 仅平台运营方 |
| 应当管什么 | **本租户**已授权菜单的**显隐开关** | **全局**菜单树定义（权限码 + 路由 + 组件路径） |
| 本系统实际管什么 | **直接增删改 `sys_menu`（`tenant_id = 0` 的全局行）** —— 与「菜单管理」同一张表、同一批端点 | 同左 |
| 组件 | `views/set/menu-config/index.vue` | `views/system/menu/index.vue` |

> **分工结论（现状）**：两页**共用后端** `SysMenuController` 与同一张 `sys_menu`，差别只在前端列的取法与页面壳。按 README §1.1「两个模块不共用页面组件」的红线，本页应当只改**租户级显隐**（`sys_tenant_menu` 机制，后端已存在，见 §5.4），而**不应**改全局菜单定义。这是本页最主要的建模缺口。

> **就地更正（本轮施工后）**：实际的租户级显隐载体是 **`sys_project_config`**（键 `set:menu-config:hidden`，值 = 隐藏菜单 id 的 JSON 数组），**不是** `sys_tenant_menu`（该表仍是既有的「授权」机制，本页未接）。详见文末「实现收口」。

**1.2 本页不提供的能力（如实登记）**

- ❌ 无查询区（不能按菜单名 / 权限码 / 路径检索）；无 `DEFAULT_QUERY_FIELDS` 常量
- ❌ 无分页（`:pagination="false"`，整棵树一次性渲染）
- ❌ 无页面配置弹窗（无 `PageConfigPanel`）、无表头齿轮列配置、无 `storage-key` / `global-config-key`
- ❌ 无「权限标识」落库位置（列与表单项存在，但实体与表都没有该列，见 §7.2）
- ❌ 无拖拽排序（只有数值型 `排序` 字段的编辑）；无批量启停；无导入导出
- ❌ 无权限按钮门控（`grep -rn "v-permission\|hasPermission" FE/views/set/` → 零命中）
- ❌ 无 `StandardPagination`、无 `CategoryListLayout`
- ⚠️ 有「新增菜单」按钮（可创建**任意层级 / 任意 `client_type`** 的菜单），但表单里**没有 `client_type` 字段**（见 §7.2 与 README 记录的「菜单漏写 client_type 与孤儿菜单同症」）

## 4. 表单页配置

**本页无表单页**：菜单 `80620` 的 `display_mode = 0`（单入口）、`list_path = null`（devdb 实测），页面自身即全部界面。页内唯一浮层为**新增 / 编辑菜单弹窗**（`a-modal`，`:85-200`），字段清单见 §3.7（10 项）。

**目标规格（对标 ql361 + 本模块建模口径，标 ★ 者为建议新增）**：★把弹窗拆成「**租户级开关**」与「**全局菜单定义**」两类操作，后者应移出本页（属「菜单管理」）｜★补 `client_type` 必填（`tenant-admin` / `system-admin`）｜★补 `menu_code` 字段（实体已有列 `menu_code`，当前弹窗**完全没有该输入项**）｜★补 `list_path` / `display_mode` / `tag_label` / `biz_flow_tag` / `display_group` / `menu_level`（实体与表均已有列，本页均未暴露）｜★权限标识应绑定到**真实存在的权限码载体**（`sys_permission` + 角色关联），而非一个不存在的列。
> **不发明字段**：★ 项全部指向 `sys_menu` **已有列**（§7.1）或**已有表**（`sys_permission` / `sys_role_permission` / `sys_tenant_menu`），无需新增任何列。

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-set-*.cjs` / `e2e-settings-*.cjs`）。落地脚本建议命名 `tools/e2e-settings.cjs`（接口 + 直连 DB 对账 + 写库后复原 + Playwright UI 断言）。

### 10.1 接口验收（≥ 20 项）

**菜单树读取（①–⑤）**
① `GET /api/menu/tree` **不带参数** → 断言 **400**，错误信息含 `Required request parameter 'tenantId' is not present`（登记 P0-①；修复后改为 200）。
② `GET /api/menu/tree?tenantId=1` → 200，返回树与直查 DB（`SELECT count(*) FROM sys_menu WHERE deleted=0 AND tenant_id=0` 的层级展开）**节点数一致**。
③ 对 ② 的返回断言**顶层节点 `parent_id = 0`**，且 6 个设置页（80620~80625）出现在 `61201 系统配置` 之下。
④ 断言 ② 的返回中**每一行都不含 `perms` 字段**（登记 P0-②）。
⑤ `GET /api/menu/tree?tenantId=0` 与 `?tenantId=1` 返回**完全相同**（验证后端「忽略 tenantId」的注释，`SysMenuServiceImpl.java:96-99`）。

**权限（⑥–⑨）**
⑥ 用**超管账号**（`admin`，`is_super_admin = true`）调 `GET /api/menu/tree?tenantId=1` → 期望 **200**（`*` 通配放行）。
⑦ 用**非超管账号**调同一端点 → 断言 **403**（登记 P0-③；种子补齐后改为 200）。
⑧ 直查 `SELECT count(*) FROM sys_permission WHERE permission_code LIKE 'system:menu%'` → 断言**当前为 0**（登记 P0-③；修复后断言 ≥ 6，覆盖 list/detail/create/update/delete/update-status）。
⑨ 断言 `PUT /api/menu/{id}`、`POST /api/menu`、`DELETE /api/menu/{id}` 在非超管下均为 **403**。

**写操作（⑩–⑯，全部要求「改库 → 回读 → 按原值复原」）**
⑩ `POST /api/menu` 创建测试菜单（`menuName=E2E菜单`、`menuType=1`、`path=e2e/menu`）→ 200 且返回雪花 ID；**直查 DB 断言新增行 `status = 1`、`visible = 1`（后端强制覆盖，登记 P1）**、**`client_type IS NULL`（登记 P0-④）**；断言完毕后**按 ID 删除**。
⑪ `PUT /api/menu/{id}` 修改 `menuName` → 200；直查断言 `menu_name` 已变；**回写原值**。
⑫ `PUT /api/menu/{id}` 传 `{"perms":"system:config:list"}` → 200 但**直查断言表中不存在 `perms` 列**（`information_schema.columns` → 0 行），登记 P0-②。
⑬ `PUT /api/menu/{id}` 传 `{"status":0,"visible":0}` → 200；直查断言两列**确实被改为 0**（说明更新路径不覆盖，与新增路径不同）；**回写为 1**。
⑭ `DELETE /api/menu/{id}`（该菜单**有子菜单**）→ 断言业务失败，消息含 `存在子菜单，无法删除`（`SysMenuServiceImpl.java:82-94`）。
⑮ `DELETE /api/menu/{id}`（无子菜单）→ 200；直查断言 `deleted = 1`（**逻辑删除**，`@TableLogic`）。
⑯ `POST /api/menu` 用**已存在的 `menu_code`** → 断言失败，消息含 `菜单编码已存在`（`SysMenuServiceImpl.java:52-54`）。

**租户机制（⑰–⑳）**
⑰ 直查 `SELECT count(*) FROM sys_tenant_menu` → 断言**当前 4 行**；断言 6 个设置页（80620~80625）**均不在**该表中。
⑱ 断言**不存在**任何租户级菜单显隐端点（对候选路径 `PUT /api/menu/tenant/{tenantId}/visible` 断言 **404**），登记 §6.4 缺口。
⑲ 直查 `SELECT tenant_id, count(*) FROM sys_menu GROUP BY tenant_id` → 断言 `0 → 380`、`1 → 1`（证明本页改的是全局菜单）。
⑳ 断言 `/api/menu/user/mega/{clientType}` 的租户过滤逻辑走**两级交集**（读取返回条数并与 `sys_tenant_menu ∩ sys_role_menu` 的直查结果比对；无权限时返回空数组，`SysMenuServiceImpl.java:290-293`）。

## 12. 剩余缺口（不阻塞，如实登记）

> 级别口径与 README §7 一致：**P0** = 页面不可用 / 数据不落库 / 越权；**P1** = 与对标不符或能力缺失但页面能用；**P2** = 体验与一致性。

**P0**
① **`/menu/tree` 少传必填 `tenantId` → 预期 400**，页面首屏菜单树加载失败（`index.vue:249` vs `SysMenuController.java:83`）。**这是本页不可用的直接原因**；修复只需复用 `api/menu.ts:81` 的既有封装。
② **「权限标识（`perms`）」无落库位置**：`SysMenu` 实体与 `sys_menu` 表**均无 `perms` 列**（真实列名 `menu_code`）→ 列表列恒空 + 弹窗填写静默丢弃。
③ **权限码种子全缺**：`sys_permission` 中 `system:menu%` = **0 行**（全表 264 行）→ 4 个端点的 `@SaCheckPermission` 对非超管全部 403。
④ **越界与孤儿**：本页直接增删改 **全局** `sys_menu`（380/381 行为 `tenant_id = 0`），而非租户级显隐；`sys_tenant_menu` 机制（后端已实现两级交集）**无任何页面可编辑**；且新增菜单**必然缺 `client_type`** → 孤儿菜单。

**P1**
⑤ `status` / `visible` **显示语义与后端相反**（后端 1 = 启用/显示），6 行设置页菜单全被标为「停用 / 隐藏」。
⑥ 新增时 `status` / `visible` 被后端**无条件覆盖为 1/1**，弹窗两个下拉形同虚设。
⑦ **形态完全不对标**：ql361 是「左分组 + 右开关 + 底部统一保存」，本系统是一张菜单树表格；无分组导航。
⑧ 无查询区（无 `DEFAULT_QUERY_FIELDS`）、无分页（`:pagination="false"`）、无列配置齿轮、无 `PageConfigPanel`、无 `storage-key` / `global-config-key`。
⑨ **前端零权限门控**（与后端逐端点注解不匹配）。
⑩ 未复用 `@/api/menu` 封装（该封装**带 `tenantId`**，本可规避 ①）。
⑪ 「图标」列不渲染图标组件，只显示字符串，配置效果不可见。

**P2**
⑫ **无本系统验收截图、无模块级 E2E**（`tools/` 下无 `e2e-set-*.cjs`）。
⑬ `fixed:'right'` 操作列 + 外壳未传 `full-height` 的组合下可能造成操作列错位（**未验证**）。
⑭ 未使用专用端点 `PUT /{id}/status`（启停），改用通用 `PUT /{id}`。
⑮ 「删除」对有子菜单的行必失败，但 `Modal.confirm` 未作前置提示（用户需被后端文案告知）。
⑯ 菜单增删改**无变更日志可查**（`@OperationLog` 注解存在但覆盖范围未实测）。
⑰ 无拖拽排序（仅数值 `排序` 字段）；无批量启停 / 批量删除。
⑱ 无导入 / 导出。

要点（均对源码核实）：

- **只读全局菜单定义**（`sys_menu`，平台资产），**不提供任何菜单增删改端点**；写操作只落**本租户**配置行，`tenantId` 一律取登录会话（`MyBatisPlusConfig.getCurrentTenantIdValue()`），不接受前端传入 → 跨租户影响不可能。
- 自锁保护：`set:menu-config` 页自身 `locked = true`，前端置灰 + 后端兜底拒绝隐藏（否则关掉后再也进不来）。
- 只列 `client_type = tenant-admin` 的**页面级**菜单（`menu_type = 1`）；目录承担分组语义。
- **挂不到一级域的页面菜单不进本页**：`6130701 菜单管理`（`client_type = tenant-admin` 却挂在 `system-admin` 域 `61307` 下）会让左侧分组多出一个 `domainId = null` 的空组（2026-09-18 实机踩到），已在 controller 内以 `resolveDomain` 排除。
- 「权限标识」列取**真实列** `sys_menu.menu_code`（表里没有 `perms` 列）。
- `SysMenuServiceImpl.getUserMegaMenus` 新增**租户级隐藏过滤**（`menuVisibilityService.getHiddenMenuIds`）；隐藏集合为空时行为与改造前**完全一致**。
- 未新增权限码：`sys_permission` 中不存在 `set:*` 通配码，凭空新增而不授予角色会复现「注解齐全但非超管全 403」同症，故本页沿用租户自助配置口径（登录校验 + 会话租户收敛）。

### ③ 数据库变更

**无迁移**。显隐配置复用既有表 `sys_project_config`：

| 键 | 值 | 说明 |
|---|---|---|
| `set:menu-config:hidden` | 隐藏菜单 id 的 JSON 数组 | `MenuVisibilityServiceImpl` 读写；按 `tenant_id` 隔离，`status = 0`；配置损坏时按「全部显示」兜底 |

### ④ 仍存在的缺口（如实登记）

1. 本页**只管显隐**，不提供菜单定义的增删改（`sys_menu` 的增删改仍在平台侧「菜单管理」）；`/menu/*` 4 个端点的权限码种子缺失问题**未在本轮修复**（属系统模块范围）。
2. 全局菜单 `status`（启用 / 停用）在本页为**只读展示**；开关只写租户隐藏集合，不能启停全局菜单。
3. 无拖拽排序、无批量启停 / 批量隐藏、无列行选择批量操作、无导入 / 导出。
4. **无变更历史查询入口**：`@OperationLog` 已写入 `sys_oper_log`，但本页不提供「谁在何时隐藏了哪个菜单」的查看界面。
5. 「图标」列仍为文本展示（不渲染图标组件），沿用 §12-⑪ 的登记。
