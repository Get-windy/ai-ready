## 1. 页面概述

配送渠道 = **运力来源**。企业的配送员有两类（见《配送员管理开发文档》）：**企业员工**（自有运力）与**外部平台**的骑手/配送员（第三方运力）。本页维护这些运力渠道档案，是"外部平台配送员"落地的前提。

### 3.4 业界生产级实践要点

1. **适配器模式落地**：每个渠道实现统一接口（`createOrder / cancelOrder / queryRider / subscribeTrack / callback`），`getAdapter(channelType)` 由**派单流程真实调用**。→ ✅ 第二轮落地：`DispatchService` 经 `ChannelOrderService` 调 `DeliveryAdapter.createOrder`。
2. **幂等与重试**：对外下单必须带业务幂等键（订单号）；失败走指数退避 + 死信队列（见《API监控开发文档》）。→ ✅ 幂等键与指数退避已落地；**死信队列未接**（当前为同步重试 + 台账留痕，人工可在台账页重推）。
3. **回调安全**：验签 + 时间戳防重放；回调日志入库可追溯。→ ✅ 第二轮落地（HMAC-SHA256 + 时间戳容差 + nonce 唯一 + 日志表）。
4. **运力画像**：外部配送员按渠道拉取后统一入 `dms_rider`（`rider_type=PLATFORM_RIDER`，`channel_id`），与自有员工在调度侧同权可比（评分/负载）。→ ✅ 首轮落地。
5. **降级策略**：外部渠道不可用时自动回退到自有运力或转人工，避免派单中断。→ ✅ 第二轮落地（`dms.channel.push.fallback`，默认开启；降级失败给出「无自有运力可派」原因）。

**修复的既有缺陷**（原实现实测）
1. `create()` 硬编码 `tenantId=0` → 新建数据落到租户 0、当前租户不可见；
2. `create()` 强制 `status=0` → 忽略入参，新建后必须手动启用；
3. **假删除**（前端复用 `updateStatus`）→ 改真删除 + 引用保护；
4. `updateStatus` 前端以请求体传参，后端为 `@RequestParam` → 状态切换实际无效；
5. 前端渠道类型字典与后端 `ChannelTypeEnum` 语义冲突（线上/线下 vs 自有员工/外部平台）；
6. `getAdapter()` 全仓无调用者、适配器无连通自检能力。

### 5.2 第二轮实现（2026-09-14：派单接线 / 回调安全 / 凭据加密 / Stub 去伪）

**新增表**（迁移 `V11.350.0__Enhance_Dms_Channel_Adapter_Dispatch.sql`）
- `dms_channel_order`（外部单台账，20 列）：幂等键 `idem_key = taskNo:channelId`（部分唯一索引 `uk_dms_channel_order_idem`）、外部单号、单状态（0 待提交/1 已提交/2 已接单/3 配送中/4 已完成/5 已取消/6 提交失败）、尝试次数、最近失败原因、提交/回撤时间。
- `dms_channel_callback_log`（回调日志，21 列）：验签结果 / 重放标记 / 处理结果（OK/REPLAY/REJECT）/ 处理说明 / 原始报文 / nonce（`(tenant_id, channel_id, nonce)` 部分唯一索引，防重放）。

**后端**（`cn.aiedge.dms.channel`）
- `ChannelCryptoService`：配置 JSON 字段级加密（AES-256-GCM，`ENCv1:` 前缀，随机 IV）；只加密敏感键名（secret/token/password/...），非敏感键（appKey/回调地址）保持明文可读；**fail closed**——加密失败拒绝保存、解密失败拒绝使用，绝不静默降级明文；兼容历史明文（无前缀原样返回）。
- `ChannelService`：`create/update` 落库前加密；`update` 按「同名键掩码保留原值」逐键合并（普通字段仍可改）；新增 `findByCodeAcrossTenants()`（回调无会话场景）与 `decryptConfig()`（供适配器/验签，明文不出服务端）。
- `ChannelOrderService`：`pushOrder()` 幂等（命中台账直接复用原单号，不重复外呼）+ 重试（`dms.channel.push.retry`，指数退避 150→300→600ms）+ 台账落库 + 成功后任务流转「已分配」并写调度审计（含渠道名与外部单号）；`handleCallback()` 解析渠道（跨租户 + 可选 `tenantId`）→ 切临时租户上下文 → nonce 防重放 → 时间戳容差 → HMAC-SHA256 验签 → 台账 upsert（同任务同渠道已有失败台账时**复用该行**，避免撞幂等键唯一索引）→ 任务状态回写（仅允许前进，终态不回写；回写外部配送员**姓名**快照，电话记入调度审计 `reason`——`dms_task` 无 `rider_phone` 列，该字段是 `@TableField(exist=false)` 展示字段）→ 渠道对接状态刷新 → 日志留痕 + 事件外发（`CHANNEL_CALLBACK`）。
