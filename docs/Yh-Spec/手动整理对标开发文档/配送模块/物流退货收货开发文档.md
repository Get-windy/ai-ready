# 物流退货收货开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`dispatch/return-receive`
> 对标菜单：**配发收 → 收货业务 → 物流退货收货**（实测 menuId `300401`，billType `2734`）
> 数据来源：**Playwright 实测抓取（2026-09-12）**——双 Tab 分别抓列配置弹窗 + 页面配置弹窗 + 页面结构 + 截图。
> 通用规范见《对标开发技术参考文档》第 4、5 章，本文不重复。

## 1. 页面概述

- **列表操作页（入口直达型）**：实测点击「物流退货收货」打开的是 **「销售退货申请-历史」**——即本页是**销售退货申请的历史视图**，跟踪退货的订货/已收/未收进度，并可「新增」退货申请。
- **双 Tab**：`按单据`（表头默认 21 列）/ `按明细`（表头默认 23 列），两 Tab 各有独立列配置与页面配置。
- 落地时必须**复用《销售退货申请》的视图组件**，不重复造页面。
- 截图：`tool-results/ql361/pages/配发收__收货业务__物流退货收货.png`

## 4. 业务规范

- **本页 = 销售退货申请的历史视图**（销售退货流程的入口与跟踪页），跟踪口径为**订货数量 / 已收数量 / 未收数量**（按单据）与**退货数量 / 已收数量 / 未收数量**（按明细）。
- **新增**：可从本页「新增」按钮进入退货申请表单（生成销售退货申请单）。
- **状态**：单据状态（待审核/已审核等）+ 结算状态分别跟踪。
- **仓储口径**：仓库、退货数量、（明细）单位/换算关系/包装；收货完成后进入销售退货单入库（见《销售退货单开发文档》）。
- **物流口径**：物流公司、运单号（隐藏列）、配送方式——本页亦称「物流退货收货」，即退货经物流回流后的收货确认。
- **商品扩展列**：按明细含 规格/型号/产地/货号/条码/大中小包装/换算关系等商品档案列（多数隐藏）。
- **自定义字段**：单据自定义 1–5、表体自定义 6–10（含往来单位/职员/部门类型）。

## 5. 实现差异说明（本系统现状）

| 项 | 对标实测 | 本系统现状 | 差距 |
|----|---------|-----------|------|
| 页面形态 | 销售退货申请-历史（双 Tab 直达） | `views/dispatch/return-receive/index.vue` 独立列表（78 行） | 应对齐为复用《销售退货申请》历史视图的直达入口 |
| Tab | 按单据 / 按明细 | 单视图 | 补双 Tab + 各自列配置（`storage-key` 按视图拼后缀） |
| 列 | 按单据 47（默认 20）/ 按明细 62（默认 22） | 少量占位列 | 按第 3 章重建 |
| 查询条件 | 27 / 16 | 少量 | 按第 2 章补齐 |
| 功能按钮 | 按单据 6 / 按明细 5 | 打印、导出 | 补新增、批量打印、F8 |
| 新增入口 | 「新增」进入退货申请表单 | 无 | 接《销售退货申请》表单页 |
