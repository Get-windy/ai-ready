## 1. 页面概述

- **参数配置页**：维护 DMS 配送模块的运行参数（键值对），供调度、时效、费用、地图、推送等策略读取。
- 数据落地：`dms_config`（实体 `DmsConfig`：`configKey` / `configValue` / `configDesc` / `scope`）。

## 2. 本系统现状（改造前实测 · 2026-09-12，保留作缺陷证据）

> ⚠️ 本节记录**改造前**现状（6 列 KV 编辑、纯字符串值、前端过滤、无元数据/无审计）；当前实现见 §7。

### 2.1 查询条件

| 查询条件 | 控件 | 说明 |
|---------|------|------|
| 关键字 | 输入框 | 配置键 / 描述，⚠️ **前端过滤**（`configApi.list()` 全量拉取后在内存过滤） |

### 2.2 数据表格列（6 列）

配置键、配置值（等宽字体展示）、描述、作用域、更新时间、操作（编辑）。

### 2.3 编辑弹窗「编辑配送参数」

| 字段 | 控件 | 可编辑 |
|------|------|:-----:|
| 配置键 | 输入框 | ❌ 禁用 |
| 配置值 | 文本域（3 行，必填） | ✅ |
| 描述 | 输入框 | ❌ 禁用 |
| 作用域 | 输入框 | ❌ 禁用 |

保存：`configApi.update(configKey, { configValue })` → 成功提示 + 刷新。

### 2.4 现状问题

- 参数**无分组、无类型**：所有值都是字符串文本域，数字/开关/JSON 均手输，易配错。
- **无分页**（`/dms/config/list` 返回全量）、无多条件查询。
- **无元数据**：默认值、取值范围、单位、是否可改、影响面均不可见。
- **无变更审计**：改了什么、谁改的、改前改后无记录。
- 参数键散落在代码中（`DmsConstants`），页面与消费方无契约。

## 3. 金标准目标设计

### 3.1 参数元数据（配置项注册表）

每个参数以**元数据驱动**渲染与校验，建议字段：

| 元数据 | 说明 | 示例 |
|--------|------|------|
| `configKey` | 参数键 | `dispatch.auto.strategy` |
| `group` | 分组 | 派单策略 / 时效 / 费用 / 地图 / 推送 / 签收 / 风控 |
| `valueType` | 类型 | `NUMBER` / `TEXT` / `BOOLEAN` / `ENUM` / `JSON` / `TIME_RANGE` |
| `configValue` | 当前值 | `2` |
| `defaultValue` | 默认值 | `1` |
| `min` / `max` / `unit` | 取值范围与单位 | `0` / `100` / `%` |
| `enumOptions` | 枚举项 | `[{label:'按负载',value:1},...]` |
| `editable` | 是否允许页面修改 | `true` |
| `effect` | 生效方式 | 热生效 / 需重启 |
| `configDesc` | 描述 | 自动派单策略 |
| `scope` | 作用域 | 租户 / 全局 |

**页面按 `valueType` 渲染控件**：数字 → `a-input-number`（带 min/max/单位）；布尔 → `a-switch`；枚举 → `a-select`；JSON → 带校验的代码编辑器；时间范围 → 时间选择器。

### 3.2 页面结构（金标准）

```
工具栏：页面配置 | 刷新 | 导出 | 批量保存 | 恢复默认
├─ 左：参数分组树（派单策略/时效/费用/地图/推送/签收/风控）
└─ 右：参数表（BillDetailTable，序号列齿轮 + 列配置）
        列：参数名 | 参数键 | 当前值(类型控件) | 默认值 | 取值/单位 | 生效方式 | 描述 | 更新时间 | 操作(保存/恢复默认)
```

- 骨架：`CategoryListLayout`（左侧分组成员树）+ `BillTableList`/`BillDetailTable`（`storage-key` = `dms-config-params-columns`）。
- 支持**行内编辑**（就地保存）或**批量编辑后统一保存**（业界配置中心常见模式）。
- `PageConfigPanel`（查询条件/功能按钮）。

### 3.3 查询条件（页面配置）

参数分组、参数键/名称（模糊）、参数类型、作用域、生效方式、是否可改、更新时间范围。

### 3.4 功能按钮（页面配置）

刷新、批量保存、恢复默认（单行/全组）、导出参数清单、导入参数（JSON）、变更历史。

## 7. 本系统落地实现（✅ 2026-09-13）

> **定位**：本页是 DMS 运行参数的**唯一可写入口**（《配送配置》80890 已收敛为只读业务域总览），
> 口径仍为「**全局默认（tenant_id=0）+ 租户覆盖**」，保存即热生效。

### 7.1 后端接口（增量，复用既有读写/审计/热生效口径）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/dms/config/page` | 参数中心**分页 + 多条件**（关键词/分组/类型/生效方式/仅看已配置/**作用域（租户覆盖·继承全局）/是否可改/更新时间区间**）；返回行 = 合并值 + 元数据（参数名/类型/默认值/范围/单位/生效方式/是否敏感/是否租户覆盖） |
| GET | `/api/dms/config/meta` | 元数据 + **分组树计数**（`{groups:[{key,text,count}], items:[DmsConfigMeta…]}`），驱动前端按类型渲染控件 |
| PUT | `/api/dms/config/batch` | **批量保存（事务）**：逐项做类型/范围/枚举/JSON/时间范围校验；敏感键留空=不修改；任一项非法则整体拒绝 |
| POST | `/api/dms/config/{key}/reset` | **恢复默认**（依据注册表 default 值；未登记元数据的键拒绝） |
| GET | `/api/dms/config/export` | **导出参数集（JSON）**：按查询条件过滤，结构 `{schema,exportedAt,tenantId,count,items[]}`；**敏感键不导出明文**（值置空 + `secret/configured` 标记）；见 §7.6 |
| POST | `/api/dms/config/import` | **导入参数集（JSON）**：`mode=PREVIEW` 预览差异（不落库/不记审计/不发事件）/ `APPLY` 落库（事务 + 逐项校验 + `IMPORT` 审计）；**存在失败项整体拒绝**；敏感键留空或掩码=跳过；`overwrite=false` 时已覆盖项跳过；见 §7.6 |
| GET/PUT/DELETE | `/api/dms/config/{key}`、`/{key}/history`、`/{key}/rollback`、`/list` | 既有能力（前一轮完成），本次仅**修默认租户口径**（见 7.3） |

### 7.2 元数据注册表（`DmsConfigMetaRegistry`）

9 个分组、**47 个**已登记键，与代码同源：**派单策略(10，含《智能调度》区域分包严格模式)** / **配送跟踪(6)** / **签收(1)** / **结算与收款(9，含收款管理资金安全键)** / **实名与核验(8)** / **能耗与补能(3)** / **地图与位置服务(5，含 4 个敏感键)** / 其他（未登记键动态归入，按 TEXT 处理）。
类型覆盖 `NUMBER / TEXT / BOOLEAN / ENUM / JSON / TIME_RANGE`；`effect=HOT` 表示保存即热生效。

> 键数随各业务域增量增长（如《智能调度》新增 `dms.dispatch.area.strict`）；**新增配置键必须同步登记**，否则页面退化为纯文本、且无法恢复默认。E2E 的分组数量断言与注册表对齐、不硬编码。

### 7.3 本轮修复的真实缺陷

| # | 缺陷 | 现象 | 修复 |
|---|------|------|------|
| 1 | **参数中心接口 `tenantId` 默认 0** | 页面（登录租户=1）执行「保存 / 恢复默认 / 查历史 / 回滚」时写到/读的是**全局行**，页面值看起来「改了不变」、历史查询恒 0 条 | 新增 `effectiveTenant()`：显式传入优先，**未传则取当前登录租户**（无上下文回落 0）；控制器 `tenantId` 改为 `required=false` |
| 2 | 敏感键回写风险 | 页面拿到的是掩码，直接保存会把 `****` 写库 | 批量保存中敏感键**留空=不修改**（显式跳过），页面提示「已配置（留空=不修改）」 |

### 7.5 参数集导入 / 导出（JSON，二轮补齐）

> 对应 §3.4「导出参数清单 / 导入参数（JSON）」与 §3.5 `GET /config/export`、`POST /config/import`；用于**跨环境/跨租户迁移参数**（如测试 → 生产预置）。

| 项 | 规则 |
|----|------|
| 导出物结构 | `{schema:"dms-config-export/v1", exportedAt, tenantId, count, items:[{configKey,name,group,valueType,unit,configValue,secret,configured,defaultValue}]}`，**可直接作为导入请求体回灌** |
| 导出范围 | 按当前筛选条件（分组/类型/关键词/作用域…）或全部；敏感键**不导出明文**（`configValue` 置空 + `secret=true`） |
| 导入模式 | `PREVIEW`：只返回差异（`preview[]` + `failed[]`），**不写库、不记审计、不发事件**；`APPLY`：逐项落库（`IMPORT` 审计 + 热生效事件 + Redis 广播） |
| 逐项校验 | 键必须已存在（不支持导入新增键，避免"影子参数"）、参数可改、类型/范围/枚举/JSON/时间范围；失败项**逐项返回原因** |
| 事务语义 | 存在任一失败项 → **APPLY 整体拒绝**（与批量保存一致，不落任何一项）；空 item 列表直接拒绝 |
| 敏感键 | 值空或为掩码（含 `*`）→ 跳过（不修改），**杜绝掩码写库** |
| 幂等 | 导出物原样回灌为零变更（值相同 → `SAME`、敏感键 → `SKIP`）；`overwrite=false` 时已有租户覆盖值 → 跳过 |
| 审计 | 落库路径复用 `applyValue(..., changeType="IMPORT")`，变更历史「变更类型」显示为**导入** |

### 7.6 验收

- 脚本：`tools/e2e-dms-config-params.cjs`（接口 + UI 共 **86 项**，全绿）；种子 `tools/e2e-dms-config-params-user.sql`（账号 `e2e_config` + 5 个用例键重置为已知值，含 1 个敏感键明文用于脱敏断言）。
- 覆盖的关键断言：元数据分组树与计数、NUMBER/ENUM 元数据字段、分页多条件（分组/类型/关键词/仅已配置/翻页/**是否可改/作用域/更新时间区间**）、**敏感键脱敏且留空不修改**、**四类类型校验**（数字越界/非数字/非法枚举/非法布尔/非法时间范围）、**批量事务**（任一项非法整体拒绝）、**恢复默认落在租户覆盖行**（回归项）、变更历史与**回滚**、**导出结构/敏感键无明文/按分组与关键词过滤**、**导入预览不落库**、**逐项失败原因（越界/未登记键）**、**导入 APPLY 生效 + IMPORT 审计**、**含非法项整体拒绝**、**overwrite=false 跳过**、**导出物幂等回灌**、空导入拒绝、UI 导入导出全流程（下载/预览/确认导入/页面配置）、测试后还原参数。
- 截图：`tool-results/dms-config-params/`（ui-list / ui-save-confirm / ui-history / ui-colconfig / ui-group / **ui-import-preview**）。
- 运行方式：验收后端 `java -jar <fat jar> --server.port=<空闲端口>`；前端独立 `vite --port=<空闲端口>`，脚本内 `page.route` 把 `/api` 转发到验收后端（本次实测 `ERP_PORT=5673 FE_URL=http://localhost:5691`）。

### 遗留（非阻塞）

- **导入仅支持已有参数键**：不支持通过导入新建参数（避免产生无元数据、无消费方的"影子参数"）；如需新增参数，先在 `DmsConfigMetaRegistry` 登记 + 迁移预置默认值。
- **`RESTART` 生效方式**：元数据保留了 `effect` 字段并已在页面展示，但当前 42 个键全为 `HOT`；若后续加入需重启的项，需在消费方实现重启检测。
- **配置灰度（按区域）**：`scope` 目前只有 TENANT/global 两级，§3.6.5 的「按区域灰度」未建模。
