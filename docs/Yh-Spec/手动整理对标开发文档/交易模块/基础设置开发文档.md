# 基础设置开发文档

> **文档类型：** 页面对标复刻（配置/表单型页面）
> **对标系统：** ql361（来肯企汇，`22stable.ql361.com`）商城模块
> **对标来源：** 顶部「商城」菜单 → 「商城设置」组 → 「基础设置」。**来源=对标实测抓取 2026-09-07**
> **定位：** 按金标准结构编写；商城基础信息/显示/水印/访问/小程序/消息全局配置中心。即 XSMK 商城「商城设置 → 基础设置」。

## 页面概述

基础设置是**商城全局基础配置中心**：配置商城 LOGO、名称、主营类目、营业资质、联系方式、退货地址、商品详情/列表显示字段、图片水印、访问域名、绑定小程序、消息订阅等。**单入口，配置/表单型页面**（无数据表列表）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 基础设置 | `mall/basic-config` | 配置/表单页（左侧 6 子项导航 + 右侧配置表单 + 底部「保存」） |

单入口：商城 → 商城设置 → 基础设置。

- 实测实据：页面左侧 **6 个子项导航**：基础设置 / 显示设置 / 图片水印 / 访问设置 / 绑定小程序 / 消息设置。右侧为当前子项配置表单，底部「保存」按钮；右侧嵌套 iframe 为商城首页预览。
- ⚠️ 说明：图片类控件（商城LOGO/公众号二维码/营业资质）在未上传时显示占位图（实测截图注：「商城LOGO已损坏」）。

### 配置功能说明
- **列配置/页面配置弹窗**：**无**。配置/表单型页面，无数据表列配置 `.icon-shezhi2`，无顶部「配置」齿轮（无查询条件/功能按钮 Tab），按其真实设置项清单改写。
- ⚠️ **当前实现说明**：本页为**单表单 `PageContainer` + antdv `a-form`**（非金标准左项导航+多子页），见「实现差异说明 → 待完善」。

## 业务规范说明

- **商城主线**：基础设置驱动商城买家端全局表现——商城名称/LOGO/介绍（分享与展示）、营业资质（合规公示）、联系方式/退货地址（交易服务）、显示字段（商品详情/列表展示列）、图片水印（商品图防盗）、访问设置（微商城入口与授权域名、默认仓库）、绑定小程序（小程序商城）、消息设置（订阅消息推送）。
- **营业资质合规**：按《电商法》第十五、十六条，营业执照与经营许可证需在店铺首页显著位置持续公示；食品行业需公示食品经营许可证。
- **显示字段**：商品详情页显示字段（规格/型号/货号/产地/品牌/条码/保质期/生产日期/重量/体积）与商品列表页显示字段（批次号）控制买家端展示哪些商品属性。
- **访问设置**：公众号网页授权域名决定微信登录/支付可用的域名；网店仓库=公众号跳转微商城默认发货仓库。
- **消息设置**：系统消息订阅（注册成功/订单/退换/退款/物流/促销等）控制给买家推送的通知类型。

## 实现差异说明

**实现文件**：
- 前端：`frontend/apps/pc-admin/src/views/mall/basic-config/index.vue`
- API：`src/api/erp/mall.ts`（`shopConfigApi`：`GET/PUT /erp/mall/admin/config`）
- 后端：`ShopConfig` 实体（`/erp/mall/admin/config`）

### 页面对齐（已建成：单表单 `PageContainer` + antdv `a-form`）
- **单表单（5 字段）**：商城状态（status，启用/停用）、开放注册（enableRegister）、注册自动审核（enableAutoAudit）、最小起订金额（minOrderAmount）、支付方式（paymentMethods：ALIPAY/WECHAT/UNIONPAY/BANK/CASH）。**未对齐金标准 6 子项/多分组**。
- **无左侧子项导航**：当前为单卡片表单；金标准为基础设置/显示设置/图片水印/访问设置/绑定小程序/消息设置 6 子项。
- **字段缺失**：无 商城LOGO/公众号二维码/主营类目/营业资质/商城介绍/联系方式/退货地址/显示设置/水印/访问设置/小程序/消息设置 等。
- **数据模型**：3 个页面（基础设置/店铺设置/运费设置）共用**同一个 `ShopConfig` 单行实体**，各自只读写部分字段（保存时合并，避免互相覆盖）。

## 业界对标 / 跨模块 / 最终裁决

- **业界对标**：商城「基础设置」为全局配置中心，同类（零售通/来肯/订货宝）均以「多子项配置 + 合规资质公示 + 消息订阅」组织；核心差异是 ql361 将商城展示（LOGO/名称/介绍）与业务规则（显示字段/水印/访问/小程序/消息）统一放在「基础设置」，而本系统拆分为「基础设置/店铺设置/运费设置」三页共用 `ShopConfig` 单行。
- **跨模块**：绑定小程序/消息设置/访问设置联动「支付配置」（支付配置为独立 `PaymentConfig` 视图，含微信/支付宝/聚合/京东/农行/建行/微企付等「支付方式×场景」矩阵）；网店仓库联动 ERP 仓库主数据；营业资质合规披露联动商城店铺首页装修。
- **最终裁决**：本页不存在数据表，**无列/页面配置弹窗**（配置/表单型）。金标准应对齐「6 子项配置」结构；当前单表单为占位/简化实现，需按上表补齐而非复用查询型金标准组件。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
