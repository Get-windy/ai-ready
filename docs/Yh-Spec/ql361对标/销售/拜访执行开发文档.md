# 拜访执行开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`sales/visit/execute`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **地图页**：按日期 + 职员查询外勤行动轨迹与实时定位，外勤拜访三步流程（1.拜访规划 → 2.拜访执行 → 3.拜访检视）的第二步。
- 页面结构：查询区 + 全幅电子地图（无数据表格、无底部分页）；子标签「职员轨迹（本页）/ 职员定位」。

## 2. 页面配置

### 查询条件（抓取 JSON filterLabels 实据，2 项）

- 日期\*（必填，单日选择，默认当天）
- 职员\*（必填，弹窗选择）

### 功能按钮（抓取 JSON buttons 实据）

查询（无新增/打印/导出/刷新等工具按钮）

### 打印配置

无。

## 3. 数据表格列配置

无（本页为地图页，抓取 JSON columns 为空数组）；「职员定位」子标签的页面结构（实时定位点位地图）抓取未覆盖，待复核。

## 4. 业务规范

- 日期与职员均必填（标红\*），两者确定后查询该职员当日外勤轨迹。
- 轨迹数据来源为移动端（外勤 APP）上报的 GPS 点位，需有定位上报机制支撑；本系统技术栈已定高德地图 Web API（见根 AGENTS.md）。
- 外勤三步流程：1.拜访规划（定计划）→ 2.拜访执行（本页，查轨迹/定位）→ 3.拜访检视（统计完成率）。
- 本页轨迹数据是拜访检视「异常拜访次数」等统计的佐证数据来源（推断，具体口径待复核）；拜访执行依赖移动端签到/定位上报，与 PDA/移动端签到功能联动。
