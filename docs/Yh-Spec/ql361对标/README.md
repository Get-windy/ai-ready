## 2. 每个页面怎么开发（标准七步）

以「销售出库单」为例，任何页面都按这个流程走：

1. **读对标文档**：打开 `ql361对标/<域>/<页面名>开发文档.md`，通读 Tab 结构 / 筛选区 / 按钮 / 表格默认列 / 列配置弹窗全量列 / 表单字段 / 业务规则。文档数据全部来自真实抓取，篇内注明了 JSON 剔除拼接串的口径
2. **看现状差距**：12 个重点页面直接查《字段级对比附录》对应章节（已给出我方字段的 `文件:行号` 和 ❌ 缺失清单）；其余页面自己按同样口径核对：打开我方 `frontend/apps/pc-admin/src/views/` 下对应 `.vue`，逐字段比对
3. **四问流程**（缺失判定的铁律，R6 事故根源就是没走这步）：
   - Q1 真缺失，还是换名/换位置已存在？（grep 我方源码 + `\d+ 表名` 查真实列）
   - Q2 有没有可复用的组件/接口？（ARReportPage / BillFormPage / BillTableList / useBasicForm / DocCenterLayout / SearchFieldsGrid / useColumnConfig）
   - Q3 新增内容的落点在哪？（前端 views 对应域目录；后端对应业务模块，**禁止再往 core-api 堆业务控制器**）
   - Q4 怎么补？（前端组件编排 / 后端实体+迁移+端点）
4. **实现**：表单页对齐「金标准 8 要素」（见第 4 章）；列表/报表页对齐 ARReportPage 模式（查询区/统计卡/表格列配置/导出/空态）。后端改动遵守：新表补列走 Flyway（`backend/core/api/core-api/src/main/resources/db/migration`，编号从 V11.36.0 起接续）、status=1 启用/0 停用、审计五字段、租户隔离、主键策略与所属模块基类一致（营销/采购用 `ASSIGN_ID` 雪花，勿混用 `AUTO`——R6 支付方式 400 事故的根因）
5. **自测**：按第 5 章「开发自测清单」逐项打勾，**每个写端点至少真实调用一次**（curl 带数据，DB 查终态）
6. **更新文档**：实现与对标文档有出入时，在对应开发文档末尾补「实现差异说明」；抓取了新证据的，消除文档中的「待复核/近似口径」标记
7. **交付**：按第 5 章「交付 6 件套」提交，缺一不收

## 3. 文档没写全/存疑时：四级溯源（按顺序用）

**铁律：任何「文档里没写清楚」的字段，都必须追溯到真实证据后才能开发，禁止发明字段名**（R6 报价转订单 500 事故的根因就是发明了不存在的 `source_type` 列）。

### 一级：查原始抓取（最快，覆盖全部 142 页）

```
tool-results/ql361/pages/<域>__<组>__<页面>.json   # 结构数据
tool-results/ql361/pages/<域>__<组>__<页面>.png    # 全屏截图
```

JSON 字段含义：`url` `title` `tabs`（页内标签页）`filters`/`filterLabels`（查询条件）`buttons`（操作按钮）`columns`（表格默认列）`_desktop`（桌面标签栏信息，含快捷键如「保存草稿 Ctrl+S」）`bodyPreview`。截图用于核对布局、分组表头、按钮位置。

### 二级：查抓取日志与探针

`tool-results/ql361/crawl*.log` 记录每页抓取过程；`colconfig_probe*.js` 是列配置弹窗的提取探针，补抓「列配置」时直接复用。

### 三级：重新抓取（文档标注「待复核/近似口径」时必须执行）

对标文档中凡标注「待复核」「近似口径」「表格列待补」的页面（《对比附录》各章节已显著标注），按以下 SOP 补抓：

1. 用浏览器工具打开 https://www.ql361.com/Account/Logon，输入账号密码登录
2. 在桌面按「域 → 分组 → 页面」模拟点击目标菜单，等待标签页加载完成
3. 逐项提取：页内 Tab 标签 → 查询区字段 → 工具栏按钮 → 表格默认列 → **打开「页面设置/数据表表格配置」弹窗提取全量可配置列** → 有表单的打开新增页提取表单字段
4. 落盘：JSON 存 `tool-results/ql361/pages/<域>__<组>__<页面>.json`（双下划线命名，与现有 287 个文件一致），全屏截图存同名 `.png`
5. 回到对应开发文档，用新证据重写对应章节，删除「待复核」标记，在《对比附录》重跑该页对齐度

### 四级：在线人工核对

涉及交互细节（弹窗行为、联动规则、校验提示）抓取无法覆盖时，人工登录目标系统操作取证，截图存档到 `docs/Yh-Spec/对标页面截图/<日期>/`，并在开发文档中引用。

### 4.3 域内开发顺序原则

1. **主数据先行**：档案页（商品/客户/供应商/账户）→ 单据页 → 查询报表页（单据跑通后报表才有真数据可验）
2. **主干链优先**：订单 → 出/入库 → 收付款 → 凭证，打通一条完整业务链再铺广度
3. **表单页对齐金标准 8 要素**（所有表单页的验收标尺）：
   头部档案区（全选择器）→ 明细网格（行增删/合计联动）→ 底部功能区（收款/物流/备注/制单信息）→ 金额面板（实时计算+后端复核）→ 操作链（草稿→提交→审核→红冲→打印，含快捷键 Ctrl+S / Ctrl+Enter / F8）→ 配置弹窗（页面配置/录单默认值/打印设置）→ 双入口（菜单直进表单 + [历史] 进列表）→ 后端闭环（状态机+单号+事务+库存/财务联动+审计+租户）
   参照实现：`frontend/apps/pc-admin/src/views/erp/sale/form.vue`（销售订单，已验证的生产级金标准）

## 5. 怎么验收

### 5.1 开发自测清单（报「完成」前必须全部打勾）

**页面层**：
- [ ] 对标文档中该页的全部默认列/筛选/按钮已实现或标注差异原因
- [ ] 表单页金标准 8 要素逐项齐
- [ ] 档案字段全部是选择器（可搜可新增），无手输文本
- [ ] 无 mock、无假数据、无「开发中」占位

**接口层（R6 最重要教训：每个写端点必须真实跑一次）**：
- [ ] 页面每个操作按钮都 grep 过后端端点，真实存在
- [ ] **每个写端点 curl 带数据实测一次**：返回 200 且 `psql` 查库有行、字段值正确
- [ ] 状态翻转类操作（提交/审核/转换）验证**失败时事务回滚**（构造一次异常用例，DB 无脏数据）

**基线层**：
- [ ] `vue-tsc --noEmit` 全仓 0 错误
- [ ] `mvn` 编译绿；涉及多模块的整链 install + exec.jar 重启验证
- [ ] 新迁移脚本已手动执行且 `flyway_schema_history` 有 success=t 记录

### 5.2 交付 6 件套（缺一不收，R4 起强制执行）

1. 构建日志（mvn install 成功尾部）
2. Flyway 记录查询（新迁移 success=t）
3. 启动日志（端口监听成功）
4. 新端点 curl 实测输出（**带数据的**，不是空壳 200）
5. vue-tsc 输出（error 计数 = 0）
6. 本批改动文件清单（git status）

### 5.3 PM 复查流程（每批次交付后执行）

1. 结构检查：重跑 `tool-results/audit_pages.py`（菜单→组件可达性、断点复发）
2. 基线检查：vue-tsc = 0、mvn 编译绿
3. E2E 抽测：每页至少 1 条业务场景 curl 实测（登录 → 操作 → DB 终态核对）
4. 对标打勾：表单页按金标准 8 要素逐项核；其余页按对标开发文档逐字段核
5. 输出批次完成度报告（通过项/总项 + 不通过项返工清单），样式参照 `docs/acceptance-report-2026-07-23-r6.md`

### 5.4 返工规则

- 不通过项打回后，修复人**必须先自己跑通一遍**（启动 → curl → DB 查询）再报完成——R2~R6 连续五轮失败的共同根因就是「报修复但从未执行过被修复的功能」
- 同一缺陷连续两轮复验不通过，升级为阻塞项，暂停该域新页面开发，集中清零

## 6. 红线（任一触犯即返工，无例外）

1. mock / 假数据 / 造假默认值
2. 表单页档案字段手输文本（必须选择器）
3. 金额由前端计算后直接落库、未经后端复核
4. 新表/补列未走 Flyway 迁移（或未手动执行 + 登记 flyway_schema_history）
5. 发明不存在的字段名/列名/端点（缺失判定未走四问流程）
6. 同一仓库混用主键策略（新实体主键对齐所属模块基类，推荐 `ASSIGN_ID`）
7. 字符串状态字段（status 一律 0/1 整数，见 AGENTS.md 状态字段规范）
8. vue-tsc 新增错误、mvn 编译破坏
