## 4. 业务规范

- **本页 = 采购收货处理工作台**：跟踪采购订货的**订货数量 / 已收货数量 / 待收货数量**（按明细）与**应收数量 / 未收数量**（按单据）。
- **批量收货**：工具栏「批量收货」对多选单据执行收货；收货后生成**采购入库单**（见《采购入库单开发文档》）。
- **状态**：单据状态（如 待收货 / 部分收货 / 已收货）+ 结算状态分列跟踪。
- **往来单位口径**：往来单位 + 结算单位（含隐藏的往来编号/结算单位编号）——采购单据可采用不同结算主体。
- **数量列口径差异**：按单据默认显示「应收数量/未收数量」（隐藏「已收数量」）；按明细默认显示「订货数量/已收货数量/待收货数量」——两 Tab 的收发货数量命名不同，落地时需分别映射。
- **商品扩展列**：按明细含 货号/条码/规格/型号/产地/品牌/大中小包装/换算关系/优惠折扣/优惠后单价金额（多数隐藏）。
- **预计收货日期**：按单据默认显示，用于收货排程。

### 实现要点

- **不重复建页面/接口**：数据源复用既有 `purchaseDocQueryApi.docPage/detailPage`（`/api/erp/purchase/order/doc-query/page`、`/detail-query/page`），
  本页只做「工作台化」（双 Tab + 收货动作 + 配置弹窗），符合「页面组件优先复用、功能不重复开发」。
- **单据状态列 = 收货进度**（对标 §4「单据状态（如 待收货/部分收货/已收货）」）：
  `已收 ≤ 0 → 待收货`；`已收 ≥ 应收 → 已收货`；否则 `部分收货`。原始订单状态（0 草稿…6 已完成）另置**默认隐藏**列「订单状态」便于对照。
- **结算状态列**：按 `已结金额(settledAmount) / 本单金额(billAmount)` 推导（未结算 / 部分结算 / 已结算）——对标有该列而本系统采购订单无独立结算状态列，取值口径见 §6.3。
- **批量收货**：按选中单据逐个调 `POST /api/erp/purchase/inbound/from-order/{orderId}`，失败逐条回报；已收满的订单前端先跳过（后端也只带出「待收数量 > 0」的明细）。

### 6.2 收货闭环（原实现是「空头入库单」，已修正）

原 `createFromOrder` 只创建**入库单头**（无明细、无待收数量），工作台点完「收货」得到一张没有任何商品行的草稿单，必须人工再录一遍——这不是收货。本次补齐为**真实收货**：

1. **带出单据头快照**：订单号 / 供应商（订单伙伴快照表，与《采购单据查询》同口径）/ 仓库 / 经手人 / 部门；
2. **带出待收明细**：仅取 `订货数量 − 已收数量 > 0` 的行，入库数量口径 = 本次待收数量，明细挂 `orderItemId` 回链；
3. **后续仍走既有链路**：入库单落 `DRAFT`，在《采购入库单》确认收货 / 质检 / 记账，库存写入复用既有 `InventoryChangeEvent`（不重复实现）；
4. 已全部收完的订单 → 不产生待收明细（前端也会跳过并提示），避免生成空入库单。

> ⚠️ **已收数量口径踩坑**：`erp_purchase_order_item` 同时存在 `received_quantity` 与 `received_quantity_detail` 两列，后者**全项目无任何写入方（历史死列）**。
> 《采购明细查询》读的是 `received_quantity`，故收货时也必须用该列，否则待收数量恒等于订货数量（会带出全量、且与列表显示不一致）。

### 6.3 口径差异与推导说明（不发明字段）

| 对标列/条件 | 本系统处理 | 原因 |
|------|------|------|
| 「结算单位 / 结算单位编号」（按单据，默认显示） | **不落地** | 本系统采购订单不区分「往来单位 / 结算单位」（无该字段），采购结算主体即供应商。列出会造出长期空白列，故省略（按单据 28 → 26 列、默认 11 → 10 列） |
| 「结算状态」 | **推导**：`settledAmount / billAmount` → 未结算 / 部分结算 / 已结算 | 采购订单无独立结算状态列；结算明细在 `erp_purchase_order_settlement`（1:1），如需精确口径可后续接该表（列为 P2 待完善） |
| 「单据状态」 | **推导**：收货进度（待收货 / 部分收货 / 已收货）+ 隐藏「订单状态」原值列 | 对齐对标 §4 的收货进度语义，同时保留订单自身状态可追溯 |
| 查询条件「单据状态」 | 过滤**订单原始状态**（0 草稿…6 已完成） | 后端 `doc-query` 的 `status` 即订单状态；收货进度是派生值，不入查询（避免误导） |

**回归断言（已固化，防复发）**

- 按单据默认表头 **精确集合**（10 数据列 + 操作）；按明细默认表头 **精确集合**（16 数据列 + 操作，覆盖「切 Tab 不串列」）。
- 「自定义字段1(数字)」开启后查询区为**区间控件**（最小/最大 2 输入）且区间查询真实过滤（仅命中 E2E-CGD-0001）。
- 打印次数回写：`batch-print` 以字符串雪花 ID 调用 + 递增 1。
- 按明细勾选明细行后「批量收货」带选中计数，取消后恢复空态；F8 打开打印弹窗；批量收货成功后勾选态清除（按钮回到空态）。

> 缺陷 1、5 属**跨页面通用问题**（消一处、全站受益）：前者影响所有「storage-key 随 Tab 切换」的多视图页面；后者是「页面漏传 prop 时静默回落组件内置销售订单默认」的陷阱，其它页面接线时需注意同名 prop 必须显式传入。
