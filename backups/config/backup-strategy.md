# AI-Ready 测试环境数据库备份与恢复策略

## 1. 备份策略概述

### 1.1 备份目标
- 确保测试环境数据安全，支持灾难恢复
- 提供数据完整性验证机制
- 支持时间点恢复（Point-in-Time Recovery, PITR）
- 最小化备份对测试环境性能的影响

### 1.2 备份范围
1. **PostgreSQL数据库**：所有业务数据库
2. **Redis缓存数据**：缓存数据库持久化
3. **配置文件**：应用配置、环境变量
4. **日志文件**：应用日志、系统日志
5. **文件系统**：重要的静态文件和上传文件

## 2. 备份策略详细设计

### 2.1 PostgreSQL数据库备份策略

#### 2.1.1 全量备份（Full Backup）
- **频率**：每日一次
- **时间**：凌晨 02:00（低负载时段）
- **保留周期**：7天
- **备份方法**：`pg_dump` + `pg_dumpall`
- **压缩**：gzip 压缩，压缩率约 70%

#### 2.1.2 增量备份（Incremental Backup）
- **频率**：每4小时一次
- **时间**：00:00, 04:00, 08:00, 12:00, 16:00, 20:00
- **保留周期**：30天
- **备份方法**：WAL日志归档 + 增量备份

#### 2.1.3 日志备份（Log Backup）
- **频率**：实时/每小时
- **方法**：WAL日志归档 + 传输到备份存储
- **保留周期**：48小时（用于PITR）

### 2.2 Redis数据备份策略

#### 2.2.1 RDB持久化
- **频率**：每小时一次
- **触发条件**：数据集变化超过1000次写操作
- **保留周期**：7天
- **备份方法**：RDB快照

#### 2.2.2 AOF持久化
- **频率**：每秒钟fsync
- **策略**：appendonly yes, appendfsync everysec
- **保留周期**：30天（压缩归档）

### 2.3 文件系统备份策略

#### 2.3.1 应用配置文件
- **频率**：每日一次（随数据库全量备份）
- **备份内容**：
  - 应用配置文件（*.yml, *.properties）
  - 环境配置文件（.env, .env.*）
  - 密钥文件（*.pem, *.key）

#### 2.3.2 日志文件
- **频率**：每日滚动备份
- **保留周期**：30天
- **压缩**：gzip压缩存储

## 3. 备份存储策略

### 3.1 存储层次
```
┌─────────────────────────────────────┐
│          本地备份存储               │
│  ├── 热备份（最近7天）             │
│  │   ├── PostgreSQL全量+增量       │
│  │   ├── Redis RDB快照             │
│  │   └── 配置文件                  │
│  └── 冷备份（7-30天）              │
│      ├── 压缩归档                  │
│      └── 离线存储                  │
└─────────────────────────────────────┘
```

### 3.2 存储容量规划
| 数据类型       | 每日增量 | 7天保留 | 30天保留 | 压缩后 |
|----------------|----------|---------|----------|--------|
| PostgreSQL全量 | 500MB    | 3.5GB   | -        | 1.0GB  |
| PostgreSQL增量 | 200MB    | 1.4GB   | 6.0GB    | 3.0GB  |
| Redis RDB      | 100MB    | 700MB   | -        | 300MB  |
| 配置文件       | 10MB     | 70MB    | 300MB    | 150MB  |
| 日志文件       | 200MB    | 1.4GB   | 6.0GB    | 3.0GB  |
| **总计**       | **1010MB**| **7.1GB**| **12.3GB**| **7.5GB** |

### 3.3 备份保留策略
```
备份周期保留策略：
├── 最近24小时：每小时备份（24个点）
├── 最近7天：每日全量备份（7个点）
├── 最近30天：每4小时增量备份（180个点）
└── 长期保留：每月第一个备份（12个点/年）
```

## 4. 备份验证策略

### 4.1 自动验证机制
1. **备份完整性检查**：每次备份后自动验证checksum
2. **恢复测试**：每周执行一次恢复测试
3. **数据一致性检查**：恢复后执行数据完整性验证

### 4.2 验证指标
- ✅ 备份文件完整性（MD5校验）
- ✅ 备份文件可读性（格式验证）
- ✅ 恢复时间目标验证（RTO < 1小时）
- ✅ 恢复点目标验证（RPO < 15分钟）

## 5. 监控与告警

### 5.1 监控指标
| 指标 | 阈值 | 告警级别 | 检查频率 |
|------|------|----------|----------|
| 备份成功率 | < 95% | 警告 | 每小时 |
| 备份耗时 | > 2小时 | 警告 | 每次备份 |
| 存储使用率 | > 80% | 警告 | 每日 |
| 存储使用率 | > 90% | 严重 | 每日 |
| 备份验证失败 | 任意失败 | 严重 | 每次验证 |

### 5.2 告警通知
- **严重告警**：立即通知（企业微信 + 邮件）
- **警告告警**：每日汇总报告
- **恢复失败**：立即通知 + 自动重试

## 6. 恢复策略

### 6.1 恢复时间目标（RTO）
- **关键系统恢复**：< 1小时
- **完整环境恢复**：< 4小时

### 6.2 恢复点目标（RPO）
- **数据库数据**：< 15分钟
- **文件系统**：< 1小时

### 6.3 恢复优先级
1. **优先级1**：PostgreSQL数据库（关键业务数据）
2. **优先级2**：Redis缓存（应用状态）
3. **优先级3**：配置文件（应用配置）
4. **优先级4**：日志文件（调试和分析）

## 8. 附录

### 8.1 备份脚本命名规范
```
格式：backup_{type}_{database}_{timestamp}.{ext}
示例：
  backup_full_postgres_20250430_020000.sql.gz
  backup_incr_postgres_20250430_120000.sql.gz
  backup_redis_20250430_010000.rdb
```

### 8.2 备份目录结构
```
backups/
├── postgresql/
│   ├── full/          # 全量备份
│   ├── incremental/   # 增量备份
│   └── wal/          # WAL日志
├── redis/
│   ├── rdb/          # RDB快照
│   └── aof/          # AOF文件
├── filesystem/
│   ├── config/       # 配置文件
│   └── logs/         # 日志文件
└── validation/       # 验证报告
```
