# 整单促销开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`marketing/order-promo`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **列表页**：按整单门槛（金额/数量）生效的促销规则维护页，查询区 + 活动列表；新增整单促销/修改维护，与商品促销页同构。
- 截图：![整单促销](../../../../tool-results/ql361/pages/营销__营销活动__整单促销.png)

## 2. 页面配置

### 查询条件

- 商品、客户（弹选）
- 促销类型（全部）、组合促销（全部）、促销模式（全部）
- 起始时间、结束时间
- 使用范围（全部）、活动状态（全部）、制单人（弹选）
- 勾选项：显示已过期/已作废活动（默认不勾选）

### 功能按钮

- 工具栏（抓取 JSON buttons）：新增整单促销、更多玩法告诉我们..、查询、跳转（分页跳转）
- 行级操作（同构于商品促销页，截图表头确认操作列存在；抓取时点无数据行，行级动作明细待复核）

### 打印配置

无（页面无打印按钮，截图确认；列表页打印能力待复核）

## 3. 数据表格列配置

### 默认显示列（14 列，抓取 JSON columns 实据）

操作、活动名称、起始时间、结束时间、促销方式、促销商品、组合促销、促销类型、促销模式、促销规则、促销客户、使用范围、活动状态、制单人

> JSON columns 首项即"操作"，无拼接串，14 列全部为真实列；与《商品促销开发文档》列结构完全一致（JSON 实据），差异在"促销方式"列取值（整单促销 vs 商品促销）。

### 全部可配置列

待复核（未抓取列配置弹窗）。

## 4. 业务规范

- 促销规则模型（同构实据归纳）：
  - 作用层级：按整单门槛生效——整单金额/数量满 N 触发减/赠/折（具体促销类型/模式枚举抓取时点无数据行，待复核）；落点为销售订单摘要结账面板"促销优惠、优惠金额(−)"（销售域抓取实据）
  - 与商品促销的分工（列结构同构实据）：商品促销按"订单单个促销商品"（行级，实据规则文本）触发；整单促销按整单汇总门槛触发；两页查询区与 14 列完全一致，说明共用同一套促销活动模型，仅促销方式不同
  - 定向维度：促销商品、促销客户、使用范围三维定向（列实据）
  - 组合促销：是否可与其他活动叠加的标记（列实据），行级取值待复核
  - 生命周期：新增 → 时间窗内生效 → 过期/作废；"显示已过期/已作废活动"默认隐藏（勾选项实据）
- 与其他页面关系：与《商品促销开发文档》互补（行级 vs 单级；叠加规则由"组合促销"列控制）；销售开单联动（整单优惠在销售订单摘要面板体现）；商城侧（我要推广可推广"促销"活动）；本系统落地对应 `/api/sale/promotion`（促销活动，api/marketing.ts 实据）
