## 1. 页面概述

业务员提成页是**销售提成的核算页**：查询区给出时间区间与业务过滤条件，点「查询」后由后端按「提成方案」实时计算各业务员的提成结果。其页面性质有三点区别于普通台账：

1. **计算型（不查询不出数）**——首屏不预加载数据，空态文案即「点击查询才能计算提成统计数据」（实测 `head` + `.png` 实据）；
2. **规则驱动**——结果完全由「提成方案」决定，方案入口在工具栏（`提成方案`），改方案即改口径（方案字段明细**待复核**）；
3. **口径可选**——查询区有 `按已结算提成` 勾选项，勾选后只统计已结算部分（勾选项带 `?` 帮助提示，实据）。

| 页面 | 地址（ql361） | 说明 |
|------|------|------|
| 业务员提成 | 分析 → 提成分析 → 业务员提成 | **单视图计算型页**（无页内 Tab）：查询区 + 提成方案入口 + 结果区（打开时空态） |

- 单入口：分析 → 提成分析 → 业务员提成。
- 实测实据（2026-09-15）：**无页内 Tab、无列配置齿轮、无记录数、无表格渲染**，页面处于空态（见头部 ⚠️）。
- 同组关系：本页＝销售侧提成计算；`回款统计`＝回款侧三口径核算；`业绩提成中心`＝按月矩阵的结算闭环工作台。

## 4. 业务规范

### 提成计算口径

- **计算时点**：查询时**实时计算**（非预存快照）——页头提示「点击查询才能计算提成统计数据」为直接实据。方案变更后重查即按新方案出数。
- **取数范围**：查询期内、属于所选 `经手人 / 部门 / 商品` 且符合 `单据类型 / 销售类型` 的销售单据。
- **方案驱动**：结果列由 `提成方案` 定义，方案可按「按金额 / 按毛利 / 按数量 / 按回款 / 按单价」等多口径配置（该组词仅出现在 §3.3 的 DOM 残留表头中，**方案类型枚举待复核**）；基准文档记「按销售额/毛利/数量阶梯」亦标注为待复核。
- **已结算过滤**：勾选 `按已结算提成` 后，仅统计已结算提成部分；帮助提示（`?`）内容**未抓取，待复核**。

### 结算状态机（本系统侧可确认口径）

本系统 `erp_commission_record.status` 的取值与含义（`views/analytics/commission-center/index.vue:61-66`、`CommissionRecordMapper.java:27-33`）：

| 状态 | 含义 | 结算归属 |
|---|---|---|
| `DRAFT` | 待确认 | 未结 |
| `CONFIRMED` | 已确认 | 未结 |
| `PAID` | 已结算 | **已结** |
| `CANCELLED` | 已取消 | 不计入 |

即本系统的「已结 / 未结」二分口径为：**已结 = `PAID`**；**未结 = `DRAFT` + `CONFIRMED`**。

### 与其他页面关系

- 同组三页分工：`业务员提成`（销售侧实时计算）→ `回款统计`（回款侧三口径核算）→ `业绩提成中心`（按人员 × 月份矩阵做**批量结算**并锁定）。
- 下游约束：`业绩提成中心` 的提示条「若存在某月份提成未结算，此后月份提成将不显示」表明结算必须**按月顺序推进**，本页计算结果即其上游数据源之一。
- 上游数据：销售单据（经手人归属）+ 提成方案规则。
