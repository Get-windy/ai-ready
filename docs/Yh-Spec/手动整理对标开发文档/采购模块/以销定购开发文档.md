## 实现差异说明（2026-08-29 生产级化）

### 一、页面归属与菜单

- 前端页面：`frontend/apps/pc-admin/src/views/purchase/sales-driven/index.vue`
- 路由：`/purchase/sales-driven`（动态路由已存在，无需改菜单）
- 原页面为「库存补货建议」占位实现，本次重写为对标文档描述的「以销定购」列表页（销售订单视角的采购准备）。

### 二、后端接口（erp-purchase 模块，跨模块只读销售表）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/erp/purchase/sales-driven/page` | GET | 以销定购列表分页，返回 42 列 + 订金前两条 + 是否已采购 |
| `/api/erp/purchase/sales-driven/{id}/purchase-finished` | POST | 采购成品：按销售订单商品默认供应商生成采购订单并提交 |
| `/api/erp/purchase/sales-driven/{id}/purchase-material` | POST | 采购原料：按销售订单商品 BOM 拆解原料生成采购订单并提交 |

- 后端代码位于 `backend/erp/erp-purchase/src/main/java/cn/aiedge/erp/purchase/saledriven/`
- 列表数据源 `erp_sale_order` 主表 + `erp_sale_order_deposit` 订金子表（取 sequence 前两条）+ `erp_purchase_order` 按 `source_bill_no` 反查是否已采购。
- 采购动作复用已有 `PurchaseOrderService.createOrder + submitForApproval`，生成单号 `CG+日期+流水` 并自动提交审批。

### 三、列字段映射（42 列）

- 「单据子类型」=`sale_type`（1正常/2样品/3促销）；「录入方式」=`generation_method`；「记账状态」=`bookkeeping_time` 是否为空；
- 「订金账户1/2 与 金额1/2」取 `erp_sale_order_deposit` 的 sequence 前两条；
- 「是否采购」= 是否已存在 `source_bill_no` 等于本单号且在途（status < 4）的采购单；
- 「强制终止」系统未独立建模，恒 `false`（该业务能力当前未启用）；
- 「支付状态」=`payment_status`；「发货商品/已发/未发数量」=`total_quantity/shipped_quantity/unshipped_quantity`。

### 四、业务规则（采购成品/采购原料）

1. 采购成品：取销售订单明细商品，作为采购明细。
2. 采购原料：按销售订单商品匹配 `erp_product_kit`（active 且未删除）拆解出原料，原料采购数量 = 成品销售数量 × BOM 单耗；商品无物料清单时返回业务错误。
3. **商品默认供应商**：采用「最近一次采购订单的供应商」（`erp_purchase_order_item` join `erp_purchase_order` 按 `product_id` 取 `order_date` 最近一张）。商品从未采购时返回业务错误「商品[...]无默认供应商」。
4. 按供应商分组，每组生成一张采购订单并提交审批；同一销售单重复采购时拦截（按 `source_bill_no` 反查）。

### 五、验收实测（2026-08-29）

- 登录（admin/admin123，SVG 验证码解析，`系统租户`）→ token 获取成功。
- `GET /page` 返回 200，total=1，42 列字段完整（含 `QO202607232493`、是否采购、订金等）。
- `POST /purchase-finished`（销售单 `QO202607232493`，商品 1/2 均有最近采购供应商）返回 200，生成采购单 `CG202608290051` 并提交（status=1），明细 2 条（商品1 qty2 / 商品2 qty3），`source_bill_no=QO202607232493`。
- 重复采购 `POST /purchase-finished` 返回业务错误「该销售订单已生成采购单，请勿重复采购」；采购后列表 `hasPurchased=true`。
- `前端 vue-tsc`：本页面无类型错误（全仓既有错误来自其它模块，非本次引入）。

### 六、注意事项 / 已知限制

- 测试数据「测试商品A/B」未登记于 `erp_product`，故采购价回退为 0（单据金额 0）。真实商品会取 `erp_product.purchase_price` 作为采购单价。
- 采购原料依赖 `erp_product_kit` 有成品物料清单数据；测试数据无 BOM，故该端点在无 BOM 商品上会按业务规则返回错误（代码路径已实现并可达）。
- `generateNextOrderNo` 存在既有并发/租户隔离下单号重复风险（见后端 `PurchaseOrderServiceImpl.generateNextOrderNo`），本次未改动，属既有问题。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
