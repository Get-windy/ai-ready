## 1. 页面概述

商机（Opportunity）是 CRM 里**有明确成交预期**的机会点：由线索转化或销售开发产生，沿**阶段（Stage）**推进，最终赢单（转订单/报价）或输单。

| 页面 | 地址 | 组件 | 说明 |
|------|------|------|------|
| 商机列表页 | `crm/opportunity/index` | `views/crm/opportunity/index.vue`（**1932 行**） | 三视图（**管道/看板**、列表、统计）+ 内嵌表单弹窗 + 详情抽屉 + 移动阶段弹窗 |
| 商机表单页 | `crm/opportunity/form` | `views/crm/opportunity/form.vue`（89 行） | 新增/编辑商机（`BillFormPage` + `useBasicForm`） |

> **⚠️ 双入口方向提醒**：菜单主 `path` 指向**列表页**，标签 `添加` 指向**表单页** —— 与「报价单 / 发票」两页方向相反，勿照抄。

### 1.1 本页三视图（重点，与其余 CRM 页最大的结构差异）

| 视图 | 触发值 | 内容 | 位置 |
|------|--------|------|------|
| **管道（看板）** | `pipeline`（**默认值**） | 按 5 个「进行中」阶段列（`pipelineStages` 去掉 `won`/`lost`）渲染可拖拽卡片 | `index.vue:285-371`，默认值 :1050 |
| 列表 | `list` | `BillTableList` 9 列 | :374-539 |
| 统计 | `statistics` | 2 张图表卡（阶段分布饼图 / 金额趋势折线）+ 1 张「阶段详情统计」只读表 | :542-593 |

视图切换器为页头 `a-radio-group button-style="solid"`（`AppstoreOutlined 管道` / `UnorderedListOutlined 列表` / `BarChartOutlined 统计`，:29-43）。

> **⚠️** 本页默认落在**管道视图**（`activeTab = ref('pipeline')`，:1050）—— 即用户一进商机页看到的是**看板**，而非列表；这与 CRM 其他列表页（客户/线索/合同）**默认列表**不同，做验收与截图时必须显式切视图。

### 1.2 与「商机阶段」页的分工

| | 商机（本页，`80220`） | 商机阶段（`70321`，另文） |
|---|---|---|
| 定位 | 商机台账 + 管道推进 + 阶段统计 | 商机阶段的**推进/赢单/输单**工作台（`ARReportPage` 路线 B） |
| 阶段推进 | 看板拖拽、行内「移动阶段」弹窗 | 「推进商机阶段」按钮 → `POST /advance`；赢单 `POST /win`；输单 `POST /lose` |
| 阶段值域 | **字符串 key**（`lead/qualification/…`，:1071-1079） | **数字 1-5**（`opportunity-stage/index.vue:137-143`） |
| 后端 | `/api/crm/opportunity/*`（共用） | 同左 |

> **⚠️ 三套阶段值域（P0）**：`opportunity/index.vue` 用字符串 key（:1071-1079 与表单 :660-674）、`opportunity-stage/index.vue` 用数字 **1-5**（:137-143 与 :145）、`opportunity/form.vue` 用数字 **1-6**（:44-53），而后端实体是 `opportunity_stage INTEGER`（表默认 0），Service 的 `advance` 只在 **1→5** 递增（`CustomerOpportunityServiceImpl.java:109-114`）。详见 §5.1。

> **⚠️ 缺陷（P0）**：阶段筛选**语义错位**。`findIndex` 返回 **0-6**（字符串 key 在数组中的下标），而后端阶段是 **1-5**（`STAGE_OPTIONS`，`opportunity-stage/index.vue:137-143`）：
> - 选「线索」(index 0) → 传 `opportunityStage=0` → 后端 `opportunity_stage = 0` 的行（表默认值 0，正常情况下无）→ **结果为空**；
> - 选「资格确认」(index 1) → 传 1 → 后端理解为「初步接触」；
> - 选「已流失」(index 6) → 传 6 → 无对应数据。
> 修法：建立显式映射表 `{lead:0|1, qualification:1, proposal:3, negotiation:4, closing:5, won:…, lost:…}` 并**与后端字典对齐**（见 §5.1），不要用 `findIndex`。
> **⚠️ 缺陷（P1）**：`customerName` / `ownerId` / `minAmount` / `maxAmount` **4 个查询项全部无效**（输入后点「查询」结果不变），但 `hasActiveFilters`（:1221-1223，读 `searchForm`）为真 → 空态显示「没有符合条件的商机，清除筛选」的误导文案。
> **⚠️ 缺陷（P1）**：`BillTableList` 的 `filter-fields`（3 项，:1093-1097）走的是另一个回调 `handleFilterChange`（:1370）→ 写入 `searchFilters`，而 `fetchData` **从不读 `searchFilters`**（:1283-1292）→ **该筛选面板完全无效**（同型问题见《线索开发文档》§3.3）。

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 下无 `e2e-crm*.cjs`）。

### 10.1 接口验收（商机部分 ≥ 14 项）

1. 探针：`GET /api/crm/opportunity/page`（登录态）返回 200（租户列问题见 §9.2 P0）。
   > 2026-09-18 更新：`tenant_id` 已由 `V11.379.0` 补列，登录态探针预期直接 200。
2. `GET /page` 默认查询 `total` 与直查 DB（`deleted=0`）一致；`pageNum/pageSize` 生效。
3. `keyword` 命中 `opportunity_name` 与 `customer_name`（各造 1 条）。
4. `customerId` / `opportunityStage`（**数字 1-5**）/ `status` / `salesPersonId` 四参数逐个生效。
5. `POST /` 用实体字段名创建：`opportunityName`、`customerId`、`opportunityStage=1`、`estimatedAmount`、`probability`、`salesPersonId` → 返回 `opportunityCode` 形如 `OPP-YYYYMMDDNNNN`。
6. `PUT /{id}` 改名后三级回读一致；`DELETE /{id}`、`DELETE /batch` 生效（逻辑删）。
7. `GET /export` 条数 = `page.total`；`GET /code/{code}`、`GET /customer/{id}`、`GET /salesPerson/{id}` 命中。
8. `POST /{id}/advance`：1→2→3→4→5 递增，`opportunity_stage_desc` 同步；到 5 后再调返回 400「商机已处于最终阶段」。
9. `POST /{id}/win?actualAmount=…`：`status=2`、`probability=100`、`actual_close_date=今天`。
10. `POST /{id}/lose?loseReason=…`：`status=3`、`probability=0`、`lose_reason` 落库；**缺 `loseReason` 返回 400**。
11. `GET /statistics`：造 1 赢单 + 1 输单 + 1 进行中 → `totalCount=3/ winCount=1 / loseCount=1 / activeCount=1 / winRate=50.00`；**再造"只有进行中商机"的库（无赢单无输单）断言不抛 500**（对应 §6.3 除零坑）。
   > 2026-09-18 更新：除零缺陷**仍未修**（守卫仍是 `totalCount > 0`），该项为待办；页面已改用前端聚合规避，不阻塞 UI。
12. `PUT /{id}/stage`（补齐后）：可直接跨阶段设置（如 1→4），落库正确；目标值非法（如 9）返回 400。
   > 2026-09-18 更新：端点已补齐（`stage` 走 query 参数），本项可直接执行；另补断言「拖到 5 → `status=2`；从 5 拖回 → 赢单痕迹清除（`status=1`、`actual_close_date` 置空）」。
13. 写入回归后清理自产数据。

## 12. 剩余缺口（不阻塞，如实登记）

1. **阶段模型未落配置表**：`pipelineStages` 硬编码，缺 `sequence/default_probability/is_won/fold`；这也是「商机阶段」页存在的意义（**跨两页的共同前置项**）。
2. **阶段值域三套未统一**（前端字符串 key / 表单 1-6 / 后端与阶段页 1-5）。
3. **`statistics` 数据源未接线**（4 张卡恒 0）+ `/statistics` 除零 500 + 裸 Map key 不一致。
4. **`PUT /{id}/stage` 端点缺失**（拖拽 404）。
5. **表单保存、移动阶段、转订单、创建报价、添加跟进、关闭商机 六处桩**。
6. **表缺 `priority` / `source` 列**；`opportunity_type` / `opportunity_source` 两列前端零引用。
7. **租户列缺失**（`crm_customer_opportunity` 无 `tenant_id`）—— 全模块运行时前提。
8. **线索 → 商机链路断裂**（线索转化不建商机；`lead_id` 列无写入方）。
9. **详情抽屉的跟进时间线 / 关联报价单无数据源**（需接 `crm_customer_follow_up` 与 `crm_quotation`）。
10. **无阶段变更历史、无停滞提醒、无加权预计收入、无多管道/销售团队**（均标注为**业界建议、本系统未实现**）。
11. **权限码未落库**（`crm:opportunity:*` 8 个码）。
12. **无模块级 E2E、无验收截图**；`crm_customer_opportunity` 当前 **0 行**，管道/拖拽/统计视图**从未在任何环境跑通**。
