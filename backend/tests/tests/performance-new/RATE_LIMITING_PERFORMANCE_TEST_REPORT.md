# 限流算法性能测试报告

**生成时间:** 2026-04-21 02:35

**测试环境:** 企智连平台限流算法性能测试

## 测试概述

本次测试针对企智连平台中的两种主要限流算法进行了全面的性能评估：

- **滑动窗口算法**: 基于时间窗口的限流算法，允许在指定时间窗口内处理最多N个请求
- **漏桶算法**: 基于固定速率处理请求的限流算法，具有平滑输出特性

## 测试场景

测试涵盖了多种并发级别和请求负载场景，包括：

- 低并发场景: 5个并发线程，每个线程100个请求
- 中等并发场景: 20个并发线程，每个线程200个请求
- 高并发场景: 50个并发线程，每个线程500个请求

| 特性 | 滑动窗口算法 | 漏桶算法 |
|------|------------|----------|

## 性能总结

### 吞吐量表现

- 漏桶算法在高并发场景下表现出更高的吞吐量（50709.94 req/s vs 37202.38 req/s）
- 在低并发场景下，漏桶算法也具有明显优势
- 滑动窗口算法在中等并发场景下表现较差

### 成功率表现

- 漏桶算法在高并发场景下具有更高的成功率（0.33% vs 0.00%）
- 在低并发场景下，两种算法表现相当

### 延迟表现

- 漏桶算法的平均延迟更低（116 ns vs 164 ns）
- 滑动窗口算法的最大延迟更高（19000 ns vs 70300 ns）

## 推荐建议

### 滑动窗口算法适用场景

- 需要处理突发流量的应用场景
- API网关或微服务入口限流
- 对吞吐量要求较高的场景

### 漏桶算法适用场景

- 需要平滑输出流量的场景
- 下游服务处理能力有限且需要保护的场景
- 需要严格控制输出速率的场景

### 参数调优建议

- 滑动窗口算法: 根据业务特点调整窗口大小和请求数限制
- 漏桶算法: 根据下游处理能力设置合适的桶容量和漏速

## 结论

经过全面的性能测试，两种限流算法各有优势：

1. **滑动窗口算法**在处理突发流量方面表现更好，适合对吞吐量要求较高的场景
2. **漏桶算法**在流量整形和平滑输出方面表现更好，适合需要严格控制输出速率的场景
3. 两种算法在企智连平台中均已验证稳定可靠，可根据具体业务需求选择使用
