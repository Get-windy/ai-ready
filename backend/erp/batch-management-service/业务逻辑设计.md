# 批次管理模块业务逻辑设计

## 1. 业务场景分析

### 1.1 核心业务场景
1. **批次创建**：生产入库、采购入库、退货入库时创建批次
2. **状态流转**：批次状态变更（正常、隔离、过期、作废）
3. **追溯查询**：批次来源、流转历史、质量记录
4. **库存关联**：批次与库存量、货位、仓库关联
5. **质检关联**：批次与质检报告、合格率关联

### 1.2 业务规则和约束条件
1. **批次号生成规则**：前缀+日期+序列号（可配置）
2. **状态转换规则**：ACTIVE → QUARANTINED → ACTIVE/CANCELLED → EXPIRED
3. **业务约束**：库存量>=0，出库不能超过可用数量
4. **数据一致性**：批次信息与库存、质检数据同步

## 2. 服务层设计

### 2.1 批次创建服务 (BatchCreationService)
- 支持批量创建和单条创建
- 参数校验：批次号唯一性、必填字段验证
- 默认值设置：状态、创建时间等

### 2.2 状态流转服务 (BatchStateTransitionService)
- 状态机模式实现
- 状态转换验证：当前状态→目标状态是否合法
- 关联操作：状态变更时触发相关操作（如隔离时通知质检）

### 2.3 查询服务 (BatchQueryService)
- 复杂查询条件：批次号、产品、状态、日期范围等
- 分页查询支持
- 性能优化：索引设计、缓存策略

### 2.4 关联服务 (BatchAssociationService)
- 库存关联：批次与库存量同步
- 质检关联：批次与质检报告绑定
- 追溯关联：批次与供应商、生产订单关联

## 3. 业务规则实现

### 3.1 批次号生成规则
```java
规则：{前缀}{日期}{序列号}
示例：B202605010001
配置项：前缀、日期格式、序列号长度、序列号重置规则
```

### 3.2 状态转换验证规则
```java
状态流转矩阵：
ACTIVE → QUARANTINED（质检发现问题）
QUARANTINED → ACTIVE（质检通过）
QUARANTINED → CANCELLED（质检不合格）
ACTIVE → EXPIRED（超过有效期）
ACTIVE → CANCELLED（手动作废）
```

### 3.3 数据完整性校验
1. 必填字段校验
2. 数据类型校验
3. 业务逻辑校验（库存量>=0）
4. 关联数据存在性校验

### 3.4 操作权限控制
1. 角色权限：管理员、质检员、仓库员
2. 操作权限矩阵
3. 数据访问权限（仅查看自己的仓库批次）

## 4. 异常处理和事务管理

### 4.1 异常分类
1. **业务异常**：参数校验失败、业务规则违反
2. **系统异常**：数据库连接失败、服务不可用
3. **并发异常**：乐观锁冲突、数据已修改

### 4.2 事务管理
1. **本地事务**：@Transactional注解
2. **分布式事务**：Saga模式、TCC模式
3. **事务边界**：服务层事务、跨服务事务

### 4.3 操作日志和审计
1. **操作日志**：谁在什么时间做了什么操作
2. **数据变更审计**：数据变更前后的值
3. **日志存储**：数据库表+ELK

### 4.4 重试机制和幂等性
1. **重试策略**：指数退避、最大重试次数
2. **幂等控制**：请求ID、业务唯一键
3. **幂等处理**：先查后操作、状态机防重
