## 1. 页面概述

- **配送跟踪页**：展示**配送员最新位置**与**历史轨迹点**，是配送执行的"在途可视化"入口。
- 业界定位：TMS/即时配送的 **Live Tracking**——实时位置 + 轨迹回放 + 时效预警（超时/偏航/停留）。

### 3.6 实时推送（业界实践）

- **上报端（司机端）**：定位上报策略——**每 5–10 秒或位移 > 50m** 上报一次；离线缓存补传。
- **服务端**：位置写入时序表（按天分区 / 定期归档），最新位置缓存 Redis（`rider:loc:{riderId}`）。
- **下发端**：WebSocket / SSE 推送在线配送员位置增量（**避免前端轮询**）；前端按 30s 兜底刷新。
- **轨迹抽稀**：回放时按 Douglas–Peucker 抽稀，避免万级点渲染卡顿。
- ✅ **本系统落地（见 §7.1/§7.2）**：服务端 `GET /api/dms/tracking/stream`（SSE，按租户分组，默认 5 秒/帧推送在线配送员位置）+ 前端 `fetch` 流式读取并按 `riderId` 合并；30 秒兜底轮询保留、连接断开自动降级并 30 秒后重连。抽稀实现为**等间隔抽稀 + 首尾必留**（`/tracking/replay`，比 Douglas–Peucker 更稳定可控）。司机端上报策略与 Redis 最新位置缓存仍为遗留（见文末）。

### 3.7 数据模型（现状与建议）

- 已有：`DmsTracking`（轨迹点）、`DmsRider`（配送员）、`DmsTask`（任务）。
- 建议补充：`上报表/时序分区`、`超速/偏航/停留异常表`、`GPS 上报设备与来源字典`。
- **本系统落地**：预警**实时计算**（`/tracking/alerts`，读 `dms_tracking` + `dms_task`），**不建异常表**（避免双写不一致）；阈值全部配置化（§7.3）。时序查询走 `V11.215.0` 已建的 `(tenant_id, rider_id, report_time)` 索引；保留策略见 §7.1 `clean-expired`。

## 4. 业务规范

- **在线判定**：`online = 最近上报时间在阈值内（默认 2 分钟）`；超时视为离线。
- **轨迹归属**：轨迹点可挂在配送员（连续轨迹）与任务（配送过程）两维度——现表含 `taskId`，支持双向查询。
- **隐私与合规**（生产级要求）：仅**配送时段**采集配送员位置；非工作时段停止上报；位置数据按合规要求脱敏/保留期限管理。
- **异常预警**（业界）：超速、偏航（偏离规划路径 > X 米）、异常停留（> Y 分钟未移动）、超时未送达。

### 7.3 配置落位

| 配置项 | 键 | 落位 | 默认 |
|--------|----|------|------|
| 在线判定阈值(分钟) | `dms.tracking.online.minutes` | 配置中心（配送参数可改，租户可覆盖） | 2 |
| 超速阈值(km/h) | `dms.tracking.speed.limit` | 同上 | 60 |
| 异常停留阈值(分钟) | `dms.tracking.stop.minutes` | 同上 | 15 |
| 偏航阈值(米) | `dms.tracking.deviation.meters` | 同上 | 1000 |
| 位置采集时段 | `dms.tracking.collect.hours` | 同上（`HH:mm-HH:mm`，支持跨天；空=全天） | `00:00-23:59:59` |

### 遗留（非阻塞）

- **已补齐（2026-09-13 第二轮）**：SSE 实时推送、偏航预警、合规（采集时段 + 保留策略）三项已落地并纳入 E2E；§6 实施清单全部关闭，余项见下。
- **上报侧（依赖司机端改造）**：司机端定位上报策略（每 5–10s / 位移 >50m 触发上报、离线缓存补传）与 Redis 最新位置缓存（`rider:loc:{riderId}`）未接——当前最新位置以轨迹表回溯窗口内的末点为准，功能正确，高频场景建议加缓存。
- **SSE 多实例**：推送为**单实例内存订阅表**（按租户分组）。多实例部署需接 Redis 发布订阅扇出（同 `ConfigService.publishToCluster` 思路）；默认单实例部署，暂不影响。
- **偏航口径升级**：现为「起点→客户」两点基线；接入路线单规划点序列（`erp_route_point`）后可升级为多段折线最短距离。
- **异常停留的语义边界**：规则为「相邻点位移 <50 米且间隔 ≥ 阈值」，若某配送员长时间未移动但仍在**同一位置**（如跨午休后继续上报）会被判为停留——阈值建议按业务时段收紧，或叠加「配送时段」判定（可与 `collect.hours` 合并）。
- **在线阈值 / 超速 / 停留 / 偏航 / 采集时段 / 保留天数**：均落**配置中心**（配送参数页可改，租户可覆盖），默认值见 §7.3。
- **无位置口径**：`有位置/无位置` 以「是否有过任何轨迹点」统计；配送员位置表的最新位置取**回溯 30 天**窗口内的点（超窗口视为无位置，避免全表扫描）。
