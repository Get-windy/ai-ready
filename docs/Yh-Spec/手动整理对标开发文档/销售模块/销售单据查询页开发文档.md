### 本轮实现要点（2026-09-10）
1. **换货单类型查询打通（P0）**：`erp_sale_exchange` 实体声明 78 字段但建表仅 23 列，`/api/sales/doc-query/page?documentType=EXCHANGE` 与 `/api/erp/sale/exchange/page` 均直接 500。迁移 `V11.123.0` 按实体补齐表头 57 列 + 明细 68 列（含 `cost_price` / `cost_amount`），并回填 `creator_id` / `creator_name` / `create_by`。
2. **成本 / 毛利真实化（P1）**：`UnifiedSalesDocQueryServiceImpl.fillCostAndProfit()` 按单据 ID 批量聚合明细（`selectMaps + GROUP BY`），避免逐行 N+1；无成本数据保持 `null`，不以 0 冒充。
3. **整单备注闭环（P0）**：`SalesDocQueryController.updateRemark` 改为 `UpdateWrapper` 只更新 `remark` 列，增加单据存在性校验与 500 字符上限。
4. **查询条件接线**：日期类型（单据日期 / 制单时间 / 记账时间）按类型解析真实列名；补齐自定义字段区间、自定义文本、商品行属性（明细 `EXISTS` 子查询）、仓库 ID / 名称、仅统计车辆库（口径同「销售明细查询」：仓库名含「车辆」）。
5. **分页稳定性**：`Page(current,size)` 直接用 `LIMIT take OFFSET skip`（替换原先的 `skip/pageSize+1` + `subList` 取数）；排序移至 `Page.addOrder`，避免 `ORDER BY` 进入 `COUNT` 查询导致 PostgreSQL 报错。
6. **字段口径修正**：订单「记账人」不再冒充制单人、订单结算状态由已结算金额派生（UNPAID / PARTIAL_PAID / PAID）、订单积分抵扣映射 `used_points`、制单时间优先 `create_time`、来源订单优先 `source_order`。
7. **前端**：单据类型 / 结算状态中文本地化、日期列格式化、51 列 formatter、搜索区由页面配置驱动渲染、功能按钮开关生效、查询方案可用、导出真实 xlsx、打印接 `PrintDialog`。
8. **搜索区「查询」按钮可见性（对标截图回归）**：搜索字段按页面配置动态渲染后，默认可见字段数变化会把「查询」按钮挤出 2 排折叠区（`.search-container:not(:has([data-expanded])) > .search-grid { max-height: 80px; overflow: hidden }`）→ 按钮被裁掉，页面看起来"没有查询按钮"。修复：字段网格只渲染非勾选类字段，**「查询」按钮与勾选项移到网格之外的固定操作行**（`.search-action-row`），任何字段数量 / 视口宽度下都可见；同时按对标把「显示红冲」默认置为不在搜索区（`visible: false`，可在页面配置中勾出），默认第 2 排只跟「仅统计车辆库」。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
