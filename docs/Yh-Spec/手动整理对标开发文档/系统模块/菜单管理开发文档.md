## 1. 页面概述

菜单管理页是**平台级菜单树与权限码定义页**：一张**自研「扁平化 + 缩进」的树形 `a-table`**（13 列）+ **4 张统计卡** + **6 个查询/工具栏控件** + **12 个按钮** + 一个 **`FullScreenDetail` 全屏表单（19 个字段）** + 一个 `FullScreenDetail`「分配角色」面板。它属于 `61307 系统管理` 组的**唯一子节点**（`sort=100`），是**全模块行数最多（1641）、结构最复杂的一页**。

> **一句话定性**：这是**全系统最"卡在自己设计里"的一页** —— 它是 `sys_menu` 中**唯一 `tenant_id=1` 的行**（其余 380 行全为 0）、`client_type='tenant-admin'`（**却挂在 `system-admin` 的父节点下**）；**超管能看到它**（`getAllMenusForSystemAdmin()` 同时收两类 `client_type`），**但它管不到自己** —— `GET /api/menu/tree` **强制 `eq(tenant_id, 0L)`**（`SysMenuServiceImpl.java:96-100`、`:206-212`）→ **6130701 永远不出现在本页自己的表格里**（**无法在本页编辑/删除它自己**）。
> **第二条硬结论**：**后端要求 6 个 `system:menu:*` 权限码，而 `sys_permission` 中该前缀 0 行** → **非超管对 `/api/menu/**` 的任何调用都 403**；**而本页按钮用的是 `system:permission:*`（另一个域）** → 即使授了按钮码，**按钮能显示、接口照样 403**（README **P0-16**）。

**其它后端缺口**：

- ❌ **无「菜单树拖拽排序」端点**（`PUT /{id}/sort` 存在但**每次只动一个节点**，无批量重排）；

### 8.2 按钮级权限（ACL 矩阵，**Odoo 源码级**；A 级）

Odoo `ir.model.access` 字段（**官方源码原文照录**）：`name`（Char，required，index）、`active`（Boolean，default True）、`model_id`（Many2one `ir.model`，required，index，**ondelete='cascade'**）、`group_id`（Many2one `res.groups`，**ondelete='restrict'**，index）、`perm_read` / `perm_write` / `perm_create` / `perm_unlink`（各为 Boolean）。

判定语义（**官方文档原文，A 级**）：「a user belongs to any number of groups」「security mechanisms are associated to groups」；ACL 一行 = **模型 × 组 × CRUD 四位**；「**an empty group_id means the ACL is granted to every user**」；「the user doesn't have access」（**无匹配即无权限**）；**「Access rights are additive」「a user's accesses are the union of the accesses they get through all their groups」**。

> ⚠️ **范式差异（必须写清）**：本系统用的是**权限码字符串**（如 `system:menu:list`），而 Odoo 用的是「**模型 × 组 × CRUD 四位**」→ **两者是不同范式**。RuoYi 的 `perms` 字符串与本系统一致，**但 RuoYi 的字段清单为 C 级**（底稿 §9.1 第 7 条）。
> **建议（本系统设计）**：菜单管理页在"按钮权限"上**继续用权限码范式**（与本系统现有实现一致），**但应把"按钮权限"与"菜单节点"绑定**（RuoYi 的 F 型即为此设计）—— 否则平台侧**无法回答「这个权限码属于哪个页面」**（**本系统当前正是这个问题**：`sys_menu.menu_code` 是**菜单自身的码**，而按钮的权限码（如 `system:menu:create`）**在 `sys_menu` 表里根本没有对应行**）。

### 8.3 数据权限（记录规则，**Odoo 官方文档原文**；A 级）

要点：**「Record rules are default-allow」**；**「evaluated record-by-record, following access rights」**（**先 ACL 后记录规则，且逐条记录评估**）；`domain_force` 是 domain（可用 `time`/`user`/`company_id`/`company_ids`）；`perm_*` **未选操作不检查**该规则（默认全选）；组合语义 **「Global rules intersect」「Group rules unify」「The global and group rulesets intersect」**；风险警告 **「Creating multiple global rules is risky」**（可能形成不重叠的规则集，移除所有访问）；字段级可设 `groups` 属性 → 受限字段**自动从视图移除**、**从 `fields_get` 响应移除**、**显式读写会报 access error**。

> ⚠️ **对照本系统**：本系统用的是 **`tenant_id` 行级隔离**（MyBatis-Plus 多租户插件），**与 Odoo 的"全局规则交集 + 分组规则并集"是两套模型**。本模块的"**平台级菜单绝不能进 `tenant_id` 过滤**"这一条，本系统**已在 `MyBatisPlusConfig.IGNORE_TENANT_TABLES` 里豁免 `sys_menu`**（`:35`）→ ✅ **这一点是对的**；而**"数据权限"若要做**（比如平台运营方只读某些租户），应走 Odoo 的 `domain_force` 思路，**并且要警惕官方警告的"全局规则交集导致什么都看不到"**。

### 8.4 平台级菜单 vs 租户级菜单的边界（**最强佐证，A 级**）

**jeecg 官方文档原文**：「系统用户、系统角色菜单，这个是给超级管理员用的，**不做租户隔离**」；隔离范围是「租户用户、租户角色、部门、我的部门、字典、分类字典、多数据源、职务」；「租户的个性化权限，可以通过租户下的套餐实现」；官方还强调一部分是「通过硬编码实现数据查询，按租户 ID 隔离」，另一部分是「直接通过 `MybatisPlusSaasConfig` 加入 tenantTable 的表配置」。

**本系统的落地边界（对照结果）**：

| 建议边界 | 本系统实际 | 判定 |
|---|---|---|
| `client_type=system-admin` 的菜单**全部豁免 `tenant_id` 过滤**，且**不纳入任何租户套餐** | ✅ `sys_menu` 在 `IGNORE_TENANT_TABLES`（`MyBatisPlusConfig.java:35`）；`sys_tenant_menu` 实测 4 行**不含任何平台菜单** | ✅ **对的（README §1.3 红线①）** |

### 8.5 明确不借鉴

| 不借鉴 | 理由 |
|--------|------|
| Odoo 的「菜单动作 = `fields.Reference` 强类型指针」 | 本系统是 Vue SPA + 字符串路由，引入 strong-typed action 需重构路由体系（**改动面过大，收益低**）→ 改为**弱校验**（§8.1-1） |

| Odoo.sh 的分支/构建模型 | 与本页无关 |
| **RuoYi 的 M/C/F 模型作为"业界标准"引用** | 🔴 底稿 §9.1 第 7 条：**官方文档站未提供表结构章节**、源码 SQL 两次 `ECONNRESET` 未取得 → **只能作参考（C 级），不得写"业界标准"** |

### 8.6 不发明字段承诺

本文档所有「建议字段」**均不预先承诺字段名**。已确认**可以不动表**就能落地的四项是：

## 10. 验收标准（目标）

> **前置**：本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）。脚本建议命名 `tools/e2e-system.cjs`（接口 + 直连 DB 对账 + 写库后复原 + Playwright UI 截屏，参照 `tools/e2e-crm.cjs`）。
> **🔴 本页验收的五条硬纪律（务必先读）**：
> 1. **绝对不要改 `sys_menu` 中 `id ≤ 6130701` 的既有行**（尤其平台菜单 `60013`/`61301`-`61307`/`62001`-`62505`）—— **改错会让平台菜单整棵消失，且 sh 会话再也点不开设置页**；
> 2. **绝对不要删除任何菜单**（`deleteMenu` 无子节点保护 → **删父节点会让整棵子树不可达**）；
> 3. **新增断言建议用「新增 → 断言 → 删除自产行」闭环**（`sys_menu` 是软删 `deleted`，**新增行可直接 `DELETE` 物理删掉自产行**；**但不得删非自产行**）；
> 4. **`sys_menu` 的 `tenant_id` / `client_type` / `parent_id` 三个字段宁可不测**（测了容易把平台菜单挂错地方）；
> 5. **权限断言必须写死"用哪个账号 + 是否重登"**（README §1.3 红线②：超管重登后才有 `tenantScopeExempt`）。

### 10.1 接口验收（**22 项**）

**可达性与超管豁免对照（①–④）**

① 用 `admin`（`id=1`，`tenant_id=1`，SUPER_ADMIN）**重新登录**后调 `GET /api/menu/tree?tenantId=1` → **期望 200**（超管走 `*` 通配绕过 `system:menu:list`）。
② 🎯 **超管（重登后）能查到 ≥ 380 行的对照断言**：断言 ① 返回**是一棵树**（顶层为 `parent_id=0` 的节点），**递归拍平后的节点数 = 380**（= `SELECT count(*) FROM sys_menu WHERE tenant_id=0` 的实测值）。
③ 🎯 **「6130701 不在本页表格里」的专门断言（本页最独特的缺陷）**：直查 `SELECT id FROM sys_menu WHERE tenant_id=1` → **= 6130701**；再断言 ① 的递归拍平结果中**不包含 6130701** → **「本页无法编辑自己」的可执行证据**（`SysMenuServiceImpl.java:98`、`:206-211` 的 `eq(tenant_id,0L)`）。

### 11.1 必须写清的「通道判别」事实（《对标开发技术参考文档》§5.6.2 硬规则）

1. **模块自带 yml 不生效**：本页**不涉及** yml 配置（菜单数据在表里、可见性在代码里）→ **本规则在本页不适用**；但**若将来把"菜单树过滤规则"做成可配置**，**必须**写到 core-api 的 `application.yml`（不能写 `core-base` 模块自带的 yml）。
2. **前端 `VITE_*` 是构建期注入**：本页**未使用**；但**本页有更硬的"构建期"约束** —— `CLIENT_TYPE = 'tenant-admin'`（`dynamicRoutes.ts:7`）、图标清单（`:797`）、业务流向词表（`:888-926`）**全部是构建期常量** → **改它们必须重新构建前端**。
3. **密钥优先不入库**：本页**无凭据** → 不适用。**但本页的"数据"比凭据更危险**：**改错 `sys_menu` 会让整个系统的导航失效**（尤其删父节点 → 子树不可达）→ 运维必须走页面而非直改库。
4. **必须有降级**：菜单接口失败时 → 前端走 `getFallbackRoutes()`（`dynamicRoutes.ts:1730` 起，`:1220-1222` 触发）→ **只给静态兜底路由**（含 `system/user`/`role`/`menu`/`config` 于 `:1785-1788`，以及无条件注入的 `system/data-import` 于 `:1454-1459`）→ **表现为"菜单大幅缺失但系统还能进"**（**这是有意设计的降级，勿当作缺陷**）。
5. **换配置要能生效**：本页的"配置"= `sys_menu` 行 → **生效方式 = 页面保存 → `refreshAllMenus()` 清 `localStorage` 缓存 + `setupDynamicRoutes()` 重装路由**（`:979-989`）→ ✅ **本页在这一点上做得比同组其他页好**（其他页根本没有生效链路）。
   ⚠️ **但注意两个例外**：(a) 直接改库（不走页面）→ 前端**最长 30 分钟**才生效（`dynamicRoutes.ts:1096` 的 TTL）；(b) 其他已登录用户的 `localStorage` **不受本次操作影响** → 他们需要重新登录或等 TTL。
6. **多租户读全局**：`sys_menu` **已豁免**（`MyBatisPlusConfig.java:35`）→ 读它**不需要** `@InterceptorIgnore`；**但业务层用 `eq(tenant_id, 0L)` 人为排除 6130701** —— **这是"配置落位"层面最需要写清的一条**：**排除发生在 SQL，不发生在插件**。

## 12. 剩余缺口（P0 / P1 / P2）

> 口径与《系统模块/README.md》§7 保持一致。README §7.1 **P0-16**（`system:menu:*` 6 个码 0 行）、**P0-17**（平台侧无审计）在本页的适用性逐条标注。

### P0（7 条）

① **6 个 `system:menu:*` 权限码在 `sys_permission` 中 0 行 → 非超管对 `/api/menu/**` 的任何调用都 403**（README §7.1 **P0-16** 在本页的具体化）：`SysMenuController.java:39/53/68/82/136/149/160/171/183`；devdb `like 'system:menu%'` = **0 行**；超管靠 `UnifiedPermissionCacheService.java:82-88` 的 `*` 通配旁路。
    建议：**补 6 个权限码种子（写迁移）**，并把前端 5 处按钮码统一到 `system:menu:*`。
② **前端按钮码与后端接口码不同域**（README **P0-16** 的另一半）：按钮用 `system:permission:create/update/assign/delete`（`menu/index.vue:96/302/312/322/332`），接口要 `system:menu:*` → **即使授了按钮码，按钮显示、接口照样 403**。
    建议：同 ①。
③ **本页无法编辑它自己那一行**：`GET /api/menu/tree` 的 `SysMenuServiceImpl.java:96-100` + `:206-212` **强制 `eq(tenant_id, 0L)`**，而 6130701 是**唯一 `tenant_id=1`** 的行 → **本页的表格里永远没有它**（无法编辑/删除/改状态）。
    建议：**二选一** —— (a) 把 6130701 的 `tenant_id` 改为 `0`（**最小改动**，但要评估"唯一非 0 行"这一约定是否被别处依赖）；(b) 把 `getMenuTree` 的过滤改为 `.in(tenant_id, 0L, 系统租户)`（**语义更清晰**）。**在裁定前不要动**。
④ **`GET /api/menu/tree` 的 3 个查询条件后端不接收**：`SysMenuController.java:83` **只声明 `@RequestParam Long tenantId`**（且无 `required=false`），前端传的 `menuName`/`menuType`/`status` **被静默忽略** → **本页查询区形同虚设**。
    建议：后端补 3 个 `@RequestParam(required = false)` 并在 `SysMenuServiceImpl.getMenuTree` 内做过滤（**同时保留"必需参数 `tenantId` 但值被忽略"这一矛盾——建议直接删除该参数**）。
⑤ **「菜单类型」选项恒空**：依赖字典 `MENU_TYPE`，而 devdb `sys_dict_item` **0 行**、`dict_code like '%MENU%'` **0 行** → `menuTypeOptions` 恒 `[]`（`menu/index.vue:868-879`）→ **新增/编辑时无法选择菜单类型**、查询区该下拉**无选项**；且 `formData.menuType` 初值 `1` 使必填校验**仍能通过** → **缺陷被掩盖**。
    建议：**补字典种子**（`sys_dict_type` + `sys_dict_item` 各一条 `MENU_TYPE`，3 个项）**或**前端写死 3 个选项（**前者更符合本系统的字典体系**）。
⑥ **「角色」功能链路 404**：`menu/index.vue:1225` → `GET /role/{id}/menus`，而 `SysRoleController` **无该端点** → 整个「角色」弹窗**不可用**；且其提交逻辑**只能添加、不能移除**（`:1224-1229` 只在"不包含"时追加）。
    建议：补 `GET /role/{id}/menus` 端点，并把提交改为**全量覆盖语义**（先算差集，再增删）。
⑦ **删除父菜单无保护 → 子树变孤儿**：`SysMenuController.java:70-75` 无"存在子节点则拒绝"的校验；删父节点后子菜单的 `parent_id` 指向已删除行 → `buildMenuTree`（`SysMenuServiceImpl.java:346-357`）从 0 开始递归 → **整棵子树不可达**。
    建议：补 Odoo `ondelete="restrict"` 同款校验（**A 级对照**）；**并补"删除前提示受影响子节点数"**。

### P1（8 条）

⑧ **`status` 语义四处不一致**：DB 默认 `0` / 实体注释「0-正常 1-禁用」（`SysMenu.java:107-109`）/ `createMenu` 强制 `status=1` 且注释「默认启用」（`SysMenuServiceImpl.java:56`）/ 可见性要求 `status=1`（`:298`）、前端开关 `status===1`（`:243`）→ **实体注释是错的**；且**绕过 `createMenu` 直接 INSERT 的行默认不可见**。建议：统一注释与文档到「**1 = 启用**」，并考虑把 DB 列默认值改为 `1`。
⑨ **`updateMenu` 走 `updateById` → null 字段不更新**（`SysMenuServiceImpl.java:76`）→ 用户**无法清空可选字段**（`component`/`remark`/`icon` 等）。建议：改用 `UpdateWrapper.set(...)` 显式处理 null（参见记忆《MyBatis 两个静默陷阱》）。
⑩ **表单字段覆盖不全**：`keepAlive`（`is_cache`）/ `external`（`is_external`）**无控件**；`routeName` / `redirect` **完全未覆盖**（`sys_menu` 28 列有这 4 列，表单 19 个字段里没有，`:395-620`）→ 用户无法设置"是否缓存""是否外链""路由名称""重定向"。
⑪ **`permissions` 是"发了没人收"的死字段**：`formData.permissions`（`:946`）进入提交 payload（`:1141`），但 `sys_menu` **无该列**（是 `menu_code`）、`SysMenu` 实体**无该字段** → **静默丢弃**；**「保存并新增」语义也不成立**（`handleFormSaveAndNew`，`:1186-1188` **只调 `handleSubmit()`**，未保留面板）。
⑫ **`checkMenuCodeExists`（`:213-219`）无权限注解 + 本页未使用它**：任何登录用户可枚举权限码；且新增菜单时**不做 `menu_code` 重复校验** → 可造出重复权限码。同时 **`updateSort`（`:171`）存在但前端未接线** → 后端有能力、页面无入口（**拖拽排序**属典型缺口）。
⑬ **无列配置 / 无 `PageConfigPanel` / 无 `storage-key`**（全文件 0 处）→ 13 列硬编码、**且列数组是 `any[]`**（`:849`，类型全丢）→ README §7.2 口径。

### P2（6 条）

⑭ **值域超出前端**：`menu_level` 前端只认 `0=租户级 / 1=系统级`（`:282-299`、`:571-580`），而 devdb 分布为 `0→214`、`1→40`、**`3→124`**、**`4→3`** → 127 行**显示为 `—`**（无标签）；`client_type` 实体注释（`SysMenu.java:112`）列了 6 个客户端，**未含 `pc-admin`（6 行）与 `system-admin`（37 行）**。
⑮ **超管角色码两处口径不一致**：`SysMenuServiceImpl.java:255` 硬编码 `roles.contains("SUPER_ADMIN")`，而 `SuperAdminConfig.java:26` 是 `Set.of("SUPER_ADMIN","admin","super_admin")` → 若超管角色码被配成 `admin`，**菜单树分支与权限缓存分支会走不同路径**；另 **`getAllMenusByClientType` 是死方法**（`SysMenuServiceImpl.java:318-326`，私有且全仓无调用点）。
⑯ **图标选择器只有前 60 个图标**：`commonIconNames = Object.keys(Icons).filter(name => name.endsWith('Outlined')).slice(0, 60)`（`:797`）→ **按 `Object.keys` 顺序取前 60**，非全量；且非法图标名静默返回 `null`（`iconComponent`，`:882-885`）。
⑰ **统计卡口径易误读**：「菜单总数」`menuType !== 2`（`:815`）、「按钮数量」`menuType === 2`（`:816`）→ **两者相加才是总节点数**；且**卡片不显示"总节点数"**。
⑱ **重复实现未收敛**：`views/set/menu-config/index.vue`（80620，362 行）与本页是同一功能的第二份实现，**且自身 400 不可用**（未传 `tenantId`）+ 用 `sort`/不存在的 `perms`（README §2.5 组 C）→ 建议**裁定单一入口**（保留本页，80620 改为跳转或直接下线）。
⑲ **无验收截图资产 / 无模块级 E2E**（`tools/` 下不存在 `e2e-system-*.cjs`）→ README §7.3 已登记。
