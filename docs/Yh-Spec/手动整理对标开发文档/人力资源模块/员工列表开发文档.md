## 1. 页面概述

员工档案是人力资源域的**主数据根节点**：部门/岗位是它的归类维，考勤/请假/薪资/绩效是挂在它上面的行为数据，劳动合同是它的从属档案。本页承担「员工台账查询 + 建档 + 转正/离职状态流转 + 合同查看」四件事。

| 页面 | 地址 | 组件 | 说明 |
|------|------|------|------|
| 员工列表页（**唯一有菜单的页**） | `hr/employee` | `frontend/apps/pc-admin/src/views/hr/employee/list.vue`（518 行） | 原型级台账：原生 `a-table` + 两个弹窗 |
| 伴生页 · 列表重制版（**未挂菜单**） | 无路由记录 | `views/hr/employee/index.vue`（352 行） | 与列表页同业务、字段更多、带 `ErrorBoundary`/`PageContainer`/删除按钮 |

### 1.1 三个 employee 组件的归属关系（**必须先读，否则会抄错文件**）

### 1.2 与整站金标准的关系（**整页未达标**）

> **参考来源**：Odoo 18 HR `https://www.odoo.com/documentation/18.0/`（章节待补充）｜SAP SuccessFactors / S/4HANA HCM `https://help.sap.com/`（章节待补充）｜金蝶 s-HR / 金蝶云·星空 `https://vip.kingdee.com/`（章节待补充）｜用友 DHR / YonSuite 人力云 `https://success.yonyou.com/`（章节待补充）

| 能力 | 业界做法 | 本系统当前 | 差距与建议 |
|------|---------|-----------|-----------|
| **员工主档模型** | Odoo `hr.employee`：`department_id` / `job_id` / `parent_id`（直属上级）/ `work_location` / `contract_type_id` / `date_start`；SAP Employee Central 用 **Info Types（信息类型）**分组存员工数据（个人/地址/银行/合同/薪资…），并支持 **Effective Dating（生效日期 + 历史版本）**——改一条数据是「新增一个版本」，可回溯任意时点 | `hr_employee` **平铺 29 列**单表，无子表、无生效日期、无历史版本，主档**覆盖式修改** | ❌ **最大能力缺口**。建议至少补 `parent_id`（直属上级）、`work_location`（工作地点），并按 §4.2 分区；**历史版本**需引入异动表（见下条） |
| **Job / Position / Employee 三层模型** | SAP：`Job`（职务，跨部门通用描述）→ `Position`（职位，具体编制岗位，**数量受编制管控**）→ `Employee`（人）。同一职位可多人 | `hr_position` 一张表兼作「岗位」，员工用 `position_id` 指过去；**无 Job 层** | ⚠️ 现状可用但粗糙。建议：`hr_position` 明确定位为 Position，如需统一职务名再补 Job 维度；**先补编制维护**（下条） |
| **编制（Headcount）管控** | SAP Position Management 与金蝶/用友的编制管理都强调「编制数 vs 在编数」，**超编要拦截或警告** | `hr_position.quota_count`（编制人数）/ `current_count`（在岗人数）**两列都有，但 `HrEmployeeServiceImpl` 从不维护 `current_count`**，也无超编校验 | **P1**：员工创建/转正（2→1）时 `current_count + 1`、离职（1→0）时 `-1`，并在 `job_key` 写入前比对 `quota_count`；超编按「警告不阻断」起步（与业界一致，硬拦截常见于编制冻结期） |
| **试用期与合同到期提醒** | Odoo `hr.contract` 有 `trial_date_end` + 合同 `date_end` 到期告警；用友有「合同到期提醒」 | `hr_contract` 有 `start_date` / `end_date` / `status`，**无 `trial_date_end`**，且**全模块无任何 `@Scheduled`**（hr-base 内 grep 0 命中） | **P1**：补调度任务（挂在《调度任务模块》上）+ 到期告警；试用期到期可由 `hire_date + 试用月数` 推算起步 |
| **员工自助（ESS）** | Odoo / SAP 均有员工自助门户（查工资条、提交请假、查考勤） | ❌ 无：`hr_employee` **无 `user_id`**，员工没有系统账号 | **P1**：补 `user_id` 关联 `sys_user` + 账号开通/停用动作，才谈得上 ESS |
| **人员异动** | 金蝶 s-HR / 用友 DHR 的核心是**异动流程**——入职 / 转正 / 调岗 / 调薪 / 晋升 / 借调 / 离职 / 退休，每类异动有**生效日期 + 异动记录 + 主档变更历史** | ❌ **完全没有**：无异动表、无异动类型枚举、无生效日期概念；主档只能覆盖式修改，**改完查不到历史**（`hr_employee` 无任何历史表） | **P1（能力缺口第一位）**：新增 `hr_employee_change`（id, employee_id, change_type, effective_date, before_json, after_json, reason, approve_status, operator…）；入职/转正/离职先收口为异动单 |
| **员工档案的字段分组** | 普遍分「基本信息 / 联系方式 / 教育经历 / 工作经历 / 合同信息 / 薪资信息 / 证件附件 / 紧急联系人」（SAP Info Types、金蝶 s-HR 员工卡片） | `hr_employee` **平铺 29 列**；教育经历**只能存一条**（`school` / `major` 单值）；无工作经历表、无附件表 | **P1**：先补齐 `hometown_address` / `current_address` 的录入入口（三套表单全缺）；教育/工作经历多段化与附件表按需新建（勿塞进 `remark`） |
| **离职建模** | 离职是异动单据：离职申请 → 审批 → 最后工作日 → 交接 → 状态变更 → 封存账号 | 只是 `status = 0` + `leave_date = 当天`（`HrServiceImpls.java:87-93`），**无离职类型/原因/交接/最后工作日/审批** | **P1**：按上条异动表承载；「当天」应改为**可填的最后工作日**（当前是系统当天，与真实业务不符） |
| **证件与附件** | 员工档案普遍含身份证正反面、学历证书、体检报告扫描件 | `hr_employee.avatar_url` 是唯一文件列，**无任何附件表** | **P2**：复用既有证件上传模式（见《往来单位证件信息通用组件》`CertUploadList`），上传端点 `/api/file/upload` 已可用（`FileUploadController.java:41,74`） |

**明确不借鉴**：SAP 的多国薪资合规引擎、Odoo 的完整 payroll 本地化包（本系统 `hr_salary_structure` 口径已自成一体的简化模型）、业界界面的视觉样式。

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 下无 `e2e-hr*.cjs`）。落地脚本命名 `tools/e2e-hr.cjs`，覆盖「第 0 节 端点可达性 + 接口 + 直连 DB 对账 + UI + 写库后复原」。
> **第 0 节必须先于一切**：先断言 `/api/hr/employees/page` 返回 **200**（当前为 404），否则后续全部无意义。

### 10.1 第 0 节：可达性（P0 回归）

1. `GET /api/hr/employees/page` → 200（**当前 404**）；`GET /{id}`、`POST /employees`、`PUT /{id}` 均 200。
2. `PUT /api/hr/employees/{id}/status?status=1` → 200（**当前 500 `Invalid bound statement`**）；`GET /{id}/contracts` → 200（**当前 500**）。
3. 全页 UI 打开后 **DevTools 网络面板无 4xx/5xx**、Console **无 error**。

### 10.2 接口验收（目标 ≥ 18 项）

1. `page` 默认查询 200，`total` 与直查 DB 一致（**注意**多租户 `tenant_id` + `deleted = 0` 两个隐式条件）。
2. `pageNum / pageSize` 生效；`pageSize = 1` 时 `records.length === 1`；排序为 `create_time DESC`。
3. `deptId` / `employeeName` / `status` 三个过滤参数**逐个生效**（各自造数验证）。
4. 新增后 **`employee_no` 非空**（号段生效）、**`status = 2`**（强制试用）、DB 可查回。
5. **连续新增 2 条**均成功（验证工号不再撞唯一约束 —— 当前会失败）。
6. 更新后三级回读（DB / 详情 / 列表）一致；未提交字段未被清空。
7. `PUT /{id}/status?status=1` 后 DB `status = 1`；`status=0` 后 DB `status = 0` **且 `leave_date` 非空**。
8. 非法状态迁移被拒（如 `0 → 1`）—— 修复后断言，当前无校验应如实标注。
9. `DELETE /api/hr/employees/{id}` 后列表不出现（`deleted = 1`）—— 补端点后断言。
10. 合同：新增 → 查回 → 终止，`status` 依次为 `1 / 1 / 3`。
11. 编制联动：创建员工后 `hr_position.current_count` +1；离职后 -1；超编时按裁定给出警告或拦截。
12. 导入 / 导出 / 统计端点各 1 项；越权：未登录访问应 **401**（`@SaCheckLogin` 补齐后断言），无权限码用户应 403。

### 10.3 UI 验收（目标 ≥ 15 项）

1. 菜单「人力资源 → 员工管理 → 员工列表」点开渲染列表（**非空白页**）。
2. 外壳为 `ErrorBoundary > PageContainer(full-height) > CategoryListLayout`。
3. 查询区为**横向自适应网格**（非纵向单列），查询项逐个生效（造数验证）。
4. 表格列渲染正确：性别/学历/状态显示**中文标签**而非数字；日期列已格式化；部门 / 岗位列显示**名称**（不是雪花 ID）。
5. 表头齿轮可改列显隐/顺序，刷新后**个人配置保留**；「恢复默认」可用（`default-*-config` 已传）；分页栏为**经典形态**（`.classic-pagination`）。
6. 新增 → 保存 → 列表出现新行（工号自动生成且可见）。
7. 编辑 → 保存 → 列表值更新；**跳转式表单页可达**（`form.vue` 不再落 404）。
8. 转正：`status = 2` 的行显示「转正」，点击后状态变「在职」；离职：`status = 1` 的行显示「离职」，点击后状态变「离职」且出现离职日期。
9. 合同弹窗展示真实合同行（**而非恒为「暂无合同记录」**）。
10. 头像上传成功且回显（断言 `/api/file/upload` 200）。
11. `PageConfigPanel` 可开关查询项/按钮，刷新后保留。
12. 页面控制台无 `ReferenceError`（参见《重构搬迁后必须做运行时验证》）。

### 本页落地

- **外壳**：原生 `a-table` + 自绘页头 → `ErrorBoundary > PageContainer(full-height) > CategoryListLayout`（左树 = **部门**，数据源 `sys_department`，HR 只读引用）+ `BillDetailTable` + `StandardPagination(classic)` + `PageConfigPanel`。
- **列**：24 列（默认可见 12：工号/姓名/部门/岗位/员工类型/入职日期/状态/性别/学历/手机号 + 序号 + 操作；隐藏 12：离职日期/工龄/出生日期/身份证号/毕业院校/专业/邮箱/户籍地址/现居住地址/紧急联系人/紧急联系电话/备注）。`storage-key = hr-employee-table-columns`，页面配置 `hr-employee-page-config`。
- **查询**：关键字（工号/姓名/手机号）、状态、员工类型、岗位、学历、性别、入职日期区间（横向网格，受页面配置控制）。
- **按钮**：新增员工 ｜ 页面配置 / 刷新 / 打印(F8，员工花名册) / 导出（CSV，全量按当前筛选）。
- **表单**：员工档案改为**抽屉 + 分区卡片 + 两列栅格**（基本信息 / 联系方式 / 任职信息），行内校验（姓名、入职日期必填；手机号 / 邮箱 / 身份证号格式）。—— 主数据用分区卡片而非 `BillFormPage`，符合《表单布局选型》。
- **行内动作**：修改 / 合同（增删改 + 终止，真实落库）/ 更多（转正 · 离职 · 异动记录 · 删除）。

- **状态机**（新增）：试用(2)→在职(1)→离职(0)；`0 → 1` 一律拒绝（复职须走专门动作）。`PUT /employees/{id}` 做**字段白名单**，状态类字段不接受表单直改。
- **编制联动**（新增）：建档/调岗/离职后重算 `hr_position.current_count`；岗位下有在岗员工时删除岗位被拒。
- **人事异动**（新增）：`hr_employee_change` 表 + 建档/转正/转岗/离职自动写前后快照 JSON，页面「异动记录」抽屉可查。
