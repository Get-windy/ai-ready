## 1. 页面概述

## 2. 页面截图

**N/A —— 本模块无对标系统截图。**

**原因（本模块的通用前提，本页严格遵守）**：ql361（来肯企汇 v2.2，`22stable.ql361.com`）是**租户级进销存产品**，它对客户暴露的只有「设置」域（`client_type = tenant-admin`）。本页属于**平台控制台**（`client_type = system-admin`，`sys_menu` 实测）——「平台方怎么观测自己数据库的慢查询」——**任何厂商都不会把自己的 SaaS 控制台给客户看**。因此：

- ql361 中**不存在**「慢查询」这个页面（`client_type='system-admin'` 的行不会出现在租户登录的菜单树中），**无可对标截图**；
- **不使用 Odoo / SAP / 金蝶 / 用友的界面截图**（口径见《系统模块/README.md》§5.3：本模块按业界**能力模型**建模，**不照搬任何一家的界面**）；§8 只写**业界能力对标**，逐条标来源与可信度级别。

**本系统截图**：当前无本系统验收截图（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）→ **P2 缺口**（README §7.3）。

**数据现状（devdb 实测 2026-09-18）**：`select count(*) from information_schema.columns where table_name='sys_slow_query'` → **13**；`select count(*) from sys_slow_query` → **0**；`select extname from pg_extension` → **仅 `plpgsql`**。

- 表内 **0 行** → 表格**恒空**（`a-table` 渲染空态）；因 4 张统计卡全部由拉到的记录派生（`index.vue:214-226`），**卡片恒为 `0 / 0ms / 0ms / 0`**；
- 页面**不会报错**：接口 404 被 `catch` 静默吞掉（`:253-255`）→ 用户看到的是「0 条 + 四张 0 卡片」，**与「数据库确实没有慢查询」在界面上完全无法区分**（这是本页最危险的失败模式，见 §9.2）；
- `pg_stat_statements` 扩展**未安装**（`pg_extension` 实测仅 `plpgsql`）→ §8 的业界方案在当前实例上**尚不具备前置条件**；`SHOW shared_preload_libraries` 因当前 DB 角色权限不足（需 `pg_read_all_settings`）**未能读取**，如实标注**未实测**。

### 8.2 业界做法要点（逐条给级，**逐字保留底稿引用**）

1. **「慢」要有阈值定义与两种口径**：①**已完成的贵查询**（`pg_stat_statements` 按 `mean_exec_time` / `total_exec_time` 排序）；②**正在跑的贵查询**（`pg_stat_activity` 中 `state='active'` 且 `query_start` 早于 N 秒）。**「业界两者并存（SAP 即 Expensive Statements + Statements Monitor 两个工具）」**。**A**
2. **按「总耗时」还是「平均耗时」排序会得出完全不同的结论**：`total_exec_time` 找「整体拖累」，`mean_exec_time` 找「单次很慢」，`calls` 找「调用最频繁」。**「页面必须提供三种排序」**。**A**
3. **必须能看「是不是在等锁」**：`pg_stat_activity` 的 `wait_event_type` 取值含 `Lock`、`LWLock`、`IO`、`IPC`、`BufferPin`、`Client`、`Timeout`、`Activity`、`Extension`、`InjectionPoint` —— **「`Lock` 等待是『慢查询』的常见真因」**。**A**
4. **要有「杀掉查询」的出口（并做权限控制）**：`pg_stat_activity` 提供 `pid`，数据库侧对应 `pg_cancel_backend` / `pg_terminate_backend`。**⚠️ 底稿明确标注：本条未直取该页正文，属 D 级提示，实施前须核 PostgreSQL 官方文档对应章节。**
5. **重置粒度**：`pg_stat_statements_reset(userid, dbid, queryid, minmax_only)` —— **「支持只重置某个 query 的 min/max，不必全清」**。**A**
6. **统计会被意外清空**：非干净关闭（崩溃、基础备份、PITR）后「all statistics counters are reset」→ **「页面上要有 `stats_since` 展示，避免运营方误判『没有慢查询』」**。**A**
7. （底稿 §8.6）`pg_stat_statements` 的配置项：`pg_stat_statements.max` **默认 5000**、`track` **默认 `top`**、`track_planning` **默认 `off`**、`save` **默认 `on`**。**A**

## 10. 验收标准

> **前置**：本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下无 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）。建议落地 `tools/e2e-system.cjs`（接口 + 直连 DB 对账 + 写库后复原 + Playwright UI 截屏，参照 `tools/e2e-crm.cjs`）。
> **权限账号**：`admin`（`SUPER_ADMIN`，`sys_user.is_super_admin=t`）用作 200 基线；另需一个**非超管账号**（建议持 `SYSTEM_ADMIN` 或 `DEPT_ADMIN` 角色，二者均**无** `*` 通配）做 403 对账。
> **🔴 本页验收的首要断言（双因恒空专项）**：① 端点**可达性**（当前 404）；② 表**有数据的前置**（当前 0 行）。**两条都必须先登记现状、再给修复后期望**，不得只写「期望 200」。
> **🔴 数据类型注记**：⑪ 的「改库 → 回读 → 复原」**只允许在测试库或自造行上执行，且必须在用例结束前删除复原**；**不得在本页对生产/共享库写入任何数据**（本页是只读页，任何写入都属验收脚本自造数据）。

### 10.1 接口验收（**24 项**）

**可达性与基线（①–⑤）**

① `GET /api/data-source/slow-query/export`（带 `admin` 的 `Authorization: Bearer <token>`）→ **当前实测 404** `{"code":404,"message":"接口不存在: api/data-source/slow-query/export"}`（与 `list` 同包同因）；**修复装配后改断言 200** 且 body 含 `success` / `records` / `total` 三键（`SlowQueryController.java:58-62`）。
② `GET /api/data-source/slow-query/list`（`admin`，带 token）→ **当前实测 404**，报错原文 `接口不存在: api/data-source/slow-query/list`；**修复后改断言 200** 且 body 含 `records` / `total` / `current` / `size` / `pages`（`:41-47`）。
③ **阳性对照**：`GET /api/config/list`（`admin`，带 token）→ **期望 200**（证明「服务在跑、token 有效」，从而把 404 归因到包未装配而非环境问题）。
④ **对照 2**：`GET /api/menu/tree` **不带 `tenantId` 参数** → **期望 400** `缺少必要参数: tenantId`（证明控制器映射存在；本页 2 个端点返回的是 `code:404 接口不存在`，**语义不同**，不得混为一谈）。
⑤ **未挂 token**：上述 2 个端点不带 `Authorization` → **期望 401**（Sa-Token 全局拦截）。

**数据对账（⑥–⑨）**

⑥ **DB 直查对账**：`select count(*) from sys_slow_query` = **0**（实测）→ 断言 `/export` 的 `records` 长度**与直查值一致**（当前两者都为 0；修复后仍须一致）。
⑦ **列数对账**：`select count(*) from information_schema.columns where table_name='sys_slow_query'` = **13** → 断言与实体字段数（13 个）一致；并逐列核对 DDL（`V6.14.0__...sql:291-305`）。
⑧ **索引存在性**：`select indexname from pg_indexes where tablename='sys_slow_query'` → 断言含 `idx_slow_query_ds_id`、`idx_slow_query_time`（DDL `:307-308`）。
⑨ **权限码直查**：`select count(*) from sys_permission where permission_code like 'datasource:slowquery%'` = **0**（当前事实）；补种子后改断言 ≥ 2（`datasource:slowquery:list` / `:export`）。

**权限断言（⑩–⑬）**

⑩ 用 `admin`（SUPER_ADMIN）调 2 个端点 → **修复装配后期望 200**（`*` 通配旁路，`UnifiedPermissionCacheService.java:86`）。
⑪ 用**非超管账号**（无 `*`）调 2 个端点 → **修复装配后期望 403**（两个码在 `sys_permission` 中 0 行）——**这是当前缺陷的显式登记**（补权限种子后应改为 200）。
⑫ **同模块前缀不一致专项**：断言 `select count(*) from sys_permission where permission_code like 'system:datasource%'` = **0**（实测）→ 证明 `DataSouceController` 的前缀同样未落库，两条前缀都需补。
⑬ **超管豁免专项（红线②）**：用 `admin` **重新登录**（拿新 token）后调 `/list` → 断言返回的 `records[].tenantId` **不因会话租户被过滤**（构造 `tenant_id=0` 的测试行时尤为关键）；再用**旧 token**（豁免标记缺失）对比，断言行为差异。

**过滤与分页（⑭–⑱）**

⑭ `dataSourceId=1` → 断言后端 `eq` 生效（`SlowQueryServiceImpl.java:24`）；`dataSourceId` 不传 → 断言**无该条件**（返回全量）。

⑱ **`list` 是死代码专项**：断言 `slowQueryApi.page`（`api/admin.ts:142-145`）在 `views/admin/data/slow-query/index.vue` 中**无调用点**（grep 零命中），页面只调 `exportAll`。

**写库 → 回读 → 复原（⑲–⑳，**仅限测试库 / 自造行，用例结束必须删除**）**

⑲ **正向造数**：在**测试库**对 `sys_slow_query` 插入 1 行（`query_time_ms = 6000`、`tenant_id = 0`、`query_time = now()`）→ 回读 `/export` → 断言 `records` 出现该行且 `total = 1` → **断言统计卡变为「慢查询总数 1 / 最长耗时 6000 / 超过5s 1」**（`:214-226`）→ **用例结束前 `DELETE` 该行并断言 `count(*)` 回到 0**。

**未用端点与缺口（㉑–㉔）**

㉑ `GET /api/data-source/list`（数据源下拉的来源）→ **当前 404**；修复后断言 200 且返回 `records`（用于填充下拉）。

## 12. 剩余缺口（P0 / P1 / P2）

> 口径与《系统模块/README.md》§7 对齐：**P0** = 页面不可用 / 数据不落库 / 越权 / 红线；**P1** = 与业界能力差距大但页面能开；**P2** = 体验与一致性。
> README §3.4-P0-1（4 个包漏配 `scanBasePackages`）、§3.4-P0-2（数据管理 5 页 22 端点全 404）、§3.5（`sys_slow_query` 13 列 / 0 行「僵尸表，恒空」）、§7.2（数据管理 5 页权限码不存在）在本页的具体化见下。

### P0（3 条）

① **端点未装配 → 2 个端点运行期 404（README §7.1-P0-1 / P0-2 的具体化）**：`cn.aiedge.datasource` **不在** `scanBasePackages`（`AiReadyApplication.java:21-96`，grep 命中 0），而 `@MapperScan("cn.aiedge.**.mapper")`（`:117`）是**通配**的 → Mapper 注册、Service/Controller 不注册 → 表现为「表能建、点不动」。**实测证据**：`GET /api/data-source/slow-query/list` → 404 `接口不存在`；阳性对照 `GET /api/config/list` → 200。建议：把该包补进 `scanBasePackages`（README B0 批次），并按 §5.5 修法处理租户豁免。

② **僵尸表：`sys_slow_query` 无任何写入方 → 即使装配好后端也恒空（本页独有的第二重根因）**：全仓 grep `slowQueryMapper` / `SlowQueryMapper` / `sys_slow_query` 的写入点**零命中**（仅读实现、Mapper 声明、实体、DDL、文档 5 处）；DDL 文件**无 `INSERT` 种子**（`V6.14.0__...sql:291-308`）；表实测 **13 列 / 0 行** → **不存在慢查询采集器 / 采集任务**。**后果**：与《连接管理》「只是端点 404」不同，本页是**「端点 404 ＋ 表无写入方」双因恒空**，用户看到的是「0 条 + 4 张 0 卡片」且**无任何提示**。建议：**不要自研抓取器**（§8.5），改读 **`pg_stat_statements` + `pg_stat_activity`**；`sys_slow_query` 属多余表，评估**废弃或改为归档表**（§8.6）。

③ **权限码未落库 → 非超管必然 403（README §7.1-P0-16 / §7.2 同源）**：`datasource:slowquery:list`（`SlowQueryController.java:27`）与 `datasource:slowquery:export`（`:51`）在 `sys_permission`（共 **264 行**）中实测 **0 行**；前端又**零 `v-permission`** → 即使装配好后端，「非超管点了就 403」。建议：补权限种子（迁移），并**统一前缀**（见 P1-④）。

### P1（9 条）

④ **同模块两套权限前缀**：本控制器 `datasource:slowquery:*` vs `DataSourceController` `system:datasource:*`（`DataSourceController.java:27`）→ 两个前缀的码都 0 行，无法统一授权。建议：全模块统一到一个命名域（如 `system:data:slow-query:*`）。

⑤ **列表走 `/export` 全量拉取 + 前端过滤 + 前端分页**：`index.vue:250` 调 `exportAll`（`api/admin.ts:146`），`list` 端点成**死代码**；`SlowQueryServiceImpl.export` 就是 `return list(...)`（`:31-33`）。**无分页、无上限、无时间窗** → 数据一多即**全表进浏览器**。建议：改回 `/list` **SQL 分页**；`export` 若要保留须改为**真导出文件**（当前只返回 JSON）。

⑥ **静默吞错 → 双因恒空被伪装成「没有慢查询」**：`catch { allRows.value = [] }`（`index.vue:253-255`）**无任何提示**；数据源下拉失败仅 `console.warn`（`:265-267`）。这与本模块红线②「页面空白而非报错」同源。建议：补可见错误提示（`message.error` 或页面级 `a-alert`），并区分「接口失败」与「确实无数据」。

⑦ **行内「详情」是纯前端弹窗（桩按钮口径登记）**：`:110` → `:242-245` 不调任何接口。功能上正确（行数据已在内存），但**验收不得断言其产生网络请求**；若未来改为「详情接口」，须同步更新验收。

⑧ **阈值语义反直觉 + 无重置**：过滤是**严格大于**（`:186`）→ 「全部(0)」仍排除 `queryTimeMs = 0` 与空值；默认 `1000` 意味着进页只显示 `>1s` 的记录；查询区**无「重置」按钮**。建议：改 `>=`（「全部」走独立分支）+ 补重置。

⑨ **无实时刷新 / 无轮询**：全页 0 处定时器 → 观测页只能手点刷新。建议：补可开关的自动刷新（默认关）。

⑩ **与业界能力差距最大：无「正在运行的贵查询」、无三种排序、无等锁可见性**：后端固定 `ORDER BY query_time DESC`（`SlowQueryServiceImpl.java:26`），表无 `wait_event_type`、无 `total_exec_time` / `mean_exec_time` / `calls` / `stats_since`（§8.6）。建议：按 §8.5 改读 PG 官方视图后自然补齐；**这些字段都是 PG 视图已有列，不是发明字段**。

⑪ **「杀掉查询」为待取证项**：底稿标 **D 级**（未直取官方章节）→ **首版不提供**。建议：实施前先核 PostgreSQL 官方文档对应章节（`pg_cancel_backend` / `pg_terminate_backend`），并配套权限控制与二次确认。

⑫ **未达金标准路线 A**：无 `ErrorBoundary`、无 `BillDetailTable`（无列配置齿轮）、无 `PageConfigPanel`、无 `storage-key`、无经典分页栏、同时承载前端分页（`:2`、`:40`、`:91-113`、`:203-211`）—— 与 README §7.2「30 页全部无 `PageConfigPanel` / 无 `storage-key` / 无经典分页 / 无列配置齿轮」一致。
