## 项目背景

### 紧急制动教训
根据ERP系统架构现状评估报告（2026-05-04），发现以下核心问题：
1. **缺乏自动化检查工具**：架构规范无法有效执行
2. **手工检查效率低**：容易遗漏问题，检查成本高
3. **重复模块问题**：未能及时发现目录结构违规

### 项目目标
开发自动化检查工具，实现以下核心功能：
1. 目录结构合规性自动化检查
2. 包命名规范自动化检查
3. API路径规范自动化检查
4. 代码质量规范自动化检查

### 2. 技术方案设计

#### 2.1 总体架构
```
┌─────────────────────────────────────────────┐
│             架构合规性检查工具               │
├─────────────────────────────────────────────┤
│                 API网关层                    │
│          ┌─────────┴─────────┐             │
│      CLI接口           REST API接口         │
├─────────────────────────────────────────────┤
│                  服务层                      │
│      ┌─────┬─────┬─────┬─────┐             │
│   目录检查 包检查 API检查 代码检查          │
├─────────────────────────────────────────────┤
│                  引擎层                      │
│      ┌─────┬─────┬─────┬─────┐             │
│  规则引擎 插件系统 缓存管理 报告生成         │
└─────────────────────────────────────────────┘
```

#### 2.2 核心组件设计

##### 2.2.1 规则引擎
- **特性**：支持优先级、条件规则、自定义规则
- **扩展**：插件式架构，支持新增检查规则
- **管理**：规则配置化，支持热更新

##### 2.2.2 缓存系统
- **文件缓存**：基于内容哈希的检查结果缓存
- **内存缓存**：高性能内存缓存，减少IO操作
- **过期机制**：自动清理过期缓存

##### 2.2.3 报告系统
- **多格式输出**：JSON、HTML、Markdown、Console
- **详细诊断**：问题定位、原因分析、修复建议
- **统计分析**：趋势分析、团队报告、改进建议

#### 2.3 技术选型方案

##### 方案A：Java技术栈（推荐）
- **优势**：
  - 与现有ERP技术栈完全一致
  - 团队熟悉，开发效率高
  - Java生态丰富（JavaParser、ANTLR等）
- **技术栈**：
  - 框架：Spring Boot 3.2.5
  - 构建：Maven
  - 测试：JUnit 5 + Mockito
  - 解析：JavaParser + ANTLR

##### 方案B：Python技术栈
- **优势**：
  - 开发速度快
  - 静态分析库丰富
  - 脚本化，易于集成
- **劣势**：
  - 与现有技术栈不一致
  - 团队学习成本

##### 方案C：混合技术栈
- **优势**：
  - 核心引擎用Java，保证性能
  - 插件系统用Python，灵活扩展
- **劣势**：
  - 技术复杂度高
  - 维护成本高
