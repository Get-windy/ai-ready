## 业务规范说明

- **申请主线**：商城注册买家（公司）提交入驻申请 → 本页审核；审核结果写入「状态」字段（通过/驳回）。
- **行级操作**：通过 / 驳回（驳回需填原因，展示给买家）。审核通过后关联「绑定客户」（ERP 客户往来单位）。
- **字段口径**：公司名称（企业主体）、联系人姓名/手机号/地址/qq/微信（联系方式）、营业执照（资质图片）、申请时间（提交时间）。
- **审核状态**：待审核 / 已通过 / 已驳回（本系统 `auditStatus`：0 待审核 / 1 已通过 / 2 已驳回）。

### 当前实现
- **实现文件**：`frontend/apps/pc-admin/src/views/mall/buyer-apply/index.vue`（`defineOptions({ name: 'MallBuyerApply' })`）
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout(:tabs="[]" :show-category-panel="false" :show-table-footer="true") > BillDetailTable(表头 rowNo 列齿轮列配置) + StandardPagination(variant="classic")` + 工具栏（刷新 / 打印(F8) / 导出）+ `handlePrint()` / `handleF8Key()`（F8 全局快捷键监听）。**未接入** `PageConfigPanel`（无页面配置齿轮）
- **Tab**：无 Tab（`tabs=[]`），无左侧分类树（`show-category-panel=false`）；工具栏左侧为**审核统计**（待审核/已通过/已驳回，由 3 次 `GET /user/page`（`pageSize=1`）的 `total` 计数）
- **列**：共 **17 列可配置**（默认显示 11：公司名称、联系人姓名、地址、手机号码、状态、备注、营业执照、绑定客户、申请时间、qq、微信；默认隐藏 6：用户名、昵称、身份、来源、驳回原因、审核时间）；固定列：序号（`rowNo`，fixed left，承载列配置齿轮）、操作（`action`，fixed left）
- **查询条件**：3 项（筛选条件 `keyword`＝公司名称/联系人/手机号、日期范围 `dateRange`、状态 `auditStatus`＝待审核/已通过/已驳回）+「查询」按钮常显
- **功能按钮**：3 个（刷新 / 打印(F8) / 导出），均为**固定按钮**（无 `PageConfigPanel` 可关闭）
- **行级操作**：2 个 —— **通过**（`a-popconfirm` 二次确认 → `PUT /user/{id}/approve`）/ **驳回**（弹窗填原因，必填、`maxlength=500` → `PUT /user/{id}/reject?reason=`）；**仅** `auditStatus === 0`（待审核）行显示，其余行显示 `-`
- **打印(F8) / 导出**：打印＝前端拼装 HTML 打印窗口（表头 8 列：序号/公司名称/联系人姓名/地址/手机号码/状态/绑定客户/申请时间，含筛选条件/打印时间/记录数），F8 全局快捷键触发；导出＝前端拼装 CSV（`买家申请管理_YYYYMMDD.csv`，`\uFEFF` BOM，10 列：公司名称/联系人姓名/地址/手机号码/状态/备注/绑定客户/申请时间/qq/微信）；两者均过滤 `__ghost` 占位行；**无后端打印/导出端点**
- **storage-key**：列配置 `mall-buyer-apply-table-columns`（`global-config-key` 同值，全局配置经 `userPageConfigApi` 以 `col-config` 键持久化）；页面配置：**无**（本页未接入 `PageConfigPanel`）
- **同源关系**：与《买家账号开发文档》共用**同一 `shop_user` 实体与同一组 `/api/erp/mall/admin/user/*` 端点**（`MallAdminController`，`/api/erp/mall/admin`）；视角差异＝**本页以 `auditStatus`（0 待审核/1 已通过/2 已驳回）为主视角做入驻审核**（通过/驳回），买家账号页以 `status`（1 正常/0 禁用）为主视角做账号启停并把 `auditStatus` 作为默认隐藏列
- **数据来源**：`apps/pc-admin/src/api/erp/mall.ts` → `shopUserApi`
  - `GET /erp/mall/admin/user/page`（`pageNum`/`pageSize`/`keyword`/`auditStatus`/`status`）——列表加载 + 审核统计（3 次调用取 `total`）
  - `PUT /erp/mall/admin/user/{id}/approve`、`PUT /erp/mall/admin/user/{id}/reject?reason=`
  - `PUT /erp/mall/admin/user/{id}/status?status=`（API 文件存在，**本页未调用**）

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
