## 1. 页面概述

应用中心是设置模块的**租户应用总览页**：以卡片栅格展示「租户套餐」与「已开通模块（N）」，并提供模块名称 / 编码的本地搜索。
**核心事实**：① `sys_tenant_module` 实测 **0 行** → 「已开通模块」**在任何租户下都恒为空态**；② 整页 **0 个按钮**（无购买、无开通、无续费、无跳转）；③ 套餐区依赖 `platform:tenant-package:list` 权限，**无权限时静默隐藏**（README §7.2 已登记，本文档 §3.4 / §7 / §9 / §12 逐条取证）。

| 项 | 值 | 证据 |
|----|-----|------|
| 页面 / 组件 | `set/app-center` / `views/set/app-center/index.vue`（**237 行**） | `sys_menu.id=80625`；`component=views/set/app-center/index.vue` |
| 外壳 | `ErrorBoundary > PageContainer`（**未传 `full-height`**）+ 一张 `.content-card` + `a-spin` + `a-card` 栅格 | `index.vue:2,3,4,5,7-44,58-107` |
| 后端（模块） | `TenantModuleController`（前缀 `/api/tenant-module`，**2 个端点**，类级 `@SaCheckLogin`） | `core/api/core-api/.../tenant/controller/TenantModuleController.java:24,25` |
| 后端（套餐） | `TenantPackageController`（前缀 `/api/tenant-package`，**6 个端点**） | `core/api/core-api/.../tenant/controller/TenantPackageController.java:19` |

**1.1 与相邻页的分工**

| | **应用中心（本页，80625）** | **租户套餐（系统模块，`system/tenant-package`）** | **模块管理（系统模块，`system/tenant-module`）** |
|---|---|---|---|
| 域 | 设置模块（`tenant-admin`，**租户视角**） | 系统模块（`system-admin`，**平台视角**） | 系统模块（平台视角） |
| 视角 | 「**我开通了什么**」——只读总览 | 「平台定义有哪些套餐」——增删改 | 「平台给租户开通了哪些模块」——增删改 |
| 数据表 | 读 `sys_tenant_module` + `sys_tenant_package` | 写 `sys_tenant_package`（17 列） | 写 `sys_tenant_module`（12 列） |
| 端点 | `GET /tenant-module/list` + `GET /tenant-package/list` | `POST` / `PUT` / `DELETE /tenant-package/{id}` | （本系统未见独立控制器，模块端点只有上述 2 个） |

> **分工结论（现状）**：本页是**唯一的租户侧只读入口**，且**只读**（0 按钮）；平台侧的两个管理页在系统模块中。**本页与「租户管理」的套餐字段存在口径重叠**：ql361 的信息卡展示「到期日期」，而本系统 `sys_tenant.expire_time`（企业信息页的数据源）与本页的套餐/模块数据**互不引用**。

**1.2 本页不提供的能力（如实登记）**

- ❌ **整页 0 个按钮**（`grep -c "<a-button"` → **0**）→ 无「购买记录」、无「设置」、无「开通/续费」、无跳转
- ❌ 无「剩余短信 / 物流查询次数」类**用量卡**（ql361 信息卡有「剩余短信：100条」「物流查询：1000次」）
- ❌ 无「存储空间」环形图（ql361 右侧有：附件 / 图片 / 视频 / 剩余空间）
- ❌ 无「硬件服务」区（ql361：商米L2）
- ❌ 无「短信及其他」增值服务入口（ql361：短信包 / 企汇存储空间 / 物流查询 / 智能排线）
- ❌ 无「客户服务」区（ql361：WMS实施费 / 数据恢复）
- ❌ 模块卡片虽为 `a-card hoverable`（`:68`）但**未绑定任何 `@click`** → 悬停有手型、点击无响应（**交互暗示与实现不符**）
- ❌ 无表格、无分页、无列配置（本页用卡片栅格，故**列配置 N/A**；但无 `PageConfigPanel`）
- ❌ 无 `StandardPagination`、无 `CategoryListLayout`
- ❌ 无「刷新」按钮；失败提示全静默（仅 `console.warn`）
- ❌ 无 `storage-key` / `global-config-key`
- ❌ 前端零权限门控；后端 `system:tenant:query` / `platform:tenant-package:list` 两个权限码**在库中都不存在**

### 3.8 接口调用与降级（源码级）

```js
// index.vue:190-208
async function loadModules() {
  loading.value = true
  try {
    const res: any = await tenantModuleApi.getList(userStore.tenantId || 1)   // :192
    moduleList.value = Array.isArray(res) ? res : res?.data || []
  } catch (e) {
    console.warn('[应用中心] 租户模块获取失败', e)                             // :195-198（静默）
  } finally { loading.value = false }
}

async function loadPackages() {
  try {
    const res: any = await tenantPackageApi.getList()                          // :203
    packageList.value = Array.isArray(res) ? res : res?.data || []
  } catch (e) {
    // 无平台套餐权限（platform:tenant-package:list）时仅展示模块区              // :205-207（注释）
    console.warn('[应用中心] 套餐列表获取失败', e)
  }
}
```

**两处降级都是静默的**：

| 场景 | 表现 | 用户感知 |
|---|---|---|
| `/tenant-module/list` 403 或失败 | `moduleList = []` → 「已开通模块（0）」+ `a-empty` | 与「真的没开通任何模块」**无法区分** |
| `/tenant-package/list` 403 或失败 | `packageList = []` → 套餐区**整块不渲染**（`v-for` 无数据） | 用户**不知道有套餐区这回事** |

- **租户取值口径**：`userStore.tenantId || 1`（`:192`）—— 用 **pinia store** 而非 `localStorage`（与《企业信息》页的 `localStorage.getItem('tenantId')` **口径不一致**，P2）
- 无 `onMounted` 之外的刷新入口（无「刷新」按钮）

### 5.2 模块状态的三态口径（源码级）

```js
// index.vue:166-172
function moduleStatus(mod) {
  if (mod.status !== 1) return { label: '已停用', color: 'default' }
  if (mod.expireTime && new Date(mod.expireTime).getTime() < Date.now()) {
```

## 二轮收口（2026-09-19）

> 本节记录**二轮收口的实际实现**，取代《实现收口》④ 中已被处置的结论（第 2 条「短信用量未接入」）。
> **验收证据**：模块级 E2E `tools/e2e-settings.cjs` → **201 项全过**；本页截图 `tool-results/e2e-settings/ui-80625.png`。

### ① 短信用量：接入真实来源（README §10.5「短信/物流查询未接入」部分闭环）

**实现**：`SetAppCenterController#smsUsage(tenantId)`，返回体 `overview.sms`：

| 字段 | 来源 | 口径 |
|---|---|---|
| `quotaTotal` / `quotaUsed` | `mkt_sms_setting`（按租户单行） | 发送侧 `SmsSendServiceImpl` 每次发送 `quota_used += sent` |
| `quotaRemain` | 计算 | `max(total - used, 0)`；**total 为空 → 余量未知（null），绝不当 0** |
| `monthSent` | `mkt_sms_record`（一行 = 一条短信） | 本月已发送条数（与配额计数器是**两套口径**，两个数字都返回并各自标注来源，不「取其一冒充全部」） |
| `source` | — | `mkt_sms_setting（配额）+ mkt_sms_record（本月发送记录）` |

- **租户安全**：两张表属营销域（`erp-marketing`），此处用 `JdbcTemplate` **只读聚合**，不引入该模块的 Mapper/实体；JdbcTemplate **不走租户拦截器**，故 SQL **显式带 `tenant_id = ?`**。
- **降级**：无本租户行 → `available=false`（前端显示「未配置」，不显示 0 余量）；表缺失/结构不符 → `available=false` + reason，**绝不让概览接口 500**。

### ② 物流查询次数：**仍未接入**（如实保留）

`logisticsQueryUsage()` **不返回任何数字**，只返回 `available=false` + 具体 reason：全库与「物流」相关的表（`dms_logistics_ship` / `erp_sale_order_logistics` / `erp_purchase_order_logistics` / `erp_partner_logistics_ext` / `dms_channel_callback_log`）**均不记录「对外部运单轨迹的查询次数」**；代码侧亦无快递轨迹查询对接实现 → 前端文案**不再只显示含糊的「未接入」**，而是说清「缺少物流查询计量表 / 本系统未对接外部运单轨迹查询」。

### ③ 到期日期：保持「长期有效」（如实保留）

`sys_tenant.expire_time` **三租户全 NULL**（devdb 实测）→ 页面保持「**长期有效（未设置到期日期）**」，剩余天数为空；**明确不采用**「`create_time` + 套餐时长」推算到期日（那是编造）。

### ④ 二轮后**仍然成立**的缺口

1. **物流查询次数仍无计量来源**（见 ②）。
2. **`expire_time` 仍全 NULL**（需平台侧维护）。
3. **购买记录 / 硬件服务目录 / 增值服务商品目录仍无表** → 以「未提供能力」清单如实列出。
4. **模块开通 / 停用 / 续费写入口不存在**（属平台侧授权下发）。
5. **无 `PageConfigPanel`**（本页非数据表列表，N/A）；**无「设置」入口**。
