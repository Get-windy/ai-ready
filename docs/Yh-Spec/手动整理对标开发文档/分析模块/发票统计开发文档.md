## 4. 业务规范

### 统计口径（增值税进销项）

- **销项开票**：销售发票（蓝字=正数，红冲=负数）；`销项开票金额 = 正数开票金额 − 负数开票金额`（净额）；`销项价税合计 = 金额 + 税额`；`销项税额` 按税率拆分。
- **取得进项专票**：供应商**专用发票**（已认证抵扣口径）；同样正/负数分列；`进项开票金额 = 正数 − 负数` 净额。
- **抵扣后应交税额 = 销项税额 − 进项税额**（留抵为负）——本页**首列即为该净额**，是该页的核心输出。
- **按月查询**：税务申报月度口径（与纳税期一致），故本页以「年度 + 月份」为行而非日期区间。
- **正/负数分列而非合并**：便于核对红冲发票张数与金额（税务申报需分别报送正数/负数发票份数）。

### 取数来源与上下游关系

- **取数**：销售发票（销项） + 采购进项发票（进项）；发票模块单据。
- **同源页**：财务域《发票管理》（开票动作端，`invoiceApi` 即指向 `/erp/invoice/*`）；《经营分析》（税前利润口径，不含税）。
- **与本系统关系**：本系统后端的发票域（`/erp/invoice/*`）是**普通发票登记 + 收款跟踪**模型（含 `paymentStatus` 付款状态、`paidAmount` 已收金额），**没有进销项分离、没有正负数分列、没有税额抵扣**——这是本页差距的根因（见第 5 节）。

- **合计行**：取后端 `summary`（按当前过滤范围），净额与应交税额按口径重算（避免对已派生列再求和）。
- **打印(F8) + 导出**：`handlePrint()` + `handleF8Key()`（`onBeforeUnmount` 移除监听）；导出走 `useExport`。
- **取数**：`GET /api/erp/finance/analytics/invoice-stats/page`（**新端点**，`InvoiceStatsController` + `InvoiceStatsServiceImpl`）；
  既有 `/erp/invoice/date-range`、`/erp/invoice/statistics`（按日开票 + 收款进度）**保留未动**。
- **数据源与口径（关键订正）**：原文档记「本系统发票域无进项发票 / 税额抵扣模型」——**该结论已核实为不成立**：
  `invoice` 表（发票域 `cn.aiedge.erp.invoice`，`InvoiceType` 枚举）**已完整支撑对标两组 7 列**：
  - 销项 / 进项由 `invoice_type` 区分（`isSalesType()` 8 类 / `isPurchaseType()` 2 类，与枚举逐一对应）；
  - 正数 / 负数由 `is_credit_note`（红字发票）区分；
  - `subtotal_amount`（不含税开票金额）/ `tax_amount`（税额）/ `total_amount`（价税合计）；期间取 `invoice_date`。
  - 口径：`销项开票金额 = 正数开票金额 − 负数开票金额`；`抵扣后应交税额 = 销项税额 − 进项税额`（留抵为负）；
    剔除 草稿 / 已拒绝 / 已取消 的发票；`invoice.tenant_id` 是 **varchar(50)**（与本系统其余表 bigint 不同），按字符串参数化比较，**未修改** `MyBatisPlusConfig`。
  - 未勾选「进销均无发生的不显示」时，区间内**每个月都出行**（月份骨架由 `generate_series` 生成、指标列 LEFT JOIN 真实聚合，
    **不做任何数值兜底**）——与对标实测（2026-09-15 共 9 条、逐行全 0）行为一致。
- **旧实现遗留**：原「按日开票 + 收款进度」8 列 + 7 张指标卡**已整体移除**（与对标税务口径不是同一模型）。
