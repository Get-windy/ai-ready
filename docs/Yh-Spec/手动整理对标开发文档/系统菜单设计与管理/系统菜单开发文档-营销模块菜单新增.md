> **文档类型：** 菜单变更实施文档
> **版本：** V1.0
> **日期：** 2026-09-18
> **变更执行人：** 智能体（AtCode）按需求整理并执行
> **变更来源：** 营销模块业界对标调研结论（2026-09-18）——「缺口项中确有 2 项需要单开页」

## 一、变更背景与目标

2026-09-18 营销模块 17 页金标准落地后，做了一轮业界对标调研（SAP Commerce / Odoo 18 / 用友畅捷通 / 金蝶云星辰 / 有赞 / 微盟）。结论是：**缺的不是"页面"，而是"能力层"**——绝大部分缺口应补进现有 17 页（促销引擎补促销弹窗与销售结算面板、短信合规补发短信页、积分有效期与会员等级补会员设置页、库存限购补编辑弹窗），**只有 2 项在结构上无法塞进任何现有页面，需要单开页**：

| # | 拟新增页 | 为什么必须单开（不能补现有页） |
|---|---------|------------------------------|
| 1 | **营销自动化** | 形态是「**多条规则 × 多个触发点 × 执行台账**」：规则要能增删改启停、执行记录要能分页筛选与排障。塞进「会员设置」（对标为三分区参数单页）会变成畸形参数页；塞进任何列表页则与既有单据语义冲突。业界同类（有赞营销画布 / 微盟营销中心 / 畅捷通 100+ 场景自动化）均为独立模块 |
| 2 | **储值卡** | 形态是**独立账户 + 单据**：卡档案 → 充值单（含赠送）→ 消费扣减 → 退款 → 余额流水台账。与「优惠券（券形态）」「会员积分（积分为单位）」是三个不同的价值载体，共表会污染口径（业界：金蝶"积分储值"、有赞"储值即会员/充300送60"亦分开建账） |

**目标：** 在营销域「会员中心」分组下新增 2 个菜单页，并如实标注其为本系统建模（对标无对应页）。

## 二、菜单动态管理机制（背景）

本系统菜单由数据库表 `sys_menu` 动态管理，前端 `dynamicRoutes.ts` 将后端菜单树转换为 Vue Router 路由。关键字段（完整 26 列，本轮用到的）：

| 字段 | 含义 | 本轮取值 |
|------|------|---------|
| `id` | 菜单 ID（固定数字编号） | 80303 / 80304 |
| `parent_id` | 父级菜单 ID（0＝顶级） | 60801（会员中心 → 顶级 60008 营销） |
| `menu_type` | 0=目录 / 1=菜单 / 2=按钮 | 1 |
| `path` / `component` | 路由 / 组件路径（前端 `getComponent` 解析） | `marketing/<页名>` / `views/marketing/<页名>/index.vue` |
| `menu_code` | 权限/标识码 | `mkt:auto-campaign` / `mkt:stored-card` |
| `menu_level` | 层级（顶级 0 → 分组 0 → 页面 3，**沿用同组既有值**） | 3 |
| `client_type` | 客户端 | `tenant-admin`（与同租户营销页一致） |
| `display_mode` / `list_path` / `tag_label` | 双入口模式（1=双入口） | 0 / NULL / NULL（**这两个页是列表页，非单据，不适用双入口**） |
| `sort` | 组内排序 | 4 / 5（接在 会员设置 之后） |
| `visible` / `status` / `is_cache` / `is_external` / `deleted` | 可见/启用/缓存/外链/逻辑删除 | 1 / 1 / 1 / 0 / 0 |
| `tenant_id` | 租户（0＝平台级全租户下发） | **0**（与同域 17 页完全一致） |

> **授权说明**：`sys_role_menu` / `sys_tenant_menu` **无营销菜单记录**（超管全量下发），故新增菜单**无需补授权**——与《营销模块 README》既有结论一致。

### 3.2 新增菜单 2：储值卡（80304）

| 项 | 值 |
|----|----|
| 菜单名 | 储值卡 |
| menu_code | `mkt:stored-card` |
| path / component | `marketing/stored-card` / `views/marketing/stored-card/index.vue` |

### 3.3 为什么其余缺口项**不**新增页面（避免误加）

| 缺口项 | 落点 | 判定依据 |
|--------|------|---------|
| 促销引擎（命中/优先级/叠加互斥/条目消耗/行级分摊/服务端重算） | 促销活动编辑弹窗加「叠加设置」分区 + 销售开单结算面板接服务端试算 + 订单详情「优惠分摊」区块 | 配置与现有页同域，单开会造成同一能力两处维护 |
| 优惠券核销闭环 | 「优惠券 → 领用明细」行级补「核销」+ 开单侧选券 | 同上 |
| 短信合规（退订名单/时段/频控/同意留痕） | 「发短信」页 +1 Tab（退订名单）+1 设置弹窗 | 同上 |
| 积分有效期与过期 | 「会员设置 → 会员积分」分区 +2 项；积分明细弹窗 +1 列 | 同上 |
| 会员等级规则 | 「会员设置」+1 分区「会员等级」（复用既有 `/api/erp/member-level`） | 同上 |
| 秒杀/拼团/预售 服务端库存限购 | 后端扣减 + 编辑弹窗展示"已售/剩余"（**不加列**） | 加列会破坏对标列口径（秒杀 5 列/弹窗广告 5 列均为实测逐字） |
| 促销原价合规、手机号脱敏 | 促销表单校验 + 会员列表掩码 | 属现有页的校验/展示细节 |

## 五、落地方案与执行记录

### 5.1 数据库迁移脚本

```
backend/core/api/core-api/src/main/resources/db/migration/V11.377.0__Marketing_Menu_New_Pages.sql
```

- **版本号**：取已执行最高版本（11.376.0）之后一个（**11.377.0**）。
- **幂等策略**：`INSERT ... ON CONFLICT (id) DO NOTHING`——重复执行安全，也不会覆盖运维在库里改过的名称/排序。
- 只插 `sys_menu` 两行，不动任何其它表。

### 5.2 数据库生效

- 目标库：`devdb`（PostgreSQL @ localhost:5432）。
- 生效路径：后端启动时 Flyway 自动执行 `V11.377.0`；执行后回查 `sys_menu` 确认两行存在且字段值正确。
- 回滚方式：`DELETE FROM sys_menu WHERE id IN (80303, 80304);`（两页尚无业务数据，硬删除无副作用）。

### 5.3 生效后的复核口径

```sql
SELECT id, parent_id, menu_name, menu_code, path, component, menu_level, sort, client_type, display_mode
FROM sys_menu WHERE parent_id = 60801 ORDER BY sort;
-- 期望 5 行：会员管理(1) 积分兑换(2) 会员设置(3) 营销自动化(4) 储值卡(5)
```

## 七、后续建议

1. **两页的实现顺序**：营销自动化依赖"券发放 + 短信触达 + 调度"三者稳定，储值卡依赖预付卡合规方案定稿 → 建议**营销自动化先于储值卡**，且储值卡上线前补齐退款规则与合规提示文案。
2. **不要为了"菜单不浪费"而提前建空页**：两页的 `component` 指向的 Vue 文件在实现前**不存在**时，打开菜单会空白。本轮先落菜单（便于排期与验收对齐），**实现时再创建组件文件**；若需在此之前上线菜单，请把 `status` 置 0 隐藏。
3. **新增页同样要过金标准自检**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout` + 经典分页 + `storage-key` 与页面配置分离；`tools/e2e-marketing.cjs` 需相应增加两节（当前 240/240，加页后应同步增长）。
