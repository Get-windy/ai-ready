# 预警查询开发文档

## 页面概述

预警查询是只读的库存预警列表查询页，按仓库/商品/预警类型查询触发库存上下限预警的商品清单。

| 页面 | 地址 | 说明 |
|------|------|------|
| 预警查询页 | http://localhost:5656/erp/alert-query | 查询区 + 左侧商品分类树 + 数据表格 + 分页 |

### 菜单配置（本系统）

| 项 | 值 |
|----|----|
| 菜单 ID | 5017 |
| menu_code | `erp:alert-query` |
| path | `erp/alert-query` |
| component | `views/erp/alert-query/index.vue` |
| display_mode | 0（单入口，只读查询页） |

## 业务规范说明

- 本页为只读查询：列出在预警设置中配置了上下限、且当前库存触发预警（高于上限或低于下限）的商品。
- 预警类型（全部）下拉：推断含 库存不足（低于下限）/ 库存积压（高于上限） 等类型（枚举待复核）。
- 库存上下限的比较口径在预警设置页配置（「库存上下限比较值：账面库存-待发货」，见《预警设置开发文档》）。
- 工作台登录时弹出「预警提醒」（含近效期预警）与本页同属预警体系（`tool-results/ql361/menu-仓储.png` 实据：预警提醒弹窗含近效期预警子标签，筛选项 仓库/商品/品牌/商品状态(近效期商品)/批次条码，列 图片/商品名称/货号/仓库/批号/生产日期/到期日期/有效天数）。
- 数据来源：预警设置（库存上下限阈值在此维护）；采购域联动：采购→采购准备→库存预警补货（按预警缺货生成补货建议）。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），具体见 `docs/Yh-Spec/ql361对标/README.md`。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
