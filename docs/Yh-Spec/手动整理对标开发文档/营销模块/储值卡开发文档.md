## 0. ⚠️ 合规前置（本页与其它页最大的不同）

本页是**预付费**业务，受两组硬性规定约束，**页面必须提供退款入口与告知，不得设计为「只进不出」**：

| 规定 | 要求 | 本页落地 |
|------|------|---------|
| 商务部《单用途商业预付卡管理办法》 | 发卡须备案；规模发卡有认定标准 | 开卡弹窗内置合规提示；充值档位与赠送比例由业务自行控制 |
| 最高法《关于审理预付式消费民事纠纷案件适用法律若干问题的解释》（法释〔2025〕4 号，2025-05-01 施行） | 对"卷款跑路""套路营销"明确责任认定 | **行级「更多 → 退款」** + 全额退款即退卡；退款流水单独记 `REFUND` 类型便于追溯 |

> 未做（如实标注）：**发卡备案流程**属线下行政事项，系统不承载；**备付金/资金存管**不在本模块范围。

## 4. 业务规范

### 账户口径

| 项 | 口径 |
|----|------|
| 卡类型 | `STORED` 储值卡（充值后消费）/ `GIFT` 礼品卡（固定面值消费） |
| 余额 | **面值 + 赠送 + 后续充值（含赠送） − 消费 − 退款**，与流水**恒等**（可对账） |
| 状态 | `ACTIVE` 正常 / `FROZEN` 已冻结 / `USED_UP` 已用尽 / `EXPIRED` 已过期 / `REFUNDED` 已退卡 |
| 冻结门控 | 冻结 / 已退卡 / 已过期 / **超过有效期** 均不可充值消费（解冻后恢复） |
| 余额保护 | 消费与退款均校验余额，**不允许透支**；余额耗尽自动置 `USED_UP` |
| 退卡 | **全额退款**即置 `REFUNDED`；部分退款保留卡 |

### 流水类型（`mkt_stored_card_flow.flow_type`）

`ISSUE` 开卡 / `RECHARGE` 充值 / `BONUS` 赠送（单独一行，便于核算赠送成本）/
`CONSUME` 消费 / `REFUND` 退款 / `ADJUST` 调整（含状态变更留痕）。

> 每条流水都记 **变动后余额**，因此「卡余额 = 末条流水余额」是可验证的不变量。

## 6. 资金闭环（2026-09-18 收口）

### 6.1 记账口径（业财一体，凭证与余额**同事务**）

| 业务 | 借方 | 贷方 | 说明 |
|------|------|------|------|
| 开卡 / 充值 | `1001` 库存现金 / `1002` 银行存款 | `2203` 预收账款 | 预付卡余额是**负债**，收钱时不能确认收入 |
| 消费扣减 | `2203` 预收账款 | `6001` 主营业务收入 | 消费发生时才把负债转成收入 |
| 退款 | `2203` 预收账款 | `1001` / `1002` | 冲减负债、资金原路退回 |
| 赠送（`BONUS`） | — | — | **不产生现金流，不生成凭证** |

- **结算账户**（`settle_account`）：开卡时在卡上记默认账户，充值/退款可在弹窗里逐笔覆盖；
  决定凭证用 `1001` 还是 `1002`。不指定时记账侧回落 `1002`。
- **幂等**：流水 `voucher_no` 已有值则直接返回，重试/补偿不会重复记账。
- **失败即整笔回滚**：凭证生成失败抛 `IllegalStateException`，余额变动一并回滚
  —— 不允许出现「钱动了账没动」。
- **踩坑**：`2203 预收账款` 原先**不在科目表里**（V11.28.0 的手写种子清单漏了它），
  首笔开卡当场报「科目编码不存在: 2203」。已由 **V11.389.0** 补齐，并顺带补齐源码里
  真实引用却同样缺失的 `1123 预付账款` / `1405 库存商品` / `1901 待处理财产损溢`。

### 6.2 定时到期处理

`StoredCardExpireJob`（每日 03:20，种子见 **V11.387.0**）：把已过有效期且仍为 `ACTIVE` 的卡
置 `EXPIRED`，并写一条 `ADJUST` 流水留痕。

> ⚠️ **只改状态、不动余额**：预付卡余额属消费者已付款项，系统不做过期没收；
> 余额处置（退款/续期）必须由人工按合规流程处理。
> 作业默认 `enabled = 0 / STOPPED`，需在「调度任务」页显式启用。

## 7. 剩余缺口

1. **余额消费未从销售单据结转**：储值卡侧的「消费扣减」已闭环记账，但开单侧尚未接
   「储值卡支付」（收款单 → 自动扣卡 + 生成销售凭证链路）。
2. **无充值赠送比例配置**：赠送额由开卡/充值弹窗手工填写；按比例自动赠送（充 300 送 60）属规则化改造。
3. **无会员端查询**：持卡人自助查余额/流水未做（商城/M 端属另一批）。
4. **发卡备案、备付金存管**：属线下行政与资金事项，系统不承载。
