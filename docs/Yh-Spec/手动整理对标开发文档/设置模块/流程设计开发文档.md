## 5. 业务规范

### 5.1 流程类型值域（前端 6 值 ⇄ 后端 6 值）

`APPROVAL_FLOW_TYPE_MAP`（`src/api/workflow/index.ts:145-152`）：`order`=订单审批/blue、`purchase`=采购审批/purple、`expense`=报销审批/orange、`leave`=请假审批/green、`finance`=财务审批/cyan、`custom`=自定义流程/default。
后端 `processTypeToInt`（`WorkflowConverter.java:135-146`）：`leave→1`、`expense→2`、`purchase→3`、`order→4`、`finance|reimbursement→5`、`custom→6`、**其余 → `null`（不过滤）**。
> `PROCESS_TYPE_MAP`（`index.ts:184-191`）是**另一套**中文名（请假/报销/采购/**销售**/**费用**/其他）→ 两套常量文案不一致（P2）。

### 5.2 审批人类型与落库分流

`APPROVER_TYPE_MAP`（`index.ts:154-159`）：`user`=指定用户、`role`=指定角色、`dept_leader`=部门负责人、`applicant_self`=申请人本人。
后端 `approverTypeToInt`（`WorkflowConverter.java:111-120`）：`role→2`、`dept→3`、`leader|dept_leader→4`、`applicant_self→5`、**缺省 `1`（用户）**。
**落库分流**（`WorkflowConverter.java:249-256`）：
```
assignee_type = 2（角色）→ approverIds 写入 workflow_node.role_ids
assignee_type ≠ 2        → approverIds 写入 workflow_node.assignee_ids
```
→ **同一份输入按类型落到两个互斥列**（§11 已写明）。

### 5.3 审批模式与节点类型

- `APPROVE_MODE_MAP`（`index.ts:161-165`）：`single`=单人审批、`or`=或签（任一通过）、`and`=会签（全部通过）；
  落库位置：**`workflow_node.branch_nodes`（JSON）** 的 `approveMode` 键（`Converter.java:258-262`）—— **不是独立列**。
- 节点类型 `nodeTypeToInt`（`Converter.java:87-96`）：`start→1`、`cc→3`、`condition→4`、`end→5`、**默认 `approval→2`**；
  但 `handleSave` 把**所有节点强制写成 `nodeType: 'approval'`**（`designer/index.vue:737`）→ **画布上新增的开始/结束节点不会入库为 `start`/`end`**，`cc` / `condition` 类型**根本产出不了**（除种子数据外）。

### 5.4 保存链路（`handleSave :705-756`）

```
designer/index.vue:744  approvalFlowApi.create(payload)
  → POST /api/workflow/definitions                    WorkflowController.java:82
  → WorkflowServiceImpl.saveWorkflowDefinition:103
      ├─ definitionId 为空 → 新建(:104-121)
      │     insert workflow_definition（process_config = nodesToJson(nodes)，:113）
      │     + mirrorNodes(:119) → 先 delete 后 insert workflow_node(:1005-1013)
      └─ definitionId 非空 → updateWorkflowDefinition(:128)   ← 版本 +1
```

**前置校验（`:706-725`，均 `message.warning` + 自动打开「流程信息」弹窗）**：流程名称非空 → 流程编码非空 → 类型非空 → **至少 1 个有 `nodeName` 的节点**。
**payload（`:729-743`）**：`{ definitionId, name, code, type, description, enabled, version, nodes[] }`；节点**重编号** `node_${idx+1}`、`nodeType:'approval'`、`nextNodeId = idx < len-1 ? node_${idx+2} : '__end__'`。
**成功**：`applyDefinition(saved)`（`:746`）→ `dirty=false`（`:748`）→ `message.success(isNew ? '创建成功' : '保存成功（已生成新版本）')`（`:749`）→ `loadDefinitions()`（`:750`）。
**失败**：`console.warn('[流程设计] 保存流程失败', e)`（`:753`）→ **无用户可见提示**（P1）。

### 5.5 启停的真实语义与「意外递增版本」（P0）

```
designer/index.vue:636   GET  /definitions/{definitionId}
designer/index.vue:640   POST /definitions  { ...detail, enabled }    ← 用「新建」端点做「更新」
  → WorkflowServiceImpl.saveWorkflowDefinition:103
      definitionId 非空 → :128 转 updateWorkflowDefinition（Service 自认：「POST 带 definitionId 即为更新」）
  → version +1，且 process_config / workflow_node 整份重写（mirrorNodes :1005-1013）
```

**后果**：① 每次点启停开关 = **该流程版本 +1**；② 并发编辑中的其他节点改动可能被这次覆盖；
DB 实测旁证：`9101 order_approval` `version = 2`、`2079743652222652418 test_flow` `version = 2`（4 行中有 2 行已是 v2）。
> 前端自认：`message.success('保存成功（已生成新版本）')`（`:749`）；`:630` 注释「后端无独立启停接口」**与事实相反**（后端 `POST /definitions/{id}/disable` 在 `WorkflowController.java:119`，`/publish` 在 `:106`）。

### 5.6 状态值域（启停）

前端只以布尔 `enabled` 表达，后端写入的 `status` **因路径而异**：

| 写入路径 | `enabled = true` | `enabled = false` | 行 |
|---|:---:|:---:|---|
| **新建**（insert 分支） | `status = 1` | **`0`** | `WorkflowServiceImpl.java:118` |
| **更新**（本页启停走的路径：「POST 带 definitionId」） | `status = 1` | **`2`** | `WorkflowServiceImpl.java:151` |
| `POST /definitions/{id}/publish` | `status = 1`（**不动 version**） | — | `:161-169` |
| `POST /definitions/{id}/disable` | — | **`status = 2`**（**不动 version**） | `:172-180` |

读取只有一条映射：`toModel` → `enabled = (status != null && status == 1)`（`WorkflowConverter.java:205`）→ **`0` 与 `2` 在界面上都显示为「停用」，无法区分**。
前端文案：启用 / 停用（`:112`）；tooltip「点击停用」/「点击启用」（`:81`）。`DEFINITION_STATUS_MAP`（`index.ts:193-197`，`0=草稿 1=已发布 2=已停用`）**本页未引用**，但后端**确实会写 0（新建停用）与 2（更新停用 / `/disable`）** → 三值在库里都可达（P2：语义未收敛）。
> ⚠️ **注意**：本页的启停**走的是「更新」路径**（`designer/index.vue:640` 用 `POST /definitions` 带 `definitionId`），所以**从本页停用会写 `status = 2`**；而新建时停用写 `0`。
