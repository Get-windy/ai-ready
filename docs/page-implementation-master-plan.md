## 2. 金标准参照系（销售域模式解剖）

所有表单页改造统一对齐销售订单表单已验证的生产级模式：

1. **头部档案区**：客户/仓库/经手人/日期/类型/收货人——全部档案选择器（可搜可新增），非手输文本
2. **商品明细网格**：扫描枪录入、货号/条码/规格/货位/计价单位/批次/生产日期/保质期/件散数量/多包装，行增删、合计联动
3. **底部功能区**：收款/物流/会员 Tab + 单据备注/买家备注 + 制单人/制单时间/打印次数/源单追溯
4. **金额面板**：数量/商品金额/促销优惠/优惠金额/其他费用/本单金额，实时计算
5. **操作链**：保存草稿(Ctrl+S) → 提交(Ctrl+Enter) → 审核（工作流驱动）→ 红冲/作废 → 打印(F8) → 导入
6. **配置弹窗**：页面配置/录单默认值/打印设置 三 Tab
7. **双入口**：菜单直进表单，[历史] 进列表（列表含状态 Tab/批量操作/列配置）
8. **后端闭环**：状态机 + 单号生成 + 主从事务落库 + 库存/财务联动 + 审计五字段 + 租户隔离

## 4. 通用验收标准（每页面必查，五层闭环）

| 层 | 验收项 | 检查方式 |
|---|---|---|
| 菜单层 | 菜单可点击直达；双入口菜单 [历史] 可进列表 | DB sys_menu 核查 + 路由解析脚本（tool-results/audit_pages.py） |
| 页面层 | 无 mock、无"开发中"占位提示（message.info 级也不允许）；档案字段全部选择器；金额实时计算；快捷键生效 | 代码审查 + 页面实测 |
| 接口层 | 每个操作有真实端点；先 grep 后端核实；禁止造假 | curl E2E 实测 200 |
| 数据层 | 实体-表对齐（Flyway 迁移留痕）；审计五字段；租户隔离 | psql \d+ 核对 + 落库后 SELECT 验证 |
| 业务层 | 单据流转到终态；下游联动生效（库存/应收应付/凭证/审批）；异常有提示且回滚 | 端到端业务场景实测（如：收款单核销→应收余额减少→凭证生成） |

**表单页专项**（对齐金标准 8 要素，见第 2 章）：头部档案区 / 明细网格 / 底部功能区 / 金额面板 / 操作链（草稿→提交→审核→红冲→打印）/ 配置弹窗 / 双入口 / 后端闭环——**逐项打勾，缺项即不通过**。

**报表页专项**：查询条件完整 / 统计卡 / 导出 / 口径说明注释 / 空态展示。

**红线（任一触犯即返工）**：
- 出现 mock/假数据/造假默认值
- 表单页档案字段手输文本（应选择器）
- 金额由前端计算后直接落库未经后端复核
- 新 SQL 未走 Flyway 迁移且未手动执行+登记
- vue-tsc 出现新错误、mvn 编译破坏

## 5. 验收执行方式（PM 检查动作）

每批次交付后，我执行以下检查并出具完成度报告：

1. **结构检查**：重跑 `tool-results/audit_pages.py`（菜单→组件可达性、断点复发检测）
2. **类型/编译**：`vue-tsc --noEmit` 全仓 0 错误；`mvn` 主代码编译绿
3. **E2E 抽测**：每页至少 1 条业务场景 curl 实测（登录→操作→DB 终态核对）
4. **对标打勾**：表单页按金标准 8 要素逐项核对；有截图的页面与截图逐项比对；无截图的按 Odoo 对应模块字段/流程清单核对
5. **报告输出**：批次完成度 %（通过项/总项）、不通过项清单及返工要求
