### 口径说明（多级表头与三维度归位）

- 三 Tab **均无分组表头**（单层列）；`tab2/tab3` 的列集合**完全相同**，仅维度列名不同（`职员编号/职员名称` vs `部门编号/部门名称`）。
- **维度专有列**：`结款方式`、`所属区域`、`默认经手人`、`客户备注`、`客户一票通` 仅存在于 `查应收`（结算单位维度）；`信用额度/可用额度/动态收款期限/固定账期/结算期/联系人/联系电话` 亦为结算单位专有。
- **三组「预收」列并列**：`期初预收 → 本期预收 → 预收余额`（预收款滚动）；`期初预订货款 → 本期预订货款 → 预订货款余额`（预订货款滚动，**默认全隐藏**）。二者是**两种不同的客户预存资金**，不可混用。
- **期初列名差异**：`查应收` 用 `期初应收`/`期初预收`，`职员应收`/`部门应收` 用 `此前应收余额`/`此前预收`——**同一口径的不同命名**（职员/部门视图按「此前」表述，表示期初结转额）。

## 4. 业务规范

### 统计口径（应收滚动）

- **核心恒等式 1**：`应收余额 = 期初应收(此前应收余额) + 本期应收款 − 本期已结(本期收款) − 优惠(结算优惠)`（三 Tab 逐行验证 ✅）。
- **核心恒等式 2**：`期末余额(期末发生余额) = 应收余额 − 预收余额`（三 Tab 多数行成立 ✅；**管理部行例外，差 4,000，疑含预订货款项，待复核**）。
- **预收滚动**：`预收余额 = 期初预收(此前预收) + 本期预收`（高晓丽行验证 ✅）。
- **预订货款滚动**：`预订货款余额 = 期初预订货款 + 本期预订货款`（管理部行 `4,000 + 4,683,884.4 = 4,687,884.4`，实测 `428,343.22` ❌ **不成立**，口径**待复核**）。⚠️ 该列默认隐藏且「预订货款」与「预收」的关系未明，本轮**不做推断**。
- **期初负值**：期初应收为负（实据 -4.9 / -170 / -1,364 / -272,186.12） = 该单位此前多收/预收净额。
- **本期应收款**：期内销售出库/退货净增应收；**本期已结 / 本期收款**：期内收款 + 预收抵扣；**优惠 / 结算优惠**：收款让利冲减。
- **包含已审核未记账收款单/预收款单**：勾选后未记账单据也计入已结（**权责发生 vs 收付实现**口径切换）。
- **结款方式**：`挂账`（赊销）/ `现结`（款到发货）——仅 `查应收` Tab 有该列（实据 `挂账`/`现结`）。

### 取数来源与上下游关系

- **取数**：销售出库单（应收发生） + 收款单/预收款单（已结） + 优惠/结算优惠；
- **行级动作**：`收款` → 收款单表单页（财务域）；`对账` → 该单位/职员/部门的应收明细；
- **同源页**：《销售欠款分析》（职员/区域侧口径，欠款余额与本页应收余额同口径）、《往来余额表》（应收应付净额口径）、《查应付》（供应商侧镜像）。

### 剩余缺口（按本页自身规格＝账表页逐项判定）

1. **6 个查询控件置灰（后端无入参）**：日期类型、结款方式、部门、经手人、「包含已审核未记账收款单/预收款单」勾选（`/erp/finance/auxiliary/balance/page` 无对应参数）。
2. **12 个对标列无数据源、恒空白**：优惠、期初 / 本期 / 余额预订货款、收款合计、信用额度、可用额度、动态收款期限、固定账期、结算期、联系人、联系电话、客户备注、客户一票通、已开票未收款（`normalize()` 未赋值）。
3. **预收余额依赖单页 500 条**：`loadPartnerMap()` 固定 `page=1&size=500`，结算单位超过 500 个时，超出的单位「预收余额 / 期末余额」为空并无法联查对账明细（`index.vue:526-538`）。
4. **合计行两列受分页限制**：预收余额、期末余额按当前已取行求和（四段余额取后端 summary），口径为「当前页求和」而非全量。
5. **对账明细仅「查应收」Tab 可用**：职员 / 部门 Tab 无凭证级明细端点，弹窗内仅提示「凭证级明细端点待补」；且只有按结算单位名匹配到 `partnerId` 时才能联查。
6. **「结款方式」列与筛选均无数据源**：应收台账未落该字段（`normalize()` 未赋值），列恒空。
7. **`tools/e2e-analytics.cjs` 的接口探针路径与实现不一致（工具侧缺陷）**：脚本写的是 `/erp/finance/receivable/page`（实测 **404**），本页实际走 `/erp/finance/receivable/list`（实测 200）；该脚本若执行此项会误报失败。
