## 1. 页面概述

推广分析页是**职员推广成效的漏斗台账**：行 = 一名开通商城推广的职员，列 = 分享次数 / 浏览次数 / 下单笔数 / 下单金额 / 新客注册 五段漏斗指标，末行合计。用于回答「谁在分享、分享带来多少曝光、转化了多少单与多少新客」。**单入口、单视图**（本页**无**页内视图 Tab），形态为「查询区（两行）+ 表格 + 合计行 + 分页」。

| 页面 | 地址 | 说明 |
|------|------|------|
| 推广分析 | `analytics/promotion-analysis` | 单入口单视图漏斗台账（查询方案 + 8 段时间快捷 + 日期/职员/分享类型 + 7 列表格 + 合计行 + 分页） |

单入口：分析 → 采销分析 → 销售分析 → 推广分析。

## 4. 业务规范

### 统计口径（推广漏斗）

- **四段漏斗链路**（列序即链路序）：
  1. `分享次数` —— 职员转发商城商品/店铺链接的次数（行为埋点计数）；
  2. `浏览次数` —— 客户打开被分享链接的次数（曝光计数）；
  3. `下单笔数` / `下单金额` —— 经该链接转化成交的订单笔数与金额（**去重下单笔数 + 金额求和**两个独立指标）；
  4. `新客注册` —— 由该链接带来的新注册客户数（拉新结果）。
- **归因口径**：订单与新客按**分享链接来源**归因到职员；`分享类型` 下拉用于区分不同分享场景（商品分享/店铺分享/活动分享等，**枚举待复核**）。
- **漏斗校验（本期不可用）**：正确口径下应满足 `分享次数 ≥ 浏览次数 ≥ 下单笔数` 且 `新客注册 ≤ 下单笔数` 的数量级关系；本期实测全 0（分享 0 / 浏览 0 / 下单 0 / 新客 0），**无法做任何漏斗不等式校验**，属"无埋点数据"而非"口径正确"。
- **数据范围**：B2B 商城渠道的推广行为；仅统计**开通推广**的职员（本期仅 HC001 一人出现在报表中）。
- **金额口径**：`下单金额` 未标注是否含税/是否含运费——**待复核**（列头 `?` 浮层文案未抓取）。

### 取数来源与上下游关系

- **取数**：商城分享埋点（分享/浏览）＋ 商城订单（下单笔数/金额，按分享来源归因）＋ 商城客户注册（新客数）。
- **与《营销推广分析》的分工**：《营销推广分析》（营销分析组，`analytics/mkt-promote-analysis`）为**营销活动侧**的推广效果；本页为**职员分享侧**的推广效果，二者互补、不重复。
- **下游**：职员推广提成/考核——本系统《业务员提成》《业绩提成中心》的取数候选之一（当前两页均未接入分享漏斗口径）。
- **与《客户活跃分析》的关系**：同属「销售分析」子分组；新客注册与本页关联，存量客户的活跃/流失在《客户活跃分析》。

## 5. 实现差异说明

> 本节按当前源码与真机实测（2026-09-18）回写。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/promotion-analysis/index.vue`。
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout`（单视图，`:tabs="[]"`）+ `BillDetailTable` + `StandardPagination`（`variant="classic"`）。
- **列**：全部 **7 列 / 默认 7 列（全可见）**，与对标逐列一致：职员编号 / 职员名称 / 分享次数 / 浏览次数 / 下单笔数 / 下单金额 / 新客注册；`storage-key` 与 `global-config-key` 同为 `analytics-promotion-analysis-columns`。
- **页面配置**：**有** `PageConfigPanel`（对标有页面配置弹窗实据），同时传两个 `default-*-config`。
- **查询方案**：`shared/QuerySchemeBar.vue`，storage-key `analytics-promotion-analysis-query-scheme`。
- **打印 / 导出**：`handlePrint()` + `handleF8Key()` + CSV 导出。
- **取数端点**：`GET /api/erp/sale/analysis/promotion-funnel/page`（`api/analytics-supply.ts` 的 `promotionFunnelApi`）。
- **后端**：新增按分享人归因的漏斗聚合端点。分享次数 / 浏览次数 / 下单笔数 / 下单金额**取自既有的分享记录表（只读复用，未新增埋点、未新增表）**；下单侧按分享人归因。参数化 SQL 显式带 `tenant_id`。
- **实现口径变化（重要）**：本页此前是「促销活动效果分析」（读 CRM 营销活动表），与对标「**职员商城分享推广漏斗**」不是同一模型；本轮按对标重建为分享人漏斗，取数源随之改为既有的分享记录表。

### 剩余缺口

1. **「新客注册」列无数据源**：全库不存在「分享链接 → 客户注册」的归因链路（无分享来源字段落到客户 / 注册记录上），该列**如实返回 null、前端显示 `-`**，不返回 0 冒充。
2. **对标「指标设置 / 设置」弹窗的字段级明细从未抓取**，未伪造入口。
3. **下单笔数 / 下单金额的归因深度**：依赖既有分享记录里「分享人」与订单的关联强度；若后续需要严格的「链接来源 → 订单」逐单归因，需商城侧补埋点。
