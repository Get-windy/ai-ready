## 业务规范说明

- **退货主线**：商城订单发货后客户申请退货 → 本页受理（审批通过/拒绝）→ 完成。退货类型区分（售后退货）。
- **行级操作**：详情（弹窗）、通过（审批通过）、拒绝（必填原因）、完成（已完成状态可操作）。
- **金额/数量口径**：退货数量（明细退货数量合计）、退货金额（单价×数量合计）、本单金额=退货金额+费用；已结金额=已结算部分。
- **收货**：订货数量/已收数量/未收数量（收货进度跟踪）。
- **关联**：来源订单（来源单据）关联商城订单；结算状态（未结算/已结算）。
- **审批流**：状态流转 草稿→待审批→已审批→已完成→已取消；审批通过后进入完成，完成即办结。

### 当前实现
- **实现文件**：`frontend/apps/pc-admin/src/views/mall/return-process/index.vue`（1506 行）

  - 按单据：列配置 `mall-return-process-table-columns-doc`；页面配置 `mall-return-process-page-config-doc`

  - 已核实后端 `SaleReturnController`（`/api/erp/sale/return`）上述 7 个端点全部真实存在（`page` / `page-detail` / `{id}` / `{id}/items` / `{id}/approve` / `{id}/reject` / `{id}/complete`）

- 依据 ②（真实数据源）：该列在 `V8.99.9` 建表即存在，有真实写入口，且已被 `/page`（实体字段）与 `/page-detail`（DTO `approvedNote`）透出；
- 依据 ③（备选排除）：`internal_note`（V9.53.0）语义为「内部备注」，不是审核环节产物，故不采用；`approvedNote` 同时承载
  「审批意见」与「拒绝原因」，拒绝后该列会被拒绝原因覆盖（见「剩余缺口」）；
- 前端列 key 直接使用 `approvedNote`（title 仍为「审核备注」），不做同列别名伪装。

### 剩余缺口

> 本轮已闭环（原第 3、4、6 条，及第 5 条中按单据/按明细可闭合部分）已从本清单移除，闭环依据见上「后端改动（本轮）」。

1. **独立商城退货后端仍无映射**：前端 `api/erp/mall.ts` 的 `mallReturnApi` 声明了 `GET /erp/mall/admin/return/page`、`GET /erp/mall/admin/return/stats`、`GET /erp/mall/admin/return/{id}`、`PUT /erp/mall/admin/return/{id}/approve`、`PUT /erp/mall/admin/return/{id}/reject`、`PUT /erp/mall/admin/return/batch-approve`、`PUT /erp/mall/admin/return/batch-reject`，但**后端全库无该路径映射**（`MallAdminController`（`/api/erp/mall/admin`）只有 `config`/`user/*`/`banner`/`template/list`/`product/*`/`order/*`，无 `return/*`；已复核全库 grep 无 `admin/return`、`return/page`、`return/stats`）→ 页面调用 404，或继续复用销售退货申请单（本页现走后者）。
2. **批量审批未接线**：`mallReturnApi.batchApprove` / `batchReject` 已声明但页面未接入，工具栏也无批量按钮 → 若业务需要批量通过/拒绝，待后端补齐后接线。（注：erp-sales 侧 `POST /erp/sale/return/batch-approve` 已存在且可用，但本页工具栏对标按钮栏（配置/刷新/打印/导出）无批量按钮，未接入。）
3. **「退货类型」筛选未接线 + 列无字典**：按单据 `returnType` 查询项已渲染（自由文本输入），但后端 `erp_sale_return.return_type` 为 `INTEGER` 枚举且**全库无该表字典**（`erp_sale_return_doc` 注释为 `0-质量问题/1-错发退货/2-其他`，`erp_purchase_return` 为 `1-质量退货/2-数量退货/3-其他退货`，两者不一致，不能推定）→ 直接传参会 400，故本轮**不传参、不接线**；同时列表「退货类型」列 `RETURN_TYPE_MAP` 为空，当前渲染原始数字。待确定字典后改下拉并接线。
4. **审核备注的语义边界**：以既有 `approved_note` 承载（见上「审核备注结论」），但该列同时被 `approve(note)` 与 `reject(reason)` 写入，**拒绝后审批意见会被拒绝原因覆盖**；如需区分「审批意见 / 拒绝原因」需新增列，本轮不新建。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
