运费设置是**商城配送方式与运费规则配置中心**：配置是否自有配送、启用物流、物流方式/运费模板，以及到店自提（提货地址）。**单入口，配置/表单型页面**（无数据表列表）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 运费设置 | `mall/freight-config` | 配置/表单页（左侧 2 子项导航 + 右侧配置表单 + 底部「保存」） |

单入口：商城 → 商城设置 → 运费设置。

- 实测实据：页面左侧 **2 个子项导航**：物流 / 到店自提。右侧为当前子项配置表单，底部「保存」按钮。
- ⚠️ 加载说明：进页面出现「**网络资源请求失败，请关闭此页面重新打开或刷新再试**」弹窗（红叉+「我知道了」按钮）；「物流」子项的物流方式/运费模板数据区因网络资源失败**未加载**。

## 业务规范说明

- **配送方式**：自有配送（商家自配送）与启用物流（第三方物流）两种；对应配送方式/物流公司/运单号/运费/运费承担方在商城订单侧落地。
- **运费规则**：本页配置商城配送方式（物流/到店自提）；运费模板/计价规则（如按重量/件数/金额阶梯）对应商城订单的运费计算。
- **到店自提**：开启后买家可线下门店提货；需维护至少 1 条提货地址（联系人/联系电话/提货地址），否则影响买家商城下单。
- **关联**：运费设置联动商城订单的配送方式/物流公司/运单号/运费/运费承担方/代收金额（见「订单处理」文档）。

## 实现差异说明

**实现文件**：
- 前端：`frontend/apps/pc-admin/src/views/mall/freight-config/index.vue`
- API：`src/api/erp/mall.ts`（`shopConfigApi`：`GET/PUT /erp/mall/admin/config`）
- 后端：`ShopConfig` 实体（`/erp/mall/admin/config`）

### 页面对齐（已建成：单表单 `PageContainer` + antdv `a-form`）
- **单表单（2 字段）**：免运费金额（freeShippingAmount）、固定运费（freightAmount）；顶部 alert 说明规则（订单满免运费金额免运费，否则按固定运费；免运费金额=0 全部免运费）+ 当前规则预览。**未对齐金标准 2 子项（物流/到店自提）**。
- **无左侧子项导航**：当前为单卡片表单；金标准为物流/到店自提 2 子项。
- **字段差异**：本系统「运费设置」用的是**简单固定运费/免运费金额**模型（无配送方式、无物流模板）；金标准为「配送方式启用 + 物流模板计价 + 到店自提提货地址」。本系统未实现 自有配送/启用物流/物流方式模板/到店自提/提货地址 等。
- **数据模型**：3 个页面（基础设置/店铺设置/运费设置）共用**同一个 `ShopConfig` 单行实体**（含 freeShippingAmount/freightAmount 两个运费字段）。

### 待完善（非阻塞 · 建议对齐金标准）

2. **物流子项补齐**：自有配送/启用物流开关 + 物流方式/运费模板数据区（计价规则：按重量/按件/按金额阶梯），对齐 gql361 运费模板。

## 业界对标 / 跨模块 / 最终裁决

- **业界对标**：商城「运费设置」以配送方式（物流/到店自提）与运费模板（计价规则）组织；本系统「免运费金额/固定运费」属**简化固定运费模型**，仅适用于统一运费场景，不支持物流方式/计费模板/到店自提。
- **跨模块**：物流模板与商城订单「配送方式/物流公司/运单号/运费/运费承担方/代收金额」联动（见「订单处理」）；到店自提与商城订单「提货门店/地址」、ERP 门店/仓库主数据联动。
- **最终裁决**：本页不存在可配置列的数据表，**无列/页面配置弹窗**（配置/表单型）。金标准应按「物流/到店自提」2 子项结构对齐（含物流模板数据区），当前单表单「固定运费」为占位/简化实现。**注意**：金标准「物流」子项的物流方式/计费模板数据区因对标系统网络资源失败未能实测到字段，需后续补抓。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
