## 页面概述

渠道配置是**外部平台渠道对接配置中心**：维护各外部平台（电商/社交/自有/ERP）的渠道主数据，含 API 端点、应用密钥、同步开关/间隔，并支持一键初始化连接、手动同步。**单入口，列表型 + 新增/编辑表单（弹窗）**；本轮已升级为金标准列表（服务端分页，`GET /api/trade/channel/page` 取代原 `listEnabled` 一次性返回全部启用渠道）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 渠道配置 | `trade/channel/config` | 列表页（服务端分页）+「新增渠道」弹窗表单 |

单入口：交易模块 → 外部平台 → 渠道配置。

- 实测实据（本系统实现）：渠道列表走服务端分页（后端 `GET /api/trade/channel/page`）；共 **11 列可配置**（默认显示 8 / 默认隐藏 3）+ 固定列「序号」「操作」；顶部工具栏含「新增渠道」主按钮与 刷新 / 打印(F8) / 导出，右侧为「页面配置」齿轮；查询条件 4 项（渠道 / 类型 / 同步开关 / 启用状态）。
- 渠道编码枚举：TAOBAO/JD/PDD/DOUYIN/WECHAT_MINI/SELF_MALL/POS/ERP_API。渠道类型枚举：ECOMMERCE/SOCIAL/SELF/ERP。

## 业务规范说明

- **渠道主线**：外部平台（电商/社交/自有/ERP）接入 → 本页配置 API 端点与密钥 → 初始化连接 → 同步订单/商品/库存到本系统。渠道主数据驱动「外部订单/库存同步/API监控」三页的 `channelCode` 下拉与数据归属。
- **连接状态**：配置了 accessToken 视为「已连接」；未配置视为「待配置」，只能点「初始化」拉取 accessToken。
- **同步开关/间隔**：syncEnabled（1/0）+ syncInterval（分钟）控制定时任务对渠道的订单/库存拉取与推送频率。
- **操作**：初始化=打通渠道连接（换取 accessToken）；同步=立刻从外部平台同步订单/商品到本系统，返回 `{syncedOrders, syncedProducts, message}`。
- **渠道类型映射**：ECOMMERCE=淘宝/京东/拼多多；SOCIAL=抖音/微信小程序；SELF=自有商城/POS；ERP=ERP对接。
- **下游**：渠道配置 → 外部订单（接收/转换外部订单）→ 内部订单；库存同步（推送本系统库存到外部平台）。

### 后端改动（本轮）
- **新增** `GET /api/trade/channel/page`（`ChannelConfigController`）：参数 `pageNum`(默认1)、`pageSize`(默认20)、`keyword`（渠道编码/渠道名称）、`channelType`(ECOMMERCE/SOCIAL/SELF/ERP)、`syncEnabled`(1开/0关)、`status`(1正常/0禁用)；服务层 `pageChannels`。
- **新增** `GET /api/trade/channel/{id}/secret` — 查看渠道密钥（**脱敏**）：`appSecret`/`accessToken`/`refreshToken` 一律脱敏返回（保留前 2 位 + 后 2 位，中间 `****`；长度 ≤6 时全掩码 `******`），另返回 `appSecretConfigured`/`accessTokenConfigured`/`refreshTokenConfigured` 布尔值；**不返回明文**；同时返回 `id`/`channelCode`/`channelName`/`appId`/`tokenExpireTime`。
- **已有端点（本轮未改）**：`POST /`、`PUT /{id}`、`DELETE /{id}`、`GET /{id}`、`GET /code/{channelCode}`、`GET /enabled`、`POST /{id}/toggle?enabled=`、`POST /{id}/initialize`、`POST /{id}/sync`（返回 `{syncedOrders, syncedProducts, message}`）。
- **新增** `GET /api/trade/channel/stat` — **真实聚合端点**（单条 `COUNT + FILTER` SQL，`deleted = 0`，租户过滤）：返回 **`total`（渠道总数）/ `enabledCount`（status=1）/ `syncEnabledCount`（sync_enabled=1）/ `abnormalCount`（已禁用或令牌已过期）**；**注意：该端点不返回「已连接（accessToken 非空）」口径**，故前端第 2 张卡片由「已连接」改为后端真实提供的「异常（abnormalCount）」。已于本轮接入前端（本轮前端改动）。
- 后端落位：实体 `ExternalChannelConfig`；表 `external_channel_config`（迁移 `V8.14.0__Multi_Channel_Integration_Tables.sql`）；渠道适配器 `core/base/core-base/.../trade/channel/`（`ExternalChannelAdapter` / `TaobaoChannelAdapter` / `ErpApiChannelAdapter`）。
- 其他本轮改动（与本页基本无关）：`PaymentController`/`RefundController`/`ReconciliationController` 扩参 + 4 个 stat 端点；`ExternalOrderController` 补 `/page`、`/stat`、`/{id}/retry`、`/pending-count`；`InventorySyncController` 补 `/stat`、`/{id}/retry`；迁移 `V11.361.0`（`mall_keyword.remark`）、`V11.361.1`（`payment_reconciliation.handle_method`）、`V11.361.2`（`refund_request.process_time`）、`V11.361.3`（交易模块金标准字段）、`V11.361.4`（`refund_request.approver_name`）。

### 剩余缺口
1. **后端导出端点仍缺**：导出为前端拼装 CSV（非 xlsx），无 `/api/trade/channel/export`。
2. **「已连接」口径无聚合来源**：后端 `stat` 只提供 `abnormalCount`（禁用或令牌过期），无「accessToken 非空数」；第 2 张卡片因此改为「异常」（如需「已连接」聚合，属后端待补项）。
3. **密钥轮换/重置无独立端点**：仅能通过「配置」弹窗重填 App Secret 后保存；`accessToken`/`refreshToken` 无页面入口可重置。
4. **既有端点未接入本页**：`GET /api/trade/channel/{id}`、`GET /code/{channelCode}`、`GET /enabled` 在 API 文件中存在但本页未调用（`listEnabled` 已被 `/page` 取代，保留为「开放侧/其他页使用」）。
5. **同步开关与启用状态共用同一端点（后端待拆分）**：后端**无独立 sync 开关端点**；`POST /{id}/toggle?enabled=` 仅切换 `status`，而行内「同步开关」`<a-switch>`（绑定 `syncEnabled`）也调该端点——**本页保留现状（不造端点）**，因此切换后列表刷新时该开关仍显示库中 `syncEnabled` 原值；`syncEnabled` 的真实写入口是「配置」弹窗保存（update）。

## 对标判断 / 业界标准 / 跨模块

- **对标判断（ql361 实测）**：`22stable.ql361.com` 顶栏「商城」菜单下为 订单处理（订单处理/退货申请处理）、基础业务（商品上架/单位显示/买家申请管理/买家账号/商品组合）、商城设置（基础设置/店铺设置/运费设置/商城装修/公告设置/关键词库）；「销售」「设置」菜单亦未见 渠道配置/外部订单/库存同步 相关页。**ql361 未见到独立页**。ql361 的「设置→系统配置→支付配置」为微信公众号绑定/支付方式/场景配置/在线退款（在线支付通道），与本页「外部平台渠道（电商/社交/ERP）API 对接」**概念不同**，不构成对标。
- **业界标准**：外部平台渠道对接（淘宝/京东/拼多多/抖音/微信小程序等）业界通常采用「渠道主数据 + 授权凭据 + 同步任务」三要素：渠道编码/渠道类型/API端点/AppID/AppSecret/访问令牌/刷新令牌/同步开关/同步间隔/最后同步——与本系统 `external_channel_config` 表结构一致。
- **跨模块**：本页 `channel_code` 驱动 外部订单（`external_order_raw`）、库存同步（`inventory_sync_record`）、API监控（`api_access_log`）三页；渠道适配器（Taobao/ErpApi）为多态策略，外部平台各自实现 `ExternalChannelAdapter`。
- **最终裁决**：本页为**本系统独有页**，ql361 无对应，按本系统实现+业界标准描述。存在数据表（列表型），**本轮已升级为金标准列表**：`CategoryListLayout` + `BillDetailTable`（表头 rowNo 列齿轮列配置）+ `StandardPagination` + `PageConfigPanel` 页面配置；字段取自本系统实测源码，未臆造。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
