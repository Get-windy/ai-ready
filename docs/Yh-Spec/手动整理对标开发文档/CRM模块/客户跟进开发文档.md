## 1. 页面概述

本页是 **CRM 跟进记录台账**：把所有「已发生的客户跟进」按时间倒序铺开，并提供**新建跟进**入口。

| 页面 | 地址 | 组件 | 行数 | 说明 |
|------|------|------|:----:|------|
| 客户跟进（本页） | `crm/customer-follow` | `views/crm/customer-follow/index.vue` | 282 | `ARReportPage`（**路线 B**）外壳 + 9 列表格 + 1 个「新建跟进」弹窗 |
| 客户（兄弟页） | `crm/customer/index` ↔ `crm/customer/form` | `views/crm/customer/{index,form}.vue` | 1620 / 116 | 客户台账；其行操作「跟进」打开**另一套**跟进弹窗（§1.1） |

> **单入口提醒**：本页 `display_mode = 0`、`tag_label = NULL`、`list_path = NULL`（devdb 实测）—— **没有配对标签页**，与「客户/线索/商机/合同」（主 path 指列表、标签指表单）及「报价单/发票」（主 path 指表单、标签指列表）**都不同**。

### 1.1 ⚠️ 本页与「客户」页内嵌跟进弹窗是**两套并存实现**（P0，必读）

同一个业务对象（客户跟进），存在**两条互不相通的写入路径**：

| | **A. 本页「新建跟进」** | **B. 客户页行操作「跟进」**（`customer/index.vue:614-689`） |
|---|---|---|
| 入口 | 页头 `新建跟进` 按钮（`:13-23`） | 列表/看板行操作（`:303`、`:415`），权限码 `crm:customer:follow` |
| 端点 | `POST /api/crm/followUp`（`api/crm.ts:359-361`） | `POST /api/customer/{customerId}/follow`（`api/customer.ts:156-158`） |
| 后端 | `CustomerFollowUpController.java:46-52` | `CustomerController.java:158-167`（**同一张表**） |
| 采集字段 | 客户/类型/联系人/电话/日期/内容/结果/下一步/下次跟进（9 项） | 类型/内容/结果/下次跟进时间（4 项） |
| **实际落库** | `customer_id`、`customer_name`、`follow_up_type(+desc)`、`contact_name`、`contact_phone`、`follow_up_date`、`content`、`follow_up_result(+desc)`、`next_action`、`next_follow_up_date` | **只有 `customer_id` + `content`**（其余字段名不匹配被**静默丢弃**） |
| 校验 | 客户必选 + 内容必填（`:235-242`） | 仅内容必填（`:1168`） |

**B 路径字段名错配（P1，已核到行）**：客户页提交 `{customerId, followType, content, result, nextFollowTime}`（`customer/index.vue:1171-1177`），而实体字段是 `followUpType` / `followUpResult` / `nextFollowUpDate`（`entity/CustomerFollowUp.java:30,44,46`）；前端 `FollowRecord` 接口同样按错名声明（`api/customer.ts:45-55`）。全仓**只有** `erp-supplier-portal` 的 yml 显式设 `fail-on-unknown-properties: false`（Spring Boot 默认即关闭该特性）⇒ **未知字段被静默忽略、不报错也无日志** ⇒ 从客户页录入的「类型/结果/下次跟进时间」**全部丢失**。

> **后果**：同一张表里，A 路径的行有类型/结果，B 路径的行两列为 `NULL`；本页「类型」「结果」对 B 路径数据恒显示 `-`（兜底 `:154-156`），**数据上无法区分「没填」与「被吞」**。
> **收敛建议（P0）**：① 客户页跟进弹窗**改为复用本页弹窗组件**（或跳本页并带 `customerId`，本页已支持该查询项）；② 后端 `/customer/{id}/follow(s)` 保留兼容但前端只留一套；③ 删改 `FollowRecord`/`FollowQuery` 两个错名类型。

### 3.5 客户下拉（本页唯一选项数据源）

```ts
onMounted(async () => {                                     // :271-281
  try {
    const list = await crmCustomerApi.dropdown()             // GET /api/customer/dropdown
    customerOptions.value = (Array.isArray(list) ? list : []).map(c => ({ label: c.name, value: c.id }))
  } catch (e) { console.warn('[客户跟进] 客户下拉获取失败', e) }
```

| 项 | 实情 |
|----|------|
| 端点 | `GET /api/customer/dropdown`（`api/crm.ts:424-426` → `CustomerController.java:101-120`） |
| 后端过滤 | `select id, customer_name` + **`status = 1`** + **`LIMIT 200`**（`:107-112`） |
| 返回类型 | 裸 `List<Map{id,name}>`；`id` 是 `Long`，被全局 `ToStringSerializer` 序列化为**字符串**（`JacksonConfig.java:18-25`）。前端 `{ id: number }` 声明与运行期不符（`api/crm.ts:424`），`createForm.customerId` 也声明为 `number`（`:210`）—— 因全用 `===`/`!` 判定，**当前不报错**，但类型契约是错的 |
| 分页 / 搜索 | **无分页**，固定 200 上限 → 超 200 家时**下拉选不到全部客户**（无提示）；搜索是前端 `:filter-option`（`:170-172`）本地按 label 过滤，后端 `keyword` **未传** |
| 失败处理 | **只有 `console.warn`**（`:279`）→ 界面无提示，用户只见空下拉，点保存报 `请选择客户` |

> **🔴 P0 连锁：下拉可能是空的（本页不可用的直接原因）**
> `dropdown` 硬过滤 `status = 1`（`CustomerController.java:111`），而 **`crm/customer/index.vue` 的客户表单把「正常」写成 `status = 0`**（弹窗默认 `status: 0`，`:1053-1056`；状态字典 `正常=0 / 停用=1`，`:879-882`；渲染 `status === 0 ? '正常' : '停用'`，`:748`）⇒ **从客户页新建的「正常」客户不会出现在本页下拉里** ⇒「新建跟进」永远选不到客户。
> 反证：devdb 实测 `crm_customer.status` 的**列默认值是 1**，与 `dropdown`、`客户分级`页、`客户分析`页、`客户表单页`的「1=正常」一致 —— **只有客户列表页那一套是反的**。该 P0 已在《CRM模块/README.md》§7 登记，本页是**直接受害方**。

### 7.1 `crm_customer_follow_up`（**29 列**，devdb 实测 2026-09-18）

|----|------------|------|
| `id` | `bigint`，`nextval(...)`，**PK** | 自增（非雪花）→ 前端用 `number` 传 id 安全 |
| **`tenant_id`** | **不存在** | 🔴 见 §7.2 |
| `follow_up_code` | `varchar` **NOT NULL**，`uk_crm_follow_up_code` UNIQUE | §5.2 序号冲突会打到该约束 |

| `follow_up_date` / `next_follow_up_date` | `date`，**可空** | 未填 → 排序坑（§3.4） |

| `follow_up_type` / `follow_up_result` | `integer`，可空，**无默认** | 无字典表、无 CHECK |
| `deleted` / `version` | `integer` **NOT NULL DEFAULT 0** | 实体 `@TableLogic` / `@Version`（`CustomerFollowUp.java:72-76`）⇒ 逻辑删与乐观锁**均不会 NPE**（对比《商机阶段》页 `deleted` 可空 NPE）✅ |
| 审计 4 列 | `created_at`/`updated_at` `timestamp` DEFAULT `CURRENT_TIMESTAMP`；`created_by`/`updated_by` `varchar` 可空 | ⚠️ `updated_at` **不随更新刷新**、`created_by`/`updated_by` **永远为 `NULL`**（见下） |

> **⚠️ 审计列自动填充不生效（P2，跨表共性）**：实体标了 `@TableField(fill = FieldFill.INSERT)` 的 `createdBy`/`createdAt`（`:60-64`），但全仓 `MetaObjectHandler` 只 `strictInsertFill` **`createTime` / `updateTime` / `tenantId`** 三个字段名（`MyBatisPlusConfig.java:170-173,190`）—— 与 `createdAt`/`createdBy` **名字对不上** ⇒ 填充值被忽略；`created_at` 靠 **DB 默认值**落地，`updated_at` 在 `UPDATE` 时**保持插入时刻**，`created_by`/`updated_by` 恒 `NULL`。**跟进记录因此没有「谁录的 / 最后谁改的」审计**（与 §3.4 同源）。

### 7.2 🔴 本表**没有 `tenant_id` 列**，但**未登记进租户忽略名单**（P0）

| 证据 | 内容 |
|------|------|
| 建表迁移 | `V9.11.0__Create_CRM_Core_Tables.sql:142-176` 无 `tenant_id`；同文件的 `crm_customer`、`crm_customer_pool` 都有。devdb 实测 `information_schema.columns` 亦无该列，`select count(*) … where tenant_id=1` → **`ERROR: 字段 "tenant_id" 不存在`** |
| 忽略名单 | `MyBatisPlusConfig.IGNORE_TENANT_TABLES`（`:32-66`）**不含**本表（也不含 `crm_customer_lead`、`crm_customer_opportunity`） |
| 拦截器 | `ignoreTable()` 只跳过「名单内」或「表名无下划线」（`:137-141`）→ 本表两条都不占 ⇒ **会注入 `AND tenant_id = x`** |
| 触发条件 | 登录态下 Sa-Token 会话含 `tenantId`（`SysUserServiceImpl.java:83` 登录时写入；`MyBatisPlusConfig.java:88-107` 读取）→ `AiReadyTenantLineInnerInterceptor.shouldSkip()` 为假（`:31-41`）→ 正常注入 |
| **预期表现** | `GET /api/crm/followUp/page` → SQL 报错 → 页面表格显示 `查询失败，请检查网络后重试`（`ARReportPage.vue:303`） |

> **口径声明（诚实标注）**：本项为**源码静态取证 + devdb 列实测 + 迁移文件三方互证**，**尚未真机复现**（避免与并行会话争抢共享 dev 环境登录态）。**验收第一步必须真机复现**。修复二选一：① 补 `tenant_id`（出迁移回填存量行）；② 把三张无租户列的 CRM 表加入 `IGNORE_TENANT_TABLES`（可立即止血，语义为「本表不做租户隔离」）。**同类先例**：《_开发指南-金标准》陷阱 15（`shop_template`）。
> **同源风险（跨页，登记备查）**：`crm_customer_lead`、`crm_customer_opportunity` 同样**无 `tenant_id`** 且未登记忽略 → 线索页/商机页 `/page` 存在**同一模式**的问题（由各自文档跟踪）。

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-crm*.cjs`）。落地脚本命名 `tools/e2e-crm.cjs`（界面 + 接口 + 直连 DB 对账 + 写库后复原）。
> **前置**：两表当前**均为 0 行** → 必须先造客户（`status=1`）+ 跟进数据。

### 10.1 接口验收（建议 ≥ 15 项）

① **`GET /api/crm/followUp/page` 登录态返回 200 且 `total` 与直查 DB（`deleted=0`）一致**（当前**预期 500**，即 §7.2 的真机复现）；② `pageNum`/`pageSize` 生效（`pageSize=1` → `records.length===1`）；③ `customerId` 过滤生效；④ `opportunityId`/`leadId`/`salesPersonId` 三个后端已支持参数**各自造数验证**（前端未接）；⑤ `POST /api/crm/followUp` 后 `followUpCode` **非空且形如 `FUP-yyyyMMddNNNN`**，DB 可查回；⑥ 提交 `followUpType=5` → `follow_up_type_desc` 为 `其他`；⑦ **软删后新建 → 断言唯一索引冲突**（修复后断言单号仍唯一）；⑧ `PUT /{id}` 改内容后三级回读一致；⑨ `DELETE /{id}` 后列表不出现（`deleted=1`）；⑩ `GET /customer/{customerId}` 与 `/page?customerId=` 结果一致；⑪ **`sales_person_name` 断言**：新建后直查 DB 为 `NULL`（登记「跟进人无写入」）；⑫ **`created_by`/`updated_at` 断言**：新建后 `created_by IS NULL`；更新后 `updated_at` **未变化**（登记填充失效）；⑬ **`follow_up_date` 留空** → DB 为 `NULL` 且列表首行是它（NULLS FIRST）；⑭ 前端 CSV 仅当前页（与 `/page` 的 `total` 不对等）；⑮ **写库隔离**：造数用专用记录并在断言后清理（含软删行）。

> 2026-09-18 更新：① 已补 `tenant_id`（`V11.379.0`），不再预期 500；⑦ 号段已改「当日最大号 + 1」，断言改为「软删后新建单号仍唯一」；⑪ 已写跟进人，断言改为「`sales_person_name` 非空」；⑫ 填充失效两项**未变**；⑬ 页面新建已默认今天，但直接调接口造数仍可落 `NULL`。

### 10.2 UI 验收（建议 ≥ 16 项）

① 菜单 `CRM → 客户管理 → 客户跟进`（`80201`）点开落在 `crm/customer-follow`，**无配对标签页**（`tag_label=NULL`、`list_path=NULL`）；② 查询区 1 项且**「客户」标签可见**；③ **客户下拉非空**（先造 1 个 `status=1` 客户）；④ 表格 9 列渲染，类型/结果显示**中文 tag**（蓝/绿/紫/青 + 绿/红/橙）；⑤ 断言行操作列**不存在**；⑥ 不选客户点保存 → `请选择客户` 且**无网络请求**；⑦ 只选客户不填内容 → `请输入跟进内容` 且无请求；⑧ 正常填写（类型默认「电话」）→ 保存 → `跟进记录已保存` → 列表出现新行（**断言网络无 4xx**）；⑨ 断言新行「跟进人」为**空**；未选日期时「跟进日期」为空且**排首行**；⑩ 断言类型/结果**筛选不存在**；⑪ 查询请求参数含 `customerId`/`pageNum`/`pageSize`（**不是** `page`/`size`）；⑫ 重置清空并回第 1 页；⑬ 导出 `客户跟进_*.csv`，UTF-8 BOM，**表头 9 列且类型/结果为数字**；⑭ 分页切页/改 `pageSize` 生效；⑮ 断言页面**无 `v-permission`**；⑯ 控制台**无 error**（含 `ReferenceError` —— 参见《重构搬迁后必须做运行时验证》）。

## 12. 剩余缺口（不阻塞，如实登记）
