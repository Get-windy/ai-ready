## 业务规范说明

### 状态流转与特殊交互

- 保存草稿（Ctrl+S）→ 记账（Ctrl+Enter）：记账后调整生效——结算单位应收/应付余额按方向增减
- 四向语义（实据归纳）：
  - 应收增加：客户欠款调增（如漏记费用转应收、期初补录）
  - 应收减少：客户欠款调减（如坏账豁免、差错冲减，不动资金）
  - 应付增加：欠供应商款调增
  - 应付减少：欠供应商款调减
- 与收/付款单的本质区别：本单**无账户字段**（截图与 JSON 均无收/付款账户），不产生资金流水，仅调整往来余额与对应科目
- 明细"科目编号/科目名称"：调整的对转科目（差额去向，如营业外收入/营业外支出等），金额可多行拆分
- 记账后生成会计凭证（KJPZ-）

### 与其他页面关系

- 余额结果体现：《按单收款开发文档》/《按单付款开发文档》未结算金额、查应收/查应付（分析域）
- 科目主数据：资料 → 财务账户 → 会计科目（抓取成功：列=操作、科目编号、科目名称、核算项）
- 期初场景：配合期初余额录入使用（总账 4000 期初资本科目实据佐证系统存在期初体系）
- 本系统前端目录 `finance/ar-ap-adjust`（dynamicRoutes.ts 实据）

### 客户来源

结算单位来源通过 ERP 模块的往来单位分类处理（客户/供应商均可，随调整方向定），而非 CRM 模块的客户信息。
