## 1. 页面概述

查资金页是**资金域的总账**：`资金余额` Tab 按**会计科目层级**给出每个账户的期初/发生额/期末余额（行级「对账」入口）；`收支汇总` Tab 以「日期」为行、**按每个资金账户动态展开「收入/支出」两列**的宽表矩阵；`资金流水` Tab 逐笔列出记账流水（含单据编号/类型/往来单位/账户/收支）。**单入口、三视图 Tab，逐 Tab 独立列配置**。

| 页面 | 地址 | 说明 |
|------|------|------|
| 查资金 | `analytics/check-fund` | 单入口复合页（3 个视图 Tab：资金余额 / 收支汇总 / 资金流水；逐 Tab 独立列配置） |

单入口：分析 → 财务分析 → 查资金。

- 实测实据（2026-09-15）：`资金余额` **无记录数输出**（`snapshot.record` 为空串，表格为科目台账不分页）；`收支汇总` 共 **2 条记录**；`资金流水` 共 **0 条记录**（`.png` 实据 `第 (0/0) 页`、`共 0 条记录`、`每页显示 20 行`）。
- **对标子分组归属**：本页属 ql361「财务分析」组下 **`资金费用`** 子分组（`.popupmenu__list-title`，**分组标题、非页面**）；同分组另有《查费用》《发票统计》。本系统 `sys_menu` **无该层级**，仅保留菜单 80453 直挂 61005。

- 切换 Tab 后**工具栏随之变化**：`资金流水` Tab 实测无 `图形` 按钮（仅 列配置齿轮 / `刷新` / `打印(F8)` / `导出`）；`收支汇总` Tab 基准文档记有 `图形`（表格/图表切换）——**逐 Tab 工具栏差异待复核**。

## 4. 业务规范

### 统计口径（期初 + 借贷 = 结存）

- **恒等式**：`期末余额 = 期初金额 + 借方发生额 − 贷方发生额`（Tab1 逐行成立，实测见上）。
- **科目层级汇总**：一级科目行 = 其下二级账户行合计（基准文档实据「现金库存 = 186 + 5,161.33 + 946」；本轮实测 `1001 现金库存 / 1002 银行存款` 两行直接给出，子行紧随其后）。
- **账户科目体系**（基准文档 2026-07-23 实据，与本轮 `收支汇总` 列名可互相印证）：`100101 现金`、`100102 店面备用金`、`100103 敦煌店面备用金`；`100201 农业银行一`、`100202 微信账户`、`100203 支付宝账户`、`100204 开单微信钱包`、`100205 农业银行二`、`100206 建设银行`、`100207 工商银行`、`100208 中国银行`、`100209 酒泉农商行`、`100210 皇朝银行对公账户`、`100211 信合对公账户`、`100212 兰州银行`、`100213 农行信用卡`、`100214 蚂蚁花呗`、`100215 农行快E贷`、`100216 农行乐易分期`。
- **信贷类账户符号**：信用卡/花呗/快E贷等负债类账户期初为负、贷方增加（与 Tab1「贷方余额账户」注释一致）。
- **日期类型**：`单据日期`（实测默认值）；其他可选值**待复核**。
- **显示红冲**：勾选后红冲单据并入统计（实测勾选项，与《查费用》`包含红冲` 同一设计）。
- **单据类型 / 流水类型**：`流水类型` 实测默认 `全部`，与《资金流水》视图的收支方向/来源类型筛选同一设计；可选值枚举**待复核**。

### 取数来源与联查关系

- **取数**：收款单 / 付款单 / 预收款单 / 预付款单 / 提存现现转款 等资金单据（按账户归集），即《经营历程》的流水侧。
- **联查**：Tab1 行级 `对账` → 账户资金流水（本页 `资金流水` Tab 或财务域《明细账》1001-1002 科目）；Tab2 行级 `明细` → 该日该账户流水。
- **同源页**：《经营分析》（收支损益口径）、财务域《总账》（同一科目体系）、《明细账》（科目级明细）。

- **取数端点与口径**：
  - 资金余额：`GET /erp/finance/report/v2/trial-balance-page`（`subjectKeyword=1001` 库存现金 / `1002` 银行存款，含下级科目，合并去重），按科目层级给出期初余额 / 本期借贷发生额 / 期末余额。
  - 收支汇总：`GET /erp/capital-flow/page` 逐页取流水（单次 500 条、最多 20 页）后**前端按「日 × 账户」透视**（收入合计 / 支出合计 / 净收入合计 / 34 个账户的收支 / 预收款使用）。
  - 资金流水：`GET /erp/capital-flow/page`（服务端分页 + 本页内下钻过滤）。
- **后端**：本轮未改后端；未新增迁移。

### 剩余缺口（按本页自身规格＝账表页逐项判定）

1. **6 个查询控件置灰（后端无入参）**：日期类型、单据类型、账户、往来单位、经手人、显示红冲 均 `disabled` + title 说明（资金端点无对应条件）。
2. **「收支汇总」无专用聚合端点**：由资金流水前端透视而得（单次 500 条 / 最多 20 页，超出部分不计入）。
3. **账户列白名单硬编码**：34 个账户列名写死在 `STATEMENT_ACCOUNTS`（`index.vue:339-345`），透视时 `if (acct && STATEMENT_ACCOUNTS.includes(String(acct)))` 才落列 → **不在白名单内的账户，其收支只进「收入合计 / 支出合计」，不进任何账户列**；账户改名 / 新增账户需改代码。
4. **合计口径非后端 summary**：`/erp/capital-flow/statistics` 的 `startDate/endDate` 后端未生效，故收支汇总与资金流水的合计按当前取到的数据前端实时汇总。
5. **资金余额为「科目余额表替代」**：后端无「按会计科目层级汇总资金余额」端点，现以科目余额表（1001 / 1002）替代，科目范围固定为库存现金 + 银行存款。
6. **对账明细未做凭证级下钻**：资金流水行只能切换对账标记，无凭证级明细联动。
7. **查询方案为占位**：`queryScheme` 未被任何请求使用。
