# 辅助核算余额表开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`finance/aux-balance`（列表查询页）
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- 列表查询页（账簿查询：查询区 + 分组表头汇总表格 + 合计行；无分页栏），按科目 × 核算项（往来单位等辅助维度）汇总四段余额的明细余额表。
- 单入口：菜单 财务 → 账簿 → 辅助核算余额表；另有 `finance/subsidiary-balance` 目录（对应关系待复核）。
- 数据实据（截图）：科目=1122 应收账款；核算项编码=客户编码（20221105204… 等）；核算项名称=客户名称（敦煌市阿堡仔店、金塔县中学、肃州区瑞瑞翔餐饮店(明洞炸鸡) 等）——一行一个"科目×往来单位"组合。

## 2. 页面配置

### 查询条件

按抓取 JSON filterLabels 实据（会计月(止)*、科 目）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 会计月(起)、会计月(止)*（必填）、科目（可指定）、核算项（下拉，默认"往来单位"；可选值域待复核——明细账查询条件实据另有核算部门/核算职员两维度）
- 勾选项：无本期发生额不显示、余额为0不显示
- 布局（截图）：查询区两行——第一行查询方案 + 工具栏按钮，第二行查询条件 + 勾选项

### 功能按钮

按抓取 JSON buttons 实据：刷新、打印(F8)、导出、明细对账、查询

## 3. 数据表格列配置

### 默认显示列（12 个数据列，含 4 个分组表头，抓取 JSON columns 实据）

科目编码、科目名称、核算项编码、核算项名称、期初余额（分组表头，下辖：借方、贷方）、本期发生额（分组表头，下辖：借方、贷方）、本年累计（分组表头，下辖：借方、贷方）、期末余额（分组表头，下辖：借方、贷方）

> JSON columns 共 10 项（科目编码、科目名称、核算项编码、核算项名称、期初余额、本期发生额、本年累计、期末余额、借方、贷方），首项"科目编码"经截图核对为真实首列，非抓取拼接串；JSON 中"借方、贷方"为四组分组子列的去重抓取，按图展开后数据叶子列=前 4 列 + 4 组×2 = 12 列。

### 全部可配置列

待复核（未抓取列配置弹窗）

## 4. 业务规范

- 取数逻辑：数据源自会计凭证分录按"科目 × 核算项"聚合，仅带辅助核算的科目（如应收账款 1122 核算项=往来单位）出现在本表；四段余额（期初/本期发生/本年累计/期末）与科目余额表同口径，按核算项再细分。
- 核算项体系（实据归纳）：会计科目主数据"核算项"列定义科目挂接的辅助维度（往来单位/部门/职员）；本页"核算项"下拉选择维度类型。
- 合计行实据（截图）：本期借方 1,191,804.51 / 本期贷方 1,286,023.29 / 本年累计借方 10,068,713.3 / 本年累计贷方 10,311,993.38（应收账款科目 × 往来单位维度合计；期初/期末合计在右侧被截断区域）。
- 与查应收的关系：应收账款 × 往来单位的期末余额即客户欠款明细（与分析域"查应收/往来余额表"同口径，联动待复核）。
- 表格结构（截图）：表头两级——"期初余额""本期发生额""本年累计""期末余额"四个分组表头，各辖"借方/贷方"子列；无分页栏。
- 与其他页面关系：数据源《会计凭证开发文档》；汇总视图《科目余额表开发文档》（科目级合计应与本表按科目汇总一致）；逐笔联查《明细账开发文档》（核算单位/核算部门/核算职员三个查询条件同源）；本系统前端目录 `finance/aux-balance`、`finance/subsidiary-balance`（双目录对应关系待复核）。
