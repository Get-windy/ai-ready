商品组合是**商城组合商品/套餐统一管理**页：按组合名称、显示状态查询组合商品，管理组合的定义（组合名称/编号），并查看/编辑组成商品明细，支持新增、启停用、批量删除。**单入口，无独立表单，无子 Tab**。

## 业务规范说明

- **组合主线**：商城组合商品/套餐 → 本页统一管理；组合名称 + 编号唯一标识；「商品明细」= 组成商品子表（组合内的组件商品及数量）。
- **组合状态**：已启用/已停用（顶部「启用/停用/批量删除」对选中行生效；「新增」新建组合）。
- **组合类型（本系统扩展）**：组合套装/捆绑套装/礼品套装/组装产品/拆分产品；对应 ERP 组装拆分场景。
- **成本与价格**：组合价 = 组合售价；组合成本 = 组件成本合计；利润率 = (组合价−组合成本)/组合价。
- **下游**：组合商品作为商城可售商品（成品）→ 关联商品上架（本页「成品编码/成品名称」）；「商品明细」子表存组件（商品编码/名称/单位/数量/单位成本/行成本）。

## 实现差异说明

> 本节按当前源码回写（本轮金标准升级后）。

### 当前实现
- **实现文件**：`frontend/apps/pc-admin/src/views/mall/product-combo/index.vue`
- **骨架**：`ErrorBoundary` > `PageContainer(full-height)` > `CategoryListLayout(:tabs="[]"、:show-category-panel="false" 无分类树)` > `BillDetailTable` + `StandardPagination(variant="classic")`；**无** `PageConfigPanel`（对标无页面配置弹窗）
- **Tab**：无 Tab（`CategoryListLayout :tabs="[]"`）
- **分类树**：无（`show-category-panel="false"`）
- **列**：共 9 列可配置（默认显示 4：组合名称、编号、商品明细、状态；默认隐藏 5：类型、组合价、组合成本、利润率、创建时间）；固定列：序号（rowNo，承载列配置齿轮）、多选（checkbox）、操作（action）。`columns` 数组共 12 项（含 rowNo、checkbox、action 三条 `LOCKED_COLUMNS`）；对标 3 列 = 组合名称/编号/商品明细，另 6 列（状态/类型/组合价/组合成本/利润率/创建时间）为本系统扩展
- **查询条件**：3 项（组合名称=组合编码/名称 关键字、组合类型（本系统扩展）、显示状态）+「查询」按钮（无重置）
- **功能按钮**：左侧 新增组合、启用、停用、批量删除（后三者未勾选时禁用）；右侧 刷新、打印(F8)、导出；**无**页面配置齿轮
- **行级操作**：详情（抽屉，含「组合组件」子表：商品编码/商品名称/单位/数量/单位成本/行成本）、编辑（弹窗，内嵌组件编辑子表，含 添加组件/删除）、复制（popconfirm）、启用/停用
- **打印(F8) / 导出**：`handlePrint()` 按 6 列（序号/组合名称/编号/类型/状态/组合价）`window.open` 内联 HTML 打印，`handleF8Key()` 绑定 F8；导出为前端 CSV（`\uFEFF` BOM，8 列：组合名称/编号/类型/状态/组合价/组合成本/利润率(%)/创建时间，文件名 `商品组合_YYYYMMDD.csv`）
- **storage-key**：列配置 `mall-product-combo-table-columns`（global-config-key 同值）；页面配置：无（本页未挂 `PageConfigPanel`）
- **数据来源**：`apps/pc-admin/src/api/erp/mall.ts` → `GET /erp/product-kit/page`（`productKitApi.page`）、`GET /erp/product-kit/{id}/items`（`productKitApi.items`，详情抽屉与编辑弹窗）、`POST /erp/product-kit`（`productKitApi.create`）、`PUT /erp/product-kit/{id}`（`productKitApi.update`）、`POST /erp/product-kit/{id}/copy`（`productKitApi.copy`）、`POST /erp/product-kit/{id}/activate`（`productKitApi.activate`）、`POST /erp/product-kit/{id}/deactivate`（`productKitApi.deactivate`）、`POST /erp/product-kit/batch-activate` 与 `POST /erp/product-kit/batch-deactivate`（`productKitApi.batchActivate` / `batchDeactivate`，批量启停），body 均为 `{"ids":[…]}` 并返回实际更新条数；`KitType` 口径 1组合套装 / 2捆绑套装 / 3礼品套装 / 4组装产品 / 5拆分产品（`product_kit.kit_type`）；后端在 `erp-sales` 的 `ProductKitController`（`/api/erp/product-kit`）

### 后端改动（本轮）
- **前端已接删除端点**：`productKitApi.remove(id)`（行级/单条删除）与 `productKitApi.batchRemove(ids)`（批量删除）已在 `views/mall/product-combo/index.vue` 接入，原「点击仅提示接口待补」已闭环。
- **后端新增批量启停端点**：`ProductKitController` 新增 `POST /api/erp/product-kit/batch-activate` 与 `POST /api/erp/product-kit/batch-deactivate`（body `{"ids":[…]}`，返回实际更新条数）；`ProductKitService` 新增 `activateKits(ids)` / `deactivateKits(ids)`，实现复用 `listByIds` + `updateBatchById`（受租户插件与逻辑删除约束，只命中当前租户真实存在的套装，口径与既有 `deleteKits` 一致）。
- **前端批量按钮已改为一次请求**：`handleBatchActive()` 不再 `for` 循环逐条调 `POST /{id}/activate|deactivate`，改为调用上述批量端点；行级单条启停仍走原 `activate/deactivate`。
- 本页其余后端本轮无改动：`ProductKitController`（`/api/erp/product-kit`）其余端点未变动；本轮新增的 `ExternalOrderController`、`ChannelConfigController` 补口、`Payment/Refund/Reconciliation` 扩参与 stat 端点、`InventorySyncController` 补口及 Flyway `V11.361.0`~`V11.361.5` 迁移均与本页无关。

2. **「显示状态」查询走 `product_kit.status`，行级启停用走 `POST /{id}/activate|deactivate`（`active` 字段）**，两者口径需核对是否同源（待核）。
3. ~~**截图待补 / E2E 脚本未补**~~ ✅ **已闭环（2026-09-14）**：`tools/e2e-trade.cjs`（**103/103**，含本页接口断言）；对标复核 `tool-results/ql361/mall-live/商品组合.json` + `.png`（2026-09-15，列配置 3/3 全默认可见）。**本页无 E2E 截图**（不在该脚本 UI 抽检 6 页清单内），如需补图请扩展 `UI_PAGES` 后重跑。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
