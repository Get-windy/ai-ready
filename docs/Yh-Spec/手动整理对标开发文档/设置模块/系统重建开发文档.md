## 1. 页面概述

### 1.1 一句话说清「模型错位」

| | **ql361 的「系统重建」** | **本系统的「系统重建」** |
|---|---|---|
| 页面性质 | **危险操作页 / 数据清零台** | **只读列表页（异步任务台账）** |
| 用户在这里干什么 | **勾选要清除的数据范围 → 输入登录密码 → 点「确定」→ 清空账套** | 看一张**任务编号/任务名称/任务类型/执行人/状态/创建时间**的列表 |
| 主控件 | **12 个复选框 + 1 个密码输入框 + 1 个「确定」按钮** | `BillTableList`（且**传了组件不存在的 prop**） |

| 二次验证 | ✅ **必输登录密码** | ❌ 无（连提交都没有） |

| 数据表 | （对标私有） | **零表**（库中无 `%rebuild%` 表） |

### 1.4 本页不提供的能力（如实登记）

**① 本页「应有」但因 prop 误用而完全失效的能力**：

- ❌ **表格恒空**：给 `BillTableList` 传了**组件不存在的 prop `apiUrl` / `params`** → 数据源永远取组件默认 `dataSource: []`。
- ❌ **查询/重置完全无效**：两按钮都调 `tableRef.value?.reload()`，而 `BillTableList` **未暴露 `reload`** → 可选链**静默失效**。
- ❌ **日期范围条件完全无效**：`dateRange` 是独立 `ref`，**不在 `searchParams` 内**，而传给组件的是 `searchParams`。

**② 对标有、本系统完全没有的能力**（这才是真正的差距）：

- ❌ **12 个清除范围复选项**（业务草稿/库存期初/买家账号/往来期初/银行现金期初/商品/仓库区域/货位信息/往来单位/职员/操作员/发票）。
- ❌ **必输登录密码的二次验证**。
- ❌ **不可恢复的顶部警告**。
- ❌ **「确定」提交按钮**（以及其背后的清数据执行引擎）。
- ❌ **执行后的引导提示**（对标：`系统重建后请点击右上角的"刷新"或者重新登录后进行系统开账！`）。
- ❌ 无「先备份」的出口（对标：`注意：若需单独备份数据，请联系客服！`）。

**③ 通用能力缺失**：无 `PageConfigPanel`、无列配置齿轮、无 `storage-key`、无 `StandardPagination`、无权限门控、无 `PageContainer(full-height)`。

### 10.1 接口验收（34 项）

**A. 现状登记（①–⑨，当下可执行）**

1. **断言后端零控制器**：`grep -rn "set/rebuild\|rebuild/page\|SystemRebuildTask\|erp_rebuild\|sys_rebuild_task" backend/` → **仅命中 SQL 迁移文件**（无 `.java`）。
2. **断言库中无 `%rebuild%` 表**：`select count(*) from information_schema.tables where table_name like '%rebuild%'` = **0**。
3. **断言前端零接口调用**：`grep -n "request\.\(get\|post\|put\|delete\)" views/set/rebuild/index.vue` → **0 命中**（`request` 被 import 但从未使用）。
4. **断言 `apiUrl` 仅作 prop**：`/set/rebuild/page` 字符串只出现在 `:70`；**断言页面无任何请求发出**（Playwright 断言 **network 中无该请求**）。
5. **断言 `BillTableList` 无 `apiUrl`/`params` prop**：读 `components/BillTableList/BillTableList.vue:283-315` 的 `defineProps`，**断言两个名字都不在其中**。
6. **断言 `BillTableList` 未暴露 `reload`**：读组件 `:432-435` 的 `defineExpose`，**断言只有 `clearSelection` / `getSelectedRecords`**。
7. **断言 `sys_permission` 中 `set:*` 0 行**（基线）。
8. **断言菜单 `70560` 与 `80630` 的 `sort` 相同**（`select id,menu_name,sort from sys_menu where parent_id=61203`）。
9. **断言 `61203` 下无 `sort=1`**（基线）。

**B. 二次验证（⑩–⑯，目标能力）**

10. **未输密码提交重建** → **断言 400/拒绝**，且**错误文案明确指向密码**（不接受「参数错误」这类含糊提示）。
11. **错误密码提交** → **断言拒绝**；**断言未产生 `sys_rebuild_task` 行**（**关键：验证失败不得留下任务**）。
12. **正确密码提交** → **断言接受**并返回 `task_id`。
13. **断言密码校验不依赖当前会话**：用**有效 token 但错误密码** → **断言拒绝**（证明是**独立校验**，不是「已登录就通过」）。
14. **断言无「记住密码/免验证」路径**：同一账号连续两次提交，**每次都要求密码**（不接受首次通过后免验）。
15. **断言密码不从请求参数回显**：响应体、日志中**不含明文密码**（`grep` 网络响应 + 应用日志）。
16. **API 直调（绕过 UI）** 调重建端点 → **断言同样要求密码**（防「前端拦了、后端没拦」）。

**C. 幂等（⑰–㉒，目标能力）**

17. **同一 `tenant_id` 在有一个 `pending`/`running` 任务时再次提交** → **断言被拒（409）**，**不产生第二个任务**。
18. **同一 `task_no` 重复提交**（幂等键）→ 断言**返回同一任务，不新建**。
19. **重复提交不造成二次删除**：任务成功后再次提交相同范围 → 断言**要么被拒（无待清数据），要么删除行数为 0**（不得报错）。
20. **并发提交**（两个请求同时发出）→ 断言**只有一个成功**（数据库唯一约束或分布式锁生效），另一个 409。
21. **范围 JSON 顺序无关**：`["a","b"]` 与 `["b","a"]` → 断言**等同**（不产生两个任务）。
22. **空范围提交** → 断言拒绝（至少勾 1 项）。

**D. 失败回滚 / 部分成功（㉓–㉚，目标能力）**

23. **注入失败**（如某范围的目标表被临时改名）→ 断言任务 `status=failed` 或 **`partial`**，且 **`error_msg` 非空**。
24. **断言失败出现在 `_detail` 的对应 `scope_key` 行上**（可定位到具体范围）。
25. **断言失败范围可单独重试**（对失败范围重跑 → 该行转为成功）。
26. **断言事务边界**：若设计为「逐范围事务」，则**已成功的范围不回滚**（`partial` 语义）；**断言该语义被显式写入文档**（不允许含糊）。
27. **断言重建全程写审计**：`sys_oper_log` 中新增一条含**执行人 / IP / 范围 / 结果**的记录。
28. **断言执行期间的写操作被拒**（若实现独占机制）→ 另一账号调业务写端点 → 断言 **423/409**。
29. **断言任务表与明细表的行数一致**：`_detail` 的行数 = 勾选范围数。
30. **断言失败任务不改变 `tenant_id` 的任何业务数据**（对**只读目标表**做行数前后比对）。

**E. 权限与隔离（㉛–㉞）**

31. **无 `set:rebuild:execute` 权限的账号** → 断言 **403**（目标）；且前端**断言页面不可见/按钮禁用**。
32. **跨租户**：A 租户 token 提交 B 租户的重建 → **断言被拒**（**跨租户清数据是本项目红线**）。
33. **未登录** → 401。
34. **断言重建范围不超过本租户**：即使请求体伪造 `tenant_id`，断言**只影响当前租户**（服务端强制覆盖租户）→ **须直查目标表验证**。
