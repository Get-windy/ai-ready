## 1. 页面概述

预订货查询页是**预订货单的订 → 发货履约汇总页**：同一批预订货数据可切两种视角——`商品预订货分析`（每商品一行，看某商品被预订了多少、转单多少、发货多少）与 `客户预订货分析`（每客户一行，看某客户预订了多少、已订/已发多少、预订金收付余额）。两视图均为**汇总台账 + 合计行**，配左分类树与「显示层次结构」勾选。**单入口、双视图 Tab**。

| 页面 | 地址 | 说明 |
|------|------|------|
| 预订货查询 | `analytics/pre-order-query` | 单入口复合页（2 个视图 Tab：商品预订货分析 / 客户预订货分析；逐 Tab 独立列配置、独立左分类树） |

单入口：分析 → 采销分析 → 销售分析 → 预订货查询。

- **对标子分组归属**：ql361「采销分析」组下有 **3 个 `.popupmenu__list-title` 子分组**（`销售业绩` / `销售分析` / `采购分析`，均为分组标题、非页面，`.png` 实据）；本页归在 **`销售分析`** 下。本系统 `sys_menu` **无该层级**，仅保留菜单 80419 直挂 61002（文档层面记录此对应关系）。
- 实测实据（2026-09-15）：**两个 Tab 均为 0 条记录**（`商品预订货分析` 共 0 条、`客户预订货分析` 共 0 条，`第 (0/0) 页`），故**全部列口径均无数据可验证**，本页口径说明以「表头 + 基准文档 + 本系统后端字段」三方交叉，**凡无实据者一律标注待复核**。

- **列名同名不同义**：`商品预订货分析` 的 `金额`（#16）与 `客户预订货分析` 的 `金额`（#13）口径应一致（预订货金额），但客户侧另拆出 `已订金额 / 已发金额`、商品侧另拆出 `折后金额 / 价税合计 / 税额`，**两侧金额维度的拆分粒度不对称**（客户侧偏履约、商品侧偏价格税）。

## 4. 业务规范

### 统计口径（预订货订发履约）

- **数据范围（红线，页面提示条实据）**：预订货单（**YDHD-**）明细口径；**已取消、已驳回订单不参与统计**（`.png` 提示条实据，与基准文档一致）。本系统后端号段实据：`SalePreOrderController.java:111`「生成下一预订货单号（号段 **YDHD-yyyyMMdd-NNNN**）」。
- **三量递进（订 → 转 → 发）**：
  - `预订货数量` —— 客户预订的原始数量（预订货单明细数量）；
  - `已订数量` —— 已转为正式订单（销售订单）的数量；
  - `已发数量` —— 已完成发货的数量。
  递进关系应满足 `预订货数量 ≥ 已订数量 ≥ 已发数量`；存在**未订数量 = 预订货数量 − 已订数量**、**未发数量 = 已订数量 − 已发数量**（列配置中两列均默认隐藏，**公式待复核**）。
- **赠品三口径（商品 Tab，三列均默认可见）**：`赠品数量`（预订时的赠品量）→ `赠品订货数量`（转单时的赠品量）→ `赠品发货数量`（实发赠品量）——与主商品三量**同构**的三段递进。
- **金额/价税双口径（商品 Tab）**：`金额`（不含税）与 `价税合计`（含税）并列；另有 `折扣` 侧三列（`折后单价 / 折后金额`，默认隐藏）与 `税额`（默认隐藏），价格口径共 **6 列**（单价 / 金额 / 折后单价 / 折后金额 / 含税单价 / 价税合计）。
- **换算语境（商品 Tab 序号 10-14）**：`单位`（大单位）与 `小单位` 并列，`预订货数量`（大单位数量）与 `小单位数量` 并列，中间夹 `换算结果`（大↔小换算的展示列）。即「**数量 × 换算率**」三件套在列上被拆成 5 列（单位 / 预订货数量 / 换算结果 / 小单位 / 小单位数量）——**换算率与换算结果的确切取值口径未抓取，待复核**。
- **客户维度独有口径（客户 Tab，全部默认隐藏）**：
  - `已订金额 / 已发金额` —— 已订/已发对应的金额口径（与数量的金额拆分）；
  - `已收预订金 / 未收预订金 / 预订金余额` —— **预订金三口径**，收付状态与余额不可混算（本系统财务域预订金对应科目 **2204 预收账款**类，具体科目待复核）；
  - 档案快照列 `默认经手人 / 客户编号 / 客户级别 / 所属分类 / 地址 / 所属仓库 / 所属区域 / 联系人 / 客户一票通` —— 便于按区域/仓库/级别做运营分组（全部默认隐藏）。
- **显示层次结构**：勾选后按分类树层级**分层汇总**（分类小计 + 明细行）；实测**已勾选**但两 Tab 均 0 条记录，**分层呈现形态待复核**。

### 取数来源与上下游关系

- **取数**：预订货单（YDHD-，销售域）明细 + 客户主数据（客户维度视图）＋ 商品档案（商品维度视图）＋ 预订金收付（财务域）。
- **上游**：预订货单录入（`sales/pre-order` 金标准页，号段 YDHD-、含审核库存事件）。
- **下游**：
  - 预订货**转销售订单/销售出库单**发货 → `已订数量 / 已发数量` 的增长来源；
  - **与《采购准备》互为上下游**：预订货未发货量是《采购准备》`以销定购` 策略的输入之一（按未发货销售订单反推采购需求），本页的 `未发数量` 与《采购准备》`以销定购` Tab 的「未发数量」**同源**；
  - **与《销售履约分析》的分工**：本页为**预订货单（YDHD-）**的订发履约；《销售履约分析》为**正式销售订单**的履约口径，二者单据口径不同、不可直接相加。

2. **🔴 双 Tab 全缺**：`商品预订货分析`（28 列）与 `客户预订货分析`（23 列）均未实现；且**后端无对应汇总端点**，需先补后端（按商品/按客户聚合 + 赠品三口径 + 预订金三口径）再谈前端。
3. **🔴 客户维度（预订金与档案快照）全缺**：`已收预订金 / 未收预订金 / 预订金余额` 三列是本页与《查应收/查应付》交叉对账的关键，本系统 0 列落地。

5. **🔴 取数红线未实现**：对标明示「已取消、已驳回订单不参与统计」；本系统 `pageDetail` 透传查询参数、前端无 `status` 相关过滤，`STATUS_MAP` 中的 `已取消（−1）`**会照常出现在列表里**——**存在口径错误风险**（需在汇总接口中显式排除）。
6. **🔴 无列配置 / 合计行 / 分类树 / 层次结构 / 打印**：对标五项俱全，本页全无。
7. **🟡 查询能力弱**：对标「查询方案 + 8 段快捷 + 日期 + 客户 + 商品 + 经手人 + 显示层次结构」共 7 类控件；本页为「关键字 + 状态 + 单据日期」3 项，且 `状态` 是**对标没有**的筛选（对标用红线过滤替代状态展示）。
8. **🟡 导出弱**：`ARReportPage` 内置 CSV 为**当前页**导出（`ARReportPage.vue:340-371`，非真实 xlsx、非全量）。
