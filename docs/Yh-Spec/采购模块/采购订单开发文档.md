# 采购订单开发文档

## 页面概述

采购订单模块包含两个核心页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 采购订单列表页（订单处理中心） | http://localhost:5656/purchase/order/index | 有2个tab页面：按单据和按明细 |
| 新增/编辑采购订单表单页 | http://localhost:5656/purchase/order/form | 编辑模式为新增模式加id |

### 配置功能说明

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结

## 业务规范说明

### 价格等级字段处理

餐饮店、食堂团餐、自助vip、大团餐、特价客户、外围餐饮店、重点vip01、连锁|vip 这8个字段是用户对价格等级自定义的昵称，需按标准化产品价格等级处理。这些字段应该是销售模块用的，感觉是复刻对标系统的错误，你看看怎么处理这些字段和其他你认为不是采购模块的字段。

### 供应商来源

采购订单的客户来源通过 ERP 模块的往来单位下的供应商分类处理。

### 架构师红线（Ponytail六步过滤网）

动手前必过六关：①此功能业务真需要？②标准库/原生API能搞定？③现有依赖能否复用？④能否一行代码干净解决？⑤能否复用已有组件？⑥通通走不通才写最小可用闭环。**Lazy, not negligent**——跨边界防注入、容灾、安全防御代码不准省。

### 业务逻辑要求

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑和交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。订金是带使用条件的预收款或预付款。
