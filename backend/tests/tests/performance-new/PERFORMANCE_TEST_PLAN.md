# 企智连性能测试方案

## 1. 测试概述

### 1.1 测试目标
- 验证企智连系统在高并发场景下的稳定性和响应速度
- 识别系统性能瓶颈
- 为系统容量规划提供数据支撑

### 1.2 测试范围
- 接口性能测试
- 业务流程性能测试
- 数据库性能测试

### 1.3 测试指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 响应时间(P95) | < 500ms | 95%请求响应时间 |
| 响应时间(P99) | < 1s | 99%请求响应时间 |
| 吞吐量(QPS) | > 1000 | 每秒处理请求数 |
| 并发用户数 | > 1000 | 同时在线用户数 |
| 错误率 | < 0.1% | 请求失败率 |
| CPU利用率 | < 70% | 服务器CPU使用率 |
| 内存利用率 | < 80% | 服务器内存使用率 |

// k6脚本示例

    { duration: '5m', target: 100 },
    { duration: '2m', target: 200 },
    { duration: '5m', target: 200 },
    { duration: '2m', target: 0 },

  thresholds: {
    http_req_duration: ['p(95)<500'],
    http_req_failed: ['rate<0.01'],
  },
};

export default function () {
  const payload = JSON.stringify({
    username: 'testuser',

  });
  
  http.post('http://test.qizhilian.com:8080/api/v1/auth/login', payload, {
    headers: { 'Content-Type': 'application/json' },
  });
}

```sql

-- 优化前

-- 创建索引
CREATE INDEX idx_orders_created_at ON orders(created_at);

-- 优化后
EXPLAIN ANALYZE SELECT * FROM orders WHERE created_at > '2026-04-01';
```

### 4.4 慢查询分析

```sql
-- 查看慢查询日志
SELECT * FROM pg_stat_statements 
WHERE calls > 100 AND mean_time > 100 
ORDER BY mean_time DESC;

-- 查看锁等待
SELECT * FROM pg_locks WHERE NOT granted;
```

## 5. 性能监控方案

### 5.1 监控工具

| 工具 | 用途 | 部署方式 |
|------|------|----------|
| Prometheus | 指标采集 | Docker |

| Arthas | Java诊断 | Agent |
| JMeter | 压测工具 | 本地 |
| k6 | 压测工具 | Docker |

### 5.2 监控指标

#### 应用层指标
- HTTP请求数
- 响应时间分布
- 错误率
- 吞吐量
- JVM内存使用
- GC频率
- 线程池状态

#### 数据库层指标
- 连接池使用率
- 慢查询数量
- 锁等待时间
- 缓存命中率
- 磁盘IO

#### 系统层指标
- CPU使用率
- 内存使用率
- 磁盘使用率
- 网络IO
- 负载均衡

## 8. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 测试环境与生产差异 | 高 | 尽量保持环境一致 |
| 测试数据不足 | 中 | 提前准备充足测试数据 |
| 网络波动 | 中 | 多次测试取平均值 |
| 监控工具故障 | 中 | 准备备用监控方案 |
