## 页面概述

上架单用于收货暂存后把商品从「收货暂存位」移动到「存储货位」（源货位 → 目标货位），来源可为收货上架或移库上架。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 上架单列表页 | `wh/putaway-order/index`（list_path 别名 `wms/putaway`） | 双入口「历史」标签 |
| 新增/编辑上架单表单页 | `wh/putaway-order/form` | 编辑模式为新增模式加 id |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序。
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结。
- ✅ **当前实现说明**：列表页采用 `CategoryListLayout`（金标准）+ `ColumnConfigPanel`/`PageConfigPanel`，表单页采用 `BillFormPage` + `BillDetailTable`（含 3 Tab 配置弹窗），页面配置/列配置均已接入。

## 新增编辑上架单表单页配置

### 页面结构（设计值）

`PageContainer` 三段自建面板：**单据头** → **作业明细** → **最近上架单列表**。

### 单据头字段

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 单号 | a-input | 是 | taskNo，前端 `genTaskNo('PA')` 预填，可修改 |
| 上架仓库 | a-select | **是** | warehouseId，`warehouseApi.listAll()`，联动加载货位 |
| 来源类型 | a-select | 否 | 收货上架 0 / 退货上架 1 / 调拨上架 2 / 其他 3 |
| 来源单据 ID | a-input-number | 否 | sourceId（来源单据ID，可选） |
| 备注 | a-input | 否 | remark |

### 工作流按钮

| 状态 | 按钮 | 动作 |
|------|------|------|
| 任意 | 保存单据 / 保存修改 | `putawayApi.save` / `update` |
| 任意 | 新建 | 重置表单 |
| status=0 | 开始上架 | `putawayApi.startPutaway(id, userId, userName)` |
| status=1 | 确认上架（popconfirm） | `putawayApi.confirmPutaway(id, userId, userName)` |
| status=0/1 | 取消（popconfirm） | `putawayApi.cancelPutaway(id, reason)` |

### 作业明细表格

明细仅**待上架（status=0）**可编辑，保存为**整体替换**（`putawayApi.saveDetails`，先删后插）。

**编辑态列**：行号、商品（a-select）、规格、单位、上架数量（a-input-number）、来源货位（a-select）、目标货位（a-select）、批次号、操作（删除）。

**只读态列**：行号、商品编码、商品名称、规格、单位、上架数量、来源货位编码、目标货位编码、批次号、状态。

> 明细保存校验：明细非空、每行必选商品、上架数量 > 0；选商品/货位后自动回填 code/name/spec/unit。

## 业务规范说明

- 收货暂存 → 上架：商品从收货暂存位（源货位）移动到存储货位（目标货位），是库内实物位置流转。
- 来源类型：收货上架 / 移库上架，对应上架任务的来源归属。
- 明细状态：待上架 0 → 已上架 1；确认上架后明细只读。
- 单号前缀 `PA`，前端 `genTaskNo` 生成（`PA-yyyyMMddHHmmss`），后端 `save` 原样落库；**后端无 next-no / 序列号自动生成**。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），仓储模块无上架页，本页为设计新增。

### 页面对齐（已建成）
- **列表页**：`CategoryListLayout` + `BillTableList`，**双Tab（按单据/按明细）**——按单据 11 列、按明细 15 列，两套列配置独立存储键；查询条件随 Tab 分流；接入 `ColumnConfigPanel`/`PageConfigPanel`；新增跳转 `/wh/putaway-order/form`。
- **表单页**：`BillFormPage` + `useBillForm` + `BillDetailTable`（from/to 双货位、批次号、生产日期、有效期）+ 配置三Tab（页面配置/录单默认值/打印设置，`userPageConfigApi`）；工作流（保存/开始/确认/取消）在列表行与表单 header 双入口；**底部无"最近上架单"段**（由双入口列表页"历史"标签承担，2026-09-06 移除）。基础组件能力（远程搜索/配置三Tab）详见 `components/BillFormPage/*` 及 `components/FormField/*`，**改造或使用前请先读基础组件代码**，勿在业务页重复实现（遵"功能/模块不重复开发"）。
- **工作流**：保存/开始上架/确认上架/取消四段状态流转已接通真实 API（`/start`、`/confirm`、`/cancel`）；列表行内操作均传当前登录人。
- **明细保存**：整体替换（`/wms/putaway/detail/save`），仅待上架可编辑；明细含 from/to 双货位 + 生产/有效期。
- **数据对齐**：`sourceType`（0-3 收货/退货/调拨/其他）前后端注解已对齐；明细 `productionDate/validityDate` 已暴露录入控件，后端以 `@JsonFormat(pattern = "yyyy-MM-dd")` 前后端传输。
- **按明细分页**：后端新增 `/wms/putaway/page-detail`（两阶段：先按单据级过滤取 taskId 集，再按明细过滤分页并补齐主表字段），列表明细 Tab 走该接口，支持商品名称/编码/货位编码过滤。
- **状态守卫**：删除仅待上架（status=0）且级联删明细；确认上架反写已上架数量（putawayQuantity=totalQuantity）并将待上架明细置为已上架。
- **来源单号**：`WmsPutawayTask` 新增 `sourceOrderNo`（迁移 V11.71.0），表单可录入，列表按单据/按明细均可按来源单号检索。
- **库存联动（红线）**：确认上架统一经 `InventoryService.move`（源货位→目标货位，源/目标同减同增 + 库存日志）完成库位移动，**严禁绕过引擎**；源货位（收货暂存位）库存由收货确认 `confirmReceipt` 的 `increase` 建立。并做批次效期到期校验（有效期已过禁止上架）。
- **质检 PASS 前置（由收货端覆盖）**：收货上架前的质检校验由收货单 `confirmReceipt` 的"未检不入库"门禁（`quality.gate.enabled` 灰度开关，`qualityInspectionService.hasPassed("PURCHASE_ORDER", sourceOrderNo, null)`）覆盖，上架单不重复校验。
- **货位推荐**：表单新增「推荐货位」按钮，调用 `locationApi.recommend` 为未分配目标货位的明细行自动填充。

### 明细表格金标准对齐（2026-09-06）
本页明细列已统一采用 `BillDetailTable` 原生单元格：商品/来源货位/目标货位 `searchable`(SearchSelect 搜索下拉)、生产/有效期 `date`、数量 `number`、文本 `input`，**不再用 `type:'slot'` 内嵌 `a-select`/`a-date-picker`**；新建时 `onMounted` 生成 **20 行**，`min-rows` 沿用组件默认 **20**（`components/BillFormPage/BillDetailTable/index.vue` `minRows:20`，仅确需改变才传 `:min-rows` 并注释原因）。`BillDetailTable` 默认项（`minRows=20`、默认 `input` 原生单元格）已在组件 `types.ts`/`index.vue` 注释说明。

### 最终裁决方案（2026-09-02 · 严格按此执行）

> 与《发货单最终裁决》一致，本页遵循同一库存单一口径红线。

- **P0 库存单一口径（红线）**：库位移动统一经 `InventoryService.move`（源/目标同减同增 + 库存日志），**严禁绕过引擎**直接改库存（禁止双轨）。收货端补建暂存位库存后，本页改由 `move`（暂存→存储）完成闭环。
- **P2 批次/效期校验（本次做）**：上架校验批次到期（有效期已过禁止上架），并按 FEFO 先进先出排库。
- **明确不做的（红线）**：与收货/移库共用一套 `wms_inventory` 分账，不做第二套库位库存账。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
