## 业务规范说明

- **申请主线**：商城注册买家（公司）提交入驻申请 → 本页审核；审核结果写入「状态」字段（通过/驳回）。
- **行级操作**：通过 / 驳回（驳回需填原因，展示给买家）。审核通过后关联「绑定客户」（ERP 客户往来单位）。
- **字段口径**：公司名称（企业主体）、联系人姓名/手机号/地址/qq/微信（联系方式）、营业执照（资质图片）、申请时间（提交时间）。
- **审核状态**：待审核 / 已通过 / 已驳回（本系统 `auditStatus`：0 待审核 / 1 已通过 / 2 已驳回）。

## 实现差异说明

**实现文件**：
- 前端：`apps/pc-admin/src/views/mall/buyer-apply/index.vue`
- API：`apps/pc-admin/src/api/erp/mall.ts`（`shopUserApi`：`/erp/mall/admin/user/page`、`PUT /user/{id}/approve`、`PUT /user/{id}/reject`、`PUT /user/{id}/status`）
- 后端：`backend/erp/erp-mall/.../MallAdminController.java`（`@RequestMapping("/api/erp/mall/admin")`：`/user/page`、`/user/{id}/approve`、`/user/{id}/reject`、`/user/{id}/status`）

### 页面对齐（已建成：`ARReportPage`）
- **单表列表**：当前为 `ARReportPage`，带 3 张审核统计卡片（待审核/已通过/已驳回，`@loaded` 分页计数）。
- **查询区（2 字段）**：关键字（用户名/昵称/手机号/公司）、审核状态（待审核/已通过/已驳回）。未对齐金标准固定查询项（筛选条件、日期范围、状态）。
- **数据表列（11 列）**：用户名、昵称、公司、手机号、身份（企业客户/个人会员）、来源、审核状态、驳回原因、申请时间、审核时间、操作。
- **行级操作**：通过（popconfirm）、驳回（弹窗填原因，必填）；非待审核行显示「-」。
- **状态**：`auditStatus` 0 待审核 / 1 已通过 / 2 已驳回；`userType` ENTERPRISE 企业客户 / MEMBER 个人会员。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
