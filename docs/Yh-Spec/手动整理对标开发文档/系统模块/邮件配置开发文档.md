## 1. 页面概述

邮件配置页是**平台运营方的 SMTP 出站配置台账**：**双卡片并排布局**（左 `a-card title="SMTP 配置"` 内一个 5 字段内联表单；右 `a-card title="邮件模板"` 内一张 3 列裸 `a-table`）+ **3 个按钮**（`保存配置` / `测试连接` / 行内 `编辑`）。它属于 `61306 平台设置` 组的第 2 页（`sort=200`）。

> **一句话定性**：**本页整页不可用** —— 后端控制器 `MailConfigController` 所在包 `cn.aiedge.platform` **不在** `AiReadyApplication` 的 `scanBasePackages` 内 → **3 个端点从未装配、运行期全部 404**；同时前端另加调一个**后端根本不存在**的 `GET /api/mail/templates`（**必然 404**）→ **4 个请求 100% 失败**，且**全部被 `catch` 静默吞掉**，用户看到的是「一份像模像样的默认表单 + 一个恒空的模板表格」。

### 5.2 取值口径（「配置是怎么读出来、写回去的」）

```text
【读】onMounted(:171)
  ├─ GET /api/mail/config            → 404（后端未装配）
  │    └─ 失败 → catch { message.error('获取配置失败') }(:155-157)  ← 有提示
  │         → 表单保持硬编码默认值（host='' / port=465 / encryption='ssl' / username='' / password=''）
  └─ GET /api/mail/templates         → 404（端点不存在）
       └─ 失败 → catch { templates.value = [] }(:162-164)           ← 无提示
            → 表格恒空
【写】saveSmtp(:126-133)
  ├─ message.loading('正在保存...', 0)(:127)   ← 🔴 duration=0 → 永不自动关闭，且未持有 close 句柄
  ├─ POST /api/mail/config  body = smtp 整体   → 404（后端未装配）
  └─ catch { message.error('保存失败'?) }(:130-132)
```

**「页面显示的是什么」**：由于读接口 404，**用户看到的永远是与 DB 无关的硬编码默认值**（`port=465`、`encryption='ssl'`）。DB 里那两行（`host=smtp.example.com`）**在页面上永远回显不出来**。
**「保存写了什么」**：404 → **什么都没写**。DB 两行在页面上**既读不到也写不动**。

### 11.1 必须写清的「通道判别」事实（《对标开发技术参考文档》§5.6.2 硬规则）

1. **模块自带 yml 不生效**：若把 `spring.mail.*` 写进 `core/notification` 或任何**模块自带**的 `src/main/resources/*.yml`（位于嵌套 jar 内），**core-api 启动时不会加载**（Spring Boot 只读 classpath 根那一份）→ **必须写到 core-api 的 `application.yml`**（或 `application-{profile}.yml` / 启动参数 `--spring.mail.host=...` / 外部化文件 `--spring.config.additional-location=file:./config/`）。
2. **前端 `VITE_*` 是构建期注入**：本页**未使用** → 无需 CI 注入；代价是**任何前端改动都要重新构建**（本页的两个 `message.loading(..., 0)` 缺陷、按钮接线等修复都属前端改动 → **必须 rebuild 才生效**）。
3. **密钥优先不入库**：`sys_mail_config.password` 是明文列 —— 能用环境变量/Secret 的**绝不写进表**；确需页面维护的，按通道 ④ 落库，并遵循「**脱敏展示 + 仅授权角色可见 + 日志不打印**」（本页日志侧**已做到不打印**，其余两项**均未做到**）。
4. **必须有降级**：配置缺失时**不得阻塞业务**。当前 `spring.mail.*` 缺失 → 邮件通道不可用（明确失败）；**但本页不可作为兜底**（未接线）→ 表现为「用户在页面上配了也没用」。
5. **换配置要能生效**：本页**当前无生效方式**（无消费方）。目标形态有两种，**须先裁定**：
   - **路线 A**：保持 `spring.mail.*` 为唯一真源（**推荐**）→ 本页应改成**只读诊断页**（显示当前生效的 host/port/encryption 来源 + 是否配置，**不回显明文**，参照 `GET /api/dms/route/config` 的 `keySource` 口径）；
   - **路线 B**：让 `EmailSenderImpl` 改读 `sys_mail_config`（热生效）→ 需补**缓存失效机制**（保存后发领域事件 + 消费方失效本地缓存，多实例 TTL 兜底），并**显式豁免租户插件**（§11.1-6）。
6. **多租户读全局默认行**：`sys_mail_config` 的 2 行都是 `tenant_id=0` → 读它**必须** `@InterceptorIgnore(tenantLine = "true")`；否则被租户插件注入条件 → **查回 null → `Map.of` NPE → 500**（§7.4）。
