## 页面概述

费用审批用于对**已提交的费用单**进行审批处理（通过/驳回）。模块为单一工作区页（待审批队列 + 审批操作弹窗 + 审批详情弹窗），单入口。

| 页面 | 地址 | 说明 |
|------|------|------|
| 费用审批 | `finance/expense-approval` | 待审批费用单队列 + 通过/驳回/提交审批/详情 |

菜单：财务 → 费用管理 → 费用审批。

### 配置功能说明

- **列配置**：**只保留「数据表表头齿轮」入口**（`BillDetailTable` 内置「数据表列配置」弹窗，个人/全局配置），24 个可配置列（默认显示 12），存储键 `expense-approval-table-columns`。**工具栏不放列配置按钮**（重复入口，2026-09-10 用户明确指出）。
- **页面配置**：工具栏齿轮（`PageConfigPanel`），**查询条件**（11 项）+ **功能按钮**（刷新/导出/页面配置），存 `localStorage: expense-approval-page-config`。
- **审批人配置**：工具栏「审批人配置」（人员图标），按级别配置默认审批人（第一级/第二级/第三级），保存于系统参数 `sys_project_config`（`config_group = expense_approval`），用于审批人**自动指派**。
- **导出**：工具栏「导出」，导出当前查询条件下的待审批清单 CSV（文件名 `费用审批_yyyyMMdd_HHmmss.csv`）。
- **快捷日期**：昨日/今日/本周/近一周/本月/上月/近三月/本年（默认近三月）。
- **悬停提示（全局组件约定）**：图标按钮的 `a-tooltip` 一律**下置**（`placement=bottom`）避免浮层压住按钮/标签栏。该约定已做成**组件级默认值**（`utils/antdDefaults.ts` 覆盖 `Tooltip.props` 默认：bottom + 0.4s 悬停延迟），各页无需逐个传参。

## 审批人自动指派

> 目标：提交/通过环节不再每次手选审批人，按「级别」自动路由，同时保留手动改选。

### 指派规则（后端唯一口径，前端仅展示）

| 级别 | 解析顺序 | 来源标记 |
|------|---------|---------|
| 第一级（部门审批） | ① 费用单所属部门负责人（`sys_dept.leader` 姓名匹配 `sys_user` 的昵称/姓名/用户名）② 审批人配置·第一级 | `DEPT_LEADER` / `CONFIG` |
| 第二级（财务审批） | 审批人配置·第二级 | `CONFIG` |
| 第三级（总经理审批） | 审批人配置·第三级 | `CONFIG` |

未解析到审批人时返回 `source = NONE`，前端提示「未配置该级默认审批人，可先在「审批人配置」中预设」，提交/通过时要求手选。

### 接口

| 接口 | 说明 |
|------|------|
| `GET /api/erp/finance/expense-approval/approver-config` | 读取三级默认审批人 |
| `POST /api/erp/finance/expense-approval/approver-config` | 保存三级默认审批人（`null` = 清除该级别） |
| `GET /api/erp/finance/expense-approval/suggest?docId=&totalLevel=` | 按级别返回建议审批人（含来源），供提交/通过弹窗预填 |

### 存储

系统参数表 `sys_project_config`（`config_group = expense_approval`，`config_key = expense.approval.level{N}.approverId`，值 = 审批人用户ID），复用系统参数能力（`SysConfigService`），不新建配置表。

### 自动流转

- **提交**：不带 `approverId` → 后端按规则自动指派第一级。
- **通过**：不带 `nextApproverId` → 后端按规则自动指派下一级；末级直接置「审批通过」。
- **手动改选**：弹窗内可随时改选，改选后 `nextApproverId` 以弹窗选择为准（优先于自动指派）。
- **部门负责人优先**：若部门已维护负责人（`sys_dept.leader`），第一级审批自动取该负责人，无需配置第一级默认审批人。

## 审批详情弹窗

- **费用单**：单据编号/单据日期/费用类型/本单金额/往来单位/往来编号/经手人/部门/制单人/制单时间/单据状态/审批状态/当前审批人/提交时间/付款账户1/付款金额1/摘要/单据备注（有驳回原因时追加红字展示）。
- **费用项明细**：行号/费用编号/费用名称/费用科目/金额/备注 + 标题行合计。

数据源 `GET /api/erp/finance/expense-approval/detail/{docId}`（费用单详情 + 费用项明细 + 审批记录）。

## 业务规范说明

- **审批链**：`未提交 → 部门审批中(1/n) → 财务审批中(2/n) → 总经理审批中(3/n) → 审批通过`；任一环节可驳回。`n` = 提交时选择的审批级数（1-3，默认 3）。
- **action 语义**：`APPROVE` 通过（未到末级须指定下一级审批人，`approval_level + 1`）／`REJECT` 驳回（原因必填，写 `erp_expense_doc.reject_reason`，状态置「审批驳回」）。
- **审批人隔离（P1）**：提交时**自动指派**第一级审批人（部门负责人 → 审批人配置，可手改），逐级通过时自动指派下一级；`erp_expense_doc.current_approver_id` 即本级待办归属。「仅看我的待办」默认勾选，后端按其过滤；已被指派的单据，非当前审批人调用 `/process` 直接拦截。
- **审批留痕**：每次操作（提交/通过/驳回）写 `erp_expense_approval`（单号/级别/审批人/动作/意见/时间/前后状态），可经 `/records` 追溯。
- **记账门控（P1）**：审批中/已驳回的费用单**禁止记账**；未提交（未经审批直接记账，兼容 ql361「草稿→记账」原生流程）与审批通过均可记账。审批中的费用单同时**禁止修改与取消**。
- **下游（P1 费用支付）**：审批通过后费用单进入可记账状态；《费用单》的「记账」即费用支付落账（扣付款账户余额 + 记资金流水 + 生成会计凭证 `KJPZ-`），不另建 `expense_payment` 表，避免重复开发。
- **待审批范围**：`/pending` 默认返回 `approval_status = 1`（审批中）的费用单；可切换审批状态筛选查看未提交/审批通过/审批驳回。
- **上游**：《费用单》（`finance:expense-doc`）保存草稿后，页头操作「提交审批」或在《费用审批》列表行内「提交审批」进入本页队列。
