## 测试策略概述

### 1.1 测试目标

- **功能验证**: 确保API接口按照需求规格正确实现
- **稳定性保障**: 验证接口在各种负载条件下的稳定性
- **安全合规**: 确保接口符合安全标准和数据保护要求
- **性能基准**: 建立接口性能基准，监控性能退化

### 1.2 测试原则

| 原则 | 说明 |
|------|------|
| **自动化优先** | 核心接口测试用例必须自动化，减少人工回归成本 |
| **左移测试** | 在开发阶段即介入接口契约定义和设计评审 |
| **数据驱动** | 使用外部数据文件驱动测试，提高可维护性 |
| **环境隔离** | 测试数据与生产数据完全隔离，避免污染 |
| **持续监控** | 接口测试集成到CI/CD流水线，每次代码变更自动触发 |

### 1.3 测试类型分布

```
测试类型占比:
├── 功能测试 (Functional)     40%
├── 边界测试 (Boundary)       20%
├── 异常测试 (Exception)      15%
├── 安全测试 (Security)       15%
├── 性能测试 (Performance)    10%
```

#### 2.1.2 测试深度

| 测试层级 | 描述 | 覆盖范围 |
|----------|------|----------|
| **单元接口测试** | 单个接口的独立验证 | 所有接口的CRUD操作 |
| **集成接口测试** | 多接口组合的业务流程 | 核心业务场景 |
| **端到端测试** | 完整用户操作流程 | 关键业务链路 |

### 2.2 测试边界

#### 2.2.1 包含范围

- ✅ RESTful API接口（HTTP/HTTPS）
- ✅ 标准HTTP方法（GET/POST/PUT/DELETE/PATCH）
- ✅ JSON/XML数据格式处理
- ✅ 认证授权机制（JWT/OAuth2）
- ✅ 文件上传/下载接口
- ✅ 分页、排序、筛选功能

#### 2.2.2 不包含范围

- ❌ WebSocket实时通信接口（由专项测试覆盖）
- ❌ 第三方系统集成接口（由集成测试覆盖）
- ❌ 移动端原生SDK接口

## 测试数据准备策略

### 3.1 数据分类

| 数据类型 | 描述 | 管理方式 |
|----------|------|----------|
| **静态数据** | 不随测试执行变化的数据（如配置、枚举值） | 配置文件管理 |
| **动态数据** | 测试执行过程中生成的数据（如订单号） | 运行时生成 |
| **测试专用数据** | 为特定测试场景准备的数据 | JSON/CSV文件 |
| **敏感数据** | 涉及隐私的数据（如手机号、身份证号） | 脱敏/伪造处理 |

### 3.2 数据生成策略

#### 3.2.1 数据生成方式

Faker faker = new Faker(Locale.CHINA);

// 2. 使用时间戳保证唯一性
String uniqueId = "TEST_" + System.currentTimeMillis();

// 3. 使用UUID生成唯一标识
String uuid = UUID.randomUUID().toString();

// 4. 从测试数据文件加载
TestDataLoader.load("customers.json");

### 3.3 数据清理策略

| 策略 | 适用场景 | 实现方式 |
|------|----------|----------|
| **测试后清理** | 大多数场景 | @AfterEach注解清理 |
| **测试前清理** | 需要干净环境 | @BeforeEach注解准备 |
| **定期清理** | 长期运行环境 | 定时任务清理测试数据 |
| **事务回滚** | 数据库测试 | Spring事务回滚 |

```java
@AfterEach
void cleanup() {
    // 删除测试创建的数据
    testDataCleaner.cleanup("users", "username LIKE 'TEST_%'");
    testDataCleaner.cleanup("orders", "order_no LIKE 'TEST_%'");
}
```

### 3.4 数据隔离原则

1. **命名空间隔离**: 测试数据使用特定前缀（TEST_）
2. **租户隔离**: 使用独立租户/组织存放测试数据
3. **时间戳隔离**: 数据包含创建时间戳，便于识别和清理
4. **环境隔离**: 各环境使用独立数据库实例

## 测试环境配置

### 4.1 环境矩阵

| 环境 | URL | 用途 | 数据策略 |
|------|-----|------|----------|
| **开发环境** | http://dev.qizhilian.com:8080 | 开发自测 | 自动生成 |
| **测试环境** | http://test.qizhilian.com:8080 | 自动化测试 | 测试数据集 |
| **预发布环境** | http://staging.qizhilian.com | 回归测试 | 生产数据脱敏 |
| **生产环境** | https://qizhilian.com | 监控探测 | 只读操作 |

### 4.2 环境配置管理

#### 4.2.1 配置文件结构

```properties
# application.properties (默认配置)
base.url=http://localhost:8080
api.version=/api/v1
connection.timeout=10000
socket.timeout=30000

# application-dev.properties (开发环境)
base.url=http://dev.qizhilian.com:8080

# application-test.properties (测试环境)
base.url=http://test.qizhilian.com:8080

# application-staging.properties (预发布环境)
base.url=http://staging.qizhilian.com

# application-prod.properties (生产环境-只读)
base.url=https://qizhilian.com
read.only=true
```

#### 4.2.2 环境切换命令

```bash
# 指定环境运行测试
mvn test -Dspring.profiles.active=test

# 指定自定义配置
mvn test -Dbase.url=http://custom.api.com
```
