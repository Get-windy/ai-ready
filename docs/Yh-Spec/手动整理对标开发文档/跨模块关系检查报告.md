# 跨模块关系检查报告 —— 库内作业 & 质量管理 与 采购/销售/库存 的关系审视

> **文档类型：** 架构审查报告
> **日期：** 2026-09-02
> **审查范围：** 仓储「库内作业」5 单据（收货/上架/拣货/发货/移库，80012-80016）+「质量管理」3 页面（质检单/质量标准/缺陷记录，90201-90203）与 采购订单/销售订单/销售出库/库存引擎 的跨模块业务关系。
> **对标参照：** Odoo Inventory / SAP EWM+QM / 金蝶 / 用友 / 管家婆 等生产级系统的业务闭环。
> **结论性质：** 页面级（表单/列表/配置）已对齐金标准；**业务链级**存在系统性断链，详见下。

---

## 〇、总体判断

当前系统呈现**"三套各自为政"**：

- **ERP 采购域 / 销售域**各有自己的闭环，但**只在自己模块内部转，不向下游 WMS 派发**。
- **WMS 库内作业**是**纯作业执行层孤岛**：只推进任务状态机，不产生库存变动、不回调 ERP、不生成下游单据。
- **质量域**是**四套并行的孤岛**：①ERP 采购入库内置"走过场质检" ②WMS 收货无质检 ③独立 `quality_inspection` 质检单 ④批次质检。

**核心病灶（4 处）**：
1. **库存与作业脱节**——WMS 收货/上架/拣货/发货完成 = 库存零变化。
2. **库存双轨割裂且不对称**——`erp_stock`（仓库级总账）与 `wms_inventory`（库位级分账）。
3. **单据无下推链**——PO→收货、SO→波次→拣货→发货全靠"自由文本来源单号"，无外键强关联。
4. **质检不参与门禁**——不合格（FAIL）仍可入库。

## 一、采购域：收货 ↔ 采购订单 ↔ 质检（对标 SAP GRN + IQC）

### 1.1 采购订单现状
- 主表 `PurchaseOrder`（`erp_purchase_order`）：`orderNo/status(0草稿…2已审批)[3已下达/5履行中/6已完成 从未写入]`、`totalQuantity`、`receivedAmount(实为金额)`。
- 明细 `PurchaseOrderItem`：含 `receivedQuantity`/`unreceivedQuantity` 等"已收字段"，但**全库无任何模块回写**。
- **只支持「下单→审批」**，无下达/到货/转收货/完成端点。
- `addReceivedQuantity`（Mapper）**零调用**；列表把 `received_amount` 当数量展示 → **已收/未收为死列/伪数据**。

### 1.2 WMS 收货与采购的关系
- `ReceiptServiceImpl.createFromPurchaseOrder` **不存在**（非 TODO，是未实现）。
- `ErpIntegrationController`（`POST /api/wms/erp/purchase-order`）字段映射正确（sourceType=0/sourceOrderId/sourceOrderNo/supplierId），但**全后端无任何 ERP 调用方**。
- 前端收货单"来源单号 `sourceOrderNo`/供应商 `supplierName`"为**自由文本**，`buildPayload` 不提交 `sourceOrderId/supplierId`。
- **三套并行入库**：`erp_purchase_inbound`（写 `erp_stock`+生成应付）／ `wms_receipt_task`（纯任务，不写库存）／ `erp_stock-in`（其他入库）。互不引用 → **三轨冲突/重复入账风险**。

### 1.3 质检联动
- `purchase_inbound` 主表有 `qualityCheckResult`(String)、`qualityCheckedBy/Time`；明细 `qualityStatus/qualityNote`（**从不写**）。
- `qualityCheck(id,result)`：仅把状态置 `QUALITY_CHECKED(6)`，**不校验 result**，FAIL 仍可 `confirmWarehouse` 入库（`updateStock` 直接加 `erp_stock`+生成应付）。
- 独立 `quality_inspection`（bizType=bizId=bizNo/inspectionResult=PASS/CONCESSION/FAIL）**零联动**：无模块自动创建、无模块消费结果去放行/拦截库存。

## 二、销售域：拣货 ↔ 发货 ↔ 销售出库（对标 SAP SO→波次→拣货→出库）

### 2.1 销售域内部闭环（ERP 自成）
- `SaleOrder`（`erp_sale_order`）审批冻结库存；`SaleOutbound`（`erp_sale_outbound`）是**销售出库单**实体，`ship()` 调 `updateStock→stockService.decreaseStock` 扣 `erp_stock` 并回写订单已发数量。
- **重复扣减隐患**：订单级 `SaleOrderServiceImpl.confirmShipment`（auto createFromOrder + decrease）与出库单级 `SaleOutboundServiceImpl.ship` 两条路径都会扣；且 `erp/sale` 页 "拣完发货" 传 `warehouseId=0` → `decreaseStock` 返回 false 被忽略 → **静默失效**。
- `StockOut`（其他出库单，`/erp/stock/out`）与销售出库**解耦**，且 `StockOutServiceImpl.execute` 只置状态3，**实际不扣库存**（注释"扣减库存"但无实现）。

### 2.2 WMS 拣货/发货与销售完全断链
- `WmsPickTask`（sourceType 1销售/2退货/3调拨/4盘亏；sourceOrderId/sourceOrderNo/customerId/customerName）——字段在，但**无赋值路径**。
- `PickServiceImpl.createWave(List<Long>)` 是**桩**：只插一条 `wms_pick_wave` 头，不查 `erp_sale_order`、不生成 `wms_pick_task`/`wms_pick_detail`。
- `ErpIntegrationController.receiveSaleOrder` 内部仅调 `createWave`，仍不产任务/明细；ERP 侧**零调用**。
- 前端 wave 页"生成拣货任务"调 `pickApi.waveCreate({waveId})` **vs** 后端收 `List<Long>` → **契约错位**。
- 拣货/发货表单"来源单号/客户"自由文本；`waveId/pickTaskId/sourceOrderId/customerId` **前端永不填**。
- `completePick`/`confirmShip` 只改状态，**不生成 `erp_sale_outbound`、不扣库存、不回写订单**；outbox 无生产者、ERP 回调（`ErpCallbackServiceImpl`）**只打日志**。

## 三、库存域：各单据是否落库存台账（对标 Odoo 库存移动 / SAP 物料凭证）

### 3.1 库存两表 + 引擎口径
| 表 | 粒度 | 关键列 |
|---|---|---|
| `erp_stock` | 仓库级（product+warehouse，可 batch） | quantity/available/frozen/unit_price |
| `wms_inventory` | 库位级（product+warehouse+**location_id**+batch） | quantity/available/frozen/unitCost |
| `wms_inventory_log` | 每笔变动一行 | traceId/changeType/direction/before-after/sourceType/sourceId/sourceNo |

`InventoryServiceImpl`（increase/decrease/freeze/unfreeze/move，`FOR UPDATE` 锁 + 写 `wms_inventory_log` + 镜像 `erp_stock`）：
- **镜像单向且不对称**：仅 WMS 引擎 `increase/decrease` 向外写 `erp_stock`（decrease 镜像失败仅告警不回滚 → 允许两账漂移）；ERP 侧直写 `erp_stock` **无反向、无日志、无对账/初始化**。
- `freeze/unfreeze/move` 不镜像 `erp_stock`（总量不变）。

### 3.2 各单据驱动库存判定

**驱动库存（只落 erp_stock，无日志/无 wms）：** 采购入库 `confirmWarehouse`、采购退货、销售下单/发货、销售出库、零售、销售换货、报损 `execute`、报溢 `execute`、盘点 `StockTake.process`、组装/拆分 `execute`（绕过 StockService 裸写 mapper）、调拨 `execute`。

**走 WMS 引擎（wms_inventory+log+镜像 erp_stock）：** WMS 借进借出（记账/归还）、**WMS 移库 `executeMove→InventoryService.move`（唯一接入引擎的库内单，仅库位间**）、`InventoryController`（手工调整）。

**确认后库存零变化（业界严重缺陷）：**
- ERP 其他入库/其他出库 `StockIn/StockOut.execute`（只置状态3，无记账）。
- **WMS 收货 `confirmReceipt`、上架 `confirmPutaway`、拣货 `completePick`、发货 `confirmShip` 全部只推任务状态**，不产生任何库存变动、不联动 ERP 采购/销售过账。
- WMS 盘点 `submitResult/approveCheck` 不调库存。
- 拣货**未做可用量 freeze 预留**；缺货 `markShortage` 不基于 `wms_inventory.available` 引擎级校验。

## 四、业界对照总结

| 业界生产级系统关键特征 | 本系统现状 | 判定 |
|---|---|---|
| 库存**单一来源**，业务动作产生库存移动/物料凭证，自动生成账 | `erp_stock` 与 `wms_inventory` 两套账，单向镜像且允许漂移，无收敛 | **双轨割裂** |
| 单据**下推/转换**成链，source doc 贯穿（PO→GRN→IQC→入库；SO→出库→拣货→发货→扣库存） | PO→收货、SO→波次→拣货→发货全是**自由文本来源单号**，`createWave`/`createFromPurchaseOrder` 桩、契约错位 | **无下推链** |
| **状态机门禁**：质检不合格不入库、拣货基于可用量预留、发货确认才扣库存 | FAIL 仍入库；拣货无冻结；WMS 4 单确认不扣库存 | **门禁缺失** |
| **事件/回调**驱动下游 | outbox 无生产者，ERP↔WMS 回调全是日志占位 | **空转** |
| 作业完成 = 库存过账 | WMS 收货/上架/拣货/发货完成**库存零变化** | **严重缺陷** |

## 五、P0 → P2 问题清单

| 级别 | 问题 | 影响 |
|---|---|---|
| **P0-1** | **WMS 收货/上架/拣货/发货完成不产生库存变动、不生成/联动 ERP 出入库单** | 前端"已收货/已发货"与账面库存**必然不一致** |
| **P0-2** | **库存双轨割裂**（erp_stock 主账 / wms_inventory 分账），单向镜像可漂移、无初始化/对账 | 两套库存账随时不一致 |
| **P1-1** | **单据无下推链**：PO→收货、SO→波次→拣货→发货无外键关联；`createWave`/`createFromPurchaseOrder` 桩、前后端契约错位 | 业务链无法自动流转，全靠手填单号 |
| **P1-2** | **质检不参与门禁**：FAIL 仍可入库；`quality_inspection` 结果无人消费；质检四套孤岛 | 不合格品可入库 |
| **P2-1** | **销售域重复扣减**（订单级 `confirmShipment` 与出库单级 `ship` 两次扣）；`erp/sale` 页传 `warehouseId=0` 静默失效；PO 已收/未收为伪数据；其他出入库 `execute` 假记账 | 库存/订单进度失真、可能重复扣 |
| **P2-2** | 事件/回调空转（outbox 无生产者、ERP 回调日志占位） | 模块间无法自动协同、无审计 |

## 复查结论（2026-09-03 · 代码级核验）

> 开发大幅推进后，对"文档已实现"与否做代码级核验（防文档超前于代码）。核验方式：grep 端点映射 + 读关键 Service/Executor 行号。

### ✅ 已达标（真实落码）
- 收货确认 → `InventoryService.increase`（同事务镜像 `erp_stock`，失败抛异常回滚）+ 效期过期拦截 + IQC 门禁（`qualityInspectionService.hasPassed`）+ HTTP 调 ERP `/api/erp/purchase/order/received` 回写 PO 已收（`addReceivedQuantity` 真实）。
- 上架确认 → `InventoryService.move`（源→目标，禁绕引擎）+ 效期校验；移库 = `move` + 单内序列号唯一校验（`FOR UPDATE` 锁）。
- 拣货：startPick `freeze(应拣)`、completePick `unfreeze+decrease(实拣)`（仅一次，禁双扣）、cancelTask 只 `unfreeze`。
- 金标准列表/表单（`CategoryListLayout`/`BillTableList`/`BillFormPage`/`BillDetailTable` + 列/页面/打印配置弹窗）、单号 `next-no`（ZJD-/QSTD-）、货位推荐、`listAvailableBatch`(FEFO 按 validityDate)。

### ❌ 仍未闭环（代码事实，文档超前）
| 项 | 代码现状 | 业界要求 |
|---|---|---|
| **发货→ERP 出库确认（P0 断点）** | WMS `confirmShip` 只 `freeze`，HTTP 调 `/api/erp/sale-out/confirm` —— **该端点 ERP 源码不存在**（erp-sales 前缀 `/api/erp/sale/outbound`，无 confirm 子路径）→ `confirmShip` 执行即 **404 抛异常回滚**；且 WMS 侧**无解冻承接**，确认量以冻结态滞留 `wms_inventory` | 发货确认 → 生成销售出库单 + 唯一扣减 |
| **库存双账仍割裂** | ERP 侧大量直写 `erp_stock` 不经引擎、永不同步 `wms_inventory`（采购入库/销售确认/零售/换货/退货/报损/盘盈/期初）；**无初始化/对账/回填**（`wms_inventory` 建行仅 3 处 increase/move/borrow）；`decrease` 镜像失败仍仅告警（与 increase 强一致不对称） | 单一库存来源 + 库存移动 + 对账 |
| **采购下推 WMS 无触发** | WMS `/api/wms/erp/purchase-order` 接收端真实，但 **ERP 侧零调用方** → 采购审批后不自动生成收货任务（仅手工） | PO→GRN 下推链 |
| **拣货→发货现金口径不自洽** | `completePick` 已 decrease 入 `erp_stock`；`confirmShip` 对同一 (product/warehouse/location/batch) 又 `freeze` → 可用量可能不足抛错；且 ERP `SaleOutbound.ship` 再扣一次 → **同单两处扣减** | 拣货→发货→出库一条扣减链 |
| **ERP 采购入库不经引擎** | `confirmWarehouse` 仍直改 `erp_stock`（不写 `wms_inventory`）；`qualityCheck` 仍**不校验 result**（FAIL 可入库，只看外部质检记录） | 未检/不合格不入库 |
| **其他出入库假记账** | `StockIn/StockOut.execute` 仍"只置状态"，无库存 SQL | 出入库过账必落库存 |
| **扫码复核非累计** | `scanItem` 是**覆盖写 + 单次扫码**（status=1 后二次扫被拒），非累加 `scannedQuantity` | 复核逐箱累加 |
| **质量门禁无开关+无生产方** | `quality.gate.enabled` 配置**不存在**（硬编码强制开启）；且无"按 PO 自动建质检单"生产方 → 需手动建 PASS 记录才能收货，否则被拦 | 质检自动产生 + 可开关灰度 |
| **事件/回调空壳** | `publishEvent` **无任何生产者**；`ErpCallbackServiceImpl` 4 个回调仍为 **log-only** 占位 | 模块间事件驱动 + 审计 |

### 对照业界总评
已对齐：WMS 作业确认驱动库存（收货增/上架移/拣货发扣/移库移动）、批次效期(FEFO)、质量校验门禁、金标准 UI —— 具备生产级 WMS 骨架。
未达标（= 与 Odoo/SAP 差距）：①单一库存来源未实现（`erp_stock`/`wms_inventory` 双账、ERP 直写点未收敛、无对账）；②发货→出库扣减闭环断裂（`/api/erp/sale-out/confirm` 缺失 + 无解冻承接）；③单据下推链不全（采购下推无触发、拣货→发货口径不自洽）；④未检/不合格入库在 ERP 侧仍可绕过；⑤事件/回调空转。

> 参考：单体应用（`AiReadyApplication` 同扫 `cn.aiedge.erp.*` 与 `cn.aiedge.wms`，端口 5655），WMS 的 `wms.erp.base-url` 为**本进程自调用**；依赖方向为 `wms → erp-stock`（erp-sales/erp-purchase 不依赖 wms）。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
