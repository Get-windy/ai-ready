## 1. 页面概述

经营历程是**跨业务域「已过账」单据的全量流水台账**：把销售 / 采购 / 收付款 / 库存 / 费用等各域已记账的正式单据按业务日期倒序汇总，提供红冲（作废）、复制、备注等行级操作，是全系统单据级「经营档案」。**单入口、单视图**（无页内 Tab）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 经营历程 | `analytics/business-history` | 单视图列表页（跨 13 类单据全量流水 + 行级红冲/复制/备注） |

单入口：分析 → 综合单据 → 经营历程。

- 页面结构：查询方案 + 时间快捷段 + **两行查询区** + 流水台账表格（首列红色齿轮列配置入口 + 序号线 + 固定「操作」列，**无行勾选框**）+ 底部合计行 + 分页条。
- 实测实据（2026-09-15）：共 **2,934** 条记录、第 **1/147** 页、每页显示 **20** 行、底部合计 **2,087,351.86**。当前页可见行均为「收款单」（`SKD-20260915-0xx`）。
- 多 Tab 判定：实测 JSON `tabs` 为 `{}`（空对象），`.png` 顶部仅一个「经营历程」页签 → **单视图，无子 Tab**。

### 配置功能说明

- 实测工具栏（右上）：`刷新`、`打印(F8)`、`导出`（另有 `更多` 折叠项）；**本组三页中唯本页有打印**。
- 实测行级动作：每行「操作」列 = `红冲(作废)`、`复制`、`备注`（三个动作）。
- 列配置：数据表表头**红色齿轮**图标（首列），弹出列配置弹窗（含「个人配置 / 全局配置」两 Tab）；下表列数取自**全局配置**实测。
- **无行勾选框**：与同组《待审批单据》《业务草稿》不同，本页表头无 checkbox → 无批量动作。

## 4. 业务规范

### 统计口径与数据关系

- **数据范围**：全部业务域已过账（已记账）单据的全量流水，一行一单，默认按时间快捷段过滤（实测 2026-09 月内共 **2,934** 条）。
  - 后端实现为 13 个单据分支的 UNION 聚合（`DocQueryService.java` 的 `BRANCHES`，`DocQueryService.java:50-127`），`StatusMode.ALL` 时**不过滤状态**，按业务日期倒序分页。
- **金额口径**：单据金额原值列示，底部合计对当前过滤范围求和（实测 `2,087,351.86`）。红冲单以负数 / 红字参与合计。
- **来源订单列**：由订单下推生成的单据（如销售订单 → 销售出库单）记录来源订单号，实现单据链追溯。
- **红冲(作废)**：冲销后原单不删除而成对保留（原单 + 红冲单），保证流水可审计；勾选 `显示红冲` 可见红冲记录。红冲单同步回写库存 / 往来 / 资金。
- **复制**：以当前单据为模板快速开新单。
- **备注**：维护单据备注信息（对应列配置中的 `单据备注`）。
- **组内分工**（综合单据组三页 = 单据生命周期的三个横切状态）：
  《业务草稿》提交记账后进入本页；本页是全系统单据级「经营档案」，各统计分析页均以此为底层取数源。

### 与其他页面关系

- **上游**：《业务草稿》（提交记账过账）、各业务域表单页直接提交 / 记账的单据。
- **下游**：红冲(作废) 生成红冲单同步回写库存 / 往来 / 资金；销售业绩、经营分析、查应收 / 查应付等分析页取数基础。
- **同组页面**：待审批单据、业务草稿。

## 5. 实现差异说明

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/business-history/index.vue`（共 83 行）。
- **骨架**：`ARReportPage` 只读报表壳（`index.vue:2-21`，`title="经营历程"`、`export-file-name="经营历程"`、`row-key = docTypeCode-docNo`）。`ARReportPage` 为纯报表壳（`components/ARReportPage/ARReportPage.vue`：内联查询表单 `:16-64` + `a-table` `:100-120` + 内置分页 `:234-240` + 内置 CSV 导出 `:340-371`），**不含** `BillDetailTable` / `StandardPagination` / `PageConfigPanel`，**无列配置齿轮、无页面配置弹窗**。
- **查询条件**：`queryFields`（`index.vue:45-50`）= `单据类型`（select，13 项，`DOC_TYPE_OPTIONS` 见 `:29-43`）、`单号`（input）、`往来单位`（input）、`业务日期`（date-range）。**共 4 项**。
- **列定义**：`columns`（`index.vue:53-61`），共 **7 列**：单据类型、单号、业务日期、往来单位、金额、状态、操作人。
- **状态着色**：`statusColor()`（`index.vue:64-71`）；金额格式化 `formatMoney()`（`:73-76`）。
- **数据请求**：`fetcher`（`index.vue:79-81`）→ `docQueryApi.businessHistoryPage`。
- **无统计卡片**：本页**未传** `stat-cards`、**未监听** `@loaded`（同组另两页有卡片区）——与对标一致（对标本页无卡片区）。
- **行选择**：**禁用**（`ARReportPage` 的 `enableRowSelection` 默认 `false`，`ARReportPage.vue:199`；本页亦未传该 prop）→ 无勾选框 —— 此点**与对标一致**（对标本页亦无勾选框）。
- **打印（F8）**：**无实现** —— `ARReportPage` 仅内置「刷新」「导出」两个工具栏按钮（`ARReportPage.vue:80-97`），无打印能力、无 F8 快捷键绑定。
- **导出**：`ARReportPage` 内置「当前页 CSV 导出」（`ARReportPage.vue:340-371`），**非真实 xlsx、非全量导出**；本页传了 `export-file-name="经营历程"`（`index.vue:7`）故导出按钮可见。
- **数据来源**：`apps/pc-admin/src/api/analytics.ts` → `docQueryApi.businessHistoryPage`（`analytics.ts:86-88`，`GET /docquery/business-history/page`）。
- **后端**：`backend/core/api/core-api/src/main/java/cn/aiedge/docquery/controller/DocQueryController.java:38-52`（`@RequestMapping("/api/docquery")`，`businessHistory`，`StatusMode.ALL`）；服务层 `docquery/service/DocQueryService.java:144`（`page`）。
- **storage-key**：无（未使用列配置 / 页面配置持久化）。

### 剩余缺口

1. **🔴 未达金标准（骨架层）**：本页为 `ARReportPage` 只读壳，未使用 `CategoryListLayout` / `BillDetailTable` / `StandardPagination` / `PageConfigPanel`；无列配置齿轮、无页面配置弹窗。（按本页对标规格，达标线 = 查询区齐全 + 列配置可用 + 分页 + 行级操作，本页仅命中「分页」一项。）
2. **🔴 列配置能力完全缺失**：对标 17 列 / 默认 9 未落地；无表头齿轮、无个人 / 全局配置持久化。缺 `来源订单`、`制单人`、`记账人`、`摘要`、`单据备注`、`附件`、`制单时间`、`记账时间`、`打印次数` 等关键列。
3. **🔴 行级操作完全缺失（本页核心动作）**：对标行级 `红冲(作废)` / `复制` / `备注` 均无实现；`columns` 中无「操作」列。其中 `红冲(作废)` 是最重的业务缺口（红冲需生成红冲单并回写库存 / 往来 / 资金）。
4. **🔴 查询条件不对齐**：对标 9 项 + 1 勾选（查询方案 / 时间快捷段 / 日期范围 / 单据类型 / 单据编号 / 往来单位 / 仓库 / 经手人 / 部门 / `显示红冲`），本页仅 **4 项**；缺 `仓库`、`经手人`、`部门`、`显示红冲` 勾选项、查询方案、时间快捷段。
5. **🔴 列结构不对齐**：本页 7 列（单据类型 / 单号 / 业务日期 / 往来单位 / 金额 / 状态 / 操作人）vs 对标 17 列。语义近似仅 4 列（单据类型 / 单据编号(单号) / 往来单位 / 金额）；缺 9 列默认可见列中的 `单据日期`（本页用 `业务日期`）、`来源订单`、`仓库`、`经手人`、`部门`（5 列）+ 8 个隐藏列；本页多出 `状态`、`操作人` 两列（对标无）。
6. **🔴 底部合计行缺失**：对标底部固定合计行（实测 `2,087,351.86`）；`ARReportPage` 的 `a-table` 无 `summary` 配置。本页**亦无统计卡片**可近似呈现，故金额合计能力完全缺失。
7. **🔴 打印(F8) 未实现**：对标有 `打印(F8)`（本组三页中唯本页有）；本页 `ARReportPage` 无打印按钮、无 F8 绑定。
8. **🔴 导出不达标**：对标为其自身导出（全量 / 服务端导出口径**待复核**）；本页为 `ARReportPage` 内置**当前页 CSV**（`ARReportPage.vue:340-371`），非真实 xlsx、非全量。
9. **无行勾选框 → 对齐（非缺口）**：本页 `enableRowSelection=false` 与对标一致（对标本页亦无勾选框，故无批量动作），此点无需整改。
10. **无 E2E 脚本**：`tools/` 下**无** `e2e-analytics*.cjs` —— 本页**未跑过** E2E，如实标注。
