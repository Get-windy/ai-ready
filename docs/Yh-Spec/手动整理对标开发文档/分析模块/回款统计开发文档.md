## 1. 页面概述

回款统计页是**回款的三口径归集报表**：同一份底层回款数据，按人员维度（职员）与组织维度（部门）各出一个视图；每个视图的每一行给出 `单量 + 收款金额 + 预收款金额 + 预订货收款金额 + 回款总金额`，并支持从行级 `明细` 下钻到构成该行金额的单据流水。它是**销售回款考核与提成取数的口径页**。

| 页面 | 地址（ql361） | 说明 |
|------|------|------|
| 回款统计 | 分析 → 提成分析 → 回款统计 | 单入口复合页（**2 个视图 Tab**：`按职员` / `按部门`；逐 Tab 独立列配置） |

单入口：分析 → 提成分析 → 回款统计。

- 实测实据（2026-09-15）：`按职员` **7 条记录**（职员 `HC001` 杨生淮 ~ `HC017` 王昶元）；`按部门` **3 条记录**（管理部 / 客服部 / 配送部），脚本翻页控件实测 `共 3 条记录 / 每页显示 16 行`（`.png`）。

## 4. 业务规范

### 统计口径（三口径回款）

- **核心恒等式：`回款总金额 = 收款金额 + 预收款金额 + 预订货收款金额`**。2026-09-15 实测逐行逐合计验证**全部成立**：
  - `按部门`：`27,527.38 + 102.6 + 0 = 27,629.98` ✅；`0 + 8,055.64 + 0 = 8,055.64` ✅；`4,758.41 + 140 + 0 = 4,898.41` ✅；合计 `32,285.79 + 8,298.24 + 0 = 40,584.03` ✅。
  - `按职员`：`21,954.5 + 7,310.5 + 0 = 29,265` ✅；`5,572.88 + 359.72 = 5,932.6` ✅；`0 + 314.37 = 314.37` ✅；`154.93 + 0 = 154.93` ✅；`2,936.28 + 140 = 3,076.28` ✅；`1,667.2` ✅；`0 + 173.65 = 173.65` ✅。
- **口径含义（基准文档，部分待复核）**：
  - `收款金额` —— 收款单（`SKD-`）实收；
  - `预收款金额` —— 预收款单（`YSKD-`）新增预收，**可为负**（负值 = 预收抵扣 / 退回）；
  - `预订货收款金额` —— 预订货单（`YDHD-`）预订金；
  - `单量` —— 回款关联单据张数。
- **日期口径**：`日期类型` 默认 `单据日期`（其他可选值**待复核**）。
- **空值展示**：实测 `0` 与空单元格混用（如客服部 `收款金额 = 0`、预订货收款列整列为空/0）—— `0` 与「无数据」在展示层未区分，**待复核**是否刻意。

### 与其他页面关系

- **取数**：收款单 / 预收款单 / 预订货单（经营历程流水，按经手人 / 部门归属）。
- **上游**：`销售业绩`（其「回款总额」与本页 `回款总金额` 同口径，基准文档记统计时点/口径存在微差，**待复核**）。
- **下游**：`业务员提成`（回款提成取数）、`业绩提成中心`（按月矩阵结算）。
- **同组三页分工**：`业务员提成`＝销售侧实时计算 → `回款统计`＝回款侧三口径核算 → `业绩提成中心`＝结算闭环。

## 5. 实现差异说明

> 本节按 2026-09-18 金标准批次**升级后**源码回写；升级前快照见 §6.3 遗留说明。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/collection-stats/index.vue`
- **骨架（路线 A′）**：`ErrorBoundary > PageContainer(full-height 静态属性) > CategoryListLayout(:tabs) > BillDetailTable`（未传 `:max-height`）+ `StandardPagination(variant="classic")`；`PageConfigPanel` 置于布局外。
- **视图 Tab**：**2 个**（`按职员` / `按部门`），顺序逐字取自对标实测；**逐 Tab 独立列配置**：
  `storage-key` 与 `global-config-key` 同值且按 Tab 换 key（`analytics-collection-stats-columns-staff|dept`），
  页面配置 key 为 `analytics-collection-stats-page-config`（与列配置 key 不同值）。
- **列定义**：两 Tab **各 7 列、全部默认可见**（`按职员`：职员编号/职员名称/单量/收款金额/预收款金额/预订货收款金额/回款总金额；`按部门`：部门编号/部门名称/其余 5 列同构）。
  固定列 `操作`（行级「明细」钻取）以 `key='action'` 命中组件锁定列判定，**不进列配置弹窗**，口径 = 对标 `columnConfig.count=7`。
- **查询区**（横向自适应网格 `.search-grid`）：查询方案（`QuerySchemeBar`）+ 时间快捷段 **8 段**（昨日/今日/本周/近一周/本月/上月/近三月/本年，**无「上周」**）+ 日期范围 + 职员（`按职员` Tab）/部门（`按部门` Tab）+ 日期类型 + 单据类型 + 查询/重置。
- **工具栏**：刷新 | 打印(F8) | 导出 | **页面配置**（`PageConfigPanel`，4 个查询项 + 3 个功能按钮，`:default-query-fields-config` / `:default-function-buttons-config` 齐备）。
- **合计行**：取后端 `summary`（按当前过滤范围 SUM，非当前页求和），两 Tab 均显示。
- **行级 `明细`**：弹窗列出该职员/部门在 **收款单 / 预收款单 / 预订货单** 三口径下的回款流水（真实数据）。
- **打印(F8) + 导出**：`handlePrint()` + `handleF8Key()`（`onBeforeUnmount` 移除监听）；导出走 `useExport`（全量拉取 + CSV）。
- **取数**：`GET /erp/finance/analytics/collection-stats/page|detail`（**新端点**，`CollectionStatsAnalyticsController` + `CollectionStatsAnalyticsServiceImpl`，`JdbcTemplate` 分块聚合 + Java 合并派生列）；
  旧端点 `GET /erp/finance/collection-stats`（支付方式分桶口径）**保留未动**。
- **三口径与状态口径**：
  - 收款金额 = `erp_receipt.receipt_amount`（`status >= 2 AND status NOT IN (3,8)`）
  - 预收款金额 = `erp_pre_receipt`（`COALESCE(NULLIF(pre_receipt_amount,0), NULLIF(amount,0), NULLIF(total_amount,0), 0)`，剔除 `forfeited` / `refunded`）
  - 预订货收款金额 = `erp_sale_pre_order.received_deposit`（`status > 0 AND status <> 6`）
  - 单量 = 三表命中张数之和；`回款总金额 = 收款 + 预收款 + 预订货收款`（逐行与合计均成立，接口探针已断言）
- **维度归集按「名称」**：本系统历史单据的经手人/部门 ID 不统一（同名部门在不同单据上落 9001 / 900009 / 1），按 ID 会把同一部门拆成多行；
  故按名称归集、名称回标量回主数据取编号（职员 = `sys_user.username`，部门 = `sys_department.dept_code`），与《辅助核算余额表》同一做法。
- **旧实现遗留**：`views/analytics/collection-stats/index.vue` 的 `ARReportPage` 壳 + 5 张汇总卡片**已整体移除**（对标无指标卡）。
