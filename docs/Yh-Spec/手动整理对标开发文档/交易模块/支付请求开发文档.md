## 页面概述

支付请求是**在线支付单统一查询/处理**页：按业务类型、渠道、状态查询系统发起的支付请求（支付单），查看支付渠道、金额、状态、渠道订单号、创建/完成时间，并对线下渠道（现金/银行转账）的支付单做「确认收款」。（**无创建入口**——支付请求由业务流程调用 `/api/payment/request` 自动发起，本页只读查询 + 确认收款。）**单入口，无子 Tab，无独立表单**。

| 页面 | 地址 | 说明 |
|------|------|------|
| 支付请求 | `payment/request` | 单视图列表页（统计卡片 + 5 查询字段 + 数据表） |

单入口：交易模块 → 支付管理 → 支付请求。

- 实测实据：数据表列配置 11（默认显示 7）、查询字段 5、列/页面配置弹窗 **有**（表头 rowNo 列齿轮列配置 + 独立页面配置面板）。
- 状态机（`PAYMENT_STATUS_MAP`）：0 待支付 / 1 支付中 / 2 已支付 / 3 已取消 / 4 支付失败。
- 支付渠道（`PAYMENT_CHANNEL_MAP`）：ALIPAY 支付宝 / WECHAT 微信支付 / UNIONPAY 银联支付 / BANK 银行转账 / CASH 现金/线下。

## 页面结构（含配置）

支付请求 = 单视图列表页（无子 Tab；列配置为表头 rowNo 列齿轮、页面配置为独立 `PageConfigPanel`）。查询区与按钮区可通过页面配置调整显隐/启用。

### 统计卡片（后端聚合 4 项）
待支付（status 0/1）、成功（status 2）、失败（status 3/4）、累计金额（全部记录金额合计）；走后端聚合 `GET /api/payment/request/stat?channel=`，**已随查询区「支付渠道」联动**（`loadStats()` 传 `channel`）。

### 查询条件字段（5 项，显隐可由页面配置弹窗控制）
- 业务类型（文本框，等值）
- 业务单号（文本框，模糊）
- 支付渠道（下拉：全部渠道/支付宝/微信支付/银联支付/银行转账/现金+线下）
- 支付状态（下拉：全部状态/待支付/支付中/已支付/已取消/支付失败）
- 创建时间（区间，含时分秒）
- 查询、重置（按钮）

### 功能按钮 / 行级操作
- 头部按钮：刷新、打印(F8)、导出。
- 行级操作：**详情**（抽屉）、**确认收款**（仅 `status===1` 且渠道为 `CASH`/`BANK` 时显示；弹窗填收款单号 → `/request/{id}/confirm`）、**取消支付**（仅 `status !== 2` 时显示；`a-popconfirm` 二次确认 → `POST /request/{id}/cancel`，成功后刷新列表+统计）。

### 数据表列配置：共 11 列可配置（默认显示 7 / 默认隐藏 4：渠道交易号、付款人、支付完成时间、过期时间）；固定列：序号、操作（详情/确认收款/取消支付）
默认显示：业务类型、业务单号、支付金额（¥ 绿色）、支付渠道（Tag）、渠道订单号、状态（Tag）、创建时间、操作（详情/确认收款）。

## 业务规范说明

- **支付主线**：业务单据（bizType + bizId + bizNo）→ 本页生成支付单（taker：`/api/payment/request`）→ 渠道下单（orderNo/tradeNo）→ 回调 `POST /api/payment/callback/{channel}` 落支付记录并更新状态 → 本页可查。
- **金额口径**：支付金额 = 本次支付单金额；不同渠道含最小/最大限额（`/api/payment/channels?amount=`）。
- **渠道**：支付宝/微信/银联/银行转账/现金；现金、银行转账走**线下确认收款**（`/request/{id}/confirm`，需填渠道订单号）。
- **状态流转**：待支付 → 支付中 → 已支付（回调成功）；可取消（`/request/{id}/cancel`）；支付失败（status 4）。
- **下游**：支付成功回调后关联业务单据回款（`bizNo`）。

## 实现差异说明

> 本节按当前源码回写（本轮金标准升级后）。

### 当前实现
- **实现文件**：`frontend/apps/pc-admin/src/views/payment/request/list.vue`
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout(:tabs="[]" :show-category-panel="false" :show-table-footer="true") > BillDetailTable(view-mode，列配置齿轮在表头 rowNo 列) + StandardPagination(variant="classic")` + 独立 `PageConfigPanel`（页面配置：查询条件显隐 + 功能按钮启用）
- **Tab**：无 Tab（`tabs=[]`，无分类树）
- **列**：共 **11** 列可配置（默认显示 **7**：业务类型、业务单号、支付金额、支付渠道、渠道订单号、状态、创建时间；默认隐藏 **4**：渠道交易号、付款人、支付完成时间、过期时间）；固定列：序号（`rowNo`，fixed left）、操作（`action`，fixed left，宽 130）；无多选列
- **查询条件**：**5** 项（业务类型(文本框，等值)、业务单号(文本框模糊)、支付渠道(下拉 `PAYMENT_CHANNEL_MAP` 5 渠道)、支付状态(下拉 `PAYMENT_STATUS_MAP` 0~4)、创建时间(区间，含时分秒)）+ 查询/重置按钮；均可通过页面配置显隐
- **功能按钮**：**4** 项（刷新、打印(F8)、导出、确认收款）。工具栏右侧渲染「页面配置(齿轮)/刷新/打印(F8)/导出」；「确认收款」**不在工具栏渲染**，仅作为行级「确认收款」按钮的启用开关（`isButtonEnabled('confirmOffline')`）
- **行级操作**：详情（抽屉，宽 600）、确认收款（仅 `status===1` 且 `channel` ∈ {CASH, BANK} 且功能按钮启用时显示；弹窗「确认线下收款」展示收款金额、收款单号必填 → `POST /api/payment/request/{id}/confirm?channelOrderNo=`）、**取消支付**（仅 `status !== 2` 时显示；`a-popconfirm` 二次确认，按钮带行级 loading → `POST /api/payment/request/{id}/cancel`，成功后 `refreshAll()`；后端对 `status==2` 抛「支付已完成，无法取消」）
- **打印(F8) / 导出**：`handlePrint()` 以新窗口输出打印模板（表头附业务单号/渠道/打印时间/记录数；正文 8 列：#/业务类型/业务单号/支付金额/支付渠道/渠道订单号/状态/创建时间）；`handleF8Key()` 全局 keydown 监听 F8；`handleExport()` 前端拼装 CSV（10 列，含渠道交易号/付款人/支付完成时间；文件名 `支付请求_YYYYMMDD.csv`）
- **统计卡片**：4 项，走后端聚合 `GET /api/payment/request/stat?channel=`（待支付 `pendingCount`(status 0/1) / 已支付 `successCount`(status=2) / 已取消·失败 `failedCount`(status 3/4) / 累计金额 `totalAmount`），**已随查询区「支付渠道」联动**（`loadStats()` 传 `channel`；查询/重置/刷新均重新拉取；统计失败仅 `console.warn`，不影响列表）
- **详情抽屉**：支付请求ID/业务类型/业务单号/支付金额/支付渠道/状态/渠道订单号/渠道交易号/付款人/创建时间/支付完成时间/过期时间/备注
- **storage-key**：列配置 `payment-request-table-columns`（`global-config-key` 同值）；页面配置 `payment-request-page-config`
- **数据来源**：`apps/pc-admin/src/api/payment/index.ts`（`paymentApi`、`PAYMENT_CHANNEL_MAP`、`PAYMENT_STATUS_MAP`）→ `GET /api/payment/request/page`、`GET /api/payment/request/stat?channel=`（`paymentApi.statRequest({ channel })`）、`POST /api/payment/request/{id}/confirm`、`POST /api/payment/request/{id}/cancel`（`paymentApi.cancel`，**本轮首次接入页面**）

### 后端改动（本轮）
- `PaymentController`（`cn.aiedge.payment.controller`，`@RequestMapping("/api/payment")`）
  - `GET /request/page` **扩参**：pageNum、pageSize、bizType(等值)、bizNo(模糊)、channel、status、startTime、endTime；时间口径 = `payment_request.create_time`（创建时间），按创建时间倒序 + ID 倒序

  - 其他已有：`POST /request`（创建）、`GET /request/{id}`、`POST /request/{id}/cancel`（status≠2 可取消，并调用渠道关单；**前端行级「取消支付」入口已接入**）、`POST /request/{id}/confirm?channelOrderNo=`（确认线下支付，`@RequestParam` 非请求体）、`POST /callback/{channel}`、`GET /channels?amount=`

### 剩余缺口
1. **「取消支付」显示口径偏宽（前端按 spec 实现，后端待补语义）**：入口条件为 `status !== 2`，故 `3 已取消 / 4 支付失败` 行也显示「取消支付」（后端幂等置 3）；如需仅 `0/1` 可取消，需前后端统一口径。
2. **业务类型取值缺字典**：`bizType` 为自由文本输入、后端等值匹配；实体注释给出既有取值（`SALE_ORDER` / `TRADE_ORDER` / `DMS_DELIVERY`），前端无枚举字典与下拉，需补 bizType 字典后改为下拉。
3. **运行截图与端到端脚本（已闭环，2026-09-15 复核）**：模块级 E2E `tools/e2e-trade.cjs` 已落地 **103/103 通过、退出码 0**（`tool-results/e2e-trade/e2e-run3.txt`，第八节含本页分页 total 直查对账）；接口探针 33/33 PASS。本页运行截图资产见 `tool-results/e2e-trade/`。（ql361 无此页，无对标截图需补。）

> 已闭环（本轮从缺口移除）
> - **「确认收款」后端渠道校验已补**：`PaymentServiceImpl.confirmOfflinePayment` 原先只校验 `status==1`，任意在线渠道「支付中」的支付单都能被人工置为已支付（绕过前端即失效）。现与前端展示条件对齐，**只允许 `CASH`/`BANK`**；`ALIPAY`/`WECHAT`/`UNIONPAY` 等在线渠道必须由渠道回调入账，否则抛「渠道 X 为在线支付，须由渠道回调确认，不支持人工确认收款」。
> - **付款人（`payerName`）可查已闭环**：后端 `GET /api/payment/request/page` 新增 `payerName` 模糊参数（三层签名同步）；前端 `paymentApi.pageRequest` 参数类型补 `payerName`，查询区新增「付款人」输入项（受「页面配置」显隐控制，`key='payerName'`，出厂默认显示），并写入 `searchForm` / `buildQuery` / `handleReset`。至此「付款人」列不再只能展示与导出。
> - **「取消支付」行级操作缺入口**：`paymentApi.cancel`（`POST /request/{id}/cancel`）已接入，`status !== 2` 时显示 + `a-popconfirm` 二次确认 + 行级 loading，成功后 `refreshAll`。
> - **统计与筛选不联动**：`statRequest` 已传 `channel`，查询/重置统一走 `refreshAll`，卡片随查询区联动。

| **差额处理交互**：差额金额 + 二选一（保留未结 ／ 标记全额结清）+ **差异记账科目** + 核销标签 | 本页「确认收款」仅填**收款单号**，**无差额语义**（少收/多收无处表达） | **可借鉴该交互**：确认收款弹窗补「**差额处理（保留未结／标记结清，`a-radio-group`）**」+「**差异科目（下拉）**」；用本系统 `a-modal` + `a-form`（与 `PageConfigPanel` 同版式规范），**颜色/字体走本系统主题**，不自定义样式 |
| **汇总卡片**（金额/笔数分项以卡片聚合） | 已有 4 张统计卡片（待支付/已支付/已取消·失败/累计金额） | 已具备该形态；如需增列指标，复用本系统 `ARStatCards` / `a-card` + `a-statistic`，**不引入第三方式样** |
| 支付单据字段：`Amount` / `Payment Date` / `Memo`（挂业务单号）/ `Journal` / `Payment Method` | 已有：支付金额、创建时间、渠道订单号、业务单号、支付渠道 | 口径一致，**无需改**；`Memo` 语义对应本系统「业务单号」 |
| 卡信息采集（`Card number`/`Expiration`/`CVC`/`Country`/`ZIP`）与卡 token 化 | 本页是**后台支付单台账**，只读 + 确认收款 | **不借鉴**（非样式问题，是**落点与合规**问题）：卡信息属前台收银台采集，后台不留存（PCI 合规）；卡 token 属**收单渠道**职责，对应本系统《渠道配置》的渠道凭据 |

- **业界界面视觉样式**（唯一不借鉴项）：不采用其配色、圆角、阴影、字体、表单栅格与按钮外观；一切外观令牌取自本系统既有主题（与现有代码统一）。
- **不照搬其字段命名**（`journal`/`payment_method`/`post_difference_in` 等）：仅**语义**对齐，本系统字段名以库表与既有实体为准。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
