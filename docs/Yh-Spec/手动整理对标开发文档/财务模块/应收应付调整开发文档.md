- **表单页**：不动资金账户的往来余额调整（应收增加/应收减少/应付增加/应付减少四向）。页面性质 = 调整方向单选 + 表头字段区 + 科目明细表格 + 备注区 + 单据信息 + 底部金额与操作。
- **双入口**：主菜单 → `finance/ar-ap-adjust/form`；标签「历史」→ `finance/ar-ap-adjust`（列表）。
- 单号实据 NO. YSKZJ-20260907-001（YSKZJ- 前缀 + YYYYMMDD-序号，"应收/应付增减"类拼音首字母）；标题行含附件、键盘（快捷录入）、齿轮（配置）图标（截图实据）。

## 5. 业务规范

- 状态流转：保存草稿（Ctrl+S）→ 记账（Ctrl+Enter）：记账后调整生效——结算单位应收/应付余额按方向增减，并生成会计凭证（KJPZ-）。
- 四向语义（实据归纳）：
  - 应收增加：客户欠款调增（如漏记费用转应收、期初补录）
  - 应收减少：客户欠款调减（如坏账豁免、差错冲减，不动资金）
  - 应付增加：欠供应商款调增
  - 应付减少：欠供应商款调减
- 与收/付款单的本质区别：本单无账户字段（截图与 JSON 均无收/付款账户），不产生资金流水，仅调整往来余额与对应科目。
- 明细"科目编号/科目名称"：调整的对转科目（差额去向，如营业外收入/营业外支出等），金额可多行拆分。
- 与其他页面关系：余额结果体现于《按单收款开发文档》/《按单付款开发文档》未结算金额、查应收/查应付（分析域）；科目主数据：资料 → 财务账户 → 会计科目；期初场景：配合期初余额录入使用（总账 4000 期初资本科目实据佐证）；本系统前端目录 `finance/ar-ap-adjust`（dynamicRoutes.ts 实据）。

## 实现记录（2026-09-09，V11.91.0）

- **后端**：`cn.aiedge.erp.finance.arapadjust`（controller/dto/entity/mapper/service/impl）；主表 `erp_ar_ap_adjust` + 明细 `erp_ar_ap_adjust_item`；单号前缀 `YSKZJ-`；接口 `/api/erp/finance/ar-ap-adjust/*`（page / doc-query / next-no / {id} / create / update / confirm / cancel / delete）。
- **前端**：`finance/ar-ap-adjust/form.vue`（表单）+ `index.vue`（单表列表）；API `api/finance/ar-ap-adjust.ts`（导出 `arApAdjustApi`）。
- **设计落地**：
  - 列表页为**单表**（不拆按单据/按明细），默认显示 8 列（单据日期/编号/状态/结算单位/经手人/调账类型/金额/打印次数），隐藏 8 列。
  - 表单页四向「调整方向」单选 + 表头（编号/单据日期/结算单位/经手人/部门）+ 科目明细（科目编号/名称/金额/备注）+ 备注区 + 单据信息 + 本单金额（Σ明细）。
  - P0 记账必须经会计凭证（KJPZ-）；P1 本单金额 = Σ科目明细金额（confirm 二次强校验）。
  - 记账凭证方向：应收增加 Dr1122/Cr明细；应收减少 Dr明细/Cr1122；应付增加 Dr明细/Cr2202；应付减少 Dr2202/Cr明细。
  - 余额调整：应收增加→客户应收+X；应收减少→客户应收−X；应付增加→供应商应付+X；应付减少→供应商应付−X。通过在 `finance_receivable`/`finance_payable` 插入带符号记录（source_type=`ar_ap_adjust`）；`PartnerBalanceMapper` 已放宽过滤以纳入该来源（含负向）。
  - 结算单位按方向过滤：应收方向（1/2）→客户，应付方向（3/4）→供应商。
- **遗留**：审批流/红冲机制尚未接入（与文档前述一致）；`V11.86.0` 存在并行遗留的重复迁移版本（付款单金标准 + 预付款单增强），核心包启动需先重编号其一。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
