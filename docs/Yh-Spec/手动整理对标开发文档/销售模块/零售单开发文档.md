### 本次修复明细（对照原文差异清单）
1. **P0 结算接通**：`handleSettle` 改为「先 `create/update` 落草稿 → `POST /{id}/settle`」，结算由后端完成支付明细落库、各支付方式汇总回写、找零服务端计算、库存扣减/退货回补（同事务，不足抛业务异常回滚）。
2. **P0 单号接通**：新增 `GET /api/sales/retail/next-no`（`generateRetailNo()` 提升为接口方法，走 `BizNumberGeneratorService` 统一号段）；表单传 `codeApiPath` 并去掉前端演示号。
3. **P0 去桩**：列表打印(F8) 取 `GET /{id}/print-data` 渲染小票并调 `POST /{id}/print` 计数；列表导出按当前 Tab 导出 CSV；表单 `更多 → 导出` 导出明细 CSV；表单新增 `打印` 动作。
4. **P1 表单配置弹窗**：新增「页面配置(36) / 零售设置 / 打印设置」三 Tab，配置持久化到 `userPageConfigApi('retail-form','form')`，勾选即控制表单区块（基本信息 / 优惠 / 扩展信息 / 收款面板 / 单据信息）显隐。
5. **P1 列对齐**：列表按明细 85 → 52；表单明细 69 → 66。
6. **P1 搜索区/工具栏联动**：搜索条件由 `queryFields` 配置驱动，工具栏由 `functionButtons` 配置驱动。
7. **组合收款**：收款方式改为按方式存放金额（10 种），非组合收款单选互斥、组合收款补足剩余；结算落库每方式一行，主表 `paymentMethod` 单方式原样 / 多方式 `MIXED`、`combinedPayment` 置真。
8. **会员积分闭环**：结算时「产生积分 = 应收金额（1 元 = 1 分，向下取整）/ 使用积分」，写回单据 `prev_points / member_generated_points / current_points` 并同步 `biz_party.points`（积分不足抛业务异常）。
9. **按明细分页准确性**：改为「先按主表条件取命中单据 ID → 再带明细条件一次分页」，`total` 与过滤结果一致（原实现先分页明细再过滤，total 虚高）。
10. **搜索字段真实生效**：后端补 `handlerName / departmentName / warehouseName / printCount / extNum1~2 / extText1~3` 条件与 `productAttribute` 明细反查；按明细补 `summary / attachment / bookkeeperName / bookkeepingTime` 字段。
11. **顺带修复**：表单 `handleHoldOrder` 真实调 `POST /{id}/hold`（挂单）、列表新增「取单」动作（`unhold`）；POS 历史查询参数 `startDate → dateStart` 与状态映射纠正；列表新增行选择列（原 `:row-selection` 为无效属性，选择永远为空）；转义 HTML 防注入（打印模板拼接）。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
