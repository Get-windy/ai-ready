## 1. 页面概述

连接管理页是**平台运营方的数据源连接台账**：分页表格列出平台登记的外部数据源（连接名称 / 数据库类型 / 主机地址 / 端口 / 数据库名 / 状态 / 更新时间），并提供「新增连接 / 编辑 / 删除 / 测试连接」四个动作。它是 `61304 数据管理` 组的第 1 页。

**本页核心事实三条**：

1. **页面与后端逻辑都是真实实现、零桩**（§9.1）——「测试」是真的 JDBC 连接测试（`DataSourceServiceImpl.java:110-132`）。
2. **但控制器从未被 Spring 装配**（`cn.aiedge.datasource` 漏配 `scanBasePackages`，§6.5）→ 6 个端点运行期全部 404 → 用户看到**空表**且**无任何错误提示**（前端主动吞错，`connection/index.vue:365-368`）。
3. **即使装配起来也跑不通**：`sys_data_source.deleted` 的 DB 类型是 `integer`，实体是 `Boolean`（§7.4）→ `.eq(deleted, false)` 在当前库上直接报「操作符不存在: integer = boolean」（本轮实测）→ 读接口会 500、写接口会抛类型错。

## 2. 页面截图

**N/A —— 本模块无对标系统截图。**

**原因（本模块通用前提）**：ql361（来肯企汇 v2.2，`22stable.ql361.com`）是**租户级进销存产品**，对客户只暴露「设置」域（`client_type = tenant-admin`）。本页属**平台控制台**（`client_type = system-admin`）——「平台方怎么管自己连到哪些库」——**任何厂商都不会把自己的 SaaS 控制台给客户看**。因此：

- ql361 中**不存在**「连接管理」页（`client_type='system-admin'` 的行不会出现在租户登录的菜单树中），**无可对标截图**；
- **不使用 Odoo / SAP / 金蝶 / 用友的界面截图**（口径见《系统模块/README.md》§5.3：本模块按业界**能力模型**建模，**不照搬任何一家的界面**）；
- §8 只写**业界能力对标**，逐条标来源与可信度级别。

**本系统截图**：当前无本系统验收截图（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）→ **P2 缺口**（README §7.3）。

**数据现状（devdb 实测 2026-09-18）**：

```
select count(*) from sys_data_source                                             → 0 行
select count(*) from information_schema.columns where table_name='sys_data_source' → 16 列
```

- **表内 0 行 → 表格恒空**（渲染 `a-empty`），这是本页在当前库上的**确定形态**，不依赖后端是否装配；
- **0 行的直接后果**：行内动作「测试 / 编辑 / 删除」与删除确认**在界面上无处可点**（合计 4 个交互控件无触达对象）；页头「查询」「刷新」只能得到空表；
- 「新增连接」是空表下**唯一**能打开的入口，但其提交同样落到 404 端点（§6.5）→ 弹窗填完提交必然失败；
- 因此本页验收必须**先解决装配与类型冲突，再经接口造数**（§10.1-㉒/㉔）。

### 3.8 数据获取与错误处理（`fetchData`，`:355-371`）

```ts

try {
  const res = await dataSourceApi.page({ keyword: keyword.value || undefined, page: pagination.current, pageSize: pagination.pageSize })
  list.value = res?.records || []; pagination.total = res?.total || 0
} catch {                       // ← 无参数、无提示
  list.value = []; pagination.total = 0
} finally { loading.value = false }
```

**缺陷（P0，本页「静默」的根源）**：`catch` **无参数、无提示**（`:365-368`）→ 后端 404 / 类型冲突 500 时页面**只显示空表**，用户得不到任何错误信息。与《租户列表》「无 `catch`」不同：本页是**主动吞掉**异常并渲染空列表。

**响应解包（正确）**：`request.get('/data-source/list', params)`（`api/admin.ts:102-104`）返回 `Map{records,total,current,size,pages}`，前端取 `res?.records` / `res?.total`（`:363-364`），与后端键名（`DataSourceController.java:41-47`）**逐字一致**。

**分页口径**：前端 `{current:1, pageSize:20, showSizeChanger:true, showTotal:'共 N 条'}`（`:235-241`）｜后端 `@RequestParam keyword / page(default "1") / pageSize(default "20")`（`DataSourceController.java:30-32`）｜翻页 `handleTableChange` 回写后 `fetchData()`（`:270-274`）｜判定：参数名与默认值**一致**（`page`/`pageSize`，**不是** `pageNum`），`showSizeChanger` + `showTotal` 已有，**优于**《租户列表》｜`row-key="id"`（`:68`）｜排序：后端固定 `orderByDesc(createTime)`（`DataSourceServiceImpl.java:39`），前端**无**列排序、无 `sorter`。

### 3.9 自动刷新与内存泄漏

**无轮询**：全页 0 处 `setInterval` / `setTimeout`；数据仅在 `onMounted(fetchData)`（`:373`）、查询、刷新、翻页（`:71`）、保存成功（`:323`）、测试 `finally`（`:341`）、删除后（`:352`）时拉取。**无泄漏**：无定时器、无事件监听、无手动 observer；唯一 observer 在 `PageContainer` 内部且已在 `onUnmounted` 中 `resizeObserver.disconnect()`（`components/PageContainer/PageContainer.vue:85-90`，该组件自带 `ReconnectBanner` `:10`）。

### 5.3 流转规则（本页动作）

```
（无）── 新增连接 POST /data-source/ ──▶ status='disconnected'（强制）
disconnected ── 测试成功 ──▶ connected
disconnected / connected ── 测试失败 ──▶ error
error ── 测试成功 ──▶ connected
（任意）── 编辑 ──▶ status 不变（字段白名单不含 status）
（任意）── 删除 ──▶ deleted=1（逻辑删除，status 不变）
```

| 动作 | 后端 | 前置校验 | 失败文案 | 副作用 | 行号 |
|------|------|:--------:|---------|--------|----|
| 新增 | `POST /api/data-source/` | 无（前端仅查 4 字段非空） | 无（任何入参都返 `success:true`） | 强制 `status='disconnected'`；`createTime`/`updateTime` 置当前；`deleted=false`；`tenantId` 取请求头 | `DataSourceController.java:61-70`；`DataSourceServiceImpl.java:49-57` |
| 编辑 | `PUT /api/data-source/{id}` | **有**：先 `selectById`，`null` → `success:false, message:"数据源不存在"` | 前端弹 `e.message` | **null-safe 部分更新**（8 字段逐个判 `!= null`）；`updateTime` 置当前；`tenantId != null` 时**改挂租户** | `:72-85`；`:60-75` |
| 删除 | `DELETE /api/data-source/{id}` | 有：先 `selectById`，`null` → `success:false` | 同上 | **逻辑删除**（`setDeleted(true)` + `updateById`）→ DB 行仍在 | `:87-93`；`:78-84` |
| 测试连接 | `POST /api/data-source/test`（body `{id}`） | 有：`id` 缺失 → `success:false, message:"请提供数据源ID"`；`selectById` 为 null → 返 false | `"连接失败，请检查数据源配置"` | **真实 JDBC 连接**（§5.4）；`finally` 中必定回写 status | `:95-111`；`:110-132` |

**编辑/删除均无越权校验（P1）**：`update`（`:60-75`）与 `delete`（`:78-84`）只做存在性校验，**不校验该行是否属于调用方租户**；`update` 甚至允许把行**改挂到请求头指定的其它租户**（`:72`）。当前唯一保护是平台级多租户插件与会话豁免（§5.6）。
**删除是幂等的**：本实体**没有** `@TableLogic`（`DataSource.java:64-65` 是普通列），已逻辑删除的行**仍能被 `selectById` 查到** → 再次 `DELETE` 仍返回 `success:true`（与《租户列表》的 `@TableLogic` 语义相反）。

### 5.4 测试连接的真实实现（本页唯一「重」能力）

`DataSourceServiceImpl.testConnection`（`:110-132`）逐行事实：取行 `selectById`（null 直接返 false，`:112-113`）→ 拼 URL `buildJdbcUrl`（`:115`）→ `Properties` 设 `user`/`password`（空值兜底空串，`:116-118`）→ `DriverManager.getConnection(url, connProps)`（try-with-resources 自动关闭，`:120`）→ **`conn.isValid(5)`（超时 5 秒，硬编码）**（`:121`）→ 成功写 `connected`（`:122`）、`isValid=false` 写 `error`（`:122`）、抛 `SQLException` 写 `error`（`:126`）→ **`finally { updateById(ds) }` 无论成败都回写 status**（`:129-131`）→ 成功 `log.info`（`:123` 含 id/name/status）、失败 `log.error`（`:127` 含 id/name/**url**，URL 会进日志，不含密码但含主机/库名）。

**这是真实能力、不是桩**（与 README §3.2 把本页归为「真实数据」一致）。它当前**只是无法从页面触达**（控制器未装配）。

### 5.6 多租户口径（本模块红线②，必须逐页写清）

**本页专属事实**：`sys_data_source` **有 `tenant_id` 列**（`V6.14.0:218`，`BIGINT DEFAULT 0`），且**不在** `MyBatisPlusConfig.IGNORE_TENANT_TABLES` 白名单（白名单 `:32-93` 逐项核对无命中；全仓 `grep sys_data_source` 在 Java 侧仅命中实体 `@TableName` 与报表消费点）。

| 事实 | 证据 |
|------|------|
| 实体**没有** `@TableLogic` → 租户插件不是唯一过滤层，`list` 另手写 `.eq(deleted, false)` | `DataSource.java:64-65`；`DataSourceServiceImpl.java:31` |
| **超管整体豁免已接线**：登录时 `StpUtil.getSession().set("tenantScopeExempt", StpUtil.hasRole("SUPER_ADMIN"))` | `SysUserServiceImpl.java:88` |
| 读取点：`shouldSkip()` = 「租户不可解析」**或** `isTenantScopeExempt()` → 为真则不注入 `tenant_id` | `AiReadyTenantLineInnerInterceptor.java:41-44`；`MyBatisPlusConfig.java:157-167`（只读 Session 缓存） |
| **旧 token 不豁免**：改动前已签发的 token 无该标记 → 按会话租户收敛，需**重新登录一次** | `MyBatisPlusConfig.java:150-152`（注释原文） |
| **非超管账号**（`SYSTEM_ADMIN` 等）→ 被收敛到会话租户，**查回 0 行且不报错** | 同源 |
| **本页还有第二层收窄**：前端给**所有**请求加 `X-Tenant-Id`（`localStorage.getItem('tenantId') \|\| '1'`），后端 `list` 用它 `eq(tenant_id, tenantId)` → 即使会话豁免生效，页面**仍只看到 `tenant_id = 1` 的行**，而 DDL 默认值是 `0` | `request.ts:127-129`；`api/admin.ts:25-32`；`DataSourceServiceImpl.java:32`；`V6.14.0:218` |
| 表现形态 | **页面空白 / 查不到数据，而不是报错** —— 本模块最危险的失败模式（README §1.3 红线②） |

**结论（写入口径）**：本页如实写成「**当前被超管整体豁免掩盖，但配置脆弱；且 `X-Tenant-Id` 缺省 `1` 与建表默认值 `0` 口径不一致，会额外制造一次「数据在库里但页面看不见」**」。

**修法（新写平台级查询推荐，不依赖会话豁免）**：① 读全局用 `@InterceptorIgnore(tenantLine = "true")`；② 写目标租户行前 `MyBatisPlusConfig.setTempTenantId(tid)`（`:101-103`）；③ 理由：会话豁免依赖 Sa-Token Session，对**定时任务 / 无会话上下文**的链路语义不同，显式声明更稳。

### 7.4 类型冲突（**P0，本轮 psql 探针已复现**）

**冲突本体**：DDL 是 `deleted INT DEFAULT 0`（`V6.14.0:223`），实体是 `private Boolean deleted;`（`DataSource.java:65`）。

**探针一（读路径，本轮实测，只读语句）**：

```sql
select count(*) from sys_data_source where deleted = false;
-- 错误: 操作符不存在: integer = boolean
-- 提示: 没有匹配指定名称和参数类型的操作符
```

→ `DataSourceServiceImpl.list` 的 `.eq(DataSource::getDeleted, false)`（`:31`）在 PostgreSQL 上会**直接抛错**。**即使控制器被装配，`GET /list` 也会 500** 而不是返回数据。这比「未装配」更隐蔽：装配修好后页面**仍然是坏的**。

**探针二（写路径，事务内执行后 `ROLLBACK`，不改任何数据）**：同类型列上 `insert ... values (..., true)` → **错误「字段 "deleted" 的类型为 integer，但表达式的类型为 boolean」**（同根因在**同包兄弟表**上可复现）。→ `create` 的 `setDeleted(false)`（`:54`）与 `delete` 的 `setDeleted(true)`（`:81`）在装配后**都会抛类型错**。

**全仓对照**：`private Integer deleted` **333 个文件** / `private Boolean deleted` **仅 8 个文件**（其中 3 个是 datasource 三实体）→ 本包属**少数派写法**，实现方未对齐项目约定。

**修法（二选一，须在迁移中定案）**：① 改实体为 `Integer deleted`（对齐 387 列的多数派），并把 `.eq(deleted, false)` 改成 `.eq(deleted, 0)`；② 或迁移把列改为 `boolean`（影响面大且与同包其余表不一致，**不推荐**）。修法须与 README §8 的 B0/B3 批次一致，**修完必须重跑 §10.1-⑩ 的探针**。

### 7.5 多租户插件对本表的作用（见 §5.6）

`sys_data_source` **有** `tenant_id` 列且**不在**白名单 → 插件会在 SQL 上追加 `AND tenant_id = <会话租户>`（**超管会话被整体豁免时不追加**；非超管 / 旧 token 会追加）。**叠加前端恒发的 `X-Tenant-Id`（缺省 1）**，就出现「库里明明有 `tenant_id=0` 的行、页面却看不到」的第二种成因。因本表**有** `tenant_id` 列，**不应**加进白名单（白名单化会让**所有**租户看到**所有**数据源）；显式 `@InterceptorIgnore` 只适用于「平台级全局视图」这一种读法。

### 8.2 业界做法要点（编号列表，保留底稿原文引用，**A 级**）

⑯ 点行内「删除」→ 出现 popconfirm 文案逐字 `确定删除此连接?`（`:90`）→ 确认后出现 `连接已删除` 提示；**断言该行从表格消失但 DB 物理行仍在**（与 §10.1-㉓ 对账）。
⑰ 点行内「测试」→ 断言按钮点击后该行变为置灰（`text-disabled`，`:83`/`:380-383`）且在请求结束前**不可重复点击**（`testingId` 门闩，`:332`）；**本条只断言交互，不实际对生产库发起测试连接**。
⑱ **页面控制台无 `error`**（含 `TypeError` / `ReferenceError`）；并用 Network 面板断言：除**已知的 404**（`/api/data-source/list`）外无其它 4xx/5xx；若出现 500，即为 §9.2-P0「类型冲突」的可执行证据。

## 12. 剩余缺口（P0 / P1 / P2）

> 口径与《系统模块/README.md》§7 对齐：**P0** = 页面不可用 / 数据不落库 / 越权 / 红线；**P1** = 与业界能力差距大但页面能开；**P2** = 体验与一致性。
> README §7.1-P0-1/P0-2（数据管理 5 页 22 端点全 404）、P0-15（平台级表未豁免多租户）、P0-16（权限码 0 行）、P0-17（平台侧无审计）、§7.2（`host` 搜索缺陷）在本页的具体化见下。

### P0（4 条）

① **`cn.aiedge.datasource` 漏配 `scanBasePackages` → 本页 6 端点全 404（README §7.1-P0-1/P0-2 的具体化）**。证据：`AiReadyApplication.java:21-96`（`grep` 命中 0）；`:117` 的 `@MapperScan` 通配导致「Mapper 注册、Service/Controller 不注册」→「表能建、点不动」；运行态实测 `GET /api/data-source/list` → **404**（阳性对照 `/api/config/list` → 200）。**建议**：补包进 `scanBasePackages`（README §8 的 B0 批次），并复核其余未列包。

② **`sys_data_source.deleted` 类型冲突（integer vs Boolean）→ 装配后读写都会报错**。证据：DDL `V6.14.0:223`（`deleted INT DEFAULT 0`）、实体 `DataSource.java:65`、条件 `DataSourceServiceImpl.java:31`；**本轮只读探针实测**：`select count(*) from sys_data_source where deleted = false` → 「操作符不存在: integer = boolean」；全仓对照 `Integer deleted` 333 文件 vs `Boolean deleted` 8 文件。**建议**：实体改 `Integer` + 条件改 `.eq(...,0)`；**修完必须重跑 §10.1-⑩**。**注意**：这是「修好装配也仍然坏」的第二道 P0，最容易被漏掉。

③ **平台侧写操作零审计（README §7.1-P0-17 / 红线③ 的具体化）**。证据：控制器 6 个端点零审计调用；`sys_audit_log` 实测 **0 行**。后果：「谁在什么时候从哪个 IP 改了哪个数据源的连接信息、或把某行改挂到哪个租户」，**事后无法从业务表还原**。**建议**：按「时间 + 主体 + 来源 IP + 目标记录 + 操作 + 变更前后值 + 结果」落审计；**尤其必须审计 `update` 的租户改挂**（§9.2-P1）。

④ **5 个权限码未落库 → 非超管角色无从授权（README §7.1-P0-16 同源）**。证据：`DataSourceController.java:27/51/62/73/88/96` 要求 `system:datasource:list/create/update/delete/test`；`sys_permission`（264 行）中这 5 个码 **0 行**；前端**零 `v-permission`**。**建议**：补权限种子（迁移，README §8 的 B1 批次）+ 前端补指令，统一到 `system:datasource:*` 命名域。

### P1（8 条）

⑤ **`host` 搜索永远搜不到**：placeholder「连接名称/主机搜索」（`:22`）vs 后端 `like` 仅 `name`/`dbType`/`databaseName`（`DataSourceServiceImpl.java:33-38`）→ 改后端补 `host` 或改文案。
⑥ **密码明文存储**：`password VARCHAR(500)` 明文列（`V6.14.0:215`），创建/更新直存、测试时明文进 `DriverManager`（`:50/69/118`）→ **实施前须另行取证**（官方无加密章节），不能当「业界标准」。
⑦ **`update` / `delete` 无越权校验，且 `update` 可改挂租户**（`:61-62/72/79`）→ 补行归属校验。
⑧ **驱动与下拉选项脱节**：fat jar `BOOT-INF/lib` 仅 `postgresql-42.7.11.jar` → MySQL/Oracle/SQL Server 三种类型必定测试失败（下拉见 `:127-138`）。
⑨ **两份 `buildJdbcUrl` 参数不一致**：`DataSourceServiceImpl:89-108` vs `ReportDataSourceServiceImpl:241-260`（PG URL 一个有超时、一个没有）→ 抽取共用方法。
⑩ **`list` 全表捞回 + 内存分页，且 `pageSize` 无上限 / 可为 0（除零）**（`DataSourceController.java:32/35-39/46`）→ 换物理分页 + 入参校验。
⑪ **失败不可见**：`catch` 无提示（`connection/index.vue:365-368`）→ 404/500 时只渲染空表，用户无法区分「没有数据」与「接口坏了」。
⑫ **未达金标准路线 A**：无 `ErrorBoundary`、无 `BillTableList/BillDetailTable`、无列配置齿轮、无 `PageConfigPanel`、无经典分页（`:2`、`:63`、`:64-98`、`:243-252`）—— 与 README §7.2「30 页全部无 `PageConfigPanel` / 无 `storage-key` / 无经典分页 / 无列配置齿轮」一致。

### P2（7 条）

⑬ **数据库类型与端口无 JS 校验**（`required` 只是星号，`:122-140`、`:154-164` vs `:296-299`）。
⑭ **未知 `dbType` 静默回退 MySQL**（`DataSourceServiceImpl.java:104-106`）→ 报「连接失败」而非「类型不支持」。
⑮ **DDL 列注释漏 `error`**（`V6.14.0:227` 只写 connected/disconnected）→ 只改注释、不改行为。
⑯ **`updateTime` 无格式化 + 无列排序**（`:250`）；**`createBy` / `updateBy` 两列恒 NULL**（`DataSource.java:59/62` 无写入点）；**`name` 无唯一约束**（DB 仅 pkey + 7 条 NOT NULL）→ 可建同名连接。
⑰ **无统计卡 / 无页内 Tab / 无导出 / 无打印 / 无快捷键 / 无行选择 / 无详情入口**（`getById` 闲置）。
⑱ **行数漂移提醒**：`sys_data_source` 本轮实测 0 行，并行会话可能写入测试数据 → 验收断言请以「≥ 本页记录值」而非「==」。
⑲ **无本系统验收截图、无模块级 E2E**（README §7.3 末条）；且本页**无 ql361 截图可嵌入**（无对标页，§2）。
