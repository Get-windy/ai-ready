- 单据摘要：路线编号 / 配送线路 / 线路类型 / 配送员 / 车辆 / 计划日期 / 总里程 / 预计时长 / 实际时长 / 起点 / 终点 / 创建人 / 开始时间 / 完成时间 / 取消时间 / 取消原因 / 备注。
- 点位表：序号 / 状态 / 客户名称 / 联系电话 / 来源单号 / 地址 / **纬度 / 经度** / 到达时间 / **预估到达(ETA)** / 签收人 / 签收时间 / 失败原因 / 备注 / 操作。
- **地图查看**：复用《路线规划》的 `RouteMapCanvas` 矢量画布，按访问顺序连线 + 点位标记（按状态着色）+ 叠画绑定围栏几何（圆形/多边形）——**不自建地图实现**。
- 点位操作：**提前**（催单，指定目标序号）/ 到达 / 送达 / 失败；催单过的点位在 ETA 列显示「催单」标记。
- 点位操作（逐点独立，终态点位显示「已处理」）：**到达**（ARRIVED）、**送达**（DELIVERED，必填签收人）、**失败**（FAILED，必填失败原因）。

### 2.8 配送需求归集（围栏自动 + 手动添加）

> 对应需求：**「按围栏自动归集」+「围栏外订单也可人工补进」**两条路径并存。

**① 围栏自动归集**（工具栏「围栏归集」→ 弹窗「围栏自动归集」Tab）

| 步骤 | 说明 |
|------|------|
| 规则 | 销售出库单（已发货 `status=10`）/ 销售订单（待发货 2、部分发货 3）的**客户配送坐标**落入路线单绑定的电子围栏内 → 自动追加为该路线单点位 |
| 目标 | 指定路线单；不指定则扫描**全部「规划中/待出发 + 已绑围栏 + 开启归集」**的路线单 |
| 预览 | 干跑（`dryRun`），返回 `scanned / matched / added / missingCoordinate / outsideFence` 与逐条原因，**不落库** |
| 执行 | 命中项写入点位（去重：同一单据在同一条未结束路线单内不重复入线） |
| 缺坐标 | 客户未维护配送坐标时**不猜测、不跳过静默**：计入 `missingCoordinate` 并在弹窗内提供**就地补录经纬度**（写 `biz_party.latitude/longitude`），保存后重新预览 |

**② 手动添加（不受围栏限制）**（同弹窗「手动添加（围栏外）」Tab）

选择目标路线单 → 查询待配送单据 → 勾选 → 添加；可选「添加后按地图能力重排」。重复单据会被拒绝并提示「已在本路线单中」。

**坐标口径（关键）**：判断「地址是否在围栏内」需要坐标，本系统口径为
**单据收货坐标优先 → 客户档案默认配送坐标（`biz_party.latitude/longitude`）兜底**；
两者皆无则明确提示缺坐标，**不臆造地址编码结果**（配地图 Key 后可由《路线规划》的地址编码补齐）。

**③ 催单：动态调整后续顺序**（抽屉点位行「提前」）

把指定点位移到目标序号（其余点位按原相对顺序顺延、不丢点），可选**对其后的剩余点位按地图能力重排**（催单点自身固定不动，满足「客户催单必须先到」）。催单过的点位记 `expedited=1` 并在备注追记原因。

**④ ETA 预估与客户通知**

- `ETA 预估`：沿**既定顺序**（不重排）逐点累计，得到预计到达时间并落库到点位；缺坐标的点位不参与累计且 ETA 留空，接口返回 `message` 说明。
- `推送客户`：按当前 ETA 生成客户通知，**落库为「待发送」**（`erp_delivery_eta_notify`）。⚠️ 短信/微信/APP 通道**尚未接入**，接口返回 `channelReady=false` 并在提示语中明示，不假装发送成功。
- `通知台账`（抽屉按钮）：分页查看通知（状态/客户/手机号/ETA/内容），支持三种运营动作——
  **尝试发送**（通道未接入时明确返回未配置且**不篡改状态**）、**标记已发送**（线下发送后回写 `SENT`）、**作废**（`CANCELLED`）。
  这样在通道接入前后都形成闭环，避免"记录只能堆着没人管"。

## 3. 状态机与业务规范

### 3.1 路线状态（`RouteStatus`）

```
PLANNING 规划中 ──→ READY 待出发 ──→ IN_PROGRESS 配送中 ──→ COMPLETED 已完成（终态）
       └──────────────┴────── cancelRoute ──────┴──────→ CANCELLED 已取消（终态）
```

| 迁移 | 允许前置状态 | 副作用 |
|------|-------------|--------|
| 开始配送 | PLANNING / READY | 写 `start_time`；**首个未处理点位**置 `IN_ROUTE` |
| 完成配送 | IN_PROGRESS | 写 `complete_time`；`actual_duration = complete_time − start_time`（分钟）；**未处理点位（PENDING/IN_ROUTE/ARRIVED）收口为 `SKIPPED` 已跳过** |
| 取消 | 非终态 | 写 `cancel_time` + `cancel_reason`；未处理点位收口为 `SKIPPED` |

- **改单约束**：仅 PLANNING / READY 可改，点位**整体替换**（与线路档案子表同口径）。
- **收口口径说明**：完成后仍有未处理点位时统一标记「已跳过」而不是伪造「已送达」，保证 `完成进度 = 已送达 ÷ 总点位` 恒等自洽；前端二次确认时明确提示。
- **统计重算**：任何点位状态变更后按 `COUNT(*) / COUNT(DELIVERED) / COUNT(FAILED)` 重算主表 `total_points / completed_points / failed_points`。

### 3.2 点位状态（`PointStatus`）

`PENDING 待配送` / `IN_ROUTE 在途中` / `ARRIVED 已到达` / `DELIVERED 已送达` / `FAILED 配送失败` / `SKIPPED 已跳过`

### 3.3 编号规则

`PSXL-` + `YYYYMMDD` + `-` + 4 位当日序号（如 `PSXL-20260912-0001`）；同租户内 `route_code` 唯一（部分唯一索引 `uk_erp_delivery_route_code ... WHERE deleted = 0`），由 `GET /api/delivery/route/next-no` 提供。

### 3.4 与《配送单》（DmsTask）的边界

配送路线单管**多点批量配送**（一车多点，点位表 `erp_route_point`）；配送单（`DmsTask`）管**单订单配送**。两者共享配送员/车辆资源但**不合并、不双写**（分属 `erp_delivery_route` 与 `dms_task` 两套模型）。

## 11. 研判：配送路线单 vs 路线规划（2026-09-13）

> 两个页面都能"规划路线"，必须先把边界定死，否则地图能力会出现第二、第三份实现。

### 11.1 现状对照

| 维度 | 路线规划（80830 `dms/route`） | 配送路线单（80700 `dms/route-list`） |
|---|---|---|
| 定位 | 地理能力**工具台** + 围栏**档案管理** | 多点配送**执行单台账** |
| 后端 | `/api/dms/route/*`（规划/重规划/编码/逆编码/距离/坐标转换/围栏校验/能力状态）+ `/api/dms/route/fence/*`（围栏 CRUD） | `/api/delivery/route/*`（执行单 CRUD/状态机/签收/归集/规划/催单/ETA/导出） |
| 自有数据 | 仅围栏档案 `dms_geo_fence` | `erp_delivery_route` + `erp_route_point` + `erp_delivery_eta_notify` |
| 地图能力 | **提供方**（统一路由器 + **未配 Key 自动降级**） | **消费方**（`plan-order` 委托 DMS） |
| 围栏 | 建档案（几何：圆形/多边形） | 绑定引用 + 业务判定（归集/到点） |
| 交集 | 「一键生成配送路线单」→ 调本页 `POST /api/delivery/route`（payload 已核对兼容） | 接收规划结果落地 |

### 11.2 结论：**不重复，但必须收敛 3 处错位**

1. **地图能力双实现（本次已收敛）**：本模块历史上自建 `AmapService`；现已改为**依赖 `dms-delivery`、只消费不自建**（`plan-order` 走 DMS，含降级）。历史端点保留但不在主链路，建议后续删除。
2. **围栏归属（已明确）**：围栏**档案 CRUD 只在《路线规划》**；执行单只做**绑定引用 + 判定**。本页建单弹窗的围栏是选择器，无新建入口。
3. **入口重叠（不合并）**：`路线规划→一键生成` 是「规划结果落地」，`配送路线单→新增路线` 是「手工建单」；两者**必须共用同一个 create 接口**（已确认兼容），但保留两个入口符合各自工作流。

### 11.3 边界铁律（后续开发必须遵守）

- 地理能力（规划/重规划/编码/距离/坐标转换/围栏几何/围栏档案）**只在 `dms-delivery` 实现一次**，其它页面（配送路线单、调度任务、实时跟踪、渠道管理）**只调用不重写**。
- 围栏**档案**归《路线规划》维护；围栏**绑定与业务判定**归各业务单据。
- 客户配送坐标的单一口径是 `biz_party.latitude/longitude`，**禁止另建坐标表**。
- 配送路线单**不自建地图调用**；"路线规划/重新规划"统一走 `/api/dms/route/*` 能力。
