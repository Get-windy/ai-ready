## 1. 页面概述

查应付页是**应付域的核心滚动台账**：以「结算单位」为行，逐行给出 `期初应付 → 本期应付款 → 本期已结 → 优惠 → 应付余额` 的滚动链，并以 `预付余额` 冲抵得出 `期末余额`；左侧配合往来单位分类树，行内提供「付款 / 对账」动作。**单入口、单视图**（本页**无**页内视图 Tab，与《查应收》的三 Tab 结构不同）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 查应付 | `analytics/check-payable` | 单入口单视图账表（查询区 + 左分类树 + 滚动台账表格 + 合计行 + 分页） |

单入口：分析 → 财务分析 → 查应付。

- 实测实据（2026-09-15）：共 **43 条记录**，底部分页 `第 (1/3) 页`、`每页显示 16 行`；表格底部**有合计行**（实测 `198,149 / 0 / 539,533.26 / 437,348.49 / 102,184.77`）。
- **对标子分组归属**：本页属 ql361「财务分析」组下 **`往来经营`** 子分组（`.popupmenu__list-title`，**分组标题、非页面**）；同分组另有《查应收》《往来余额表》。本系统 `sys_menu` **无该层级**，仅保留菜单 80458 直挂 61005。

## 4. 业务规范

### 统计口径（应付滚动）

- **核心恒等式 1**：`应付余额 = 期初应付 + 本期应付款 − 本期已结 − 优惠`（逐行验证 ✅）。
- **核心恒等式 2**：`期末余额 = 应付余额 − 预付余额`（逐行 + 合计行均验证 ✅）——`预付余额` 为正向冲减项，故期末呈负值表示「我方多付/预付净额」。
- **预付款滚动**：`预付余额 = 期初预付 + 本期预付`（`期初预付/本期预付` 默认隐藏，本轮 `head` 未给出其值，**该等式待复核**）。
- **本期应付款**：期内采购入库/退货净增应付；**本期已结**：期内付款 + 预付抵扣；**优惠**：付款让利冲减。
- **包含已审核未记账付款单/预付款单**：勾选后未记账单据也计入已结（**权责发生 vs 收付实现**口径切换）。
- **结算单位范围**：供应商 + 个人往来（实据 `老婆-高晓丽`/`老妈-王会兰`）——**不限于供应商主数据**。
- **信用与账期列**：`信用额度 / 可用额度 / 动态付款期限 / 固定账期 / 结算期` 为供应商主数据投影（不可加总），用于对账时判断超期/超额。

### 取数来源与上下游关系

- **取数**：采购入库单（应付发生） + 付款单/预付款单（已结） + 优惠；
- **行级动作**：`付款` → 付款单表单页（财务域）；`对账` → 该单位应付明细；
- **同源页**：《查应收》（客户侧镜像）、《往来余额表》（应收应付净额口径）、《采购分析》（采购侧金额）。

- **查询项**：工具栏左侧查询方案（占位）+ 8 段时间快捷段（默认本月）；查询区：日期、「日期类型」（**disabled**）、结算单位、部门（**disabled**）、经手人（**disabled**）+ 3 个勾选（前两个可用：显示有发生期末为 0 的结算单位、显示全部结算单位；第三个「包含已审核未记账付款单/预付款单」**disabled**）+ 查询 / 重置。
- **行级动作**：「付款」→ 跳 `/finance/payment-doc/form?partnerName=...`；「对账」→ 弹窗展示该行四段余额 + 应付单据明细（`a-table`，需匹配到结算单位主数据）。
- **打印(F8) / 导出**：打印为 `window.print()`（去固定列 + 合计行），绑定 F8；导出为逐页 200 条取全量 CSV。
- **合计行**：期初应付 / 本期应付款 / 本期已结 / 应付余额取后端 `summary`（全量口径，`beginCredit-beginDebit` 等四段）；预付余额与期末余额按**已取到的行**求和（受分页限制）。
- **取数端点与口径**：主表 `GET /erp/finance/auxiliary/balance/page`（`auxType=SUPPLIER`、`subjectCode=2202` 应付账款，按结算单位四段余额 `beginDebit/beginCredit/periodDebit/periodCredit/yearDebit/yearCredit/endDebit/endCredit`）；辅表 `GET /erp/finance/partner-balance/page?partnerType=supplier`（按结算单位名补齐「预付余额」与对方 ID，`page=1&size=500` 单页）；对账明细 `GET /erp/finance/payable/list`（`supplierId` 精确匹配）。
- **后端**：本轮未改后端；未新增迁移。

### 剩余缺口（按本页自身规格＝账表页逐项判定）

1. **4 个查询控件置灰（后端无入参）**：日期类型、部门、经手人、「包含已审核未记账付款单/预付款单」勾选。
2. **12 个对标列无数据源、恒空白**：优惠、付款合计、信用额度、可用额度、动态付款期限、固定账期、结算期、联系人、联系电话、供应商备注、已开票未付款、期初 / 本期预付（仅「预付余额」「期末余额」由往来余额表补齐）。
3. **预付余额依赖单页 500 条**：`loadPartnerMap()` 固定 `page=1&size=500`，供应商超过 500 个时超出的单位「预付余额 / 期末余额」为空且无法联查对账明细（`index.vue:381-393`）。
4. **合计行两列受分页限制**：预付余额、期末余额按当前已取行求和，非全量口径。
5. **对账明细需匹配主数据**：只有按结算单位名匹配到 `partnerId` 时才能联查应付单据明细，否则仅提示。
6. **`tools/e2e-analytics.cjs` 的接口探针路径与实现不一致（工具侧缺陷）**：脚本写的是 `/erp/finance/payable/page`，本页实际走 `/erp/finance/payable/list`；该脚本若执行此项存在误报风险（本次未执行该脚本）。

## 开发原则（通用）

> - **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
> - **【金标准】模块级 E2E 脚本统一放 `tools/`**：命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖。
> - **【金标准】启动进程随手关**：收工关闭自己启动的实例与临时产物，不得清理他人产物（见 `AI_DEVELOPER_RULES.md` 7.3）。
