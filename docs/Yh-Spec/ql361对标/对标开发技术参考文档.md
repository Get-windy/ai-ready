## 1. 对标系统与数据抓取方法

### 1.1 对标系统（来肯企汇 ql361 v2.2）

- 入口：https://www.ql361.com/Account/Logon ｜ 版本口径：**22stable.ql361.com**（文档以此为准）
- 架构：**桌面式多标签系统，页面无独立路由**——登录后在桌面点菜单图标，页面以标签页打开。抓取不能用 URL 直达，必须模拟点击菜单。

### 1.2 原始抓取证据（一级事实源）

```
tool-results/ql361/pages/<域>__<组>__<页面>.json   # 页面结构数据
tool-results/ql361/pages/<域>__<组>__<页面>.png    # 全屏截图
```

JSON 字段含义：

| 字段 | 含义 |
|---|---|
| `url` / `title` | 页面地址 / 标题 |
| `tabs` | 页内标签页 |
| `filters` / `filterLabels` | 查询条件字段 |
| `buttons` | 工具栏按钮 |
| `columns` | 表格**默认显示列** |
| `_desktop` | 桌面标签栏信息（含快捷键，如「保存草稿 Ctrl+S」） |
| `bodyPreview` | 页面主体预览 |

### 1.3 页面配置 / 列配置弹窗抓取（探针）

页面配置、列配置弹窗内容不在常规抓取 JSON 内，需用探针单独 dump：

- 探针脚本：`frontend/_probe_cfg2.js`（Playwright：登录 → 打开页面 → 点齿轮 dump 弹窗）
- 目标清单：`frontend/_probe_targets.json`（`[{domain, group, item, hasList}]`）
- 运行：`cd frontend && node _probe_cfg2.js "../tool-results/ql361/pages"`
- 输出：`tool-results/ql361/pages/<域>__<组>__<页面>__cfg.json`

**cfg JSON 结构**（字段提取的权威实据）：

| 键 | 含义 |
|---|---|
| `pageConfig.lines` | 表单/列表页「页面配置」弹窗的字段清单（格式 `序号\t\t字段名`） |
| `columnConfig.lines` | 表单/列表页「数据表列配置」弹窗的列清单（格式 `序号\t\t列名`） |
| `listPageConfig` / `listColumnConfig` | 双入口页面的**列表页**页面配置 / 列配置 |

提取规则：`re.sub(r'^\d+\t\t', '', line)` 去掉序号，得到纯字段/列名。

> ⚠️ **探针局限与修复（2026-08-15 实测 → 2026-08-18 修复）**：对标系统为桌面多标签架构，无独立路由，探针点「配置」齿轮时可能点到**其他已打开标签页**的齿轮（错页抓取）。修复：打开目标页后**关闭其他 `.dijitTab` 标签**（保留活动 + 含目标名的标签），齿轮定位恢复全局。错页 cfg 一律不用于覆盖文档。**2026-08-18 已用修复后探针重抓补全 6 篇待复核文档**：采购订单（35 字段 57 列）、预付款单（15+5）、提存（10+4）、其他收入（17+4）、借出单（14+45）、盘点单（13+34）——各文档第 7 章「cfg 实测数据」；对账过程 `tool-results/ql361/cfg_summary.txt`。

## 2. 两类「配置」的本质区别（开发必读，勿混淆）

我们的页面存在**两个独立的配置入口**，字段范围互不重叠：

| 维度 | 页面配置 | 数据表列配置 |
|---|---|---|
| **入口** | 页面顶部「配置」齿轮按钮 | 数据表左上角表头单元格内的齿轮 |
| **配置对象** | **页面级字段**（表单字段 / 查询条件 / 按钮 / 摘要项） | **数据表的列字段** |
| **可配置项** | 字段的显示 / 隐藏、排序 | 列的显示 / 隐藏、显示顺序、列宽度、左固定、右固定 |
| **字段可位于** | 页面头部（搜索区 / 输入区）、页面底部（其他区）；**不含数据表列** | 仅数据表内 |
| **对标弹窗 Tab** | 页面配置 / 录单默认值 / 打印设置 | 个人配置 / 全局配置 |
| **对标配置列** | — | 序号、上级、列名、显示名、显示、回车键跳转、公式内容 |

> 抓取与落文档时严格区分：**「全部表单字段/查询条件」进「页面配置」，「默认列 + 全量可配置列」进「数据表格列配置」**，两者字段清单不得混写。

## 3. 双入口菜单规范

依据：`docs/Yh-Spec/41条双入口菜单的正确配置.md`（sys_menu `display_mode=1`，共 44 条）。

- `path` = 主菜单路径（主标签指向）；`list_path` = 标签路径（`tag_label` 按钮指向）
- **历史/列表标签（34 条）**：主菜单 → 表单页(`/form`)，标签「历史」→ 列表页(`/index`)
- **添加标签（9 条）**：主菜单 → 列表页(`/index`)，标签「添加」→ 表单页(`/form`)

开发文档对「双入口」页面需同时写**表单页 + 列表页**两部分；单入口页面只写其一。

对标系统的「产品价格等级」已被用户改为自定义昵称，共 **8 个**：

> 餐饮店、食堂团餐、自助vip、大团餐、特价客户、外围餐饮店、重点|vip01、连锁|vip

## 5. 通用业务规范（各开发文档不再重复，统一在此）

### 5.1 客户来源

单据客户来源于 **ERP 往来单位下的客户分类**（实体客户），而非 CRM 模块的客户信息。CRM 客户是公海客户，ERP 客户是实体客户。

### 5.2 架构师红线（Ponytail 六步过滤网）

动手前必过六关：①此功能业务真需要？②标准库/原生 API 能搞定？③现有依赖能否复用？④能否一行代码干净解决？⑤能否复用已有组件？⑥通通走不通才写最小可用闭环。
**Lazy, not negligent**——跨边界防注入、容灾、安全防御代码不准省。

### 5.3 业务逻辑基准

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑与交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。订金是带使用条件的预收款或预付款。

### 5.4 验收标准（通用）

- 无桩（Stub）与模拟数据：代码不得出现 TODO/FIXME/stub/模拟/mock/假数据/临时/演示/示例/占位/placeholder
- 档案字段一律选择器（可搜可新增），无手输文本
- 金额由后端复核，前端不直接落库
- 新表/补列走 Flyway 迁移并登记 `flyway_schema_history`
- 主键策略对齐所属模块基类（营销/采购用 `ASSIGN_ID`）
- 状态字段一律 0/1 整数（`status=1` 启用）

## 6. 开发文档标准模板（简洁版）

每篇 `ql361对标/<域>/<页面>开发文档.md` 遵循以下结构，**只保留本页特有内容**：

```markdown
# <页面>开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：<path>
> 通用规范见《对标开发技术参考文档》第 4、5 章

## 1. 页面概述
（表单页/列表页/双入口；页面性质一句话；双入口的 path / list_path）

## 2. 页面配置           ← 列表页/查询页才有；表单页改为「表单页配置」
### 查询条件            （字段列表，用行内代码或紧凑列表）
### 功能按钮            （按钮列表）
### 打印配置            （有则写，无则省略）

## 3. 表单页配置         ← 仅表单页
### 表头字段            （必填 * 标注 / 选填；底部 Tab 分组一句话）
### 全部表单字段        （N 个，紧凑列举）
### 录单默认值 / 打印设置 （有则写，无则省略）

## 4. 数据表格列配置
### 默认显示列          （N 列，抓取 JSON columns 实据）
### 全部可配置列        （N 列，XSMK/探针实据）

## 5. 业务规范           （本页特有的状态流转 / 规则 / 与其他页面关系）

## 6. 实现差异说明        （实现与对标有出入时补；无出入省略）
```

**写作铁律**：

1. **不重复通用规范**：价格等级 8 字段、客户来源、架构师红线、验收标准，统一指向本文，不在每篇重复。
2. **不发明字段**：字段名必须出自抓取 JSON / XSMK 标杆 / 探针实据，标注数据来源。
3. **字段用紧凑列表**：避免大段逗号长串，改成分组列表或行内代码，便于扫描。
4. **截图用相对路径**：`tool-results/ql361/pages/...`，不用本地绝对路径。
5. **「页面配置」与「数据表格列配置」严格分开**（见第 2 章），字段清单不得混写。
