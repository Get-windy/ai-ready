## 实现说明（2026-08-29 开发）

### 页面

- 地址：`/purchase/shortage-replenish`（无Tab，单页面），左侧商品分类树 + 右侧缺货补货表格
- 复用组件：`CategoryListLayout`（左侧分类树）+ `BillTableList`（表格，支持行选择）+ `PageConfigPanel`（页面配置）+ `ColumnConfigPanel`（列配置，个人/全局）+ `useColumnConfig`

### 查询区（页面配置查询条件，10项）

| 字段 | 控件 | 后端参数 |
|------|------|----------|
| 日期 | 日期范围 + 快捷日期（昨日/今日/本周/近一周/本月/上月/近三月/本年） | startDate/endDate |
| 商品 | 输入 | productKeyword |
| 仓库 | 下拉 | warehouseId |
| 客户 | 下拉 | customerId |
| 供应商 | 输入 | supplierName |
| 经手人 | 下拉 | salesmanId |
| 单据状态 | 下拉（全部/待发货/部分发货/发货完成/交易完成/已取消） | orderStatus |
| 订单来源 | 下拉（全部/内部销售/B2B商城/B2C零售/H5商城/小程序） | orderSource |
| 缺货数量= | 下拉（待发货数量-账面库存 / 待发货数量-未收货数量-账面库存） | shortageMode（1/2） |
| 仅显示缺货商品 | 勾选 | onlyShortage |

### 表格列（16列）

图片、商品名称、商品货号、规格、型号、产地、品牌、单位、订单数量、价税合计、已发货数量、待发货数量、待收货数量、账面库存、缺货数量、备注。

> 文档正文"表格列字段（35个）"为笔误，按截图实际为 16 列实现。

### 数据口径

- 主体：有效销售订单明细按「商品×仓库」聚合（`erp_sale_order_item` JOIN `erp_sale_order`，状态取 2/3/4/5，排除草稿/待审核/已取消）
- 订单数量/价税合计/已发货/待发货：`erp_sale_order_item.quantity / amount_with_tax / shipped_quantity / unshipped_quantity` 聚合
- 待收货（在途）：`erp_purchase_order_item (quantity - received_quantity)`，采购订单 status IN (2,3,5) 且未关闭未取消
- 账面库存：`erp_stock.quantity`
- 缺货数量：`GREATEST(0, 待发货 - [待收货] - 账面库存)`，非负；仅显示缺货商品时过滤 > 0

### 后端接口

`GET /api/erp/stock/shortage-replenish/page`（erp-stock 模块，纯SQL跨表聚合，无 Mock），入参见上表 + pageNum/pageSize/categoryId（分类树）。

### 操作

- **采购**：勾选行后跳转 `/erp/purchase/form?productIds=商品ID,商品ID`，采购订单表单自动预填选中商品明细。
- 刷新 / 打印(PDF) / 导出（当前可见列 CSV）/ 页面配置 / 列配置（个人+全局）。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
