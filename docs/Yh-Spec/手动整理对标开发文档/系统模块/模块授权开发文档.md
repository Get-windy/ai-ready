## 1. 页面概述

模块授权页是**平台运营方给某个租户勾选「可用功能」的授权工作台**。它属于 `61301 租户管理` 组的第 4 页（`sort=400`）。页面形态是「**选租户 → 复选框卡片 → 保存**」的**单视图表单页**（**不是表格页**）：无 `a-table`、无分页、无行操作、无弹窗。

## 2. 页面截图

**N/A（本模块无对标系统截图）。**

**原因（本模块的通用前提，本页严格遵守）**：ql361（来肯企汇 v2.2，`22stable.ql361.com`）是**租户级进销存产品**，它对客户暴露的只有「设置」域（`client_type = tenant-admin`）。本页属于**平台控制台**（`client_type = system-admin`）—— 「平台方怎么管所有租户」—— **任何厂商都不会把自己的 SaaS 控制台给客户看**。因此：

- ❌ **不使用 ql361 截图**（`client_type='system-admin'` 的菜单不会出现在租户登录的菜单树里，本页在 ql361 中根本不存在）；
- ❌ **不使用 Odoo / SAP / 金蝶 / 用友的界面截图**（口径见《系统模块/README.md》§5.3：本模块按业界**能力模型**建模，**不照搬任何一家的界面**）；
- §8 只写**业界能力对标**，逐条标来源与可信度级别。

**本系统截图**：**当前无本系统验收截图**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）→ **P2 缺口**（README §7.3）。

**数据现状（devdb 实测 2026-09-18）**：

| 项 | 实测值 |
|---|---|
| `sys_tenant_menu` 列数 / 行数 | **5 列 / 4 行** |
| 4 行的 `tenant_id` | **全 0**（不是 1/2/3，也**不是任何真实租户**） |
| 4 行的 `menu_id` | `80601` / `80602` / `80603` / `80604` |
| 这 4 个 menu_id 是什么 | **单据级隐藏菜单**：`80601 新增换货单`（`sales:exchange:create`）、`80602 编辑换货单`、`80603 新增退货单`、`80604 编辑退货单`（`sys_menu` 直查，`client_type=pc-admin`）—— **与「模块」毫无关系** |
| `sys_tenant` 行数 | **3 行**（其中 `id=0` 是 `deleted=1` 的脏行 → 租户下拉实际 2 项：`系统租户 (SYSTEM)` / `E2E验收租户2 (E2E_T2)`） |

| `sys_menu` 行数 | **381 行**（`/menu/list` 若接通将一次渲染 381 张卡片） |
| **live 探针实测** | `GET /api/tenant-menu/1` → `200 {"code":200,"message":"操作成功","data":[]}`（**回显为空**，且与所选租户无关） |

> **本页的最刺眼事实**：库里唯一存在的 4 条「授权记录」挂在 `tenant_id=0` 上，而授权接口按**路径参数 `tenantId`** 过滤（`SysTenantMenuMapper.xml` 的 `WHERE tenant_id = #{tenantId} AND deleted = 0`）→ **无论选哪个租户，回显永远是空数组**（live 已证）。

- ❌ SAP 的**数字分配与配额预留**（属《配额管理》页职责，不在本页）；
- ❌ Odoo 的「**模块 = Python 包**」模型（本系统模块 = 菜单 + 权限 + 表结构的功能块）；
- ❌ 金蝶的界面样式与「云/应用」目录结构。

**不发明字段承诺**：本页所有「建议字段」（`source` / `expire_at` / `override` 标记）**均需新增**（建议落 `sys_tenant_entitlement`，本系统**不存在**该表）；本页当前可用的字段**只有** `sys_tenant_menu` 的 5 列（§7.1）。

## 10. 验收标准（目标）

> **前置**：本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）。脚本建议命名 `tools/e2e-system.cjs`（接口 + 直连 DB 对账 + 写库后复原 + Playwright UI 截屏，参照 `tools/e2e-crm.cjs`）。
> **⚠️ 本页验收的三条前提**：
> 1. **写库断言（`PUT /api/tenant-menu/{id}`）必须用「改库 → 回读 → 按原值复原」**：本页写的是**真实租户授权表**，且**当前 4 行挂在 `tenant_id=0`**；建议**只对测试租户（`id=2 E2E验收租户2`）做写断言**，写前记录该租户原始授权集合（预期为空集），写后**立即复原为空集**；
> 2. **不得修改 `tenant_id=0` 的那 4 行**（它们是现有唯一数据，见 §7.1）；
> 3. **权限账号**：`admin`（`id=1`，`tenant_id=1`，SUPER_ADMIN）作 **200 基线**（走 `*` 通配）；另需一个**非超管的平台运营账号**做 **403 对账**（`tenant:menu:*` 与 `system:menu:list` 实测 0 行）。

### 10.1 接口验收（**22 项**）

**可达性与基础（①–⑤）**

① 用 `admin` 登录（Bearer），`GET /api/tenant/page?pageNum=1&pageSize=200` → **期望 200**，`data.records` 为**数组**、`data.total` = **2**（与 `SELECT count(*) FROM sys_tenant WHERE deleted=0` 直查一致）。
② 🎯 **超管登录后本表能查到 ≥ 4 行**（README §1.3 红线②的验收纪律）：`SELECT count(*) FROM sys_tenant_menu WHERE deleted=0` = **4**；并断言**按租户逐个查询都返回 0 行**（`GET /api/tenant-menu/{1,2,3}` 全部 `data: []`）→ **这是 P0-③ 的接口证据**。
③ `GET /api/menu/list`（**不带 `tenantId`**，即页面现有调用）→ **期望 400**，报文含 `缺少必要参数: tenantId` → 记录为**缺陷基线**。
④ `GET /api/menu/list?tenantId=1` → **期望 200**；断言返回数组**每行的键为 `menuName`/`menuCode`**（**不含 `moduleName`/`moduleCode`**）→ **这是 P0-② 字段错配的接口证据**；断言返回条数 = `sys_menu` 中符合条件的条数（**实测 381 行总量**，接口口径以实际返回为准并记录）。

**回显与写语义（⑥–⑫）**

⑥ `GET /api/tenant-menu/{tenantId}`（`tenantId` = 1/2/3 逐个）→ **期望 HTTP 200**，`data` 为**空数组**（`[]`）→ 与 ② 互证「库中 4 行不可被任何租户读出」→ 登记 **P0-③**。

⑨ 🎯 **空数组早退断言**：先确保租户 2 有 1 条授权（用 ⑧ 的写入）→ 调 `PUT /api/tenant-menu/2`，body `[]` → **期望 200「授权成功」**，但**直查 DB 断言该租户的授权行数仍为 1（未被清空）** → **这是「不落库却报成功」的接口证据（P0-⑤ 的服务端一半）**。

> **结论一句话**：本页**全部参数与权限均为平台级**；唯一的租户级对象是**授权记录行**（`tenant_id` 列，**当前全为 0，与任何真实租户都不对应**）。

## 12. 剩余缺口（P0 / P1 / P2）

> 口径与《系统模块/README.md》§7 保持一致。README §7.1 **P0-15**（平台级表未豁免多租户）、**P0-16**（权限码 0 行）、**P0-17**（平台侧无审计）在本页的具体化见下。

### P0（5 条）

① **候选模块接口必失败（缺必填参数）**：`module-auth/index.vue:114` 调 `GET /menu/list` 只传 `pageNum`/`pageSize`；后端 `listAllMenus(@RequestParam Long tenantId)`（`SysMenuController.java:161`）**无默认值**→ live 实测 **400 `缺少必要参数: tenantId`**；叠加权限码 `system:menu:list` **0 行** → 非超管再叠 403。**现象**：候选区恒空、且**无任何提示**（`:116-118` 静默吞掉）。
   建议：补 `tenantId`（或改调 `/api/tenant-module/*`），并**先裁定「模块」的实体边界**（§8 落地建议）。
② **字段名不匹配致卡片恒空白**：卡片绑定 `mod.moduleCode`/`mod.moduleName`（`:62-66`），而 `SysMenu` 只有 `menuCode`/`menuName`（`SysMenu.java:43,48`；live 返回键名已证）→ **即便接口修好，381 张卡片也全是空白标题、勾选值为 `undefined`**，提交后 `map(Number)` 得 `NaN → JSON null`（`:133`）。
   建议：字段名对齐（或先做「模块」视图模型映射）。
③ **已授权状态永不回显**：`:123-127` 取 `res.data`，而拦截器**已把 `Result` 解包为数组本身**（`utils/request.ts:208-221`）→ `res.data === undefined` → `Array.isArray` 恒假 → `selectedModules` 恒 `[]`。**live 佐证**：`GET /api/tenant-menu/1` → `data: []`；且库中 4 行 `tenant_id=0`，**任何租户都读不出内容**。
   建议：改 `Array.isArray(res) ? res.map(String) : []`；并处置 `tenant_id=0` 的 4 行存量数据。
④ **数据模型错位（本页最根本的缺陷）**：名义「模块授权」，实际读写 `sys_tenant_menu`（菜单）；`sys_tenant_module`（12 列 / **0 行**）与 `TenantModuleController` **本页零引用**（§5.4）→ 设置侧「应用中心」因无数据**恒空**。README §4「系统 → 租户库」行已登记该接线缺口。
   建议：**先裁定授权实体**（模块 or 菜单），再统一两端读写；不要新建第二套表（§8 落地建议：复用未来的 `sys_tenant_entitlement`）。
⑤ **「保存授权」会谎报成功**：前端 `handleSave` **无条件** `message.success('授权保存成功')`（`:134`）；后端 `assignMenus` 在**空数组时直接 `return`**（`SysTenantMenuServiceImpl.java:42-44`，不落库、不报错，但 Controller 仍返回 `Result.ok("授权成功", null)`，`:52`）→ **一条都没勾也提示成功、且 DB 无任何变更**（**超管会话下必现**；非超管会话因权限码 0 行会先撞 403，走 `catch` 提示失败）。**这是本页最容易被误判为「已修好」的缺陷。**
   建议：后端空数组应显式返回「未做任何变更」语义；前端按返回内容提示。

### P1（7 条）

⑥ **平台级表未豁免多租户（README §7.1 P0-15 的具体化）**：`sys_tenant_menu` 不在 `MyBatisPlusConfig.IGNORE_TENANT_TABLES`（`:32-93`），现存数据 `tenant_id` 全 0 → **非超管平台账号查询被注入 `tenant_id=<会话租户>`，页面空白而非报错**。**当前被超管整体豁免掩盖**（`SysUserServiceImpl.java:88` ＋ `AiReadyTenantLineInnerInterceptor.java:41-44` ＋ `MyBatisPlusConfig.java:157-167`），**但配置脆弱、红线仍在**。
⑦ **权限码 0 行（README §7.1 P0-16 的同类）**：`tenant:menu:query/assign/remove` 与 `system:menu:list` 在 `sys_permission`（264 行）中**全为 0** → 非超管全 403。
⑧ **授权零审计（README §7.1 P0-17 的具体化）**：保存授权不写任何审计；`sys_audit_log` 实测 **0 行** → 「谁在什么时候从哪个 IP 给哪个租户开了什么」**事后不可还原**。
⑨ **未使用任何撤销能力**：后端 `DELETE /{tenantId}/remove`、`DELETE /{tenantId}` 存在（`SysTenantMenuController.java:55-79`）但页面未接 → 只能「全量覆盖」，无法按项撤销、无法清空。
⑩ **无脏数据保护**：切租户直接覆盖 `selectedModules`（`:121-128`），未保存的勾选**静默丢弃**，无二次确认。
⑪ **未达金标准路线 A**：无 `ErrorBoundary`（页内）、无列配置齿轮、无 `PageConfigPanel`、无 `storage-key`、无经典分页 —— 与 README §7.2「30 页全部无 `PageConfigPanel` / 无 `storage-key` / 无经典分页 / 无列配置齿轮」一致；本页形态为矩阵表单，**建议按 README §5.3 改造为「租户 × 模块」矩阵列表**（`BillDetailTable` + 表头齿轮）。
⑫ **候选区无搜索 / 无分类 / 无分页**：381 行菜单一次渲染为卡片（`:52-56`），无筛选入口 → 实际不可用。

### P2（4 条）

⑬ **租户下拉解包错误（静态结论，待运行验证）**：`fetchTenants` 读 `res.data.records`（`:106`），但 `res` 已是拦截器解包后的 `data` 本体（`utils/request.ts:202-221`；live 响应体 `{"code":200,...,"data":{"total":"2","records":[...]}}`）→ `res.data` 为 `undefined`，读 `.records` **抛 `TypeError`**；该函数**无 `try/catch`**、`onMounted` 也**未 `await`/`catch`**（`:142-145`）→ 租户下拉恒空、控制台有未捕获异常。
