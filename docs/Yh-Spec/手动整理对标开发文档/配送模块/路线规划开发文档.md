## 1. 页面概述

- **地图能力工具页**：封装后端 `dms/route` 的地理能力——**路径规划 / 地址编码 / 逆编码 / 坐标转换 / 电子围栏管理**（5 项，左侧能力菜单切换）。
- 定位：给《配送路线单》《实时跟踪》《智能调度》提供底层 LBS 能力；本页是这些能力的**调试验证入口 + 围栏档案维护入口**。
- 落地页面：`CategoryListLayout`（左侧能力菜单）+ 右侧「表单 + 地图」双栏 + 结果区；围栏能力为「台账 + 校验 + 落图」三栏。

| 能力 | 作用 | 后端 |
|------|------|------|
| 路线规划 | 起点 + 多目的地，最近邻重排，驾车/骑行/步行 | `POST /api/dms/route/plan`、`POST /api/dms/route/reoptimize` |
| 地址编码 | 地址 → 坐标候选列表（带缓存） | `GET /api/dms/route/geocode` |
| 逆编码 | 坐标 → 结构化地址（省市区+街道门牌） | `GET /api/dms/route/reverse-geocode` |
| 坐标转换 | WGS-84 / GCJ-02 / BD-09 互转（单点 + 批量） | `POST /api/dms/route/convert` |
| 围栏管理 | 圆形/多边形围栏 CRUD + 单点/批量校验 | `/api/dms/route/fence/*`、`POST /api/dms/route/fence-check` |

## 2. 本系统实现（金标准已完成）

### 2.1 前端结构

| 区域 | 内容 |
|------|------|
| 左侧能力菜单 | `CategoryListLayout` 分类面板承载 5 项地理能力（`categoryEditable=false`），点击切换右侧主体 |
| 工具栏 | 规划路线 / 生成配送路线单（路线规划）；新增围栏（围栏管理）｜ 地图服务状态标签 + 刷新(F5) + 打印(F8) + 导出 |
| 查询区 | 按能力切换：出行方式 + 导航策略 + 已送达点位 + 重新规划（规划）；城市（编码）；入参坐标体系（逆编码）；源/目标体系（转换）；筛选条件 + 围栏类型 + 状态 + 查询（围栏）。未配置地图 Key 时显示**降级横幅**并给出配置项键名 |
| 主体 | 规划/编码/逆编码/转换：左表单 + 右地图双栏 + 结果区；围栏：台账（`BillTableList`，表头齿轮列配置 `dms-route-fence-columns`）+ 围栏校验面板 + 围栏落图 |
| 地图控件 | `components/business/RouteMapCanvas`（自研矢量画布，详见 2.2） |
| 底部 | 围栏台账经典分页栏（`StandardPagination variant="classic"`） |

**交互闭环**：地图点击拾取坐标回填表单（起点/目的地/待校验点/围栏中心点）；规划结果折线落图；选中围栏即在地图渲染圆形/多边形几何；「校验点位」把规划结果批量送围栏判定并在结果表回填「围栏校验」列。

### 2.2 地图能力（`RouteMapCanvas`）

零外部依赖的矢量画布（SVG），与后端 Haversine 口径一致的**等距圆柱投影**（以米为平面、按中心纬度折算经度尺度）：

- 自适应视野（含圆形半径外扩）、网格参考线、**比例尺**（自动选取 100 m / 500 m / 1 km …）、实时经纬度读数；
- 标记点（起点/途经点/终点/标记点，带图例与标签）、规划折线、圆形围栏（半径按米换算像素）、多边形围栏（顶点绘制）、多边形**地图绘制模式**（点击加顶点 / 撤销 / 清空）；
- 地图点击回调 → 回填表单；`ResizeObserver` 自适应容器尺寸。

> 未接入高德/百度 JS SDK：真实路网规划由**后端**地图服务完成（本页只做可视化与校验），故前端无需地图 Key，也不存在两套 Key 漂移问题。详见「待完善 1」。

### 2.3 后端实现

**包**：`cn.aiedge.dms.route`（controller / dto / entity / mapper / service / spi）+ `cn.aiedge.dms.common.util.GeoUtils`。

| 接口 | 说明 |
|------|------|
| `POST /api/dms/route/plan` | 规划。请求体**同时兼容 `waypoints` 与 `destinations`（历史字段名不一致导致目的地被静默忽略的缺陷已消除）**，另兼容 `destination`；`direction` 驾车/骑行/步行；`optimizeOrder` 是否最近邻重排；`coordSystem` 入参体系自动转 GCJ-02；返回 `stops`（起点+各点，含距上点距离/时长）、`totalDistance/totalDuration`、`optimizedOrder`、`provider`、`degraded` |
| `POST /api/dms/route/reoptimize` | 重新规划：以当前位置为起点对剩余点位重排，`visitedCount` 续编点位序号 |
| `GET /api/dms/route/geocode` | 地址编码，返回**候选列表**（`candidates`）+ 首条平铺字段；进程内 TTL 缓存（24h / 2000 条，只缓存成功结果） |
| `GET /api/dms/route/reverse-geocode` | 逆编码（结构化省市区 + 街道门牌），支持 `from` 入参体系转换 |
| `POST /api/dms/route/distance` | 批量距离/时长（1 直线 2 驾车 3 骑行），回填起终点坐标 |
| `POST /api/dms/route/fence-check` | 围栏校验：**围栏档案（fenceId）/ 内联圆形 / 内联多边形**三选一，支持单点与 `points[]` 批量；返回结论 + 距中心/边界距离 |
| `POST /api/dms/route/convert` | 坐标体系互转（单点 + 批量） |
| `GET /api/dms/route/config` | 服务商状态与 Key 落位诊断（provider / configured / degraded / **keySource** / **envVarName** / **configKey** / **hint** / providers[] / 坐标体系 / 出行方式 / 缓存条数；不回显 Key 明文，见 §8） |
| `/api/dms/route/fence/*` | 围栏档案 `page / {id} / next-code / options / POST / PUT / DELETE / {id}/status` |

**关键实现**：

1. **服务路由与降级**（`MapServiceRouter` + `MapKeyResolver` + `LocalMapService`）：按 `dms.map.default-provider` 选择服务商；**未配置 Key 时自动降级为本地直线模式**（Haversine 距离 + 出行方式平均时速），外部服务调用失败亦回退直线并标记 `degraded`，保证规划/距离/围栏链路不因 Key 缺失整体中断；地址编码/逆编码无法离线完成时**明确失败并给出配置指引，绝不返回假坐标**。Key 的**四种来源与优先级见 §8**（环境变量 > Spring 配置 > 配置中心《配送参数》 > 未配置），支持热更新（配置保存立即生效，跨实例 ≤30 秒）。
2. **统一几何口径**（`GeoUtils`）：Haversine 球面距离、圆形判定、**多边形射线法判定**（含点到多边形边界的距离、边界点容差 0.01 m 按「在围栏内」处理）、多边形文本解析/序列化、WGS-84↔GCJ-02↔BD-09 转换。`DispatchService` 原「经纬度等权欧氏距离」直角近似已改为 Haversine（对齐本工具页口径）。
3. **围栏档案**：表 `dms_geo_fence`（迁移 `V11.180.0__Create_Dms_Geo_Fence.sql`），CIRCLE（中心+半径）/ POLYGON（顶点串）两类；可绑定线路档案（ROUTE）/ 运力渠道（CHANNEL）/ 仓库区域（WAREHOUSE）/ 其它；编码 `WL` + 3 位序号（同租户唯一，软删可复用）；`FieldStrategy.ALWAYS` 保证「圆形→多边形」时 `center_lat/radius_meters` 等字段**真实写空**（避免 MyBatis-Plus 默认忽略 null 导致的脏数据）。
4. **坐标体系固化**：对外统一 GCJ-02；`plan/reverse-geocode` 支持 `coordSystem/from` 入参自动转换；`/convert` 供 GPS 原始点入库前转换。

### 2.4 与《配送路线单》联动（规划结果复用）

- 结果区「**生成配送路线单**」→ 弹窗选择配送员（必填）、线路档案（可选）、计划日期 → 调 `POST /api/delivery/route`（执行单手工建单接口，**不依赖地图 Key**）写入路线单 + 点位明细，随后可在「配送 → 配送路线 → 配送路线单」派车、开始配送、逐点签收。
- 起讫点取规划的起点坐标，点位明细取规划结果的各目的地（含经纬度与地址），实现了「规划 → 执行」的闭环。

### 2.5 快捷键与导出

- **F5** 真实刷新（重载配置 + 当前能力数据，规划结果存在时按当前参数重新规划）；**F8** 打印（浏览器打印，打印样式隐藏工具栏/搜索区/地图）；弹窗 Enter 保存。
- **导出**：按当前能力导出**真实 xlsx**（规划点位 / 编码候选 / 逆编码结果 / 坐标转换结果 / 围栏台账），前端 `xlsx` 生成，非 JSON、非 CSV。

- 配置中心（《配送参数》）配套：`dms.ConfigService`（全局默认 + 租户覆盖合并 / upsert / 值归一化 / **敏感键脱敏** / **留空不改** / **clearConfig 清除**）、`dms.config.event.ConfigChangedEvent`（进程内热生效）、`dms.common.util.SecretMasker`（敏感键识别与掩码）、`DmsConfigMapper`（`@InterceptorIgnore` 读全局行）、`ConfigController`（值归一化 + `DELETE /{key}` 清除）
- **跨实例即时生效**：`MapKeyResolver` 以**常驻 Redis 连接**订阅 `dms:config:change`（`ConfigService` 保存后广播）；⚠️ 不能用 `StringRedisTemplate.execute(...)` 内订阅（回调返回即归还连接，订阅失效——平台既有监听器即此写法）

- 平台配置：`backend/core/api/core-api/src/main/resources/application.yml` 的 `dms.map.*` + `amap.key`（见 §8.1）
- 迁移：`V11.180.0__Create_Dms_Geo_Fence.sql`、`V11.181.0__Seed_Dms_Map_Config.sql`
- E2E：`node tools/e2e-dms-route.cjs`（API + UI 共 **138 项，全绿**）

## 8. 地图服务 Key 配置落位（2026-09-13 增补）

> **统一口径**见《对标开发技术参考文档》**§5.6「外部服务与密钥配置落位」**（四条通道 + 全量清单 + 硬规则）。本节是本页的具体落位与排障：
> 页面上那句「未配置地图服务 Key …」到底**在哪配**？结论先说：
> **生产用环境变量 `AMAP_API_KEY`；私有化单机可在《配送参数》页面配（保存即热生效）；两者都读不到时才降级。**

### 8.1 根因：模块自带 yml 不生效（此前写成环境变量也读不到）

`dms` 模块自带的 `dms-application.yml` 里虽然写了 `dms.map.amap.api-key: ${AMAP_API_KEY:}`，但**模块级 application.yml 位于嵌套 jar 内，core-api 启动时不会加载**（Spring Boot 只读 classpath 根的那一份，即 core-api 自己的 `application.yml`）。因此此前无论怎么设 `AMAP_API_KEY`，DMS 侧读到的始终是空值 → 页面永远显示降级。

**修复**：在 `backend/core/api/core-api/src/main/resources/application.yml` 显式声明（全平台单一入口）：

```yaml
dms:
  map:
    default-provider: ${DMS_MAP_DEFAULT_PROVIDER:amap}   # amap / tencent / baidu
    amap:    { api-key: ${AMAP_API_KEY:} }
    tencent: { api-key: ${TENCENT_MAP_API_KEY:} }
    baidu:   { api-key: ${BAIDU_MAP_API_KEY:} }
# 配送路线单（erp-delivery-route）的路线优化/导航复用同一把高德 Key
amap:
  key: ${AMAP_API_KEY:}
```

### 8.2 四种配置方式（优先级从高到低）

| # | 落位 | 怎么做 | 生效 | 适用 |
|---|------|--------|------|------|
| 1 | **环境变量**（推荐） | 启动前设置 `AMAP_API_KEY=<Key>`（`TENCENT_MAP_API_KEY` / `BAIDU_MAP_API_KEY` 同理；**前端底图另有 `AMAP_JS_KEY`**，见 §8.6） | 重启后端 | 生产/容器（密钥不进仓库、不入库） |
| 2 | **Spring 配置** | 改 core-api `application.yml`；或启动参数 `--dms.map.amap.api-key=xxx`；或外部化配置文件 `--spring.config.additional-location=file:./config/` | 重启后端 | 单机、编排注入、按环境隔离 |
| 3 | **配置中心《配送参数》** | 菜单「配送 → 配送配置 → 配送参数」编辑 `map.amap.api-key`（`map.default-provider` 可切服务商） | **保存即热生效**（本实例立即；跨实例 ≤30 秒） | 私有化部署一键运维、临时换 Key |
| 4 | 未配置 | — | — | 自动降级：直线距离 + 本地几何围栏；**地理编码/逆编码不可用并明确提示**（不返回假坐标） |

判读当前来源：`GET /api/dms/route/config` → `keySource` = `ENV` / `SPRING` / `CONFIG` / `NONE`，并在响应里给出 `envVarName`（如 `AMAP_API_KEY`）与 `configKey`（如 `map.amap.api-key`）；页面顶部标签与降级横幅按此渲染，横幅右侧「去《配送参数》配置」直达配置页。

### 8.3 部署示例

```yaml
# docker-compose / k8s（Key 由 .env 或 Secret 注入，勿写入仓库）
services:
  core-api:
    environment:
      - AMAP_API_KEY=${AMAP_API_KEY}
      # - DMS_MAP_DEFAULT_PROVIDER=amap
```

> **前端不需要地图 Key**：底图与路网规划由后端完成，前端只做矢量可视化（`RouteMapCanvas`），避免两套 Key 漂移。

### 8.4 配置中心读写口径（本次一并修正）

`dms_config` 采用「**全局默认（`tenant_id=0`）+ 租户覆盖**」：

- 读取：`listAll` 合并两级（同名键以租户值优先），`getConfig` 租户优先、全局兜底；**敏感键只回掩码**（`secret/configured` 标记）；
- 保存：租户无该键时**新增覆盖行**（只影响本租户）；值做归一化（剥掉前端 `JSON.stringify` 的一层引号，使数值型配置可被 `getInteger` 解析）；**敏感键留空=不修改**，清空走 `DELETE /api/dms/config/{key}`；
- 热生效：保存后 ① 进程内发布 `ConfigChangedEvent`；② **Redis 广播** `dms:config:change` 让所有实例即时失效缓存（`MapKeyResolver` 以常驻连接订阅）；
- 预置：迁移 `V11.181.0__Seed_Dms_Map_Config.sql` 预置全局 4 键（`map.default-provider` + 3 个 `*.api-key`，value 留空）并加 `(tenant_id, config_key)` 部分唯一索引。
- ⚠️ **坑**：登录租户=1 时，多租户插件会给 SQL 注入 `tenant_id = 1`，导致「全局默认行（tenant_id=0）」读不到 / 更新影响 0 行。故全局读用 `@InterceptorIgnore(tenantLine="true")` + 显式 `tenant_id = 0`；写路径在目标租户上下文内执行（`MyBatisPlusConfig.setTempTenantId(tid)`）。

### 8.6 前端底图 JS SDK Key（`map.amap.js-key`）

- **两把 Key 别混用**：`map.amap.api-key` 是**服务端 Web 服务 Key**（调 REST API，绝不下发前端）；`map.amap.js-key` 是**浏览器 JS SDK Key**（设计上即公开，需在高德控制台按域名限制）。
- 落位：环境变量 `AMAP_JS_KEY` > core-api `application.yml` 的 `dms.map.amap.js-key` > 《配送参数》`map.amap.js-key`；`GET /api/dms/route/config` 以 `jsKey/jsKeyConfigured` **明文**下发（JS Key 性质如此），前端加载失败/超时（8s）自动回退矢量画布并提示一次。
- 未配置时：`底图：矢量（未配 JS Key）`，功能完全可用（自研画布支持选点/拖拽/折线/圆/多边形）。

### 8.5 排障

| 现象 | 原因与处置 |
|------|-----------|
| 页面一直显示降级 | 查 `/api/dms/route/config` 的 `keySource`：`NONE` = 三处都没配；确认环境变量名是 `AMAP_API_KEY`（不是旧的 `AMAP_KEY`）、且改了配置后**重启过**后端或用《配送参数》保存过 |
| 改了模块里的 `dms-application.yml` 没反应 | 该文件不会被 core-api 加载，改 core-api 的 `application.yml`（见 8.1） |
| 填了 Key 仍降级 | 看规划失败原因：`INVALID_USER_KEY` 等表示 Key 无效/未开通 Web 服务 → 修正 Key 后重新保存；**业务不会被阻断**（自动降级直线） |
| 保存后想撤销 Key | 点《配送参数》行内**「清除」**（`DELETE /dms/config/{key}`）；⚠️ 敏感键**留空保存 = 不修改**（页面拿到的是掩码，避免把掩码写回库） |
| 多租户下想给某租户单独用 Key | 后端口径已支持「租户覆盖全局」（`dms_config.tenant_id = 该租户`），但《配送参数》页面目前固定以 `tenantId=0` 读写**全局默认行**，页面内暂无租户级切换 → 需租户级 Key 时调 `PUT /api/dms/config/map.amap.api-key?tenantId=<租户>`（后续在配置页补租户切换 + 掩码，见 §5 待完善 2） |
