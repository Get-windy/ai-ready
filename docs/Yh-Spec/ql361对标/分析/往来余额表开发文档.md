# 往来余额表开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`analytics/ar-balance-sheet`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **账表页**（往来总账）：结算单位应收/预收/应付/预付四象限余额与往来净额（五组期初/本期/期末三列，支持应收应付清账）；往来单位资金净额的总览报表。菜单路径：分析 → 财务分析 → 往来余额表。
- 页面结构：查询区（两行）+ 多级表头表格（操作 | 结算单位编号 | 结算单位 | 应收/预收/应付/预付金额四组 | 往来合计）+ 清账历史入口。
- 页面截图：`tool-results/ql361/pages/分析__财务分析__往来余额表.png`

## 2. 页面配置

### 查询条件（抓取 JSON filterLabels + 截图实据）

## 3. 数据表格列配置

### 默认显示列（3 个固定列 + 5 个分组表头 + 15 个叶子列，抓取 JSON columns 实据）

- 固定列：操作、结算单位编号、结算单位
- **应收金额**：期初应收余额、本期应收、期末应收余额
- **预收金额**：期初预收金额、本期预收、期末预收金额
- **应付金额**：期初应付金额、本期应付、期末应付金额
- **预付金额**：期初预付金额、本期预付、期末预付金额
- **往来合计**：期初余额、本期发生、期末余额

> JSON columns 共 24 项，首项"操作 结算单位编号 结算单位"为抓取拼接串剔除；余 23 项按截图多级表头归位为 3 个固定列 + 5 个分组表头 × 各 3 个叶子列（期初/本期/期末），叶子数据列合计 18 个。

## 4. 业务规范

### 统计口径（四象限 + 净额）

- **四象限滚动**：每象限 期末 = 期初 + 本期发生（应收/预收/应付/预付各自独立滚动）
- **往来合计（净额）**：期初余额/本期发生/期末余额 = （应收 + 预付）−（应付 + 预收） 的债权净额口径（正=对方欠我，负=我欠对方；具体符号方向待复核）
- **与查应收/查应付的关系**：应收金额组=《查应收》口径、应付金额组=《查应付》口径的并集呈现；本表为同一单位四象限全量视图
- **清账**：同一单位既是客户又是供应商时，应收与应付可对冲清账（"仅显示既是客户又是供应商"勾选即为此场景筛查；清账历史追溯）

### 与其他页面关系

- 取数：《查应收》+《查应付》全量（应收/预收/应付/预付四账簿）
- 下游：清账动作回写应收应付余额；对账单输出（打印/导出）
