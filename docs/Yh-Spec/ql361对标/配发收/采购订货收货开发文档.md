# 采购订货收货开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`dispatch/purchase-receive`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **列表操作页**：采购到货的收货处理待办工作台——按单据/按明细两视图，跟踪待收货/部分收货状态，支持批量收货。
- 入口形态：菜单"采购订货收货"打开的桌面标签为"**收货处理**"，单据状态查询条件默认"待收货,部分收货"。
- 单入口（无历史/添加标签）。
- 截图：![采购订货收货](../../../../tool-results/ql361/pages/配发收__收货业务__采购订货收货.png)

## 2. 页面配置

### 查询条件

按抓取 JSON 实据（filterLabels：往来单位、经手人、仓库）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止）、单据编号、往来单位、经手人、仓库、单据状态（多选，默认：待收货,部分收货）
- 单据备注

### 功能按钮

按抓取 JSON buttons 实据：刷新、批量收货、打印(F8)、导出、查询、跳转（分页跳转）

行级操作：本次快照无数据行未捕获（待复核；按"批量收货"推断存在行级"收货"动作）。

### 打印配置

## 4. 业务规范

- 业务对象为**待收货的采购订货单据**：单据状态查询默认"待收货,部分收货"，即本页是收货待办工作台，已完成收货的单据默认不再出现。
- **应收数量 / 未收数量**：按单据跟踪收货进度，支持分次收货（"部分收货"状态实据）；未收=应收−已收。
- **预计收货日期**：采购到货计划管理。
- **往来单位 / 结算单位**双列：供货的供应商与结算主体可不同（如总部供货、分仓结算场景）。
- **结算状态**：收货与付款结算进度解耦。
- **批量收货**：勾选多行后批量执行收货确认，适配集中到货场景。
- 与源单关系：采购订单（订货）→ 本页收货处理（实物收货确认，待收货→部分收货→已收货）→ 采购入库单（入库记账、库存增加）；与销售线对称（销售订单 → 拣货/发货 → 销售出库单）。收货确认与采购入库单的生成关系（收货即生成入库单 / 收货后另行入库）待复核。
- 上下游：上游采购订单（采购域）；同组物流退货收货（退货线收货）；下游采购入库单（采购域，入库记账）；应付款结算（结算状态口径来源，待复核）。
