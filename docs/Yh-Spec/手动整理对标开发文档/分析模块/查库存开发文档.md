## 1. 页面概述

查库存是**库存实时台账查询页**（商品 × 仓库粒度、时点存量）：三个页内视图 Tab 共用一套查询区与工具栏，逐 Tab 切换列集合与行模型：

| 视图 Tab | 行模型 | 列数 / 默认 | 实测记录数 | 分类树 |
|---|---|---|---|---|
| 当前库存 | 商品 × 仓库台账 | 54 / 8 | 2814 | ✅ 有 |
| 按属性 | 按商品属性展开的库存视图 | 50 / 6 | 2248 | ✖ 无 |
| 库存分布 | 商品 × 仓库二维分布（动态仓库列） | 33 / 2 | 1683 | ✖ 无 |

单入口：分析 → 仓配分析 → 查库存（菜单 **80431**，path `analytics/check-stock`）。

- 实测实据（2026-09-15）：三 Tab 的 `snapshot.record` 分别为「共 2814 条记录」「共 2248 条记录」「共 1683 条记录」。
- 本系统落地页 `views/analytics/check-stock/index.vue` 为**单表三 Tab 骨架**（`:4-15`），未按 Tab 拆列集合。

### 口径说明

- **`当前库存` = 时点存量台账（商品×仓库一行）**：`账面库存\*` 与 `可用库存\*` 两组各含 数量 / 换算结果 / 小单位数量 / 中单位数量 / 大单位数量 / 总重量 / 总体积 七个子列，是**同一存量的不同计量表达**（大中小单位 + 重量 + 体积）。
- **在途三口径**：`已发待记账数量` / `已收待记账数量` / `未发数量` / `未收数量` 四列与台账分列，支撑账实核对（前两者默认可见）。
- **`成本金额` 口径**：实测行 `成本单价 16.272 / 成本金额 244.08 / 账面库存\数量 15` → 244.08 = 16.272 × 15，即 **成本金额 = 成本单价 × 账面数量**（脚本行实据 `head`）。
- **定价体系价值列**（39-54 列）：`餐饮店 / 食堂团餐 / 外围餐饮店 / 自助vip / 大团餐 / 重点|vip01 / 连锁|vip / 特价客户` 为**客户级别 8 档**（与《对标开发技术参考文档》价格等级 8 字段同源），每档带同名 `…价值` 列 = 该档价格 × 存量。
- **`库存分布` = 商品×仓库二维透视**：行=商品，列=仓库，单元格=该仓 `账面库存`，末列 `合计` 跨仓求和（实测 319 校验通过）。
- **`按属性` = 属性展开视图**：与当前库存同源，去掉重量/体积汇总子列，默认列收窄为「名称 + 单位 + 账面双数量 + 待记账双数量」。

## 4. 业务规范

### 库存口径（可用 / 账面 / 在途 / 成本）

- **账面库存**：全部出入库流水净额（含已发待记账 / 已收待记账）。`账面库存\数量` 为主单位数量，`\小单位数量` 为折算到最小单位的数量，`\换算结果` 为多单位表达（如 `1箱3瓶`），`\中/大单位数量` 为按商品换算关系折算结果。
- **可用库存**：账面 − 占用（待发货锁定 / 拣货中等待出）。实测 `当前库存`（默认含账面双列）与 `库存分布`（仅账面口径）并存的根因即**可用口径只在部分视图暴露**。
- **在途四口径**：`已发待记账数量`（已发货未记账）、`已收待记账数量`（已收货未记账）、`未发数量`（已下单未发货）、`未收数量`（已下采购未收货）——台账与在途分列，不做轧差。
- **成本口径**：`成本单价` 实测 4 位小数（行实据 `16.272` / `30.3083`），`成本金额 = 成本单价 × 账面数量`，与《进销存分析》同源。
- **零库存色标**：基准确认「零库存商品名称红色显示」，本次截图受菜单浮层遮挡未取到该行实据，**待复核**。
- **仓库选择上限**：单次查询至多 10 个仓库（查询区提示串实据），`库存分布` 视图的列数即由此上限约束。

### 与其他页面关系

- 同组页面：《查批次》（批次粒度）、《进销存分析》（期间变动口径）、《库存明细》（流水粒度）。
- 联查四件套（基准文档）：`分布` → 本页「库存分布」视图；`明细` → 《库存明细》；`对账` → 库存对账；`批次号` → 《查批次》。**2026-09-15 实测行级仅见 `明细`、`对账`**。
- 下游：商城商品上架状态联动（基准文档「批量上架/下架」，本页实测未见）；《采购准备》缺货补货。

### 剩余缺口

1. **查询区 3 项当前不生效（静默失效风险）**：后端 `StockController.page`（`StockController.java:109-125`）只支持 `pageNum/pageSize/productId/warehouseId/keyword`，本页传的 `brand`（品牌）、`productStatus`（显示状态）、`categoryId`（分类）均被后端忽略。实测：加 `brand=NOPE_XYZ&productStatus=disabled&categoryId=1` 后 `total` 不变（4）。其中仅「分类」在首次选中时弹一次提示（`categoryTipShown`），品牌 / 显示状态**无任何提示**。
2. **「库存分布」Tab 列数随仓库数漂移**：对标为固定 33 列 / 默认 2；本页该 Tab 会按所选仓库动态追加仓库列 + 合计列并进入列配置额度，实测 dev 库（3 仓）为 **37 / 6**，与对标口径不一致（列数断言会随仓库数量变化）。
3. **默认可见列存在空列**：`/erp/stock/page` 返回的是 `erp_stock` 实体，实测行内 `productName / productCode / warehouseName / unit / unitPrice` 均为 `null`（dev 库 stock 行未回填这些冗余列），因此默认可见的「商品名称 / 单位 / 成本单价」以及前端由 `quantity × unitPrice` 计算的「成本金额」当前显示为空 / 0；「小单位数量 / 已发待记账数量 / 已收待记账数量」在 `Stock` 实体上无对应字段，恒为空列。
4. **无合计行**：默认可见的数量类列（数量、小单位数量等）无合计。
5. **分页与拉取上限**：多仓查询时最多合并 5000 行（超出仅提示），且为前端分页；仓库默认只取前 10 个（对标同为「默认只查询 10 个仓库」，一致）。
6. **查询方案为占位**：`queryScheme` 未被任何请求使用。
