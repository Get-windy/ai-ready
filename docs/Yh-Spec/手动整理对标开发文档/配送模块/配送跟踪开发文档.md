## 1. 页面概述

- **轨迹台账页**：按配送员/任务/时间查询**轨迹点明细**（经纬度、速度、方向、来源），是《实时跟踪》的"数据底座"视图。
- **与《实时跟踪》的分工**：

| | 实时跟踪（`dms/realtime-tracking`） | 配送跟踪（本页 `dms/tracking`） |
|---|---|---|
| 视角 | 在线配送员**最新位置** + 轨迹**回放**（可视化） | 轨迹点**明细台账**（表格/可导出/可对账） |
| 受众 | 调度主管实时盯盘 | 运营/客服/审计查证 |

### 3.5 业界生产级实践要点

1. **时序存储**：轨迹表按天分区/定期归档，明细查询走时间索引，避免全表扫描（`dms_tracking` 数据量增长最快）。
2. **抽稀与聚合**：明细查询限制返回条数；里程按段增量聚合，不实时全量计算。
3. **来源可溯**：来源字典（APP/后台/渠道回传）用于判断数据可信度与对账。
4. **合规**：仅配送时段采集（`dms.tracking.collect.hours`，`assertWithinCollectWindow`）；查询留审计（谁查了谁的轨迹）——✅ 本轮已实现，见 §6.5。
5. **异常联动**：速度异常/长时间停留推《人员核验》预警体系（人车分离/异常滞留），口径统一——✅ 本轮已实现，见 §6.6。

### 6.5 查询审计（§3.5.4）

- **落点**：`TrackingController` 的 `/page`、`/export`、`/track-vo`、`/task-vo/{taskId}`、`/replay` 加 `@OperationLog(module = "配送跟踪", type = QUERY|EXPORT, desc = …)`，由 core-base `OperationLogAspect` 异步落 `sys_oper_log`。
- **可回答的问题**：谁（`username`/`user_id`）、何时（`oper_time`）、从哪个 IP（`oper_ip`）、查了什么条件（`request_params`，含 `riderId`/`taskId`/时间范围）、耗时（`cost_time`）。
- **已知边界**：导出端点带 `HttpServletResponse` 入参，切面序列化参数会失败 → 该行 `request_params` 为 `null`（框架既有行为，`配送路线单` 同样如此）；导出仍留痕「谁在何时导过」，但条件要看紧随其前的 `/page` 记录。
- 这是**整个 dms 模块首次接入查询审计**（此前 `grep -rl "@OperationLog" backend/dms` 为空）。

### 6.6 异常联动预警（§3.5.5）

- **落点**：`TrackingService.reportLocation` 插点后调用 `raiseAbnormalAlerts`：
  - **超速**（`speed > dms.tracking.speed.limit`，默认 60）→ `AlertTypeEnum.SPEED_ANOMALY(3)`，级别 警告(2)；
  - **异常停留**（与同一配送员**上一点**时间差 ≥ `dms.tracking.stop.minutes`，默认 15 分钟，且位移 < 50 米）→ `AlertTypeEnum.ABNORMAL_STAY(2)`。
  - 预警带 `taskId` + 告警时刻经纬度，便于在《人员核验》预警列表回溯。
- **去重契约**：复用 `VerificationService.raiseAlert`（同配送员 + 同类型 + `handle_status=0` 存在即不重复产生）；处理后才可能再次触发。
- **不阻断主链路**：整个预警过程包在 `try/catch` 内，失败只记 `warn`，位置上报仍成功。
- **依赖破环**：`VerificationService` 已构造注入 `TrackingService`（反向依赖），故 `TrackingService` 用 `ObjectProvider<VerificationService>` 延迟解析，避免构造器循环依赖（项目虽开了 `spring.main.allow-circular-references`，但**构造器循环**仍无解）。
- **口径统一**：`/tracking/alerts`（实时跟踪页的预警列表）与本联动共用同一套阈值配置键，避免「页面标红但预警体系不认」的两套口径。

### 遗留（非阻塞）

- **抽稀策略**：等间隔取样 + 首尾必留（`maxPoints` 默认 500），非 Douglas-Peucker 曲线简化；如需更高保真可替换算法。
- **逆地理编码**：`address` 只存上报端回带值，服务端逆编码待接《路线规划》（`dms/route`）。
- **归档触发器**：`cleanExpiredData` / `retentionDays` / `POST /clean-expired` 已就绪（`dms.tracking.retention.days`，0=不清理），但**定时触发器/分区表**待生产上线前配置。
