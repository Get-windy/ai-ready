# 物流退货收货开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`dispatch/return-receive`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **列表操作页**：以销售退货申请为主对象的收货进度管理视图——按单据/按明细两视图，跟踪退货商品的已收/未收进度。
- 入口形态：菜单"物流退货收货"打开的桌面标签为"**销售退货申请-历史**"，订货数量/已收数量/未收数量三列直接挂在退货申请行上。
- 单入口（无历史/添加标签）。
- 截图：![物流退货收货](../../../../tool-results/ql361/pages/配发收__收货业务__物流退货收货.png)

## 2. 页面配置

### 查询条件

按抓取 JSON 实据（filterLabels：客户、经手人、部门、仓库）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 单据时间*（必填，起 至 止）、单据编号、客户、经手人、部门
- 仓库、产生方式（全部）、单据状态（全部）、结算状态（全部）、打印次数（带 ≥ 比较符下拉）

### 功能按钮

按抓取 JSON buttons 实据：新增、刷新、批量打印、打印(F8)、导出、查询、跳转（分页跳转）

行级操作：本次快照无数据行未捕获（待复核；按"已收数量"列推断存在行级收货确认动作）。

### 打印配置

待复核（抓取数据未覆盖打印配置弹窗）。

## 3. 数据表格列配置

### 默认显示列（21 列，抓取 JSON columns 实据，按单据子标签）

操作、单据日期、单据编号、单据状态、仓库、客户、客户编号、客户级别、联系人、联系电话、联系地址、客户备注、经手人、部门、本单金额、订货数量、已收数量、未收数量、附件、打印次数、单据备注

## 4. 业务规范

- 业务对象为**销售退货申请**：列表行即退货申请单，**订货数量（申请退货数量）/ 已收数量 / 未收数量** 三列构成收货进度——退货商品由物流/配送带回后按申请单做收货确认，已收回写、未收=订货−已收。
- **新增**红色主按钮：可在本页直接新增销售退货申请（直达销售域退货申请表单）。
- 结算状态查询条件：退货涉及退款/抵扣结算进度（与销售退货单的付款方向退款口径对应）。
- 按单据/按明细两视图：按单据=一行一申请单；按明细=一行一商品明细（明细列结构待复核）。
- 与源单关系：销售域退货主线两条路径（销售域实据）："销售退货申请（审核）→ 销售退货单（入库）"或直接开销售退货单；订单处理中心查询勾选项"不显示有关联审核中退货申请单的单据"证明申请单与原销售订单存在关联审核。**销售退货单（入库记账）与本页收货确认的先后关系**（先收货确认再生成退货单入库、还是收货确认即触发退货单）待复核；收货完成后的入库记账与库存回增由销售退货单承担。
- 上下游：上游销售退货申请（销售域表单页；本页"新增"直达）、销售订单（原单）；同组采购订货收货（采购线收货，对称页）；相关配送查询（退货带回的配送任务）、销售退货单（退货入库记账）。
