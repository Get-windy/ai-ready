## 页面概述

商品条码用于查看与维护**商品的条码信息**：一行 = 一个商品的一个单位（`erp_product_unit`），条码按单位分别维护（EAN13/CODE128/QR/OTHER）。已接入真实后端 `ProductBarcodeController`（`/api/erp/product/barcodes/page`），条码优先取单位行 `erp_product_unit.barcode`，缺失时回退既有条码表 `erp_product_barcode` 的默认记录（**单一口径，不另建重复条码表**）。行级「修改」= 打开该商品的档案编辑页（对标行为），在「商品单位」明细里维护条码，保存时统一做全局唯一性校验与条码表双口径同步。

## 业务规范说明

- **条码类型**（`erp_product_barcode.barcode_type`）：EAN13 / CODE128 / QR / OTHER。
- **条码来源**：条码挂商品单位行（换算关系/单位/条码），非独立主档；本页按商品分类树浏览，无「新增」，仅行级「修改」。
- **数据源与落库口径**：读取时条码取 `erp_product_unit.barcode`，为空则回退 `erp_product_barcode` 默认记录（`is_default=1`）；行级修改同时写单位行条码与条码表默认记录，**不另建重复条码表**。
- **条码唯一性**：修改时同时校验单位行与条码表，重复即拒绝（含跨商品）。

### 本次对齐修复的真实缺陷（跨模块 P0/P1）
| 级别 | 缺陷 | 修复 |
|---|---|---|
| P0 | 商品档案保存单位是「先删后插」，校验/插入失败时**原有单位被删光且不回滚**（实测丢 2 行单位数据） | 校验前置到删除之前 + `@Transactional` + `catch` 内 `setRollbackOnly()`；实测失败后单位快照完全不变 |
| P0 | 前端 `productFormApi.batchUpdate/batchCreate` 请求路径写错（`PUT /erp/product/{id}`、`POST /erp/product`），**单位/推荐/条码全部不落库** | 改为 `/erp/product/batch-update/{id}`、`/erp/product/batch-create` |
| P0 | 商品档案 `productId = Number(route.params.id)` 使雪花 ID 丢精度（`990000000000000001` → `990000000000000000`），按 id 查不到商品、页面空壳 | `productId` 全程保持字符串 |
| P0 | `erp_product_unit` 缺 `weight`/`volume` 列，`GET /erp/product/{id}/form` 直接 500，行级「修改」跳转不可用 | 补列；已由商品模块迁移 `V11.154.0__Add_Weight_Volume_To_Product_Unit.sql` 承载（不重复建迁移），本次仅确保执行到位 |
| P1 | 商品档案保存条码无唯一性校验、条码表不随档案同步（条码页改造后唯一性落点缺失） | `validateUnitBarcodes` + `syncUnitBarcodes` 挂到商品保存路径，单位行与 `erp_product_barcode` 双口径一致 |
| P1 | 种子数据商品缺「销售/采购/库存常用单位」，编辑商品被前端必填校验拦截、无法保存 | 数据补齐（`default_*_unit_id` = 基本单位） |
