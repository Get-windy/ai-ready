# ERP价格策略模块性能基准测试

## 概述

本目录包含ERP价格策略模块的性能基准测试框架，用于建立性能基准、监控性能变化和发现性能瓶颈。

## 目录结构

```
performance-tests/
├── README.md                          # 本文档
├── scripts/
│   ├── run-benchmarks.sh              # Linux/Mac执行脚本
│   ├── run-benchmarks.bat             # Windows执行脚本
│   └── setup-test-data.py             # 测试数据生成脚本
├── jmeter/
│   └── api-load-test.jmx              # JMeter API负载测试配置
├── jmh/
│   ├── RuleEngineBenchmark.java       # 规则引擎性能基准测试
│   ├── OptimizationBenchmark.java     # 优化算法性能基准测试
│   └── CacheBenchmark.java           # Redis缓存性能基准测试
├── test-data/                         # 生成的测试数据
└── reports/                           # 测试报告输出目录
```

## 快速开始

### 1. 环境要求

- **Java 11+**: JMH基准测试需要Java 11或更高版本
- **Maven 3.6+**: 用于编译和运行JMH测试
- **Python 3.7+**: 用于生成测试数据（可选）
- **JMeter 5.6+**: 用于API负载测试（可选）

### 2. 运行基准测试

#### Linux/Mac:
```bash
cd performance-tests/scripts
chmod +x run-benchmarks.sh
./run-benchmarks.sh
```

#### Windows:
```bash
cd performance-tests\scripts
run-benchmarks.bat
```

### 3. 手动执行特定测试

#### 生成测试数据:
```bash
python3 scripts/setup-test-data.py --size 1000 --type strategy --output test-data/strategies.json
```

#### 运行JMeter测试:
```bash
jmeter -n -t jmeter/api-load-test.jmx -l reports/jmeter_results.jtl -e -o reports/jmeter_report
```

#### 运行JMH基准测试:
```bash
cd performance-tests
mvn clean compile
mvn exec:java -Dexec.mainClass="cn.aiedge.erp.price.engine.performance.RuleEngineBenchmark"
```

## 性能测试类型

### 1. API负载测试 (JMeter)
- **目标**: 模拟实际业务负载，测试API的并发处理能力
- **场景**:
  - 策略查询接口性能测试
  - 策略创建接口性能测试
  - 混合场景负载测试
- **指标**:
  - 响应时间 (P50, P95, P99)
  - 吞吐量 (TPS)
  - 错误率
  - 资源使用率

### 2. 微基准测试 (JMH)
- **目标**: 精确测量关键组件的性能特征
- **测试组件**:
  - **规则引擎性能**: Drools规则执行效率
  - **优化算法性能**: 遗传算法等优化算法的计算性能
  - **缓存性能**: Redis读/写/并发操作性能
- **指标**:
  - 执行时间 (纳秒/微秒/毫秒)
  - 吞吐量 (操作/秒)
  - 内存使用情况
  - 垃圾回收影响

### 3. 数据生成测试
- **目标**: 生成不同规模的测试数据
- **数据类型**:
  - 价格策略数据
  - 价格计算请求数据
- **规模**:
  - 小规模 (100-1000条)
  - 中规模 (1000-10000条)
  - 大规模 (10000+条)

## 性能基准指标

### API层性能指标
| 指标 | 基准值 | 单位 | 说明 |
|------|--------|------|------|
| 策略查询P95响应时间 | < 100ms | 毫秒 | 95%的请求响应时间 |
| 策略创建P95响应时间 | < 200ms | 毫秒 | 创建操作的响应时间 |
| 策略查询吞吐量 | > 500 TPS | 事务/秒 | 每秒处理的查询请求数 |
| 策略创建吞吐量 | > 200 TPS | 事务/秒 | 每秒处理的创建请求数 |
| API错误率 | < 0.1% | 百分比 | 请求失败的比例 |

### 规则引擎性能指标
| 指标 | 基准值 | 单位 | 说明 |
|------|--------|------|------|
| 单规则执行时间 | < 5ms | 毫秒 | 单个规则的平均执行时间 |
| 多规则并发吞吐量 | > 1000 TPS | 事务/秒 | 并发规则执行能力 |
| 规则引擎内存使用 | < 512MB | 兆字节 | 规则引擎运行时的内存占用 |
| 规则加载时间 | < 5s | 秒 | 规则库加载到引擎的时间 |

### 优化算法性能指标
| 指标 | 基准值 | 单位 | 说明 |
|------|--------|------|------|
| 100条数据优化时间 | < 100ms | 毫秒 | 小数据集的优化计算时间 |
| 1000条数据优化时间 | < 1000ms | 毫秒 | 中等数据集的优化计算时间 |
| 10000条数据优化时间 | < 10s | 秒 | 大数据集的优化计算时间 |
| 并发优化性能提升 | > 2x | 倍数 | 多线程优化相比单线程的性能提升 |

### 缓存性能指标
| 指标 | 基准值 | 单位 | 说明 |
|------|--------|------|------|
| 缓存读取延迟 | < 1ms | 毫秒 | Redis读取操作的平均延迟 |
| 缓存写入延迟 | < 2ms | 毫秒 | Redis写入操作的平均延迟 |
| 批量读取吞吐量 | > 5000 OPS | 操作/秒 | 管道批量读取的性能 |
| 缓存命中率 | > 95% | 百分比 | 缓存读取的成功率 |
| 并发访问性能 | > 10000 OPS | 操作/秒 | 高并发下的缓存性能 |

## 测试执行流程

1. **环境准备**
   - 安装必要的软件和依赖
   - 配置测试环境参数
   - 准备测试数据库和缓存

2. **数据生成**
   - 生成基准测试数据
   - 验证数据质量和规模
   - 导入测试数据到系统

3. **性能测试执行**
   - 运行JMeter API负载测试
   - 执行JMH微基准测试
   - 收集性能指标数据

4. **结果分析**
   - 分析性能测试结果
   - 识别性能瓶颈
   - 生成性能测试报告

5. **基准建立**
   - 建立性能基准线
   - 制定性能优化目标
   - 规划后续监控机制

## 测试报告

测试执行后会在`reports/`目录下生成以下报告：

1. **JMeter测试报告**: HTML格式的详细API性能报告
2. **JMH基准测试结果**: 控制台输出的微基准测试结果
3. **性能综合报告**: Markdown格式的综合性能分析报告
4. **原始测试数据**: 原始的JTL和日志文件

## 自定义配置

### 调整测试规模

修改`scripts/setup-test-data.py`的参数：
```python
# 调整数据规模
python3 setup-test-data.py --size 5000 --type strategy
```

### 修改JMeter测试参数

编辑`jmeter/api-load-test.jmx`文件：
- 调整并发用户数
- 修改请求参数
- 配置测试持续时间

### 自定义JMH测试参数

在JMH基准测试类中调整注解参数：
```java
@Warmup(iterations = 5, time = 1)     // 预热迭代次数和时间
@Measurement(iterations = 10, time = 2) // 测量迭代次数和时间
@Fork(3)                              // 测试进程数
```

## 最佳实践

1. **定期运行测试**: 建议每周或每次重要发布前运行性能测试
2. **监控基准变化**: 跟踪性能指标的变化趋势，及时发现性能退化
3. **与实际业务结合**: 根据实际业务场景调整测试参数和场景
4. **结果存档**: 保存历史测试结果，便于对比分析
5. **自动化集成**: 将性能测试集成到CI/CD流水线中

## 故障排除

### 常见问题

1. **JMeter测试失败**
   - 检查目标服务是否正常运行
   - 验证网络连接和防火墙配置
   - 检查JMeter脚本参数是否正确

2. **JMH测试内存溢出**
   - 增加JVM堆内存：`-Xmx4g -Xms2g`
   - 减少测试数据规模
   - 优化测试代码的内存使用

3. **测试数据生成失败**
   - 检查Python版本和依赖
   - 验证输出目录的写入权限
   - 检查JSON格式的正确性

### 性能优化建议

1. **API层优化**
   - 使用缓存减少数据库访问
   - 优化数据库查询和索引
   - 实施异步处理和批量操作

2. **规则引擎优化**
   - 优化规则逻辑和条件判断
   - 使用规则分组和优先级
   - 实施规则缓存和预编译

3. **算法优化**
   - 优化算法参数和配置
   - 实施并行计算
   - 使用更高效的算法变体
