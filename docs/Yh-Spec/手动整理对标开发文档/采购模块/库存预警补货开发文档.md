## 实现差异说明（2026-08-29 深度复刻）

**实现文件名**：`frontend/apps/pc-admin/src/views/purchase/alert-replenish/index.vue`
**后端接口**：`GET /api/erp/stock/alert-replenish/page`（erp-stock 模块）

### 页面结构（与对标对齐）
- 仅单个页面，无 Tab 标签页，无页面配置按钮（与文档一致）
- 左侧商品分类树（数据源 `erp_product_category`，含"全部商品"虚拟根节点）
- 顶部说明条：`缺货数量 = 库存上限+待发货-账面数量-待收货`，右侧"点击设置"链接跳转预警配置页
- 查询区：全部仓库/指定仓库（单选联动下拉）、商品、品牌、所属供应商、备注、"查询"、`只显示下限预警的商品`复选框
- 工具栏：采购（生成补货建议并跳转智能补货）、刷新、打印(F8)、导出（CSV）
- 表格 25 列 + 列配置弹窗（BillDetailTable 自带个人配置/全局配置 Tab，支持列显隐/排序/宽度/冻结，localStorage 持久化）

### 25 列字段映射（数据源）
| # | 列 | 来源 |
|---|---|---|
| 1 | 仓库编号 | erp_warehouse.warehouse_code |
| 2 | 仓库名称 | COALESCE(erp_stock.warehouse_name, erp_warehouse.warehouse_name) |
| 3 | 商品名称 | COALESCE(erp_stock.product_name, erp_product.product_name) |
| 4 | 货号 | COALESCE(product_code_alias, product_code) |
| 5-7 | 品牌/重量/体积 | erp_product.brand / weight / volume |
| 8 | 口味 | **系统无该字段**，恒为空（列保留，显示名与对标一致） |
| 9,13 | 型号 | erp_product.model（文档第 9、13 列同名"型号"，均取 model） |
| 10 | 预警类型 | 计算：账面≤0 缺货 / <下限 下限预警 / >上限 超储 / 其他 正常 |
| 11-15 | 条码/规格/产地/单位 | erp_product.barcode / spec / origin / COALESCE(stock.unit,product.unit) |
| 16 | 缺货数量 | 库存上限 + 待发货 - 账面库存 - 待收货 |
| 17-18 | 库存上限/下限 | erp_stock.max_stock / min_stock |
| 19 | 备注 | COALESCE(erp_stock.remark, erp_product.remark) |
| 20 | 待发货数量 | erp_sale_outbound_item.pending_quantity 汇总（销售出库未发货） |
| 21 | 账面库存 | erp_stock.quantity |
| 22 | 待收货数量 | erp_purchase_order_item (quantity-received_quantity) 汇总（在途采购，status IN 2,3,5 且未关闭未取消） |
| 23-25 | 最近采购日期/供货商/价 | 该商品+仓库最近一条采购订单明细（ROW_NUMBER 取最新） |

### 业务口径
- **缺货数量**：`max_stock + pending_qty - book_qty - in_transit_qty`（负值表示不缺货）
- **待收货**：采购订单在途，`status IN (2,3,5)`（已审批/已下达/履行中）且 `closed_flag=0`、`cancellation_flag=0`
- **待发货**：销售出库单明细 `pending_quantity`（已售未出库，占用库存）
- **分类过滤**：递归 CTE 取所选分类及其后代分类的商品
- **租户隔离**：Mapper 方法标注 `@InterceptorIgnore(tenantLine="true")` 禁用全局租户行拦截（因 `WITH RECURSIVE` CTE 无法被拦截器正确注入），改在 SQL 内显式用 `CAST(#{tenantId} AS BIGINT)` 过滤所有表，保证租户隔离正确。

### 已知差异
1. **口味字段**：本系统 Product 档案无"口味"属性，该列恒为空（列配置保留，不影响其它列）。
2. **验收口径**：当前开发库 `erp_stock` 仅 1 条记录、`erp_stock_alert_config` 0 条，故实测返回 1 行；接口/查询/分页/过滤逻辑已用 SQL 与 curl 双重验证（多条件筛选均正确返回）。
