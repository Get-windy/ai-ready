## 一、变更背景与目标

本系统菜单通过数据库表 `sys_menu` 动态管理（前端 `dynamicRoutes.ts` 将后端菜单树转换为 Vue Router 路由）。仓储域菜单自 Mega Menu 改造（V1）与菜单聚合改造（V2）后，存在以下问题：

1. **单据入口不统一**：部分仓储单据仍为单入口，且存在"XX管理"非单据命名，与对标系统单据命名不一致。
2. **命名歧义**：库存预警（5031）与预警查询（5017）都叫"库存预警"+ 预警语义混淆；仓储侧"补货管理"与采购侧补货菜单重复。
3. **作业列组碎片化**：收货/上架/拣货/发货/库存 5 个作业列组各自只承载 1 张单据。
4. **重复菜单**：库存作业下的"盘点作业单"与盘点列组下的"库存盘点（盘点单）"功能重复；质检单无独立表单入口。

**目标：** 对齐业务语义与对标命名，统一双入口，合并碎片化作业列组，硬删除研判后的冗余/废弃菜单。

## 二、菜单动态管理机制（背景）

`sys_menu` 关键字段（后端实体 `SysMenu.java`）：

| 字段 | 含义 |
|------|------|
| `id` | 菜单 ID（固定数字编号） |
| `parent_id` | 父级菜单 ID（0 = 顶级） |
| `menu_type` | 0=目录 / 1=菜单 / 2=按钮 |
| `path` / `component` | 路由 / 组件路径（前端 `getComponent` 解析） |
| `display_mode` | 入口模式：0=默认，1=双入口 |
| `list_path` | 双入口模式下列表页（[历史]标签）路由 |
| `tag_label` | 标签文案：历史 / 列表 / 添加 |
| `sort` / `client_type` / `deleted` | 排序 / 客户端类型 / 逻辑删除 |

**双入口渲染逻辑（`dynamicRoutes.ts`）**：

```ts
// 主菜单 → 表单页（component 指向 form），标记 autoCreate 触发新增
if (menu.displayMode === 1) { meta.autoCreate = true }
// 双入口额外注册一条隐藏列表页路由（list_path 指向列表页）
if (menu.displayMode === 1 && menu.listPath) { routes.push({ component: getComponent(menu.listPath) }) }
```

## 三、变更需求梳理（原始要求 + 复核）

- **5.1 双入口转换与命名对齐**：其他入库单、调拨单、报损单、报溢单、盘点单、成本调价单、组装单、拆分单均应为双入口；研判质检单是否应双入口。
- **5.2 作业列组合并**：收货/上架/拣货/发货/库存 5 作业列合并；其下 5 张单据迁入（最终命名「库内作业」）；盘点作业单与盘点单重复需删除。
- **5.3 硬删除**：研判后需删除的菜单项一律物理删除。
- **复核调整（2026-08-30）**：
  - 库存预警(5013) → **预警设置**（消除与预警查询重名歧义）。
  - 补货管理(5012) 与采购模块补货菜单重复，**删除**。
  - 质检单(90201) 落地**简单表单页**并**转双入口**。
  - 拆分单**不采用对标"拆卸单"命名**，沿用**拆分单**。
  - 作业列组命名为**库内作业**（非"收发货作业"）。

## 八、落地方案与执行记录

### 8.1 数据库迁移脚本

Flyway 迁移脚本（幂等设计，覆盖全部仓储变更）：

```
backend/core/api/core-api/src/main/resources/db/migration/V11.49.0__Storage_Menu_Reorg.sql
```

- 版本号：取已执行最高版本（11.48.0）之后一个（**11.49.0**）。
- **幂等策略**：`INSERT ... ON CONFLICT (id) DO NOTHING`；`UPDATE`/`DELETE` 按主键幂等。

### 8.2 数据库生效

- 目标库：`devdb`（PostgreSQL @ localhost:5432）。
- 变更分两批通过事务执行并提交：首批 12 条（列组重组+8 双入口+删除），复核批 5 条（预警设置/删补货/拆分单/库内作业/质检单双入口）。
- 变更前后数据快照备份至 `tool-results/storage_menu_backup_20260830.json`。

### 8.3 生效方式

本变更已在目标库即时生效。后端下次重启时 Flyway 自动执行 `V11.49.0` 并注册；脚本幂等，重复执行安全。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
