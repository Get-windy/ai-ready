## 1. 页面概述

- **运营看板页**：配送业务的全局概览——车辆/配送员规模、任务与单量、人车绑定状态、待处理预警、准时率与配送时长。
- 业界定位：即时配送/TMS 的 **Ops Dashboard**，供调度主管每日盯盘（时效 / 质量 / 运力三维）。
- 页面结构：工具栏（时间范围快捷段 + 页面配置/图表/刷新/自动刷新/导出/全屏）→ 查询条件（运力渠道/订单类型）→ 口径回显条 → **14 张 KPI 卡（可下钻）** → **3 张图表**（单量时效趋势 / 任务状态分布 / 渠道分布）→ 待办区（活跃人车绑定 / 待处理预警）→ 配送员绩效 Top。
- **待办区指标**（金标准 §3.3）：待分配任务、异常任务、超时未签收、待处理核验预警 —— 前两者与「已取消」等状态结构一并由 KPI 卡与状态分布图呈现，后两者走《实名认证》数据源。

## 2. 统计口径（固化 · 各页复用同一统计源）

> 口径在本节固定，避免各页数字打架；页面侧**禁止二次汇总**，全部指标由后端聚合产出。

| 指标 | 口径 |
|------|------|
| 统计区间 | 左闭右开 `[start, end)`；`today` 今日 00:00~24:00、`yesterday` 昨日、`last7` 含今日近 7 日、`last30` 含今日近 30 日、`month` 本月 1 日至今、`custom` 自定义（缺开始日期报错） |
| 单量类 | `count(dms_task)`，按 **`create_time`** 落在区间统计，`deleted = 0` |
| 状态结构 | 待分配 = `0`；已分配/已接单 = `1,2`；**在途 = `3,4`**（取货中/配送中）；已完成 = `5,6`（已签收/已完成）；已取消 = `7`；异常 = `8` |
| 超时未签收 | 状态 `0~4`（未签收）且 `deadline_time < now()` |
| 准时率 | 准时签收量 / 有截止时间的已签收量，即 `completed_time <= deadline_time` 且 `deadline_time`、`completed_time` 均非空（分母为 0 时返回 `null`，前端显示「-」，不显示假 0） |
| 平均配送时长 | `avg(completed_time - pickup_time)`，单位分钟，保留 1 位小数 |
| 配送费 / 代收货款 | 区间内 `sum(delivery_fee)` / `sum(collect_on_delivery)` |
| 在线配送员 | `last_report_time >= now() - 阈值`，阈值取自配送参数 **`dashboard.online.minutes`**（默认 2 分钟，可配 1~120） |
| 活跃配送员 | `status ∈ (1 空闲, 2 忙碌)`；配送员总数 = 租户内未删除全量 |
| 活跃车辆 | `status ∈ (1 使用中, 4 已出勤)` |
| 活跃人车绑定 | `dms_rider_vehicle_binding.status = 0`（绑定中） |
| 待处理预警 | `dms_verification_alert.handle_status = 0`（未处理） |
| 趋势补零 | 按日聚合，缺失日期补 0，保证折线连续；天数由时间范围推导（今日/昨日 → 7 天，近 30 日/本月 → 30 天），可显式传 `days` 覆盖（上限 90） |
| 分布 | 按运力渠道（未指派渠道归入「未分配渠道」）/ 按订单类型（1 销售配送 2 调拨 3 退货） |
| 配送员绩效榜 | 仅列**区间内有单**的配送员（0 单不入榜），按接单量倒序、完成量次之 |
| 待办计数 | 活跃人车绑定 / 待处理预警为**实时快照**，**不随**时间范围与渠道筛选收敛（E2E 已断言该不变性） |

**刷新间隔**：自动刷新间隔由后端返回（**`dashboard.refresh.seconds`**，默认 30 秒，可配 5~600），页面离开即停轮询。

## 3. 后端实现（`cn.aiedge.dms.dashboard`）

| 接口 | 说明 |
|------|------|
| `GET /api/dms/dashboard/stats` | KPI 聚合（运力规模 / 单量结构 / 时效 / 金额 / 待办计数 + 口径回显 + 刷新间隔） |
| `GET /api/dms/dashboard/active-bindings` | 活跃人车绑定（仅绑定中，按绑定时间倒序，分页） |
| `GET /api/dms/dashboard/pending-alerts` | 人车核验预警（默认未处理，级别倒序，分页；可传 `handleStatus`） |
| `GET /api/dms/dashboard/task-summary` | 任务状态分布（9 态全量、区间无数据补 0、含状态名与占比） |
| `GET /api/dms/dashboard/trend` | 单量时效趋势（按日，含单量/完成量/准时量/准时率/平均时长/配送费）；`custom` 区间直接取该区间（避免「统计区间是历史月份、趋势却是近 30 天」的口径错位），其余按 `days`/range 推导，缺失日期补 0，上限 90 天 |
| `GET /api/dms/dashboard/top-riders` | 配送员绩效 Top（接单量/完成量/准时率/平均时长/评分，默认 10 上限 50） |
| `GET /api/dms/dashboard/distribution` | 任务分布（`by=channel` 按渠道 / `by=orderType` 按订单类型） |

- 公共查询参数：`range`、`startDate`/`endDate`（custom）、`channelId`、`orderType` —— **筛选对全部接口一致生效**（运力类指标为全量口径，不随渠道/订单类型收敛，已在文档与 E2E 中固化）。
- 实现文件：
  - `dashboard/controller/DashboardController.java`、`dashboard/service/DashboardService.java`
  - `dashboard/mapper/DashboardMapper.java`（`@Select` 条件聚合，全部 SQL 显式带 `deleted = 0` 与 `tenant_id`）
  - `dashboard/dto/`：`DashboardStatsVO` / `TaskAggVO` / `CapacityAggVO` / `TrendPointVO` / `TopRiderVO` / `TaskSummaryItemVO` / `DistributionItemVO`
- **无新增表、无迁移**：全部复用 DMS 既有表（`dms_task` / `dms_rider` / `dms_vehicle` / `dms_rider_vehicle_binding` / `dms_verification_alert` / `dms_channel` / `dms_config`）。
- 权限：类级 `@SaCheckLogin`（看板为只读聚合，未引入权限码，避免菜单未配权限导致 403）。

## 4. 前端实现

- **页面骨架**：`ErrorBoundary` > `PageContainer(full-height)` > `CategoryListLayout`（`show-category-panel=false`，看板不适用分类树）+ `#toolbar-left/#toolbar-right/#search-fields/#table` 插槽。
- **页面配置**（`PageConfigPanel`，`storage-key=dms-dashboard-page-config`，无打印配置 Tab）：
  - 查询条件（3）：时间范围、运力渠道、订单类型 —— 勾选真实控制查询区渲染；
  - 功能按钮（5）：图表显示切换、刷新、自动刷新、导出、全屏 —— 勾选真实控制工具栏按钮显隐。
- **图表**：复用通用组件 `ARReportChart`（echarts）；趋势为「单量/完成量柱 + 准时率折线（双 Y 轴）」，状态分布与渠道分布为环形饼图；点击**状态饼图扇区**下钻到调度任务按该状态过滤。
- **卡片下钻**（`ARStatCards` 新增 `clickable` + `card-click`，全站通用增强）：

  | 卡片 | 目标页 | 携带条件 |
  |------|--------|---------|
  | 配送单量 | `dispatch/query` | `createTimeStart/createTimeEnd`（当前区间） |
  | 待分配任务 | `dms/dispatch-task` | `status=0` |
  | 在途任务 | `dispatch/query` | `status=DELIVERING` + 区间 |
  | 已完成 | `dispatch/query` | `status=DELIVERED` + 区间 |
  | 异常任务 | `dms/dispatch-task` | `status=8` |
  | 超时未签收 | `dispatch/query` | `status=PENDING,DELIVERING` + 区间（多值以逗号分隔） |
  | 配送费 | `dms/settlement` | — |
  | 代收货款 | `dms/payment` | — |
  | 在线配送员 | `dms/rider` | — |
  | 活跃车辆 | `dms/vehicle` | — |
  | 活跃人车绑定 | `dms/verification` | `tab=binding` |
  | 待处理预警 | `dms/verification` | `tab=alert&handleStatus=0` |
  | 准时率 / 平均配送时长 | 不可下钻（无对应台账） | — |

- **下钻落地闭环**（目标页真实消费 query，非空跳）：
  - `ARReportPage` 新增 `initialQuery` prop（挂载写入查询模型，全站复用）→ `dms/dispatch-task` 消费 `status`；
  - `dispatch/query` 消费 `status`（三值 PENDING/DELIVERING/DELIVERED，**支持逗号分隔多值**）与 `createTimeStart/End`；
  - `dms/verification` 消费 `tab`（binding/alert/inspection）与 `handleStatus`。
- **去硬编码**：预警类型/级别、绑定状态字典集中到 `views/dms/shared.ts`（`DMS_ALERT_TYPE` / `DMS_ALERT_LEVEL` / `DMS_BINDING_STATUS`，与后端枚举一一对应）；页面内不再内联字典。
  - 修复原页面的字典口径错误：绑定状态「0=绑定中」（原页面写成 `status===1` 为绑定中）、预警类型由 3 种补齐为 6 种、级别由「低/中/高」更正为后端「提示/警告/严重」。
- **占位符清零**：KPI 初值不再是 `'-'`；无数据显示「-」（如无样本的准时率）由后端 `null` 驱动。
- **数值归一化**：后端全局 Jackson 将 `Long` 序列化为字符串（防 JS 精度丢失），`api/dms/dashboard.ts` 在入口统一把计数/金额类字段转 `number`，ID 类字段保持字符串（雪花 ID 不转 number，避免精度丢失）。
- **导出**：真实 xlsx，5 个 Sheet（KPI / 单量时效趋势 / 任务状态分布 / 渠道分布 / 配送员绩效）。
- **自动刷新**：默认开启，间隔读后端 `refreshSeconds`，倒计时显示在按钮上；支持一键关闭；页面卸载清理定时器与键盘监听（F5 刷新）。

## 5. 端到端验收

- **E2E 脚本**：`tools/e2e-dms-dashboard.cjs`（API + UI 双验收，**149/149 通过**）
- **2026-09-13 独立复验**（另起实例、按同种子重跑）修复 2 处**真实缺陷**，均为「样本无关」的硬缺陷，非脚本期望值问题：
  1. **后端 NPE → 订单类型分布整页 500**：`dms_task.order_type` 可空，聚合出的行 `item_key = NULL`，`DashboardService` 用 `Map.of(...).getOrDefault(null, ...)`（**JDK 不可变 Map 对 null key 取 hash 直接 NPE**）→ `GET /dms/dashboard/distribution?by=orderType` 500，且 `%` 分布图与「销售配送单量」断言连带失败。修法：Mapper `COALESCE(order_type, -1)` + Service 新增 `orderTypeName()`（`-1`/空/非数字 → **「未指定」**，未登记编码 → 「其他」）。E2E 期望值改为同口径 `COALESCE(order_type, -1)`，并新增回归守卫「未填订单类型归入「未指定」（null 键不崩）」。
  2. **前端图标名不存在 → 调度任务页白屏（连带本页两处下钻失效）**：`views/dms/dispatch-task/index.vue` 从 `@ant-design/icons-vue` 导入 **`AlarmOutlined`**，而已装 **v7.0.1 无此导出** → 该路由动态 `import()` 抛 `SyntaxError` → vue-router 中止导航（URL 不变、页面空白），仪表盘「待分配任务 / 异常任务」下钻 `/dms/dispatch-task` 全部失效。修法：改用同语义且存在的 `ClockCircleOutlined`。**全量扫描已确认这是全前端唯一一处**（433 处 icons-vue 导入 / 2512 个图标名，见 `tools/audit-icons-vue.cjs`）。
- **测试数据**：`tools/e2e-dms-dashboard-seed.sql`（覆盖 4 种配送员状态、4 种车辆状态、9 种任务状态 + 准时/超时样本、人车绑定、核验预警、收款；幂等，按 ID 段清理）
- **验收账号**：`tools/e2e-dms-dashboard-user.sql`（`e2e_dmsdash`，避免与并行会话共用 admin 被 sa-token 互踢）

## 6. 依赖前置与部署注意

- 本页依赖 **DMS 模块的 `dashboard` 包进入运行中的 fat jar**。《配送模块 README》§1.2 记录的「运行 jar 未包含 DMS 模块」问题已于 2026-09-12 修复。
- ✅ `dms-delivery-0.3.18.jar`（含 16 个 `cn.aiedge.dms.dashboard.*` 类）已 `install` 进本地 m2，**重打 core-api fat jar 即会带上本页接口**。
- ⚠️ 打包/重启前需确认 core-api 迁移无**同版本冲突**：2026-09-12 并行开发期间曾出现三个会话同时占用 `V11.171.0` 导致 fat jar 启动即失败（Flyway "Found more than one migration with version 11.171.0"），后由各会话改名避让至 `V11.175.0` / `V11.176.0`。**新增迁移前先 `ls db/migration | grep V11.17` 避让版本号**。
- 后续若再改 DMS 代码：`mvn -pl dms clean install -DskipTests` → 重新 `package` core-api → **重启后端**。
- 共享环境运行中的 fat jar 会被并行会话占用，本次验收采用**独立副本**方案：复制 fat jar → 用 `jar u0f` 以 STORED 方式替换嵌套的 `dms-delivery` jar（同名覆盖，避免双 jar 类冲突）→ 以独立端口启动，不影响他人实例（本次为 5677 端口，验收后已关闭并清理副本）。

## 8. 开发原则（通用）

- **页面组件优先复用**：复用 `CategoryListLayout` / `ARStatCards` / `ARReportChart` / `PageConfigPanel`，仅对 `ARStatCards`（下钻）与 `ARReportPage`（`initialQuery`）做向后兼容的通用增强。

- **阶段结束前回写开发文档**：本节「待完善」与状态随代码实现同步更新。
- **【金标准】模块级 E2E** 放 `tools/e2e-<模块>.cjs`；**【金标准】启动进程随手关**（见 `AI_DEVELOPER_RULES.md` 7.3）。
