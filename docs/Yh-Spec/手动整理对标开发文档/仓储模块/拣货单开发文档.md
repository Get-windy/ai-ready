## 页面概述

拣货单用于仓库拣货作业（销售出库/退货出库/调拨出库等场景），可由销售订单/波次自动生成拣货任务，或 PC 端手工录入。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 拣货单列表页 | `wh/picking-order/index`（list_path 别名 `wms/pick`） | 双入口「历史」标签 |
| 新增/编辑拣货单表单页 | `wh/picking-order/form` | 编辑模式为新增模式加 id |

### 配置功能说明（每个页面都有）

## 新增编辑拣货单表单页配置

### 页面结构（设计值）

`PageContainer` 三段自建面板：**单据头** → **作业明细** → **最近拣货单列表**。

### 单据头字段

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 单号 | a-input | 是 | taskNo，前端 `genTaskNo('PK')` 预填，可修改 |
| 拣货仓库 | a-select | **是** | warehouseId，`warehouseApi.listAll()`，联动加载货位 |
| 来源类型 | a-select | 否 | 销售出库 0 / 调拨出库 1 / 其他出库 2（⚠️ 与列表页字典不一致） |
| 来源单号 | a-input | 否 | sourceOrderNo |
| 客户 | a-input | 否 | customerName（自由文本，无客户主数据选择器） |
| 期望发货时间 | a-date-picker | 否 | expectShipTime，带时间，`YYYY-MM-DDTHH:mm:ss` |
| 优先级 | a-select | 否 | 普通 0 / 紧急 1 / 加急 2 |
| 备注 | a-input | 否 | remark |

### 工作流按钮

| 状态 | 按钮 | 动作 |
|------|------|------|
| 任意 | 保存单据 / 保存修改 | `pickApi.taskSave` / `taskUpdate` |
| 任意 | 新建 | 重置表单 |
| status=0 | 开始拣货 | `pickApi.taskStart(id, userId, userName)` |
| status=1 | 完成拣货（popconfirm） | `pickApi.taskComplete(id)`（不带用户参数） |
| status=0/1 | 取消（popconfirm） | `pickApi.taskCancel(id, reason)` |

### 作业明细表格

明细仅**待拣货（status=0）**可编辑，保存为**整体替换**（`pickApi.saveDetails`，先删后插）。

**编辑态列**：行号、商品（a-select）、规格、单位、拣货货位（a-select）、应拣数量（a-input-number）、批次号、操作（删除）。

**只读态列**：行号、商品编码、商品名称、规格、单位、拣货货位编码、应拣数量、已拣数量、缺货数量、批次号、状态。

> 明细保存校验：明细非空、每行必选商品、应拣数量 > 0。

### 最近拣货单列表（表单页底部）

列：单号、来源类型、来源单号、仓库、客户、进度（拣/总）、状态、创建时间、操作（载入 / 开始 status=0 / 完成 status=1）。

## 业务规范说明

- 波次 → 拣货 → 发货：拣货任务可由销售订单/波次自动生成（`pickApi.waveCreate` 生成 `WmsPickWave`），或 PC 段手工录入；拣货完成后进入发货/出库环节。
- 来源类型：销售出库/退货出库/调拨出库/盘亏出库。
- 明细状态：待拣货 0 → 已拣货 1 / 缺货 2；拣货完成前可编辑，完成后只读。
- 缺货处理：`detailShortage`（PDA 标记缺货）写缺货数量并回算已拣 = 应拣 − 缺货。
- 单号前缀 `PK`，前端 `genTaskNo` 生成（`PK-yyyyMMddHHmmss`），后端 `taskSave` 原样落库；**后端无 next-no / 序列号自动生成**。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），仓储模块无拣货页，本页为设计新增。

### 页面对齐（已建成 · 金标准）
- **列表页**：`ErrorBoundary` + `PageContainer(full-height)` + `CategoryListLayout`，双Tab「按单据/按明细」，`BillTableList` 渲染；列配置弹窗（`ColumnConfigPanel` + `useColumnConfig`，两组列持久化）、页面配置弹窗（`PageConfigPanel`，localStorage）、快捷日期；行内 查看/编辑/开始拣货/完成拣货/取消/删除（按状态显隐）。新增跳 `/wh/picking-order/form`，查看/编辑跳 `/wh/picking-order/form?id=`。
- **表单页**：`BillFormPage` + `BillDetailTable`（列配置持久化 `picking-order-form-columns`、`viewMode` 锁定态）+ `useBillForm`（`codeApiPath=/wms/pick/next-no` 真实编号、api.create/update 组合 taskSave+detail/save、getById 组合 taskGetById+detailList）+ 配置3Tab弹窗（页面配置/录单默认值/打印设置，**走 `userPageConfigApi` 服务端共享**，2026-09-06 由 localStorage 迁移）+ 按状态动态 header 操作（开始/完成/取消）。基础组件能力详见 `components/BillFormPage/*`，**改造或使用前请先读基础组件代码**，勿重复开发（遵"功能/模块不重复开发"）。
- **工作流**：保存/开始/完成/取消接通真实 API；明细整体替换（`/wms/pick/detail/save`），仅待拣货可编辑。

### 跨模块落实（2026-09-02 · 按最终裁决）
- **P0（红线）**：拣货**前冻结**（`startPick freeze(应拣量)`）+ 拣货**确认统一扣减**（`completePick`：先 `unfreeze(应拣量)` 释放，再 `decrease(实拣量)` 镜像 erp_stock，仅一次，**禁双扣**）；`cancelTask` 只 `unfreeze` 不扣。注：`decrease` 镜像 erp_stock，故销售域 `ship` 不得再扣 erp_stock（销售域配合，统一单一路径）。
- **P2**：`saveDetails` 校验商品必选+应拣量>0；`markShortage` 缺货红线（缺货≤应拣）；`serialNo` 已暴露（可选）。注：批次/序列**强制**校验依赖商品主数据批次/序列管控标志（跨模块），待 ERP 侧提供后开启。
- **P1（延后）**：`createWave`（查销售订单→生成波次/任务/明细，明细带 locationId）延后下迭代；前端销售订单选择器**不做**，来源单号/客户保持自由文本；wave 页传参对齐延后。模块边界：WMS 不依赖 erp-sales，跨模块走 HTTP。

### 明细表格金标准对齐（2026-09-06）
本页明细列已统一采用 `BillDetailTable` 原生单元格：商品 `searchable`(SearchSelect 搜索下拉)、货位数量/文本 `input`/`number`，**不再用 `type:'slot'` 内嵌 `a-select`**；新建时 `onMounted` 生成 **20 行**，`min-rows` 沿用组件默认 **20**（`components/BillFormPage/BillDetailTable/index.vue` `minRows:20`，仅确需改变才传 `:min-rows` 并注释原因）。`BillDetailTable` 默认项（`minRows=20`、默认 `input` 原生单元格）已在组件 `types.ts`/`index.vue` 注释说明。

### 跨模块检查问题（P0→P2 · 本页负责区域）

> 来源：《跨模块关系检查报告.md》。由拣货单负责人修复本页相关项。

| 级别 | 问题 | 修复要点 |

### 最终裁决方案（2026-09-02 · 严格按此执行）

> 档案级决策。与《发货单最终裁决》一致，本页按同口径执行。

- **P0 冻结+扣减（红线）**：拣货**前冻结**可用库存（`InventoryService.freeze`），拣货确认**统一扣减**（`InventoryService.decrease`）。**禁两条扣减链路**（WMS 拣货与 ERP 销售域不得重复扣 `erp_stock`）。
- **P1（本次隐藏 · 延后）**：拣货任务数据源 → 调 **WMS 自身拣货任务 API**（`/api/wms/pick/task/*`）；销售出库单 → 调 **ERP 出库单查询 API**；客户主数据复用 **`md-customer.ts`**(前端)；波次生单（`createWave`）延后至下一迭代。
- **P2（本次做）**：批次/序列号强制校验；缺货基于 `wms_inventory.available` 引擎级校验。
- **模块边界**：WMS 不直接依赖 erp-sales；跨模块缺接口 → 提需 ERP 侧暴露 REST API，WMS 只 HTTP 调用。
- **执行范围**：先 P0+P2 开工稳定；P1 前端入口先隐藏，不阻塞本次发版。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
