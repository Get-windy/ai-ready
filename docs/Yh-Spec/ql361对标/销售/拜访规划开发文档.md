## 页面配置

### 查询条件

按抓取 JSON 实据（filters / filterLabels / bodyPreview）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止，与快捷段联动）
- 筛选条件：请输入计划名称/编号（模糊匹配计划名称或计划编号）
- 职员（弹窗选择）
- 创建人（弹窗选择）
- 计划类型（下拉，默认"全部"）
- 计划状态（下拉，默认"全部"）

### 功能按钮

按抓取 JSON buttons 实据：刷新、新增、打印(F8)、导出、查询、跳转（分页跳转）

### 打印配置

无（抓取数据未覆盖打印配置弹窗；页面有打印(F8)按钮，打印模板配置细节待复核）

## 业务规范说明

### 状态流转与特殊交互

- 拜访计划存在"计划状态"字段（查询条件下拉与表格列均有），具体状态枚举（如未开始/进行中/已结束/已停用）待复核
- "计划类型"与"循环拜访周期"两列表明计划支持循环拜访（按周期自动生成拜访任务），类型枚举待复核
- 查询方案可保存复用，时间快捷段与日期范围联动（选快捷段自动填充起止日期）
- 左侧部门树作为表格数据的过滤维度（按所属部门筛选职员）

### 与其他页面关系

- 外勤拜访三步流程入口：**1.拜访规划**（本页，定计划）→ 2.拜访执行（职员轨迹/职员定位，地图页）→ 3.拜访检视（拜访统计/拜访记录等，统计分析页）
- 子标签"拜访设置 / 拜访线路 / 任务列表"与本页同域：拜访线路维护线路-客户绑定，任务列表承载由计划生成的拜访任务（抓取未覆盖这两页，待复核）
- 拜访计划是"拜访检视"中"计划内拜访"统计口径的数据来源

### 客户与职员来源

- 客户来源通过 ERP 模块的往来单位下的客户分类处理，而非 CRM 模块的客户信息。CRM客户是公海客户，ERP客户是实体客户。
- 职员、部门来源于 core-base 的组织架构（SysDept / User），与系统权限体系打通。

### 架构师红线（Ponytail六步过滤网）

动手前必过六关：①此功能业务真需要？②标准库/原生API能搞定？③现有依赖能否复用？④能否一行代码干净解决？⑤能否复用已有组件？⑥通通走不通才写最小可用闭环。**Lazy, not negligent**——跨边界防注入、容灾、安全防御代码不准省。

### 业务逻辑要求

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑和交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。

- 没有桩（Stub）与模拟（Mock）数据：代码中不得出现 TODO、FIXME、stub、模拟、mock、假数据、临时、演示、示例、占位、placeholder，确保使用真实数据
