## 1. 页面概述

「我的已办」的**设计意图**是展示**我处理过的任务**（含已处理与已转交），支持查看只读详情。

**但当前实现的落点与菜单语义相反**：本菜单与 803「我的待办」**归一化后指向同一组件**（`dynamicRoutes.ts:922` 的归一化规则去掉 `views/` 前缀与 `.vue` 后缀），而该组件**完全不读路由**（`useRoute` / `useRouter` / `route.` / `$route` / `query.` / `defineProps` **命中 0 次**），Tab 初值**硬编码** `const activeTab = ref('todo')`（`task-management.vue:508`）→ **从「我的已办」菜单进入，页面停在「待办任务」Tab，显示的是待办数据**。用户必须**手动点第二个 Tab** 才能看到已办记录。

### 1.1 与 803「我的待办」的关系（**本文档的核心，必须写透**）

| 组件是否读路由 | **否** —— `useRoute`/`useRouter`/`route.`/`$route`/`query.`/`defineProps` **命中 0** | `task-management.vue` 全文 |
| 组件内区分机制 | **只有页内 `a-tabs` 手动点击**（`:99-111`），Tab 值 `todo`/`done` | 同左 |
| **Tab 初值** | **硬编码 `const activeTab = ref('todo')`（`:508`）** | 同左 |
| 后端区分 | 请求参数 `tab`（`:614`）→ `WorkflowServiceImpl.java:644-647` | 同左 |
| **804 的实际落点** | **`tab = 'todo'` → 显示「待办任务」**，与菜单名「我的已办」**相反** | 组合结论 |
| 顺带发现 | 804 的 `component` 带 `.vue` 后缀，**与全站写法不一致**（README §7.3 已登记为 P2）；但**正是归一化把这个后缀差异吃掉了**，才造成"同一 key" | devdb 实测 |

**现象**：点「设置 → 审批 → 我的已办」→ 页头显示「任务管理」→ **默认高亮「待办任务」Tab** → 看到的是**待办数据**（默认会话下 **1 行**），而不是已办数据（**13 行**）。
**影响**：① 菜单语义与落点相反，**用户不手动点第二个 Tab 就永远看不到已办**；② 同一份数据被两个菜单指向，**无法判断用户到底想看哪个**；③ 由于「审批」「转办/委托」两个按钮带 `v-if="activeTab === 'todo'"`（`:211,219`），用户从「已办」菜单进来后**看到的是可操作的行**，进一步强化了错误认知。

**修法建议（推荐第 ① 条，最小改动）**：
```
// task-management.vue:508 附近
- const activeTab = ref('todo')
+ const route = useRoute()
+ const DEFAULT_TAB = route.name === 'MyDone' || route.path.includes('/workflow/done') ? 'done' : 'todo'
+ const activeTab = ref<'todo' | 'done'>(DEFAULT_TAB)
```
- ① **读路由决定初值**（如上；804 的 `route.name` / `route.path` 取值须在实现时用 `console.log(route.name)` 现场确认 —— 本文档**未实测** `route.name` 的确切字符串，**不编造**）；
- ② 或**改菜单指向**（把 804 的 `component` 改为一个薄壳组件，进入后 `activeTab = 'done'`）—— 但**仍需组件读路由**才能区分；
- ③ 或**合并两个菜单**为一个（页内 Tab 已能覆盖两种视图）—— 改动最小但会失去"两个入口"；
- 无论哪种，**必须同时补 `storageKey`**，否则用户手点的 Tab 在刷新 / 切菜单后仍会丢失。

### 1.2 本页不提供的能力（如实登记）

**已办台账没有「处理时间 / 审批结果 / 审批意见」三列**（后端返回了结果与意见、未返回处理时间，前端一个都没渲染，见 §5.7）｜**详情抽屉也没有这三项**｜**已办 Tab 无任何写操作**（`审批`、`转办/委托` 被 `v-if="activeTab === 'todo'"` 隐藏，仅剩「查看详情」）｜无**批量导出**｜无**按审批结果筛选**（无此查询项）｜无**审批意见检索**｜无**撤回我审批过的单据**｜无**我的发起**（`GET /my-applications` 后端有、无入口）｜无**催办 / 提醒**。

### 3.2 页内 Tab（**804 落点错误的直接现场**）

`a-tabs v-model:active-key="activeTab" @change="handleTabChange"`（`:99-102`）：

| Tab 名 | value | 行 | 从 804 进入时的可见性 |
|--------|:-----:|----|---------------------|
| 待办任务 | `todo` | `:103-106` | 🔴 **默认高亮（错误落点）** |
| 已办任务 | `done` | `:107-110` | 需**手动点击**才可见 |

- **默认值 `const activeTab = ref('todo')`（`:508`）** —— 硬编码，**不读路由、不读 storage**；
- 切换 `handleTabChange`（`:602-605`）：`pagination.current = 1` 后 `handleQuery()`；Tab 值作为请求参数 `tab`（`:614`）下发；
- 后端已办判定：`if ("done".equals(tab))` → `status IN (TASK_STATUS_DONE(1), TASK_STATUS_TRANSFERRED(2))`，否则 `status = TASK_STATUS_PENDING(0)`（`WorkflowServiceImpl.java:644-651`）；
- **Tab 状态不持久化** → 刷新 / 切菜单后**回到 `todo`**（即从 804 菜单每次进来都是待办）。

### 5.3 已办记录为什么会有 `submit` / `intervene`？

- `ACTION_SUBMIT(4)`：**提交动作也会写成一条任务记录**（12 行）→ 已办台账里混入了"我提交的单"这类记录；
- `ACTION_INTERVENE(7)`：**流程干预（终止/挂起/恢复）也会写成任务记录**（4 行，来源见《流程实例开发文档》§7.3 的 `insertRecordTask(..., ACTION_INTERVENE, ...)`，`WorkflowServiceImpl.java:790-791`）。
→ **已办台账不是纯粹的"审批结论流水"**，而是"与该用户相关的任务动作流水"（含提交与干预）。**这一点必须在界面上用「动作」列区分**，否则用户会误读（P1：当前无「动作」列）。

### 9.2 P0-① 专段：一组件多菜单（**现象 + 证据 + 修法**）

**现象（用户可见）**
