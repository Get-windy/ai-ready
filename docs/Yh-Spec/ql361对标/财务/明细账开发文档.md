## 页面配置

### 查询条件

按抓取 JSON filterLabels 实据（科目*、核算单位、核算部门、核算职员、经手人、部门）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止）、日期类型（单据日期）、科目*（必填，可点选左侧科目树带入）
- 核算单位、核算部门、核算职员（辅助核算三维度）、经手人、部门
- 对账标记（全部）、摘要、单据备注
- 勾选项：显示红冲

### 功能按钮

按抓取 JSON buttons 实据：刷新、打印(F8)、导出、查询、跳转（分页跳转）

### 打印配置

无（抓取数据未覆盖打印配置弹窗；有打印(F8)按钮，打印模板配置细节待复核）

## 表格列配置

### 默认显示列（抓取 JSON columns 实据，15 列）

对账标记、记账日期、单据日期、单据编号、单据类型、摘要、核算单位、核算部门、核算职员、借方发生额、贷方发生额、期末余额、经手人、部门、单据备注

> JSON columns 首项"对账标记 记账日期 单据日期 单据编号"为抓取拼接串（前四列表头拼接），已剔除，不计入列数。

### 特殊行与标记（截图实据）

- 此前余额行：表格首行（黄色高亮），显示查询起始日前的科目余额
- 显示红冲：勾选后红冲分录纳入查询（红冲=红字冲销凭证分录）
- 对账标记列：可点击标记（银行对账场景逐笔勾对）

## 业务规范说明

### 数据来源与取数逻辑

- 数据源自会计凭证分录：按科目逐笔列出借/贷发生额，期末余额随每笔滚动
- 摘要实据证明凭证自动生成链：业务单据（收款单 SKD-/提现存现转款单 YHZKD- 等）记账 → 生成会计凭证（KJPZ-）→ 摘要回写"由[单据类型 单号]…"→ 本页按科目呈现
- 核算单位/核算部门/核算职员：辅助核算三维度过滤（对应会计科目主数据"核算项"设置）
- 科目* 必填：明细账必须指定科目（点选左树或输入），防止全量流水无边界查询

### 与其他页面关系

- 上游：《会计凭证开发文档》（分录来源）
- 汇总视图：《总账开发文档》（同科目按期汇总）；《科目余额表开发文档》《辅助核算余额表开发文档》
- 联查：单据编号链接穿透至会计凭证；凭证"源单"再穿透至业务单据
- 本系统前端目录 `finance/detail-ledger`（dynamicRoutes.ts 实据）

### 架构师红线（Ponytail六步过滤网）

动手前必过六关：①此功能业务真需要？②标准库/原生API能搞定？③现有依赖能否复用？④能否一行代码干净解决？⑤能否复用已有组件？⑥通通走不通才写最小可用闭环。**Lazy, not negligent**——跨边界防注入、容灾、安全防御代码不准省。

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑和交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。

- 没有桩（Stub）与模拟（Mock）数据：代码中不得出现 TODO、FIXME、stub、模拟、mock、假数据、临时、演示、示例、占位、placeholder，确保使用真实数据

- 查询条件（含辅助核算三维度、摘要/单据备注模糊、对账标记、显示红冲）真实过滤；查询方案可保存
- 15 个默认列真实渲染；此前余额行正确；期末余额逐笔滚动计算正确；合计行与分页正确
- 单据编号链接穿透至会计凭证；红冲分录按勾选显示/隐藏
- 打印(F8)、导出真实可用
