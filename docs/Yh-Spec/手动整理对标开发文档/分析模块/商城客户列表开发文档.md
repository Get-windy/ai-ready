## 4. 业务规范

### 统计口径（客户行为）

- **行为口径与《交易分析》对齐**：`访问次数` 对应《交易分析》的「登录客户数」底数，`成交数量` 对应「下单笔数」底数；《交易分析》按日期汇总，本页按客户明细展开。
- **停用客户**：默认不显示，勾选 `显示停用` 后纳入（实测勾选项）；`status` 语义为「正常/禁用」（本系统映射，见第 5 节）。
- **触达动作**：`发短信` / `发优惠券` 是**对勾选客户的批量营销动作**，动作发生后回流商城侧触达记录。

### 与营销模块的上下游关系（**取数关系，必须写清**）

- **上游 = 资料模块 + 商城注册数据**：
  - 客户级别 / 联系人 / 联系电话 / 联系地址 / 所属仓库 / 默认经手人 ← **资料模块「往来单位→客户」主数据**；
  - 买家账号 / 最后登录时间 / 注册时间 ← **商城用户注册与登录**数据；
  - 访问次数 / 成交数量 ← **商城访问埋点 + 商城订单**。
- **下游 = 《营销模块》触达动作**：本页的 `发短信`（← 《营销模块》发短信页）与 `发优惠券`（← 《营销模块》优惠券页）是**营销模块能力在本页的入口复用**；本页负责「选人」，营销模块负责「配置与发送内容」，发送后进入《营销推广分析》的推广客户列表口径。
- **同源页**：《交易分析》（商城整体转化口径）、《客户活跃分析》（ERP 侧活跃口径）、《商城客户列表》为客户端明细。
- **与《营销推广分析》推广客户列表的分工**：本页是**全量商城客户名册**（1149 条），推广客户列表只含**被推广触达过**的客户（本次实测 0 条）。

### 本系统对应关系

- 本系统当前取数自 `/erp/mall/admin/user/page`（商城后台用户分页，见第 5 节），**字段模型与对标不等价**（无访问次数/成交数量/成交率/所属仓库/所属分类树；多出审核状态/来源/昵称等）。

- **取数端点**：`GET /erp/mall/admin/user/page`（`shopUserApi.page`：`pageNum/pageSize/keyword/createTimeStart/createTimeEnd/gradeId/showDisabled/categoryId`）；行键 `U:<username|id>`（雪花 ID 按字符串透传）。

### 剩余缺口（按本页自身规格＝统计报表页逐项判定）

1. **3 个对标列无数据源、不渲染**：访问次数、成交数量、成交率(%) —— 全库无商城访问 / 浏览埋点表，`shop_user` 亦无访问与成交计数字段，`/erp/mall/admin/user/page` 只返回账号与主数据字段。为禁返回 0 / 占位假值，这 3 列**不渲染**（13 列 → 10 列）。

3. **首列勾选框 + 批量「发短信 / 发优惠券」未接**：后端无「对客户发触达」端点（`smsApi` 只有配置 / 测试，无发送），故不放勾选框与按钮，避免死入口。
4. **分类过滤生效性未确证**：dev 库 `shop_user` 无数据（`/erp/mall/admin/user/page` 实测 `total=0`），加 `categoryId=999999` 仍为 0，**无法用对照法判定 `categoryId` 是否被后端识别** —— 缺数据，未确证。
5. **无合计行**：对标是否有合计未确证；本页无。
6. **查询方案为占位**：`queryScheme` 未被任何请求使用。
