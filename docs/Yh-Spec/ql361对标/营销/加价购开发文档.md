## 1. 页面概述

- **列表页**：购主商品后加价换购指定商品的连带销售规则维护页，查询区 + 活动列表；新增加价购/维护。
- 截图：![加价购](../../../../tool-results/ql361/pages/营销__商城营销__加价购.png)

## 2. 页面配置

### 查询条件

- 起始时间、结束时间
- 活动状态（全部）
- 勾选项：显示已过期/已作废活动（默认不勾选）

### 功能按钮

- 工具栏（抓取 JSON buttons）：新增加价购、查询、跳转（分页跳转）
- 行级操作（操作列存在，抓取时点无数据行，行级动作明细待复核）

### 打印配置

无（页面无打印按钮，截图确认）

## 3. 数据表格列配置

### 默认显示列（6 列，抓取 JSON columns 实据）

操作、活动名称、起始时间、结束时间、活动状态、制单人

> JSON columns 首项即"操作"，无拼接串，6 列全部为真实列，与截图表头一一对应。

## 4. 业务规范

- 加价购模型（实据归纳）：
  - 连带销售规则（页面定位）：买家购买主商品后，可加 N 元换购指定商品——主商品与换购品、加价金额在新增表单维护（列表列未覆盖，待复核）
  - 生命周期：新增 → 时间窗内生效 → 过期自动失效或人工作废；"显示已过期/已作废活动"默认隐藏历史活动（勾选项实据，与商品促销/整单促销/特价同构）
  - 制单人审计列
  - 换购入口（推断，待复核）：商城商品详情/购物车结算环节提示可加价换购
- 与其他页面关系：商城营销组玩法之一（与拼团/秒杀/预售价格玩法、弹窗广告/热搜词引流位互补，加价购做连带提升客单价）；本系统落地对应加价购 `/api/erp/marketing/addon-rule`（api/marketing.ts 实据）
