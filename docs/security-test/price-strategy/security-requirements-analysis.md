# 价格策略模块安全需求分析

## 1. 业务安全分析

### 1.1 价格数据保护需求
价格策略模块处理的敏感业务数据包括：
- **核心业务数据**：产品基础价格、折扣率、价格系数、最小数量门槛
- **客户敏感数据**：客户等级定价、战略客户专有价格
- **商业机密**：定价公式、价格策略优先级配置
- **财务数据**：折扣金额、价格计算结果

### 1.2 权限控制需求
#### 1.2.1 垂直权限控制
- **超级管理员**：可管理所有租户的价格策略
- **租户管理员**：可管理本租户的价格策略
- **销售经理**：可查看和创建价格策略，需审批
- **销售专员**：只能查看生效中的策略和使用价格计算

#### 1.2.2 水平权限控制
- 用户只能访问自己所属租户的数据
- 策略创建者只能修改自己创建的策略（除非有管理员权限）

### 1.3 审计需求
- 所有价格策略的创建、修改、删除操作需要记录操作日志
- 价格计算请求需要记录请求者和计算结果
- 敏感操作（如大额折扣设置）需要双人复核

## 2. 合规要求分析

### 2.1 行业合规要求
- **GB/T 35273-2020**：个人信息安全规范（涉及客户定价信息）
- **网络安全法**：关键信息基础设施保护要求
- **数据安全法**：数据分类分级保护要求

### 2.2 数据分类分级
| 数据类别 | 敏感级别 | 保护要求 |
|---------|---------|---------|
| 价格计算公式 | 高 | 加密存储，访问控制，操作审计 |
| 战略客户价格 | 高 | 严格的权限控制，操作审批 |
| 一般客户价格 | 中 | 基本访问控制，数据加密 |
| 价格计算日志 | 低 | 访问控制，定期备份 |

### 2.3 数据跨境传输要求
- 价格数据如涉及跨境传输，需符合数据出境安全评估要求
- 国际定价策略需考虑不同国家的数据保护法规（如GDPR）

## 3. 威胁建模分析

### 3.1 STRIDE威胁分析

#### 3.1.1 欺骗（Spoofing）
- **攻击场景**：攻击者伪造用户身份访问敏感价格数据
- **潜在影响**：获取商业机密价格策略，进行不当竞争
- **风险等级**：高

#### 3.1.2 篡改（Tampering）
- **攻击场景**：
  1. 篡改价格计算公式JSON配置
  2. 修改折扣率或价格系数
  3. 非法激活/停用价格策略
- **潜在影响**：造成重大经济损失，破坏定价体系
- **风险等级**：高

#### 3.1.3 否认（Repudiation）
- **攻击场景**：管理员创建不合理价格策略后否认操作
- **潜在影响**：责任追溯困难，审计失效
- **风险等级**：中

#### 3.1.4 信息泄露（Information Disclosure）
- **攻击场景**：
  1. 未授权访问其他租户价格策略
  2. 通过API泄露敏感价格计算公式
  3. 日志中包含敏感价格数据
- **潜在影响**：商业机密泄露，竞争优势丧失
- **风险等级**：高

#### 3.1.5 拒绝服务（Denial of Service）
- **攻击场景**：
  1. 恶意大量调用价格计算API
  2. 创建大量无效价格策略占满数据库
- **潜在影响**：价格计算服务不可用，影响销售业务
- **风险等级**：中

#### 3.1.6 权限提升（Elevation of Privilege）
- **攻击场景**：普通用户通过漏洞提升权限修改他人策略
- **潜在影响**：非法控制价格体系，造成经济损失
- **风险等级**：高

### 3.2 攻击面分析

#### 3.2.1 外部攻击面
1. **API接口**
   - RESTful API：/api/sale/pricing/**
   - 可能的攻击：SQL注入、XSS、CSRF、权限绕过

2. **数据库访问**
   - 直接数据库访问（如有）
   - 可能的攻击：SQL注入、数据泄露

3. **文件系统**
   - 配置文件、日志文件
   - 可能的攻击：敏感文件读取、配置篡改

#### 3.2.2 内部攻击面
1. **权限滥用**
   - 授权用户滥用权限访问敏感数据
   - 可能的攻击：内部信息泄露、恶意修改

2. **逻辑漏洞**
   - 价格计算逻辑错误
   - 可能的攻击：价格计算漏洞利用

3. **配置错误**
   - 安全配置不当
   - 可能的攻击：权限绕过、数据泄露

## 4. 安全目标定义

### 4.1 核心安全目标

#### 4.1.1 机密性目标
1. 敏感价格数据在存储和传输过程中必须加密
2. 访问价格数据需严格权限控制
3. 价格计算公式作为商业机密需额外保护

#### 4.1.2 完整性目标
1. 价格数据不能被未授权修改
2. 价格计算公式配置需完整性校验
3. 价格计算逻辑需防篡改保护

#### 4.1.3 可用性目标
1. 价格计算服务需保证高可用性
2. 需防DoS攻击保护
3. 关键操作需有容错机制

### 4.2 安全测试成功标准

#### 4.2.1 技术成功标准
- [ ] 所有API接口通过OWASP ZAP安全扫描无高危漏洞
- [ ] 代码安全扫描工具（SonarQube、Fortify）无高危安全问题
- [ ] 渗透测试未发现可利用安全漏洞
- [ ] 安全配置符合安全基线要求

#### 4.2.2 业务成功标准
- [ ] 敏感价格数据访问有完整审计日志
- [ ] 权限控制机制有效，无权限绕过风险
- [ ] 价格计算逻辑安全，无逻辑漏洞
- [ ] 系统具备防篡改、防泄露、防滥用能力

#### 4.2.3 合规成功标准
- [ ] 符合个人信息保护要求
- [ ] 符合数据安全法分类分级保护要求
- [ ] 符合行业安全标准
- [ ] 安全控制措施可审计、可验证

## 5. 安全测试风险评估

### 5.1 风险矩阵

| 风险等级 | 概率 | 影响 | 风险值 | 处理优先级 |
|---------|------|------|--------|-----------|
| 价格数据泄露 | 中 | 高 | 高 | 1 |
| 价格计算逻辑篡改 | 低 | 高 | 中 | 2 |
| 权限绕过攻击 | 中 | 中 | 中 | 3 |
| 拒绝服务攻击 | 高 | 中 | 中 | 4 |
| 审计日志缺失 | 低 | 中 | 低 | 5 |

### 5.2 风险应对策略
1. **规避风险**：通过技术手段消除高风险漏洞
2. **转移风险**：通过保险、合同转移部分风险
3. **减轻风险**：通过安全控制降低风险概率和影响
4. **接受风险**：对低风险项接受残留风险

## 6. 安全基线要求

### 6.1 身份认证安全基线
1. 所有API接口需支持身份认证
2. 敏感操作需强身份认证
3. 密码策略符合复杂度要求

### 6.2 权限控制安全基线
1. 基于角色的访问控制（RBAC）
2. 最小权限原则
3. 权限定期审计

### 6.3 数据安全基线
1. 敏感数据加密存储
2. 数据传输加密（TLS 1.2+）
3. 数据备份和恢复机制

### 6.4 安全开发基线
1. 安全编码规范
2. 安全测试集成到CI/CD
3. 依赖组件安全更新
