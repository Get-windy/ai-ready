# 按单收款开发文档

> **文档类型：** 页面对标复刻（已完成代码）
> **对标系统：** ql361（来肯企汇，`22stable.ql361.com`）
> **定位：** 按金标准结构编写；应收款统一核销工作台（复合页，非标准列表页）。

## 页面概述

按单收款是**应收款核销工作台**：按欠款单据逐单收款的处理中心（列表查询 + 阶段 Tab + 行级收款）。**单入口**，无独立表单。

| 页面 | 地址 | 说明 |
|------|------|------|
| 按单收款 | `finance/receipt-by-doc` | 复合页（列表 + 4 阶段 Tab） |

单入口：财务 → 收款 → 按单收款。

### 配置功能说明
- **页面配置/列配置**：管理页面级字段与数据表列的显示/隐藏/排序/宽度/冻结。
- 页面配置在页面顶部按钮区域，列配置在页面内嵌数据表右上角表头单元格内齿轮图标
- 列配置弹窗结构：个人配置 Tab / 全局配置 Tab，配置列：上级、列名、显示名、显示、回车键跳转、公式内容；支持上移/下移/恢复默认/保存。
- ⚠️ **当前实现说明**：本页尚未升级金标准组件（复合页），见「实现差异说明 → 待完善」。

## 业务规范说明

- **应收主线**：销售业务单据（销售出库单 XSCKD-/销售退货单 XSTHD-）记账产生应收 → 本页「待收款」；超期 →「超期待收款」；发票查询看开票。
- **行级「收款」**：对该单据发起收款 → 进入《收款单》（SKD-）；收款后已结算↑、未结算↓，待审金额=收款单已提交未记账。
- **对账（√/否）**：标记该单据与对方对账，记录最后对账标记时间/人。
- **欠条领取**：挂账客户欠款以欠条借出/归还登记。
- **无结算收款单核销**：对已记账但未勾选核销单据的收款单事后补核销。
- **金额口径**：本单金额 = 已结算 + 待审金额 + 未结算。
- **交账前置**：职员经手未交账单据不可选择收款（须先《账款交账》）——页面提示实据。
- **下游**：收款单记账生成会计凭证（KJPZ-）→ 总账/明细账/科目余额表/辅助核算余额表（应收账款 1122）。

## 实现差异说明

**实现文件**：
- 前端：`views/finance/receipt-by-doc/index.vue`（金标准复合页，4 Tab）
- API：`api/finance/index.ts`（`receiptByDocApi`：应收来源统一查询 + 发票方向查询）
- 后端：`UnifiedSalesDocumentDTO`（补应收核销字段）、`UnifiedDocConverter`（映射 + 未结算计算）、`UnifiedSalesDocQueryServiceImpl`（修复列名 + 应收来源过滤）

### 页面对齐（金标准已建成）
- **复合页**：`CategoryListLayout` + `BillTableList` + `ColumnConfigPanel`/`PageConfigPanel`。
- **阶段 Tab（4）**：待收款 / 超期待收款 / 全部单据 / 发票查询（发票分销售/采购子方向）。
- **列配置**：待收款 40 列 / 超期 35 列 / 全部 46 列 / 发票 19 列，默认显隐按文档；每 Tab 独立 `useColumnConfig`（storage key 独立）。
- **页面配置**：每 Tab 独立查询条件显隐 + 功能按钮显隐。
- **行级收款**：行「收款」联动《收款单》（`/finance/receipt-doc/form`）。
- **金额口径**：本单金额 = 已结算 + 待审金额 + 未结算（`decorateDocRows`）。
- **功能按钮**：无结算收款单核销 / 欠条领取 / 合并收款 / 强制结算 / 开具发票 / 刷新 / 打印(F8) / 导出 / 配置。

### 遗留说明（非阻塞）

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 应收单一口径（红线）**：按单收款为应收核销唯一入口，**严禁绕过《收款单》直接改应收余额**；行级收款后已结算↑/未结算↓，待审=收款单已提交未记账。
- **P1 金额守恒**：本单金额=已结算+待审金额+未结算，不得断层。
- **P1 上游联动**：待收款来自销售应收来源（XSCKD-/XSTHD-）；对账标记记录时间/人；经手人须先《账款交账》方可收款。
- **P2 验收**：无桩/无模拟；阶段 Tab、无结算核销、欠条领取、凭证需真实数据闭环验证。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
