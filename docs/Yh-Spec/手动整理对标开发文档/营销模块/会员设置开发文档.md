## 4. 业务规范

- **积分规则模型**：
  - 积分流入三路：注册初始积分（开户即送）、会员生日倍积分（生日当天消费按 N 倍计）、消费积分（日常消费累计）；另有签到积分（线上签到玩法）。
  - 消费积分两种算法**互斥（单选）**：按销售金额积分（全局统一比例，实测 100 元=1 分）或按不同商品累计积分（商品级系数，`详细设置` 维护）。
  - 勾选项「按折扣积分」决定按折前/折后金额计积分（**具体口径待复核**）。
  - 积分规则 = 四舍五入（消费金额换算积分时的取整方式）。
  - 积分应用场景：线下开单 / 微商城双通道，控制积分在哪些渠道产生与使用（勾选态待复核）。
  - 签到积分递增模型：首日 3 分、连续签到每日 +1、封顶 8 分。
- **积分流出（积分抵现）**：实测 100 积分=1 元，单笔订单最高可抵扣 100%（即可全额抵扣，比例可调）；另一流出方向为《积分兑换开发文档》的礼品兑换。
- **跨页关系**：
  - 《会员管理》：会员积分账户按本页规则累计与扣减；「客户 | 会员管理」开关证实**会员档案依托客户（ERP 往来单位）**。
  - 《积分兑换》：消费积分余额的兑换出口。
  - 销售开单：「会员信息」Tab（销售积分/兑换积分/使用积分/当前积分）按本页「积分应用场景-线下开单」启用；「微商城」对应 B2B 商城渠道。

## 本轮落地记录（2026-09-18 · P1 会员等级规则与积分有效期）

> **背景**：业界调研确认这两项是会员体系标配，而本系统此前只有「会员自动升级」一个开关（无等级门槛）、
> 积分只有流入/抵现规则（**无有效期、无过期处理**）。

### 一、会员等级规则

| 层 | 文件 | 说明 |
|----|------|------|
| 档案 | `erp-partner` `MemberLevel` 补 4 列（`upgrade_amount` / `upgrade_points` / `keep_months` / `is_default`） | **复用既有等级档案表**，不另建等级表 |
| 迁移 | **V11.381.0** | 补列 + **去重**（等级档案此前被重复播种，同一 level_name 有多行）+ 兜底门槛（0/2000/10000/50000，保级 12 个月，最低级为默认） |
| 后端 | `erp-marketing` `MemberLevelRuleController`（**新增**） | `GET /rules`、`POST /evaluate`（dry-run）、`POST /apply`（执行升降级） |
| 前端 | 本页新增**第 4 分区「会员等级」** | 等级表（名称/折扣率/消费额门槛/积分门槛/保级周期/默认/排序）+ 新增/修改弹窗 + 等级评估 + 执行升降级 |

**评估口径**：目标等级 = 满足「累计消费额 ≥ `upgrade_amount`」或「积分 ≥ `upgrade_points`」中
**序号最大的那一级**；都不满足则落到默认等级（`is_default=1`）。
动作分为 `INIT` 首次定级 / `UPGRADE` / `DOWNGRADE` / `KEEP`；评估是 **dry-run（只算不写）**，
执行才回写 `biz_party.member_level`，且受本页**「会员自动升级」开关门控**（关闭时拒绝执行，除非显式 force）。

### 二、积分有效期与过期

| 层 | 文件 | 说明 |
|----|------|------|
| 参数 | 本页「会员积分」分区 +2 项 | **积分有效期（月，0＝永久）**、**到期前提醒（天）** ← 对标三分区无此项，属本系统新增字段 |
| 台账 | `erp-marketing` `mkt_points_batch`（新表） | 一笔「获得」= 一个批次；含 获得/剩余/获得时间/**到期时间**/来源/状态 |
| 流水 | `erp-marketing` `mkt_points_journal`（新表） | `EARN/USE/EXPIRE/ADJUST` + **变动后余额**（可对账） |
| 服务 | `PointsLedgerService(+Impl)`（**新增**） | 获得（按有效期算到期）/ **FIFO 扣减** / 过期执行 / 即将过期清单 / 可用积分 |
| 端点 | `erp-marketing` `PointsLedgerController`（**新增**） | `/batch/list`、`/available`、`/journal/page`、`/earn`、`/use`、`/expire`、`/expiring-soon` |
| 接线 | `LoyaltyCardServiceImpl.addPoints/deductPoints` | 积分增减**同步落批次**（账户余额与批次剩余恒等，过期才有准确口径） |
| 前端 | 本页 +2 个动作按钮 | 「查看即将过期」（到期提醒清单）、「立即执行过期」 |

**为什么必须做批次**：过期过的不是"账户总额"，而是**某个批次尚未用完的剩余**；
只有批次 + FIFO 才能算准（业界通行：有效期 12 个月 + 提前 30 天提醒）。

### 定时过期（2026-09-18 收口）

`MemberPointsExpireJob`（`job_key = mkt.member.pointsExpire`，每日 03:00，种子见 **V11.387.0**）：

- 多实例互斥（Redis 锁）；按 `MarketingTenantMapper.selectActiveTenantIds()` 逐租户切上下文执行，
  单租户异常不影响其余租户。
- **过期只清「批次剩余」，不动账户总额**：写 `EXPIRE` 流水留痕（口径唯一来源是 `mkt_points_batch`）。
- 作业默认 `enabled = 0 / STOPPED`，需在「调度任务」页显式启用；本页「立即执行过期」按钮保留（人工补跑）。

### 边界（如实标注）

- **保级周期（`keep_months`）只落库、未参与计算**：降级需要"近 N 个月消费/成长值"的历史聚合口径，
  本系统当前只有累计值（`member_total_consume`），故本轮**只做按累计门槛的升级/降级判定**，
  保级周期与"临期保级提醒"如实标注为待办。
- **等级折扣率（`discount_rate`）未接入开单折扣**：价格引擎仍按价格体系走，等级折扣属价格域改动，另行处理。
- 等级评估默认最多评估 500 人（接口 limit 可调，上限 5000），大账套需分批执行。
