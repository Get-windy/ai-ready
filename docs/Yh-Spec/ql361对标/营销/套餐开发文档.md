# 套餐开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`marketing/package-deal`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **列表页**：多商品组合套餐维护页，套餐档案列表（组合定价/套餐条码/捆绑销售）+ 商品明细；新增/修改/停用/复制/删除维护，行勾选支持批量操作。
- 截图：![套餐](../../../../tool-results/ql361/pages/营销__营销活动__套餐.png)

## 2. 页面配置

### 查询条件

- 套餐（套餐名称/编号/助记码/套餐条码 四合一模糊检索）
- 筛选条件（商品名称/货号/条码/规格/型号——按套餐内含商品反查套餐）
- 显示状态（全部）

### 功能按钮

- 工具栏（抓取 JSON buttons）：新增、刷新、打印(F8)、条码打印、更多、查询、跳转（分页跳转）
- 行级操作（截图确认）：修改、停用、复制、删除（操作列）；行勾选框（批量操作，批量动作明细在"更多"内，待复核）

### 打印配置

页面有打印(F8)与**条码打印**（打印套餐条码标签，配合套餐条码列）两个打印入口；打印模板配置细节待复核

## 3. 数据表格列配置

### 默认显示列（8 列，抓取 JSON columns 实据）

操作、图片、套餐名称、套餐编号、套餐金额、套餐条码、捆绑销售、商品明细

> JSON columns 首项"操作 图片 套餐名称 套餐编号"与第 5 项"套餐金额 套餐条码 捆绑销售 商品明细"为抓取拼接串（表头合并单元格的文本拼接），非真实单列，已剔除，不计入列数。

### 全部可配置列

待复核（未抓取列配置弹窗）。

## 4. 业务规范

- 套餐模型（行数据实据归纳）：
  - 套餐 = 多商品组合的销售单元：商品明细列实据"90口径-700ml注塑杯-磨砂\*1箱、90口径-…"（多行"商品\*数量"组合）；套餐金额 176 为整组定价（组合价，非单品价简单加总的可能性存在，待复核）
  - 套餐编号规则（行实据）：tc + 序号（tc0001）——"tc"为"套餐"拼音首字母，与销售域单据编号规则（XSDD- 等）同为业务前缀风格
  - 套餐条码：套餐可独立赋码，配合"条码打印"打印套餐条码标签，开单扫码按套餐整组录入
  - 捆绑销售（实据 √）：勾选后套餐内商品必须整套购买、不可拆零；未勾选时是否可拆卖待复核
  - 生命周期：新增 →（可复制快速建档）→ 停用（下架停售，显示状态查询条件对应）→ 删除；复制动作用于同构套餐快速复制
  - 双条件检索：既可按套餐自身（名称/编号/助记码/条码）查，也可按内含商品（名称/货号/条码/规格/型号）反查——套餐与商品为多对多关系
  - 与仓储"组装单/拆卸单"的区别：套餐是销售侧组合定价（发货时可能仍为散件或组合装），组装/拆卸是仓储侧实物加工改变库存形态；两者业务归口不同，不可混用
- 与其他页面关系：销售开单联动（套餐作为可售单元进入销售开单商品选择，套餐条码扫码录入；销售明细按套餐行或拆行计价待复核）、库存扣减（套餐发货扣减各明细商品库存，推断，扣减时点与批次规则待复核）、本系统落地对应套餐 `/api/erp/product-kit`（api/marketing.ts 实据）
