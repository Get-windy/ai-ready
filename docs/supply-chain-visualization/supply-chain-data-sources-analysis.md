# 供应链数据源分析

## 1. 数据源概览

基于现有ERP系统分析，供应链数据主要分布在以下模块：

### 1.1 采购管理模块 (erp-purchase)
- **数据表**: 采购订单、采购合同、供应商信息、采购价格
- **关键字段**: 
  - 订单编号、供应商ID、采购日期、预计到货日期、实际到货日期
  - 物料编码、采购数量、采购单价、总金额
  - 订单状态（待审核、已审核、已发货、已收货、已完成）

### 1.2 库存管理模块 (erp-stock)
- **数据表**: 库存记录、库存流水、仓库信息、库位信息
- **关键字段**:
  - 物料编码、仓库ID、库位ID、当前库存量、安全库存
  - 入库时间、出库时间、批次号、有效期
  - 库存状态（正常、冻结、报废）

### 1.3 订单管理模块 (erp-order)
- **数据表**: 销售订单、客户信息、订单明细
- **关键字段**:
  - 订单编号、客户ID、下单时间、预计发货时间、实际发货时间
  - 物料编码、订购数量、销售单价、订单金额
  - 订单状态（待处理、处理中、已发货、已完成、已取消）

### 1.4 销售管理模块 (erp-sale)
- **数据表**: 销售记录、销售退货、销售分析
- **关键字段**:
  - 销售单号、销售日期、客户ID、销售员ID
  - 销售数量、销售金额、折扣、净销售额
  - 退货原因、退货数量、退货金额

### 1.5 仓库管理模块 (erp-warehouse)
- **数据表**: 仓库配置、库区管理、货架管理
- **关键字段**:
  - 仓库编码、仓库名称、仓库类型、仓库容量
  - 库区编码、库区类型（存储区、拣货区、暂存区）
  - 货架编码、货架层级、最大存储量

### 1.6 供应商门户模块 (erp-supplier-portal)
- **数据表**: 供应商信息、供应商绩效、合同信息
- **关键字段**:
  - 供应商编码、供应商名称、联系人、联系方式
  - 供应商品类、供货能力、交货准时率、质量合格率
  - 合作开始时间、合同有效期、绩效评分

### 1.7 采购退货模块 (erp-purchase-return)
- **数据表**: 退货单、退货明细、退货原因
- **关键字段**:
  - 退货单号、采购订单号、供应商ID、退货日期
  - 物料编码、退货数量、退货原因（质量问题、数量问题、规格不符）
  - 处理状态（待处理、已处理、已关闭）

## 2. 数据关联关系

### 2.1 核心数据流
```
供应商 → 采购订单 → 库存入库 → 销售订单 → 客户
            ↓            ↓          ↓
        采购退货    库存调整    销售退货
```

### 2.2 关键关联字段
- **物料编码**: 贯穿所有供应链模块的唯一标识
- **订单编号**: 采购订单和销售订单的关联
- **供应商ID/客户ID**: 供应链上下游主体标识
- **批次号**: 库存管理和质量追溯的关键

## 3. 数据特征分析

### 3.1 数据量估算
| 数据表 | 记录量（日增） | 数据量（MB/日） | 保留周期 |
|--------|---------------|----------------|----------|
| 采购订单 | 500-1000 | 5-10 | 3年 |
| 库存流水 | 2000-5000 | 20-50 | 2年 |
| 销售订单 | 1000-2000 | 10-20 | 3年 |
| 库存记录 | 10000-50000 | 100-500 | 实时 |

### 3.2 数据更新频率
- **实时数据**: 库存记录、库存流水、订单状态
- **准实时数据**: 采购订单状态、销售订单状态（分钟级）
- **批量数据**: 供应商绩效、销售分析、库存统计（小时/天级）

### 3.3 数据质量要求
1. **完整性**: 关键字段（物料编码、数量、金额）必须完整
2. **一致性**: 跨模块数据必须保持一致性
3. **时效性**: 实时数据延迟不超过5分钟
4. **准确性**: 数量、金额等数值字段精度要求0.01

## 4. 数据抽取策略

### 4.1 实时数据抽取
- **技术**: Change Data Capture (CDC) + Kafka流处理
- **源表**: 库存流水表、订单状态变更表
- **频率**: 实时/准实时（<1分钟延迟）
- **目标**: 实时监控仪表板

### 4.2 批量数据抽取
- **技术**: ETL工具（Apache Airflow/Sqoop）
- **源表**: 历史订单、统计报表
- **频率**: 每小时/每天
- **目标**: 分析型数据仓库

### 4.3 增量抽取策略
- **基于时间戳**: 使用created_at/updated_at字段
- **基于版本号**: 使用version或revision字段
- **基于触发器**: 数据库触发器捕获变更

## 5. 数据质量监控设计

### 5.1 监控指标
1. **数据完整性监控**
   - 空值率检查
   - 必填字段完整性
   - 外键关联完整性

2. **数据准确性监控**
   - 数值范围校验
   - 业务规则校验
   - 跨系统一致性校验

3. **数据时效性监控**
   - 数据延迟监控
   - 处理时间监控
   - SLA符合性监控

### 5.2 异常处理机制
1. **实时告警**: 数据质量异常实时通知
2. **自动修复**: 可配置的数据清洗规则
3. **人工干预**: 重大异常人工处理流程

## 6. 技术选型建议

### 6.1 数据抽取层
- **CDC工具**: Debezium
- **消息队列**: Apache Kafka
- **流处理**: Apache Flink/Spark Streaming

### 6.2 数据存储层
- **实时数据**: Redis/ClickHouse
- **分析数据**: PostgreSQL/TiDB
- **历史数据**: HDFS/对象存储

### 6.3 数据处理层
- **ETL工具**: Apache Airflow
- **数据质量**: Great Expectations
- **监控告警**: Prometheus + Grafana
