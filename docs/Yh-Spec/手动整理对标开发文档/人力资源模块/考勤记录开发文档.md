## 1. 页面概述

「考勤记录」承载**员工每日打卡与出勤结果台账**：上班打卡、下班打卡、按员工/月份查考勤流水，并把出勤结果供**薪资模块**（`HrSalaryPaymentServiceImpl.generateMonthlyPayment`）计算工时、加班与缺勤扣款。

| 页面 | 地址 | 组件 | 行数 | 菜单挂载 | 说明 |
|------|------|------|:----:|:--------:|------|
| 考勤记录（列表） | `hr/attendance` | `views/hr/attendance/list.vue` | 70 | ✅ `90002` | 只读台账：5 列 / 无查询区 / 无任何操作按钮 |
| 考勤管理（伴生页） | `hr/attendance/index` | `views/hr/attendance/index.vue` | 137 | ❌ **未挂菜单** | 8 列 / 3 项查询 / 签到·签退按钮 / 迟到·早退列 |

> **⚠️ 伴生页提醒（全站 HR 模块共性）**：`index.vue` 已在 `router/dynamicRoutes.ts:504` 注册组件映射，**但 `sys_menu` 中没有任何一行把 `component` 指向 `views/hr/attendance/index.vue`**（全迁移文件 grep 为空）。
> 路由表由菜单驱动（`transformMenuToRoutes`），故 `index.vue` **用户不可达** —— 只能由开发者在代码中直接 import。
> 后果：**功能更完整的那个页面用户看不到，用户看到的是功能最少的那个**。两页必须先**收敛为一页**（建议保留 `list.vue` 之名、吸收 `index.vue` 能力），再谈金标准升级。

### 1.2 本页与「请假管理」的耦合（跨页一致性缺陷）

请假与考勤在当前实现中**互不感知**：

- 请假批准（`hr/leave/{id}/approve`）**不会**在 `hr_attendance` 写入或标记任何行；
- 而薪资生成把 `status = 'ABSENT'` 的记录当作**缺勤**并按 `日薪 × 缺勤天数` 扣款（`HrServiceImpls.java:301-303`、`:328`）。

> **⚠️ 业务后果**：员工请假获批后，其考勤流水仍为空白（既无 `NORMAL` 也无 `ABSENT`）；一旦有人用「缺勤」口径补录/导入考勤，**请假期间会被当作缺勤扣钱**。这是**跨页数据一致性缺陷**，详见《请假管理开发文档》§5.4 与本文 §9。

## 5. 业务规范

### 5.1 状态与值域

| 字段 | 值域 | 当前实现 | 问题 |
|------|------|---------|------|
| `status` | `NORMAL 正常 / LATE 迟到 / EARLY 早退 / ABSENT 缺勤`（String） | 前端 `ATTENDANCE_STATUS_MAP`（`api/hr/index.ts:276-281`）；DB 注释一致（`V8.9.0:131`） | ✅ 词表一致，**但见下** |
| `late_minutes` | 整数（分钟） | **从不被打卡流程写入** | ❌ 恒为 DB 默认 `0` |
| `early_minutes` | 整数（分钟） | **从不被打卡流程写入** | ❌ 恒为 DB 默认 `0` |
| `work_hours` | `DECIMAL(4,1)` 小时 | **从不被打卡流程写入** | ❌ 恒为 `NULL` |

> **⚠️ 词表缺陷（P0 的业务根因）**：`status` 只有 4 个值，**没有「休假（LEAVE）」「出差（TRIP）」「加班（OVERTIME）」「调休（OFF）」**。
> 这与请假模块**无法收敛**：请假批准后无值可写，只能留空 → 薪资侧按「无考勤记录」处理，而缺勤扣款只数 `ABSENT` 行 → 请假既未被计为出勤、也未被计为缺勤，是**未定义态**。
> 修法：扩值域 `LEAVE`（并补 `ABSENT` 的真实判定逻辑），或新增 `leave_request_id` 关联列（推荐后者，语义更清晰）。

### 5.2 打卡规则（当前：完全缺失）

**`hr_attendance` 与 hr 模块内不存在任何考勤规则数据**：无班次表、无上下班时间、无工作日历（节假日/调休）、无迟到判定阈值、无弹性打卡规则。

`clockIn` 的实现（`HrServiceImpls.java:142-151`）逐行为：

```
new HrAttendance()
  .setEmployeeId(employeeId)
  .setAttendanceDate(LocalDate.now())
  .setClockInTime(LocalTime.now())
  .setStatus("NORMAL")          ← 硬编码
  .setCreateTime(LocalDateTime.now())
save(...)
```

`clockOut`（`HrServiceImpls.java:154-165`）：按 `employeeId + attendanceDate = today` 查当天记录，**只**回写 `clockOutTime` 与 `updateTime`。

> **⚠️ P0：永远判不出迟到与早退**
> 因为 ① 没有「应到时间」这个基准，② `clockIn` 把 `status` 写死 `NORMAL`，③ `late_minutes` / `early_minutes` / `work_hours` **在打卡路径中零写入**。
> 全仓对这三列的**唯一读取方**是薪资生成（`HrServiceImpls.java:293-299`），且它是**用 `clock_in_time` / `clock_out_time` 现算分钟数**，**根本不读 `work_hours` 列**。
> 即：`work_hours` 是**死列**，`late_minutes` / `early_minutes` 是**永远为 0 的装饰列**。

### 5.3 关键业务规则

| 规则 | 当前 | 目标 |
|------|------|------|
| 每天每人唯一考勤记录 | ❌ **无唯一约束**（`V8.9.0:133-134` 只有两个非唯一索引）且打卡前的查重只在 `clockOut` 里用 `getOne` | 加 `UNIQUE (tenant_id, employee_id, attendance_date)` 或幂等 upsert |
| 重复 `clock-in` | ⚠️ **直接再插一行**（`clockIn` 无查重）→ 同日多条记录 | 当日已有记录时改为幂等更新（或拒绝并提示） |
| `clockOut` 定位当天记录 | ⚠️ `getOne(wrapper)`（`HrServiceImpls.java:158`） | 应改 `list()` + 取最后一条，或加唯一约束后 `getOne` 才安全 |
| 迟到/早退判定 | ❌ 无 | 按班次规则计算分钟数并写 `late_minutes` / `early_minutes` / `status` |
| 工作时长 | ❌ 无（`work_hours` 死列） | 由 `clock_out - clock_in` 自动计算写回（业界做法，见 §8） |
| 跨天班次（夜班） | ❌ 无（`clock_in_time` / `clock_out_time` 是 `TIME` 类型，**无日期**） | 需 `clock_in_datetime` / `clock_out_datetime` 或加班跨天标记 |
| 补卡 | ❌ 无（只能改库） | 补卡申请 + 审批闭环 |
| 外部打卡机/移动打卡 | ❌ 无（hr 模块 3 个控制器**均无 import/export**） | 导入端点或设备对接 |
| 月结锁定 | ❌ 无 | 月考勤结账后禁止改动（供薪资取数） |
| 统计汇总 | ❌ 无（无出勤率 / 迟到次数 / 加班时长端点） | 补 `/stat` 类端点 |

## 8. 业界对标（Odoo / SAP / 金蝶 / 用友）

> 本页在 ql361 **无对应页**（该对标系统**无人力资源模块**）。以下为业界标准做法与本系统的差距。
> **参考来源：** Odoo 18 HR `https://www.odoo.com/documentation/18.0/`（章节待补充）；SAP SuccessFactors / S·4HANA HCM `https://help.sap.com/`（章节待补充）；金蝶 s-HR `https://vip.kingdee.com/`（章节待补充）；用友 DHR `https://success.yonyou.com/`（章节待补充）。

| # | 能力 | 业界做法 | 本系统当前 | 差距与建议 |
|:-:|------|---------|-----------|-----------|
| 1 | **考勤记录模型** | Odoo `hr.attendance`：`check_in` / `check_out` / **`worked_hours`（系统按前后者自动计算，非手工填）**；加班是独立对象 `hr.attendance.overtime` + 规则 `hr.attendance.overtime.rule` | `hr_attendance` 有 `clock_in_time` / `clock_out_time` / `work_hours` 三列，但 **`work_hours` 从不被打卡流程写入**（死列）；无加班对象、无加班规则 | **P0**：`clockOut` 时按 `Duration.between` 回写 `work_hours`（薪资侧已在用同一算法，`HrServiceImpls.java:296`，只是没落库）；加班独立建模 |

| 3 | **考勤异常处理闭环** | **Odoo（A 级）**：考勤错误(Error) = 签到后 24 小时未签退 或 单次签到超 16 小时；异常条目在列表/甘特视图**标红**，须由有权限者**修改或删除**后才能进入薪资（底稿 §1.5）。⚠️ 其中"**补卡申请单**"环节**未获官方文档佐证**（底稿 §6 第 14 条），**不作为业界对标** | **无任何异常处理**：缺卡只能**直接改库**；`status` 值域里 `ABSENT` 无人写入；`remark` 是唯一可写备注 | **P0（业务）**：先做**异常判定 + 标红 + 有权限者修改**（Odoo 口径）；补卡申请闭环按**本系统需求**立项，勿称"业界标配" |
| 4 | **打卡数据来源** | 业界支持**考勤机导入 / 移动定位打卡 / 人脸识别 / 第三方（钉钉·企业微信）同步** | 只有系统内 `clock-in` / `clock-out` **两个端点**，且**无定位、无照片、无设备信息**（表连来源列都没有）；hr 模块 3 个控制器**均无 import/export** | **P0（业务）**：本页最大的可用性缺口 —— 真实企业不可能靠手点网页打卡。建议先补**文件导入**（成本最低）+ 来源列 |
| 5 | **考勤月结与锁定** | SAP 有 **Time Evaluation（时间评估）** 按周期运行并产出结果供薪资使用；金蝶/用友有「考勤月结」，**结账后不可再改** | 薪资生成时**实时现算**（`HrServiceImpls.java:290-328`），**无月结、无锁定**；hr 模块内**无任何 `@Scheduled`** | **P1**：月结锁定是薪资正确性的前提（否则薪资算完后考勤被改，账实不符）。建议落**调度任务**（参考《调度任务模块》） |

## 10. 验收标准（目标）

> 本模块**尚无 E2E 脚本**（`tools/` 目录下无任何 `e2e-hr*.cjs`）。以下为按金标准制定的验收清单。
> **前置条件（重要）**：所有 HR 表**当前 0 行**，故任何验收**必须先造数**（至少 1 个 `hr_employee`、1 个在职员工对应的 `sys_user`），并**在收尾时清理自产数据**（参见《共享db E2E 断言必须加作用域》）。

### 10.1 接口验收（目标 ≥ 15 项）

1. `GET /api/hr/attendance/page` 返回 200（**当前应为 404，修复 P0-1 后才成立**）—— 这一条本身就是 P0-1 的回归断言。
2. 默认查询 `total` 与直查 DB（`deleted = 0` + `tenant_id = 当前租户`）**逐值一致**。
3. `pageNum` / `pageSize` 生效：`pageSize=1` 时 `records.length === 1`。
4. `employeeId` 与 `month` 过滤各自生效（造 2 名员工各 1 条验证前者）；**并断言 `month='2026-1'` 不会误命中 `2026-10/11/12`**（若仍为 `like` 实现则此断言应失败，作为 P1 的证据）。
6. `POST /api/hr/attendance/clock-in` 后 DB 新增 1 行，且 `attendance_date = 今天`、`clock_in_time` 非空。
7. **同日重复 `clock-in` 的行为符合目标语义**（幂等更新，而非插第 2 行）。
8. `POST /api/hr/attendance/clock-out` 后当天记录的 `clock_out_time` 非空。
9. **`work_hours` 被正确回写**（目标行为；当前应断言为 `NULL` 以记录缺陷）。
10. **工作日 09:00 上班的迟到场景**：`clock_in_time = 09:30` 时 `status = 'LATE'` 且 `late_minutes = 30`（目标行为；依赖考勤规则配置）。
11. 无当天记录时 `clock-out` 的返回语义明确（**目标：报错而非静默成功**）。
12. 同日 2 条记录时 `clock-out` **不抛 500**（当前 `getOne` 会抛，此项为 P0 回归断言）。
13. `POST /api/hr/attendance/import` 导入 N 行 → DB 落 N 行；`GET /api/hr/attendance/stat?month=` 返回聚合（出勤天数 / 迟到次数 / 加班时长）（均为目标）。
14. 薪资联动：`POST /api/hr/salary/payment/generate` 后 `hr_salary_payment` **条数 > 0**（当前因 P0-2 应为 0，此项为 P0-2 的回归断言）。
15. 越权/未登录：未带 token 请求应 401（**当前 `HrController` 无鉴权注解，此项预期失败**，作为 P1 证据）。

### 10.2 UI 验收（目标 ≥ 10 项）

1. 菜单 `人力资源 → 考勤管理 → 考勤记录` 点开落在本页，**页面不空白**（目录节点透传组件已就位，见 `dynamicRoutes.ts:945-957`）。
2. 页面**控制台无 error**（含 `ReferenceError` —— 参见《重构搬迁后必须做运行时验证》）。
3. **断言网络无 4xx**：`GET /api/hr/attendance/page` 必须 200（当前 404）。
4. 表格列渲染正确，且**「员工姓名」列有值**（当前恒空）；状态列显示**中文标签**而非 `NORMAL`/`LATE` 原文。
5. 迟到 / 早退列：`0` 显示 `-`，`> 0` 显示橙色「N分钟」。
6. 查询区为**横向自适应网格**（不得纵向单列），3 项条件**逐个生效**（当前 2 项静默失效）。
7. 表头齿轮可改列显隐/顺序，刷新后**个人配置保留**（目标）。
8. `签到` / `签退` 按钮走后端真实接口（**断言请求体 `employeeId` 非 0 且等于登录员工**）；补卡申请：提交 → 审批 → 考勤记录被更新（目标）。
9. 分页为**经典形态** `.classic-pagination`，页长选项 `[20,50,100]`（目标）；**打印判 N/A**（勿按模板硬加）。
10. 收尾：清理验收造出的 `hr_attendance` / `hr_employee` 行，并复核现场已复原。
