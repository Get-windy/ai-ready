## 新增线路表单（对标系统实测 · 弹窗标题「配送路线」）

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 线路类型 | 单选（自配 / 物流） | **是** | usetype_zp（自配）/ usetype_wl（物流）；二次实测为**互斥单选**，默认选中「自配」 |
| 线路编号 | 输入框 | **是** | code；新增时自动带出下一个号（`XL001` 递增），可改写 |
| 线路名称 | 输入框 | **是** | fullname |
| 物流公司 | 输入框 | 否 | expressname（线路类型=物流 时显示） |
| 配送区域 | 行政区划多选 | 否 | **2026-09-12 二次实测**：控件为 `city-list`（行政区划多选），默认 `--无--`，已选项按 `data-code`（形如 `86,0`）逐项渲染并带删除按钮；2026-09-07 首抓记录为「区域子表（配送区域类型 gptype + 配送区域编码 gpcode）」，两者为同一能力的两种记账，落地以**行政区划多选**为准 |
| 备注 | 输入框 | 否 | remark |

按钮：**保存(Enter)**、**关闭(Esc)**。

> **本系统落地口径**：线路类型用 `a-radio-group`（互斥，默认自配，后端同时校验「不可两者都选」）；配送区域用 `a-tree-select`（`tree-checkable` + `SHOW_PARENT`，数据源 `sys_region` 行政区划树），已选项以标签呈现、支持删除；后端按行政编码回填 `area_name`（名称）与 `area_type`（PROVINCE/CITY/DISTRICT）。

## 业务规范说明

- **实现状态**：✅ `/api/erp/md/route/*` 已实现（page / detail / options / next-code / create / update / delete / status / batch-status / import-template / import-excel / export），无桩无模拟。
- **红线（单一口径）**：线路主数据 = `erp_route`，与《配送路线单》执行单据（`erp_delivery_route` + `erp_route_point`）**严格区分**：执行单存配送员 / 进度 / 起讫时间 / 状态流（`PLANNING/READY/IN_PROGRESS/COMPLETED/CANCELLED`），主数据只存线路档案本身，**不得互相替代或重复建表**。
- **编号规则**：`XL` + 3 位序号（`XL001`、`XL002` …，同租户内 `route_code` 唯一；软删除后允许复用，靠 `uk_erp_route_code ... WHERE deleted = 0` 部分唯一索引保证）。
- **线路类型互斥**：`route_self` / `route_logistics` 两列记账（0/1），但业务上二选一，前后端 + Excel 导入三处一致校验。
- **配送区域**：子表 `erp_route_area` 存 `area_code`（行政区划编码）+ `area_name` 快照 + `area_type`（层级），保存时整体替换（对标子表行为）。
- **引用方**：销售订单/出库单表头「配送线路」、订单处理中心「按线路」维度、DMS 配送任务调度；下拉口径见 `GET /api/erp/md/route/options`（仅启用线路）。

## 重复性研判：「资料 → 配送管理 → 线路」vs「配送 → 线路管理 → 线路列表」（2026-09-12）

> 数据库菜单实测（`sys_menu`）：`70530 md:route`（本页，挂在 `61104 配送管理` 下）与 `60501/80700 dms:route-list`（挂在 `60005 配送` 下）。

| 维度 | 资料 → 配送管理 → 线路（70530 `md:route`） | 配送 → 线路管理 → 线路列表（80700 `dms:route-list`） |
|---|---|---|
| 页面 | `views/md/route/index.vue`（本页） | `views/dms/route-list/index.vue` |
| 数据 | `erp_route` + `erp_route_area`（**档案主数据**） | `erp_delivery_route`（**执行任务**） |
| 接口 | `/api/erp/md/route/*` | `/api/delivery/route/list`（+ start/complete/cancel） |
| 语义 | 这条线路"是谁、覆盖哪些区域、自配还是物流" | 某次配送"谁跑、跑到哪、开始/完成/取消" |
| 关键字段 | 线路类型/编号/名称/物流公司/配送区域 | 配送员/进度/起点终点/里程时长/状态机 |

**结论：两者不重复**（档案 vs 执行单据，数据模型与生命周期完全不同），但存在 3 处真实冗余/混淆，需分别处理：

1. **命名撞车（建议处理）**：执行单列表被命名为「线路列表」、父级「线路管理」，与本页「线路」字面重复，用户难以区分。建议执行单侧更名为「配送路线单 / 配送路线」，保留 `dms:route-list` 页面本体不动。
2. **孤儿页（建议处理）**：`views/dms/route/index.vue`（路线规划页，14.9KB）在 `dynamicRoutes.ts` 的 `componentMap` 注册但 **`sys_menu` 无任何菜单挂载** → 不可达死页；其功能与执行单 `/delivery/route/plan` 重叠。建议删除或补菜单入口。
3. **未接线（见「待完善」）**：本页线路档案尚未被《配送路线单》引用（P1 关联一致性）。

> 本次开发**只做本页（70530 主数据）**，未改动执行单侧页面与菜单（避免影响并行工作）。
