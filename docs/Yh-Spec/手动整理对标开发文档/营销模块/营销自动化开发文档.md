## 4. 业务规范

### 触发点口径（逐条，实现即文档）

| 触发点 | 候选口径 |
|--------|---------|
| 新客首单后 | `biz_party.first_order_time` 在 **N 天内** |
| 会员生日 | 生日平移到今年后落在 **未来 N 天内**（跨年可用） |
| 沉睡未消费 | `last_trade_time` **早于 N 天前**（且有过交易） |
| 复购周期到期 | 距上次消费落在 **[N-3, N] 天**窗口内（与沉睡互斥，避免重复触达） |
| 积分即将过期 | `mkt_points_batch` 中 **N 天内到期且仍有剩余** 的批次按会员聚合 |
| 会员卡到期 | `member_valid_end` 在 **N 天内** |

### 动作口径

| 动作 | 复用实现 | 说明 |
|------|---------|------|
| 发优惠券 | `CouponTemplateService.issue` | 校验未领取余量，超发被拒 |
| 发短信 | `SmsSendService.sendBatch` | **与手工群发同一实现**：发送时段 / 退订名单 / 频控 / 同意留痕全部生效 |
| 赠积分 | `PointsLedgerService.earn` | 写积分批次（按《会员设置》的积分有效期算到期） |

- 短信内容支持占位符：`{会员名称}` `{客户名称}` `{会员卡号}`（未匹配的占位符原样保留，便于排障）。
- 执行顺序：**筛候选 → 频控/每人仅一次判定 → 执行动作 → 写执行台账**；
  单个会员触达失败**不影响**其余会员，失败原因写入台账 `resultMsg`。

### 执行入口

- 页面「执行一次」= `POST /auto-campaign/{id}/run`（人工触发）。
- 页面「执行全部启用规则」= `POST /auto-campaign/run-all`（**定时任务同入口**，见「剩余缺口」）。
- 候选预览 = `GET /auto-campaign/{id}/candidates`：**只按触发点筛选，不执行动作、不计入频控**。

## 6. 双频控（2026-09-18 收口）

### 6.1 单规则频控（原有）

规则自带 `freq_days` / `freq_count`（N 天内最多触达 M 次），按 **本规则 × 本会员** 的成功台账计数。

### 6.2 全域频控（跨规则，本轮新增）

单规则频控只管得住「同一条规则不重复骚扰」，管不住「多条规则同一天一起发」——
后者才是真实骚扰来源（业界称 **frequency cap / 全域触达上限**）。

- 口径：同一会员在 N 天内被**任意**规则成功触达达到上限即跳过；跳过原因写入台账。
- 默认 `1 天 2 次`，可用系统参数覆盖（`sys_project_config`，可在「系统参数」页维护）：

  | 参数键 | 含义 | 默认 |
  |--------|------|------|
  | `marketing.autoCampaign.globalFreqDays` | 统计窗口（天） | `1` |
  | `marketing.autoCampaign.globalFreqCap` | 窗口内触达上限（次） | `2` |

- 读配置复用平台 `SysConfigService`（**不重复造配置读取**）；**读不到就回落默认值**
  —— 保护措施不因配置缺失而失效。

### 6.3 定时执行

`AutoCampaignRunJob`（`job_key = mkt.autoCampaign.runAll`，每日 09:00）：

- **多实例互斥**：Redis 分布式锁，另一实例在跑就跳过本轮。
- **全租户遍历**：按 `MarketingTenantMapper.selectActiveTenantIds()`（三表 UNION：规则 / 积分批次 / 储值卡）
  逐个切租户上下文执行，单租户异常不影响其余租户。
- **首次启用默认 `dryRun = true`**：只算候选数不真发，避免「一启用就群发」。
- 种子默认 `enabled = 0 / STOPPED`，需在「调度任务」页显式启用。

## 7. 剩余缺口

1. **未做「触达效果回流」**：台账只记「发了什么」，未关联「领了没 / 买了没」（需与订单、券核销打通）。
2. **无 A/B 与素材库**：业界加分项，本轮不做。
3. **「新客首单」触发点的首单时间取自销售单**（按 `erp_sale_order.customer_id` 求 `MIN(order_date)`），
   若历史销售单缺失，该触发点会取不到候选。

## 8. 验收证据

- **模块级 E2E**：`tools/e2e-marketing.cjs` §二十「营销自动化（80303 · 本系统建模页）」+ §二十二「闭环收口」。
- 覆盖：规则 CRUD 与校验 → 候选预览（含触发依据）→ 执行并**真实发券** → 台账落库 →
  「每人仅一次」二次执行跳过且不重复发券 → 沉睡→短信链路（复用合规实现）→
  停用规则执行被拒 → 无效配置被拒 → 执行记录分页 → 执行概况 → run-all →
  **全域频控：连续三次执行，第 3 次被跨规则拦截且台账写明原因** →
  **系统参数覆盖上限后放行** → **调度种子存在且默认停用 + JobHandler 白名单含三个营销作业** →
  UI（双 Tab / 表头 / 工具栏 / 经典分页）。
