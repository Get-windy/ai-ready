## 1. 页面概述

报价单是 CRM 流程的报价环节：商机 →（本页）报价单 → 转销售订单 / 转合同。它是 CRM 模块中**唯一真正打通到 ERP 单据**的页面（`POST /{id}/convert` 直写 `erp_sale_order`）。

| 页面 | 地址 | 组件 | 行数 | 说明 |
|------|------|------|:----:|------|
| **报价表单页**（菜单主入口） | `crm/quotation/form` | `views/crm/quotation/form.vue` | 575 | 5 张 `a-card`：基本信息 / 报价明细 / 费用汇总 / 附加信息 / 审批流程 |
| **报价列表页**（标签 `历史`） | `crm/quotation/index` | `views/crm/quotation/index.vue` | 1547 | 4 张手写统计卡 + `BillTableList` 9 列 + 新建/编辑 `FullScreenDetail` + 详情 `a-drawer`(80vw) |

### 1.1 ⚠️ 双入口方向与「客户/线索/商机/合同」**相反**

| 页面群 | 主 `path` | `tag_label` | 点菜单第一屏 |

| **报价单 `70330`／发票 `70350`** | **表单页 `*/form`** | **`历史` → `*/index`** | **直接进录单页** |

### 1.2 CRM 报价单 vs ERP 销售订单

| | CRM 报价单（本页） | ERP 销售订单 |
|---|---|---|
| 表 | `crm_quotation`(65 列) + `crm_quotation_item`(31 列) | `erp_sale_order` + `erp_sale_order_item` |
| 后端 | `crm` 模块 `QuotationController`，前缀 `/api/crm/quotation` | `erp-sales` 模块 |
| 语义 | **对客户的价格提议**（可反复出、可作废、有版本） | **已确认的交易**（占库存、产生应收） |
| 影响库存/应收 | **否** | **是** |
| 关联 | `POST /api/crm/quotation/{id}/convert` **直接 INSERT** `erp_sale_order` | — |

### 5.1 状态值域：前端字符串 vs 后端 Integer（**P0，本页最严重缺陷**）

| | 值域 | 证据 |
|---|------|------|
| **前端**（列表/筛选/详情/统计） | **字符串**：`draft 草稿 / sent 已发送 / accepted 已接受 / rejected 已拒绝 / expired 已过期` | `index.vue:864-870,873-874` |
| **后端**（枚举+状态机） | **`Integer` 0–8**：`0 草稿 / 1 待审批 / 2 已审批 / 3 已发送 / 4 已接受 / 5 已拒绝 / 6 已过期 / 7 已转订单 / 8 已取消` | `QuotationStatus.java:4-12`；`crm_quotation.status` 实测 `integer` |
| **前端表单初值** | `status: 'draft'`（字符串） | `form.vue:249` |

**三处必坏**：
1. **筛选恒失败**：前端发 `status=draft`，后端 `@RequestParam(required=false) Integer status`（`QuotationController.java:40`）→ **String→Integer 转换异常（400）** 或过滤全不匹配 → 结果恒空。
2. **状态列显示为空标签**：`getStatusText(status) = statusTextMap[status]`（`index.vue:895`），后端返 `0`/`7` 时查表得 `undefined` → 返回 `''` → `a-tag` 渲染空白；`getStatusColor` 回退 `'default'`（`:894`）。**devdb 实证**：`select status,count(*) from crm_quotation where deleted=0 group by status` → **`0` 有 1 行、`7` 有 1 行** → **现存 2 行在本页状态列全显示空白**。
3. **统计卡恒 0**：`statusCounts` 比 `r.status === 'sent'` / `'accepted'`（`:877-881`）→ 后端从不返回这两个字符串 → **「已发送」「已接受」两张卡恒为 0**。

> 后端 9 个状态中前端只认 5 个，缺 `1 待审批 / 2 已审批 / 7 已转订单 / 8 已取消` 的中文映射。
> **裁定建议（P0）**：前端全改 `Integer`，映射表与 `QuotationStatus` 逐字对齐；颜色建议 `0 default / 1 orange / 2 cyan / 3 blue / 4 green / 5 red / 6 orange / 7 purple / 8 default`。

### 5.2 状态机（后端唯一真源）

```
createQuotation → 0 草稿
  ├─ submit(仅0) → 1 待审批 ── approve(仅1) → 2 已审批 ── send(仅2) → 3 已发送
  │                            └─ reject(仅1) → 回 0 草稿
  ├─ update / addItem / updateItem / removeItem / reorder（均仅 0）
  └─ cancel（除 7 外任意）→ 8 已取消
3 已发送 ── accept(仅3) → 4 已接受 ── convert(仅4) → 7 已转订单
        └─ reject-by-customer(仅3) → 5 已拒绝
3 / 4 且 valid_to < 今天 ── mark-expired ──→ 6 已过期
```

| 迁移 | 前置 | 前置校验失败文案 | 副作用 | 行 |
|------|:----:|-----------------|--------|----|
| `submit` | 0 | 只有草稿状态的报价单可以提交审批 | — | `:259-272` |
| `approve` | 1 | 只有待审批状态的报价单可以审批 | 写 `approved_*` | `:274-290` |
| `reject` | 1 | 只有待审批状态的报价单可以拒绝 | **状态回 `0`** + 写 `rejected_*` | `:292-308` |
| `send` | 2 | 只有已审批状态的报价单可以发送 | 写 `sent_*` | `:310-326` |
| `accept` | 3 | 只有已发送状态的报价单可以标记为已接受 | 写 `accepted_*` | `:328-344` |
| `reject-by-customer` | 3 | 只有已发送状态的报价单可以标记为已拒绝 | 写 `rejected_*` | `:346-362` |
| `convert` | 4 | 只有已接受状态的报价单可以转订单 | **INSERT `erp_sale_order`(+item)**、`converted_*`、状态 → 7 | `:364-405` |
| `cancel` | 任意（除 7） | 已转订单的报价单不能取消 | 状态 → 8；**`reason` 写入 `remark`（覆盖原备注！）** | `:408-422` |

| **后端（生效）** | `QT + yyyyMMdd + 4 位序号`（取当日最大号 +1） | `QuotationServiceImpl.java:97-113` |

**后端两处风险**：① **无租户条件**（`:101-105` 只加 `likeRight` + `deleted=0`）→ 跨租户取最大号 → 撞号（同口径对比：`countByStatus` **显式带了 `tenant_id`**，`QuotationMapper.java:30`，说明是漏写）；② **并发不安全**（`select max+1` 无唯一约束保护）→ 同秒并发建单生成相同单号。应统一走 `next-no` 号段（对照《销售换货单》`XSHHD-yyyyMMdd-NNNN`）。

### 5.5 发送（`send`）—— **必然 400（P0）**

| | |
|---|---|
| 后端签名 | `@PostMapping("/{id}/send")` + **`@RequestParam String method`（必填，无 `required=false`）**（`QuotationController.java:185-193`） |
| 前端调用 | `send(id) → request.post('/crm/quotation/${id}/send')` —— **不传任何参数**（`api/erp.ts:604`） |
| 调用点 | 行「发送」（`:1109-1112`）、详情「发送报价」（`:1188-1191`） |
| 结果 | **400 Missing required parameter 'method'** → `message.error('发送失败')` |
| 状态冲突 | 即使传了 `method`，后端要求 **`2 已审批`**；而前端「发送」按钮只在 **`status==='draft'`（0）** 显示 → 400「只有已审批状态的报价单可以发送」 |

**双重不匹配**：① 缺必填参数；② 按钮显示条件（草稿）与后端要求（已审批）**矛盾**。后端正确流程为 `0 → submit → 1 → approve → 2 → send → 3`，而**前端完全没有 `submit`/`approve` 入口** → **实际永远无法发送报价**。

**`sent_method` 三套词表（P1）**：`SentMethod` 枚举是 **`Integer 1–6`**（`1 邮件/2 微信/3 短信/4 传真/5 人工送达/6 在线查看`，`SentMethod.java:4-9`）；DB 列 `sent_method` 实测 **`character varying`**；实存值为 **`'email'`**。按枚举校验会直接拒绝现有数据。

### 5.6 转订单（`convert`）—— 真实闭环，但**客户 ID 域错位（P0）**

`convertToOrder` → `createSaleOrder`（`:388-405`）→ `QuotationMapper.insertSaleOrderRaw`（`QuotationMapper.java:37-47`）：

```sql
INSERT INTO erp_sale_order(id, tenant_id, order_no, customer_id, customer_name, salesman_name,
  order_date, total_amount, product_amount, status, order_source, original_order_id,
  original_order_no, remark, deleted, create_time, update_time, create_by, update_by)
VALUES(#{orderId}, #{quotation.tenantId}, #{orderNo}, #{quotation.customerId}, …, 0, 1, …)
```

| 观察 | 说明 |
|------|------|
| ✅ 真实写单 | 头 + 明细**真实 INSERT** `erp_sale_order`/`erp_sale_order_item`（`:401-404`） |
| ✅ 事务安全 | `@Transactional`，注释明确「先创建销售订单（失败则整体回滚，报价状态不受影响）」（`:375`） |
| ✅ 幂等 | 仅 `status==4` 可转（`:371-373`），转后置 `7` → 不可重复转 |
| ✅ 溯源 | `original_order_id = 报价ID`、`original_order_no = 报价单号`、`remark='报价转单'` |
| **🔴 客户 ID 域错位** | `erp_sale_order.customer_id` 应指向 **ERP 往来单位（`biz_party`）**；本页 `customerId` 来自 **CRM 客户**（`crm_customer`，`form.vue:354-362`）或**硬编码 1–5**（`index.vue:933-939`）→ **违反《CRM模块/README.md》§1.1 红线** |
| ⚠️ 自造单号 | `orderNo = "QO" + yyyyMMdd + (orderId % 10000)`（`:391`），`orderId = System.currentTimeMillis() << 10 \| random`（`:390`）→ **未走 ERP 销售订单号段**，同表两套号规 |
| ⚠️ 审计缺失 | `erp_sale_order_item` 的 INSERT **不含 `tenant_id`/`create_by`/`update_by`**（`QuotationMapper.java:49-55`） |
| ⚠️ 明细金额 | 写 `item.unitPrice`/`lineAmount` → 因 §5.3 的 `unitPrice` 恒 `NULL`，**订单行单价与金额恒 0** |
| ⚠️ 边界 | 不占库存、不产生应收（「报价转单」的合理边界，**转单后仍需 ERP 侧审核**） |

### 5.7 审批能力（后端齐全，**前端零入口**）

| 列 | 后端公式（`calculateAmounts`，`:424-443`） | 前端「费用汇总」 | 一致？ |
|----|------------------------------------------|-----------------|:------:|
| `total_amount` | **`Σ line_amount`（未扣折扣）** | 「产品金额」（前端算**折后**） | ❌ |
| `discount_amount` | `Σ discount_amount` | 「折扣金额」 | ✅ |
| `tax_amount` | `Σ tax_amount` | （无此项） | — |
| `final_amount` | `total_amount − discount_amount + tax_amount` | 「报价总额」（= 折后净额） | ⚠️ 语义对应但**绑错了列** |

**三重口径**：A = `Σ qty×price`（未扣折扣，DB `total_amount`，**列表列的「报价总额」绑的是它**）｜B = `Σ qty×price×(discount/100)`（DB `discount_amount`）｜C = A − B（DB `final_amount`，**表单预览的「报价总额」是它**）。
→ **同一张单：表单里看 90 元，保存后列表变 100 元**。**必须统一**（表单预览显示 A/C，列表列改绑 `final_amount`）。

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-crm*.cjs`）。落地脚本命名 `tools/e2e-crm.cjs`（界面 + 接口 + 直连 DB 对账 + 写库后复原）。
> **2026-09-18 更新**：下列条目中，`title` 恒 NULL（§10.1-③⑨）、`send` 不带 `method` 必 400（§10.1-⑱、§10.2-⑰）、`DELETE /{id}` 404（§10.1-㉓、§10.2-⑯）、编辑时明细恒空（§10.2-㉔）**均已在 §9.0 处置**，验收时改按「修复后」断言；其余条目仍按原样断言。

### 10.1 接口验收（建议 ≥ 34 项）

**基础查询**：① `GET /page` 默认 200，`total` 与直查 DB（`deleted=0`+租户）一致；② `pageNum`/`pageSize` 生效（`pageSize=1` → `records.length===1`）；③ `keyword` 分别命中 `quotation_no`、`title`、`customer_name`（**当前 `title` 恒 NULL → 必失败**）；④ `customerId`/`opportunityId`/`salesPersonId` 逐个生效（后端已支持）；⑤ `status` 用 `Integer` 逐值 0–8（**用字符串传必须 400** — 断言当前缺陷）；⑥ `GET /export` 条数与 `page.total` 一致；⑦ `GET /statistics` 返回 9 个中文键，计数与 `GROUP BY status` 一致。

**创建与更新**：⑧ `POST /` 后 `quotation_no` 匹配 `^QT\d{8}\d{4}$`、`status=0`、`version=1`、DB 可回读；⑨ **`title` 应有值（当前 NULL）**；⑩ 传 `items` 后 `crm_quotation_item` 行数与 `line_no` 连续（从 1），**`unit_price` 应有值（当前 NULL）**；⑪ `total_amount`/`final_amount` 与手算一致（口径 = `Σ qty×price` 未扣折扣）；⑫ `PUT /{id}` 草稿成功、非草稿 400「只有草稿状态的报价单可以修改」；⑬ `PUT /{id}` 传 `items` 时**明细全删重建**（旧 `item.id` 不再存在）；⑭ 连续创建 2 单号不重复且序号 +1；**并发创建断言不撞号（当前预期撞号）**。

**状态机**：⑮ `submit` 0→1，非 0 → 400；⑯ `approve` 1→2 且 `approved_*` 落库，非 1 → 400；⑰ `reject` 1→**0** 且 `rejected_*` 落库，非 1 → 400，**不带 `reason` → 400**；⑱ `send` 2→3 且 `sent_*` 落库，非 2 → 400，**不带 `method` → 400**（断言当前缺陷：前端必失败）；⑲ `accept` 3→4，非 3 → 400；⑳ `reject-by-customer` 3→5，不带 `reason` → 400；㉑ `cancel` → 8；`status=7` → 400；不带 `reason` → 400；**断言 `remark` 被原因覆盖**（已知行为）；㉒ `DELETE /batch` 传 2 个 ID 后 `deleted=1`；㉓ **`DELETE /{id}`（前端在调）当前 404**（修复后改断言 200）。

**跨模块与明细**：㉔ `POST /{id}/convert` 4→7 且 `erp_sale_order`/`erp_sale_order_item` **各新增对应行**（断言 `original_order_id=报价ID`、`order_no` 非空、明细行数一致）；㉕ 非 4 状态转单 → 400；**重复转单 → 400**；㉖ **`erp_sale_order.customer_id` 应指向合法 ERP 往来单位**（**当前写入 CRM 客户 ID → 断言缺陷**）；㉗ `GET /{id}` 的 `itemCount` 正确，**断言返回体不含 `items`**（已知行为）；㉘ `GET /{id}/items` 行数与 `line_no` 升序正确；㉙ `POST/PUT/DELETE /{id}/items*` 草稿成功、非草稿 400；㉚ `POST /{id}/items/reorder` 后 `line_no` 按传入顺序重排；㉛ `POST /{id}/copy` 生成新单（标题含 `(副本)`、明细一致、`status=0`）；㉜ `POST /{id}/new-version` 的 `version=max+1`（标题含 ` V{n}`），`GET /{id}/versions` 可查回；㉝ `POST /from-opportunity/{id}` 的 `quotation_date=今天`、`valid_to=今天+30天`、`title='商机报价单'`；㉞ `POST /from-template/{id}?customerId=x` → **断言当前忽略参数**（登记缺陷）；㉟ `GET /expired` 只返回 `status IN(3,4) AND valid_to<今天`，`POST /mark-expired` 后置 6；㊱ **报价模板 15 端点冒烟**；㊲ **写库隔离**：所有写断言后**按原值复原**或使用专用测试单并清理。

### 10.2 UI 验收（建议 ≥ 27 项）

**入口与骨架**：① 菜单 `CRM → 报价管理 → 报价单`（`70330`）点开**直接进录单页**；标签 `历史` 跳到**列表页** —— **双入口方向校验（与客户/线索/商机/合同相反）**；② 列表页 4 张统计卡渲染，**「已发送」「已接受」应有非零值**（当前恒 0）；③ 表格 9 列渲染，**状态列应显示中文标签**（当前 `0`/`7` 显示空白）；④ **报价单号列应非空**（当前 `formatter` 失效可能抛 `TypeError`）；⑤ **有效期列应显示 `N天`**（当前 DB 无 `valid_days` → 恒 `0天`）。

**配置与查询**：⑥ 表头齿轮可改列显隐/顺序，刷新后**个人配置保留**且**不与其它页串配置**（当前共用 `product-unit-columns-config`）；⑦ 筛选 4 项**逐个生效**（当前 `status` 必 400、`quotationNo`/`quotationName`/`customerName` 被忽略）；⑧ 搜索框命中 `quotation_no`/`customer_name`（**`title` 当前命中不了**）。

**列表动作**：⑨ `Ctrl+N` 打开新增弹窗、`F5` 刷新、`crm:create`/`crm:refresh` 跨页事件生效；⑩ **客户下拉应有真实客户**（当前是 5 条硬编码）、**搜索过滤应生效**（当前恒不过滤）；⑪ 新增→填齐必填→保存→提示 `保存成功`→列表出现新行，**断言网络无 4xx**；⑫ 保存后 **DB 中 `title`/`valid_to`/`contact_name` 应有值**（当前 NULL）；⑬ 明细：添加行、改数量/单价/折扣 →「小计」实时更新；删除行（`>1` 行时）生效；⑭ 「产品金额」与「报价总额」应分别显示**未扣折扣额**与**折后净额**（当前恒相等）；⑮ 编辑（仅 `draft`）→ 保存 → 列表更新；⑯ 「删除」（仅 `draft`）→ 二次确认 → **断言网络 200**（当前必 404）；⑰ 「发送」（仅 `draft`）→ **断言网络 200**（当前必 400）；⑱ 「转订单」（仅 `accepted`）→ 确认 → 提示 `报价已成功转为订单` → **断言 `erp_sale_order` 新增行**；⑲ 「打印」→ 断言不报错且 `documentId` 与 `record.id` **字符串相等**（当前 `Number()` 精度失真）；⑳ 更多下拉：「复制报价」拷明细到新建弹窗；**「下载PDF」「版本历史」当前为 `message.info` 桩**（接线后改断言）；㉑ 详情抽屉 12 项渲染，**「有效期」应显示 `N天`**（当前恒 `0天`），底部三个按钮按状态显隐；㉒ 批量勾选 → **「批量删除」应发请求**（当前按钮无监听）。

**表单页与全局**：㉓ `Ctrl+S` 保存、`Ctrl+Enter` 提交**应生效**（当前仅提示文字）；「提交」**应调 `/{id}/submit`**；㉔ 编辑已有报价时**明细应回填**（当前 `GET /{id}` 不含 items → 恒空）；㉕ 「审批流程」卡在有记录时应显示时间线（当前恒灰色占位）；㉖ 空态三态：加载失败「重试」/ 有筛选「清除筛选」/ 无数据「新建第一个报价」；㉗ 页面控制台**无 error**（含 `ReferenceError`/`TypeError` —— 参见《重构搬迁后必须做运行时验证》）。
