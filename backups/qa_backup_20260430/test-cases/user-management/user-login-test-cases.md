# 用户登录功能测试用例

## 测试目标
验证用户登录功能的正确性和安全性

## 测试环境
- 环境：Sprint 27+1 测试环境
- 服务：用户管理模块
- API端点：POST /api/v1/auth/login
- 数据库：测试数据库

## 测试用例设计

### 1. 正常用户登录测试

#### TC-UL-001: 正常用户登录
**测试描述**: 验证正常用户登录流程
**前置条件**: 
1. 用户"testuser001"已注册（密码: Test@12345）
2. 用户状态为ACTIVE

**测试步骤**:
1. 发送POST请求到 /api/v1/auth/login
2. 请求体包含正确的用户名和密码
3. 验证响应状态码为200 OK
4. 验证响应包含登录令牌
5. 验证用户信息正确返回

**测试数据**:
```json
{
    "username": "testuser001",
    "password": "Test@12345"
}
```

**预期结果**:
- 响应状态码: 200
- 响应体: {"success": true, "message": "登录成功", "data": {...}}
- 响应包含token字段
- 响应包含userInfo字段

---

**前置条件**:

**测试步骤**:
1. 发送POST请求到 /api/v1/auth/login

3. 验证登录成功

**测试数据**:

**预期结果**:
- 响应状态码: 200

### 2. 异常登录场景测试

#### TC-UL-003: 错误密码登录
**测试描述**: 验证错误密码登录失败
**前置条件**: 用户"testuser001"已注册

**测试步骤**:
1. 发送POST请求到 /api/v1/auth/login
2. 使用错误的密码
3. 验证登录失败

**测试数据**:
```json
{
    "username": "testuser001",
    "password": "WrongPassword123"
}
```

**预期结果**:
- 响应状态码: 401
- 响应体: {"success": false, "message": "用户名或密码错误"}

---

---

#### TC-UL-007: 连续失败登录锁定
**测试描述**: 验证连续失败登录触发账户锁定
**前置条件**: 用户"testuser002"已注册

**测试步骤**:
1. 连续5次使用错误密码登录
2. 第6次使用正确密码登录
3. 验证账户被锁定

**测试数据**:
```json
{
    "username": "testuser002",
    "password": "WrongPassword"
}
```

**预期结果**:
- 前5次: 响应状态码401
- 第6次: 响应状态码403，消息"账户已被锁定"

### 3. 登录数据验证测试

#### TC-UL-008: 登录令牌有效期验证
**测试描述**: 验证登录令牌有效期
**前置条件**: 用户登录成功

**测试步骤**:
1. 成功登录获取token
2. 等待token过期
3. 使用过期token访问受保护接口
4. 验证token失效

**测试数据**: 正常登录数据

**预期结果**:
- 过期后访问接口返回401
- 错误消息: "令牌已过期"

---

#### TC-UL-009: 登录时间记录验证
**测试描述**: 验证登录时间被正确记录
**前置条件**: 用户登录成功

**测试步骤**:
1. 用户登录
2. 查询数据库用户记录
3. 验证lastLoginTime被更新

**测试数据**: 正常登录数据

**预期结果**:
- 数据库中的lastLoginTime字段被更新
- 更新时间接近当前时间

---

#### TC-UL-010: 登录IP记录验证
**测试描述**: 验证登录IP被正确记录
**前置条件**: 用户登录成功

**测试步骤**:
1. 从不同IP地址登录
2. 查询数据库用户记录
3. 验证lastLoginIp被更新

**测试数据**: 正常登录数据

**预期结果**:
- 数据库中的lastLoginIp字段被更新
- IP地址与请求IP一致

### 4. 安全性测试

#### TC-UL-011: SQL注入攻击防护
**测试描述**: 验证系统对SQL注入攻击的防护
**测试步骤**:
1. 发送包含SQL注入代码的登录请求
2. 验证系统正确处理

**测试数据**:
```json
{
    "username": "admin' OR '1'='1",
    "password": "anything"
}
```

**预期结果**:
- 响应状态码: 400 或 401
- 系统不会执行SQL注入

---

#### TC-UL-012: XSS攻击防护
**测试描述**: 验证系统对XSS攻击的防护
**测试步骤**:
1. 发送包含XSS脚本的用户名
2. 验证系统正确处理

**测试数据**:
```json
{
    "username": "<script>alert('xss')</script>",
    "password": "Test@12345"
}
```

**预期结果**:
- 响应状态码: 400
- XSS脚本不会被执行

---

#### TC-UL-013: 暴力破解防护
**测试描述**: 验证系统对暴力破解的防护
**测试步骤**:
1. 短时间内发送大量登录请求
2. 验证系统触发限流机制

**测试数据**: 各种用户名密码组合

**预期结果**:
- 超过阈值后返回429 Too Many Requests
- 系统提示"请求过于频繁"

## 测试指标
- 登录成功率: ≥99%
- 响应时间: ≤200ms
- 并发用户数: ≥1000
- 安全性漏洞: 0
