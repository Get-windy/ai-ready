## 业务规范说明

- **单一口径（红线）**：银行账户数据在 `finance_account`（`FinanceAccountController` `/api/erp/finance/account`），本页复用同一张表，**未另建重复银行账户表**。
- **同源关系**：本页与《支付账户》（`md:payment-account`）同源 `finance_account`，银行账户是资金账户的视图（账户类型/科目载体/商城线下转账收款开关 + 开户行/账号/户主名等）。
- **对标口径**：ql361 银行账户以**会计科目为载体**（科目编号/科目名称），配「账户类型」与「是否用于商城线下转账收款」属性；本系统 `finance_account.subject_code` 即该「科目编号」，与 `finance_account_subject.subject_code`（会计科目表）对齐。
- **层级**：`parent_id` 父子挂接，`显示层次结构` 勾选时按深度优先展开（父在前、子缩进 16px/级），行首文件夹图标（有下级）/叶子图标，▸▾ 可逐级展开收起。
- **系统预置保护**：标准资金科目 `1001`/`1002`（或 `is_system=1`）账户禁止改编号、禁止删除；有下级账户、余额不为 0 时禁止删除。

### 实现差异（与对标的取舍，均已复核）
1. **默认列**：对标默认显示 4 列；本系统另默认显示「状态」1 列（否则勾选「显示停用」后无法分辨停用数据），其余字段一律默认隐藏、可在列配置勾选。
2. **账户类型字典**：沿用本系统 `account_type`（1 银行 / 2 现金 / 3 内部 / 4 外部），未采用对标下拉的「现金」默认值；新增银行默认「银行账户」。
3. **预置数据**：对标演示数据含 `1001 现金库存`、`1002 银行存款` 两条预置行；本系统**不造预置数据**（`finance_account` 被收付款/提存/费用单等账户下拉共同引用，注入纯科目节点会污染下拉），页面展示真实资金账户（实测 3 条：库存现金 / 基本户-招行 / 一般户-工行）。
4. **上级账户字段**：对标行内「修改」弹的是「分类信息--编辑」（分类名称/层级编号）；本系统统一用「银行信息」弹窗并显式提供「上级账户」树选择器 + 编号联动（对齐「层级编号」语义，且避免两套编辑入口）。
5. **无页面配置弹窗**：与对标一致（本页无查询条件/功能按钮两级页面配置），列配置只保留数据表表头齿轮入口。
6. **空行补齐（2026-09-12 修正）**：数据表按组件默认补足 **20 行**（原实现传 `:min-rows="1"` 只渲染真实行，表格下方留大片空白）。配套在共享组件 `BillDetailTable` 增加只读分支保护：`isViewMode && record.__ghost` 的空行**除行号外渲染空白**，修复空行在无插槽列（如科目编号）显示 `-` 占位符的问题；可编辑明细（非 viewMode，如单据表单）**不受影响**。该组件修正对《会计科目》《费用类型》《其他收入》《商品辅助资料》等所有使用 `minRows` 的只读列表页同样生效。
