**语义与校验（ql361 源码 `onLogisticsRemarkClick` 实测口径）**：

- 所有字段**可空**，**留空 = 不改动该字段**（弹窗允许只填其中几项）。
- **批量前置条件**：所选单据必须「**单据状态相同**」且「**配送方式相同**」，否则整批拒绝（提示"请选择单据状态相同的单据进行操作"）。
- **配送中的预算**：`status ≥ 3（部分发货）` 的单据**不允许修改配送方式**（其余字段仍可改）。
- 全空提交（一项都没填）整批拒绝。

> ⚠️ **运单号不是本页列表列**（ql361 37 列里没有「运单号」）——它只在这个弹窗里维护；
> ql361 的「运单号」列出现在**另一处**：`商城 → 订单处理`（本系统 `mall/order-process`，39 列含 运单号/物流公司/运费）。

## 4. 业务规范

- **阶段定位**：订单处理中心三阶段 `全部 / 1.待审核 / 2.拣货/发货` 的第 3 阶段，承载「拣货 → 集货 → 发货」动作。
- **拣货作业字段**：拣货仓库、集货位（拣货目标位）、已拣货数量/未拣货数量（隐藏列）——**拣货与发货数量分离跟踪**。
- **发货作业字段**：已发货数量/未发货数量（隐藏列）、预计发货时间、配送方式、物流公司、配送司机、提货地址、收货人/联系电话/收货地址（隐藏列）。
- **状态**：实测行「待发货」，即拣货完成待发货。
- **来源**：单据来源（实测值「微商城」）、单据备注。
- **与配送的关系**：发货完成后进入配送环节（《配送查询》配送任务），物流方式由「配送方式/物流公司」决定。
- **按钮语义**：`拣完批量发货`（批量执行拣货完成 + 发货）、`物流备注`（批量写物流备注）、`商品汇总`（按商品维度汇总当前结果）。

### 5.2 后端接口（`cn.aiedge.erp.sale`，`/api/erp/sale/order`）

| 接口 | 说明 |
|------|------|
| `GET /center/picking-shipping` | 阶段分页（status ∈ 2,3）；支持 单据日期/单据编号/客户/经手人/仓库/提交时间/打印次数/**区域**/物流公司/配送方式/配送司机/表头自定义字段 1-5 等条件 |
| `GET /center/picking-shipping-summary` | **合计**（销售金额 / 商品数量 / 单据数），与列表**同查询条件**全量汇总 |
| `POST /{id}/pick-complete` | **拣完**：逐行回写 `erp_sale_order_item.picked_quantity = 订货数量 − 已发数量`，主表 `picked_quantity` 汇总；状态门控（仅 2/3 可拣），拣货仓库未指定时以订单仓库兜底 |
| `POST /batch-pick-complete` | **批量拣完**：逐单尽力而为，返回成功单数（单张状态不允许时跳过） |
| `POST /{id}/ship` | **发货**（复用）：扣减/解冻库存 → 状态流转 3/4 → 生成销售出库单 `XSCKD-` |
| `POST /batch-logistics-remark` | **物流/备注**（批量 + 行内单条共用）：入参 `SaleLogisticsRemarkDTO`（§3.1 的 15 字段 + `ids`，**空值不改动**）；校验「同状态 + 同配送方式」与「配送中不可改配送方式」；返回实际更新单数 |

**拣货与发货数量分离跟踪**：`pickedQuantity`（拣货作业回写）与 `shippedQuantity`（出库回写）两个口径独立，`unpickedQuantity` 为派生值（订货 − 已拣），列表与合计均取自同一处计算。

### 5.5 已知偏差（非阻塞）

1. **快捷时间段**：ql361 在查询方案右侧有 `昨日/今日/本周/近一周/本月/上月/近三月/本年` 段；本系统该视图的工具栏左侧被「查询方案」占用，快捷段未渲染（日期范围选择器仍在，默认「近一周」）。属《订单处理中心》整体交互设计，改动会影响销售域，未在本页单独处理。
2. **分页栏样式**：沿用 `DocCenterLayout` 内置分页（「共 N 条记录 / 每页 20」），非 ql361 的经典分页栏。
3. **打印配置**：ql361 打印模板配置弹窗本次未展开复核，本页页面配置隐藏「打印配置」Tab（`hide-print-config`）。
4. **行内「更多」的「修改 / 终止」未接**：ql361 行内动作实测为 `取消 / 拣完 / 发货 / 更多(修改·终止·物流/备注)`，本次已补「物流/备注」；「修改」= 打开销售订单草稿、「终止」= 终止订单，属《销售订单》域能力，未在本页重复实现。
5. **配送方式与司机仍是自由文本**：ql361 该弹窗这两项也是输入控件；本系统未强制接《物流公司》《配送员》档案选择器（`driver_id` 已预留）。若后续要联动档案，改弹窗控件即可，落库与校验不变。

## 6. 生产级物流能力（P0/P1/P2，2026-09-14）

> **背景**：§5 之后按《物流发货-业界做法调研.md》把 ql361 的「表头两列 + 一个弹窗」升级为业界模型：
> **发货单 → 出库单 → 运单/包裹（承运商 + 运单号 + 件数重量 + 运费）**。
> 关键前提：系统里**本来就有** 1:N 物流子表 `erp_sale_order_logistics`（后端已实现、前端未接线、0 行）——本次是**接线 + 补齐**，不是造轮子。

### 6.1 P0 · 接线与口径统一

| 项 | 实现 |
|----|------|
| **物流信息改落子表** | 物流备注（弹窗批量 / 行内单条）写 `erp_sale_order_logistics` 的**默认包裹**（id 最小的一条；无则建 `P1`）；**主表 `logistics_company/waybill_no/delivery_method/driver_name` 降级为「列表展示快照」**，由 `syncOrderSnapshot` 从默认包裹回写——拣货/发货 37 列读的仍是主表，展示口径不变、双写一致 |
| **承运商引用档案** | 弹窗「物流公司」改为 `a-auto-complete`：可选《资料 → 物流公司》（`partnerType=LOGISTICS`，即 `biz_party` 物流身份），也可手输兜底；落 `logistics_company_id` + 名称快照 `logistics_company`（服务端按 id 自动补名） |

### 6.2 P1 · 一单多包

- 子表按**包裹**语义使用：一条记录 = 一个包裹（`package_no/count/weight/volume/status`）。
- 新增接口：`GET/POST /api/erp/sale/logistics/{orderId}/packages`、`DELETE .../{packageId}`。
- 规则：包裹号自动 `P1/P2…`；**运单号唯一**（防重复录号/重复取号）；**最后一个包裹不允许删除**（可清空不能删，避免快照悬空）；保存时**按运费规则自动试算** `shipping_fee`（可手工覆盖）。
- 发货时 `markPackagesShipped` 把该单所有待发包裹置「已发货」。
- 前端：拣货/发货行内「**更多 → 包裹/运单**」抽屉（`components/business/SalePackageDrawer`）。

### 6.3 P2-4 · 承运商运费规则 + 对账

- 新表 `erp_freight_rule`：按 **承运商 × 区域 × 重量区间** 取 首重/续重/基础费；匹配优先级 承运商+区域 > 承运商 > 区域 > 通用（同级按 priority）。
- 算法：`首重价 + 基础费 + ⌈(重量−首重)/续重步长⌉ × 续重单价`（向上取整）。
- 对账：子表新增 `freight_bill_amount`（承运商账单）/`freight_diff`/`freight_reconciled`；`GET /freight/reconcile` 出**运单级差异清单 + 汇总**（我方计费 vs 账单），支持录入账单金额与标记已对账。

### 6.4 P2-5 · 电子面单取号（配置化，不造假号）

- 配置：`erp.logistics.waybill.enabled/url/token/response-path`（外部服务密钥一律落 core-api `application.yml` / 环境变量，见 README §7）。
- **未配置 → 明确报错**「电子面单未开通：请配置 … 或直接手工录入运单号」，**绝不返回假号**（假号会污染对账与轨迹）——与地图 Key「宁可降级不造假」同款策略。
- 已配置 → 真实 HTTP 调承运商接口取号，按 `response-path` 解析，取号后仍做**运单号唯一校验**，并同步主表快照。

### 6.5 P2-6 · 发货通知（ASN）

- 新表 `erp_shipment_notify`：发货后按 **订单+运单号**（`idempotent_key`）**幂等**生成台账（无运单号不生成，避免空通知）。
- 推送：`erp.shipment.asn.callback-url`（+ token）；**未配置时只落台账并记录原因（不算失败）**，配置后点「发送」或批量发送即可；失败累计 `retry_count` 与 `last_error`，可重试。

### 6.6 新增页面与接口

- **菜单 `70162 物流运费对账`**（配发收 → 发货业务，本系统新增能力，迁移 `V11.341.0`）：三 Tab = 运费规则 / 运费对账 / 发货通知。
- 后端 `SaleLogisticsController`（`/api/erp/sale/logistics`）：包裹 CRUD、取号、运费规则 CRUD/试算/对账/账单录入/标记对账、ASN 台账/发送/批量发送。
