## 页面概述

待确认款项是**已申报未到账款项的确认工作台**：业务端（订单在线支付/配送代收/转账）申报款项 → 本页核对到账 → 确认入账。含两个子标签（收款待确认 / 预收款待确认），单入口。

| 页面 | 地址 | 说明 |
|------|------|------|
| 待确认款项 | `finance/pending-confirm` | 列表查询 + 2 子标签 + 单行/批量确认 |

单入口：财务 → 收款 → 待确认款项。

### 配置功能说明（对标实测）
- **页面配置**：页面顶部按钮区域「配置」齿轮。本页页面配置弹窗**仅「查询条件」一个 Tab**（无「功能按钮」Tab）。含隐藏项的全量字段。
- **列配置**：数据表右上角表头单元格齿轮图标（`icon-shezhi2`）。列配置弹窗结构：个人配置 Tab / 全局配置 Tab，配置列：上级、列名、显示名、显示；支持上移/下移/恢复默认/保存。**每个子标签一套独立列配置**。
- ⚠️ **当前实现说明**：本页尚未升级金标准组件，见「实现差异说明 → 待完善」。

## 本系统实现（当前代码 · 2026-09-07 金标准升级）

- **列表页**：`CategoryListLayout` + `BillTableList`（列表双 Tab：收款待确认 / 预收款待确认）+ `ColumnConfigPanel`（列配置）+ `PageConfigPanel`（页面配置，仅「查询条件」Tab）。
- **收款待确认**：查 `erp_receipt`（待核销/核销中 status=4,5），21 列（默认显示12），确认动作=完成核销（`complete-verify` → 已核销）。
- **预收款待确认**：查 `erp_pre_receipt`（草稿 status=draft），14 列（默认显示9），确认动作=记账（`confirm`，预收余额增加 + 生成凭证）。
- **批量确认**：单行 + 批量（`/erp/receipt/batch-confirm`、`/erp/pre-receipt/batch-confirm`）。

## 业务规范说明

- **款项主线**：业务端申报款项 → 「收款待确认」（预收款走「预收款待确认」）→ 财务核对到账 → 确认（单行/批量）→ 入账，回写来源单据收款状态。
- **未确认不计入账户余额**：确认动作即"到账入账"，确认后资金口径与查资金/账户余额一致。
- **双账户结构**：收款待确认一笔款项最多两个收款账户组合到账（收款账户1/金额1、收款账户2/金额2；可配置扩展收款账户3/4/金额3/4，默认隐藏）。
- **来源追溯**：来源订单、配送任务编号可追溯至商城/销售订单与配送任务（司机代收或客户线上支付）。
- **收款侧回写**：确认后回写《按单收款》/销售单据已结算；预收确认后增加《预收款单》预收余额。
- **凭证列**：列配置含「凭证」列（默认隐藏），确认记账后生成会计凭证（`KJPZ-`）。

| 级别 | 问题 | 修复要点 | 状态 |
|---|---|---|---|

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 到账单一口径（红线）**：待确认款项确认动作即"到账入账"，**严禁未确认即计入账户余额**；确认后必须回写来源单据收款状态/预收余额。
- **P1 分流入账**：收款确认回写《按单收款》/销售单据已结算；预收确认增加《预收款单》预收余额（2203）。
- **P1 追溯**：来源订单/配送任务编号追溯至商城/销售单与配送任务（司机代收/线上支付）。
- **P2 验收**：无桩/无模拟；双账户结构、批量确认、来源回写需真实数据闭环验证。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
