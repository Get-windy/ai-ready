## 页面配置

### 查询条件

按抓取 JSON filterLabels 实据（往来单位、仓库、经手人、部门、制单人）与截图/bodyPreview 确认的全量展开项：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止）、单据编号、单据类型（下拉，默认"全部单据"）、往来单位、仓库、经手人
- 部门、制单人、单据备注
- 勾选项：过账时自动修改单据日期为当前登录日期

### 功能按钮

按抓取 JSON buttons 实据：刷新、提交记账、删除、更多、查询、跳转（分页跳转）

- **提交记账**：勾选草稿后批量过账（草稿 → 正式单据，进入经营历程）
- **删除**：勾选后批量删除草稿
- 行级操作（截图实据）：删除、复制
- **更多**：折叠其余批量动作（具体内容待复核）

### 打印配置

无（本页无打印按钮实据；草稿不过账不打印）

## 业务规范说明

### 统计口径与数据关系

- **数据范围**：全部业务域已保存但未过账的草稿单据（Ctrl+S 保存草稿，销售域表单页快捷键实据）。一行一单，金额列为单据金额，合计行对金额求和
- **来源订单列**：草稿由订单下推生成时记录来源订单号（本批次实据该列均为空，均为手工开单）
- **提交记账（过账）**：草稿过账后成为正式单据，从本页消失并进入《经营历程》；勾选"过账时自动修改单据日期为当前登录日期"则过账日替换原单据日期（跨期补录场景）
- **组内分工**：业务草稿（未过账）→ 提交记账 → 经营历程（已过账流水）；需审批的单据类型过账后先进入《待审批单据》

### 与其他页面关系

- 上游：各业务域表单页"保存草稿 Ctrl+S"（销售订单/销售出库单/采购入库单/收款单等，截图实据含 XSCKD/SKD/CGRKD 三类）
- 下游：提交记账 → 经营历程；单据编号链接 → 打开对应单据表单页（草稿态可继续编辑）
- 同组页面：待审批单据、经营历程

### 架构师红线（Ponytail六步过滤网）

动手前必过六关：①此功能业务真需要？②标准库/原生API能搞定？③现有依赖能否复用？④能否一行代码干净解决？⑤能否复用已有组件？⑥通通走不通才写最小可用闭环。**Lazy, not negligent**——跨边界防注入、容灾、安全防御代码不准省。

### 业务逻辑要求

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑和交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。

## 验收标准

- 没有桩（Stub）与模拟（Mock）数据：代码中不得出现 TODO、FIXME、stub、模拟、mock、假数据、临时、演示、示例、占位、placeholder，确保使用真实数据
- 查询条件（含制单人、单据类型、单据备注）真实过滤；查询方案可保存
- 13 个默认列真实渲染；金额合计行与分页正确
- 勾选多条后"提交记账/删除"批量真实生效：过账后草稿从本页消失、进入经营历程，库存/往来等下游数据真实联动
- "过账时自动修改单据日期为当前登录日期"勾选真实生效
- 行级删除/复制真实可用；单据编号链接打开对应草稿表单
