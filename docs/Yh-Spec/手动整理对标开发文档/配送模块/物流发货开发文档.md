# 物流发货开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`dispatch/logistics-ship`
> 对标菜单：**配发收 → 发货业务 → 物流发货**（实测 menuId `47001`，billType `2341`）
> 数据来源：**Playwright 实测抓取（2026-09-12）**——列配置弹窗 + 页面配置弹窗（查询条件 / 功能按钮）+ 页面结构 + 截图。
> 通用规范见《对标开发技术参考文档》第 4、5 章，本文不重复。

## 1. 页面概述

- **列表操作页（入口直达型）**：本菜单**不是独立页面**——实测点击「物流发货」打开的是**「订单处理中心」**并自动选中内层 Tab **「2.拣货/发货」**。
- 因此落地时必须**复用《订单处理中心》的拣货/发货阶段视图组件**，不重复造页面（通用原则「功能/模块不重复开发」）。
- 同级 Tab：`全部` / `1.待审核` / `2.拣货/发货`；页面标题随 Tab 变化。
- 截图：`tool-results/ql361/pages/配发收__发货业务__物流发货.png`

### 实测行数据与行级操作

- 行示例：`2026-09-12 ｜ XSDD-20260912-013 ｜ 待发货 ｜ 打印次数 0 ｜ 酒洲种业冷库 ｜ 肃州区品轩瓦香鸡餐饮店 ｜ 125 ｜ 1 ｜ 杨生淮 ｜ 物流 ｜ 微商城`。
- 行级操作（实测可见）：**取消**、**拣完**、**发货**、**更多**。
- 合计行：`合计 503 ｜ 5`（销售金额合计 / 商品数量合计）。
- **下游单据编号为 `XSDD-`（销售订单号）**：本页操作对象是销售订单在拣货/发货阶段的视图，发货后生成销售出库单 `XSCKD-`（见《发货查询》）。

## 4. 业务规范

- **阶段定位**：订单处理中心三阶段 `全部 / 1.待审核 / 2.拣货/发货` 的第 3 阶段，承载「拣货 → 集货 → 发货」动作。
- **拣货作业字段**：拣货仓库、集货位（拣货目标位）、已拣货数量/未拣货数量（隐藏列）——**拣货与发货数量分离跟踪**。
- **发货作业字段**：已发货数量/未发货数量（隐藏列）、预计发货时间、配送方式、物流公司、配送司机、提货地址、收货人/联系电话/收货地址（隐藏列）。
- **状态**：实测行「待发货」，即拣货完成待发货。
- **来源**：单据来源（实测值「微商城」）、单据备注。
- **与配送的关系**：发货完成后进入配送环节（《配送查询》配送任务），物流方式由「配送方式/物流公司」决定。
- **按钮语义**：`拣完批量发货`（批量执行拣货完成 + 发货）、`物流备注`（批量写物流备注）、`商品汇总`（按商品维度汇总当前结果）。

## 5. 实现差异说明（本系统现状）

| 项 | 对标实测 | 本系统现状 | 差距 |
|----|---------|-----------|------|
| 页面形态 | 订单处理中心 2.拣货/发货（复合页直达） | `views/dispatch/logistics-ship/index.vue` 独立 `ARReportPage` 列表 | 应对齐为**复用订单处理中心阶段视图**的直达入口，而非独立页 |
| 数据源 | 销售订单阶段视图（含拣货/发货数量双跟踪） | `outboundApi.page`（销售出库单 SaleOutbound） | 口径不符：应以销售订单为行对象，出库单为下游产物 |
| 列 | 37 列（默认 17） | 10 列（出库单口径） | 按第 3 章 37 列重建 |
| 查询条件 | 16 项 | 4 项（出库单号/关键字/状态/出库日期） | 按第 2 章补齐 |
| 功能按钮 | 刷新/批量打印/商品汇总/拣完批量发货/物流备注/配置 | 仅「发货」行内按钮 + 发货登记弹窗 | 补批量发货、商品汇总、物流备注 |
| 行级操作 | 取消 / 拣完 / 发货 / 更多 | 仅发货（状态 9 → ship） | 补取消、拣完、更多菜单 |
| 状态口径 | 待审核 / 拣货 / 待发货 / 已发货 | OutboundStatus 0–12（出库单全流程枚举） | 需按订单处理中心阶段口径映射 |

### 待完善（对齐金标准）

1. **入口直达**：`dispatch/logistics-ship` 应打开订单处理中心并选中「2.拣货/发货」（复用其组件与列配置），避免与《订单处理中心开发文档》重复实现。
2. 列/查询/按钮按第 2、3 章重建，`storage-key` 建议共用订单处理中心拣货/发货的视图键。
3. 行级操作补齐「取消 / 拣完 / 发货 / 更多」；`拣完批量发货` 支持多选行。
4. 后端需基于销售订单 + 拣货/发货数量（已拣/未拣/已发/未发）提供阶段分页接口。
