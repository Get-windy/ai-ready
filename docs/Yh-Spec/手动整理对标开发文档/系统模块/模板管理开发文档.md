## 1. 页面概述

模板管理页是**平台运营方的「导入模板目录」只读台账页**：以不分页表格列出后端内置的导入模板（模板名称 / 模板ID / 数据类型 / 版本 / 字段数 / 最大导入行数 / 校验模式 / 描述），并提供「预览字段结构 / 下载 xlsx 模板 / 删除模板」三个行内动作。它是 `61305 开发工具` 组的第 1 页（`sort = 200`）。

> **⚠️ 本页的核心事实（先读这一条）**：本页的数据源**不是数据库、也不是文件**，而是**后端硬编码在 Java 里的 4 个模板定义**（`ImportTemplateRegistry.java:109-121`，进程启动时由 `@PostConstruct init()`（`:26-31`）注册进两个 `ConcurrentHashMap`（`:23-24`））。因此本页**全程不读写任何数据库表**，**删除不持久化（重启即复活）**。

### 3.8 数据获取与错误处理（`fetchData`，`:173-183`）

```ts
async function fetchData() {
  loading.value = true
  try {
    const res = await importTemplateApi.list()
    list.value = Array.isArray(res) ? res : []
  } catch {
    list.value = []          // ← 静默吞掉错误，且把列表清空
  } finally { loading.value = false }
}
```

**🔴 缺陷 P1-①：`catch` 静默吞错并把列表清空** —— `:178-180` 的 `catch {}` **无绑定变量、无 `message.error`、无任何提示**，且**主动把 `list` 置空数组**。后果：接口 404（本页当前实况）时用户看到的是**一张空表**，**没有「接口不存在」的提示** —— 这正是本模块最危险的失败模式（「页面空白而非报错」，README §1.3 红线②的同源表现）。对比：三个写动作（`:191`、`:208`、`:218`）**都有 `catch` + `message.error`**，唯独查询没有，**口径不一致**。

**响应解包口径（正确 ✅）**：后端返回**裸数组** `List<ImportTemplateDefinition>`（`:47-49` 用 `ResponseEntity.ok(...)`），前端 `admin.ts:421-425` 用 `request.get('/import-templates')`（注释明写「裸数组，拦截器透传」）→ `fetchData` 用 `Array.isArray(res) ? res : []` 兜底（`:177`）。**前后端口径一致**。

**无定时器**（`setInterval` / `setTimeout` 全文 **0 命中**）、**无事件监听 / 观察者**、仅一次性 `onMounted(fetchData)`（`:223`）、**无 `onUnmounted` / `onBeforeUnmount`** → **不存在需清理的资源，无泄漏风险**。

### 5.2 流转规则

本页**没有状态机**：模板定义是**内存对象**，只有「存在 / 不存在」两态。

```
（进程启动 @PostConstruct init() :26-31）──▶ registerDefaultTemplates() 注册 4 个模板
        │
   内存 Map 中存在（GET 可见）──┬─ POST   :71  ▶ 新增到 Map（无 DB、无文件）
                              ├─ PUT    :89  ▶ 覆盖 Map 中的对象（无 DB、无文件）
                              └─ DELETE :109 ▶ 从 Map 移除（无 DB、无文件）
        │
   （进程重启）──▶ 重新注册 4 个模板 ──▶ 被删的模板「复活」；POST/PUT 的改动全部丢失
```

| 动作 | 后端 | 前置校验 | 失败文案 | 副作用 | 行号 |
|------|------|:--------:|---------|--------|----|
| 列表 | `GET /api/import-templates` | 无 | — | 无 | `:45-49` |

| 删除 | `DELETE /{templateId}` | **无**（模板不存在也返回 **HTTP 200**，body 为 `{success:false,message:"模板不存在"}`） | 前端**只按 HTTP 状态判断** → **会提示「模板已删除」** | 仅内存 Map 移除；**无 DB、无文件** | `:109-117` |
| 新增 / 更新（前端均未接） | `POST ""`（`:71-87`）/ `PUT /{templateId}`（`:89-107`） | `templateId` 非空（否则 `badRequest`）／**模板必须已存在**（`IllegalArgumentException("模板不存在: …")`） | — | 内存 Map 新增 / 覆盖 | `:71-87`、`:89-107` |

### P1（7 条）

④ **`fetchData` 静默吞错并清空列表**（`:178-180` 的 `catch {}` 无提示、无日志、且把 `list` 置空）→ 接口失败时只显示空表，**是 P0① 难以被发现的原因**。建议补 `catch (e) { message.error(e?.message || '加载失败') }`，与三个写动作（`:192`/`:209`/`:219`）口径对齐。
⑤ **`DELETE` 失败返回 HTTP 200**（`ImportTemplateController.java:113-116` 用 `ResponseEntity.ok(...)` 而非 `notFound()`）→ 删除不存在的模板，前端仍提示「模板已删除」（`:213-217` 只看 HTTP）。**同一控制器内三种「不存在」口径并存**（`notFound()` / `sendError(404,…)` / `ok(success:false)`）。建议统一为 `notFound()`。
⑥ **9 个端点无前端**（30.8% 覆盖率）：`GET /{templateId}`、`GET /data-type/{dataType}`、`GET /data-types`、`POST ""`、`PUT /{templateId}`、`GET /data-type/{dataType}/download`、`POST /{templateId}/validate`、`POST /{templateId}/validate-row`、`GET /{templateId}/fields/{fieldName}/validation`。其中 `validate` / `validate-row` 是**导入链路的实际价值所在**，应优先补 UI。
⑦ **模板不可维护**：`POST`（`:71`）/ `PUT`（`:89`）后端就绪，**前端零入口**（无新增/编辑按钮、无表单页）→ 用户无法自定义模板。
⑧ **`dev_template` 孤岛 + `cn.aiedge.dev` 亦漏配扫描**：表 **12 列 / 7 行**（种子 `V6.17.0:87-88` 起）、实体 `DevTemplate.java:14`、Service/ServiceImpl/Mapper 齐备（`.../dev/service/DevTemplateService.java:10`、`.../dev/service/impl/DevTemplateServiceImpl.java:17-19`、`.../dev/mapper/DevTemplateMapper.java:8`），但**全仓无任何消费方**。建议二选一：明确废弃（删表/删代码，须迁移）或复用为模板落位（须先补控制器，见 §8.5）。
⑨ **`62401 代码生成` 空洞**：`sort=100` 位置空缺（`parent_id=61305` 实测仅 4 行，`sort` 为 200/300/400/500）；播种 `V6.13.0:361` → 物理 `DELETE` `V6.15.0:14`、`:48-49` → `V6.23.0:75-76` 以 `90002` 挂回 → `V9.5.0:69-73` 二次 `DELETE` 并把 `90002` 复用给 HR「考勤记录」（devdb 实测 `id=90002` → 「考勤记录」）。后端全仓 `codegen` 仅 **3 处命中**（全在迁移 SQL），无一实现。→ **该能力已判定不开发，本页 `a-alert` 的自述是准确的**；建议在 codegen 路线正式废弃后移除该常驻提示。
⑩ **未达金标准路线 A**：无 `ErrorBoundary`、无 `CategoryListLayout`/`BillTableList`、无表头齿轮、无 `PageConfigPanel`、无 `storage-key`、无经典分页（`StandardPagination`）—— 与 README §7.2「30 页全部无 `PageConfigPanel` / 无 `storage-key` / 无经典分页 / 无列配置齿轮」一致。另：**删/增/改模板零审计**（控制器全类无审计调用），应按 SAP SAL 字段口径落审计（README 红线③）。

### P2（8 条）

⑪ **面包屑与菜单层级不一致**：面包屑第二级写「**系统管理**」（`:12`），实际父级是 `61305 开发工具`（上溯 `60013 系统`）；「系统管理」是另一个分组（`61307`）的名字。建议改为「系统 / 开发工具 / 模板管理」。
⑫ **弹窗漏展示 `dropdownOptions`**：后端 `FieldPreview` 含 **8** 个字段（`ImportTemplateController.java:386-395`），前端预览子表只渲染 **7** 列（`:158-166`）→ 「下拉选项」信息丢失。建议加一列。
⑬ **下载 `Content-Type` 不精确**：`application/octet-stream`（`:132`、`:151`）而非 xlsx MIME。建议改用 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。
⑭ **无分页 / 无查询参数 / 无上限**：`:pagination="false"`（`:50`）、`getAllTemplates()` 无参（`:47-49`）；而 `POST` 可注册任意多个模板 → 数量增长后一次性全量渲染。建议补查询区（`dataType` / 模板名）+ `StandardPagination`。
⑮ **无统计卡 / 无页内 Tab / 无行选择 / 无导出 / 无打印 / 无快捷键**（全文）。
⑯ **`revokeObjectURL` 紧随 `click()` 同步执行**（`:206`），跨浏览器下载行为**未实测**。建议若发现「点了没文件」则改为延迟回收。
⑰ **无本系统验收截图、无模块级 E2E**（`tools/` 与 `tools/acceptance/` 下无 `e2e-system-*.cjs` / `e2e-admin-*.cjs`）—— 与 README §7.3 末条一致。建议落地 `tools/e2e-system.cjs`。
⑱ **「模板管理」命名有歧义**：本页管的是**导入模板**（`dataType` = user/customer/product/order），但页面挂着「代码生成（codegen）未实现」的常驻提示（`:34-39`），且同域存在 `dev_template`（**代码生成**模板表）与 `sys_print_template` 等 14 张模板类表 —— 三者语义完全不同（§5.5、§7.6）。建议在页面或文档中显式区分，避免后续开发误把「导入模板」与「代码生成模板」当成一件事。
