## 问题记录使用说明

### 1. 问题分类指南
- **功能缺陷**: 功能未按需求实现，或实现逻辑错误
- **性能问题**: 响应时间慢、资源占用高、并发能力不足
- **安全问题**: 存在安全漏洞，如SQL注入、XSS、越权访问等
- **用户体验问题**: 界面设计不合理、操作流程复杂、提示信息不明确
- **兼容性问题**: 在不同浏览器、设备或系统上表现不一致

### 2. 严重程度判定标准
- **P1 - 致命**: 
  - 系统完全无法使用
  - 核心业务功能完全失效
  - 数据丢失或损坏
  - 安全漏洞导致系统被攻击
  
- **P2 - 严重**:
  - 主要功能部分失效
  - 影响正常业务流程
  - 性能问题影响用户体验
  - 需要重启服务才能恢复
  
- **P3 - 一般**:
  - 次要功能存在问题
  - 不影响主要业务流程
  - 有替代方案可用
  - 仅影响少量用户
  
- **P4 - 轻微**:
  - 界面显示问题
  - 拼写错误
  - 提示信息不准确
  - 不影响功能使用

### 3. 优先级判定标准
- **紧急**: 
  - 生产环境出现的问题
  - 影响大量用户
  - 存在安全风险
  - 需要立即修复
  
- **高**:
  - 影响下一版本发布
  - 影响测试进度
  - 重要功能缺陷
  
- **中**:
  - 可以在下一个迭代中修复
  - 不影响当前版本发布
  - 用户体验问题
  
- **低**:
  - 建议性改进
  - 不影响功能使用
  - 可以在空闲时间修复

### 4. 问题处理流程
1. **发现与记录**: 测试人员发现问题并记录
2. **分析与确认**: 测试负责人确认问题有效性
3. **分配与处理**: 分配给相应开发人员处理
4. **修复与验证**: 开发修复后，测试人员验证
5. **关闭与归档**: 验证通过后关闭问题

### 5. 文件命名规范
- 问题文件命名: `ISSUE-XXX-[简要描述].md`
- 截图文件命名: `ISSUE-XXX-截图-[序号].png`
- 日志文件命名: `ISSUE-XXX-日志-[日期].log`
