## 1. 页面概述

- **车辆档案页**：维护配送车辆台账（车牌/品牌型号/类型/载重容积/证件有效期），支持**人车绑定**与**状态流转**。
- 车辆可分为**公司自有 / 个人自带 / 租赁**（`ownershipType`），对应企业员工与外部运力的不同装备来源。

- 页面 `statusMap` 仅定义 0–3（`:585-590`），而实体另有 **4 = 已出勤**（`DmsVehicle:119-120`）**缺映射**。

### 2.5 接口调用与后端比对（**6 处不匹配**）

| 前端调用 | 后端 `VehicleController` | 问题 |
|---------|-------------------------|------|
| `page` / `create` / `update` / `maintenancePage` / `createMaintenance` / `deleteMaintenance` | ✅ | 正常 |
| `PUT /{id}/status` body `{status}` | `@RequestParam Integer status`（`:67`） | **body vs param → 400** |
| `POST /dms/vehicle/bind-rider` body | `POST /{id}/bind-rider` + `@RequestParam riderId/riderName`（`:73-77`） | **路径 + 传参双不符** |
| `POST /{id}/bind` | ❌ **后端无此端点** | 失败 |

## 3. 金标准目标设计

### 3.1 页面结构（金标准）

`CategoryListLayout` + `BillTableList`（序号齿轮列配置，`storage-key` = `dms-vehicle-columns`）+ `PageConfigPanel`。

- **列**：车牌号、车辆类型、品牌/型号、归属类型、核定载重/容积、**当前配送员**、车队长、状态、**证件到期**（保险/年检/营运证，带剩余天数与告警色）、最近维保、当前里程、所属部门、备注、操作。
- **查询**：车牌号、类型、归属类型、状态、**证件到期（近 N 天）**、当前配送员、部门、注册日期范围。
- **功能按钮**：新增、批量启停、**批量绑定/解绑**、**导出**、刷新；行级：查看、编辑、状态变更、绑定配送员、维保记录、**解绑**。

### 3.2 状态机（建议固化）

```
空闲(0) ⇄ 使用中(1) ； 使用中 → 维修中(2) → 空闲(0) ； 任意 → 已报废(3)（终态）
```
- **已出勤(4)**：出车但未接单（与"使用中(1)"区分：1 = 有在途任务）。
- 状态变更需**校验**：有在途任务不可改为维修/报废；报废不可再绑定配送员。

### 3.3 人车绑定规则

- **一对一**：同一时刻一辆车只绑定一名配送员，一名配送员只绑一辆车（《实名认证》的"人车分离"预警基于此）。
- 绑定/解绑记流水（时间、操作人、里程），交车时**录入里程与位置**（见《实名认证》交车弹窗）。
- 社会车辆/个人自带车辆的"车主"与"配送员"可能不同，需分别记录。

### 3.4 后端接口（金标准）

| 接口 | 说明 |
|------|------|
| `GET /api/dms/vehicle/page` | 多条件分页（补归属类型/证件到期/当前配送员；**字段名统一为 `currentRider*`**） |
| `POST/PUT /api/dms/vehicle` | 新增/修改 |
| `DELETE /api/dms/vehicle/{id}` | 删除（**批量删除改传数组或逗号串由后端解析**） |
| `PUT /api/dms/vehicle/{id}/status` | 状态变更（**统一 PUT + body** + 状态机校验） |
| `POST /api/dms/vehicle/{id}/bind-rider` | 绑定配送员（**统一路径与参数形式**） |
| `POST /api/dms/vehicle/{id}/unbind-rider` | 解绑 |
| `GET /api/dms/vehicle/options` | 选择器数据源（调度/绑定/线路共用） |
| `GET /api/dms/vehicle/expiring` | 证件到期清单（保险/年检/营运证） |

### 3.5 业界生产级实践要点

1. **证件到期强提醒**：保险/年检到期前 N 天预警（沿用 `maintenance-due` 思路，扩展为统一"合规到期"视图）。
2. **载重/容积参与调度**：`ratedLoad` / `cargoVolume` 作为派单约束（《智能调度》负载均衡与超限校验）。
3. **车辆画像**：里程、维保记录、事故数、准点率，供车辆绩效与折旧分析。
4. **归属类型影响结算**：公司自有（成本内化）/ 个人自带与租赁（按时长或里程计费，见《渠道管理》计费规则）。
5. **选择器统一**：所有"选车辆"处走 `/vehicle/options`，禁止手输 ID。

#### 3.6.3 业务规则落地

- **状态机**（`VehicleStatusEnum` + 服务端校验）：`空闲(0) ⇄ 使用中(1) / 已出勤(4)`；`维修中(2) → 空闲(0) / 已报废(3)`；`已报废(3)` 为**终态**（不可再变更、不可编辑、不可绑定、不在 options 中）。
  - 有在途配送任务（`dms_task.status ∈ 1..4`）不可改为维修中 / 已报废；绑定中的车辆不可报废、不可删除。
- **人车一对一**：一辆车同时只绑一名配送员、一名配送员同时只绑一辆车（双向校验并给出明确拒绝文案）；绑定写流水（`bind_time` / `bind_mileage` / `bind_reason`），解绑结单（`handover_time` / `handover_mileage` / `status=1`）。
  - 绑定时空闲 → **已出勤(4)**；解绑时使用中/已出勤 → **空闲(0)**。
- **证件合规**：保险 / 年检 / 营运证「最近一证」在列表给出剩余天数与告警色（已过期红 / ≤30 天橙 / 正常绿），`/expiring` 提供统一到期清单（`EXPIRED` / `WARNING` / `NORMAL`）。
- **归属类型**：1 公司自有 / 2 个人自带 / 3 租赁；个人自带与租赁车辆可登记**车主姓名/电话**（与当班配送员可不同）。
- **唯一性**：车牌号、车辆编码租户内唯一（部分唯一索引，`deleted=0`），软删除后允许复用。
