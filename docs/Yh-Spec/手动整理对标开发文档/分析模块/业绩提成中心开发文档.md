## 1. 页面概述

业绩提成中心是**提成结算工作台**（复合页：统计分析 + 结算操作）：同一份提成数据按六种视角呈现，其中 `配送员 / 每月提成` 为人员 × 12 个月的**年度矩阵**（带跨年切换），`提成构成 / 方案汇总提成` 为**方案维度的拆解与汇总**，`业绩概览 / 业绩明细` 为**业绩指标的汇总与单据级明细**。核心操作是工具栏的 **`批量结算`**，其前置硬约束由页面提示条明示：**「若存在某月份提成未结算，此后月份提成将不显示」** —— 结算必须按月份顺序连续推进。

|------|------|------|
| 业绩提成中心 | 分析 → 提成分析 → 业绩提成中心 | 单入口复合页（**6 个视图 Tab**，逐 Tab 独立列配置） |

单入口：分析 → 提成分析 → 业绩提成中心。

### 口径说明

- **矩阵列 vs 配置列**：`配送员 / 每月提成 / 方案汇总提成 / 业绩概览 / 业绩明细` 五 Tab 的表头实据末尾均出现**拼接串**（如 `合计0000000000`），说明对标表头存在**合并单元格（分组表头）**；其中 `1月`~`12月`、`合计` 属**运行期生成的矩阵列 / 固定合计列**，不参与列配置 —— 这正是基准文档「14 列」与本表 `columnConfig`「2 列」差异的来源。
- **`业绩明细` 与 `业绩概览` 均为 21 列**（列池相同量级），但**默认可见数不同**（10 vs 15）：`业绩明细` 是**单据级明细**（司机/商品/单位/数量/金额/换算/毛利），默认只留最常用的 10 列；`业绩概览` 是**人员级汇总**（单量/里程/装箱/金额/毛利/点位），默认 15 列。两者共用同一批包装/重量/体积明细列的隐藏项。
- **`提成构成` 是 `方案汇总提成` 的「加人员维度」版**：前者多 `配送员 / 职务` 两列（7 = 5 + 2），其余 5 列完全同名同序 —— 构成 = 逐人 × 逐方案，汇总 = 逐方案。
- **`不显示为零数据项`**：`提成构成 / 方案汇总提成` 两 Tab 的勾选项，勾选后隐藏金额为 0 的项；旁边口径提示「列表仅显示已产生业绩数据的方案提成数据」说明**默认只显示已产生业绩的方案项**。

## 4. 业务规范

### 统计口径与数据关系

- **年度矩阵**：人员 × 12 个月，单元格为该月提成金额（`配送员` / `每月提成` 两 Tab）；年度可切 `去年 / 本年` 与具体年份（实测 `2026年`）。
- **结算顺序硬约束**：**「若存在某月份提成未结算，此后月份提成将不显示」**（页面提示条实据，逐字）。即提成必须**按月顺序结算**，未结算月份会**截断其后所有月份的显示**，保证核算连续性 —— 这是本页最核心的业务规则。
- **批量结算**：对选中范围批量执行结算，**结算后锁定**（基准文档口径，弹窗细节**待复核**）。
- **六视图分工**：

| 视图 | 粒度 | 作用 |
|---|---|---|
| `配送员` / `每月提成` | 人员 × 月份 | 年度矩阵总览（结算操作台） |
| `提成构成` | 人员 × 方案 | 单月/单期提成的方案项拆分 |
| `方案汇总提成` | 方案 | 按提成方案汇总提成金额 |
| `业绩概览` | 人员 | 配送业绩指标总览（单量/里程/装箱/体积/毛利/点位） |
| `业绩明细` | 人员 × 商品 | 单据级业绩明细（发货/退货/赠品/换算/毛利） |

- **人员角色维度**：`配送员角色`（默认 `全部`）为人员范围过滤；基准文档记「按人员角色（配送员/业务员等）切换提成口径，角色由提成方案覆盖范围决定」，其中**角色枚举与切换后查询项是否变化待复核**。
- **`业绩明细` 的日期口径**：`日期类型 = 指定配送日期`（实测），即按**配送日期**而非单据日期过滤；其他可选值**待复核**。

### 与其他页面关系

- **取数**：`业务员提成`（销售提成计算）、`回款统计`（回款侧口径）+ 配送计件/配送业绩（`业绩概览`/`业绩明细` 的配送指标）+ `提成方案` 规则。
- **下游**：提成结算 → 工资 / 费用发放（财务域）；批量结算回写结算状态。
- **状态机（本系统侧可确认）**：`erp_commission_record.status` = `DRAFT`（待确认）/ `CONFIRMED`（已确认）/**`PAID`（已结算）**/ `CANCELLED`（已取消）；「已结 = `PAID`，未结 = `DRAFT` + `CONFIRMED`」（`views/analytics/commission-center/index.vue:61-66`、`backend/.../mapper/CommissionRecordMapper.java:27-33`）。**对标侧的月份锁定语义本系统后端没有对应实现**。

### 剩余缺口

1. **🔴 视图数与业务模型整体不对齐（最大缺口）**：对标为 **6 个视图**（配送员 / 每月提成 / 提成构成 / 方案汇总提成 / 业绩概览 / 业绩明细），本页仅 **2 个**（提成记录 / 提成规则）。**本页把「台账 + 规则只读列表」当成了「结算工作台」**，二者不是同一页面性质。
2. **🔴 年度 × 月份矩阵未实现**：对标的 `配送员` / `每月提成` 是**人员 × 12 月 + 合计**的矩阵（动态列，含跨年切换 `去年/本年`）；本页无任何矩阵能力，也无动态月份列。
3. **🔴 `批量结算` 与结算顺序约束未实现**：对标核心动作是工具栏 `批量结算`（结算后锁定）+ 提示条「若存在某月份提成未结算，此后月份提成将不显示」；本页**无批量操作、无结算动作、无结算状态回写接口**（后端仅 `record` 的 page/get/delete，**无结算端点**），**月份顺序约束在后端也无对应实现**。
4. **无合计行（金标准必备项缺失）**：对标 `方案汇总提成` / `业绩概览` / `业绩明细` 三 Tab 表头末项均为 `合计`（实据）；本页 `ARReportPage`/`a-table` 无 summary 能力（`ARReportPage.vue:100-120`）。
5. **无提成方案配置入口**：对标工具栏有 `提成方案`（规则配置弹窗）；本页 `提成规则` Tab 仅为**只读分页列表**（无新增/编辑/删除按钮），**规则不可维护**。
6. **列结构不对齐**：对标六视图列池（2 / 2 / 7 / 5 / 21 / 21 列，默认 2 / 2 / 7 / 5 / 15 / 10）与本页（12 / 11 列）**无列级对应**；仅「提成方案名称 ≈ 规则名称」「提成类型 ≈ 佣金类型」「提成金额 ≈ 佣金值」等少量语义近似。
7. **未达金标准路线 A**（如实标注）：未使用 `CategoryListLayout`/`BillDetailTable`（**无列配置齿轮**）/`StandardPagination`/`PageConfigPanel`；**两 Tab 均无任何查询条件**。
8. **无角色/人员维度过滤**：对标有 `配送员`（占位 `配送员*`）、`配送员角色`（默认 `全部`）以及 `提成方案` / `提成类型` / `不显示为零数据项`；本页全无。
9. **无 `业绩概览` / `业绩明细` 的配送指标数据源**：对标这两 Tab 涉及配送里程、最优路线、装箱数量、体积、重量、点位等**配送执行域指标**；本系统提成记录表 `erp_commission_record` 只有订单/佣金字段，**无对应数据源与接口**，属跨域补数（配送域已有 `dms_*` 台账可作源，需评估）。
10. **无打印**：对标六 Tab 均有 `打印(F8)`；本页无（`ARReportPage` 无打印能力）。
11. **导出为「当前页 CSV」**：`ARReportPage.vue:354-369` 拼 CSV 下载 `.csv`，**非真实 xlsx、非全量导出**。
12. **`提成记录` 的删除为原型级实现**：后端 `DELETE /{id}`（`CommissionRecordController.java:36-40`）直接物理/逻辑删除记录，**与「已结算锁定」的业务约束冲突**（已 `PAID` 的记录也应禁止删除）—— **待复核**是否已加状态校验。
