## 1. 页面概述

库存期初页是**开账前的期初库存录入台**：在系统正式启用前，把每个商品在每个仓库的**期初数量**与**期初成本单价**录进来，作为后续出入库与成本核算的起点。使用人是**租户的建账人员 / 财务**，典型使用窗口是「开账前一次性录入 → 开账后只读备查」。

| 项 | 值 | 证据 |
|----|-----|------|
| 页面 | `set/initial-stock`（单入口） | `sys_menu.id=70550`，`display_mode=0`，`list_path=null` |
| 组件 | `views/set/initial-stock/index.vue`（**249 行**） | 上游菜单 `component=views/set/initial-stock/index.vue` |
| 外壳 | `ErrorBoundary(:2) > PageContainer(title="库存期初", **未传 full-height**)(:3)` + 裸 `a-table` | `index.vue:2-3,29-47` |
| 后端 | `InitialStockController`（前缀 `/api/set/initial-stock`，**4 个端点**） | `erp/erp-stock/.../stock/controller/initial/InitialStockController.java` |
| 数据表 | `erp_stock`（**29 列 / 4 行**，其中 `is_initial=1` 的 **0 行**） | devdb 实测 |

### 1.1 与相邻页的分工

| | **库存期初（70550，本页）** | **财务期初（70551）** |
|---|---|---|
| 数据对象 | **商品 × 仓库**的期初数量 / 成本单价 | **会计科目 / 往来单位**的期初余额 |
| 落表 | `erp_stock`（`is_initial=1`） | **无表**（后端零实现） |
| 对标分组 | ql361「期初录入」 | ql361「期初录入」 |

| | **库存期初（70550，本页）** | **入库单（`erp/stock-in`）/ 采购入库单** |
|---|---|---|
| 性质 | **开账前**的期初数据登记（非单据、无审核、无库存事件） | **日常业务单据**（审核后有库存事件与凭证闭环） |
| 是否影响可用库存 | 直接写 `erp_stock.quantity` | 经库存事件服务变更 `erp_stock` |

> ⚠️ **本页与「入库单」在数据上会写同一张 `erp_stock` 表**，但**不走库存事件服务**（`InitialStockController` 只注入 `StockService`，调 `saveInitialStock`/`updateInitialStock`）→ 期初录入**不产生库存流水**（`erp_inventory_change` 类事件无记录）。这是「期初不走事件」的**设计取舍**，但也意味着**期初录入在库存流水侧不可追溯**（见 §9 / §12）。

### 1.2 本页不提供的能力（如实登记）

- ❌ **产品下拉永远为空**（`loadOptions` 只加载仓库，`productOptions` 全文件无第二处赋值）→ 「产品」这个 **required** 字段**无法选择** → **页面根本提交不了**（P0，见 §9.2 / §12）。
- ❌ **3 个写端点全部不存在**（新增/编辑/删除 POST/PUT/DELETE 全 404，见 §6）。
- ❌ **「规格型号」「金额」两列恒空**（VO/DTO 与 `erp_stock` 表都没有 `specification` / `amount`）。
- ❌ 无分类树（对标有左分类树）、无「期初数量」筛选（对标有）、无「显示层次结构」开关、无「导出期初」、无「打印(F8)」、无「线性列表」切换（**对标 4 个都有**）。
- ❌ 无批量导入（Excel）、无「按期初总额试算」、无开账校验（数量/金额为负、单价为 0 的告警）。
- ❌ 无 `PageConfigPanel`、无列配置齿轮、无 `storage-key`、无 `StandardPagination`、无权限门控。

**本页无 status / enabled 类状态下拉，无状态列**。唯一的「值域」是借贷方向的**对立面**——本页**没有方向概念**（数量与单价均为正数录入，退库/负数期初无从表达）。

> **权限断言账号**：① 超管（`*` 通配）；② 无 `set:initial-stock:*` 权限的普通账号。

### 10.1 接口验收（30 项）

**查询（①–⑩）**

1. `GET /api/set/initial-stock/page?pageNum=1&pageSize=20` → **200**；`records` 长度 = `min(20, total)`；`total` = `SELECT count(*) FROM erp_stock WHERE is_initial=1 AND tenant_id=<当前租户>`。
2. **断言当前 `total = 0`**（登记基线；造数后改断言 > 0）。
3. `productCode` 模糊匹配生效：造 1 条 `product_code='TEST-INIT-001'` → 查 `productCode=TEST` → 命中；查 `productCode=NOPE` → 0 条。
4. `productName` 模糊匹配生效（同上口径）。
5. **`warehouseId` 参数断言**：传 `warehouseId=<某仓库id>` → **断言返回条数不变**（当前后端不接收该参数 → **登记 P1 缺陷**；修复后改为「条数按仓库收缩」）。
6. 分页边界：`pageSize=1` → `records` 长度 1；`pageNum=999` → `records=[]` 且 `total` 不变。
7. **租户隔离**：用另一租户的 token 调用 → **断言看不到本租户行**（多租户插件已全局生效）。
8. **权限断言**：用无权限的普通账号调用 `/page` → **当前预期 200**（后端仅 `@SaCheckLogin`，登记 P1；补权限后改断言 **403**）。

10. `GET /export`（后端**存在**，页面未用）→ 200 且返回 `List`；**断言其条数 = `/page` 的 `total`**。

**写库（⑪–㉒）**

11. `POST /api/set/initial-stock`（**前端实际调用路径**）→ **当前预期 404**（登记 P0；修复后改断言 200）。

> 验收证据：模块级 E2E `tools/e2e-settings.cjs` → **164 项全部通过**；截图产物 `tool-results/e2e-settings/ui-70550.png`。

### ① 前端外壳与路由（路线 A）

| 项 | 实现 |
|---|---|
| 路由 / 菜单 | `set/initial-stock`（菜单 `70550`，单入口） |

### ② 后端接口清单（`InitialStockController`，前缀 `/api/set/initial-stock`）

| 方法 | 路径 | 鉴权 | 本轮 |
|---|---|---|---|
| GET | `/api/set/initial-stock/page` | `@SaCheckLogin` | 走新 Mapper，支持 6 个查询参数（含 `warehouseId` / `categoryId` / `initialQtyFilter`） |
| POST | `/api/set/initial-stock/save` | `@SaCheckLogin` | **body 为数组**；新增；逐条校验 `productId` / `warehouseId` 非空 |
| PUT | `/api/set/initial-stock/update` | `@SaCheckLogin` | 编辑（`id` 在 body） |
| DELETE | `/api/set/initial-stock/{id}` | `@SaCheckLogin` | **本轮新增**（原前端调用的 `DELETE /{id}` 必然 404） |
| GET | `/api/set/initial-stock/export` | `@SaCheckLogin` | 导出全量（与 `/page` 同口径，不分页；前端据此生成 xlsx） |

数据口径要点：

- 新增 `backend/erp/erp-stock/.../mapper/InitialStockQueryMapper.java`：`erp_stock` ⋈ `erp_product` + **递归分类 CTE**（按商品分类下钻）；**「期初金额」由后端计算，不落库**（解决 §9.2「`amount` 列无后端来源」）。
- **顺带修复**：原 `saveInitialStock` 会「**先清空全部期初行再插入**」，会误删他人期初 → 已改为按行 upsert 语义，不再全表清空。
- 删除接口对「记录不存在或不允许删除」返回明确 400，不静默成功。

### ③ 数据库变更

**无迁移**：本轮**未新增任何列 / 表**。所有列（条码 / 规格 / 型号 / 产地 / 小单位 / 期初金额等）均取自既有 `erp_stock` ⋈ `erp_product` 的现成字段，「金额」为派生值。

### ④ 仍存在的缺口（如实登记）

1. **小单位回退口径**：当前取 `erp_stock.unit` / `erp_product.unit`；`erp_product.small_unit` **全库为 NULL**，故无法直接采用「小单位」语义，显示可能非用户预期的单位（已如实登记）。
2. **「仓库必选」未采纳**：对标仓库为必选筛选，本系统保留为**可选筛选项**（未强制）。
3. **零权限码**：本页 5 个端点仍是 `@SaCheckLogin`，`sys_permission` 中**无 `set:initial-stock:*`** 权限码；前端无 `v-permission`。
4. **期初不走库存事件、不产生库存流水**：期初变更不可追溯（谁在何时改的、改前是多少，无记录）——设计取舍，未改。
5. **无开账锁定**：期初不受《会计期间》的期间关闭保护，可在任何时候被改。
6. **无唯一约束 / 重复期初校验**：同商品 + 同仓库仍可插多行（后端无 `@Min` 等值域校验，负数仍可落库）。
7. 打印（F8）/ 刷新 / 「显示层次结构」等对标工具栏能力未逐项对齐（本轮补的是分类树 + 导出 + 横向查询区 + 路线 A 外壳）。
