# 按单付款开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`finance/payment-by-doc`（复合页）
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **复合页**：列表查询页 + 3 个阶段 Tab（待付款/全部单据/发票查询）+ 行级付款操作；应付款的统一核销工作台（按应付单据逐单付款的处理中心，与按单收款对称）。
- **单入口**：财务 → 付款 → 按单付款。

## 2. 页面配置

### 查询条件

按抓取 JSON filterLabels 实据（往来单位、结算单位、经手人、对账标记人）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止）、日期类型（默认"单据日期"）、单据编号、来源订单、往来单位、结算单位（后两者带新增+搜索）
- 单据类型（全部）、经手人、对账（全部）、对账标记人
- 勾选项：仅显示已选中、显示无结算付款单的业务单据

### 功能按钮

按抓取 JSON buttons 实据：无结算付款单核销(37)、刷新、打印(F8)、更多、查询、√（对账标记）、否（对账标记）、跳转（分页跳转）

行级操作（截图确认）：付款（操作列）。

### 打印配置

无（抓取数据未覆盖打印配置弹窗；有打印(F8)按钮，打印模板配置细节待复核）

## 3. 数据表格列配置

### 默认显示列（14 列，抓取 JSON columns 实据）

操作、单据日期、单据类型、单据编号、结算单位、付款日期、本单金额、已结金额、待审金额、未结金额、对账 (√ / 否)、最后对账标记时间、最后对账标记人、附件

> JSON columns 首项"操作 单据日期 单据类型 单据编号"为抓取拼接串（前四列表头拼接），已剔除，不计入列数。

> 表格结构实据（截图）：首列行勾选框；操作列含"付款"；单据编号为链接（CGRKD- 采购入库单）；对账列为可点击标记（当前值"否"）；底部"合计"行；分页第(1/1)页 / 共 16 条记录 / 每页 20 行。

## 4. 业务规范

### 状态流转与特殊交互

- 阶段主线：采购业务单据（采购入库单 CGRKD-）记账产生应付 → 本页"待付款"；全部单据为全集视图；发票查询查看收票情况
- 行级"付款"：对该单据发起付款，进入付款单流程（与《付款单开发文档》联动）；付款后"已结金额"增加、"未结金额"减少，待审金额为付款单已提交未记账的金额
- 金额口径（截图合计实据）：本单金额 = 已结金额 + 待审金额 + 未结金额（124,802 = 25,094 + 0 + 99,708）
- 对账（√/否）：点击切换，标记已与供应商对账；同时记录"最后对账标记时间/最后对账标记人"；对账标记人可作查询条件
- 无结算付款单核销(37)：对"付款单已记账但未勾选核销单据"的历史付款单事后补核销，按钮带未核销计数 37（实据，说明存在大量待补核销）
- 显示无结算付款单的业务单据：勾选后把存在未核销付款单的业务单据一并列出
- 与按单收款的差异：无"超期"子标签、无"欠条领取"、无"司机名称/收款日期/对账日期/制单人/仓库/销售收入"列（供应商场景无欠条与司机代收；按单收款多"超期待收款"Tab）
- 行数据实据（截图）：单据类型=采购入库单；结算单位=供应商（兰州市卓越调味品商行、河南滔展食品有限公司等）

### 与其他页面关系

- 付款对象：采购入库单（CGRKD-）——采购域单据记账后流入本页
- 付款动作 → 《付款单开发文档》（FKD- 单据）；预付抵扣见《预付款单开发文档》（YFKD-）
- 记账后生成会计凭证（KJPZ-）；应付账款 2202 科目（总账实据）
- 本系统前端目录 `finance/payment-by-doc`（dynamicRoutes.ts 实据）
