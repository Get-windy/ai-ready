### 对账 Tab（4 个）

**1. 银行对账（BankReconciliation）**：对账编号、对方名称、对账期间、系统余额、实际余额、差异、状态、对账日期、操作。

**2. 客户对账（CustomerReconciliation）**：对账编号、客户名称、对账期间、系统应收、客户金额、差异、状态、对账日期、操作。

**3. 供应商对账（SupplierReconciliation）**：对账编号、供应商名称、对账期间、系统应付、供应商金额、差异、状态、对账日期、操作。

**4. 差异处理（DifferenceHandling）**：对账编号、类型（银行/客户/供应商）、对方名称、差异金额、差异原因、操作（处理差异）。

> 银行/客户/供应商三 Tab 列差异仅「对方名称 + 系统/对方余额」命名不同（余额 vs 应收 vs 应付），其余结构一致。

## 业务规范说明

- **对账三方**：银行（`BANK`）/ 客户（`CUSTOMER`）/ 供应商（`SUPPLIER`），对应 4 张卡片 + 3 个列表 Tab + 1 个差异 Tab。
- **差异**：`difference = systemBalance - actualBalance`（系统余额 − 实际余额）；差异不为 0 的对账单进入「差异处理」Tab。
- **差异处理**：`handleDifference`（`/handle-difference/{id}?differenceReason=`）登记差异原因并结案；差异处理列表仅列出差异金额非 0 的记录。
- **对账状态**：对账单状态（如待对账/已对账），客户/供应商对账可 `reconcile` 结案。
- **数据源**：对账单存 `fin_reconciliation`（主表）+ `fin_reconciliation_item`（明细）；`/stats` 返回四类待办计数。
- **自动刷新**：30s 轮询 `/stats`，刷新统计卡片（不强制刷新列表）。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 对账单一口径（红线）**：✅ 对账复用 `fin_reconciliation`（主表 + `fin_reconciliation_item` 明细）为唯一数据载体，**严禁另建重复对账表**；`差异 = 系统余额 − 实际余额` 口径全局唯一。
- **P1 应收/应付/银行余额口径**：✅ 客户/供应商/银行对账经 `GET /balance` 分别取应收（`receivable`）/应付（`payable`）/银行账户余额作为系统余额，与业务单据一致。
- **P1 差异处理下推**：✅ 差异金额非 0 记录经「处理差异」下推《应收应付调整》（`erp_ar_ap_adjust`，记账经凭证 KJPZ- 调整应收/应付余额），登记原因并结案，形成差异闭环。
- **P2 验收**：无桩/无模拟；新增对账/对账结案/差异处理/`/stats` 四类计数闭环真实生效。前端 `vite build` 通过、后端 `erp-finance` 编译通过；**浏览器端到端需运行 core-api + 迁移 V11.87.0（应收应付调整表）+ 现有 `fin_reconciliation` 表后复验**。
