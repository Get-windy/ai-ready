## 业务规范说明

### 价格等级字段处理

餐饮店、食堂团餐、自助vip、大团餐、特价客户、外围餐饮店、重点vip01、连锁|vip 这8个字段是用户对价格等级自定义的昵称，需按标准化产品价格等级处理。

### 客户来源

销售订单的客户来源通过 ERP 模块的往来单位下的客户分类处理，而非 CRM 模块的客户信息。CRM客户是公海客户，ERP客户是实体客户。

### 架构师红线（Ponytail六步过滤网）

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑和交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。订金是带使用条件的预收款或预付款。

## 实现差异说明（2026-08-29 复刻完成）

- **数据源**：采购单据查询页 `/purchase/doc-query` 按 ql361 口径整合**采购入库单/退货单/换货单**（非采购订单主表；采购订单走独立列表页）。后端以"分包分页合并"实现（分别 count 各类型，再按全局偏移截取合并），镜像销售单据查询（UnifiedSalesDocQueryServiceImpl）。
- **新增后端接口**：`GET /api/purchase/doc-query/page`（统一分页）、`PUT /api/purchase/doc-query/{docType}/{id}/remark`（整单备注）。新增类：UnifiedPurchaseDocumentDTO / UnifiedPurchaseDocQueryDTO / UnifiedPurchaseConverter / UnifiedPurchaseDocQueryServiceImpl / SupplierSnapshotMapper。
- **37列表格**：单据类型/入库出库仓库/供应商编号/联系人/联系电话/联系地址/供应商备注/来源订单/经手人/部门/结算状态/采购数量/金额/折后金额/优惠后金额/税额/价税合计/本单金额/其他费用/优惠金额/表头自定义1-5/单据备注/摘要/附件/记账人/制单人/记账时间/制单时间/打印次数，均已映射真实列。
- **金额口径**（本系统含税口径）：金额=total_amount；折后金额=total_amount；优惠后金额=total_amount-discount_amount；税额=tax_amount；价税合计=total_amount_with_tax；本单金额=total_amount_with_tax；其他费用=fee；优惠金额=discount_amount。
- **供应商编号/联系人**：入库单主表未冗余，经 `SupplierSnapshotMapper` 跨模块（只读 `erp_supplier` 档案表，忽略租户行拦截——因 `erp_supplier.tenant_id` 为 character varying）按 supplier_id 补全；退货单用 `supplier_no`，换货单用 `supplier_code`。
- **结算状态**：入库/退货单 `settle_status`(0/1) 转文本；换货单 `settle_status`(varchar) 直接取值。
- **出库仓库**：入库单无（null），退货单用 `warehouse_name`，换货单用 `out_warehouse_name`；入库仓库：入库单/换货单 in_warehouse_name。
- **前端**：重写 `views/purchase/doc-query/index.vue` 为 CategoryListLayout+BillTableList+PageConfigPanel+ColumnConfigPanel 结构（39列含序号/操作，18个查询条件，页面配置/列配置弹窗，合计行）；API 新增 `purchaseDocUnifiedApi`。

> 已知边界：当前系统测试数据中 `erp_supplier` 档案表为空，故入库单的供应商编号/联系人暂为空（真实数据源缺失，非代码缺陷）；待供应商档案补录后自动展示。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
