# AI友好接口模块测试用例设计

## 1. 单元测试用例设计

### 1.1 AiGatewayController测试用例

#### TC-UNIT-001: 测试聊天接口正常响应
**测试目标**: 验证AI聊天接口能正常处理有效请求并返回正确响应
**前置条件**: 
- AI服务网关控制器正常运行
- Mock AI服务已配置
**测试步骤**:
1. 构造有效的AiRequest对象
2. 调用AiGatewayController.chat()方法
3. 验证返回的响应状态为200 OK
4. 验证响应体包含正确的AI回答
**预期结果**: 
- 状态码: 200
- 响应体: {"success": true, "data": {...}, "metadata": {...}}

#### TC-UNIT-002: 测试请求验证失败场景
**测试目标**: 验证接口对无效请求的正确拒绝
**前置条件**: AI服务网关控制器正常运行
**测试步骤**:
1. 构造无效AiRequest对象（空消息）
2. 调用AiGatewayController.chat()方法
**预期结果**:
- 状态码: 400 Bad Request
- 响应体: 包含验证错误信息

#### TC-UNIT-003: 测试服务层异常处理
**测试目标**: 验证服务层异常能正确转换为API错误响应
**前置条件**: Mock AI服务抛出模拟异常
**测试步骤**:
1. 构造有效的AiRequest对象
2. 设置Mock AI服务抛出ServiceException
3. 调用AiGatewayController.chat()方法
**预期结果**:
- 状态码: 500 Internal Server Error
- 响应体: {"success": false, "error": "AI服务暂时不可用"}

### 1.2 AiRequest/AiResponse模型测试用例

#### TC-UNIT-004: 测试请求对象序列化/反序列化
**测试目标**: 验证请求对象能正确转换为JSON和从JSON解析
**测试步骤**:
1. 创建AiRequest对象并设置所有字段
2. 使用Jackson序列化为JSON字符串
3. 从JSON字符串反序列化为新AiRequest对象
4. 验证所有字段值相等
**预期结果**: 序列化和反序列化后的对象字段值完全一致

#### TC-UNIT-005: 测试请求对象验证注解
**测试目标**: 验证JSR-303验证注解正常工作
**测试步骤**:
1. 创建AiRequest对象，message字段为null
2. 执行验证
**预期结果**: 验证失败，包含"消息内容不能为空"错误

## 2. 集成测试用例设计

### 2.1 AI服务网关集成测试

#### TC-INTEG-001: 测试完整AI聊天工作流
**测试目标**: 验证从API接收到AI响应的完整流程
**前置条件**:
- Spring Boot应用已启动
- Mock AI服务提供者已配置
- 测试数据库和Redis已准备
**测试步骤**:
1. 发送HTTP POST请求到/api/ai/gateway/chat
2. 请求体包含有效的聊天消息
3. 接收并解析响应
4. 验证响应结构和数据
**预期结果**:
- HTTP状态: 200
- 响应包含正确的AI回答
- 数据库记录API调用日志
- Redis记录限流计数器

#### TC-INTEG-002: 测试服务提供商路由逻辑
**测试目标**: 验证系统能根据配置正确路由到不同的AI服务提供商
**前置条件**:
- 配置多个Mock AI服务提供商（OpenAI、百度、阿里云）
- 每个提供商返回不同的标识符
**测试步骤**:
1. 发送聊天请求，指定provider="auto"
2. 验证路由逻辑
3. 发送聊天请求，指定provider="openai"
4. 验证指定提供商被调用
**预期结果**:
- auto路由: 根据路由策略选择合适提供商
- 指定提供商: 直接使用指定提供商

### 2.2 配置集成测试

#### TC-INTEG-003: 测试配置动态加载
**测试目标**: 验证配置变更能实时生效
**前置条件**: 应用已启动，外部配置服务器可用
**测试步骤**:
1. 初始状态下发送请求记录响应时间
2. 动态更新AI服务超时配置（从5秒改为1秒）
3. 再次发送请求
4. 验证配置变更已生效
**预期结果**: 第二次请求响应时间显著减少

## 3. 端到端测试用例设计

### 3.1 业务场景测试

#### TC-E2E-001: 用户商业咨询场景测试
**测试目标**: 模拟真实用户使用AI进行商业咨询的完整场景
**前置条件**:
- 完整的ERP系统环境
- 业务数据库包含真实业务数据
- AI接口网关已集成到ERP系统
**测试场景**:
1. 用户登录ERP系统
2. 导航到AI商业助手模块
3. 输入问题："当前季度哪些商品库存周转率最低？"
4. 系统调用AI接口分析库存数据
5. AI返回分析结果和建议
**预期结果**:
- 用户能收到基于真实数据的AI分析建议
- 系统记录完整的调用链路
- 响应时间在可接受范围内（<3秒）

#### TC-E2E-002: 多用户并发访问测试
**测试目标**: 验证系统在高并发场景下的稳定性和性能
**前置条件**:
- 负载均衡器已配置
- 监控系统已就绪
**测试步骤**:
1. 使用JMeter模拟50个并发用户
2. 每个用户发送10个不同的商业咨询请求
3. 监控系统资源使用情况
4. 分析响应时间和错误率
**预期结果**:
- 平均响应时间 < 500ms
- 99%分位响应时间 < 1.5s
- 错误率 < 0.5%

## 4. 异常和边界测试用例

### 4.1 异常处理测试

#### TC-EXCEPT-001: 网络异常场景测试
**测试目标**: 验证外部AI服务不可用时的降级处理
**前置条件**: Mock外部AI服务模拟网络超时
**测试步骤**:
1. 设置外部AI服务返回超时（30秒）
2. 发送聊天请求
3. 验证系统在超时前返回降级响应
**预期结果**: 系统在配置的超时时间（如10秒）内返回友好的降级响应

#### TC-EXCEPT-002: 数据格式异常测试
**测试目标**: 验证系统能处理AI返回的异常数据格式
**前置条件**: Mock AI服务返回格式错误的JSON
**测试步骤**:
1. 设置Mock返回无效JSON
2. 发送聊天请求
3. 验证系统能优雅处理并返回错误信息
**预期结果**: 系统返回格式解析错误，而非崩溃

### 4.2 边界条件测试

#### TC-BOUNDARY-001: 消息长度边界测试
**测试目标**: 验证系统能正确处理各种长度的消息
**测试数据**:
- 空字符串消息
- 1字符消息
- 7999字符消息（边界）
- 8000字符消息（最大长度）
- 8001字符消息（超出限制）
**预期结果**:
- 8000字符及以下: 正常处理
- 8001字符: 验证失败，返回400错误

#### TC-BOUNDARY-002: 并发请求边界测试
**测试目标**: 验证限流机制的有效性
**前置条件**: 配置每秒10个请求的限流
**测试步骤**:
1. 在1秒内发送15个请求
2. 监控哪些请求被限流拒绝
**预期结果**:
- 前10个请求: 成功
- 后5个请求: 429 Too Many Requests

## 5. 性能测试用例

### 5.1 基准性能测试

#### TC-PERF-001: 单接口响应时间基准测试
**测试目标**: 建立AI接口的基准性能指标
**测试环境**: 隔离的测试环境，无其他负载
**测试步骤**:
1. 预热系统（发送100个请求）
2. 测量1000个请求的响应时间
3. 计算平均值、P95、P99响应时间
**验收标准**:
- 平均响应时间: < 100ms（无外部调用时）
- P95响应时间: < 200ms
- P99响应时间: < 300ms

#### TC-PERF-002: 内存使用测试
**测试目标**: 验证系统在长时间运行下的内存稳定性
**测试步骤**:
1. 连续运行24小时压力测试
2. 每5分钟记录一次内存使用情况
3. 分析内存泄漏趋势
**验收标准**:
- 内存使用稳定，无持续增长趋势
- GC活动正常，无频繁Full GC

## 质量门禁设计

### 代码覆盖率要求
- 单元测试覆盖率: ≥85%
- 集成测试覆盖率: ≥70%
- 总体测试覆盖率: ≥80%

### 性能指标要求
- 单接口响应时间: < 100ms（无外部调用）
- 并发处理能力: ≥50 req/s
- 错误率: < 1%
- 系统可用性: ≥99.9%

### 安全要求
- 所有用户输入必须经过验证
- 敏感信息不得在日志中泄露
- 必须支持HTTPS通信
- 必须实现API认证和授权
