## 1. 页面概述

待审批单据是**跨业务域「待审批」状态单据的统一台账**：把销售 / 采购 / 收付款 / 库存 / 费用等各域处于审批中态的单据聚合到同一列表，供审批人在一处完成审核通过 / 驳回。**单入口、单视图**（无页内 Tab）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 待审批单据 | `analytics/pending-approval` | 单视图列表页（跨 13 类单据聚合台账 + 行级/批量审批） |

单入口：分析 → 综合单据 → 待审批单据。

- 页面结构：查询方案 + 时间快捷段 + **三行查询区** + 单据台账表格（首列红色齿轮列配置入口 + 序号线 + 行勾选框 + 固定「操作」列）+ 底部合计行 + 分页条。
- 实测实据（2026-09-15）：共 **6** 条记录、**1/1** 页、每页显示 **22** 行、底部合计 **1,238**。全部为「销售出库单」（`XSCKD-20260915-0xx`），点击左侧「审核」动作处理。
- 多 Tab 判定：实测 JSON `tabs` 为 `{}`（空对象），`.png` 顶部仅一个「待审批单据」页签 → **单视图，无子 Tab**。

## 4. 业务规范

### 统计口径与数据关系

- **数据范围**：全部业务域处于「待审批 / 审批中」状态的单据，一行一单，`金额` = 单据金额原值；底部合计对当前过滤范围求和。
  - 后端实现为 13 个单据分支的 UNION 聚合（`DocQueryService.java` 的 `BRANCHES`，`DocQueryService.java:50-127`），`StatusMode.PENDING` 时每类按其**自身状态枚举**取待审批值，例如销售订单 `status = 1`（`待审核`）、销售出库单 / 销售退货单 `status = 1`（`待审批`）、销售预订单 `status = 1`（`审核中`）、费用申请单 `status IN ('SUBMITTED','DEPARTMENT_APPROVING','FINANCE_APPROVING','GENERAL_MANAGER_APPROVING')`。
  - 单据类型下拉实测默认「全部单据」，可按 13 类之一过滤。
- **账期条件**：带 `≥` 比较符，按单据账期天数过滤（用于筛「账期 ≥ N 天」的超期审批单）。
- **审批动作**：`审核`（行级）/ `审核通过`、`驳回`（批量）。通过 → 单据回到来源业务域继续流转；驳回 → 退回制单人修改后重新提交。
- **组内分工**（综合单据组三页 = 单据生命周期的三个横切状态）：
  待审批单据（审批中）→ 业务草稿（未提交 / 未过账）→ 经营历程（已过账全量流水）。

### 与其他页面关系

- **上游**：各业务域单据的「提交」动作（销售订单表单页提交后进入审核中；采购 / 仓储 / 财务各域单据类推）。
- **下游**：审批通过回写源单据状态；驳回回写并通知制单人。
- **同组页面**：业务草稿、经营历程。

## 5. 实现差异说明

> 本节按当前源码与真机实测（2026-09-18）回写。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/pending-approval/index.vue`（486 行）。
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout`（`:tabs="[]"`、`:show-category-panel="false"`、`:show-table-footer="true"`）+ `BillDetailTable`（`:view-mode="true"`、`:min-rows="20"`）+ `StandardPagination`（`variant="classic"`、`page-size-options=[20,50,100]`）。
- **逐 Tab 列数**：单视图（无页内 Tab）。全部 **13 列 / 默认 12 列**（`columns` 共 16 项，含 `rowNo` / `checkbox` / `action` 三个固定列；业务列 13 项，仅「制单人」`defaultHidden`）。列配置入口为表头序号列的齿轮（`BillDetailTable` 内嵌 `.th-settings-btn`），个人 / 全局配置持久化键 `analytics-pending-approval-columns`（`storage-key` 与 `global-config-key` 同值）。
- **页面配置**：**无 `PageConfigPanel`**（对标实测无「页面配置」弹窗）→ 查询区为固定项，工具栏按钮不做启停。
- **查询项**：工具栏左侧「查询方案」下拉（占位）+ 8 段时间快捷段（昨日 / 今日 / 本周 / 近一周 / 本月（默认）/ 上月 / 近三月 / 本年，`shared/docTypes.ts` 的 `QUICK_DATES`）；查询区 10 个控件 = 单据编号、单据类型（13 类下拉 `DOC_TYPE_OPTIONS`）、往来单位、经手人、部门、单据备注、账期（比较符 `≥/≤/=/</>` + 天数）、仓库、所属区域、查询 / 重置；日期区间随快捷段联动（`startDate/endDate`）。
- **行级 / 批量动作**：行级「审核」；批量「审核通过」「驳回」（以行勾选为前提，弹窗填写审批意见 / 驳回原因）。动作按 `docTypeCode` 分发到各业务域**既有**端点（`shared/docTypes.ts` 能力矩阵 + `shared/docActions.ts`），不对状态列直改；某类型没有的动作按钮不出现，批量时先剔除并提示（如报损单 `STOCK_DAMAGE` 走登记→执行直通流程，无 submit/approve/reject）。
- **打印 / 导出**：均无（对标本身无打印(F8)、无导出）。
- **合计行 / 排序**：底部合计行「金额」列取值来自后端 `summary.amount`（按当前过滤范围 SUM，非本页求和）；仅「金额」列可排序，由后端 `sortField/sortOrder` 完成，点掉排序箭头回落到「单据日期倒序」。
- **取数端点**：`GET /docquery/pending-docs/page`（13 类单据 UNION，附 `pendingSummary` 逐类计数）；动作端点 `POST {base}/{id}/approve|reject`、`PUT {base}/{id}`（备注）、费用申请单走 `POST /erp/expense/approval/process`。
- **后端**：`DocQueryController` + `DocQueryService` 13 分支 UNION（`StatusMode.PENDING`），未新增迁移。

### 剩余缺口

1. **「查询方案」下拉仅为占位**：`queryScheme` 未被任何请求使用，既不能保存也不能加载方案（`index.vue:264`、`:18-25`）→ 对标「查询方案」能力未落地。
2. **对标工具栏「更多」折叠动作未接**：对标实测工具栏有 `更多`（折叠其余批量动作），本页只落了 `刷新 / 审核通过 / 驳回`；「更多」内的具体项在对标侧本身未抓取到，**未确证**有哪些动作。
3. **每页行数档位与对标不同**：对标实测每页 22 行，本页 `page-size-options=[20,50,100]`（默认 20）。
4. **首屏默认区间为「本月」**：dev 库现有 3 张待审批单据（采购订单，单据日期 2026-07-22 / 2026-08-29）落在区间外，故首屏为空表 + 合计 0；此为默认查询窗口口径，非取数缺陷。
