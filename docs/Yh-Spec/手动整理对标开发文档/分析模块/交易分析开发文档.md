### 口径说明（2026-09-15 实测数值交叉验证 ✅）

- **漏斗链路**：`登录客户数`（当日登录商城的去重客户）→ `下单客户数`（当日有下单的去重客户）→ `下单笔数`/`下单金额`。
- **客单价 = 下单金额 / 下单客户数**（分母为**客户数**，非笔数）：
  - 2026-09-15：926 ÷ 4 = **231.5** ✅
  - 2026-09-14：2421 ÷ 8 = **302.625** ✅
- **下单转化率(%) = 下单客户数 / 登录客户数 × 100**：
  - 2026-09-15：4 ÷ 13 = **30.77** ✅
  - 2026-09-14：8 ÷ 24 = **33.33** ✅
- **合计行**：量额列求和（登录 13+24=**37**、下单客户 4+8=**12**、下单笔数 5+8=**13**、下单金额 926+2421=**3347**）；**比率列（客单价/下单转化率）不合计**（实测为空）。
- 行粒度随粒度切换变化：`按天` 一行一日；`按周`/`按月` 为区间聚合（**对标实据未抓取，待复核**）。

## 4. 业务规范

### 统计口径（商城转化漏斗）

- **登录客户数**：来自商城登录日志的当日去重客户；`下单客户数` 来自商城订单的去重客户（同一客户当日多单只计 1）。
- **下单金额**：商城下单金额合计（**口径 = 销售业绩「实订金额」**，即商城下单即销售订单，来源单据前缀 `XSDD-` + 商城来源标记）。
- **转化口径单列**：`下单转化率(%)` 已由后端按「客户数/客户数」计算并作为一列输出，前端不再二次计算。

### 与营销模块及商城域的上下游关系（**取数关系，必须写清**）

- **本页属商城分析域**，与《商城客户列表》同子分组（「商城分析」），互为「整体口径 vs 客户级口径」：本页按日期汇总「登录→下单」整体转化，《商城客户列表》按客户汇总访问/成交。
- **上游（商品维度）**：商城内商品/价格/促销配置由《营销模块》的促销页（商品促销/整单促销/特价/优惠券）与商城页（拼团/秒杀/商城弹窗广告）产生；**本页不区分活动来源**，是活动效果的「全站汇总底」——营销活动分析/营销推广分析看「活动带来的量」，本页看「商城总的量」。
- **下游归因**：`下单金额` 与《销售业绩》「实订金额」同源，可跨页交叉验证（见第 6 节遗留：本次实测 3,347，未做跨页对账）。
- **与《营销推广分析》分工**：推广分析看「推广对象带来的转化」，本页看「商城整体转化」。

### 本系统对应关系

- 本系统当前取数自 `/erp/mall/admin/trade-analysis`（商城交易分析聚合接口，见第 5 节），**字段模型与对标不等价**（无登录客户数、无下单客户数、无转化率；多出订单数环比与支付状态分布）。

## 5. 实现差异说明

> 本节按当前源码与真机实测（2026-09-18）回写。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/trade-analysis/index.vue`（320 行）。
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout`（`:tabs="[]"`、`:show-category-panel="false"`、`:show-table-footer="true"`）+ `BillDetailTable`（`:view-mode="true"`、`:min-rows="20"`、`:summary-columns`）+ `StandardPagination`（`variant="classic"`）。
- **逐 Tab 列数**：单视图。全部 **4 列 / 默认 4 列**（无默认隐藏列）：日期、下单笔数、下单金额、客单价；列配置键 `analytics-trade-analysis-columns`（`storage-key` = `global-config-key`）。对标为 7 列，扣除 3 个无数据源列后为 4 列（见缺口 1）。
- **页面配置**：**无 `PageConfigPanel`**（对标实测无该弹窗）→ 查询区为固定项。
- **查询项**：工具栏左侧查询方案（占位）+ 8 段时间快捷段（默认本月）+ 工具栏右侧「刷新」；查询区：日期范围、「统计粒度」按天 / 按周 / 按月三段按钮（默认按天）+ 查询 / 重置。
- **粒度口径**：后端只出按日明细，周 / 月为**前端按日明细区间聚合**（周以周一为起点，`dayjs` 计算不依赖语言包）；客单价 = 区间下单金额 ÷ 区间下单笔数。
- **行级 / 批量动作**：无（列定义中无 `action`，无勾选框）。
- **打印 / 导出**：**均无**（对标实测该页工具栏无打印(F8)、无导出）。
- **合计行**：量额列取后端 `summary`（`totalOrderCount` / `totalGmv`）；比率列（客单价）不合计。
- **取数端点**：`GET /erp/mall/admin/trade-analysis`（`mallAnalyticsApi.tradeAnalysis`：`startDate/endDate`，返回 `summary` + `daily` + `paymentStatusDistribution`）；本页取 `summary` 与 `daily`（支付状态分布无对标对应块，未渲染）。
- **分页**：聚合端点一次性返回全部按日明细，故为**前端分页**（20/50/100）。
- **后端**：本轮未改后端；未新增迁移。

### 剩余缺口（按本页自身规格＝统计报表页逐项判定）

1. **3 个对标列无数据源、不渲染**：登录客户数、下单客户数、下单转化率(%) —— `MallTradeAnalysisController` / `MallTradeAnalysisMapper` 只聚合 `erp_sale_order`（`order_source IN (2,3)`），DTO（`summary` / `daily` / `paymentStatusDistribution`）无任何登录相关字段；全库无商城登录日志 / 访问埋点表（仅 `sys_login_log`，属后台账号登录审计，与商城客户无关）。为禁返回 0 / 占位假值，这 3 列**不渲染**（7 列 → 4 列）。
2. **客单价分母口径与对标不同**：本页 `客单价 = 下单金额 ÷ 下单笔数`（后端 `avgOrderAmount`），对标口径为 `÷ 下单客户数`（客户数取不到，分母差异已登记）。
3. **图形视图未接**：对标工具栏有「图形」视图切换，无图表数据源，未接（工具栏只保留「刷新」）。
4. **无合计的比率列**：客单价不参与合计（与对标实测一致）。
5. **分页为前端分页**：聚合端点无分页参数，全量按日明细在内存中切片。
