## 1. 页面概述

系统参数页是设置模块的**租户级开关与枚举配置台**：以「列表 + 弹窗编辑」的形态管理配置项（配置键 / 配置名称 / 配置值 / 类型 / 分组 / 启用）。**当前实现的所有读写都发生在一个 JVM 内存静态 Map 上，与数据库完全无关** —— 这是本页最核心的事实（README §7.1-8/9 已登记，本文档 §3.7 / §7 / §9 / §12 逐条取证）。

| 外壳 | `ErrorBoundary > PageContainer`（**未传 `full-height`**）+ 自绘查询区 + 裸 `a-table` | `index.vue:2,3,4-66,89-134` |

**1.1 与相邻页的分工（本模块最易混的一处）**

> **分工结论（现状）**：**「真配置服务」与「真配置表」都不在本页的调用链上**。本页读写的是 `/api/config` 的内存 Map；系统内另有一套已落库、带历史与回滚能力的 `/api/system/config`（§7.3），但**没有任何前端页面调用它**（`grep -rn "system/config" FE/apps/pc-admin/src` 仅命中路由文件，无 API 封装）。

**1.2 本页不提供的能力（如实登记）**

- ❌ 无变更历史 / 回滚 / 版本对比（后端 `/api/system/config` 有 `history` / `rollback` / `compare`，本页不用）
- ❌ 无 `PageConfigPanel`、无表头齿轮列配置、无 `storage-key` / `global-config-key`
- ❌ 无 `StandardPagination`（`a-table` 内置分页，且是**假分页**，见 §3.9）
- ❌ 前端零权限门控（`grep -rn "v-permission\|hasPermission" FE/views/set/` → 零命中）
- ⚠️ 有「刷新缓存」按钮，但后端实现只 `log.info`（空实现）

### 3.8 🔴 行选择 / 批量删除因 `id` 全为 `null` 而失效（P0）

```java
// SystemConfigServiceImpl.java:49-61 —— addBuiltinConfig 全文
private static void addBuiltinConfig(String key, String value, String type, String group, String name) {
    SystemConfig config = new SystemConfig();
    config.setConfigKey(key);
    config.setConfigValue(value);
    config.setConfigType(type);
    config.setConfigGroup(group);
    config.setConfigName(name);

    config.setDefaultValue(value);
    config.setEnabled(true);

```

**后果链**：12 条内置配置的 `id` **全部为 `null`** → 表格 `row-key="id"`（`:94`）退化 → `:row-selection` 的 `selectedKeys` 取值不可靠 → `handleBatchDelete`（`:403-419`）里的

```js
for (const id of selectedKeys.value) {
  const item = tableData.value.find(r => r.id === id)   // :411
  if (item) await configApi.delete(item.configKey)
}
```

`find` 结果**不可预期**（可能匹配不到任何行、也可能因 `undefined === undefined` 而全落到首行）。`index.vue:409-413` 的注释「后端批量删除需要 configKey，但选择的是 id；写一个简单实现」正好记录了这个妥协。**未做运行期验证**。

### 3.9 🔴 「分页」是假分页（P0）

```java
// SystemConfigController.java:37-38
List<SystemConfig> configs = configService.getConfigList(configType, configGroup, tenantId);
return ResponseEntity.ok(Map.of("records", configs, "total", configs.size(), ..., "pages", 1L));
```

- `total` = **返回条数**（≤12），`pages` **恒 1**
- `getConfigList` 完全**忽略 `pageNum` / `pageSize`**（`SystemConfigServiceImpl.java:104-114`）
- → 切换页码 / 每页条数**不会改变任何结果**；`pagination` 对象（`:272`）的 `showSizeChanger: true` 是纯装饰

### 8.3 明确不借鉴

- **不借鉴** ql361 的视觉样式（橙色 toggle、圆角卡片、左列高亮的具体配色）—— 按 README §5.3-4，只借交互形态（卡片分组 / `?` 气泡 / 温馨提示 / 统一保存），皮肤用本系统 `a-switch` / `a-form` / `a-tabs mode="vertical"` 的既有样式。

- **可以只靠已有列完成的**：把 12 条内置配置落库到 `sys_config` 的**已有 17 列**（`param_key` / `param_name` / `param_value` / `config_type` / `config_group` / `value_type` / `builtin` / `remark` / `sort_order` / `enabled` / `tenant_id` / …）→ **无需新增列**。
- **明确需要新增字段的**（不隐瞒）：① 「不可逆配置」需要一个布尔列（如 `locked`），`sys_config` **现无该列**；② 「生效时机」需要一个枚举列（如 `apply_mode`），`sys_config` **现无该列**。两项**均已在本文档标注为「需新增」**，不写成「已有能力」。
- 对 ql361 借鉴的配置项名（`保质期管理` / `批号管理` / `批次商品成本规则` / `近效先出` 等）**仅作对标参照**，不承诺在本系统建立同名字段或同名表。

## 11. 配置落位

> 通道口径见《对标开发技术参考文档》§5.6（通道 1 环境变量 / 通道 2 core-api yml / 通道 3 配置中心 DB / 通道 4 业务档案表）。

| 配置项 | 落位 | 生效 | 缺失行为 |
|--------|------|------|---------|
| **系统参数（本页管理的对象）** | **无真实落位**：`/api/config` 只写 JVM 内存静态 Map（`cacheService` 为可选注入） | 进程内即时；**重启即丢** | **保存后从列表里也读不回来**（新增键不在 `BUILTIN_CONFIGS`） |

**本页参数「存哪张表 / 哪一列 / 什么格式」总结**：

- **当前实际**：**不存任何表**（JVM 内存 `LinkedHashMap`，键 → `SystemConfig` 对象）。
- **DB 里应然的两张表**：① `sys_config`（17 列，`param_key` 唯一，`param_value` 为**纯文本**）——**当前零代码路径**；② `sys_project_config`（真实在用的 KV，`config_value` **纯文本、结构化内容以 JSON 字符串存**）—— 本页未接。

⑲ 无配置变更日志可查（`/logs/{key}` 依赖缓存且无写入方）。

### ② 数据落库：迁移 `V11.421.0`（`sys_config` 18 → 173 行）

|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|

- `views/set/sys-params/ParamNodeRow.vue` 新增：`value_type = 'group'` 的**分组行自身无控件**（`inlineChildren`/`rowChildren` 据此分流），仅作子项挂载点。

### ④ `GET /config/value-options`：两张表合并

- `SystemConfigController.VALUE_OPTIONS`：**23 个单键**（行业 2 / 流程 1 / 单据 11 / 库存 3 / 财务 3 / 其他 3），**全部逐字取自 ql361 展开下拉**。

### ⑤ `locked` 折算（读取时实时算，**不落库**）

| 配置键 | 判定链路 |
|---|---|
| `industry.batch.shelfLife` | `erp_product.is_batch_expiry_managed = 1`（商品表单「保质期/批次号」勾选框） |
| `industry.batch.batchNo` | `erp_product.is_batch_managed` |
| `industry.serial.enabled` | `erp_product.is_serial_managed` |
| `industry.product.specAttr` | `erp_product_attribute_def` 有行 |

- 实现：`SystemConfigServiceImpl` 读取时按引用计数折算 `locked` + `lockedReason`；**不写回 `sys_config.locked`**（商品取消勾选即应解锁，写库需商品侧反向回调）。统计失败时 `log.warn` 并按**未锁定**处理（不误锁）。
- devdb 实测：`erp_product` 中 1 个商品勾选 `is_batch_expiry_managed` → `industry.batch.shelfLife` 计算得 `locked = 1`；`sys_config.locked` 库内仍为 0 行（符合「不落库」口径）。
- 前端：锁定项渲染为禁用 + 悬浮说明；**批量保存整批只查一次引用计数，并跳过锁定项**。
