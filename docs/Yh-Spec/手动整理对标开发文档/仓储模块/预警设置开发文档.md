# 预警设置开发文档

## 页面概述

预警设置是商品×仓库库存上下限阈值的查询与维护页（页面标题「库存预警固定值设置」），支持批量设置，其结果即预警查询的过滤阈值。

| 页面 | 地址 | 说明 |
|------|------|------|
| 预警设置页 | http://localhost:5656/erp/stock-alert-config | 查询区 + 左侧商品分类树 + 设置表格（查询后渲染） |

### 菜单配置（本系统）

| 项 | 值 |
|----|----|
| 菜单 ID | 5013（原"库存预警"，本次改名"预警设置"——为预警规则维护页，消除与"预警查询"重名歧义） |
| menu_code | `erp:stock-alert-config` |
| path | `erp/stock-alert-config` |
| component | `erp/stock-alert-config/index` |
| display_mode | 0（单入口，主数据维护页） |

## 业务规范说明

- 页面流程：先查询（仓库/商品/品牌/分类树过滤出商品清单）→ 表格行内维护库存上限/库存下限 → 保存（保存按钮形态待复核，或以「批量设置」统一赋值）。
- 批量设置：对选中商品批量赋相同上下限（弹窗内容待复核）。
- 设置结果即预警查询的过滤阈值。
- 下游消费方：预警查询（按本页阈值判定预警）；采购→采购准备→库存预警补货（按缺货补货）。
- 商品与分类来自 资料→商品管理。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），具体见 `docs/Yh-Spec/ql361对标/README.md`。

## 实现差异说明

**实现文件**：`frontend/apps/pc-admin/src/views/erp/stock-alert-config/index.vue`（维护页）
**后端**：`StockAlertConfigController` / `StockAlertConfigService` / `StockAlertConfigMapper` / `StockAlertQueryVO` / `StockAlertBatchItemDTO`（erp-stock 模块）

### 页面对齐
- 本系统已建 `erp/stock-alert-config/index.vue`，用 `CategoryListLayout`（左侧商品分类树 + 右侧表格）重构为对标布局：
  顶部「库存上下限比较值」提示条（点击弹出比较口径设置弹窗）、查询区（全部仓库/指定仓库单选、商品、品牌、查询按钮）、
  功能按钮（刷新、打印F8、批量设置、更多[批量取消·导出]）、14 列数据表（商品名称/货号/口味/型号/单位/小单位/条码/规格/产地/品牌/预警仓库/库存上限/库存下限，上下限行内可编辑）。
- 菜单 5013 由原「库存预警」改名「预警设置」，单入口 `display_mode=0`，指向 `erp/stock-alert-config/index`（迁移 V11.62.0 确保 path/component/menu_code 正确）。

### 已完成
1. **查询渲染**：`GET /api/erp/stock-alert-config/config-items` 返回「商品清单 × 仓库上下限」分页。指定仓库以商品主数据为主体 LEFT JOIN 该仓库配置（未配置商品也展示，供行内新建）；全部仓库以配置表为主体展示所有已配置「商品×仓库」行。
2. **批量设置**：`POST /api/erp/stock-alert-config/batch-set` 支持 `items`（逐行 upsert，用于行内编辑保存）与统一赋值（选中商品 + 同一上下限，用于批量设置弹窗）；`GET/POST /api/erp/stock-alert-config/comparison` 读写比较口径（存 `sys_project_config`，key=stock.alert.comparison）。
3. **预警数据源联动**：阈值写入 `erp_stock_alert_config`，即「预警查询」(`/stock-alert/page`) 的过滤依据，形成设置→查询闭环；小单位取 `erp_product_unit`(SMALL) 换算单位。
4. **开发规范**：迁移 V11.62.0 补 `erp_product.taste/small_unit` 列、`erp_stock_alert_config(product_id,warehouse_id)` 索引、菜单定位更新。

### 待完善 / 注意
- 「口味」列：`erp_product.taste` 为新增列，存量商品默认空；`StockAlertQueryMapper` 预警查询的 taste 列暂保持 NULL（商品无口味数据源，待商品表单支持录入后回填）。
- 打印(F8) 输出整页；导出为前端 CSV 当前页（后端未提供 Excel 导出接口）。
- 「批量取消」当前语义为清除勾选（未删除阈值配置），如需删除配置请后续明确并补充接口。
- 需执行迁移 V11.62.0 并重启 core-api 使后端新接口生效。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
