# 质量证书开发文档

> **文档类型：** 新增页面设计文档
> **对标系统：** ql361（来肯企汇）仓储/质量模块**无此页面**，故字段/流程为本系统 + 业界成熟 QC（Odoo 质检模块 / ISO 9001 质量体系文件 / 金蝶）质量证书（COA/COC）通用设计，非对标复刻。
> **定位：** 在当前系统代码实际实现基础上补齐设计，不做过度开发、不重复开发。

## 页面概述

质量证书用于登记产品批次的质量证明文件（COA 分析证书 / COC 合格证书 / ISO 认证），记录证书类型/产品/批次/供应商/检验结论/有效期及附件。模块含一个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 质量证书列表页 | `quality/certificate/list` | 单一列表页，CRUD + 弹窗表单 |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序。
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结。
- ✅ **当前实现说明**：本页已升级为金标准 `CategoryListLayout` + `BillTableList` + `ColumnConfigPanel`（列配置）/`PageConfigPanel`（页面配置）弹窗（localStorage 持久化），查询条件/功能按钮显隐可配置；新增/编辑采用 `a-modal` 弹窗表单。

## 业务规范说明

- 证书来源：多为外部供应商/检测机构出具的 COA/COC；系统登记留档，可关联产品/批次/供应商。
- 状态流：草稿(0) → 已生效(1) → 已过期(2) / 已撤销(3)；过期可据有效期自动判定（本期手动维护）。
- 附件：certificateUrl 存储证书文件链接（本期为文本框，未做文件上传）。
- 质量证书与质检单弱关联（检验类型/检验员/结论），与产品/批次/供应商引主数据（本期均为文本录入）。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），质量模块无此页，本页为设计新增。

### 最终裁决方案（2026-09-03 · 严格按此执行）

> 与《质量标准/质检单/缺陷记录最终裁决》一致，本页遵循同一跨模块口径：**P0 红线必做、P2 本次做、P1 延后并隐藏、明确不做红线**。

**裁决1 · 红线（不做的）**
- 质量证书为**记录性档案页**，不引入单据状态流（无记账/审批）、不引入独立明细表、不做库存/采购联动（无下推链）。
- 不做独立表单页（档案弹窗已闭环；如需对齐质量标准独立 `BillFormPage` 表单页属可选，下迭代）。

**裁决2 · P0/P1**：无 P0/P1 级跨模块断链（证书是外部证明文件留档，不参与库存/门禁闭环）。

**裁决3 · P2 本次做**
- **列表金标准三件套**：`CategoryListLayout` + `BillTableList` + `ColumnConfigPanel`/`PageConfigPanel`（localStorage），多选批量删除、查看/编辑/删除、CSV 导出。
- **弹窗表单 CRUD 闭环**：新增/编辑/删除，校验产品名称/证书类型/检验结论。

**裁决4 · 延后（可选）**
- 证书编号自动生成（next-no）、状态筛选后端(`status` 参数)/过期自动判定、附件上传、主数据下拉 → 下迭代/可选（本期文本录入+状态手动维护已闭环）。

**执行指令**：本期质量证书以 P2（列表金标准 + 弹窗 CRUD）闭环；编号自动生成、附件上传、主数据选择均延后可选；无跨模块缺接口（不依赖采购/库存域）。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
