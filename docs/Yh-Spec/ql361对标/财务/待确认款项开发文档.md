## 表格列配置

### 默认显示列（抓取 JSON columns 实据，13 列）

操作、单据日期、单据编号、往来单位、单据状态、金额、收款账户1、收款金额1、收款账户2、收款金额2、来源订单、配送任务编号、经手人

> JSON columns 首项"操作 单据日期"为抓取拼接串（首两列表头拼接），已剔除，不计入列数。

### 列口径说明（实据归纳）

- 双账户结构（收款账户1/收款金额1、收款账户2/收款金额2）：一笔款项最多两个收款账户组合到账
- 来源订单、配送任务编号两列：款项来源可追溯至商城/销售订单与配送任务（司机代收或客户线上支付后由财务确认到账）

## 业务规范说明

### 状态流转与特殊交互

- 款项主线：业务端（订单在线支付/配送代收/转账）申报款项 → 本页"收款待确认"（预收款走"预收款待确认"）→ 财务核对银行/支付账户到账 → 确认（单行或批量）→ 款项正式入账，回写来源单据收款状态
- 未确认前款项不计入账户余额（确认动作即"到账入账"）；确认后资金口径与查资金/账户余额一致
- 单据状态列呈现款项当前状态（待确认/已确认等值域待复核）

### 与其他页面关系

- 收款侧：确认后的收款回写《按单收款开发文档》/销售单据已结算；预收确认后增加《预收款单开发文档》口径的预收余额
- 在线支付流水核对见《在线支付对账单开发文档》（流水号/关联交易号对账）
- 配送代收链路：配送任务编号关联 DMS 配送任务（司机代收）
- 本系统前端目录 `finance/pending-confirm`（dynamicRoutes.ts 实据）

### 客户来源

往来单位来源通过 ERP 模块的往来单位下的客户分类处理，而非 CRM 模块的客户信息。CRM客户是公海客户，ERP客户是实体客户。
