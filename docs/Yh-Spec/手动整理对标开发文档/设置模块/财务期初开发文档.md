## 1. 页面概述

财务期初页是**开账前的财务余额录入台**：把银行现金、应付、应收、固定资产、资产负债五类科目的**期初余额**录进来，作为总账/明细账的起始数。使用人是**租户的财务人员 / 建账顾问**。

**本页当前的真实性质**：**一个 218 行的纯前端壳** —— 前端完整实现了「查询 / 新增 / 编辑 / 删除」四类交互，**但后端零控制器、库零表**（`%initial%` 表一个都没有），所有请求都打到不存在的路径上。它**不是「功能有缺陷」**，而是**「功能整体不存在」**（README §7.1 第 3 条）。

### 1.1 与相邻页的分工

| | **财务期初（70551，本页）** | **库存期初（70550）** |
|---|---|---|
| 数据对象 | 会计科目 / 往来单位的**期初余额** | 商品 × 仓库的**期初数量与成本** |
| 对标 Tab | **5 个**（银行现金 / 应付 / 应收 / 固定资产 / 资产负债） | 无 Tab（分类树 + 10 列） |
| 落表 | **无表** | `erp_stock`（`is_initial=1`） |
| 后端 | **零控制器** | `InitialStockController`（4 端点） |

| | **财务期初（70551，本页）** | **会计科目（finance/subject）** |
|---|---|---|
| 定位 | 给科目**赋值**（期初金额） | 定义科目**本身**（编号/名称/借贷方向/层级） |
| 关系 | 本页的「科目」下拉**应来自**科目档案 | 是主数据 |
| 现状 | 下拉请求**路径写错** → 恒空（见 §6.2） | 接口真实存在（`AccountSubjectController`） |

> ⚠️ **本页与「会计期间」是开账前的两件事**：会计期间（70570）定义**12 期的起止日期**；财务期初（70551）定义**每个科目的起始金额**。ql361 把二者分别放在「财务设置」与「期初录入」两组；本系统同样分放（`61204` / `61202`），**分组口径一致**。

### 1.2 本页不提供的能力（如实登记）

- ❌ **后端零实现**：4 个前端调用的端点**全部不存在**（查询/新增/编辑/删除）。
- ❌ **数据库零表**：**没有任何「财务期初」业务表**，读写目标表无从确定。
- ❌ **科目下拉恒空**（请求路径少 `erp/` 段 → 404；且即便路径对了，其权限码 `finance:subject:view` **在 `sys_permission` 中也不存在**）。
- ❌ **无 5 个 Tab**（对标核心形态）、无「刷新」/「打印(F8)」/「导出」/「保存期初」/「试算平衡」。
- ❌ 无往来单位（供应商/客户）期初、无固定资产期初、无资产负债期初（对标 4 个 Tab 的内容本系统**完全没有概念**）。
- ❌ 无「合计」行、无「默认经手人」、无「预付/预收金额」、无「借贷方向」以外的方向语义扩展。
- ❌ 无期初平衡校验（借贷试算平衡）、无「科目是否已录」提示。
- ❌ 无 `PageConfigPanel`、无列配置齿轮、无 `storage-key`、无 `StandardPagination`、无权限门控。

### ⑤-③ 与《库存期初》存货对平检查（缺口 ④-5 关闭，**只检查不改数**）

口径取自本文档 §5.4（「『存货科目期初』应与库存期初金额**对平**」）与 §10.1 第 32 项验收（「把『存货类科目期初合计』与《库存期初》的 `Σ(quantity×unitPrice)` 比对 → 断言能报出差异」）：

| 侧 | 取数口径 |
|---|---|
| 财务侧 | `erp_initial_finance_subject` 中 `subject_code` **以 `140` 开头**的行金额合计（本次试算已查出的行内过滤，无二次查询） |
| 库存侧 | `SUM(quantity * unit_price)`，`erp_stock` 中 `deleted = 0 AND is_initial = 1`（与《库存期初》列表/导出同一公式；金额为派生值**不落库**）—— 见 `InitialStockOpeningMapper`（erp-finance 不依赖 erp-stock，故只读手写 SQL，租户条件自己拼且与库存期初页用**同一个** `MyBatisPlusConfig.getCurrentTenantIdValue()`） |
| 判定 | 差额 = 财务侧 − 库存侧，差额绝对值 `< 0.01` 视为对平（与资产负债表平衡容差同口径） |

**「存货类科目」为何取前缀 `140`**：本系统既有的资产负债表资产侧固定项目就是按**科目前缀**匹配 —— `FinancialReportServiceImpl.ASSET_LINE_DEFS = {{"1001","现金库存"},...,{"140","库存商品"},{"160","固定资产"}}`，覆盖 1401 材料采购 / 1403 原材料 / 1405 库存商品等全部 14xx 存货类科目。本检查**沿用同一前缀**，未新造映射表、未新增字段。

**呈现**：并入「试算平衡」接口返回的 `inventoryCheck{subjectCodePrefix, financeAmount, stockAmount, difference, matched, financeRowCount, stockRowCount, note}`；试算平衡弹窗新增「存货对平检查」区块（财务侧/库存侧/差额三行 + 结论），且**跑过一次试算平衡后**，未对平时在页面查询区提示条常驻显示同一结论（避免为它单独加一次首屏请求）。**不自动改写任何一侧数据，也不阻断保存**（是否强制对平属产品裁定）。

**devdb 实测**：库存期初 0 行（`Σ = 0`）、财务期初 0 行 → 两侧均为 0 → `matched = true`（此时为「都还没录」，不代表真实业务已对平，页面 `note` 已如实说明）。
