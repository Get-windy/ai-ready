## 业务规范说明

- **商城主线**：基础设置驱动商城买家端全局表现——商城名称/LOGO/介绍（分享与展示）、营业资质（合规公示）、联系方式/退货地址（交易服务）、显示字段（商品详情/列表展示列）、图片水印（商品图防盗）、访问设置（微商城入口与授权域名、默认仓库）、绑定小程序（小程序商城）、消息设置（订阅消息推送）。
- **营业资质合规**：按《电商法》第十五、十六条，营业执照与经营许可证需在店铺首页显著位置持续公示；食品行业需公示食品经营许可证。
- **显示字段**：商品详情页显示字段（规格/型号/货号/产地/品牌/条码/保质期/生产日期/重量/体积）与商品列表页显示字段（批次号）控制买家端展示哪些商品属性。
- **访问设置**：公众号网页授权域名决定微信登录/支付可用的域名；网店仓库=公众号跳转微商城默认发货仓库。
- **消息设置**：系统消息订阅（注册成功/订单/退换/退款/物流/促销等）控制给买家推送的通知类型。

## 实现差异说明

> 本节按当前源码回写（本轮金标准升级后）。

### 当前实现
- **实现文件**：`frontend/apps/pc-admin/src/views/mall/basic-config/index.vue`
- **骨架**：`ErrorBoundary > PageContainer(full-height) > [左侧 6 子项导航（180px `a-menu`）+ 右侧 `a-form` 分组卡片] + 底部 sticky「保存 / 重置」`。**本页为配置表单型页面，非列表型金标准骨架**：无 `CategoryListLayout`、无 `BillDetailTable`、无 `StandardPagination`、无独立 `PageConfigPanel`。
- **Tab**：6 个（基础设置 `basic` / 显示设置 `display` / 图片水印 `watermark` / 访问设置 `access` / 绑定小程序 `miniapp` / 消息设置 `message`），由左侧 `a-menu` 子项导航切换（**非 `a-tabs`**，无 Tab 模板串）
- **列**：本页为配置表单页，**全页无 `a-table`、无数据表**（无列配置齿轮；「仓库二维码」区为 `a-empty` / `a-tag` 列表，非表格）
- **查询条件**：0 项
- **功能按钮**：底部「保存」（primary，`:loading="saving"`，按子项提交）、「重置」（重新 `loadConfig()`）；基础设置子项「如何开启QQ在线客服」文字链、「新增联系方式」、联系方式行「删除」；绑定小程序子项「去授权」、「下载小程序」、「如何绑定小程序」；上述帮助类按钮统一走 `handleHelp()` → `message.info('「x」能力待接入（后端/开放平台对接后开放）')`
- **行级操作**：联系方式多值行「删除」（`removeContact(idx)`；初始 1 行，`addContact()` 追加，类型下拉 4 项：微信 / 手机 / QQ / 电话）
- **打印(F8) / 导出**：**均无**（无 `handlePrint()`、无 `handleF8Key()` 快捷键监听、无导出按钮）
- **storage-key**：**无**（本页未使用列配置 / 页面配置持久化，源码中无 `global-config-key`、无 `localStorage` 写入）
- **数据来源**：
  - `apps/pc-admin/src/api/erp/mall.ts` → `shopConfigApi`：`GET /erp/mall/admin/config`、`PUT /erp/mall/admin/config`
  - `apps/pc-admin/src/api/options.ts` → `optionsApi.getWarehouses()`：`GET /wms/warehouse/list-all`（访问设置子项「网店仓库」下拉数据源）
- **保存口径**：`handleSave()` 按当前子项分别保存，**六个子项均已真实写入后端**——
  - `basic` 子项：`{ ...(fullConfig||{}), id, status: basic.enabled ? 1 : 0, shopName, shopDesc, shopLogo, officialQrCode, mainCategory, returnConsignee, returnPhone, returnAddress, qualifications(JSON), contacts(JSON) }`
  - `display` 子项：`displayDetailFields(JSON)`、`displayListFields(JSON)`
  - `watermark` 子项：`watermarkType`、`watermarkImage`、`watermarkText`（按当前水印方式只保留有效项，另一项写 `''` 清空）
  - `access` 子项：`mallQrCode`、`wechatLink`、`authDomain`、`defaultWarehouseId`
  - `miniapp` 子项：`miniappAppid/miniappAppsecret/miniappPayMchId/miniappPayMchKey/miniappMallUrl/b2bPayMchId/b2bPayMchKey`
  - `message` 子项：`messageSubscribe(JSON，16 项布尔)`
  保存后 `await loadConfig()` 重新拉取。**未提交的字段因后端 `updateById` 忽略 null 而保持原值**，因此各子项只提交自己维护的字段是安全的。

**六个子项的真实字段清单（从源码数出）**

- **子项一「基础设置」3 分组共 12 个表单项**：

## 业界对标 / 跨模块 / 最终裁决

- **业界对标**：商城「基础设置」为全局配置中心，同类（零售通/来肯/订货宝）均以「多子项配置 + 合规资质公示 + 消息订阅」组织；核心差异是 ql361 将商城展示（LOGO/名称/介绍）与业务规则（显示字段/水印/访问/小程序/消息）统一放在「基础设置」，而本系统拆分为「基础设置/店铺设置/运费设置」三页共用 `ShopConfig` 单行。
- **跨模块**：绑定小程序/消息设置/访问设置联动「支付配置」（支付配置为独立 `PaymentConfig` 视图，含微信/支付宝/聚合/京东/农行/建行/微企付等「支付方式×场景」矩阵）；网店仓库联动 ERP 仓库主数据；营业资质合规披露联动商城店铺首页装修。
- **最终裁决**：本页不存在数据表，**无列/页面配置弹窗**（配置/表单型）。金标准应对齐「6 子项配置」结构；**本轮已由 Flyway `V11.361.7` 补齐全部对标列并打通六子项真实读写**（原「单表单占位」状态已消除）；剩余为**素材上传端点、富文本组件、仓库二维码端点、凭据加密脱敏**等结构性能力缺口，见「剩余缺口」。
