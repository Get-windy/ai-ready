## 一、三条路线（先选路线再动手）

| 路线 | 构成 | 列配置 | 页面配置 | 适用 |
|---|---|---|---|---|
| **A（金标准）** | `ErrorBoundary > PageContainer(full-height) > CategoryListLayout > BillTableList/BillDetailTable` | 表头序号列**齿轮**（BillDetailTable 内置） | 独立 `<PageConfigPanel>` | 列表页（绝大多数） |
| **A'（阶段工作台）** | 同上但布局换 `DocCenterLayout` | 同上 | 同上（`hidden-field-keys` 承接） | 多阶段/多维度工作台（订单处理、商城订单） |
| **B（报表页）** | `ARReportPage` | ❌ 无 | ❌ 无 | **仅**纯报表；交易模块**不要再走这条** |

> 交易模块原 22 页多为 `ARReportPage`（路线 B）或原生 `a-table`，**必须升级到路线 A/A'**。

## 三、列定义（`DetailColumnConfig[]`）

```ts
const columns: DetailColumnConfig[] = [
  { key: 'rowNo',  title: '',      type: 'rowNo',  width: 40,  fixed: 'left' },  // 承载列配置齿轮（锁定列）
  { key: 'action', title: '操作',  type: 'action', slotName: 'actionCell', width: 140, fixed: 'left' },
  { key: 'xxx',    title: '列名',  type: 'input',  width: 160 },                  // 只读文本列
  { key: 'yyy',    title: '列名',  type: 'slot',   slotName: 'yyyCell', width: 120 }, // 自定义渲染
  { key: 'zzz',    title: '列名',  type: 'input',  width: 160, defaultHidden: true }, // 默认隐藏（对标「隐藏列」）
]
```
- 类型：`select | input | number | date | slot | rowNo | action | checkbox | button | boolean`
- 锁定列（不进配置面板）：`rowNo / checkbox / action`
- 插槽**必须**写 `#[slotName]="{ record, column }"`

## 四、多 Tab 列表页（订单处理/商城订单/退货申请处理）

- 每 Tab 独立一套：**列定义** + **查询条件** + **功能按钮** + **storage-key**。
- `:storage-key="`xxx-table-columns-${activeTab}`"`（切 Tab 必须换 key，否则沿用上一 Tab 配置）。
- `:tabs="TABS" :active-tab="activeTab" @tab-change="handleTabChange"`。
- `PageConfigPanel` 放 layout **外面**，`:storage-key="`xxx-page-config-${activeTab}`"`。
- 工具栏按钮用 `v-if="isButtonEnabled('printF8')"` 控制显隐。

页面配置（查询条件显隐 + 功能按钮启用）：
```ts
interface QueryFieldSetting { key: string; label: string; visible: boolean }
interface FunctionButtonSetting { key: string; label: string; enabled: boolean }
const DEFAULT_QUERY_FIELDS: QueryFieldSetting[] = [{ key:'tab.field', label:'…', visible:true }]
const DEFAULT_FUNCTION_BUTTONS: FunctionButtonSetting[] = [{ key:'printF8', label:'打印(F8)', enabled:true }]
```
```vue
<PageConfigPanel :open="showPageConfig" :query-fields-config="queryFieldsConfig"
  :function-buttons-config="functionButtonConfig"
  :default-query-fields-config="DEFAULT_QUERY_FIELDS"
  :default-function-buttons-config="DEFAULT_FUNCTION_BUTTONS"
  :storage-key="pageConfigStorageKey"
  @update:open="showPageConfig = $event" @change="handlePageConfigChange" />
```

## 五、两条配置的分工（勿混淆）

| | 数据表列配置弹窗 | 页面配置弹窗 |
|---|---|---|
| 载体 | `BillDetailTable` **内置齿轮**（rowNo 列表头） | 独立 `<PageConfigPanel>` |
| 管什么 | 列的显隐 / 宽度 / 顺序拖拽 / 全局显示名 | 查询条件显隐+排序 / 功能按钮启用 / 打印配置 |
| 声明 | 列定义数组（`key/title/width/defaultHidden`） | `QueryFieldSetting[]` + `FunctionButtonSetting[]` |
| 持久化 | 个人 localStorage `storage-key`；全局 `storage-key+'-global'` + 后端 `userPageConfigApi.save('col-config', key)` | localStorage `storageKey` |
| 齿轮 | 组件内置，零接入 | 页面工具栏 `SettingOutlined` → `showPageConfig = true` |

## 六、陷阱清单（源码实测，务必避开）

1. `BillDetailTable` **不要手 push 空行**（`min-rows` 默认 20 自动填占位行）；**不要传 `:max-height`**（高度由 flex 链驱动）。
2. `row-key` 必须唯一（多行共用主表 id 时传明细主键），否则行复用错乱。
3. 切 `storage-key`（多 Tab）必须重载列配置。
4. 插槽**必须**透传 `column`，否则 `record[column.key]` 恒 undefined。
5. `BillTableList.pagination` 是**对象** `{current,pageSize,total}`；`:row-selection` / `:summary-columns` **不是**它的 prop（合计用 `:summary-data`）。
6. `PageConfigPanel` 不传 `default-*-config` 时「恢复默认」失效。
7. `CategoryListLayout` 的 `tabs` 为空数组时 Tab 栏不渲染（单视图页正常用）。
8. 路线 A 与 `ARReportPage` 别混用。
9. `useColumnConfig` 存 `{_version, columns}`，`BillDetailTable` 期望纯数组 —— 同一 storageKey 混用会脏数据。
10. 页面外壳统一 `ErrorBoundary > PageContainer(full-height) > 布局组件`，弹窗放布局外。

## 六之二、**运行期**陷阱（2026-09-14 真机实测踩出，编译期一律查不出来）

> 教训：本模块此前长期"编译通过 + 静态核对通过"就当完成，结果**一开真机就有 5 个页面整页 500/404**。
> **交付前必须对运行中的后端发一次真实请求**（`node tools/e2e-trade.cjs`，见下）。

11. **`/api` 双前缀 → 整页请求全 404（前端最易犯、后果最重）**
    `utils/request.ts` 的 axios 实例已是 `baseURL: '/api'`，`vite.config.ts` 的 proxy **没有 rewrite**。
    故 api 文件里**一律写相对路径**（`/payment/record/page`），**绝不写** `/api/payment/record/page` —— 后者会合成 `/api/api/...` 直接 404。
    反面教材：`api/payment/index.ts` 曾有 **20 处**写成 `/api/...`，导致**支付中心 4 个页面在浏览器里全部不可用**。
    > 自查：`grep "'/api/" frontend/apps/pc-admin/src/api -r` 应只在注释里命中。

12. **主键是雪花 BIGINT，前端/脚本**绝不能**用 `Number(id)` 比较或做 Map key**
    `Number(990000000000000001)` 与 `Number(990000000000000003)` 会舍入成**同一个 double**（超过 2^53），
    于是 Map 里后写入的值覆盖前一个 → 把正确的数据判成错误。**一律按字符串比对**（`String(id)`；`pg` 默认就把 BIGINT 返回为字符串）。
    > 实踩：E2E 里用 `Number(r.id)` 做聚合 Map 的 key，把 `SP-TEST-001` 的真实库存 0 读成 `SP-TEST-003` 的 152，误报视图错误。

13. **MyBatis-Plus 的 `camelToUnderline` 对「驼峰+数字结尾」不补下划线**
    `gradePrice1` → **`grade_price1`**。若库里/视图里是 `grade_price_1`（带下划线），**必须显式 `@TableField("grade_price_1")`**，否则 `BadSqlGrammarException: 字段 "grade_price1" 不存在`。
    > 实踩：`ErpProductMall.gradePrice1..8` 未加注解 → `GET /erp/mall/admin/product/page` 整页 500（商品上架页打不开）。
    > 划界：真库同类列多是**不带**下划线的（`erp_stock_in_item.price_level1`、`erp_stock_bom_item.ext_num1`），与 MP 规则一致，**只有 `v_mall_product.grade_price_1..8` 是带下划线的异类** —— 不要无脑给所有同类实体加注解。

14. **实体 `extends BaseEntity` 前，先确认真表有 `create_by`/`update_by`/`version`**
    `BaseEntity` 声明了这三列，MyBatis-Plus 生成 SELECT 时会**无条件列出它们**（与是否为 null 无关）。表里没有就**每次查询必抛** `字段 "create_by" 不存在`。
    > 实踩：`core-payment` 的 5 张表（`payment_request`/`payment_record`/`refund_request`/`refund_record`/`payment_reconciliation`）**全都没有**这三列 → 这 5 个实体的**读路径全挂**；已由 `V11.367.0` 补列（`version INTEGER DEFAULT 0`）。
    > 另外：全仓**没有 `MetaObjectHandler`**，所以 `@TableField(fill = …)` 其实不会填充 —— INSERT 侥幸不报错（null 被 `NOT_NULL` 策略忽略），SELECT 才暴露。

15. **表**没有** `tenant_id` 列时，必须把它加进 `MyBatisPlusConfig.IGNORE_TENANT_TABLES`**
    否则多租户拦截器会注入 `AND tenant_id = 1` → `字段 "tenant_id" 不存在`。
    > 实踩：`shop_template`（平台共享的行业模板库）无 `tenant_id` → `/template/list` 与 `/template/library` **双双 500**；已加入忽略表。
    > 注意：文档里把它记成「未按租户隔离」是**不够的** —— 不加忽略表它不是"隔离得不好"，而是**直接报错**。

16. **MyBatis-Plus 的 `xxx(boolean condition, column, value)` 会先求值 `value`**
    `wrapper.lt(to != null, Col::getX, endOfRange(to))` 在 `to == null` 时**仍会执行** `endOfRange(null)` → NPE。
    凡"条件式"重载里套了会 NPE 的表达式，都要在表达式内部兜 null。
    > 实踩：`PaymentServiceImpl`/`RefundServiceImpl.endOfRange` → 页面**默认查询**（不传时间区间）必 500。

17. **`ADD COLUMN … DEFAULT` 会把默认值回填到既有行** —— 只有当"默认值 == 迁移前的既有语义"时才可以用。
    - 可以：`version INTEGER DEFAULT 0`（`@Version` 需要非 null，0＝初始版本，不翻转判定）。
    - **不可以**：`reg_audit_required INTEGER DEFAULT 0`（旧列 `enable_auto_audit=0` 表示"需审核"，回填 0 会**翻转**审核行为）。
      正确做法＝**无 DEFAULT 新增 + 按旧列反向映射订正存量行**（见 `V11.365.0`）。

18. **「上架状态」是**两套词表**：写入用 `ON_SHELF`/`OFF_SHELF`，读出只有 `ON_SHELF`/`INACTIVE`**
    - **写入**：`PUT /erp/product/batch-status` body `{ids, status}`，`status ∈ {ON_SHELF, OFF_SHELF}` → 落 `erp_product.mall_shelf_status`（1/0）。
    - **读出**：视图 `v_mall_product.status` 与列表接口 `GET /erp/mall/admin/product/page` 的 `status` 字段都是
      `CASE WHEN p.mall_shelf_status = 1 THEN 'ON_SHELF' ELSE 'INACTIVE' END` —— **永远不产出 `OFF_SHELF`**。
    - **故**：前端用 `isOnShelf(record)` 做这层映射（`=== 'ON_SHELF'` 才算已上架）；**写断言/回读断言必须各按自己那套词表**，把写入值直接拿去比读出值会误判（2026-09-14 E2E 实测踩到，误报 2 项失败）。
    - 判断某页到底是哪套：**读侧一律以视图/接口返回值为准，写侧以该端点 body 的取值域为准**，不要假设两边同词表。

## 七之二、金标准自检清单（机械可验，改完必过）

路线 A 的**列表页**必须同时满足下列各项。可直接用 grep 逐页核对：

| # | 检查项 | 判定方式 | 是否强制 |
|---|---|---|---|
| 1 | 外壳 | 文件含 `ErrorBoundary`、`PageContainer`（`:full-height`） | **强制** |
| 2 | 布局 | 文件含 `CategoryListLayout` | **强制** |
| 3 | 表格 | 文件含 `BillDetailTable` **或** `BillTableList`（见一、路线表 `CategoryListLayout > BillTableList/BillDetailTable`），且**未**传 `:max-height` | **强制** |
| 4 | 分页 | 文件含 `StandardPagination`（`variant="classic"`）；**分页由布局组件内置**的页面（`DocCenterLayout` / `BillTableList` / `VxeTableList`）改看渲染结果 —— 分页栏必须是经典形态（`.classic-pagination`），见《对标开发技术参考文档》§5.5 ④ | **强制** |
| 5 | 页面配置 | 文件含 **`PageConfigPanel`**，且同时传 `:default-query-fields-config` 与 `:default-function-buttons-config` | **⚠️ 取决于对标** |
| 6 | 列配置 | `storage-key` 与 `global-config-key` **同值**，且与页面配置 `storage-key` **不同值** | **强制** |
| 7 | 打印 | 含 `handlePrint()` 与 `handleF8Key()` | 对标有打印才强制（**本系统独有页判 N/A**） |
| 8 | 导出 | 含 `exportCsv`（或后端导出端点） | 对标有导出才强制 |

> **2026-09-14 机械核验（23 个菜单页全量，脚本 `tool-results/goldcheck/Audit.ps1`）**：第 1/2/3/4/7 项全部通过，**第 5 项 13 页应有全有、6 页应无全无**（对标条件规则落地无误）。唯一未过的是 `trade/api-monitor/list.vue` 的第 7 项打印 —— 该页是**本系统独有页**（`数据同步开发文档` 记「ql361 未见到独立页，实测不可得」），且其本身即《多 Tab 列表页》参照实现，故第 7 项判 **N/A** 而非缺口。
>
> ⚠️ 本次核验也订正了清单本身两处**过窄/过宽**的措辞（原第 3 项只写 `BillDetailTable`、原第 7 项写死「强制」），与上文路线表口径统一。**核验脚本的两条已知误报**：① `$gck[0]` 在 PowerShell 中对**单个字符串**取下标得到的是首字符，会让第 6 项假失败，必须 `@(...)` 包一层；② `:full-height` 写成了带冒号的绑定形式，实际用法是**静态属性** `full-height`。

### ⚠️ 第 9 项（新增）：**按钮/入口一律以对标实测为准，不许按「通用模板应该有」补**

与第 5 项（`PageConfigPanel`）同源的坑：**「金标准模板里有的按钮」≠「每个页面都要有」**。

**已实证的案例（`商品上架`）**：对标工具栏实测逐字为 `批量上架｜批量下架｜设置商城默认排序方式｜刷新｜打印(F8)｜更多` —— **没有「新增」、没有「删除」**。因此该页：
- 不挂「新增商品」按钮、不挂删除入口 = **对标一致** ✅
- 若照通用模板补上这两个按钮 = **引入非对标功能** ❌（且「新增」会在商城页凭空 INSERT `erp_product` 主数据，缺单位/分类/价格体系，还可能撞 `product_code` 唯一约束）

**推论（判定口径）**：一个页面存在「已写好的端点但页面没挂入口」时，**先查对标实测工具栏**：
- 对标**有**该入口 → 是真缺口，要补；
- 对标**没有** → 该端点属**历史遗留**，页面保持不挂才是对的，**不要**为了「端点不浪费」而加按钮。

### ⚠️ 第 5 项必须逐页查对标，不可一刀切

### 9.3 新增的两条通用陷阱（已写入《交易模块 README》§5）

1. **「个人配置 / 全局配置」两 Tab 的默认勾选可能不同**（实测商品上架：个人 33 / 全局 32）→ 抓取文档**必须写明读的是哪个 Tab**；默写「默认显示 N 列」而不标 Tab 是不可复核的。抓取脚本用 `QL361_CFG_TAB=personal|global` 切换。
2. **多 Tab 页面的 `.icon-shezhi2` 会被 dojo 预渲染**（非激活 Tab 的图标 DOM 也在）→ 必须按可见性过滤 + 先切 Tab 再点，否则读到上一个 Tab 的列清单。

### 9.4 复核后仍存在的缺口

- **商品标签字典未抓到**（`商品上架`「商品标签」下拉的真实选项字典；也影响 `单位显示`）——脚本取到的 `opts` 是页面顶部「常用菜单」而非目标下拉，如实保留缺口，**不得推测**。
- **购物车 / 支付四页 / 外部平台三页无对标**——本系统建模，按「不发明字段」原则如实标注。
- **商城订单页 vs 订单处理页**双入口双份维护（列定义需同步改）；是否收敛为菜单重定向待定。
