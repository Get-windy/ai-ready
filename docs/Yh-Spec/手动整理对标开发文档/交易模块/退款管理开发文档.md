# 退款管理开发文档

> **文档类型：** 页面对标复刻
> **对标系统：** ql361（来肯企汇，`22stable.ql361.com`）
> **对标来源：** 本系统交易模块「支付结算」组 → 退款管理（Menu 90303。**来源=对标实测抓取 2026-09-07**）
> **定位：** 按金标准结构编写；在线支付**退款请求/退款单**审批列表页（**单视图列表**，无独立表单，含审批流「批准/拒绝」+ 批量审批 + 详情抽屉 + 4 张统计卡片）。

## 页面概述

退款管理是**在线支付退款请求的统一审批中心**：查询退款请求（申请金额、退款原因、申请人、状态、渠道退款号、创建时间），对待处理（status 0）的退款单做批准/拒绝（单条或批量），并通过渠道回调 `POST /api/refund/callback/{channel}` 结果更新为已退款/已拒绝。（**无创建入口**——退款请求由业务侧 `POST /api/refund/request` 发起，本页做审批。）**单入口，无子 Tab，无独立表单**。

| 页面 | 地址 | 说明 |
|------|------|------|
| 退款管理 | `payment/refund` | 单视图列表页（统计卡片 + 数据表 + 审批流） |

单入口：交易模块 → 支付管理 → 退款管理。

- 实测实据：数据表列 8、查询字段 **0**、列/页面配置弹窗 **无**。
- 状态机（`REFUND_STATUS_MAP`）：0 待处理 / 1 处理中 / 2 已退款 / 3 已拒绝。

### 对标参考（ql361 未见到独立「退款管理」列表页）
任务映射 ql361 两处退款相关结构做对标参考（均有实测）：
1. **设置→系统配置→支付配置→「在线退款」Tab**：仅为**自动退款开关配置**（在线支付自动退款 开/关 + 自动退款说明 + 保存），**非退款流水/审批列表**（无列/查询/审批流）。
2. **商城→订单处理→退货申请处理**：为**商城退货申请列表/审批页**（按单据/按明细 两 Tab），是退款/退货类单据列表+审批的最接近对标，其**按单据**列结构见下。

## 页面结构（含配置）

退款管理 = 单视图列表页（无子 Tab，无列/页面配置弹窗）。无查询区，仅统计卡片 + 数据表。

### 统计卡片（固定 4 项）
待审批（status 0）、已批准（status 1/2）、已拒绝（status 3）、退款金额（累计退款）。

### 查询条件字段（固定 0）
无筛选条件；仅数据表 + 刷新按钮。

### 功能按钮 / 行级操作
- 头部按钮：刷新（F5）。
- 批量操作：**批量批准**、**批量拒绝**（选中行 > 0 时显示，对选中行逐条 `/request/{id}/approve`）。
- 行级操作：**详情**（抽屉）、**批准**、**拒绝**（仅 `status===0` 时显示；Modal 确认后 `/request/{id}/approve?approved=1|0`）。

### 数据表列（固定 8 列）
支付请求ID、退款金额（¥ 红色）、退款原因、申请人、状态（Tag）、渠道退款号、创建时间、操作（详情/批准/拒绝）。

## 业务规范说明

- **退款主线**：支付成功（`payment_record`）→ 业务侧发起退款 `POST /api/refund/request`（paymentId+金额+原因）→ 本页审批（批准走在线退款流程，拒绝则结束）→ 渠道回调 `POST /api/refund/callback/{channel}` 落退款结果 → 状态 待处理/处理中/已退款/已拒绝。
- **金额口径**：退款金额 ≥0 且 ≤ 支付可退金额（对外发起）；页面以 ¥ 红色展示。
- **审批**：待处理（status 0）可批准/拒绝；单条或批量。审批后为处理中（status 1）→ 回调成功 已退款（2）/失败 已拒绝（3）。
- **审批人留痕**：`approverId`/`approveRemark`（后端）；前端详情抽屉未展示，见「待完善」。
- **与支付请求的关系**：`paymentId` 关联支付请求/支付记录；渠道退款号 `channelRefundNo` 对应第三方退款单号。
- **下游客商**：ql361 参照「设置→支付配置→在线退款」的自动退款说明：有处理中的在线退款时不能再次提交退款，在线退款处理完成后方可发起（本系统需在审批侧取值）。

## 实现差异说明

**实现文件**：
- 前端：`apps/pc-admin/src/views/payment/refund/list.vue`
- API：`apps/pc-admin/src/api/payment/index.ts`（`refundApi`）
- 后端：`backend/core/payment/core-payment/.../RefundController.java`（`@RequestMapping("/api/refund")`：`POST /request`、`GET /request/page`、`GET /request/{id}`、`POST /request/{id}/approve`、`POST /callback/{channel}`、`GET /record/page`）
- 表：`refund_request`、`refund_record`（V8.10.0__Payment_Center_Tables.sql）

### 页面对齐（当前：`BillTableList`）
- **单视图列表**：当前无子 Tab、无独立表单，符合「单入口审批列表」定位。
- **查询区（0 字段）**：无筛选条件（仅数据表 + 刷新 + 批量审批）。
- **数据表列（8 列）**：支付请求ID、退款金额、退款原因、申请人、状态、渠道退款号、创建时间、操作。
- **统计卡片（4 项）**：待审批/已批准/已拒绝/退款金额（基于当前页数据实时统计）。
- **审批流**：单条 批准/拒绝 + 批量 批准/拒绝（`/request/{id}/approve?approved=`）。
- **行级操作**：详情（抽屉）。
