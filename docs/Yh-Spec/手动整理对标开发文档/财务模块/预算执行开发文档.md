## 页面配置

### 概要卡片（本系统实测）
预算总额、已执行、冻结金额、剩余额度、执行进度、预算单数、超支科目、预警科目（8 档）。
口径：剩余 = 预算 − 已执行 − 冻结；执行进度 = 已执行 ÷ 预算 × 100%。

### 数据表列
**按预算单（16 列）**：序号、预算编号、财政年度、部门、预算单名称、状态、预算金额、已执行、冻结金额、剩余额度、执行进度、预警、预算科目数、超支科目数、最近执行、操作。

**按预算科目（18 列）**：序号、预算编号、财政年度、部门、预算科目编码、预算科目名称、状态、预算金额、已执行、冻结金额、剩余额度、执行进度、超支金额、执行笔数、最近执行、预警、备注（默认隐藏）、操作。

## 业务规范说明

- **执行跟踪**：按部门/科目看预算使用（已执行=实际发生，冻结=占用待复核，剩余=预算−已执行−冻结）。
- **超支预警**：执行进度超 100% 预警。
- **来源**：费用/支出单据记账后回写预算执行。

### 接口清单（新增）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/erp/budget/execution/rows` | 按预算单维度分页（含科目聚合、预警级别） |
| GET | `/api/erp/budget/execution/items` | 按预算科目明细维度分页 |
| GET | `/api/erp/budget/execution/logs` | 执行流水（冻结/释放/消耗 + 来源单据） |
| GET | `/api/erp/budget/execution/warnings` | 超支预警清单（>100%）与接近额度清单（≥90%） |
| GET | `/api/erp/budget/report/execution-summary` | 执行概览（补 冻结金额 / 超支科目 / 预警科目 / 已转入执行单数） |

> 只读约束：控制器**只提供 GET**，`POST /execution/items` 返回 405，无任何修改已执行/剩余额的入口。

### 口径实现
- **单一口径来源**：页面金额一律由 `budget_item`（预算科目）实时聚合，不直接采用 `annual_budget` 汇总列，从实现上杜绝汇总漂移与「直改已执行/剩余额」。
- **恒等式**：`remaining_amount = budget_amount − used_amount − frozen_amount`，由 `BudgetControlServiceImpl.applyItemAmounts()` 统一维护；任何变更后调用 `AnnualBudgetService.recalculateSummary(budgetId)` 同步主表汇总。
- **预警级别**：`over`（>100%，超支）/ `warn`（≥90%，接近额度）/ `normal`。
- **执行回写**：费用单记账成功后，`ExpenseDocServiceImpl.writeBackBudget()` 按「会计年度 + 部门 + 费用科目编码」匹配已审批/执行中的预算科目并计入已执行（`sourceType=expense`、`sourceNo=YBFYD-单号`）。与记账同事务提交；**超支不阻断记账**（`consumeBudget(..., allowOverBudget=true)`），转超支预警呈现；未匹配到预算的科目记 warn 日志。

### 待完善（非阻塞）
1. **回写覆盖面**：目前仅接通《费用单》；其他支出类单据如需计入预算，调用同一 `BudgetWritebackService` 即可。
2. **红冲/反记账**：费用单无已记账回退入口，故未实现预算已执行回冲；若后续支持红冲，需同步补冲减回写。
3. **硬控制**：当前为「预警式」软控制（超支放行 + 高亮预警），未实现采购/费用提交前的预算硬拦截。

### 遗留跨模块观察（非本页阻塞）
- `/api/erp/budget/annual/page` 的 `departmentId` 参数在编制模块重构为 `pageQuery` 后**已不生效**（`AnnualBudgetQuery` 无部门字段）。《预算执行》不依赖该接口；受影响的调用方为《预算计划》列表的部门筛选。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 预算单一口径（红线）**：预算执行只读取自预算编制+已记账支出，**严禁直改已执行/剩余额**；剩余=预算−已执行−冻结必须成立。
- **P1 执行回写**：费用/支出单据记账后回写预算执行（已执行↑），冻结=占用待复核。
- **P1 超支预警**：执行进度超 100% 预警，辅助控制超预算支出。
- **P2 验收**：无桩/无模拟；执行回写、剩余公式、超支预警需真实数据闭环验证。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
