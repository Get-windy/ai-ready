## 1. 页面概述

业务员提成页是**销售提成的核算页**：查询区给出时间区间与业务过滤条件，点「查询」后由后端按「提成方案」实时计算各业务员的提成结果。其页面性质有三点区别于普通台账：

1. **计算型（不查询不出数）**——首屏不预加载数据，空态文案即「点击查询才能计算提成统计数据」（实测 `head` + `.png` 实据）；
2. **规则驱动**——结果完全由「提成方案」决定，方案入口在工具栏（`提成方案`），改方案即改口径（方案字段明细**待复核**）；
3. **口径可选**——查询区有 `按已结算提成` 勾选项，勾选后只统计已结算部分（勾选项带 `?` 帮助提示，实据）。

| 页面 | 地址（ql361） | 说明 |
|------|------|------|
| 业务员提成 | 分析 → 提成分析 → 业务员提成 | **单视图计算型页**（无页内 Tab）：查询区 + 提成方案入口 + 结果区（打开时空态） |

- 单入口：分析 → 提成分析 → 业务员提成。
- 实测实据（2026-09-15）：**无页内 Tab、无列配置齿轮、无记录数、无表格渲染**，页面处于空态（见头部 ⚠️）。
- 同组关系：本页＝销售侧提成计算；`回款统计`＝回款侧三口径核算；`业绩提成中心`＝按月矩阵的结算闭环工作台。

### 配置功能说明
- 实测工具栏（`.png` 实据）：`提成方案`、`刷新`、`打印(F8)`、`导出`；另有 `查询`。
- 实测查询区（`.png` 实据）：`查询方案`（`--查询方案-- +`，支持保存/切换方案）、时间快捷段 `昨日 / 今日 / 本周 / 上周 / 本月 / 上月 / 近三月`、日期范围（实测默认 `2026-09-01 至 2026-09-15`）、`经手人`、`部门`、`商品`、`单据类型`（实测默认 `全部单据`）、`销售类型`（实测默认 `全部`）、勾选项 `按已结算提成`。

- 黄色/提示：无（本页未见「某月未结算」类提示条，该提示属「业绩提成中心」）。

## 4. 业务规范

### 提成计算口径

- **计算时点**：查询时**实时计算**（非预存快照）——页头提示「点击查询才能计算提成统计数据」为直接实据。方案变更后重查即按新方案出数。
- **取数范围**：查询期内、属于所选 `经手人 / 部门 / 商品` 且符合 `单据类型 / 销售类型` 的销售单据。
- **方案驱动**：结果列由 `提成方案` 定义，方案可按「按金额 / 按毛利 / 按数量 / 按回款 / 按单价」等多口径配置（该组词仅出现在 §3.3 的 DOM 残留表头中，**方案类型枚举待复核**）；基准文档记「按销售额/毛利/数量阶梯」亦标注为待复核。
- **已结算过滤**：勾选 `按已结算提成` 后，仅统计已结算提成部分；帮助提示（`?`）内容**未抓取，待复核**。

### 结算状态机（本系统侧可确认口径）

本系统 `erp_commission_record.status` 的取值与含义（`views/analytics/commission-center/index.vue:61-66`、`CommissionRecordMapper.java:27-33`）：

| 状态 | 含义 | 结算归属 |
|---|---|---|
| `DRAFT` | 待确认 | 未结 |
| `CONFIRMED` | 已确认 | 未结 |
| `PAID` | 已结算 | **已结** |
| `CANCELLED` | 已取消 | 不计入 |

即本系统的「已结 / 未结」二分口径为：**已结 = `PAID`**；**未结 = `DRAFT` + `CONFIRMED`**。

### 与其他页面关系

- 同组三页分工：`业务员提成`（销售侧实时计算）→ `回款统计`（回款侧三口径核算）→ `业绩提成中心`（按人员 × 月份矩阵做**批量结算**并锁定）。
- 下游约束：`业绩提成中心` 的提示条「若存在某月份提成未结算，此后月份提成将不显示」表明结算必须**按月顺序推进**，本页计算结果即其上游数据源之一。
- 上游数据：销售单据（经手人归属）+ 提成方案规则。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/analytics/staff-commission/index.vue`（448 行）。
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout`（`:tabs="[]"`、`:show-category-panel="false"`、`:show-table-footer="true"`）+ `BillDetailTable`（`:view-mode="true"`、`:min-rows="queried ? 20 : 0"`）+ `StandardPagination`（`variant="classic"`）+ `PageConfigPanel`（对标有「业务员提成-页面配置弹窗」实据）；页面配置键 `analytics-staff-commission-page-config`，功能按钮 3 项 + 打印配置 2 项。

- **打印(F8) / 导出**：均先校验 `queried`（未查询则提示"请先点「查询」计算提成统计数据"）；打印为 `window.print()` 直出 HTML 并绑定 F8；导出为逐页 100 条取全量 CSV。
- **合计行 / 排序**：无合计行、无列排序。
- **取数端点**：`GET /erp/marketing/commission/staff-summary/page`（`page` / `size` / `keyword` / `startDate` / `endDate`）；行键取自 `referrerId`。
- **列清单判定依据**：对标 `columnConfig.err = "no gear"`（无表头齿轮）→ 对标列清单不可得，故取「本页原有源码列 ∩ `StaffCommissionSummaryItem` 真实返回字段」，不照抄对标文档 §3.3 的 DOM 残留表头。
- **后端**：本轮未改后端；未新增迁移。

### 剩余缺口

1. **首屏无表头 / 无列配置入口**：`min-rows="queried ? 20 : 0"` 使未查询时整个 `BillDetailTable`（含表头与齿轮）不渲染，列配置只能在点过「查询」后使用（`index.vue:101`、`BillDetailTable/index.vue:20-29`）。与对标首屏空态语义一致，但列配置入口在空态不可达。
2. **对标查询项多数未落地**：后端 `/erp/marketing/commission/staff-summary/page` 仅支持 `page/size/keyword/startDate/endDate`，故对标的 部门 / 商品 / 单据类型 / 销售类型 / 「按已结算提成」/ 查询方案 均未落地。
3. **对标列清单未确证**：对标侧 `columnConfig.err="no gear"`、开发文档 §3.2 标注「待复核」，故对标「按金额 / 按毛利 / 按数量 / 按回款 / 按单价 + 各类基数与分项提成」等表头**未确证**；这些字段在 `erp_commission_record`（`orderAmount/commissionRate/commissionAmount/referrerId/status`）中亦无对应列，故本页不做（不编造列）。
4. **无合计行**：对标是否有合计行未确证；本页无。
5. **「上周」等 7 段快捷段为前端自算**：`quickRange()` 在页面内独立实现（未复用 `shared/docTypes.ts` 的 8 段版本），维护上存在重复实现。
