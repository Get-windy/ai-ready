## 1. 对标系统与数据抓取方法

### 1.1 对标系统（来肯企汇 ql361 v2.2）

- 入口：https://www.ql361.com/Account/Logon ｜ 版本口径：**22stable.ql361.com**（文档以此为准）
- 架构：**桌面式多标签系统，页面无独立路由**——登录后在桌面点菜单图标，页面以标签页打开。抓取不能用 URL 直达，必须模拟点击菜单。

### 1.2 原始抓取证据（一级事实源）

```
tool-results/ql361/pages/<域>__<组>__<页面>.json   # 页面结构数据
tool-results/ql361/pages/<域>__<组>__<页面>.png    # 全屏截图
```

JSON 字段含义：

| 字段 | 含义 |
|---|---|
| `url` / `title` | 页面地址 / 标题 |
| `tabs` | 页内标签页 |
| `filters` / `filterLabels` | 查询条件字段 |
| `buttons` | 工具栏按钮 |
| `columns` | 表格**默认显示列** |
| `_desktop` | 桌面标签栏信息（含快捷键，如「保存草稿 Ctrl+S」） |
| `bodyPreview` | 页面主体预览 |

### 1.3 页面配置 / 列配置弹窗抓取（探针）

页面配置、列配置弹窗内容不在常规抓取 JSON 内，需用探针单独 dump：

- 探针脚本：`frontend/_probe_cfg2.js`（Playwright：登录 → 打开页面 → 点齿轮 dump 弹窗）
- 目标清单：`frontend/_probe_targets.json`（`[{domain, group, item, hasList}]`）
- 运行：`cd frontend && node _probe_cfg2.js "../tool-results/ql361/pages"`
- 输出：`tool-results/ql361/pages/<域>__<组>__<页面>__cfg.json`

**cfg JSON 结构**（字段提取的权威实据）：

| 键 | 含义 |
|---|---|
| `pageConfig.lines` | 表单/列表页「页面配置」弹窗的字段清单（格式 `序号\t\t字段名`） |
| `columnConfig.lines` | 表单/列表页「数据表列配置」弹窗的列清单（格式 `序号\t\t列名`） |
| `listPageConfig` / `listColumnConfig` | 双入口页面的**列表页**页面配置 / 列配置 |

提取规则：`re.sub(r'^\d+\t\t', '', line)` 去掉序号，得到纯字段/列名。

> ⚠️ **探针局限与修复（2026-08-15 实测 → 2026-08-18 修复）**：对标系统为桌面多标签架构，无独立路由，探针点「配置」齿轮时可能点到**其他已打开标签页**的齿轮（错页抓取）。修复：打开目标页后**关闭其他 `.dijitTab` 标签**（保留活动 + 含目标名的标签），齿轮定位恢复全局。错页 cfg 一律不用于覆盖文档。**2026-08-18 已用修复后探针重抓补全 6 篇待复核文档**：采购订单（35 字段 57 列）、预付款单（15+5）、提存（10+4）、其他收入（17+4）、借出单（14+45）、盘点单（13+34）——各文档第 7 章「cfg 实测数据」；对账过程 `tool-results/ql361/cfg_summary.txt`。

### 1.5 Playwright MCP 实时抓取方法（2026-09-07 实测验证，供后续写文档复用）

> 适用：`_probe_cfg2.js` 未覆盖 / 标「待复核」的页面，直接用浏览器实时抓取对标系统配置弹窗，获取**含隐藏列的全部可配置列**与**页面配置字段**。以下流程已**实测验证通过**（2026-09-07）：「按单收款」全部 4 Tab（待收款 40 列 + 21 默认显示 / 超期 35 列 + 16 默认 / 全部单据 46 列 + 23 默认 / 发票查询 19 列 ×2 子 Tab + 11 默认）+「采购换货单」双数据表（换出/换入两表各 59 列 + 20 默认）。**两种方法——模拟点列配置弹窗 与 直接读 dgrid 列对象——抓取结果交叉校验一致**，可互相验证。

**① 登录**
- 入口 `https://www.ql361.com/account/logon`（官方登录），填账号 `15095664266` / `Ysh790921` → 自动跳转 `22stable.ql361.com/desktop.html`（桌面式多标签 ERP）。
- 登录后可能弹「预警提醒」对话框，点 `.dojoxDialogCloseIcon` 关闭。

**② 导航到页面**（桌面多标签、无独立路由，URL 不可直达，必须模拟点菜单）
- 点顶部菜单图标（销售/采购/财务/资料…）展开子菜单 → 点目标页面项。
- 用 `browser_find("页面菜单名")` 定位要点的菜单项再 `browser_click`。

**③ 抓「数据表列配置弹窗」（全部可配置列 + 默认显示列）**
- 入口 = **页面内嵌数据表**里的 **`icon-shezhi2` 设置图标**（⚠️ 不是页面顶层 `title="配置"` 按钮——那个打开的是「Show or hide columns」简化版，只含当前已选列，勿当全部列）。
- 点击 `.icon-shezhi2` → 打开正式「列配置弹窗」（标题含 **个人配置 / 全局配置** Tab，配置列「上级 / 列名 / 显示名 / 显示」，底部 上移 / 下移 / 恢复默认 / 保存，行带序号 1..N）。
- 提取：`browser_evaluate` 遍历弹窗 `tr`：`td[2]`=列名，行内 `.dijitCheckBox / input[type=checkbox]` 的 `.checked` 是否显示 → `[x]`=默认显示列、`[ ]`=隐藏列。据此得到「**全部可配置列（含隐藏）** + **默认显示列**」。
- 定位弹窗示例：`[...document.querySelectorAll('[class*=Dialog]')].find(d=>d.innerText.includes('全局配置') && d.innerText.includes('<页面特征字段>'))`。

**④ 抓「页面配置弹窗」（查询条件配置字段 / 功能按钮 tab 配置字段）**（2026-09-07 实测：入口 = 页面**最上面按钮栏**里的**齿轮状按钮**。⚠️ 注意**不是**功能按钮区那个文本「配置」按钮，也**不是**数据表内 `icon-shezhi2` —— 后两者打开的是「列配置」弹窗）
- 点击顶部按钮栏齿轮 → 打开 **"配置" Vue dialog**（⚠️ 非 dojo，勿用 `[class*=Dialog]` 锚定），顶部 2 个 Tab：**查询条件** / **功能按钮**，底部「使用鼠标拖动行可以调整顺序 + 恢复默认值 + 关闭(Esc)」。
- 按 Tab 切换后读 `dialog.innerText`，去掉标题词（配置/查询条件/功能按钮/使用鼠标拖动行可以调整顺序/恢复默认值/关闭）得字段/按钮清单。实测按单收款-待收款 => **查询条件 19 字段 + 功能按钮 8 项**（与金标准一致）。
- 判断弹窗：`[...document.querySelectorAll('*')].find(e=>e.innerText.includes('查询条件') && e.innerText.includes('功能按钮') && e.innerText.includes('使用鼠标拖动'))`。
- 提取：弹窗 `innerText`，按 `序号\t\t字段名` 逐行解析。

**⑤ 抓页面可见结构速览（查询条件 / 按钮 / 默认显示列）**
- `browser_evaluate(e=>e.innerText)` 于目标 `tabpanel`（如 `getByRole('tabpanel',{name:'待收款'})`），一次拿到查询条件、功能按钮、表头默认显示列、行数据、合计行。

**⑥ 难点 / 关键词**
- **多级 Tab**：外层 Tab（如 待收款/超期/全部单据/发票查询）+ 内层 Tab（如 发票查询→销售发票/采购发票），**每个 Tab 都要单独抓**（含各自的列配置弹窗）。
- **多 Tab 多数据表 → 列配置定位（2026-09-07 实测踩坑）**：多 Tab 复合页中**每个 Tab 的数据表各有 1 个 `icon-shezhi2`**（即"一表一列配置"），且 dojo 面板**预渲染**导致**非激活 Tab 的 `icon-shezhi2` 也"可见"**（`offsetParent` 非空）。若直接用 `document.querySelector('.icon-shezhi2')`/`.pop()` 会**点到别的 Tab 数据表**的列配置（抓错列数）。**正确做法**：先定位**当前激活 Tab 的内容容器**（用该 Tab 特征文本，如"开具发票/发票编号/结算状态"）+ 该容器内的 `.icon-shezhi2`；或点开弹窗后用 innerText 校验列数（如全部单据=46列含发票列，若只得 35/40 列说明点到别的 Tab 了，需重新定位）。
- **双数据表页面**（采购换货单/销售换货单：换出明细+换入明细）：**两个数据表各自 1 个列配置**，需分别点各自数据表的 `icon-shezhi2`。
- 「Show or hide columns」（aria-label）是另一个简化弹窗，勿混淆；正式列配置弹窗特征 = 个人配置/全局配置 Tab + 上移/下移/恢复默认/保存。
- 列配置弹窗若字段多可能需分页/滚动（40/46 列一次性都在，超出部分滚动查看）。

**◆ 本次实测验证结论（2026-09-07 · 可固化为标准方法）**
- **列配置入口 = 数据表内 `.icon-shezhi2`**（"一表一列配置"，多 Tab 多数据表 = 多个此图标）。
- **页面配置入口 = 页面顶部按钮栏「配置」齿轮 `iconButtonConfig`**（每 Tab 一个、id 各异，须点当前激活 Tab 可见的那个），打开 Vue"配置" dialog（查询条件 / 功能按钮两 Tab）。
- **`show or hide columns`（aria-label）≠ 正式列配置弹窗**，勿当作全部列来源。
- **多 Tab 多数据表定位**：非激活 Tab 面板也预渲染在 DOM 且 `offsetParent` 非空 → 不能用全页 `document.querySelector('.icon-shezhi2')`/`.pop()`，必须**在当前激活 Tab 内容面板内**定位该面板独有的 `.icon-shezhi2`（面板特征 = 该 Tab 独有文本/表头列名）。
- **保险校验**：点开弹窗后用 `innerText` 校验列数（全部单据应 46 列含发票列；若只得 35/40 列 → 点到别的 Tab 数据表，需重定位）。

### ⑦ 多 Tab 逐 Tab 抓取流程（实测验证通过 · 2026-09-07）

复合页（多 Tab）逐 Tab 抓取，务必按下面顺序，避免点到其它 Tab 的数据表/弹窗：

1. **先确认为当前激活 Tab**：`browser_find("Tab名")` 定位 Tab 元素，检查其 `className` 含 `active/selected` 或 `aria-selected="true"`；未激活先点击。
2. **抓该 Tab 页面配置弹窗**：点顶部按钮栏「配置」齿轮（`iconButtonConfig`，**每个 Tab 一个、id 各异**，须点**当前激活 Tab 可见的那个**），打开 Vue"配置" dialog（「查询条件 / 功能按钮」两 Tab），分别抓取后用「关闭(Esc)」关闭。
3. **抓该 Tab 列配置弹窗**：在该 Tab **内容面板内**查 `.icon-shezhi2`（面板特征 = 该 Tab 独有文本，如数据表表头列名），点击打开列配置弹窗，抓全部列+默认显示，关闭。
4. **确认下个 Tab 已激活后**重复。

> **关键**：多个 Tab 面板因 dojo **预渲染**都在 DOM 中，`.icon-shezhi2` 会重复（每 Tab 数据表一个），且**非激活 Tab 的也可能 `offsetParent` 非空** → 必须**在"当前激活 Tab 的内容面板"内**定位 `.icon-shezhi2`，而非全页 `document.querySelector('.icon-shezhi2')`。页面配置按钮同理（按激活 Tab 的 `iconButtonConfig` id）。

### ⑧ 更稳健：直接读 dgrid 列对象，绕过「列配置弹窗」（实测验证通过 · 推荐首选 · 2026-09-07）

dojo/dgrid 实测结论，**比"模拟点弹窗"更稳**，本次已用它抓全「按单收款」全部 Tab 列 + 「采购换货单」双数据表列，并与"点列配置弹窗"抓取结果**交叉校验一致**：

- **直接读列定义（推荐首选）**：当前 Grid 的**完整列（含隐藏）**可经 JS 直接读，无需点弹窗。在 `page.evaluate` 里：`const g = require('dojo/_base/registry').byId(gridId)`（或 `dijit.byId(...)`），读 `g.get('columns')` / `g.columns` / `g.subRows`，即得全部列定义（隐藏列只是显隐状态另存，列定义仍在）。**确定性最高、无弹窗 DOM 时序/遮挡风险、可拿全量列，且天然解决"多 Tab 多数据表 `icon-shezhi2` 定位"难题**（读对应 grid 实例即可，无需逐 Tab 点面板图标）。
- **显隐状态**：dgrid 无标准列显隐 API；ql361 的"默认显示列"状态存在于 ERP 额外配置/组件属性/localStorage。**本次成功读法**：从列对象里读 **`hidden` 标志**（或列定义上的显隐字段，如 `field` 的 `hidden`/`visible` 属性）以区分默认显示列与隐藏列；列**全量定义**从 `grid.columns` 可读；**默认显示列**亦可从列配置弹窗抓，两来源交叉校验一致。
- **激活 Tab 判断**：dojo 非激活面板可能是 `visibility:hidden` 而非 `display:none` ⇒ **`offsetParent` 不可靠**。改用 Playwright `:visible` / `locator.filter({visible:true})` / `isVisible()`；或 `getByRole('tab',{selected:true, name})`（若设了 `aria-selected`）；或先点 tab → 等该 `[role=tabpanel]` 可见 → 在其内 `locator('.icon-shezhi2')`。
- **业界通用**：列配置（显隐/顺序/宽）→ 常用 `localStorage`（key=表ID+用户ID，聚合 JSON）；列权限/敏感字段 → 后端接口动态下发。抓取优先"读配置数据源"而非"模拟点弹窗"。

## 2. 两类「配置」的本质区别（开发必读，勿混淆）

我们的页面存在**两个独立的配置入口**，字段范围互不重叠：

| 维度 | 页面配置 | 数据表列配置 |
|---|---|---|
| **入口** | 页面顶部「配置」齿轮按钮 | 数据表内 `icon-shezhi2` 设置图标（2026-09-07 实测；勿与页面顶部 `title="配置"` 的「Show or hide columns」混淆） |
| **配置对象** | **页面级字段**（表单字段 / 查询条件 / 按钮 / 摘要项） | **数据表的列字段** |
| **可配置项** | 字段的显示 / 隐藏、排序 | 列的显示 / 隐藏、显示顺序、列宽度、左固定、右固定 |
| **字段可位于** | 页面头部（搜索区 / 输入区）、页面底部（其他区）；**不含数据表列** | 仅数据表内 |
| **对标弹窗 Tab** | 页面配置 / 录单默认值 / 打印设置 | 个人配置 / 全局配置 |
| **对标配置列** | — | 序号、上级、列名、显示名、显示、回车键跳转、公式内容 |

> 抓取与落文档时严格区分：**「全部表单字段/查询条件」进「页面配置」，「默认列 + 全量可配置列」进「数据表格列配置」**，两者字段清单不得混写。

## 5. 通用业务规范（各开发文档不再重复，统一在此）

### 5.1 客户来源

单据客户来源于 **ERP 往来单位下的客户分类**（实体客户），而非 CRM 模块的客户信息。CRM 客户是公海客户，ERP 客户是实体客户。

### 5.2 架构师红线（Ponytail 六步过滤网）

动手前必过六关：①此功能业务真需要？②标准库/原生 API 能搞定？③现有依赖能否复用？④能否一行代码干净解决？⑤能否复用已有组件？⑥通通走不通才写最小可用闭环。
**Lazy, not negligent**——跨边界防注入、容灾、安全防御代码不准省。

### 5.3 业务逻辑基准

对标 Odoo、SAP、金蝶、用友、管家婆等生产级系统的业务逻辑与交互逻辑，溯源字段真实所属实体，实现真正的生产级数据闭环。订金是带使用条件的预收款或预付款。

### 5.4 验收标准（通用）

### 5.5 列表页 UI 约定（2026-09-10 用户反馈后固化，金标准列表页一律遵守）

**① 列配置只有一个入口：数据表表头齿轮。**
- 列显隐/宽度/排序/显示名由 `BillDetailTable` 内置「配置」弹窗（个人配置 / 全局配置）管理；
- **表格必须含序号列 `{ title: '', key: 'rowNo', type: 'rowNo', width: 40, fixed: 'left' }`** —— 齿轮图标就渲染在该列表头里，没有序号列 = 没有列配置入口；
- `BillTableList` **必须传 `:storage-key`**（每条表格唯一，多 Tab 页面按视图拼后缀，如 `expense-doc-table-columns-doc`），否则多个页面会共用组件默认键而互相串扰；
- **工具栏禁止再放列配置按钮**，页面里不要再引 `ColumnConfigPanel` / `useColumnConfig`（重复入口 + 两套存储互不生效）；
- 表格列一律传**原始列定义数组**（用 `defaultHidden: true` 表达默认隐藏），不要传外部过滤后的可见列；
- 多 Tab 页面动态切换 storage-key 时，`BillDetailTable` 已内置 watch 重新加载该视图配置（切 Tab 即生效，无需刷新）。

**② 图标按钮的悬停提示一律下置。**
- 全局默认已改为 `placement=bottom` + `mouseEnterDelay=0.4`（`src/utils/antdDefaults.ts`，`main.ts` 引入），页面**不需要逐个传 `placement`**；
- 案例根因：`styles/accessibility.css` 的 `[role="tooltip"]` 规则误命中 antd 浮层内层 `.ant-tooltip-inner`（同带 `role="tooltip"`），把它挤出文档流导致浮层**宽度塌成 0、中文竖排并压住按钮**；已限定为 `[role="tooltip"]:not([class*="ant-"])`。改 placement 治不了这个根因。

**③ 工具栏右侧标准构成**：页面配置 / 页面独有功能（如「审批人配置」「图表显隐」）/ 新增 / 刷新 / 打印(F8) / 导出 —— 不含列配置。

### 5.6 外部服务与密钥「配置落位」统一口径（2026-09-13 增补，开发必读）

> 任何**需要外部服务/密钥/环境相关参数**的功能（地图、短信、邮件、对象存储、支付、渠道对接、任务调度、监控…），
> 在写开发文档时必须写明「**本页的配置项落在哪里、怎么生效、缺失时降级成什么**」。
> 目的：避免出现「设了环境变量却不生效」「密钥硬编码进代码」「配了但没人知道在哪配」三类问题。

#### 5.6.1 四条落位通道（按优先级）

| # | 通道 | 落位 | 生效 | 适用 |
|---|------|------|------|------|
| 1 | **环境变量** | `AMAP_API_KEY`、`DB_PASSWORD`、`REDIS_HOST`… （Spring relaxed binding：`dms.map.amap.api-key` ⇔ `DMS_MAP_AMAP_APIKEY`） | 重启后端 | 🔴 生产首选：密钥不进仓库、不入库、可按环境隔离（K8s Secret / compose `.env`） |
| 2 | **core-api 的 Spring 配置** | `backend/core/api/core-api/src/main/resources/application.yml`（+ `application-{profile}.yml`）；或启动参数 `--dms.map.amap.api-key=xxx`；或外部化文件 `--spring.config.additional-location=file:./config/` | 重启后端 | 单机部署、编排注入、非敏感参数 |
| 3 | **配置中心（数据库）** | 《配送参数》/《配送配置》等配置页写入配置表（如 `dms_config`，口径：全局默认 `tenant_id=0` + 租户覆盖） | **页面保存即热生效**（本实例立即、跨实例 ≤30s；实现见 `MapKeyResolver`+`ConfigChangedEvent`） | 私有化一键运维、运营可自助调整的参数 |
| 4 | **业务档案表字段** | 由页面维护的角色/渠道/店铺档案（如 `dms_channel.config_json`、`external_channel_config`、`md_payment_method`/`md_payment_channel` 的商户号与证书），**而不是配置文件** | 页面保存即生效 | 多值、按对象（渠道/店铺/商户）各一套的对接凭据 |

#### 5.6.2 🔴 硬规则（踩过的坑）

1. **模块自带 yml 不生效**：`dms/src/main/resources/dms-application.yml`、`erp/erp-delivery-route/src/main/resources/application.yml` 等**位于嵌套 jar 内，core-api 启动时不会加载**（Spring Boot 只读 classpath 根那一份）。在这些文件里写 `${AMAP_API_KEY:}` 是**无效**的——必须写到 core-api 的 `application.yml`。
   - 反面证据（2026-09-13 实测）：`dms.map.*`、`amap.key`、`dms.erp.base-url`、`xxl.job.*`、`notification.sms.*`、`sync-engine.api-url`、`wms.erp.base-url`、`batch.cache.*`、`stock.alert.low-stock-threshold`、`storage.local.base-url`、`mq.rabbit.*`、`search/elasticsearch.*` 等**均未出现在 core-api 已加载的 yml 中** → 只能靠环境变量/启动参数/外部化文件配置；新功能**务必**把需要的键补进 core-api `application.yml` 并给默认值。
2. **前端 `VITE_*` 是构建期注入**：`VITE_SENTRY_DSN`、`VITE_AMAP_KEY` 等来自 `frontend/apps/<app>/.env.{development,production}`，**运行时改不了**，生产要在 CI 构建时注入；需要运行时可配的 Key（如地图）应由**后端接口下发**（参考 `GET /api/dms/route/config` 的 `keySource/envVarName/configKey` 诊断字段，只回是否配置与来源、**不回显明文**）。
3. **密钥优先不入库**：能用环境变量/Secret 的绝不写进代码或提交进仓库；确需页面维护的按通道 4 落库，并遵循「**脱敏展示 + 仅授权角色可见 + 日志不打印**」。
4. **必须有降级**：配置缺失时**不得阻塞业务**（示例：地图 Key 缺失 → 直线距离降级并在响应 `degraded=true`；地址编码等无法离线完成的 → 明确失败并给出「去哪配」的指引，**绝不返回假数据**）。
5. **换配置要能生效**：写明生效方式（重启 / 热生效 / 构建期）。热生效实现：保存后发布领域事件 → 消费方失效本地缓存（多实例用 TTL 兜底）。

#### 5.6.4 排查口诀

- **「改了配置没反应」** → 先确认写的是不是**core-api 已加载的 yml**（模块自带 yml / 嵌套 jar 内 = 不生效）；
- **「环境变量设了没用」** → 键名是否在 core-api yml 里声明过（未声明的键靠 relaxed binding 也能生效，但**拼写**必须严格，如 `DMS_MAP_AMAP_APIKEY`）；
- **「页面一直降级」** → 用模块自己的诊断接口看来源（如 `GET /api/dms/route/config` 的 `keySource`）；
- **「多租户读不到全局默认配置」** → 见记忆/文档中的「全局默认行被租户插件过滤」口径：读全局用 `@InterceptorIgnore(tenantLine="true")`，写目标租户行前 `MyBatisPlusConfig.setTempTenantId(tid)`。
