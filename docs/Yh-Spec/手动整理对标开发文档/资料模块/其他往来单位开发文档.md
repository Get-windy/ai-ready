# 其他往来单位开发文档

> **文档类型：** 自建页面（无对标）× 资料模块金标准
> **对标系统：** ql361（来肯企汇，`22stable.ql361.com`）——**本页无对标入口**
> **定位：** 按资料模块金标准实现；其他往来单位 = 非客户/非供应商/非物流的往来单位主数据（银行、政府机构、劳务公司、维修服务商……），按「单位类别」区分，类别可由用户自行维护。

## 页面概述

其他往来单位用于维护**非客户/非供应商/非物流的往来单位**（银行、政府机构、劳务公司、维修服务商、培训公司、财务公司、法律服务、保险公司、IT 服务商、咨询公司、仓储合作方、质检机构、其他），按「单位类别」区分。双入口（列表 + 表单）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 其他往来单位列表页 | `md/partner/index` | 往来单位档案列表（左「单位分类」树 + 右数据表） |
| 其他往来单位表单页 | `md/partner/form`（编辑 `?id=x`） | 新增/编辑往来单位 |

> 其他往来单位走 `biz_party.party_type`=4（other），`md/partner` 为其他往来端口。
> 🔒 **对标实测（2026-09-07）**：当前账号（杨生淮 / 肃州区皇朝酒店用品商行）的 **资料 → 往来单位** 子菜单仅包含 **客户 / 供应商 / 物流公司 / 互联账号** 四项，桌面整棵菜单树中也未检索到「其他往来单位」菜单项。
> 因此本页为**本系统独创页面**，版式与规范对齐同域的「供应商 / 物流公司」金标准页面（资料模块布局），**不以 ql361 页面作为对标数据**。

## 新增/编辑表单页配置

表单为**档案式分区卡片**（与客户/供应商/物流公司一致，非单据式 `BillFormPage`），分区与落库字段一一对应（无桩）：

| 分区 | 字段 | 落库位置 |
|------|------|----------|
| 顶部选项 | 该单位还有其他业务关系：客户 / 供应商 / 物流；勾选「客户」时可启用销售价格跟踪 | `biz_party.roles`（`OTHER` + 勾选项）、`price_track_enabled` |
| 基础信息 | 单位名称*、单位编号*、单位类别*（可内联新增类别）、助记码、状态、备注 | `party_name / party_code / category_id / mnemonic_code / status / remark` |
| 联系人 | 联系人、联系电话、联系地址 | `biz_party_contact` 主联系人（`is_primary=1`，`contact_name / phone / detail_address`），电话同步 `biz_party.phone` |
| 纳税人信息 | 公司全称、税号、地址、开户行、银行账号 | `company_full_name / tax_number / address / bank_name / bank_account` |
| 期初信息 | 期初应收金额、期初应付金额 | `opening_receivable / opening_payable` |
| 其他信息 | 默认经手人、结款方式（挂账 / 现结） | `default_handler_id / default_handler_name`、`settlement_type`（挂账=1/现结=0） |
| 证件信息 | 营业执照（固定首项）+ 可选/自定义证照（通用组件 `CertUploadList`，始终保留一个待输入位） | `erp_partner_attachment`（`category='CERT'`，`file_name`=证照名称） |
| 附件 | 附件上传 | `erp_partner_attachment` |

- **单位编号**：进入新增页时经 `GET /erp/md/customer/next-seq?prefix=WLDW` 生成 `WLDW-YYYYMMDD-序号`（序号按日重置；号段解析已修复，见「实现差异说明」）。
- **编辑**：`md/partner/form?id=x` 回填主档 + 主联系人；「保存并新增」仅新增态可用。
- **快捷键**：`Ctrl+Enter` 保存并返回列表。

## 业务规范说明

- **单位来源**：ERP 往来单位-其他（`biz_party.party_type`=4）。
- **主体关系**：客户=1 supplier=2 logistics=3 other=4 统一 `biz_party`；多重身份冗余在 `biz_party.roles`（`OTHER,CUSTOMER,...`）。
- **编号前缀**：WLDW（中文）/ PTR（英文），经 `next-seq` 生成，形态 `WLDW-YYYYMMDD-序号`。
- **类别**：`biz_party_category`（`party_type`=4），可由用户维护；列表 / 表单 / 导入统一使用 `categoryId`。
- **用途**：用于费用报销（维修/培训/咨询）、质检（质检机构）、仓储合作、银行/政府/劳务等非购销主体关联。

## 实现差异说明

**实现文件**：
- 前端：`views/md/partner/index.vue`（列表，`CategoryListLayout` + `BillDetailTable` + `PageConfigPanel` + `BaseDataImportWizard`）、`views/md/partner/form.vue`（档案式表单）
- API：`api/erp/partner.ts`（`partnerApi` / `partnerCategoryApi`）
- 后端：`erp-partner` 模块 `party/controller/MdCustomerController.java`（`@RequestMapping("/api/erp/md/customer")`，`partnerType=other`→`party_type=4`）、`PartyCategoryController`（分类 CRUD）
- 表：`biz_party`（主）、`biz_party_category`（类别）、`biz_party_contact`（联系人）、`biz_party_attachment`（附件）
- 迁移：`V11.152.0__Enhance_Partner_GoldStandard.sql`（预置 13 个其他往来单位类别 + 回填存量 `roles='OTHER'`）

### 页面对齐（已建成）

- **列表页**：资料模块布局（左单位分类树 + 右数据表），列配置走表头齿轮（个人/全局），页面配置弹窗控制查询条件与功能按钮。
- **表单页**：档案式分区（基础/联系人/纳税人/期初/其他/附件），支持 `?id=` 编辑回填与「保存并新增」。
- **导入**：真实 Excel 落库（`/erp/md/customer/import-excel`，按「单位类别」自动建/取分类，联系人落到主联系人），并复用导入向导（含模板下载）。
- **导出/打印**：真实 xlsx 流 + 真实打印视图。

### 缺陷修复（本次连带）

1. **`getNextSeq` 号段恒为 1**（`PartyServiceImpl`）：旧实现按「前缀后整串」`parseInt`，对 `WLDW-YYYYMMDD-序号` 形态必然解析失败，导致新增/导入编号重复。现同时兼容「前缀+序号」（如 `GYS494557`）与「前缀-日期-序号」两种形态，后者按日重置。
2. **Excel 导入编号口径**：导入生成的编号与表单 `generateCode` 统一为 `前缀-YYYYMMDD-3位序号`。
3. **`PageConfigPanel` 新增「恢复默认」基准 prop**（`defaultQueryFieldsConfig` / `defaultFunctionButtonsConfig`）：原实现用「当前配置」当作默认值，页面传入自身配置时「恢复默认」退化为不变化；新增可选 prop 后不传参行为不变（向后兼容），本页据此恢复出厂勾选。
4. **平台通用上传接口缺失（P0，跨模块）**：前端 8 处（证件信息 / 附件上传 / 商品附件 / 商品表单 / 员工照片 / 银行账户图片等）统一调用 `POST /api/file/upload`，但后端**无任何实现**——`cn.aiedge.storage` 模块未纳入 `AiReadyApplication.scanBasePackages`，且其自身存在双 `FileStorageService` 实现注入歧义、依赖的 `cn.aiedge.platform` 未扫描、`FilePermissionMapper` 包布局不符 `@MapperScan` 等未接线问题，导致全平台上传 404。
   已新增 `cn.aiedge.common.file.FileUploadController`：`POST /api/file/upload` 校验扩展名（图片/PDF/Office/压缩包白名单，拒 exe/js 等）与 20MB 上限，落盘 `{storage.local.base-path:./uploads}/file/{yyyy}/{MM}/{dd}/{uuid}.{ext}`，返回 `{ url, fileId, name, size, type }`；`GET /api/file/view/**` 免登录读取（供 `<img>` 直接引用，uuid 路径 + 正则白名单双重防穿越），并在 `core-base SaTokenConfig` 放行该路径。
5. **FormData 被按 JSON 发送（P0，跨模块）**：`utils/request.ts` 全局默认 `Content-Type: application/json`，axios 不会覆盖已显式设置的默认头，导致所有 FormData 上传以 JSON 发出，后端报 `Current request is not a multipart request`（500）。已在请求拦截器中对 `FormData` 自动移除该头，8 处上传调用零改动生效。
6. **证件信息编辑页数据丢失 / 保存重复（P0，共享组件 `CertUploadList`）**：`watch(partnerId)` 一律走 `sync`，编辑页打开（`undefined → id`）时以空列表 diff，会**删除已保存证件**；同时表单显式 `sync` 与 watch 并发触发，各插一次造成证件重复。已改为「本地存在待落库图片才 `sync`，否则 `load` 回显」+ `sync` 并发保护（同一 Promise 复用）。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
