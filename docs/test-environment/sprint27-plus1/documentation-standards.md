# 测试环境文档编写标准规范

## 📋 规范概述
**适用范围**: Sprint 27+1 测试环境所有文档  
**生效时间**: 2026-05-05  
**文档状态**: ✅ 标准制定完成

## 📝 文档编写基本原则

### 1. 用户中心原则
- **从用户需求出发**: 了解用户是谁，他们需要什么
- **降低认知负荷**: 内容应易于理解和记忆
- **提供实用价值**: 每个文档都应有明确的实用价值

### 2. 一致性原则
- **术语一致**: 相同概念使用相同术语
- **格式一致**: 所有文档遵循统一格式
- **风格一致**: 保持统一的写作风格

### 3. 准确性原则
- **事实准确**: 所有技术事实必须准确
- **时效性**: 文档内容应与当前版本保持一致
- **可验证**: 所有操作步骤应可验证

### 4. 完整性原则
- **覆盖全面**: 覆盖所有必要的内容点
- **无遗漏**: 关键信息不应遗漏
- **逻辑完整**: 内容逻辑应完整无断层

## 📄 文档格式标准

### 1. 文件命名规范
```
格式: {主题}-{用途}-{版本}.md

示例:
- environment-setup-guide-v1.0.0.md
- api-reference-guide-v2.1.0.md
- troubleshooting-guide-v1.0.0.md

命名规则:
1. 使用小写字母
2. 单词间使用连字符(-)连接
3. 避免特殊字符和空格
4. 包含版本号标识
```

### 2. 目录结构规范
```
# 一级标题 (文档标题)

## 1. 二级标题 (章节标题)

### 1.1 三级标题 (小节标题)

#### 四级标题 (子节标题) (谨慎使用)

##### 五级标题 (最小标题) (极少使用)

标题层级规范:
- 每个文档必须有明确的标题层级
- 标题应描述性强，便于理解
- 避免过深的标题层级 (通常不超过4级)
```

### 3. Markdown格式规范

#### 标题格式
```markdown
# 文档标题 (H1) - 每个文档只有一个

## 章节标题 (H2) - 主要章节

### 小节标题 (H3) - 小节内容

#### 子节标题 (H4) - 特殊情况使用
```

#### 列表格式
```markdown
## 无序列表
- 列表项1
- 列表项2
  - 子列表项1
  - 子列表项2

## 有序列表
1. 第一步
2. 第二步
   1. 子步骤1
   2. 子步骤2

## 任务列表
- [ ] 待完成任务
- [x] 已完成任务
```

#### 代码块格式
```markdown
## 行内代码
使用`code`标记行内代码

## 代码块
```bash
# Bash命令示例
echo "Hello World"
```

```python
# Python代码示例
def hello_world():
    print("Hello World")
```

## 带语言标识的代码块
```yaml
# YAML配置示例
server:
  port: 8080
  host: localhost
```
```

#### 表格格式
```markdown
| 参数名称 | 类型 | 必填 | 默认值 | 说明 |
|---------|------|------|--------|------|
| host | string | 是 | localhost | 主机地址 |
| port | int | 是 | 8080 | 端口号 |
| timeout | int | 否 | 30 | 超时时间(秒) |
```

#### 链接格式
```markdown
## 内链链接
[环境搭建指南](./environment-setup-guide.md)

## 外链链接
[Spring Boot官网](https://spring.io/projects/spring-boot)

## 带标题的链接
[Docker文档](https://docs.docker.com "Docker官方文档")
```

#### 图片格式
```markdown
## 基本图片
![架构图](./images/architecture.png)

## 带尺寸的图片
![架构图](./images/architecture.png =800x600)

## 带标题的图片
![架构图](./images/architecture.png "系统架构图")
```

### 4. 文档元数据
每个文档应在开头包含以下元数据：
```yaml
---
title: "文档标题"
description: "文档简要描述"
author: "作者名称"
created: "2026-05-05"
updated: "2026-05-05"
version: "v1.0.0"
status: "draft | review | released"
---
```

## ✍️ 内容编写标准

### 1. 语言风格要求
- **使用中文**: 面向国内用户，优先使用中文
- **简洁明了**: 避免冗长复杂的句子
- **主动语态**: 优先使用主动语态
- **肯定语气**: 使用肯定、明确的语气
- **避免歧义**: 确保语句无歧义

### 2. 术语使用规范
- **建立术语表**: 维护统一的术语表
- **首次使用**: 新术语首次出现时应解释
- **缩写使用**: 缩写首次出现时应给出全称
- **避免俚语**: 避免使用技术俚语和非正式表达

### 3. 示例规范
- **真实可用**: 示例代码应真实可用
- **完整示例**: 提供完整的、可运行的示例
- **注释充分**: 重要代码应有充分注释
- **输出展示**: 展示示例的预期输出

### 4. 错误信息处理
- **准确描述**: 准确描述错误现象
- **原因分析**: 提供可能的错误原因
- **解决方案**: 提供具体的解决方案
- **预防措施**: 提供预防措施

## 🎨 视觉元素标准

### 1. 图片标准
- **格式要求**: PNG或SVG格式
- **尺寸要求**: 宽度不超过1200px
- **清晰度要求**: 文字清晰可读
- **命名规范**: 使用描述性名称

### 2. 图表标准
- **图表类型**: 使用合适的图表类型
- **颜色规范**: 使用统一的配色方案
- **图例说明**: 图表应有清晰的图例
- **数据标注**: 重要数据应标注说明

### 3. 流程图标准
- **流程清晰**: 流程应逻辑清晰
- **符号统一**: 使用统一的流程图符号
- **节点说明**: 每个节点应有说明
- **流向明确**: 流向箭头应清晰明确

## 🔗 文档关联标准

### 1. 内部链接
- **相关文档**: 链接到相关文档
- **引用位置**: 明确引用位置和目的
- **链接有效性**: 确保所有链接有效
- **链接描述**: 链接应有描述性文字

### 2. 外部链接
- **权威来源**: 链接到权威的官方文档
- **链接稳定性**: 优先选择稳定的链接
- **链接检查**: 定期检查外部链接有效性
- **替代方案**: 为重要外部链接提供替代访问方式

### 3. 版本关联
- **版本标识**: 明确文档关联的产品版本
- **版本兼容**: 说明文档适用的版本范围
- **版本迁移**: 提供版本迁移指南
- **版本历史**: 维护文档版本历史

- **版本标识**: 每个文档应有版本标识
- **变更日志**: 维护详细的变更日志
- **版本兼容**: 明确版本兼容性说明

### 3. 废弃管理
- **废弃标识**: 明确标识废弃文档
- **替代指引**: 提供替代文档指引
