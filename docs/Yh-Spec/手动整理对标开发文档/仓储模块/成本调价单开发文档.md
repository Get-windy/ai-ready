# 成本调价单开发文档

## 页面概述

成本调价单用于库存商品成本单价调整录单（调前/调后成本价、调整金额(+/-)）。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 成本调价单列表页 | http://localhost:5656/erp/stock-cost-adjust/index | 双入口「历史」标签 |
| 新增/编辑成本调价单表单页 | http://localhost:5656/erp/stock-cost-adjust/form | 编辑模式为新增模式加 id |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结

### 双入口配置（本系统）

| 项 | 值 |
|----|----|
| 菜单 ID | 5008（原"成本调整"，本次改名"成本调价单"） |
| menu_code | `erp:stock-cost-adjust` |
| 主菜单路径 | `erp/stock-cost-adjust/form`（点击进新增表单） |
| 标签「历史」路径 | `erp/stock-cost-adjust/index`（进列表） |
| tag_label | 历史 |
| display_mode | 1（双入口） |
| 组件 | `erp/stock-cost-adjust/form`（表单）、`erp/stock-cost-adjust/index`（列表） |

## 新增成本调价单表单页配置

### 表头字段（对标实据）

- 必填：调价仓库\*、经手人\*（默认当前登录人）、单据日期\*（截图确认必填）
- 摘要区：合计金额（自动计算）

### 全部表单字段（11 个，cfg 实据）

编号、调价仓库、经手人、部门、单据日期、摘要、单据备注、制单人、制单时间、打印次数、合计金额

> 本系统保留我方独有字段「调价类型 / 原因类型」。

**字段分组**：顶部基本信息（调价仓库/经手人/单据日期）→ 商品明细表格 → 备注区（单据备注）→ 单据信息（制单人/制单时间/打印次数/打印记录）→ 合计金额。

### 功能按钮（对标实据）

打印(F8)、历史、导入、导出、保存草稿 Ctrl+S、记帐 Ctrl+Enter

### 明细表格列配置（默认 17 列 · 全部 26 列对标实据）

**默认显示 17 列**：操作、商品名称（带「扫描枪录入」开关）、货号、条码、货位、计价单位、换算关系、换算结果、批发价、零售价、库存数量、调前成本价、调前成本金额、调后成本价、调后成本金额、调整金额(+/-)、备注

**全部可配置 26 列**（cfg 实据）：图片、商品名称、货号、条码、规格、型号、产地、区域、货位、计价单位、换算关系、件散数量、批发价、零售价、库存数量、调前成本价、调前成本金额、调后成本价、调后成本金额、调整金额(+/-)、备注、单据自定义1~3(数字字段)、单据自定义4~5(文本字段)

> 列配置弹窗结构：个人配置 Tab / 全局配置 Tab，配置列：上级、列名、显示名、显示、回车键跳转、公式内容；支持上移/下移/恢复默认/保存。

## 业务规范说明

- 保存草稿（Ctrl+S）→ 记帐（Ctrl+Enter）：草稿进入「业务草稿」（分析-综合单据），记帐后生效：库存商品成本单价由调前成本价改为调后成本价。
- 调前成本价/调前成本金额按当前库存自动带出；调后成本价手工录入；调后成本金额=库存数量×调后成本价；调整金额(+/-)=调后成本金额−调前成本金额（可正可负），合计金额=各行调整金额之和。
- 仅调成本不动数量：库存数量列只读（调整金额不改变库存数量）。
- 调价只影响指定调价仓库的库存成本（表头「调价仓库\*」实据）。
- 记帐后影响库存成本与后续出库成本、毛利计算（查库存/库存明细/经营分析联动，待复核）；调整金额的财务去向（成本调整损益科目）待复核。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），具体见 `docs/Yh-Spec/ql361对标/README.md`。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
