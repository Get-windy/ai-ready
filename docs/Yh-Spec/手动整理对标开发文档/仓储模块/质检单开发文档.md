> **文档类型：** 新增页面设计文档

> **定位：** 在当前系统代码实际实现基础上补齐设计，不做过度开发、不重复开发。

## 页面概述

质检单用于来料/过程/成品检验录单（IQC/PQC/OQC），记录检验数量、抽检数量、检验结果、合格/不合格数，并联动缺陷记录做不合格处理。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 质检单列表页 | `quality/inspection/list`（双入口「历史」标签，三Tab） | 待检验 / 已检验 / 不合格 |
| 新建质检单表单页 | `quality/inspection/form` | 独立新建页，仅 create |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序。
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结。
- ✅ **当前实现说明**：列表页 `CategoryListLayout` + `BillTableList`（列/页面配置弹窗）+ 完成检验/不合格处理弹窗；表单页 `BillFormPage` + `BillDetailTable`（检验项目明细）+ 配置三Tab（页面配置/录单默认值/打印设置，走 `userPageConfigApi`）；基础组件能力详见 `components/BillFormPage/*`，**改造或使用前请先读基础组件代码**，勿重复开发（遵"功能/模块不重复开发"）。

## 质检单列表页配置（双入口「历史」标签 · 设计值）

### 三Tab结构

| Tab | result 过滤 | 说明 |
|-----|-------------|------|
| 待检验 | `result='PENDING'` | 带待检计数徽标 |
| 已检验 | 无过滤（⚠️ 应为 `!=PENDING`） | 已完成检验 |
| 不合格 | `result='FAIL'` | 检验不合格 |

### 查询条件

| 查询条件 | 控件 | 说明 |
|---------|------|------|
| 来源单号 | input | bizNo（⚠️ 后端 page 不接收，待补） |
| 产品名称 | input | productName（⚠️ 后端 page 不接收，待补） |
| 检验员 | input | inspectorName（⚠️ 后端 page 不接收，待补） |

### 功能按钮

待检验/已检验/不合格状态切换（含待检计数）；Tab 内：完成检验（PENDING）/ 查看（已检验）/ 不合格处理（FAIL）；ARReportPage 自带查询/重置/刷新/导出。

### 数据表列（9 列，三Tab共用）

| # | 列名 | dataIndex | 说明 |
|---|------|-----------|------|
| 1 | 来源单号 | bizNo | |
| 2 | 产品名称 | productName | ellipsis |
| 3 | 批次号 | batchNo | |
| 4 | 检验数量 | quantity | 渲染 `数量 / 抽检: sampleQuantity` |
| 5 | 检验结果 | inspectionResult | Tag 着色（PENDING橙/PASS绿/CONCESSION蓝/FAIL红） |
| 6 | 合格-不合格 | resultCount | 绿色 passQuantity / 红色 failQuantity |
| 7 | 检验员 | inspectorName | |
| 8 | 检验时间 | inspectionTime | |
| 9 | 操作 | action | 按 Tab 条件渲染（固定右） |

### 完成检验弹窗

来源单号（disabled）+ 检验结果（PASS/CONCESSION/FAIL，默认 PASS）+ 合格数量 passQuantity + 不合格数量 failQuantity + 检验备注 remark；顶部 a-alert「结果将同步入库单状态」。

### 不合格处理弹窗

来源单号（disabled）+ 缺陷类型（QUALITY/PACKAGING/LABELING，默认 QUALITY）+ 缺陷描述 defectDesc（必填）+ 缺陷数量 defectQuantity（默认取 failQuantity）。

## 业务规范说明

- 检验闭环：质检单创建（默认 PENDING）→ 完成检验（complete，回写 pass/fail 数量）→ 不合格走缺陷记录处理。
- 检验类型：INBOUND 来料 / OUTBOUND 出库 / PROCESS 过程，决定检验环节。
- 检验结果：PASS 合格 / FAIL 不合格 / PENDING 待检 / CONCESSION 让步接收（⚠️ 后端实体注释无 CONCESSION，待补）。
- 检验数量 vs 抽检数量：抽检量 ≤ 检验量，用于 AQL 抽检场景。
- **当前无质检单号（next-no）**：质检单无独立单号字段，仅记录来源单号 `bizNo`；create 时后端强制 `inspectionResult='PENDING'`。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），质量模块无质检页，本页为设计新增。

### 最终裁决方案（2026-09-02 · 严格按此执行）

> 与《发货单/上架单/移库单/质量标准最终裁决》一致，本页遵循同一跨模块口径：**P0 单一口径必做、P2 本次做、P1 延后并隐藏、跨模块缺接口走 HTTP 边界、明确不做红线**。

**裁决1 · 红线（不做的）**
- 质检单保持**单表**（一次检验一个产品），检验项目存 `inspectionItems` JSON，**不引入独立明细表**；（同质量标准裁决红线）。
- 质检作为**门禁/下推**主体不做——「未检不入库」校验、FAIL 冻结库存、complete 回写入库单状态均属跨模块联动，**延后**，前端不做入口（避免虚假校验，同上架单"质检 PASS 校验暂缓"口径）。

**裁决2 · P1 延后（下一迭代）**
- 质检不参与门禁（`InventoryService.freeze` + ERP 入库校验）、质检孤岛下推链、complete 回写入库/批次状态 → **下一迭代**，需先建立质检↔收货/入库外键关联再实现。
- 标准→质检引用：质检单可选检验标准（下迭代联动 `quality-standard listByType`），**延后**。

**裁决3 · P2 本次做**
- **检验项目明细**：本次已补（`BillDetailTable` 编辑 `inspectionItems` JSON，表单新增预置空行、编辑回填）。
- **单号/状态流/编辑/回填**：next-no(ZJD-)/status(0待检/1完成/2作废)/update/complete/cancel 已实现。

**裁决4 · 可选/后补**
- 打印(F8)、产品/供应商/检验员主数据下拉 → 可选，后补。

**执行指令**：以 P2（检验项目明细 + 单号/状态流）收尾本期；P1 门禁/孤立/下推链、标准→质检引用均延后，前端不做入口；跨模块缺接口 → 提需后端在消费侧（入库/库存）暴露，质检单仅提供 `complete(result/pass/fail)` 结果供下迭代消费。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
