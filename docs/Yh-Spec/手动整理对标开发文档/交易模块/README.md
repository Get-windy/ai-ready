# 交易模块 · 对标开发文档集

> **对标系统**：来肯企汇 ql361 v2.2（`22stable.ql361.com`，桌面式多标签，页面无独立路由）。交易模块 = ql361 顶部「**商城**」域（13 页）+ 本系统整合/新增的**支付结算**与**外部平台**（9 页）。
> **数据来源**：Playwright 实测抓取（首抓 2026-09-07；**全量复核 2026-09-15**，账号 15095664266）——列配置弹窗（数据表内 `.icon-shezhi2`，「个人配置 / 全局配置」两 Tab）、页面配置弹窗（顶部按钮栏「配置」齿轮）、页面结构（查询区/工具栏/表头/分类树）、截图。
> **抓取方法**：见《ql361对标/README.md》§2.5 与《抓取结果/抓取方法指南.md》；本模块 2026-09-15 复核的可复用脚本 = **`tools/ql361-mall-crawl.cjs`**（一条命令抓全 13 页 → `tool-results/ql361/mall-live/<页名>.json` + `.png`）。
> **通用规范**：见《ql361对标/对标开发技术参考文档》第 4、5 章；本模块施工手册见同目录 **[_开发指南-金标准.md](./_开发指南-金标准.md)**（三条路线 / 模板 / 18 条陷阱 / 自检清单 / 后端缺口）。
> **术语**：业务上「买家」= 商城注册客户（会员/企业客户）；「商城订单」= 线上下单产生的销售订单（`erp_sale_order`，`order_source` 2/3）。

## 1. 模块定位与边界

| 分块 | 对标来源 | 本系统菜单（分组） | 内容 |
|------|---------|------------------|------|
| **商城订单** | ql361 商城 → 订单处理（订单处理 / 退货申请处理，实测 2 页） | 交易 → 商城订单（4 项） | 订单处理、退货申请处理、商城订单、购物车 |
| **商城管理** | ql361 商城 → 基础业务（实测 5 页） | 交易 → 商城管理（5 项） | 商品上架、单位显示、买家申请管理、买家账号、商品组合 |
| **商城设置** | ql361 商城 → 商城设置（实测 6 页） | 交易 → 商城设置（6 项） | 基础设置、店铺设置、运费设置、商城装修、公告设置、关键词库 |
| **支付结算** | ⚠️ ql361 无独立菜单（本系统整合；「每日对账」对标财务→在线支付对账单） | 交易 → 支付结算（4 项） | 支付请求、支付记录、退款管理、每日对账 |
| **外部平台** | ⚠️ ql361 无对应页（本系统新增） | 交易 → 外部平台（3 项） | 渠道配置、外部订单、数据同步 |

## 4. 域级说明

- **入口直达/同源现象**：
  - `mall/order-process`（订单处理，菜单 80350）与 `trade/mall-order`（商城订单，菜单 90102）**同源** —— 同读 `ErpSaleOrderMall`（表 `erp_sale_order`，`order_source=2` 企业客户商城），同用 `/erp/mall/admin/order/*`，同为 2 Tab、同 39（默认 31）/ 47（默认 35）列口径；差异仅在**视角**（审核处理 vs 发货履约）与所调 api 封装。**两页列定义需同步修改**。
  - 商品上架 / 单位显示**同源**（同一商品主数据、同一分类树接口 `/erp/product-category/tree`）；差异：前者读**视图 `v_mall_product`**（`/erp/mall/admin/product/page`）+ 上下架 + 商城默认排序，后者直连 `erp_product`（`/erp/product/page`）聚焦单位显示开关。
- **商品数据源口径（重要）**：商城侧读**视图 `v_mall_product`**（源表 `erp_product`），**旧表 `mall_product` 已废弃**（`V9.0.0` Part 9 标注）。商品上架页编辑保存、商城下单通道 (`MallOrderServiceImpl`) 均已改走权威表/视图；**新增/删除分支仍写旧表**（未闭环，见《商品上架开发文档》缺口 9/10）。
- **单号规则**：销售订单 `XSDD-YYYYMMDD-序号`（商城订单同源，实测实据 `XSDD-20260915-004`）。
- **状态口径**：商城订单以 `erp_sale_order.status` 为唯一基准 **0草稿 / 1待审批 / 2已审批 / 3部分出库 / 4完成 / 5交易完成 / 6已取消**；ql361 的商城细分串（待付款/审核中/已付款…）经 `extInfo.originalMallStatus` 显示，**不落独立列**。
- **上架状态词表（易错）**：写入用 `ON_SHELF`/`OFF_SHELF`（`PUT /erp/product/batch-status`，落 `erp_product.mall_shelf_status` 1/0），**读出只有 `ON_SHELF`/`INACTIVE`**（视图 `status` 由 1/0 派生，永不产出 `OFF_SHELF`）；前端 `isOnShelf()` 做映射。**写断言/回读断言必须各按自己那套词表**。
- **对标的「上架状态」文案**：ql361 是中文二元 **全部(-1) / 已上架(1) / 未上架(0)**（下架态文案为「**未上架**」），本系统的 `ON_SHELF/INACTIVE` 是内部枚举，**不可与对标文案混用**。

## 5. 通用陷阱（跨页）

> 本模块的两类陷阱已分别沉淀，**开发前必读**：
> - **施工/组件级 10 条 + 运行期 8 条** → [《_开发指南-金标准》§六、§六之二](./_开发指南-金标准.md)。含：`/api` 双前缀 404（`api/payment/index.ts` 曾 20 处）、雪花 ID 禁用 `Number()`、`camelToUnderline` 对「驼峰+数字结尾」不补下划线、`BaseEntity` 审计列、无 `tenant_id` 表须入 `IGNORE_TENANT_TABLES`、条件式重载先求值实参致 NPE、`ADD COLUMN … DEFAULT` 回填陷阱。
> - **流程级**：「编译通过 + 静态核对通过」**不等于能用** —— 交付前必须对运行中的后端发真实请求（`node tools/e2e-trade.cjs`）。

### 5.1 「个人配置 / 全局配置」两 Tab 可能不一致（2026-09-15 实测）

ql361 列配置弹窗有「个人配置（当前操作员）」与「全局配置（租户）」两个 Tab，**两边的默认勾选可能不同**。实测 `商品上架`：个人配置 33 列默认显示（含「规格」）／全局配置 32 列（不含「规格」）。
→ **抓取文档时必须写明读的是哪个 Tab**；本模块统一以**全局配置**为基线，差异在页文档中标注。抓取脚本用 `QL361_CFG_TAB=personal|global` 切换。

### 5.2 多 Tab 页面：`.icon-shezhi2` 会被 dojo 预渲染

复合页每个 Tab 一个数据表、各有一个列配置齿轮，**非激活 Tab 的图标 DOM 也存在**。必须按 `getBoundingClientRect()` 过滤可见项、并先切到目标 Tab 再点，否则会读到上一个 Tab 的列清单。

### 5.3 交易模块 E2E（真机）

```bash
# 起后端（dev profile）→ 跑模块级 E2E → 收尾关进程
node tools/e2e-trade.cjs        # 期望：汇总 103/103 通过，退出码 0
```
- 产物：`tool-results/e2e-trade/`（`probe-after-fix.txt` 33 项接口探针、`e2e-run3.txt` 103 项输出、`ui-*.png` 6 张页面截图）。
- 口径：**先只读对账 → 再造数/改库 → 三级回读 → 按原值复原**；断言不写「只判 HTTP 200」的空炮。
