## 页面概述

收货单用于仓库收货作业录单（来源单据推送 / PDA 扫码作业 / PC 端手工录入），承接采购入库、生产入库、退货入库、调拨入库等入库场景。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 收货单列表页 | `wh/receiving-order/index`（list_path 别名 `wms/receive`） | 双入口「历史」标签 |
| 新增/编辑收货单表单页 | `wh/receiving-order/form` | 编辑模式为新增模式加 id |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序。
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结。
- ✅ **当前实现说明**：列表页采用 `CategoryListLayout` + `ColumnConfigPanel`／`PageConfigPanel`（列配置/页面配置弹窗），表单页采用 `BillFormPage` + `BillDetailTable` + 3Tab 配置弹窗（页面配置/录单默认值/打印设置），均已接入页面配置/列配置/打印设置能力。

## 业务规范说明

- **收货 → 上架 → 库存终态**：收货单确认后进入「已完成」，其明细建议继续流转到上架单（本单据**不直接回写库存**）。
- **来源类型**：采购入库/生产入库/退货入库/调拨入库/其他，决定入库业务归属。
- **明细状态**：待收货 0 → 已收货 1 → 已上架 2；仅待处理可编辑，确认收货后只读。
- **入库前质量关卡（IQC）**：业界收货常关联来料检验，未检/不合格不入库；本系统质检单为独立模块（见《质检单开发文档》），当前收货环节未做质检联动。
- **批次/效期管理**：明细支持批次号、生产日期、有效期（VO 有 `productionDate/validityDate`），业界用于先进先出（FEFO）管控；当前表单仅录批次号，生产/效期列待暴露。
- **收货差异处理**：已实现**差异明细记录**（明细可录实收/破损，差异=实收−应收展示，破损不入库、净入库=实收−破损）；红冲/调整动作（超收红冲、短收关闭）为后续。
- **单号前缀** `RC`，由前端 `genTaskNo` 生成（`RC-yyyyMMddHHmmss`），后端 `save` 原样落库；**后端无 next-no / 序列号自动生成**。
- **PDA 扫码作业**：PDA `PdaReceiveController` 走同一 Service，扫描逐行累加实收数量。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），仓储模块无收货页，本页为设计新增。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
