## 1. 页面概述

本页是 **客户等级的台账 + 快捷调级入口**：按等级/关键字筛选客户，展示信用额度、当前欠款、交易指标，并对单行客户**手工调整等级**。

| 页面 | 地址 | 组件 | 行数 | 说明 |
|------|------|------|:----:|------|
| 客户分级（本页） | `crm/customer-grade` | `views/crm/customer-grade/index.vue` | 202 | `ARReportPage`（**路线 B**）外壳 + 5 张统计卡 + 11 列表格 + 1 个「调整客户等级」弹窗 |
| 客户（兄弟页） | `crm/customer/index` ↔ `crm/customer/form` | `views/crm/customer/{index,form}.vue` | 1620 / 116 | 客户台账；等级在**列表筛选/看板分组/表单页**均可设置（字典与本页不一致，§5.1） |

> **单入口提醒**：本页 `display_mode = 0`、`tag_label = NULL`、`list_path = NULL`（devdb 实测）—— **没有配对标签页**。

### 1.1 「客户分级」不是等级字典维护页（重要定性）

| 期望职责（按菜单名） | 实际实现 |
|---|---|
| 维护等级主数据：等级名、序号、判定阈值、服务策略 | ❌ **完全没有**。等级与文案**硬编码在前端**（`:84-91`），后端无字典表、无枚举接口 |
| 设定「按交易数据自动评级」规则 | ❌ 无（但**ERP 侧已有同类阈值字段**，§1.2） |
| 查看各等级客户分布 | ⚠️ 仅 5 张统计卡（前端全量聚合），无等级维度的金额/贡献度分析 |
| **人工调整某个客户的等级** | ✅ **本页唯一真实写能力**（1 个行内动作，真实接口，**零桩**） |

**本模块没有等级字典表**：全库 `crm%` 表实测 22 张（清单见《商机阶段开发文档》§1.1），**无 `crm_customer_grade` / `crm_customer_level`**；`crm_customer.customer_level` 只是一个**裸 `integer` 列**（devdb 实测可空、无默认、无 CHECK、无外键）。
**业界对照**：Odoo 用 `Tags` + `Salesperson`，Salesforce 用 **Account Rating**（Hot/Warm/Cold，可配置 picklist），金蝶/用友用**客户价值分级**（A/B/C 或 VIP/重要/普通/潜在）—— 三者的等级值域通常是**可维护主数据**。本页当前只有「改值」，没有「改字典」。

### 1.2 ⚠️ 四个「等级」概念必须分清（P0 级口径，勿混用）

| # | 概念 | 数据源（表） | 用途 | 本页关系 |
|:-:|------|-------------|------|---------|
| 1 | **CRM 客户分级**（本页） | `crm_customer.customer_level` + `customer_level_desc`（4 级） | **CRM 服务策略**：谁优先服务、谁需要重点维护 | ✅ **本页就是这个** |
| 2 | **ERP 价格等级 / 客户级别** | `erp_customer_level`（`level_name`/`level_code`/`min_amount`/`max_amount`/`min_frequency`/`min_payment_rate`/`discount_rate`/`credit_days`…）、`erp_partner_grade`、`biz_customer_grade_price`、`erp_customer_grade_price` | **取价**：开单取价、折扣、账期 | ❌ **两回事**（《资料模块/客户开发文档》已裁定「ERP 客户级别 = 价格等级」） |
| 3 | **信用** | `crm_customer.credit_limit` / `current_debt`；`CustomerCreditService` | **风控**：额度与欠款 | ⚠️ 本页**只展示**两列，不做校验 |
| 4 | **会员等级** | `erp_member_level`（devdb 实测 **8 行**） | **营销**：会员折扣/积分 | ❌ 无关 |

> **实测旁证（devdb 2026-09-18）**：`erp_customer_level` **0 行**、`erp_partner_grade` **0 行**、`erp_member_level` **8 行**；`erp_customer_level` 的后端控制器是 `erp-partner` 模块的 `CustomerLevelController`（前缀 `/api/erp/customer/level`，含 `list`/`list/enabled`/`page`/`{id}`/`code/{code}`/`POST`/`PUT`/`DELETE`/`{id}/enable`），**前端 `pc-admin` 全仓零引用**（无页面、无菜单）。
> **裁定建议**：① 本页文案与列名统一带「CRM」前缀（如「CRM 等级」），避免与 ERP 客户级别混淆；② 等级**字典**维护**不要**在 CRM 重造 —— 需要字典时**复用** ERP 既有 `CustomerLevelController`（《功能/模块不重复开发》铁律）；③ 本页只做「**人工评定 + 展示**」，取价/账期一律留在 ERP。

| 提交 | `crmCustomerApi.update(id, {...currentCustomer.value, customerLevel: newLevel.value, customerLevelDesc: LEVEL_TEXT[newLevel.value]})` → `PUT /api/customer/{id}`（`putRaw`，绝对路径） | `:183-187`, `api/crm.ts:428-430` |
| **全量回写** | `...currentCustomer.value` 把**整个列表行**（`Customer` 实体 JSON，含 `id`/`version`/`deleted`/`status`/`creditLimit`…）一并回传 | `:183-187` |
| 成功 / 失败 | `message.success('客户等级已更新')` → 关弹窗 → `reportRef.reload()`（**保持当前页码**）+ `loadLevelStats()`；`message.error(e?.message \|\| '更新失败')` | `:188-194` |
| 防重复 | `levelSaving` 驱动 `:confirm-loading` | `:44,181,196` |

### 4.3 「全量回写」的语义与风险

`PUT /api/customer/{id}` → `CustomerController.java:58-64`（`setId` + `updateById`）→ MyBatis-Plus 默认 `FieldStrategy.NOT_NULL`（**只更新非 null 字段**，与《配置落位》口径一致）。

| 项 | 结论 |
|----|------|
| ✅ 乐观锁**生效** | 行对象含 `version`（`Customer` 实体 `@Version`，`entity/Customer.java:112-113`）→ 全量回写把它带回 ⇒ MP 生成 `SET version = version + 1 WHERE id = ? AND version = ?`，**并发调级会有一方失败**（受影响 0 行，但接口仍返回 HTTP 200 ⇒ ⚠️ **前端误报"已更新"**，§9.2） |
| ⚠️ 覆盖风险 | 提交的是**列表页快照**：弹窗打开期间若该客户被别处改动（如负责人变更），回写会用**旧快照**覆盖同名非空字段 |
| ⚠️ `updated_at` **不刷新** | 实体标 `@TableField(fill = FieldFill.UPDATE)`，但 `MetaObjectHandler.updateFill` 只填 `updateTime`（`MyBatisPlusConfig.java:188-191`）⇒ 无填充、null 被忽略 ⇒ **`updated_at` 停在插入时刻** |
| ⚠️ 无部分更新端点 | 后端有 `PUT /{id}/status` 这类**单字段端点**（`:129-140`），但**没有**等级版 ⇒ 前端只能全量 PUT |

### 4.4 目标规格（按业界「客户评级」闭环）

| 目标能力 | 说明 | 本系统现状 |
|---------|------|-----------|
| 调级**留痕** + 原因/审批/生效日期 | 记录「谁、何时、从 X 级到 Y 级、原因」；大客户升降级走审批 | ❌ **业界建议、本系统未实现**（无日志表、无「最近调级时间/人」列） |

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 与 `tools/acceptance/` 下不存在 `e2e-crm*.cjs`）。落地脚本命名 `tools/e2e-crm.cjs`（界面 + 接口 + 直连 DB 对账 + 写库后复原）。**前置**：`crm_customer` 当前 **0 行** → 必须先造客户（覆盖 4 个等级 + 未分级、`status` 0/1、金额非 0）。

### 10.1 接口验收（建议 ≥ 14 项）

① `GET /api/customer/page` 默认 200，`total` 与直查 DB（`deleted=0` **+ 租户条件**）一致（本表**有 `tenant_id`**）；② `pageNum`/`pageSize` 生效（`pageSize=1` → `records.length===1`）；③ `customerLevel` **逐值 1–4 过滤**（各造一条逐一断言）；④ `keyword` **同时命中** `customer_name`/`customer_code`/`short_name` 三者；⑤ `status`/`customerType`/`salesPersonId` 后端已支持但前端未接（接口层造数验证）；⑥ `GET /api/customer/export` 裸数组条数与 `/page` 的 `total` 一致；⑦ **`GET /api/customer/statistics` 断言当前 404**（登记「卡片靠全量聚合」的依据）；⑧ `PUT /api/customer/{id}` 调级后三级回读（DB/详情/列表）一致，`customer_level` 与 `customer_level_desc` **同步**；⑨ **`updated_at` 断言**：调级后该列**未变化**；⑩ **`updated_by` 断言**：仍为 `NULL`；⑪ **乐观锁断言**：两份相同 `version` 的快照连续 PUT → 第二次受影响 0 行但**接口仍 200**（登记「假成功」）；⑫ **`GET /api/customer/{id}/orders` 断言返回空数组**（登记「交易指标无来源」）；⑬ **`status` 语义断言**：造 `status=1` 与 `status=0` 各一条 → 本页把 `1` 显示为「正常」、客户列表页把 `0` 显示为「正常」（登记两页相反）；⑭ **写库隔离**：造数用专用测试客户，断言后按原值复原或清理。

> 2026-09-18 更新：⑤ `status` 已接入本页查询区；⑦ `statistics` 仍 404（未补聚合端点）；⑧ 调级现在只提交两个字段，`desc` 同步不变；⑨⑩⑪⑫ **未变**；⑬ 客户列表页已统一 `1=正常`，该断言后半句已不成立。

### 10.2 UI 验收（建议 ≥ 16 项）

① 菜单 `CRM → 客户管理 → 客户分级`（`70303`）点开落在 `crm/customer-grade`（**单入口**，无配对标签）；② 查询区 2 项渲染（`等级` 有可见 label、`关键字` 只有 placeholder）；③ **5 张统计卡**渲染，数值 = 页面数据聚合（与 `export` 手算一致）；④ **卡片与筛选不同源断言**：筛「VIP客户」后卡片**数值不变**（登记缺陷）；⑤ **4 张等级卡之和 ≤ 客户总数**，差额 = 未分级数（造 1 条无等级客户）；⑥ 表格 11 列渲染，**等级显示中文 tag**（gold/orange/blue/default），空值显示 `未分级`；⑦ 金额列有值 `1,234.56`、空值 `-`；⑧ 状态列：`status=1` 绿色「正常」，其它灰色「停用」；⑨ 等级筛选 / 关键字回车查询各自生效；⑩ 重置清空两项并回第 1 页；⑪ 分页请求参数为 `pageNum`/`pageSize`（**不是** `page`/`size`）；⑫ 导出 `客户分级_*.csv`，UTF-8 BOM，**表头 10 列（不含「操作」）且等级/状态为数字**；⑬ 点「调整等级」→ 弹窗显示客户名 / 当前等级 tag / 新等级**默认等于当前等级**；⑭ 清空新等级点保存 → `请选择新等级` 且**无网络请求**；⑮ 选新等级保存 → `客户等级已更新` → 表格该行等级变化**且统计卡同步重算**（**断言网络无 4xx**）；⑯ 断言卡片**不可点**、行操作**只有「调整等级」**；⑰ 控制台**无 error**（含 `TypeError`/`ReferenceError` —— 参见《重构搬迁后必须做运行时验证》）。

## 12. 剩余缺口（不阻塞，如实登记）

1. **本页不是等级字典维护页（P1）** —— 只有「改单个客户等级」；等级字典需产品裁定「复用 ERP `CustomerLevelController`」还是「明确固定 4 值」。

6. **统计相关（P1/P2）** —— 卡片不可下钻、失败仅 console、无独立 loading、与筛选不同源、无「未分级」卡、无等级维度金额口径。

8. **外壳为路线 B（P1）** —— 缺 `CategoryListLayout`（等级左树）/表头齿轮/`PageConfigPanel`/`StandardPagination`；无快捷键与跨页事件；导出仅当前页且枚举导出为数字（P1）。

10. **等级不驱动任何业务、无模块级 E2E 与验收截图（P2）** —— 取价/账期/折扣在 ERP 另一套，CRM 分级当前仅"标签"意义；`tools/e2e-crm.cjs` 尚不存在。
