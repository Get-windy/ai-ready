# 盘点单开发文档

## 页面概述

盘点单用于库存盘点录单（页面标题「库存盘点单」），快速录入行 + 盈亏状态筛选 + 刷新库存，保存/盘点处理两段操作。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 盘点单列表页 | http://localhost:5656/erp/stocktake/index | 双入口「历史」标签 |
| 新增/编辑盘点单表单页 | http://localhost:5656/erp/stocktake/form | 编辑模式为新增模式加 id |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结

### 双入口配置（本系统）

| 项 | 值 |
|----|----|
| 菜单 ID | 5003（原"库存盘点"，本次改名"盘点单"） |
| menu_code | `erp:stocktake` |
| 主菜单路径 | `erp/stocktake/form`（点击进新增表单） |
| 标签「历史」路径 | `erp/stocktake/index`（进列表） |
| tag_label | 历史 |
| display_mode | 1（双入口） |
| 组件 | `erp/stocktake/form`（表单）、`erp/stocktake/index`（列表） |

## 新增盘点单表单页配置

### 表头字段（对标实据）

- 必填：盘点仓库\*、经手人\*（默认当前登录人）、单据日期\*（截图确认必填）
- 快速录入：商品（条码/名称/编码 输入框）、X 数量（默认 1）
- 摘要区：盈亏金额（自动计算）

### 全部表单字段（13 个，cfg 实据）

编号、盘点仓库、经手人、部门、单据日期、摘要、商品、盈亏状态、单据备注、制单人、制单时间、打印次数、盈亏金额

**字段分组**：顶部基本信息（盘点仓库/经手人/单据日期）→ 商品快速录入行 → 盘点明细表格（含工具行）→ 备注区（单据备注）→ 单据信息（制单人/制单时间/打印次数/打印记录）→ 盈亏金额。

### 表格工具行（对标实据）

- 快速定位：输入商品名称、条码、货号快速定位（表格内行定位）
- 盈亏状态（全部）下拉：按盘盈/盘亏/无差异过滤明细行
- 刷新库存：重新取数当前账面库存

### 功能按钮（对标实据）

快速盘点、打印(F8)、历史、更多、快速定位、刷新库存、保存 Ctrl+S；底部「盘点处理 Ctrl+Enter」

### 明细表格列配置（默认 14 列 · 全部 34 列对标实据）

**默认显示 14 列**：操作、商品名称（带「扫描枪录入」开关）、货号、规格、计价单位、库存数量、换算结果、件散数量、盘点数量（列头带「件散数量」辅助标注）、盈亏数量、生产日期、换算关系、保质期、备注

**全部可配置 34 列**（cfg 实据）：操作、图片、商品名称、货号、条码、规格、型号、产地、区域、货位、计价单位、库存数量、换算结果、盘点数量换算结果、盘点数量、件散数量、盈亏数量、生产日期、换算关系、保质期、到期日期、备注、大包装、中包装、小包装、盘点状态、成本单价、盈亏换算结果、盈亏金额、单据自定义1~3(数字字段)、单据自定义4~5(文本字段)

> 列配置弹窗结构：个人配置 Tab / 全局配置 Tab，配置列：上级、列名、显示名、显示、回车键跳转、公式内容；支持上移/下移/恢复默认/保存。

## 业务规范说明

- 保存（Ctrl+S，注意非「保存草稿」）→ 盘点处理（Ctrl+Enter）：保存后盘点单可继续盘点，盘点处理后按盈亏生成后续单据（推断生成报损单/报溢单，待复核）。
- 库存数量=账面库存，盘点数量=实盘数，盈亏数量=盘点数量−库存数量 自动计算；盈亏金额汇总于右下角。
- 快速盘点：右上角独立按钮，推断为批量导入/扫码连续盘点模式（弹窗内容待复核）。
- 商品快速录入行：扫码或输入条码/名称/编码 + 数量直接追加盘点行。
- 快速定位/盈亏状态/刷新库存为表格辅助工具，不参与单据字段。
- 盘点处理产出报损单（盘亏）/报溢单（盘盈）（推断，待复核）；处理后影响 分析→仓配分析→查库存/库存明细。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），具体见 `docs/Yh-Spec/ql361对标/README.md`。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
