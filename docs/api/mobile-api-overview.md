# 移动端API接口文档概述

## 概述
本文档描述了AI-Ready系统测试环境（Sprint 27+1）移动端的完整API接口。该文档为前后端开发人员提供统一的API使用标准和规范，确保移动端应用能够正确集成和使用系统功能。

## 基础信息
- **基础URL**: `/api`
- **认证方式**: JWT Token (Bearer Token)
- **API版本**: v1 (移动端API使用v1版本)
- **响应格式**: JSON
- **错误码标准**: 统一使用HTTP状态码 + 业务错误码

## API分类和组织方式

### 1. 用户认证API (Authentication)
- 用户登录、注册、登出
- Token管理（刷新、验证）
- 用户信息管理

### 2. 核心业务API (Business Core)
- **订单管理**：订单查询、创建、更新、删除、状态管理
- **库存管理**：库存查询、盘点、调拨、预警
- **商品管理**：商品查询、分类、导入导出
- **消息管理**：消息发送、接收、状态管理

### 3. AI功能API (AI Capabilities)
- **智能对话**：自然语言交互、意图识别、会话管理
- **语义搜索**：智能搜索、搜索建议、拼写检查
- **智能推荐**：个性化推荐、内容发现

### 4. 移动端专用API (Mobile Specific)
- 移动端专用接口优化
- 离线数据同步
- 推送通知
- 移动端配置管理

## API文档的评级和可发现性标准

### 评级标准
1. **Level 1（基础必需）**：核心功能必须实现的API，如登录、订单查询
2. **Level 2（增强功能）**：提升用户体验的API，如搜索建议、智能对话
3. **Level 3（高级功能）**：专业功能，如数据分析、报表导出

### 可发现性标准
- **Public**：公开API，无需认证即可访问
- **Protected**：需要认证才能访问
- **Internal**：内部API，仅限系统内部使用

## 开发规范

### 1. API命名规范
- 使用RESTful风格
- 资源名称使用复数形式
- 操作使用HTTP动词表示

### 2. 请求/响应规范
- 所有请求必须包含Content-Type: application/json
- 响应必须包含统一的错误处理机制
- 分页查询必须支持page和size参数

### 3. 认证规范
- 移动端API必须使用Bearer Token认证
- Token过期时间设置为24小时
- 支持Token刷新机制

### 4. 错误处理规范
- 使用统一的错误码体系
- 错误信息必须包含明确的错误描述
- 业务错误码使用4xx系列

## 性能要求
1. **响应时间**：普通API响应时间 < 500ms，复杂查询 < 2s
2. **并发能力**：支持至少100并发请求
3. **数据安全**：敏感数据传输必须加密
4. **兼容性**：支持移动端主流浏览器和操作系统
