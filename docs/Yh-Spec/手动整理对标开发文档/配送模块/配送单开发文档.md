## 1. 页面概述

- **双入口单据页**：主菜单点击进入**表单页**（新建配送单），标签「历史」进入**列表页**（配送单列表）。
- 业务定位：**一次配送动作的载体**——由出库/送货需求生成，承载「来源单据 → 配送任务 → 司机/车辆执行 → 签收」的全过程。
- 数据落地：本系统 `DmsTask`（`/api/dms/task`，表 `dms_task`）+ 商品明细 `DmsTaskItem`（表 `dms_task_item`），状态机 0–8。
- 与《配送查询》的关系：配送查询是本单据的**台账视图**（含收发货双向统计与里程），**同一数据源**，查询侧需将 DMS 执行态映射为对标三值口径（见 §4.2）。

### 3.2 来源单据 与 货物明细（✅ 2026-09-13 建模对齐业界）

> **口径（SAP TM → Freight Order ← Freight Unit ← Delivery）**：配送单是**运输执行单**（怎么运：承运资源/路线/时间/里程/签收），
> 货值（数量/金额/重量/体积）与商品明细归**上游销售出库单**（Delivery，管货权与库存）。配送单**不重复录入货值**。

| 场景 | 表单行为 |
|------|---------|
| **有来源单据**（常态） | 「来源单据」多选销售出库单 → 表头**发货数量/发货金额/重量/体积由上游单据聚合**；关联订单号/客户/收货信息自动带出；**货物明细只读穿透**上游（不可增删改、不录单价），提示「货值由来源单据聚合，货物明细只读（单一数据源）」 |
| **无来源单据**（临时配送） | 货物信息在本单录入（10 列明细），定位为「装载/货物描述」，**不参与库存与应收**；表单提示「未选来源单据 = 临时配送」 |

**数据落地**：
- `dms_task_doc`（**新增**，配送单 ↔ 上游单据 1:N）：`doc_type/doc_id/doc_no/doc_date/quantity/amount/weight/volume/box_count`，是表头聚合的**唯一来源**；「配送单量」= 关联单据数。
- `dms_task_item`：仅临时配送使用；有来源单据时清空（明细由上游穿透）。

货物明细列（临时配送场景）：商品名称（可开**商品选择弹窗**）、货号、条码、规格、单位、数量、单价、金额（只读、后端重算）、重量（kg）、体积（m³）、明细备注。存储键 `dispatch-order-form-columns`。

### 3.3 底部与摘要

- 配置弹窗 3 Tab：**页面配置 / 录单默认值 / 打印设置**（按本系统金标准）。

## 4. 业务规范

### 4.1 单据编号

- **✅ 已实现**：后端号段 `PSD-YYYYMMDD-3位序号`（`GET /api/dms/task/next-no`，`TaskService.generateTaskNo()` 以已落库单据最大号 +1 递进）。
- 前端 `useBillForm.codeApiPath = '/dms/task/next-no'` 取号；**后端为权威**：提交时若单号为空或已存在则服务端重新分配（前端无法自增号）。
- 与销售 `XSDD-`/出库 `XSCKD-` 风格一致。

### 4.2 状态机（DMS 执行态 → 查询三值口径）

| DMS `status` | 含义 | 配送查询三值映射 |
|:---:|------|:---:|
| 0 | 待分配 | 待配送 |
| 1 | 已分配 | 待配送 |
| 2 | 已接单 | 待配送 |
| 3 | 取货中 | 配送中 |
| 4 | 配送中 | 配送中 |
| 5 | 已签收 | 已配送 |
| 6 | 已完成 | 已配送 |
| 7 | 已取消 | （不显示/灰显） |
| 8 | 异常 | （异常标记） |

> 状态流转由后端校验 `fromStatus → toStatus` 合法性（`PUT /dms/task/{id}/status`）。

### 4.3 与上下游

- **上游**：销售出库单（`XSCKD-`）/ 调拨单 / 退货单 → 生成配送任务（关联订单号）。
- **下游**：司机端（`frontend/apps/driver-delivery`）执行 → 签收（`dms_sign`）→ 回写配送状态；配送查询台账统计收发货双向单量与里程。
- **调度**：调度任务/智能调度/订单池（见《配送模块（DMS）开发文档》）为配送单指派司机与车辆。

### 5.2 关键实现口径（避免回归）

1. **单号权威在后端**：`PSD-YYYYMMDD-序号`；同一号重复提交由服务端重新分配；未落库时连续取号幂等。
2. **金额/数量口径（2026-09-13 分流）**：
   - **有来源单据**（常态）：表头 `发货数量/发货金额/重量/体积` 一律由 `dms_task_doc`（上游出库单快照）聚合，配送单**不重算货值**、不保存本单商品明细 → 与销售出库单**单一数据源**，杜绝双口径；
   - **无来源单据**（临时配送）：沿用 `金额 = 数量 × 单价`（HALF_UP 4 位）、表头由明细汇总，前端传值不采信。
3. **退货口径**：`订单类型 = 退货` 时，明细同时计入 `退货单量/退货数量/退货金额`（真实来源，非估算）；其余类型为 0。
4. **配送单量**：按「来源单据编号」去重计数（支持 `,`/`、`/`;`/空格分隔的多单），无来源单时记 1。
5. **三个「编辑中」字段**：`订金金额` / `装箱数量` / `配送里程` 为表头可录入并落库（非聚合假数据）。
6. **状态机**：沿用 `TaskStatusEnum` 9 态；列表对外映射三值（待配送 0·1·2 / 配送中 3·4 / 已配送 5·6；7 已取消 / 8 异常单独标记）。「审核」= 0→1，「反审核」= 1→0 且已指派司机的不可反审核。
7. **删除规则**：仅 0/1/7 可删（逻辑删除，明细一并逻辑删除）；已进入配送执行返回 400。
8. **「显示红冲」**：未勾选时后端 `status != 7`（隐藏已取消）。
9. **选择器统一**：配送司机/车辆/送货员/制单人复用 `/api/dms/task/filter-options`（与《配送查询》**同一口径**，不重复实现）；配送线路取线路主数据 `/erp/md/route/options`；客户/商品取自 `optionsApi` + `ProductSelectModal`。
10. **权限**：TaskController 采用类级 `@SaCheckLogin`（与 ERP 模块一致，不用 `@PreAuthorize`——sa-token 不填充 SecurityContext 会恒抛 AccessDeniedException）。
