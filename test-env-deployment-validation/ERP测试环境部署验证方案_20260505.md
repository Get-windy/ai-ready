## 3. 质量门禁设计方案

### 3.1 部署质量门禁

#### 3.1.1 部署前质量门禁
1. **代码质量门禁**
   - 单元测试覆盖率 ≥80%
   - 代码重复率 ≤3%
   - 代码复杂度（圈复杂度 ≤10）
   - 安全漏洞扫描零高危

2. **构建质量门禁**
   - 构建时间 ≤10分钟
   - 构建成功率 ≥99%
   - 构建产物完整性检查

#### 3.1.2 部署中质量门禁
1. **逐步验证门禁**
   - 每个步骤成功后才能进入下一步
   - 失败自动回滚机制
   - 实时监控和告警

2. **资源检查门禁**
   - 内存使用率 ≤70%
   - CPU使用率 ≤60%
   - 磁盘空间 ≥20%
   - 网络带宽监控

#### 3.1.3 部署后质量门禁
1. **服务健康门禁**
   - 服务启动成功（HTTP 200）
   - 健康检查通过
   - 就绪检查通过
   - 存活检查通过

2. **功能验证门禁**
   - 核心API可用性验证
   - 数据库连接验证
   - 缓存服务验证
   - 消息队列验证

### 3.2 性能质量门禁

#### 3.2.1 响应时间门禁
```yaml
性能门禁阈值：
- API响应时间：P95 ≤ 200ms
- 数据库查询：P95 ≤ 100ms
- 缓存访问：P95 ≤ 10ms
- 页面加载：P95 ≤ 2s
```

#### 3.2.2 资源使用率门禁
1. **系统资源门禁**
   - CPU使用率：平均≤60%，峰值≤80%
   - 内存使用率：平均≤70%，峰值≤85%
   - 磁盘IO：平均≤50%，峰值≤70%
   - 网络带宽：平均≤40%，峰值≤60%

2. **应用资源门禁**
   - JVM堆内存：使用率≤70%
   - 连接池：活跃连接≤80%
   - 线程池：活跃线程≤75%

#### 3.2.3 并发性能门禁
1. **并发用户门禁**
   - 支持并发用户数：≥1000
   - 并发事务处理：≥200 TPS
   - 在线用户数：≥5000

2. **压力测试门禁**
   - 错误率：≤0.1%
   - 吞吐量：≥100 req/s
   - 响应时间：满足SLA要求

#### 5.2.2 Shell验证脚本
```bash
#!/bin/bash
# 部署验证脚本

# 颜色定义
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

# 日志函数
log_info() {
    echo -e "${GREEN}[INFO]${NC} $1"
}

log_warning() {
    echo -e "${YELLOW}[WARNING]${NC} $1"
}

log_error() {
    echo -e "${RED}[ERROR]${NC} $1"
}

# 环境检查
check_environment() {
    log_info "开始环境检查..."
    
    # 检查系统版本
    if [ -f /etc/os-release ]; then
        . /etc/os-release
        log_info "操作系统: $PRETTY_NAME"
    fi
    
    # 检查内存
    total_memory=$(free -m | awk '/^Mem:/{print $2}')
    if [ $total_memory -lt 4096 ]; then
        log_warning "内存不足，建议至少4GB"
    else
        log_info "内存充足: ${total_memory}MB"
    fi
    
    # 检查磁盘空间
    disk_usage=$(df -h / | awk 'NR==2 {print $5}' | sed 's/%//')
    if [ $disk_usage -gt 80 ]; then
        log_error "磁盘空间不足: ${disk_usage}%"
        return 1
    else
        log_info "磁盘空间充足: ${disk_usage}%"
    fi
    
    return 0
}

# 服务检查
check_services() {
    local services=("postgresql" "redis" "nginx" "docker")
    
    for service in "${services[@]}"; do
        if systemctl is-active --quiet $service; then
            log_info "服务 $service 运行正常"
        else
            log_error "服务 $service 未运行"
            return 1
        fi
    done
    
    return 0
}

# 主函数
main() {
    log_info "开始部署验证..."
    
    if ! check_environment; then
        log_error "环境检查失败"
        exit 1
    fi
    
    if ! check_services; then
        log_error "服务检查失败"
        exit 1
    fi
    
    log_info "所有检查通过，环境验证成功！"
}

# 执行主函数
main "$@"
```
