## 实现差异说明（2026-08-29 生产级化）

**实现文件**：`frontend/apps/pc-admin/src/views/purchase/smart-replenish/index.vue`
**后端接口**：`GET /api/erp/stock/smart-replenish/page`（erp-stock 模块：`StockReportController#smartReplenishPage` + `SmartReplenishService` + `SmartReplenishMapper` + `SmartReplenishVO`）

### 页面结构（与对标对齐）
- 单个页面，无 Tab 标签页，无页面配置按钮（与文档「本页没有页面配置」一致）
- 左侧商品分类树（数据源 `erp_product_category`，含「全部商品」虚拟根节点）
- 顶部说明条直接内置于搜索区：`计划采购数量 = 备货天数 ✕ 日均销量 + 待发货数量 - 待收货数量 - 账面库存`
- 查询区：销售日期（区间选择）、备货天数（数字）、商品（模糊）、仓库（下拉）、供应商（模糊）、计划采购数量 ≥（数字）、「查询」按钮
- 工具栏：采购（跳采购订单表单，预填选中商品）、刷新、打印(F8)、导出（CSV）
- 表格 25 列 + 列配置弹窗（`BillTableList` + `useColumnConfig` 自带个人配置/全局配置 Tab，支持列显隐/排序/宽度/冻结，localStorage 持久化）
- 底部合计行：销售数量/销售金额/采购金额/待收货/待发货/账面库存/可用库存/计划采购数量

### 业务口径
- **计划采购数量**（公式见说明条）：`备货天数×日均销量 + 待发货数量 - 待收货数量 - 账面库存`，可负（负值表示当前库存+在途已超出需求，无需补货）
- **日均销量**：`销售数量 / 区间天数`（区间天数由前后端按 `endDate - startDate + 1` 计算；未提供区间时分母为 0，日均销量记 0）
- **销售/采购金额**：优先取 `amount_with_tax`，为空时回退 `unit_price × quantity`，确保有真实数值
- **换算结果**：`erp_product_unit` 中该商品 `is_base_unit=1` 为基础单位（如「罐」），取 `is_base_unit=0` 最大 `conversion_rate` 的非基础单位（如「箱」，1箱=12罐），换算结果 = 基础数量 / conversion_rate；未配置多单位时等于原值
- **租户隔离**：Mapper 方法标注 `@InterceptorIgnore(tenantLine="true")` 禁用全局租户行拦截（因 `WITH RECURSIVE` CTE 无法被拦截器正确注入），改在 SQL 内显式用 `CAST(#{tenantId} AS BIGINT)` 过滤所有表，保证租户隔离正确
- **商品维度**：按 `erp_product` 为中心，每商品一行；商品级（非商品×仓库）聚合，仓库参数为可选过滤（为空统计全部仓库）

### 验收口径（当前开发库 devdb 实测）
- `erp_product` 1 行、`erp_stock` 1 行、`erp_sale_order_item` 2 行（引用不存在的商品 1/2，属历史脏数据）、`erp_purchase_order` 6 行、`erp_sale_outbound` 1 行
- 实测返回 1 行：商品「博多新米坊酒酿果味酱罐头」，账面库存 85、账面库存换算结果 7.0833（85/12）、在途 100（2 张 status=2 采购单×50）、计划采购数量 -185（0×0+0-100-85）
- 接口/查询/分页/过滤逻辑已用 SQL 与 curl 双重验证：`GET /api/erp/stock/smart-replenish/page` 实测 HTTP 200，`total=1`，各过滤（productKeyword/warehouseId/minPlanQty/categoryId/关键字）均正确返回；`minPlanQty≥0` 时因计划采购数量为负故返回 0 条（符合公式逻辑）

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
