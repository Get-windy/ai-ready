### 示例：用户登录正向测试

```markdown
### TC-AUTH-001: 用户登录-用户名密码登录成功

**用例ID**: TC-AUTH-001  
**所属模块**: 用户认证模块  
**接口路径**: POST /api/v1/auth/login  
**优先级**: P0  
**测试类型**: 正向测试  
**自动化状态**: ✅ 已自动化  

#### 前置条件
1. 用户已注册且状态为"正常"
2. 用户密码正确设置
3. 测试环境服务正常运行

| 参数名 | 类型 | 必填 | 值 | 说明 |
|--------|------|------|-----|------|
| username | string | 是 | testuser_001 | 已注册用户名 |
| password | string | 是 | Test@123456 | 正确密码 |
| deviceId | string | 否 | device_001 | 设备标识 |

#### 测试步骤
1. 准备测试用户数据（testuser_001/Test@123456）
2. 发送POST请求到 /api/v1/auth/login
3. 携带JSON格式的用户名和密码参数
4. 验证响应状态码和Token返回

#### 预期结果
**HTTP状态码**: 200  
**响应体结构**:
```json
{
  "code": "0",
  "message": "登录成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 7200,
    "tokenType": "Bearer",
    "user": {
      "id": 10001,
      "username": "testuser_001",
      "nickname": "测试用户",
      "avatar": "https://...",
      "roles": ["USER"],
      "permissions": ["user:read", "order:read"]
    }
  }
}
```

**业务验证**:
- [x] 返回有效的accessToken（JWT格式）
- [x] 返回refreshToken用于Token刷新
- [x] Token有效期为7200秒（2小时）
- [x] 返回用户基本信息和权限列表
- [x] 登录日志正确记录

#### 实际结果
- HTTP状态码: 200
- 响应时间: 156ms
- 测试状态: ✅ 通过

#### 备注
- 该用例为基础登录场景，所有认证相关测试的前置条件
```

```markdown
### TC-AUTH-002: 用户登录-密码错误

**用例ID**: TC-AUTH-002

**接口路径**: POST /api/v1/auth/login

2. 发送POST请求到 /api/v1/auth/login

4. 验证登录失败次数统计

**HTTP状态码**: 401  
**错误码**: AUTH001  
**响应体结构**:
```json
{
  "code": "AUTH001",
  "message": "用户名或密码错误",

  "path": "/api/v1/auth/login"
}
```

**系统行为**:
- [x] 不返回Token
- [x] 登录失败次数+1
- [x] 记录安全审计日志
- [x] 不暴露用户是否存在

- 错误码: AUTH001

### 示例：创建用户边界值测试

```markdown
### TC-USER-001: 创建用户-用户名长度边界值测试

**用例ID**: TC-USER-001  
**所属模块**: 用户管理模块  
**接口路径**: POST /api/v1/users  
**优先级**: P1  
**测试类型**: 边界值测试  
**自动化状态**: ✅ 已自动化  

#### 边界条件定义
| 参数名 | 类型 | 约束条件 | 最小值 | 最大值 |
|--------|------|----------|--------|--------|
| username | string | 用户名长度 | 3 | 20 |

#### 边界值测试矩阵
| 测试项 | 输入值 | 预期结果 | 实际结果 | 状态 |
|--------|--------|----------|----------|------|
| 最小值-1 | "ab" | 拒绝，返回400 | 拒绝，返回400 | ✅ |
| 最小值 | "abc" | 接受，返回201 | 接受，返回201 | ✅ |
| 最小值+1 | "abcd" | 接受，返回201 | 接受，返回201 | ✅ |
| 正常值 | "testuser" | 接受，返回201 | 接受，返回201 | ✅ |
| 最大值-1 | "a"×19 | 接受，返回201 | 接受，返回201 | ✅ |
| 最大值 | "a"×20 | 接受，返回201 | 接受，返回201 | ✅ |
| 最大值+1 | "a"×21 | 拒绝，返回400 | 拒绝，返回400 | ✅ |
| 空值 | "" | 拒绝，返回400 | 拒绝，返回400 | ✅ |
| 特殊字符 | "test@user" | 拒绝，返回400 | 拒绝，返回400 | ✅ |
| 中文 | "测试用户" | 拒绝，返回400 | 拒绝，返回400 | ✅ |

#### 测试步骤
1. 准备10组边界值测试数据
2. 依次使用每组数据调用创建用户接口
3. 记录HTTP状态码和响应内容
4. 对比预期结果

#### 预期结果汇总
- 有效边界值（3-20位字母数字下划线）: 正常创建用户，返回201
- 无效边界值: 返回400，错误码PARAM001，提示"用户名格式不正确"

#### 备注
- 用户名只允许字母、数字、下划线
- 不允许纯数字（防止与手机号混淆）
```
