## 页面概述

按单付款是**应付款核销工作台**：按应付单据逐单付款的处理中心（列表查询 + 阶段 Tab + 行级付款）。**单入口**，无独立表单。

| 页面 | 地址 | 说明 |
|------|------|------|
| 按单付款 | `finance/payment-by-doc` | 复合页（列表 + 3 阶段 Tab） |

单入口：财务 → 付款 → 按单付款。

### 配置功能说明
- **页面配置/列配置**：管理页面级字段与数据表列的显示/隐藏/排序/宽度/冻结。

- ⚠️ **当前实现说明**：本页尚未升级金标准组件（复合页），见「实现差异说明 → 待完善」。

## 业务规范说明

- **应付主线**：采购业务单据（采购入库单 CGRKD-）记账产生应付 → 本页「待付款」；全部单据全集；发票查询看收票。
- **行级「付款」**：对该单据发起付款 → 进入《付款单》（FKD-）；付款后已结金额↑、未结金额↓，待审金额=付款单已提交未记账。
- **金额口径**：本单金额 = 已结金额 + 待审金额 + 未结金额。
- **对账（√/否）**：标记与供应商对账，记录最后对账标记时间/人。
- **无结算付款单核销**：对已记账未勾选核销单据的付款单事后补核销（按钮带未核销计数）。
- **与按单收款差异**：无"超期"Tab、无欠条领取、无司机名称/收款日期/对账日期等（供应商场景）。
- **下游**：付款单记账生成会计凭证（KJPZ-），应付账款 2202 科目。

## 实现差异说明

**实现文件**：
- 前端：`views/finance/payment-by-doc/index.vue`（金标准复合页：3 阶段 Tab + 列/页面配置）
- API：`api/finance/index.ts`（`paymentByDocApi`：`/purchase/doc-query/page` + `/erp/invoice/query`）
- 后端：`InvoiceController` 新增 `/api/erp/invoice/query`（方向+日期+编号+往来单位+开票人过滤）

### 页面对齐（已完成 · 金标准）
- **复合页**：`CategoryListLayout` + `BillTableList` + `ColumnConfigPanel`（列配置弹窗，个人/全局 2 Tab）+ `PageConfigPanel`（页面配置弹窗，查询条件/功能按钮 2 Tab）。
- **阶段 Tab（3）**：待付款 / 全部单据 / 发票查询。
  - **待付款**：29 列（默认显示 14）/ 查询条件 9 / 功能按钮（无结算付款单核销、合并付款、强制结算、刷新、打印(F8)、导出、配置）。
  - **全部单据**：33 列（默认显示 17）/ 查询条件 9 / 功能按钮（取得发票、刷新、打印(F8)、导出、配置）。
  - **发票查询**：销售发票查询 / 采购发票查询 2 子 Tab（radio 切换），各 19 列（默认显示 11），无功能按钮配置 Tab。
- **数据源**：
  - 待付款/全部单据 → `purchaseDocUnifiedApi.page`（`/purchase/doc-query/page`），采购单据即应付款来源（INBOUND 入库/ RETURN 退货/ EXCHANGE 换货）；待付款默认过滤 `settlementStatus=未结算`。
  - 发票查询 → `paymentByDocApi.invoicePage`（`/erp/invoice/query`），按 `direction`（sales/purchase）+ 发票类型集合过滤。
- **金额口径（真实闭环）**：本单金额 = 已结金额 + 待审金额 + 未结金额。已结=已核销/已记账付款单明细（status∈6,7），待审=已提交未记账付款单明细（status∈1,2,4,5），未结=本单-已结-待审。由后端按采购来源单据 → finance_payable → erp_payment_item → erp_payment 聚合（`UnifiedPurchaseDocQueryServiceImpl.enrichPayableSettlement`，无桩/无模拟）。
- **行级付款**：行「付款」→ 跳转 `/finance/payment-doc/form?sourceId=&sourceNo=` 联动《付款单》。
- **对账（可写）**：√/否 标记可点击切换，记录最后对账标记人/时间（finance_payable.reconcile_flag / reconcile_by_name / reconcile_at，Flyway V11.83.0）；无结算付款单核销（POST `/purchase/doc-query/no-settle-write-off`）。

### 本次已落地
1. **后端应付核销链已接通**：按单付款查询由后端聚合 finance_payable（应付）+ erp_payment_item + erp_payment，回写已结/待审/未结；采购单据 settle_status 与应付核销联动。
2. **对账标记有数据源**：finance_payable 新增 reconcile_flag / reconcile_by_name / reconcile_at（Flyway V11.83.0），前端 √/否 可点击切换并记录时间/人。
3. **无结算付款单核销 / 合并付款 / 强制结算 / 取得发票**：无结算核销、强制结算接 `POST /purchase/doc-query/no-settle-write-off`；合并付款联动付款单表单（携带多笔来源单据）；取得发票切换至发票查询 Tab。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 应付单一口径（红线）**：按单付款为应付核销唯一入口，**严禁绕过《付款单》直接改应付余额**；行级付款后已结↑/未结↓，待审=付款单已提交未记账。
- **P1 金额守恒**：本单金额=已结金额+待审金额+未结金额，不得断层。
- **P1 上游联动**：待付款来自采购应付来源（CGRKD-）；对账标记与供应商对账并记录时间/人。
- **P2 验收**：无桩/无模拟；阶段 Tab、无结算核销、对账标记、凭证需真实数据闭环验证。
