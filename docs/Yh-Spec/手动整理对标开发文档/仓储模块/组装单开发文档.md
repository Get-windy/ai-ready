# 组装单开发文档

## 页面概述

组装单用于原料组装为成品的生产入库录单（成品入库 + 原料出库同单完成，双明细表复合）。模块含两个页面：

| 页面 | 地址 | 说明 |
|------|------|------|
| 组装单列表页 | http://localhost:5656/erp/stock-assemble/index | 双入口「历史」标签 |
| 新增/编辑组装单表单页 | http://localhost:5656/erp/stock-assemble/form | 双明细表（成品入库+原料出库）+ 加工费用/计算成本 |

### 配置功能说明（每个页面都有）

- **页面配置**（页面顶部齿轮图标）：管理页面级字段的显示、隐藏和排序
- **列配置**（数据表右上角表头单元格内齿轮图标）：管理数据表列字段的显示、隐藏、排序、宽度调整及左右冻结

### 双入口配置（本系统）

| 项 | 值 |
|----|----|
| 菜单 ID | 5015（原"组装管理"，本次改名"组装单"） |
| menu_code | `erp:stock-assemble` |
| 主菜单路径 | `erp/stock-assemble/form`（点击进新增表单） |
| 标签「历史」路径 | `erp/stock-assemble/index`（进列表） |
| tag_label | 历史 |
| display_mode | 1（双入口） |
| 组件 | `erp/stock-assemble/form`（表单）、`erp/stock-assemble/index`（列表） |

## 新增组装单表单页配置

### 表头字段（对标实据）

- 必填：成品仓库\*、原料仓库\*、经手人\*（默认当前登录人）、单据日期\*（截图确认必填）
- 选填：生产单位
- 费用区：加工费用（默认 0）
- 摘要区：本单金额（自动计算）

**字段分组**：顶部基本信息（成品仓库/原料仓库/经手人/生产单位/单据日期）→ 成品详情(入库)表 → 原料详情(出库)表 → 加工费用/计算成本 → 备注区（单据备注）→ 单据信息（制单人/制单时间/打印次数/打印记录）→ 本单金额。

### 功能按钮（对标实据）

打印(F8)、历史、导出、计算成本、保存草稿 Ctrl+S、记帐 Ctrl+Enter

### 双明细表格列配置（成品表与原料表结构一致，各 14 业务列 + 操作列对齐实据）

操作、商品名称（带「扫描枪录入」开关）、货号、货位、条码、计价单位、批次条码、生产日期、保质期、到期日期、数量、件散数量、成本单价、成本金额、备注

## 业务规范说明

- 保存草稿（Ctrl+S）→ 记帐（Ctrl+Enter）：记帐后成品按「成品详情(入库)」增加成品仓库库存，原料按「原料详情(出库)」扣减原料仓库库存。
- 加工费用 + 计算成本：成品成本=原料成本合计+加工费用，点击「计算成本」按此口径回填成品成本单价（推断，待复核）。
- 生产单位：非必填，推断为生产车间/加工单位（待复核）。
- 可由生产模板带出原料构成（模板引用交互待复核）。
- 上游：生产模板（BOM 原料构成来源）；反向单据：拆分单（成品拆回原料）；记帐后影响 分析→仓配分析→查库存/库存明细。
- **架构师红线**：对标 Odoo/SAP/金蝶/用友/管家婆等生产级系统的业务与交互逻辑；动手前过六关，仅最小可用闭环，防注入/容灾/安全防御代码不准省。
- **验收标准**：无桩（Stub）与模拟（mock|todo|fixme|占位|placeholder），确保真实数据。
- **对标系统**：ql361（`22stable.ql361.com`），具体见 `docs/Yh-Spec/ql361对标/README.md`。

## 实现差异说明

**实现文件**：`frontend/apps/pc-admin/src/views/erp/stock-assemble/form.vue`（表单页）、`.../index.vue`（列表页）

### 页面对齐
- 2026-08-12 批次5 双表并排改造完成：重构为**成品详情(入库)表 + 原料详情(出库)表双明细并排**，各 14 业务列 + 操作列（行增删/扫描枪录入开关），含 货号/货位/条码/计价单位/批次条码/生产日期/保质期/到期日期/数量/件散数量/成本单价/成本金额/备注；表头字段对齐（成品仓库\*/原料仓库\*/经手人\*/生产单位/单据日期\*）；加工费用 + 计算成本按钮（成品成本 = 原料成本合计 + 加工费用，按成品数量分摊回填成品成本单价）。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
