## 1. 页面概述

- **订单池**：待分配配送任务的**公开池**，配送员可**抢单**，或由企业设定**竞价**（配送员报价、价低者得）。
- 与《调度任务》的分工：《调度任务》是**管理员指派**视角（定向派单）；《订单池》是**运力自选**视角（抢单 / 竞价），对应外卖平台的"众包大厅"与快递的"派件池"。

### 3.3 状态机（建议固化）

```
待抢单(0) ──开启竞价──> 竞价中(1) ──结算──> 已接单(2)
    ↑                      │
    └────关闭竞价──────────┘   （作废本次报价，二轮复验新增）
    │                      │
    └────下架────> 已下架(4)  └──超时──> 已过期(3)
```

- **抢单**：先到先得，命中即置 `已接单` 并生成/更新 `DmsTask.riderId`。
- **竞价**：在截止时间内收集报价，`settleBid` 选中（价低优先，同价按评分/负载），落 `is_win`。
- **关闭竞价**（2026-09-13 二轮补齐）：`竞价中 → 待抢单`，作废本次全部报价（逻辑删除留痕）、清空竞价字段，可改回「先到先得」或重设起拍价再开。用于起拍价填错/临时改模式的撤回场景。
- **过期**：定时任务扫描 `expirePools`，超时未成单 → `已过期`，可回流至《调度任务》人工指派。

### 3.5 业界生产级实践要点

1. **防作弊**：抢单需校验配送员状态（在线/负载/资质）、防脚本刷单（频控 + 验证码/信誉分）。
2. **竞价公平**：报价密封、截止时间统一、同价规则公开（评分/负载/历史履约）。
3. **池生命周期**：发布时限、过期回流、下架原因留痕。
4. **结算可信**：中标结果与任务指派**同事务**写入，避免"中标了但任务没派出去"。
5. **与外部运力协同**：池可同时向外部渠道推单（`/channel/{id}/push-order`，见《渠道管理》），回执统一收敛到池状态。

### 4.2 关键实现口径（避免回归）

1. **状态机**：`待抢单(0) ─启用竞价→ 竞价中(1) ─结算→ 已接单(2)`；`待抢单/竞价中 ─下架→ 已下架(4)`；`竞价中 ─超时→ 已过期(3)`。已接单不可下架、已下架/已过期不可强制分配。
2. **抢单**：乐观锁重试 + 先到先得；校验配送员存在且**空闲**、实名资质（`KycService.assertEligible`，租户参数 `verification.eligibility.enforce` 缺省关闭）；命中后**同事务**写池状态与任务（`riderId`/`riderName` 快照/状态=已接单/调度方式=抢单）。
3. **竞价**：起拍价为上限（高于即拒）、**截止时间后不再收单**；`settleBid` 价低者中标，**中标与任务指派同事务**（调度方式=竞价）——修复了原先「只改池、任务没派出去」的闭环断裂。
4. **强制分配**：定向指派（调度方式=手动）；**幂等**（同一骑手重复指派直接返回）；已被他人接单时拒绝。
5. **防重复入池**：同一任务已有「待抢单/竞价中」记录时拒绝重复发布，避免一笔任务被两人分别接单。
6. **发布配送费**：未填时沿用任务上的配送费（与表单提示一致）。
7. **过期处理**：`POST /expire-scan` 扫描 `竞价中 且 bidEndTime<=now` 的池 → 已过期，可回流《调度任务》人工指派（暴露为按钮，未挂定时任务）。
8. **列表取值**：任务编号/订单号/客户/订单类型/取货·收货地址/里程/货品金额由 `dms_task` 联查，池状态与订单类型文案由后端字典给出，页面不显示裸 ID。
9. **入池门控（二轮）**：只有「待分配」任务可入池；「待抢单 / 竞价中 / 已接单」任一活跃池记录存在时拒绝重复发布——否则新池被抢单会覆盖任务上的骑手，形成「一人已接单、他人又抢走」的双接单。已下架 / 已过期后可重新发布。
10. **竞价公平性（二轮）**：同一配送员重复出价 = **改价**（只保留最新一条，不再新增记录，避免刷「竞价数」/霸占名次）；`bidCount` 与当前价一律按**有效报价重算**，取消出价后当前价回退到剩余最低价（无人报价则回退起拍价）。
11. **取消出价门控（二轮）**：仅「竞价中」的池可取消出价；池一结算/下架/过期，报价即成为历史凭证（后端拦截 + 详情页隐藏按钮）。
12. **结算不选已取消报价（二轮）**：`bid-list`/`settleBid` 走的手写 SQL 必须自带 `deleted = 0`（MyBatis-Plus 逻辑删除**不作用于** `@Select`），否则已撤销的报价会出现在列表里、甚至以最低价中标。
13. **中标人资质（二轮）**：`settleBid` 与抢单/强制分配一致调用 `KycService.assertEligible`，避免「竞价中标」成为绕过实名资质的口子。
14. **竞价参数边界（二轮）**：起拍价 > 0、时长 1~1440 分钟。
15. **关闭竞价（二轮）**：`竞价中 → 待抢单`，作废本次报价（逻辑删除留痕）、清空 `bid_*` 字段；清空必须走 `LambdaUpdateWrapper.set(..., null)`（`updateById` 默认忽略 null 字段）。
16. **下架留痕（二轮）**：`offline_reason` / `offline_time` 落库（此前只写日志，页面填的原因静默丢失），并作为默认隐藏列 + 导出列可见。
17. **查询条件生效（二轮）**：`riderId`（接单配送员）与 `routeId`/`routeArea`（配送线路/区域）此前前端发参、后端不消费 → 已接入任务侧两段式过滤。

### 4.3 遗留与边界

1. **配送员端抢单/出价 UI**：接口齐备（`grab`/`bid`/`cancel-bid`），本页提供**管理端代操作**；配送员自助入口在司机端（`frontend/apps/driver-delivery`），本次未接。
2. **定时过期**：当前为手动「过期处理」按钮，未加 `@Scheduled`（多实例部署需先约定单实例执行/分布式锁）。
3. **外部运力协同**：池推单到渠道、回执收敛待《渠道管理》适配器真实化后接入。
4. **跨模块缺陷修复**：`BillDetailTable` 自定义插槽原先**未透传 `column`**，导致所有「用 `record[column.key]` 取值」的插槽列（金额/数量）显示 0（合计行却正确）——已在组件层补 `:column` 修复，影响面覆盖本页与其它使用该写法的页面。
5. **待抢单无发布时限**：`待抢单` 池没有截止时间（只有竞价的 `bid_end_time`），长期无人抢单的池需要人工下架；若要自动回收需再加 `expire_time` 列 + 扫描（本轮未做）。
6. **配送员端竞价**：司机端未接出价/竞价入口（同 1）。
