## 业务规范说明

### 采购收货模型（列实据归纳）

- 业务对象为**待收货的采购订货单据**：单据状态查询默认"待收货,部分收货"，即本页是收货待办工作台，已完成收货的单据默认不再出现
- **应收数量 / 未收数量**：按单据跟踪收货进度，支持分次收货（"部分收货"状态实据）；未收=应收−已收
- **预计收货日期**：采购到货计划管理
- **往来单位 / 结算单位**双列：供货的供应商与结算主体可不同（如总部供货、分仓结算场景）
- **结算状态**：收货与付款结算进度解耦
- **批量收货**：勾选多行后批量执行收货确认，适配集中到货场景

### 与源单（采购入库单）的关系（实据归纳）

- 采购线主线：采购订单（订货）→ **本页收货处理**（实物收货确认，待收货→部分收货→已收货）→ 采购入库单（入库记账、库存增加）
- 与销售线对称：销售订单 → 拣货/发货 → 销售出库单；采购订单 → 收货处理 → 采购入库单。收货确认与采购入库单的生成关系（收货即生成入库单 / 收货后另行入库）待复核
- 退货方向对称页：物流退货收货（销售退货回流的收货确认）

### 与其他页面关系

- 上游：采购订单（采购域）
- 同组：物流退货收货（退货线收货）
- 下游：采购入库单（采购域，入库记账）；应付款结算（结算状态口径来源，待复核）

### 往来单位来源

往来单位来源通过 ERP 模块的往来单位处理（供应商分类），与销售线客户同源不同类；CRM客户是公海客户，ERP往来单位是实体客户/供应商。
