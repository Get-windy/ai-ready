# 查资金开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`analytics/check-fund`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **账表页**（资金账）：资金账户余额与收支流水（资金余额/收支汇总/资金流水三视图，科目层级呈现，行级对账）；现金银行日记账的汇总视图。菜单路径：分析 → 财务分析 → 查资金。
- 页面结构：视图 Tab（资金余额/收支汇总/资金流水）+ 查询区（两行）+ 账户科目台账表格（科目名称按层级缩进，发生额分组表头）+ 合计行。
- 页面截图：`tool-results/ql361/pages/分析__财务分析__查资金.png`

## 3. 数据表格列配置

### 默认显示列（7 列，抓取 JSON columns 实据，资金余额视图）

操作、科目名称、科目编号、期初金额、借方、贷方、期末余额

> JSON columns 首项"操作"经截图核对为真实首列（行级"对账"单元格），非抓取拼接串，计入列数；"发生额"为**分组表头**（下辖借方、贷方两列）。收支汇总/资金流水两视图列结构不同（流水视图含单据日期/摘要/收支方向等，待复核）。

## 4. 业务规范

### 统计口径（期初+借贷=结存）

- **恒等式**：期末余额 = 期初金额 + 借方 − 贷方（逐行成立：现金库存 6,293.33+31,879−17,525=20,647.33 ✅；合计 -588,024.12+1,342,908.75−1,110,782.1=-355,897.47 ✅）
- **科目层级**：一级科目（1001 现金库存/1002 银行存款）+ 二级账户科目（1001xx/1002xx），一级行为下级合计（现金库存 6,293.33=186+5,161.33+946 ✅）。科目体系实据：100101 现金、100102 店面备用金、100103 敦煌店面备用金；100201 农业银行一、100202 微信账户、100203 支付宝账户、100204 开单微信钱包、100205 农业银行二、100206 建设银行、100207 工商银行、100208 中国银行、100209 酒泉农商行、100210 皇朝银行对公账户、100211 信合对公账户、100212 兰州银行、100213 农行信用卡、100214 蚂蚁花呗、100215 农行快E贷、100216 农行乐易分期
- **贷方余额账户**：信用卡/花呗/快E贷等信贷类账户期初为负（农行信用卡 -8,665.64、农行快E贷 -100,000）
- **日期类型**：单据日期（默认）/其他日期口径（可选值待复核）

### 与其他页面关系

- 取数：收款单/付款单/预收/预付/提现存现转款等资金单据（经营历程流水）按账户归集
- 联查：行级"对账"→ 账户资金流水（本页资金流水视图/《明细账》1001-1002 科目）
- 同源页：《经营分析》（收支损益口径）、财务域《总账》（同一科目体系）
