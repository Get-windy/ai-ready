## 3. 接口规范标准

### 3.1 基础规范要求

#### 3.1.1 请求/响应格式
```yaml
Request Headers:
  Content-Type: application/json
  Authorization: Bearer {token}
  X-Request-ID: {uuid}
  X-API-Version: v1

Response Format:
  {
    "success": true/false,
    "code": "200",              # 业务状态码
    "message": "操作成功",        # 用户友好消息
    "data": {},                 # 响应数据
    "timestamp": 1777593000000  # 响应时间戳
  }

Error Response:
  {
    "success": false,
    "code": "40001",            # 错误码
    "message": "参数验证失败",
    "errors": [                 # 详细错误信息
      {
        "field": "supplierId",
        "message": "供应商ID不能为空"
      }
    ],
    "timestamp": 1777593000000
  }
```

#### 3.1.2 状态码规范
**HTTP状态码**：
- 200：操作成功
- 400：请求参数错误
- 401：未授权
- 403：权限不足
- 404：资源不存在
- 500：服务器内部错误

**业务状态码**：
- 20000：成功
- 40000-49999：客户端错误
- 50000-59999：服务端错误

#### 3.1.3 分页规范
```yaml
Request:
  GET /api/resources?page=1&size=20&sort=name,asc&sort=createdAt,desc

Response:
  {
    "data": [],
    "pagination": {
      "page": 1,
      "size": 20,
      "total": 100,
      "pages": 5
    }
  }
```

### 3.2 安全认证规范

#### 3.2.1 认证方式
1. **JWT Token认证**：适用于用户操作接口
2. **API Key认证**：适用于服务间调用
3. **OAuth2.0**：适用于第三方集成

#### 3.2.2 权限控制
**RBAC模型**：
- 角色：管理员、供应商、采购员、财务人员
- 权限：读、写、审核、删除
- 资源：供应商数据、批次信息、价格策略、合同文档

### 3.3 接口版本管理
**URL路径版本化**：/api/v1/suppliers  
**请求头版本化**：X-API-Version: v1  
**向后兼容要求**：至少支持2个历史版本

## 4. 关键接口定义与协调

### 4.1 第一优先级接口（P1-必须在Sprint 27+1完成）

#### 4.1.1 供应商资质查询接口
**接口名称**：GET /api/v1/suppliers/{supplierId}/qualifications  
**提供方**：供应商门户模块  
**消费方**：批次管理模块  
**用途**：批次创建前验证供应商资质

**请求参数**：
```yaml
Path Parameters:
  - supplierId: string (required) - 供应商ID

Query Parameters:
  - qualificationType: string (optional) - 资质类型（quality_certificate, production_capacity, financial_status）
  - validOnly: boolean (optional) - 是否只返回有效资质
```

**响应数据**：
```json
{
  "success": true,
  "data": {
    "supplierId": "supp_001",
    "supplierName": "ABC供应商",
    "qualifications": [
      {
        "id": "qual_001",
        "type": "quality_certificate",
        "name": "ISO9001质量认证",
        "certificateNumber": "ISO9001-2024-001",
        "issueDate": "2024-01-15",
        "expiryDate": "2025-01-15",
        "status": "valid",
        "verificationLevel": "A"
      }
    ],
    "overallQualificationStatus": "qualified",
    "lastVerifiedAt": "2026-04-30T10:30:00Z"
  }
}
```

**协调要求**：
- ✅ 供应商数据模型中必须包含资质信息字段
- ✅ 批次管理模块需要调用此接口进行验证
- ⏳ 接口开发完成时间：5月5日
- ⏳ 接口测试完成时间：5月7日

### 7.1 变更类型
1. **不兼容变更**：修改请求/响应结构、删除字段
2. **兼容性变更**：添加可选字段、添加新接口
3. **内部优化变更**：性能优化、bug修复

### 7.2 变更审批流程

变更申请 → 技术评审 → 影响分析 → 开发实施 → 测试验证 → 发布上线

   - **影响**：接口对接失败
