## 页面概述

供应商是**供应商主数据档案**（含分类树 + 查询 + 工具栏），用于采购订单/采购入库/应付等的供应商主体。双入口（列表 + 表单）。

| 页面 | 地址 | 说明 |
|------|------|------|
| 供应商列表页 | `md/supplier/index`（list_path 双入口） | 供应商档案列表 + 供应商分类树 |
| 供应商表单页 | `md/supplier/form/:id` | 新增/编辑供应商 |

> 供应商/客户/物流/其他往来单位统一走 `erp/partner`（往来单位），`biz_party.partyType`=2（supplier），`md/supplier` 为供应端口。

### 配置功能说明

- **列配置**：数据表表头序号列内嵌齿轮 `.ss-header-settings`（列配置弹窗：个人配置 / 全局配置，表格列「序号 / 上级 / 列名 / 显示名 / 显示」+ 恢复默认）。
- **工具栏**：新增 / 导入 ‖ 刷新 / 打印(F8) / 导出 / 更多（更多 = 批量搬移 / 批量删除 / 停用 / 启用 / 取消价格跟踪）。
- **无页面配置弹窗**：供应商列表页查询条件/功能按钮为**固定项**（无顶部「配置」齿轮，实测 `icon-shezhi3` 数量为 0）。
- **底部**：左侧「当前路径：全部供应商」+ 表尾分页栏（资料模块经典形态，见「分页栏」章节）。
- **实现状态（2026-09-11 金标准达标）**：列表页为独立页 `views/md/supplier/index.vue`（`CategoryListLayout` + `BillDetailTable`），
  查询条件全量生效、列配置持久化、导出真实 xlsx、分类树 CRUD 闭环、行级「更多」4 项齐备；
  接口 + 浏览器验收 **113/113**（`tools/acceptance/verify-supplier.cjs`，可复跑）。

**「显示层次结构」实测行为**（`tool-results/ql361/supplier-deep/rows-hierarchy.json`）：

即由「供应商平铺列表」切换为「分类层级视图」，点击分类行可下钻该分类下供应商。

**「显示客户中的供应商」实测行为**（`tool-results/ql361/supplier-deep/rows-ascustomer.json`）：
结果集合并为「供应商 ∪ 客户中同时具备供应商身份的往来单位」（实测合并后出现编号为时间戳的客户记录），
即多重身份合并口径，而非客户/供应商二选一。

### 行级「更多」下拉（实测 4 项）

`tool-results/ql361/supplier-deep/40-row-more.png` 实测行级「更多」= **删除 ｜ 停用 ｜ 详情 ｜ 客商合并**（顺序同上）。

- **停用**：单条停用（`PUT /erp/md/customer/{id}/status?status=DISABLED`）。
- **详情**：进入编辑表单（本系统 `md/supplier/form?id=`，与「修改」同页；对标为只读详情页签）。
- **客商合并**：**仅当该往来单位同时登记为客户时可用**（实测 `dh004` 纯供应商行该菜单项为灰）；
  用于把同一主体的「供应商档案 + 客户档案」合并成一条主档。

## 业务规范说明

- **供应商来源**：ERP 往来单位-供应商（`biz_party.partyType`=2），**非 CRM 公海客户**。
- **主体关系**：客户=1 supplier=2 logistics=3 other=4 统一 `biz_party`；供应商特有经营系列/经营面积/税号/开户行/银行账号。
- **编号前缀**：GYS（中文）/ SUP（英文），经 `GET /erp/md/customer/next-seq?prefix=GYS` 异步生成；
  本系统完整编号为「前缀-YYYYMMDD-序号」（对标系统为「前缀+序号」，差异见「实现差异 1」），编号可手工修改。
- **订货下推**：列表行「订货」跳转 `/erp/purchase/form?supplierId&supplierName`，带入采购订单供应商。
- **状态**：ENABLED=1 / DISABLED=0；采购/应付仅选定启用供应商。
- **应付接入**：供应商应付余额（付款单/预付款单联动）；期初应付/预付用于初始化。
- **账期**：动态付款期限(天)/固定账期/结算期入应付账期判断。
- **客商合并（彻底合并）**：同一主体既做供应商又做客户时，主数据会出现两条 `biz_party`；行级「客商合并」把源档案**彻底**并入目标档案：
  ① 迁移源档案在**全部业务表**中的引用（联系人、附件、订单、出入库、收付款、应收应付、发票…）；
  ② 目标承接身份（`roles`）/ 分类（目标为空时）/ 期初金额（累加）；
  ③ 源档案**物理删除**。
  > 引用列由 `information_schema` **动态发现**（当前 90+ 处，覆盖 ERP/CRM/WMS/DMS/财务/商城），
  > 新增业务表自动覆盖，不需要回头维护清单；列可能是 `bigint` 也可能是 `varchar`（含 `tenant_id` 列同样如此），按列实际类型传参。
  > 开发阶段无历史数据包袱，**不做逻辑删除留痕**，也不保留"部分引用不迁移"的兼容分支。

### 实现差异（与对标不同的取舍，均有依据）

1. **编号格式**：对标为 `gys002`（前缀+3 位序号）；本系统沿用全站往来单位统一口径 `GYS-YYYYMMDD-XXXX`
   （`utils/codeGenerator.ts#generateCode`，客户/物流/其他往来单位同源）。编号可手工改写，不影响业务。
2. **表单未加「默认经手人 / 默认仓库 / 供应商等级 / 证件信息」**：文档 2026-09-07 版「待完善 5」建议按客户表单补全，
   但 2026-09-11 对标系统实测（`tool-results/ql361/supplier-deep/form2.json` 字段 id 连续 10–34）**确认供应商表单只有
   基础信息/联系人/纳税人信息/期初信息/其他信息/附件 6 分区**，无上述字段。本实现以对标系统实测为准，不做冗余加列。
   > 后端 `biz_party.default_handler_id/name` 仍保留（客户表单使用），供应商表单暂不暴露。
3. **「更多」不含「跳转」**：文档原表把分页器「跳转」误记为工具栏按钮，实测工具栏更多 = 批量搬移/批量删除/停用/启用/取消价格跟踪。
4. **期初应付/期初预付为只读展示**：与对标一致（实测该两输入框 `disabled=true`），余额由财务记账维护，表单仅展示。
5. **分类编码**：对标 `gysml002`；本系统按「类型码前缀 + 3 位序号」生成（`gysml`/`khml`/`wlgsml`/`wldwml`），
   前端未填时自动生成，可手工指定。
6. **「名称重复配置」为真实系统配置**：以系统配置键 `md:supplier:name-duplicate` 持久化（允许/提示/禁止三档），保存时会按该配置校验同名供应商。
7. **菜单 tag_label**：菜单 80511 现有 `path=md/supplier/index` + `list_path=md/supplier/form` + `tag_label=添加`
   （与 70501 商品同构，即点菜单先到列表）；对标页签为「供应商编辑」，故已在路由层把指向表单的第二标签标题统一为「XX编辑」。
8. **列配置弹窗形态**：对标弹窗为「序号 / 上级 / 列名 / 显示名 / 显示」+ 底部「上移 / 下移 / 恢复默认 / 保存」；
   本系统复用全站统一的 `BillDetailTable` 表头齿轮弹窗（个人配置 / 全局配置 + 勾选 + 显示名 + 宽度 + 拖拽排序，**改动即时持久化**）。
   本系统为功能超集（多出宽度与拖拽），交互按全站一致口径，不再单独做一份弹窗。
9. **「客商合并」交互取不到对标弹窗细节**：对标该菜单项在纯供应商行恒为灰（实测 `dh004`），
   需一条「既是客户又是供应商」的单位才可点，而对标账号下无此类数据，故弹窗形态无法抓取。
   本系统按业务语义实现**彻底合并**：源（当前行）并入目标（搜索选择的客户），
   迁移全部业务引用 → 目标承接分类/期初/身份 → 源档案物理删除；返回迁移引用数供提示。

### 待完善（非阻塞）

1. **分类树拖拽排序**：对标分类树支持排序维护，本系统目前以「排序」字段数值维护（表单内可填），未做拖拽。
2. **附件上传目录服务**：`/file/upload` 为通用文件服务，供应商附件记录落 `erp_partner_attachment`；附件与业务单据的引用校验未做。

4. **订货下推带参**：已带 `supplierId/supplierName`；供应商账期/期初尚未驱动采购订单默认值（属采购模块口径）。
