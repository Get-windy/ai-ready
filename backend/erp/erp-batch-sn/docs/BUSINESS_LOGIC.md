# 批次/序列号管理业务逻辑说明文档

## 1. 业务概述

### 1.1 功能定位

批次/序列号管理模块是ERP系统的核心库存管理组件，提供：
- **批次管理**: 对同一生产批次的产品进行统一管理和追踪
- **序列号管理**: 对单个产品进行唯一标识和全生命周期追踪
- **质量追溯**: 支持从原材料到成品的完整追溯链条
- **有效期管理**: 自动监控批次有效期，提供临期预警

### 1.2 适用场景

| 场景 | 批次管理 | 序列号管理 |
|------|----------|------------|
| 食品/药品行业 | ✅ 生产日期、保质期管理 | ✅ 单品追溯 |
| 电子产品 | ✅ 生产批次追踪 | ✅ 质保管理、维修记录 |
| 汽车零部件 | ✅ 供应商批次管理 | ✅ 单品追溯、召回管理 |
| 化工原料 | ✅ 批次质量检验 | ⚪ 可选 |

## 2. 核心业务流程

### 2.1 批次生命周期

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   创建批次   │ -> │   入库     │ -> │   库存管理   │ -> │   出库     │
│  (CREATE)   │    │ (INBOUND)  │    │  (MANAGE)   │    │ (OUTBOUND)  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                          │
                                                          v
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   完成     │ <- │   销售     │ <- │   质检     │ <- │   分配     │
│ (COMPLETE)  │    │  (SALE)    │    │  (QC)      │    │ (ALLOCATE)  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

#### 2.1.1 批次创建规则

**批次号生成规则**:
```
格式: [前缀] + [日期] + [序列号]
示例: B202604290001
      │ ││││││││ └─ 4位序列号
      │ └┴┴┴┴┴┴┴─── 8位日期(YYYYMMDD)
      └──────────── 前缀(默认B)
```

**创建时机**:
1. **采购入库**: 供应商送货时创建批次
2. **生产入库**: 生产完成时创建批次
3. **退货入库**: 客户退货时创建新批次或归入原批次

#### 2.1.2 库存数量管理

**数量关系**:
```
总数量 = 可用数量 + 预留数量 + 冻结数量

- 可用数量: 可立即出库的数量
- 预留数量: 已分配给销售订单/生产工单的数量
- 冻结数量: 质量问题或盘点差异冻结的数量
```

**状态流转**:
```
ACTIVE (活跃) 
  ├──> EXPIRED (过期) - 超过有效期自动转换
  ├──> QUARANTINED (隔离) - 质量问题人工标记
  └──> CANCELLED (取消) - 错误批次人工取消

QUARANTINED
  ├──> ACTIVE - 质检通过恢复
  └──> CANCELLED - 质检不合格销毁
```

### 2.2 序列号生命周期

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  生成序列号  │ -> │   入库     │ -> │   销售出库   │ -> │  客户使用   │
│  (GENERATE) │    │ (INBOUND)  │    │ (OUTBOUND)  │    │  (IN_USE)   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                          │
         ┌────────────────────────────────────────────────┼────────────────┐
         │                                                │                │
         v                                                v                v
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   报废     │    │   维修     │    │   质保     │    │   召回     │
│  (SCRAP)   │    │ (MAINTAIN) │    │ (WARRANTY) │    │ (RECALL)   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

#### 2.2.1 序列号生成策略

**自动生成**:
- 规则: `[产品编码] + [日期] + [6位序列号]`
- 示例: `PROD001-20260429-000001`

**外部导入**:
- 支持导入供应商提供的序列号
- 支持导入生产系统生成的序列号

#### 2.2.2 状态与阶段管理

**状态 (Status)**: 产品的可用性状态
- `AVAILABLE`: 可用，待销售
- `IN_USE`: 已销售，客户使用中
- `INSERVICE`: 服务中（租赁/维保）
- `MAINTAINED`: 维修中
- `SCRAP`: 已报废

**阶段 (Stage)**: 产品的物理位置
- `WAREHOUSE`: 仓库中
- `IN_TRANSIT`: 在途运输
- `EOF_CUSTOMER`: 客户手中
- `IN_SERVICE`: 服务现场
- `SCRAPPED`: 已报废处置

## 3. 关键业务逻辑

### 3.1 有效期管理

#### 3.1.1 临期预警计算

```java
// 临期判断逻辑
boolean isExpiring(BatchNumber batch, int warningDays) {
    if (batch.getExpirationDate() == null) {
        return false;
    }
    LocalDate today = LocalDate.now();
    LocalDate expirationDate = batch.getExpirationDate();
    long daysUntilExpiry = ChronoUnit.DAYS.between(today, expirationDate);
    
    return daysUntilExpiry >= 0 && daysUntilExpiry <= warningDays;
}
```

**预警等级**:
| 剩余天数 | 预警级别 | 处理方式 |
|----------|----------|----------|
| > 30天 | 正常 | 无 |
| 15-30天 | 黄色预警 | 邮件通知 |
| 7-15天 | 橙色预警 | 邮件+短信通知 |
| < 7天 | 红色预警 | 邮件+短信+系统弹窗 |
| 已过期 | 过期 | 自动冻结，禁止出库 |

#### 3.1.2 自动过期处理

**定时任务** (每日凌晨执行):
1. 扫描所有`ACTIVE`状态的批次
2. 检查`expiration_date < today`
3. 自动更新状态为`EXPIRED`
4. 记录过期日志
5. 发送过期通知

### 3.2 质量追溯

#### 3.2.1 追溯维度

**正向追溯** (原材料 -> 成品):
```
原材料批次A + 原材料批次B -> 生产工单 -> 成品批次C -> 序列号SN001
```

**反向追溯** (成品 -> 原材料):
```
序列号SN001 -> 成品批次C -> 生产工单 -> 原材料批次A/B
```

#### 3.2.2 追溯查询

**查询类型**:
1. **简单追溯**: 查询直接关联的上下游批次
2. **完整追溯**: 查询完整的追溯链条（多级）
3. **范围追溯**: 查询特定时间范围内的所有关联记录

### 3.3 库存分配策略

#### 3.3.1 先进先出 (FIFO)

```java
// FIFO分配逻辑
List<BatchNumber> allocateFIFO(String productCode, BigDecimal requiredQty) {
    // 1. 查询该产品所有可用批次，按生产日期升序
    List<BatchNumber> batches = batchMapper.selectAvailableByProductOrderByDate(productCode);
    
    // 2. 依次分配，优先使用最早入库的批次
    List<BatchNumber> allocated = new ArrayList<>();
    BigDecimal remaining = requiredQty;
    
    for (BatchNumber batch : batches) {
        if (remaining.compareTo(BigDecimal.ZERO) <= 0) break;
        
        BigDecimal available = batch.getAvailableQuantity();
        BigDecimal toAllocate = remaining.min(available);
        
        allocated.add(batch);
        remaining = remaining.subtract(toAllocate);
    }
    
    return allocated;
}
```

#### 3.3.2 先到期先出 (FEFO)

适用于有有效期的产品，优先使用即将过期的批次。

### 3.4 质保管理

#### 3.4.1 质保期计算

```java
// 质保结束日期计算
LocalDate calculateWarrantyEndDate(SerialNumber serial) {
    LocalDate startDate = serial.getWarrantyStartDate();
    Integer periodMonths = serial.getWarrantyPeriod();
    
    if (startDate == null || periodMonths == null) {
        return null;
    }
    
    return startDate.plusMonths(periodMonths);
}
```

#### 3.4.2 质保状态检查

```java
// 质保有效性检查
boolean isWarrantyValid(SerialNumber serial) {
    LocalDate endDate = serial.getWarrantyEndDate();
    if (endDate == null) {
        return false;
    }
    return !LocalDate.now().isAfter(endDate);
}
```

## 4. 业务规则约束

### 4.1 批次管理约束

| 规则 | 说明 | 错误处理 |
|------|------|----------|
| 批次号唯一性 | 同一租户内批次号不可重复 | 返回409冲突错误 |
| 数量非负 | 所有数量字段必须≥0 | 返回400参数错误 |
| 可用数量≤总数量 | 可用数量不能超过总数量 | 返回422业务错误 |
| 过期批次不可出库 | EXPIRED状态禁止出库操作 | 返回422业务错误 |
| 隔离批次不可分配 | QUARANTINED状态禁止分配 | 返回422业务错误 |

### 4.2 序列号管理约束

| 规则 | 说明 | 错误处理 |
|------|------|----------|
| 序列号全局唯一 | 系统内序列号不可重复 | 返回409冲突错误 |
| 序列号不可修改 | 创建后序列号字段不可更改 | 忽略修改或返回400 |
| 状态流转合法性 | 必须遵循预定义的状态机 | 返回422业务错误 |
| 维修次数限制 | 超过最大维修次数自动建议报废 | 返回警告信息 |

## 5. 异常处理

### 5.1 常见异常场景

| 场景 | 异常类型 | 处理建议 |
|------|----------|----------|
| 批次号重复 | DuplicateKeyException | 提示用户更换批次号或使用系统自动生成 |
| 库存不足 | InsufficientStockException | 提示用户检查库存或分批处理 |
| 状态非法 | IllegalStateException | 提示用户当前状态不允许该操作 |
| 有效期已过 | ExpiredException | 自动标记过期，提示用户处理 |
| 序列号不存在 | NotFoundException | 提示用户检查序列号是否正确 |

### 5.2 补偿机制

**出库失败补偿**:
1. 记录失败日志
2. 回滚预留数量
3. 发送告警通知
4. 人工介入处理

## 6. 性能优化

### 6.1 数据库优化

**索引策略**:
- 批次号、序列号: 唯一索引
- 产品编码、状态: 普通索引
- 创建时间: 倒序索引（用于列表查询）

**分区策略**:
- 流转记录表按时间分区（按月）
- 审计日志表按时间分区（按季度）

### 6.2 缓存策略

**热点数据缓存**:
- 批次库存汇总 (TTL: 5分钟)
- 序列号当前状态 (TTL: 10分钟)
- 临期批次列表 (TTL: 1小时)
