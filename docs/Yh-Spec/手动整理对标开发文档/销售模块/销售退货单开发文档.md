### 表单页头部字段口径与 2 行折叠（2026-09-10 追加修复）

对照「新增销售退货单表单页」截图复核后修正两点：

1. **头部字段区只放头部字段**：头部（Zone 2）只渲染「不属于底部区域」的字段——底部区域 = 收款 Tab / 物流 Tab / 会员 Tab / 单据备注区 / 单据信息行（制单人、制单时间、打印次数、本单金额）。原先**无存档时会回退成"显示全部候选字段"**（21 个，含客户编号/开户行/银行账号/税号/部门/自定义字段1-5），现改为回退到**页面配置的默认勾选**，与截图一致：默认头部 8 个字段（客户\* / 入库仓库\* / 经手人\* / 单据日期\* / 销售类型\* + 联系人 / 联系电话 / 收货地址）。
2. **头部默认 2 行 + 展开/收起**：启用 `BillFormPage` 的 `collapsible-fields` + `:collapsed-rows="2"`（与销售退货申请同款金标准能力）。字段超 2 行时右上角出现「展开/收起」；实测 20 个字段 = 4 行 → 收起 `max-height:60px`（2 行），展开后全部显示，切换正常。

**默认勾选口径单点维护**：新增 `views/erp/column-config/saleReturnDocFormDefaults.ts`，导出 53 字段默认值、底部区域 key 集合、存储键与 `loadSaleReturnDocFieldVisibility()`；`form.vue` 与 `SaleReturnDocFormConfig.vue` 共用同一份定义，杜绝「配置里没勾的字段却显示 / 勾了的不显示」。

**显隐规则**：勾选即生效（含必填字段，不再强制保留）；误配后可用配置弹窗的「恢复默认值」一键还原。

### 数据表格列配置入口 + 空值展示字段（2026-09-10 追加修复）

3. **列配置入口只在数据表内部**：表单页原先在数据表**上方**额外挂了一个齿轮按钮（`.detail-table-header`）打开外部列配置弹窗，属多余入口。已移除该按钮与外部弹窗调用，统一用 **`BillDetailTable` 表头首列内置齿轮**（弹窗「配置」，个人配置 / 全局配置两个 Tab，含显示、显示名、宽度、拖拽排序，68 列）。实测点击表头齿轮 → 打开「配置」弹窗、69 行（68 列 + 序号）。

   - 无值时显示字段名占位，不再出现破折号；
   - 该改动在共享字段组件层，所有使用 `type='display'` 的单据表单页（采购入库/退货、库存各单、财务各单、wh 各单等 20+ 页）同步生效。
   - `return-doc/form.vue` 中「空值展示字段直接不渲染」的临时过滤已回退为按配置渲染（勾了就显示只读框）。

### 验收脚本的两条环境坑（共享开发机）

1. **含中文的 JSON 不能作为命令行参数传**：Windows 下 `execFileSync(argv)` 会按本地代码页编码，`tenantName: "系统租户"` 传到服务端会变成乱码并报「请求参数格式错误」。改为把请求体写成 UTF-8 文件后 `curl -d @file` 提交。
2. **雪花 ID 参与 SQL 必须保持字符串**：`Number("2098024881942339586")` 丢精度，清理用的 `DELETE ... WHERE id IN (...)` 会匹配不到任何行（脚本清理静默失效）。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
