# 拜访规划开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`sales/visit/plan`
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **列表查询页**：拜访计划的查询、新增、打印、导出，外勤拜访三步流程（1.拜访规划 → 2.拜访执行 → 3.拜访检视）的第一步。
- 页面结构：查询区 + 工具按钮区 + 数据表格 + 左侧部门树 + 底部分页；子标签行「拜访设置 / 拜访线路 / 拜访计划（本页）/ 任务列表」共用桌面标签「访销业务」。

## 2. 页面配置

### 查询条件（抓取 JSON filters/filterLabels 实据，8 项）

- 查询方案（--查询方案--，可新增保存复用）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止，与快捷段联动）
- 筛选条件（计划名称/编号模糊匹配）
- 职员（弹窗选择）
- 创建人（弹窗选择）
- 计划类型（下拉，默认"全部"）
- 计划状态（下拉，默认"全部"）

### 功能按钮（抓取 JSON buttons 实据）

刷新、新增、打印(F8)、导出、查询、跳转（分页）

### 打印配置

无（页面有打印(F8)按钮，打印模板配置细节待复核）。

## 3. 数据表格列配置

### 默认显示列（抓取 JSON columns 实据，9 列）

操作、职员、计划编号、计划名称、计划类型、计划拜访日期、循环拜访周期、计划状态、创建人

> 计划拜访日期列头支持排序（截图确认）；操作列内容在空数据态未展示，待复核。

### 全部可配置列

无 XSMK 全量列依据（XSMK 目录无外勤拜访域文档），列配置弹窗全量字段待复核。

## 4. 业务规范

- 计划状态字段（查询条件下拉与表格列均有）具体枚举（未开始/进行中/已结束/已停用）待复核；「计划类型」+「循环拜访周期」表明计划支持循环拜访（按周期自动生成拜访任务）。
- 左侧部门树作为表格数据的过滤维度（按所属部门筛选职员）。
- 外勤三步流程：1.拜访规划（本页，定计划）→ 2.拜访执行（职员轨迹/职员定位，地图页）→ 3.拜访检视（拜访统计/拜访记录，统计分析页）。
- 子标签「拜访设置 / 拜访线路 / 任务列表」与本页同域：拜访线路维护线路-客户绑定，任务列表承载由计划生成的拜访任务（抓取未覆盖这两页，待复核）。
- 拜访计划是拜访检视「计划内拜访」统计口径的数据来源。
- 职员、部门来源于 core-base 组织架构（SysDept / User），与系统权限体系打通。
