## 1. 页面概述

审核设置页是设置模块的**审批规则配置台**：列出**流程定义**（`workflow_definition`），支持新建（含审批节点）与查看详情（含节点明细）。对外声称「后端仅开放列表 / 详情 / 新建」，**该说明与后端事实相反** —— 后端 `WorkflowController` 的更新、发布、停用、删除 4 个端点**全部已实现**（README §7.2 已登记）。

**1.1 与相邻页的分工**

| | **审核设置（本页，80622）** | **流程定义（801）/ 流程设计（80610）** | **流程实例（802）/ 我的待办（803）** |
|---|---|---|---|

> **分工结论（现状）**：三处页面**共用同一批流程定义端点**，本页是其中**唯一按「单据 / 流程类型」维度组织**的入口。但本页与 ql361 的对标页**语义完全不同**（见 §8.1）：ql361 是「**16 类业务单据 × 审核条件 × 审批人集合**」的规则矩阵，本系统是「**流程定义台账**」。

**1.2 本页不提供的能力（如实登记）**

- ❌ 无编辑 / 停用 / 启用 / 发布 / 删除的**行内按钮**（只有「详情」）
- ❌ 无「按单据类型」的组织维度（ql361 的 16 类单据：销售出库单 / 销售订单 / 销售退货申请单 / 商城订单取消 / 采购入库单 / 采购订单 / 费用单 / 收款单 / 付款单 / 预收款单 / 预付款单 / 会计凭证 / 预订货单 / 调拨单 / 费用合同 / 调拨申请单）
- ❌ 无「审核条件 → 审批人」的**条件配置**（ql361 的「摘要」列形如「商品低于成本价时提交给[杨生淮]审核;…」）
- ❌ 无分页（`:pagination="false"`）、无 `StandardPagination`
- ❌ 无查询区网格（只有 1 个「流程类型」下拉，且**无查询 / 重置按钮**）
- ❌ 无 `PageConfigPanel`、无表头齿轮列配置、无 `storage-key` / `global-config-key`
- ❌ 无 `CategoryListLayout`
- ❌ 无权限码门控（前端零 `v-permission`；后端零方法级注解）
- ⚠️ 有「新建审批流程」，但**新建后无任何界面入口可编辑**（编辑器无路由）

### ② 后端接口清单（方法 + 路径，逐条对源码）

| 方法 | 路径 | 权限码 | 源码 |
|---|---|---|---|
| GET | `/api/workflow/audit-config/list` | `workflow:audit:list` | `backend/core/api/core-api/.../workflow/controller/WorkflowController.java` |
| PUT | `/api/workflow/audit-config/{docType}` | `workflow:audit:update` | 同上 |

要点：

- 16 类单据（行序即 ql361 页面行序）与 7 类审核条件由后端静态目录 `AuditRuleCatalog` 提供（`LinkedHashMap` 固定顺序），**前端不硬编码**，返回在 `data.list`。
- 「摘要」由**后端拼装**：`条件描述 + 时提交给[审批人,审批人]审核;`，多条直接相连；审批人姓名以 `sys_user` 现值为准、取不到回退配置快照。
- `PUT` 为**全量覆盖**语义（body `{condition, approvers:[{userId,userName}]}` 规则数组）。
- 未新增权限码以外的东西：本控制器其余端点仍仅类级 `@SaCheckLogin`（刻意不扩面）。

### ④ 仍存在的缺口（如实登记）

1. **16 类单据里只有 3 类**（销售出库单 / 销售订单 / 调拨单）拿到 ql361 的**适用条件证据**，其余 13 类无证据 → 本系统**不做按单据裁剪条件**，7 类条件对 16 类单据**统一可选**。
2. **ql361 弹窗形态无截图证据**：字段（条件 / 审批人集合）按文档描述建模，未逐像素对齐。
3. 本控制器其余约 30 个端点仍**只有类级 `@SaCheckLogin`**（无方法级权限码）；`workflow:instance:*` / `workflow:task:*` 的种子属「流程实例 / 我的待办 / 我的已办」页范围。
4. 审批人下拉走 `/user/list`，需 `system:user:list` 权限；无权限时**降级为空列表 + 提示**（功能可用性受账号权限影响）。
5. 摘要中「时提交给[审批人]审核」的文案是**后端拼装**，前端不做二次加工（两处拼字符串易各说各话，已按单一来源处理）。
