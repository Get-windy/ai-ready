## 1. 页面概述

回款统计页是**回款的三口径归集报表**：同一份底层回款数据，按人员维度（职员）与组织维度（部门）各出一个视图；每个视图的每一行给出 `单量 + 收款金额 + 预收款金额 + 预订货收款金额 + 回款总金额`，并支持从行级 `明细` 下钻到构成该行金额的单据流水。它是**销售回款考核与提成取数的口径页**。

| 页面 | 地址（ql361） | 说明 |
|------|------|------|
| 回款统计 | 分析 → 提成分析 → 回款统计 | 单入口复合页（**2 个视图 Tab**：`按职员` / `按部门`；逐 Tab 独立列配置） |

单入口：分析 → 提成分析 → 回款统计。

- 实测实据（2026-09-15）：`按职员` **7 条记录**（职员 `HC001` 杨生淮 ~ `HC017` 王昶元）；`按部门` **3 条记录**（管理部 / 客服部 / 配送部），脚本翻页控件实测 `共 3 条记录 / 每页显示 16 行`（`.png`）。

### 口径说明

- **三口径结构**：`收款金额` / `预收款金额` / `预订货收款金额` 为并列的三个来源口径，`回款总金额` 为其加总（逐行与合计均成立，见 §4）。

- **`明细` 为行级钻取**：由该行的职员/部门出发下钻到构成金额的回款单据流水；`操作` 列固定，不进列配置弹窗（基准文档记「8 列」即由此多出的 1 列）。

## 4. 业务规范

### 统计口径（三口径回款）

- **核心恒等式：`回款总金额 = 收款金额 + 预收款金额 + 预订货收款金额`**。2026-09-15 实测逐行逐合计验证**全部成立**：
  - `按部门`：`27,527.38 + 102.6 + 0 = 27,629.98` ✅；`0 + 8,055.64 + 0 = 8,055.64` ✅；`4,758.41 + 140 + 0 = 4,898.41` ✅；合计 `32,285.79 + 8,298.24 + 0 = 40,584.03` ✅。
  - `按职员`：`21,954.5 + 7,310.5 + 0 = 29,265` ✅；`5,572.88 + 359.72 = 5,932.6` ✅；`0 + 314.37 = 314.37` ✅；`154.93 + 0 = 154.93` ✅；`2,936.28 + 140 = 3,076.28` ✅；`1,667.2` ✅；`0 + 173.65 = 173.65` ✅。
- **口径含义（基准文档，部分待复核）**：
  - `收款金额` —— 收款单（`SKD-`）实收；
  - `预收款金额` —— 预收款单（`YSKD-`）新增预收，**可为负**（负值 = 预收抵扣 / 退回）；
  - `预订货收款金额` —— 预订货单（`YDHD-`）预订金；
  - `单量` —— 回款关联单据张数。
- **日期口径**：`日期类型` 默认 `单据日期`（其他可选值**待复核**）。
- **空值展示**：实测 `0` 与空单元格混用（如客服部 `收款金额 = 0`、预订货收款列整列为空/0）—— `0` 与「无数据」在展示层未区分，**待复核**是否刻意。

### 与其他页面关系

- **取数**：收款单 / 预收款单 / 预订货单（经营历程流水，按经手人 / 部门归属）。
- **上游**：`销售业绩`（其「回款总额」与本页 `回款总金额` 同口径，基准文档记统计时点/口径存在微差，**待复核**）。
- **下游**：`业务员提成`（回款提成取数）、`业绩提成中心`（按月矩阵结算）。
- **同组三页分工**：`业务员提成`＝销售侧实时计算 → `回款统计`＝回款侧三口径核算 → `业绩提成中心`＝结算闭环。

### 剩余缺口

1. **🔴 双 Tab 未落地（结构性缺口）**：对标为 `按职员` / `按部门` **2 个视图 Tab**；本页是**单视图**，靠一个 `分组维度` 下拉切换 5 个维度（含 `按业务员`、`按客户`，**对标没有这两个维度**），且**没有「按部门」维度**（`GROUP_EXPRS` 白名单无 `dept`，`CollectionStatsServiceImpl.java:31-38`）。**卡点在后端：`erp_receipt` 是否有可用的部门字段需先确认，否则「按部门」需关联单据归属，不是加一个 `groupBy` 枚举即可。**
2. **🔴 列结构整体不对齐（最大数据缺口）**：对标 7 列为 `编号 / 名称 / 单量 / 收款金额 / 预收款金额 / 预订货收款金额 / 回款总金额`（**按业务来源三口径拆分**）；本页 8 列为 `分组 / 回款笔数 / 回款金额 / 占比 / 单笔均额 / 现金回款 / 银行回款 / 其他方式`（**按支付方式三口径拆分**）。**只有「单量 ≈ 回款笔数」「回款总金额 ≈ 回款金额」两组语义近似**；`预收款金额 / 预订货收款金额` 两列本系统**完全没有**（后端 SQL 只查 `erp_receipt` 单表，**未并预收款单 / 预订货单**），而 `现金/银行/其他方式` 三列对标**没有**。
3. **无合计行（金标准必备项缺失）**：对标 `按部门` Tab 有跨页脚注级合计行（单量 / 三口径金额 / 回款总金额）；本页用 5 张 `statCards` 代替，**表格内无合计行**——`ARReportPage`/`a-table` 均无 summary 能力（`ARReportPage.vue:100-120`）。
4. **无行级 `明细` 钻取**：对标 `操作` 列可下钻到该职员/部门的回款单据流水；本页无任何行级操作。
5. **未达金标准路线 A**（如实标注）：未使用 `CategoryListLayout`/`BillDetailTable`（**无列配置齿轮**）/`StandardPagination`/`PageConfigPanel`。
6. **查询条件不对齐**：对标为 `查询方案 / 时间快捷段（8 段）/ 日期范围 / 部门（或职员）/ 日期类型 / 单据类型` + `图形`；本页仅 `分组维度 + 收款日期`。**无时间快捷段、无查询方案、无日期类型、无单据类型过滤、无图形切换**。
7. **无打印**：对标有 `打印(F8)`；本页无（`ARReportPage` 无打印能力）。
8. **无后端分页**：`normalizeResponse` 直接 `total = details.length`（`index.vue:123-126`），聚合端点一次返回全部分组，**数据量大时会全量下发**。
9. **导出为「当前页 CSV」**：`ARReportPage.vue:354-369` 拼 CSV 下载 `.csv`，**非真实 xlsx、非全量导出**。
10. **`按客户` / `按业务员` 维度的空键兜底**：`GROUP_EXPRS` 用 `COALESCE(...,'未指定')`（`CollectionStatsServiceImpl.java:36-37`），与对标按 `编号` 展示的口径**未对齐**（**待复核**）。
