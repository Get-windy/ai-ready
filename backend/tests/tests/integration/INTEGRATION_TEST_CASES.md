# 企智连系统集成测试用例

## 1. 集成测试场景分析

### 1.1 模块间交互概述
企智连系统包含多个核心模块，包括ERP（企业资源计划）和CRM（客户关系管理）模块。这些模块之间存在复杂的数据流转和业务逻辑依赖，需要通过集成测试确保各模块协同工作正常。

### 1.2 数据流转路径
- **销售流程**: CRM线索 → 商机 → 客户 → ERP销售订单 → 库存出库 → 财务应收
- **采购流程**: ERP采购需求 → 采购订单 → 库存入库 → 财务应付
- **库存同步**: ERP库存变动 → CRM产品库存展示同步
- **财务集成**: 销售/采购交易 → 财务凭证自动生成

## 2. ERP模块集成测试用例

### 2.1 销售-库存-财务集成

#### TC_ERP_001: 销售订单创建触发库存预留
**前置条件**: 
- 产品A库存数量为100
- 客户已创建

**测试步骤**:
1. 在ERP模块创建销售订单，产品A数量为20
2. 提交销售订单

**预期结果**:
- 销售订单状态为"已提交"
- 产品A的可用库存减少为80（100-20）
- 产品A的预留库存增加为20
- 财务模块生成相应的应收账款记录

#### TC_ERP_002: 销售订单发货触发库存扣减和财务确认
**前置条件**: 
- 销售订单已创建并提交
- 产品A预留库存为20

**测试步骤**:
1. 对销售订单执行发货操作
2. 确认发货完成

**预期结果**:
- 销售订单状态更新为"已发货"
- 产品A的实际库存减少为80（100-20）
- 产品A的预留库存清零
- 财务模块应收账款状态更新为"已确认"
- 生成相应的销售收入凭证

#### TC_ERP_003: 库存不足时销售订单处理
**前置条件**: 
- 产品B库存数量为5
- 客户已创建

**测试步骤**:
1. 在ERP模块创建销售订单，产品B数量为10
2. 尝试提交销售订单

**预期结果**:
- 系统提示库存不足
- 销售订单无法提交，保持草稿状态
- 库存数据未发生变化
- 财务模块无相关记录

### 2.2 采购-库存-财务集成

#### TC_ERP_004: 采购订单收货触发库存增加和应付账款
**前置条件**: 
- 供应商已创建
- 采购订单已创建

**测试步骤**:
1. 对采购订单执行收货操作
2. 确认收货完成

**预期结果**:
- 采购订单状态更新为"已收货"
- 相关产品库存数量正确增加
- 财务模块生成相应的应付账款记录
- 生成相应的采购成本凭证

## 3. CRM模块集成测试用例

### 3.1 线索-商机-客户转化

#### TC_CRM_001: 线索转化为商机
**前置条件**: 
- 线索已创建

**测试步骤**:
1. 在CRM模块将线索标记为合格
2. 执行线索到商机的转化操作

**预期结果**:
- 线索状态更新为"已转化"
- 新商机成功创建，包含线索中的关键信息
- 商机关联到正确的销售代表
- 系统记录转化时间和操作人

#### TC_CRM_002: 商机转化为客户
**前置条件**: 
- 商机已创建且状态为"赢单"

**测试步骤**:
1. 在CRM模块执行商机到客户的转化操作

**预期结果**:
- 商机状态更新为"已转化"
- 新客户档案成功创建
- 客户信息包含商机中的关键数据（联系人、需求等）
- ERP模块中自动创建对应的客户主数据
- 客户可立即用于创建销售订单

### 3.2 CRM与销售集成

#### TC_CRM_003: 从客户创建销售订单
**前置条件**: 
- 客户已在CRM和ERP中创建
- 产品库存充足

**测试步骤**:
1. 在CRM客户详情页面点击"创建销售订单"
2. 选择产品并提交订单

**预期结果**:
- 系统跳转到ERP销售订单创建页面
- 客户信息自动填充
- 订单创建成功后，CRM客户页面显示最新的订单信息
- 库存和财务数据按预期更新

## 4. 跨模块集成测试用例

### 4.1 ERP-CRM数据同步

#### TC_INTEGRATION_001: 客户主数据同步
**前置条件**: 
- CRM中存在客户A

**测试步骤**:
1. 在CRM中更新客户A的联系信息
2. 保存更改

**预期结果**:
- ERP中的客户A主数据在5分钟内自动同步更新
- 同步后的数据与CRM中完全一致
- 历史订单仍能正确关联到更新后的客户信息

#### TC_INTEGRATION_002: 产品库存同步到CRM
**前置条件**: 
- ERP中有产品X，库存为50

**测试步骤**:
1. 在ERP中执行销售出库，减少产品X库存至30
2. 在CRM产品目录中查看产品X

**预期结果**:
- CRM中产品X的可用库存显示为30
- 库存同步延迟不超过2分钟
- CRM销售人员可以看到准确的库存信息用于客户沟通

### 4.2 业务流程端到端测试

#### TC_INTEGRATION_003: 端到端销售流程
**前置条件**: 
- CRM中有合格线索
- ERP中有充足库存

**测试步骤**:
1. 将CRM线索转化为商机
2. 将商机转化为客户
3. 从客户创建销售订单
4. 执行订单发货
5. 确认收款完成

**预期结果**:
- 整个流程无缝衔接，无数据丢失或错误
- 每个步骤的状态正确传递到下一环节
- 最终财务报表反映完整的销售收入和成本
- CRM客户档案显示完整的购买历史
- 库存数据始终保持准确

#### TC_INTEGRATION_004: 异常处理和回滚
**前置条件**: 
- CRM中有客户
- ERP中产品库存不足

**测试步骤**:
1. 从CRM客户尝试创建销售订单（数量超过库存）
2. 系统提示库存不足
3. 用户修改订单数量为可用库存数量
4. 提交订单并完成发货

**预期结果**:
- 系统正确处理库存不足的异常情况
- 用户可以修正订单并继续流程
- 最终订单处理结果正确
- 无数据不一致或系统错误

## 5. 数据一致性验证

### 5.1 财务数据一致性
- 所有销售订单必须在财务模块有对应的应收账款记录
- 所有采购订单必须在财务模块有对应的应付账款记录
- 收入和成本数据在财务报表中正确汇总

### 5.2 库存数据一致性
- ERP实际库存 = 初始库存 + 采购入库 - 销售出库
- CRM显示的可用库存与ERP实际库存一致
- 预留库存计算正确，不影响其他订单处理

### 5.3 客户数据一致性
- CRM客户档案与ERP客户主数据完全同步
- 客户交易历史在两个系统中保持一致
- 客户状态变更及时同步

## 6. 测试执行说明

### 6.1 测试环境要求
- 使用完整的企智连系统环境，包含所有模块
- 数据库包含基础主数据（客户、供应商、产品等）
- 网络连接稳定，确保模块间通信正常

### 6.2 测试数据准备
- 准备测试用的客户、供应商、产品主数据
- 确保初始库存数据满足测试需求
- 创建必要的用户账号和权限配置

### 6.3 测试执行顺序
1. 先执行单模块集成测试（ERP内部、CRM内部）
2. 再执行跨模块集成测试
3. 最后执行端到端业务流程测试

### 6.4 测试结果验证
- 每个测试用例执行后，验证所有预期结果
- 记录实际结果与预期结果的差异
- 对于失败的测试用例，详细记录错误信息和截图
