## 4. 业务规范

- **发送前置（实据归纳）**：选择客户（>0 人）→ 填写或引用模板得到短信内容 → 勾选《短信协议》→「确认发送」由置灰转可用。
- **计费规则**：67 字/条，超出部分按新一条短信计费；账户剩余短信条数为配额（实测 100 条），用尽需联系客服购买——SaaS 增值计费项。
- **签名与合规**：公司签名以【】包裹强制前置；营销短信强制带「拒收请回复R」退订后缀；通知短信与营销短信分通道（营销短信受更严内容与时段管制）。
- **模板复用**：「选择短信模板」引用「短信模板管理」维护的模板；发送结果可在「短信历史」回溯（列结构待复核）。
- **与其他页面关系**：客户选择器数据源为 ERP 往来单位-客户（带移动电话的客户档案）；发送效果归入分析域「营销分析」；本系统落地对应 `/api/sms`。

1. **全局**：发送时段（不在 8:00–21:00 → 直接拒绝，错误信息指向时段）

## 本轮落地记录（2026-09-18 · 手机号展示掩码）

> **背景**：短信历史 / 退订名单 / 同意留痕 / 自动化执行台账都是**日志台账**，一页可能被截图、导出、转发，
> 明文手机号属高敏感个人信息（《个人信息保护法》最小必要原则）。
> 成熟短信平台（阿里云短信、腾讯云、有赞、微盟）的后台发送日志一律掩码。

### 口径（有意为之）

| 环节 | 是否掩码 | 理由 |
|------|---------|------|
| 存储（`mkt_sms_record.mobile` 等） | ❌ **明文** | 短信投递、退订名单匹配必须用真实号码 |
| 出参给前端（列表/台账/预览） | ✅ **掩码** | 掩码只发生在「出参那一刻」，操作员看列表不需要完整号码 |
| 按号码**搜索** | ❌ 不掩码 | 搜索走库内明文 LIKE，输入完整号码仍能定位（掩码只影响回显） |

### 落地

| 层 | 文件 | 说明 |
|----|------|------|
| 通用工具 | `core-base` `cn.aiedge.base.util.DesensitizeUtils`（**新增**） | `mobile()` 保留前 3 后 4，长度不足原样返回（不把「-」这类占位值改得面目全非） |
| 接线点 | `SmsMarketingController` | 短信历史 / 退订名单 / 同意留痕 三处分页回参加掩码 |
| 接线点 | `AutoCampaignController` | 候选会员预览 / 执行台账 两处回参加掩码 |

> 与 core-api 的 `@DataMask` 注解**分工不同、不重复**：注解版按 `sys_field_permission`
> 字段级权限动态决定是否脱敏（需配置、需角色）；`DesensitizeUtils` 用于「该字段本身就是台账性质、
> 不需要任何角色看到全文」的场景，无需配置即生效。
> ⚠️ 模块分层限制：`erp-marketing` 不依赖 `core-api`（依赖方向是 core-api → erp-marketing），
