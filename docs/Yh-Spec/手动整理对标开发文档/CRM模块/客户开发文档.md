## 1. 页面概述

CRM 客户是**客户全量池**（含公海/潜在/待跟进），用于承载**客户服务与维护**：跟进记录、拜访、分级、商机与合同归集。

| 页面 | 地址 | 组件 | 说明 |
|------|------|------|------|
| 客户列表页 | `crm/customer/index` | `views/crm/customer/index.vue`（1620 行） | 客户台账：列表视图 + **看板视图**双形态 |
| 客户表单页 | `crm/customer/form` | `views/crm/customer/form.vue`（116 行） | 新增/编辑客户（`BillFormPage` + `useBasicForm`） |

> **⚠️ 双入口方向提醒**：菜单主 `path` 指向**列表页**，标签 `添加` 指向**表单页** —— 与「报价单/发票」两页**方向相反**，勿照抄。

### 1.1 与 ERP 客户的区别（红线，必须先读）

| | **CRM 客户（本页）** | **ERP 客户（`md/customer`）** |
|---|---|---|
| 表 | `crm_customer`（53 列） | `biz_party`（`party_type = customer`） |
| 后端 | `crm` 模块 `cn.aiedge.crm.customer.CustomerController`，前缀 `/api/customer` | `erp-partner` 模块 `MdCustomerController` |
| 语义 | **全部可能客户** —— 线索转来的、公海里的、尚未成交的、正在跟进的 | **与当前租户实际发生交易的合作客户** |
| 用途 | 客户服务与维护（跟进/拜访/商机/合同/分级/流失预警） | **交易主体**：开单（销售订单/出库单/退货单）、收款、价格等级、账期、对账 |
| 能否开单 | **否** | **是** |

> **P0 红线**：业务单据的客户选择器**一律取 ERP 往来单位**（已在销售订单 `form.vue` 验证）；CRM 客户**不得**直接作为单据往来方。CRM → ERP 的落地路径是 **线索/商机转化** 或 **往来单位建档**，二者通过 `crm_erp_customer_mapping`（18 列）建映射，**不合并两张表**。

### 1.2 「客户」与「公海池」的关系

后端已具备完整公海池能力（`CustomerPoolController`，10 个端点；表 `crm_customer_pool` 30 列），**但前端无页面、`sys_menu` 无菜单** —— 用户当前**不可达**。

| 能力 | 端点 | 前端 |
|------|------|------|
| 公海分页 | `GET /api/crm/customer-pool/page` | ❌ 无 |
| 可领取列表 | `GET /api/crm/customer-pool/available` | ❌ 无 |
| 我领取的 | `GET /api/crm/customer-pool/my-claimed` | ❌ 无 |
| 我放入的 | `GET /api/crm/customer-pool/my-returned` | ❌ 无 |
| 放入公海 | `POST /api/crm/customer-pool/put/{customerId}` | ❌ 无 |
| 领取 | `POST /api/crm/customer-pool/claim/{poolId}` | ❌ 无 |
| 退回公海 | `POST /api/crm/customer-pool/return/{poolId}` | ❌ 无 |
| 自动回收 | `POST /api/crm/customer-pool/auto-recovery` | ⚠️ **桩：方法体仅打日志** |
| 过期检查 | `POST /api/crm/customer-pool/check-expired` | ❌ 无 |
| 公海统计 | `GET /api/crm/customer-pool/statistics` | ❌ 无 |

> 本页「批量分配」按钮（`#batch-actions`）语义上属**公海分配**能力，当前是**桩**（见 §7）。

### 3.2 视图形态

- 页头 `a-radio-group`（`button-style="solid"`）切换 **`列表` / `看板`**，`UnorderedListOutlined` / `AppstoreOutlined`。
- **看板视图**：按 `levelGroups` 生成 4 列（VIP客户 / 重要客户 / 普通客户 / 潜在客户）；卡片含头像（名称首字符）、名称、状态 tag（`正常`/`停用`）、`联系人:` / `电话:` / `行业:` 三行、底部「跟进」按钮；列头有等级 tag + `N 个` + 新增按钮。
- 看板数据源 `GET /api/customer/page`（`pageNum=1, pageSize=9999`），首次切换时加载并缓存到 `kanbanData`。

> **⚠️ 字段名不一致（缺陷）**：看板分组/渲染用 `c.level` / `c.name` / `c.status`，而表格列与统计卡用 `customerLevel` / `customerName` —— **同一实体两套字段名**，看板在真实数据下会分组为空。见 §7。

## 5. 业务规范

### 5.1 状态与值域

| 字段 | 值域 | 当前实现 | 问题 |
|------|------|---------|------|
| `status` | `0 正常 / 1 停用`（列表、`filterFields`、表单 A）<br>`1 正常 / 0 停用`（表单 B、`customer-grade` 页） | **两套相反语义并存** | **P0**：同一张表两条写入路径含义相反 |
| `customer_level` | `1 VIP客户 / 2 重要客户 / 3 普通客户 / 4 潜在客户` | 列表：`levelTextMap`；表单 B：`VIP/A级/B级/C级`；表单 A：`VIP客户/重要客户/普通客户/潜在客户` | **三套标签**，值一致、文案不一致 |
| `customer_type` | `1 经销商 / 2 零售商 / 3 餐饮店 / 4 其他` | 仅表单 B | — |
| `customer_source` | `1 自主开发 / 2 转介绍 / 3 网络推广 / 4 展会 / 5 其他` | 仅表单 B | 与《客户分析》页的 `1 电话营销 / 2 网络推广 / 3 客户介绍 / 4 展会活动 / 5 其他` **不一致** |
| `industry_type` | `1 食品加工 / 2 餐饮服务 / 3 批发零售 / 4 其他` | 列表 + 表单 B | 表单 A 是字符串字典（§4.1） |
| `settlement_type` | `1 现结 / 2 月结 / 3 货到付款 / 4 预付款` | 仅表单 B | 与 ERP 客户的「挂账/现结」口径不同 |

> **裁定建议（P0）**：`status` 统一为 **`1 = 正常 / 0 = 停用`**，出 Flyway 迁移按"现有语义反向订正存量行"（**不可**用 `ADD COLUMN ... DEFAULT`，PG 会回填既有行 → 语义翻转，参见《交易模块/_开发指南-金标准》陷阱 17）。

### 5.2 编码规则

- **后端生成**：`CustomerController` 在 `POST /api/customer` 时生成 `customer_code`（前端表单 A/B 的编码输入框在"新增"时均**可手填**）。
- **导入时重新生成**：`POST /api/customer/import` 对每条**重新生成编码**后 `save` —— 即**导入不保留原编码**。
- **目标规格**：统一走**号段**（`next-no`），规则形如 `CUS + yyyyMM + 4 位序号`，租户内唯一；导入保留原编码（冲突时报错而非静默重编）。

### 5.3 关键业务规则

| 规则 | 当前 | 目标 |
|------|------|------|
| 客户名称唯一性 | ❌ 无校验 | 租户内 `customer_name` 唯一（或按"名称+负责人"唯一），冲突给明确提示 |
| 手机号校验 | 表单 A 有正则；表单 B 无 | 统一（`/^1[3-9]\d{9}$/`，仅当非空时校验） |
| 跟进记录 | ✅ `POST /api/customer/{customerId}/follow`（生成 `followUpCode`） | 保留；同时允许"无跟进 N 天"触发公海回收 |
| 公海回收 | ⚠️ `auto-recovery` 是**日志桩**，无实际回收 | 实现"最后跟进时间超过 `noFollowUpDays`(默认 30) → 自动放入公海"；建议落 `XXL-Job`/调度任务（参考《调度任务模块》） |
| 信用额度校验 | ⚠️ `CustomerCreditService` 存在但**未见调用方** | 明确其消费方（CRM 侧仅**提示**；真正的**硬门控在 ERP 开单/应收**，不在 CRM） |
| 客户重复检测 | ❌ 无 | 新增时按 `customer_name` + `phone` + `tax_number` 做**疑似重复提示**（不阻断） |

### 5.5 导入（CSV 两步向导，已接线）

| 步骤 | 内容 |
|------|------|
| Step 1 `上传文件` | `a-upload` accept `.csv`，max-count 1；未上传时提示 `请先上传CSV文件` |

## 10. 验收标准（目标）

> 本模块**尚无 E2E**。以下为按金标准制定的验收清单，落地脚本命名为 `tools/e2e-crm.cjs`（界面 + 接口 + 直连 DB 对账 + 写库后复原）。

### 10.1 接口验收（目标 ≥ 20 项）

1. `GET /api/customer/page` 默认查询 200，`total` 与直查 DB 一致（**注意**：多租户 + 逻辑删条件）。
2. 分页 `pageNum/pageSize` 生效，`pageSize=1` 时 `records.length === 1`。
3. `keyword` / `customerLevel` / `status` / `customerType` / `salesPersonId` 五个过滤参数**逐个生效**（各自造数验证）。
4. `POST /api/customer` 新建后 **编码非空**、DB 可查回。
5. `PUT /api/customer/{id}` 改名后三级回读（DB / 详情 / 列表）一致。
6. `PUT /api/customer/{id}/status` 改状态后 DB 一致。
7. `DELETE /api/customer/{id}` 后列表不出现（逻辑删 `deleted`）。
8. `DELETE /api/customer/batch` 批量删。
9. `GET /api/customer/export` 返回条数与 `page` 的 `total` 一致。
10. `GET /api/customer/dropdown` 只返回 `status=1` 且 ≤ 200 条。
11. `POST /api/customer/import` 落库条数正确，编码被重编（**已知行为，需断言确认**）。
12. `POST /api/customer/{id}/follow` 生成 `followUpCode`，`GET /{id}/follows` 能查回。
13. `GET /api/customer/{id}/orders` **当前返回空数组**（断言为桩，修复后改断言）。
14. 公海池 10 端点冒烟（放入 → 领取 → 退回 → 统计）。

### 10.2 UI 验收（目标 ≥ 15 项）

1. 菜单 `CRM → 客户管理 → 客户` 点开落在**列表页**；标签 `添加` 跳到**表单页**（双入口方向校验）。
2. 页头「列表 / 看板」切换，看板 4 列**有真实数据**（分组字段已修正）。
3. 4 张等级统计卡数值 = 当前页数据聚合。
4. 表格 9 列渲染，等级/行业列显示**中文标签**而非数字。
5. 表头齿轮可改列显隐/顺序，刷新后**个人配置保留**。
6. 查询 5 项逐个生效（造数验证）。
7. 搜索框关键字生效。
8. `Ctrl+N` 打开新增表单；`F5` 刷新。
9. 新增 → 保存 → 列表出现新行（**断言网络无 4xx**）。
10. 编辑 → 保存 → 列表值更新。
11. 删除 → 确认 → 行消失。
12. 导入：未传文件提示 `请先上传CSV文件`；必填未映射提示映射错误；正常 CSV 导入成功并可查回。
13. 跟进弹窗保存后，`GET /{id}/follows` 能查回。
14. 批量选择 → 批量分配（接线后断言网络请求）。
15. 页面控制台**无 error**（含 `ReferenceError` —— 参见《重构搬迁后必须做运行时验证》）。

> 2026-09-18 更新：第 14 条「批量分配」已接线，断言改为「发出 `PUT /api/customer/{id}` 且逐行成功」；第 2 条看板分组字段已修正，可断言 4 列有真实数据；第 4 条默认可见列集合已变化（新增「负责人」等，列均已改插槽渲染），断言按现列集执行。

## 11. 配置落位

| 配置项 | 落位 | 生效 | 缺失行为 |
|--------|------|------|---------|
| 客户编码号段 | 后端号段服务（`next-no` 体系）；当前为后端硬生成 | 即时 | 编码为空 |
| 公海自动回收天数 | 目标落**调度任务模块**参数（`dms_task`/调度任务 相关配置表） | 重启/下次调度 | 不回收 |
| 列配置（个人） | 浏览器 localStorage（`storage-key`） | 即时 | 用默认列 |
| 列配置（全局） | 后端 `userPageConfigApi.save('col-config', key)` | 刷新 | 用默认列 |
| 页面配置（查询条件/按钮显隐） | localStorage（`PageConfigPanel` 的 `storage-key`） | 即时 | 用 `default-*-config` |
| 短信/营销触达（若接发短信） | 平台通知模块（见《资料模块/客户开发文档》配置落位） | 重启 | 按钮给「需配置通道」提示 |

> 统一口径见《对标开发技术参考文档》§5.6 与《配置落位总则与清单位置》。
