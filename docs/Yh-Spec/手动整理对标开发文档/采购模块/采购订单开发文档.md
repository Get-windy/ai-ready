## 实现差异说明（2026-08-29 深度复刻 + 缺陷修复）

**实现文件**：`frontend/apps/pc-admin/src/views/erp/purchase/index.vue`（列表页）、`.../form.vue`（表单页）
**后端**：`erp-purchase` 模块（`PurchaseOrderController` / 相关实体）

### 页面对齐（与文档/对标系统 cfg 抓取一致）
- **列表页**：`DocCenterLayout` 双 Tab（按单据/按明细）。按单据列配置 **39 列**、查询条件 **17 个**（含固定日期）、功能按钮 **7 个**；按明细列配置 **59 列**、查询条件 **13 个**、功能按钮 **5 个**，均已对齐文档。
- **表单页**：明细表 **57 列**（含操作/图片/商品名称/货号/条码/规格/型号/产地/区域/品牌/计价单位/可用库存/数量/换算关系/件散/大小中包装/最近采购日期/零售/批发价/单价/金额/小单位/未收/已收/成本/优惠折扣/惠后/优惠后/体积/重量/赠品/备注/8 价格等级/10 自定义字段）+ 页面配置 **35 字段** 弹窗（页面配置/录单默认值/打印设置 3 Tab），顶部基本信息 + 底部收款区（订金账户1/金额1/更多账户/此前预付/预付余额/此前欠款/预计到货/付款期限/其他费用）+ 备注区 + 单据信息 + 摘要面板（商品金额/优惠金额/本单金额）。
- **列配置弹窗** 均用 `BillDetailTable` 自带个人配置/全局配置 Tab（显隐/排序/宽度/冻结，localStorage 持久化）；页面配置用 `PageConfigPanel`。
- 后端接口：`GET next-no`（返回 `CG202608290001`）、`GET doc-query/page`、`GET detail-query/page` 均返回真实数据。

### 缺陷修复（本次）
1. **编辑回填 getById 500**：`PurchaseOrderSettlement` / `PurchaseOrderExtInfo` / `PurchaseOrderItem` 三个实体字段名与 DB 列名不一致（DB 为 `deposit_account_1`、`ext_num_1`、`custom_field_1` 等带下划线数字，实体驼峰默认映射成 `deposit_account1` 等错误列名），导致 `getById` 报"字段不存在"500。已为相关字段加 `@TableField("xxx_1")` 显式列名映射。修复后 `getById` 返回 `order/partnerSnapshot/settlement/logisticsList/deposits/extInfo/items` 嵌套 DTO，与前端 `onDetailLoaded` 映射一致。
2. **新建/编辑 400（LocalDateTime 解析失败）**：表单日期字段 `value-format="YYYY-MM-DD"`，提交 `orderDate` 为纯日期，后端字段为 `LocalDateTime` 无法解析返回 400。已在 `transformPayload` 中补全为 `fd.date + 'T00:00:00'`（`expectedReceiveTime` 同理）。实测 `POST /erp/purchase/order` 耗时返回 200。
3. **列表页按明细多出"单价状态"查询字段**（文档 13 个查询条件无此项），已移除对齐。
4. **表单页"历史"按钮跳转路径**由 `/erp/purchase` 修正为 `/purchase/order`。

### 实测结论
- `getById` 200（订单 + 嵌套 DTO 完整）；`create` 200（ISO datetime）并 `getById` 校验 + `delete` 清理；`next-no`/`doc-query`/`detail-query` 均 200 且返回真实字段。
- 后端 clean 打包需先终止运行中的 core-api 实例（其锁定 `exec.jar` 导致 maven clean 删除失败），已通过停服→非 clean `package` 覆盖方式构建成功。

## 开发原则（通用）

- **页面组件优先复用**：页面开发优先使用已有的页面组件，除非当前页面组件不满足业务需求；确无对应组件，则优先开发合适的通用组件。
- **功能/模块不重复开发**：已开发过的业务功能、单据、通用能力在全系统范围内只实现一次；其它模块直接复用，不重复开发。
- **Service 接口签名变更需同步测试**：修改 Service 接口签名（方法名/参数/返回值）时，必须同步更新对应测试类，否则会阻塞整模块的 `test-compile`。
- **阶段结束前回写开发文档**：当前阶段工作完成后、结束前，必须更新开发文档的「已完成」与「待完善」章节，使其反映当前代码的实际实现情况。
