# 待确认款项开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`finance/pending-confirm`（列表查询页）
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **列表查询页**：2 个子标签（收款待确认/预收款待确认）+ 查询区 + 可勾选数据表格 + 批量确认动作；已申报未到账款项的确认工作台。
- **单入口**：财务 → 收款 → 待确认款项。

## 2. 页面配置

### 查询条件

按抓取 JSON filterLabels 实据（往来单位、经手人）与截图确认：

- 查询方案（--查询方案--，支持保存方案）
- 时间快捷段：昨日、今日、本周、近一周、本月、上月、近三月、本年
- 日期范围（起 至 止）、往来单位、单据编号、经手人（带新增+搜索）、来源订单、配送任务编号

### 功能按钮

按抓取 JSON buttons 实据：刷新、批量确认、打印(F8)、导出、查询、跳转（分页跳转）

行级操作（截图+列实据）：操作列（确认入口，具体动作名待复核）；批量确认为表头级按钮（勾选多行后一键确认）。

### 打印配置

无（抓取数据未覆盖打印配置弹窗；有打印(F8)按钮，打印模板配置细节待复核）

## 3. 数据表格列配置

### 默认显示列（13 列，抓取 JSON columns 实据）

操作、单据日期、单据编号、往来单位、单据状态、金额、收款账户1、收款金额1、收款账户2、收款金额2、来源订单、配送任务编号、经手人

> JSON columns 首项"操作 单据日期"为抓取拼接串（首两列表头拼接），已剔除，不计入列数。

> 表格结构实据（截图）：首列行勾选框；底部"合计"行（金额、收款金额1、收款金额2 列有合计）；分页第(0/0)页 / 共 0 条记录（抓取当周无待确认数据）。

### 列口径说明（实据归纳）

- 双账户结构（收款账户1/收款金额1、收款账户2/收款金额2）：一笔款项最多两个收款账户组合到账
- 来源订单、配送任务编号两列：款项来源可追溯至商城/销售订单与配送任务（司机代收或客户线上支付后由财务确认到账）

## 4. 业务规范

### 状态流转与特殊交互

- 款项主线：业务端（订单在线支付/配送代收/转账）申报款项 → 本页"收款待确认"（预收款走"预收款待确认"）→ 财务核对银行/支付账户到账 → 确认（单行或批量）→ 款项正式入账，回写来源单据收款状态
- 未确认前款项不计入账户余额（确认动作即"到账入账"）；确认后资金口径与查资金/账户余额一致
- 单据状态列呈现款项当前状态（待确认/已确认等值域待复核）

### 与其他页面关系

- 收款侧：确认后的收款回写《按单收款开发文档》/销售单据已结算；预收确认后增加《预收款单开发文档》口径的预收余额
- 在线支付流水核对见《在线支付对账单开发文档》（流水号/关联交易号对账）
- 配送代收链路：配送任务编号关联 DMS 配送任务（司机代收）
- 本系统前端目录 `finance/pending-confirm`（dynamicRoutes.ts 实据）
