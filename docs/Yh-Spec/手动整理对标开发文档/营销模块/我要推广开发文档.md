## 1. 页面概述

「我要推广」是**推广分享的选品/选券工作台**：操作员在 6 个视图 Tab 里挑出要推广的对象，点行级「分享」把推广链接/海报发给下游客户；同时列表回显每个对象被分享与浏览的效果（最近分享时间、分享次数、浏览人数、浏览次数），用于**辅助选品**。**单入口、6 视图 Tab，无新增/编辑单据**。

| 页面 | 地址 | 说明 |
|------|------|------|
| 我要推广 | `marketing/promote-create` | 单入口复合页（6 个视图 Tab：商品 / 优惠券 / 促销 / 拼团 / 秒杀 / 我的推广；**逐 Tab 独立列配置**） |

单入口：营销 → 营销推广 → 我要推广。

### 口径说明

- **骨架口径**：5 个候选池 Tab = 「对象主体列（选品依据）+ 4 效果列（最近分享时间/分享次数/浏览人数/浏览次数）」，效果列即**推广热度**，直接服务于选品决策；`我的推广` Tab = 当前操作员**个人**的推广效果流水（无对象列，改为 `分享类型 + 分享概要` 定位对象）。
- **`操作` 列不进列配置弹窗**（每 Tab 一个固定动作列，动作恒为 `分享`）——这是基准文档「16 列」与本表「17 列」的计数差根源。
- **`我的推广` 是转化漏斗最完整的一处**：`浏览次数/浏览人数`（触达）→ `分享领取数`（领取）→ `下单人数/下单笔数/下单金额`（转化与成交额），与《推广历史查询开发文档》的 10 列台账口径**同源**（后者多 `分享人` 列，是**全公司**视角；本 Tab 是**本人**视角）。
- **商品 Tab 是唯一带左侧分类树的 Tab**（`当前路径:|全部商品` 实据），与资料域商品档案共用同一分类体系。
- **合计数**：商品 Tab 合计的是 `库存`（量），其余 Tab 合计的是效果列（次数/人数/金额）——合计口径随 Tab 主体列而变。
- **列名逐字取自 JSON**：如 `活动ID`（大写 ID，拼团 Tab）与 `活动名称` 并存；`促销商品`/`促销客户` 两列**单元格内容为「查看商品」「查看客户」链接**（列名与内容不同，非渲染错位）。

## 4. 业务规范

- **推广模型（基准文档 + 实测列实据归纳）**：
  - **5 类可推广对象**（Tab 实据）：商品、优惠券、促销、拼团、秒杀——覆盖「商城货 + 券 + 线下促销 + 商城玩法」，与营销域各页一一对应（优惠券→《优惠券开发文档》、促销→《商品促销/整单促销/特价开发文档》、拼团→《商城拼团开发文档》、秒杀→《商城秒杀开发文档》）。
  - **分享即推广**：行级 `分享`（以及顶部 `分享` 批量入口，待复核）对选中对象生成推广链接/海报（具体形态待复核），分享给下游客户产生浏览与转化。

1. **🔴 页面模型完全不同（最大缺口）**：对标是「6 视图 Tab 的分享选品台」（列表 + 行级分享 + 效果回统计），本系统是「推广活动创建表单」（12 个字段 + 创建按钮）。**两者不是同一页面**，无任何一列/一 Tab 对齐。

   - `拼团` 10/10 —— 无（`成团类型` 无来源）；

3. **表格/列配置能力全缺**：无表头齿轮列配置（6 套）、无底部合计行、无分页（`PageContainer` 内无 `StandardPagination`）。

5. **工具栏不对齐**：对标 `分享 / 推广设置 / 刷新 / 打印(F8) / 导出 / 查询 / 跳转`（待复核）；本页仅「创建活动 / 重置」。
