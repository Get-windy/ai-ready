## 页面概述

商品货位设置用于维护**商品的推荐货位**：以商品为主体，在指定仓库下为每个商品绑定推荐货位。
左侧为商品分类树，可按分类/品牌/仓库/条码/上架状态/显示状态筛选，支持「仅显示未设置货位的商品」「仅显示有库存的商品」两个复选视角。

| 页面 | 地址 | 说明 |
|------|------|------|
| 商品货位设置 | `md/location` | 商品-推荐货位 维护页（✅ 已接入真实后端） |

菜单：资料 → 仓库管理 → 商品货位设置（菜单 ID 70520 / `md:location` / `views/md/location/index.vue` / display_mode=0）。

## 业务规范说明

- **视角**：本页是**商品-推荐货位**视角（按商品设推荐货位），不是货位清单页。
- **货位层级**：仓库 → 货位（`wms_location`，`warehouse_id` 关联 `erp_warehouse.id`）。
- **货位单一口径（红线）**：货位为全局基础数据，**复用 `wms_location`，严禁另建货位表**；本页只维护「商品 × 仓库 → 货位」的绑定关系（新表 `erp_product_location`）。
- **绑定唯一性**：一个商品在一个仓库下只保留一条推荐货位绑定（部分唯一索引 `uk_epl_product_warehouse`，软删除记录不占用）。
- **仓库必填**：不选仓库不加载数据（对标仓库字段带 `*` 且校验「该值是必需的」）。

### 与对标的**有意差异**（须保留说明）

1. **未实现项**：`goodssetpoint`（设置到单位/单位+属性）、整散认定切换、库存上下限行内编辑、区域/工作区/拣货类型/单位类型查询项、批量移库、导入、默认推荐货位。
   → 这些均挂在对标**增值配置开关**下（`SupportDynamicStorePosition`、`EnableStoreDelivery`、`p_version`、`SupportMultiGoodsPosition`），本系统无对应配置项，属未引入能力，非桩。
2. **行级删除的库存校验**：对标按「货位实时库存」（`GetGoodsPositionRealqty`）阻断；本系统库存按「商品 × 仓库」维度记录，无货位维度库存，故仅做二次确认不阻断（口径差异已在此备案）。
3. **列排序**：对标商品名称/货号/仓库/推荐货位列可排序；本系统实现为**当前页本地排序**（后端未提供排序参数）。
4. **双击行设置**：对标支持，本系统仅保留操作列「设置」入口。
5. **价格等级列名**：对标为可自定义的客户价格等级名，本系统固定「价格等级1–8」（与 `erp_product_grade` 默认名一致）。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
