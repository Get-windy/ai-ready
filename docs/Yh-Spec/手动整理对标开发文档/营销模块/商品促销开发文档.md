## 1. 页面概述

商品促销是**按商品行生效的促销活动维护页**：以「促销类型 × 促销模式」描述买赠/折扣规则，定向到促销商品与促销客户，并限定线上/线下使用范围。

| 页面 | 地址 | 说明 |
|------|------|------|
| 商品促销 | `marketing/product-promo` | 单入口列表页（无独立路由、桌面多标签） |

单入口：营销 → 营销活动 → 商品促销。

- 实测实据（2026-09-15）：**共 2 条记录**；表头 13 列（见 §3）；行数据实据：
  - 行 1「裙带丝满5件赠送1件」：2026-05-07 00:00:00 ~ 2027-05-31 23:59:00，促销方式=商品促销，组合促销=否，促销类型=按商品数量，促销模式=满赠，促销规则=「订单单个促销商品数量满5.000000，赠送『亿海裙带丝』1.000000『箱』」，使用范围=线下使用，活动状态=促销中，制单人=杨生淮。
  - 行 2「海藻菜满4件赠1件」：规则「…满4.000000，赠送『亿海海藻菜』1.000000『箱』」，使用范围列横向滚动未读值（待复核）。

## 4. 业务规范

- **促销规则模型（行数据实据归纳）**：
  - 作用层级：促销方式=商品促销，按商品/明细行生效（区别于《整单促销开发文档》按整单门槛生效）。
  - 规则要素：促销类型（实测「按商品数量」）× 促销模式（实测「满赠」）→ 促销规则自然语言化：「订单单个促销商品数量满 5.000000，赠送『亿海裙带丝』1.000000『箱』」（买 N 赠 M，赠品可为同款商品）。
  - 组合促销（实测「否」）：标记本活动是否可与其他促销活动叠加。
  - 定向维度：促销商品（哪些商品参与）、促销客户（哪些客户可享受）、使用范围（线上/线下渠道）三维定向。
  - 生命周期：新增 → 起始~结束时间窗内生效（活动状态实测「促销中」）→ 过期自动失效或人工作废；「显示已过期/已作废活动」默认隐藏历史活动。
  - 「更多玩法告诉我们..」：厂商收集促销玩法需求的反馈入口，佐证促销类型/模式为可扩展枚举。
- **与其他页面关系**：与《整单促销开发文档》互补（行级 vs 单级，列结构同构实测）；与《特价开发文档》区别（特价直接改价，商品促销按规则减免/赠送）；销售开单联动（订单摘要「促销优惠」来源之一）；商城侧「我要推广」可推广促销活动；本系统落地对应 `/api/sale/promotion`。

### 当前实现

- **实现文件**：`frontend/apps/pc-admin/src/views/marketing/product-promo/index.vue`（共 347 行）
- **骨架**：`ARReportPage`（`index.vue:2-11`，`title="商品促销"`、`page-param-style="pageNum"`、`export-file-name="商品促销"`），**非**金标准路线 A（`ARReportPage` 无列配置齿轮/页面配置弹窗，见 `components/ARReportPage/ARReportPage.vue:100-120`）。
- **查询条件**：`queryFields`（`index.vue:181-190`）= 名称 `name`（input）、状态 `status`（select，选项来自 `STATUS_MAP`）——**仅 2 项**。
- **列定义**：`columns`（`index.vue:193-202`），共 **8 列**：促销名称、折扣率、促销时间（period，由 startTime~endTime 拼接，`:27-29`）、最大使用次数、每客户限次、叠加（stackable 标签，`:30-34`）、状态、操作。
- **状态映射**：`STATUS_MAP`（`index.vue:172-177`）= draft 草稿 / published 已发布 / expired 已过期 / cancelled 已取消。
- **数据请求**：`fetcher`（`index.vue:209-211`）= `promotionApi.page({ ...params, type: 'discount' })`——**固定 `type='discount'`**（折扣促销）。

- **行级操作**（`index.vue:40-66`）：编辑；`status==='draft'` 时「发布」；`status==='published'` 时「取消」；`status in (draft,cancelled)` 时「删除」。

- **数据来源**：`apps/pc-admin/src/api/marketing.ts` → `promotionApi.page/getById/create/update/remove/publish/cancel/active`（`marketing.ts:254-279`，端点 `/sale/promotion/...`）；商品下拉 `optionsApi.getProducts()`（`index.vue:330-337`）。

## 本轮落地记录（2026-09-18 · P0 促销引擎与券核销闭环）

> **背景（业界对标调研结论）**：在此之前，`SaleOrderServiceImpl.calculateAmount` 的
> `promoDiscount` / `couponAmount` **全部由前端传参**，后端不计算、不校验 ——
> 即本模块的「商品促销 / 整单促销 / 特价 / 优惠券」**配好之后不对任何单据生效**。
> 本轮补齐服务端促销引擎，口径对齐 SAP Commerce Promotion Engine / Odoo Discount & Loyalty / Dynamicweb。

### 计算口径（逐条）

| 环节 | 口径 | 业界依据 |
|------|------|---------|
| 命中判定 | 活动状态 `published` + 时间覆盖 + 使用范围（线下/商城）匹配 + 促销客户（空＝全部，雪花 id 按字符串比对） | — |
| 优先级 | `priority` 降序，**同优先级按 id 升序兜底** | SAP 明确要求避免同优先级（否则随机选择） |
| 叠加/互斥 | `stack_policy=STACK` 继续算；`EXCLUSIVE` 命中即停（更低优先级不再参与） | SAP 独占/非独占规则组 |
| 条目消耗 | 同一商品行只被**一个行级**活动（商品促销/特价）消耗，高优先级先占 | SAP Order Entry Consumption |
| 折扣计算 | 打折＝匹配行金额×(1−折扣率)；满减＝达门槛减固定额；特价＝Σ(行成交价−特价单价)×数量；满赠＝0（只登记赠品） | Odoo Reward 类型 |
| 封顶 | `max_discount_amount` 限制单条活动在本单的优惠上限 | SAP Caps |
| 分摊 | 行级优惠摊到命中行；整单级优惠按**各行金额占比**摊到每一行（末行吃舍入残差，保证合计=优惠额） | SAP / Commerce Layer 分摊法 |
| 券校验 | 状态 UNUSED + 未过期 + 属本客户 + 通道开关 + 门槛（`use_rule`） | — |
| 次数 | 试算**不累加**；只有落单才 `quota_used + 1` | — |

### 边界（如实标注）

- **满赠不自动加赠品行**：命中后只在分摊明细里登记赠品（`gift_product_id`/`gift_quantity`）+ 备注原文；
  加行涉及库存与单据一致性，由开单侧确认后处理。
- **每客户次数上限**当前按「活动总已用次数 < 每客户上限」做保守拦截（未按客户逐一聚合历史单据），
  精确口径需按客户统计 `erp_sale_order_promo_detail`，待后续补。
- **销售开单页暂未接入试算展示**：`/promotion/calc` 已就绪，开单页面板接入属销售域改动，本轮回写为待办。

### 顺带修掉的既有缺陷（跨模块，与本轮改动无关但阻断验证）

`biz_party_grade_relation`（客户等级关系）**无 `tenant_id` 列**却未登记 `IGNORE_TENANT_TABLES` →
多租户拦截器注入 `AND tenant_id = 1` → 该查询在 `getCustomerGradeCode` 的 try 里被 catch 吞掉，
但 **PostgreSQL 已把整个事务标记为 aborted** → 其后所有语句报「当前事务被终止，事务块结束之前的查询被忽略」→
**销售订单创建整体 500（整单不可用）**。
已按「同类一次收口」把资料域无 `tenant_id` 的 5 张表一并登记：
`biz_party_grade_relation`、`biz_party_address`、`biz_party_role`、`biz_party_transaction`、
`biz_customer_grade_price`（外加 `biz_migration_log`）。
