## 1. 页面概述

配送结算解决三件事：**算得准**（一单多少钱）、**算得清**（周期内谁跑了多少）、**付得出**（推给 ERP/财务出账）。

| 结算对象 | 说明 |
|---------|------|
| **配送员**（自有员工） | 计件/计时工资，进工资或费用 |
| **外部平台/众包** | 按平台账单或竞价价格，对外应付 |
| **客户**（收费侧） | 向客户收的配送费、代收货款（见《收款管理》） |

## 3. 金标准目标设计

### 3.1 计费规则（**运费规则**，当前完全缺失）

必须把费率**配置化**，建议模型：

| 维度 | 字段（建议） |
|------|-------------|
| 适用范围 | 租户 / 渠道（自有、达达、美团…）/ 线路 / 区域（围栏） |
| 计价方式 | 按单（固定）/ 按距离（起步价 + 每公里）/ 按重量 / 按体积 / 组合 |
| 基础价 | 起步价、起步里程、每公里单价、免费等待时长 |
| 加价项 | 夜间/雨天/节假日加价、超区加价、上楼费、大件费、等待费 |
| 优惠项 | 满减、月结折扣 |
| 生效期 | 生效开始/结束（支持调价留痕） |
| 结算周期 | 日结 / 周结 / 月结（自有员工与外部平台可不同） |

> ✅ **已实现（二轮，2026-09-13）**：落表 `dms_settlement_rule`（21 列）+ `/api/dms/settlement/rule/*` CRUD + 前端「计费规则」Tab（列表 + 分区卡片表单弹窗，支持按渠道/线路/生效期/优先级差异化）。
> 算费优先级：**命中启用规则（生效期内 + 适用范围匹配 + 优先级最小）→ 整体按规则计费**；未命中 → 回落《配送参数》全局缺省费率 `dms.settlement.*`（规则表为空也能算费）。
> 计价方式：按单（固定）/ 按距离 / 按重量 / 组合。规则字段（费率、计价方式、结算周期）为**完整定义**，不做字段级合并，避免歧义。

### 3.2 结算单（锁定周期，可对账）

| 环节 | 说明 |
|------|------|
| 生成 | 按周期 + 结算对象（配送员/渠道）聚合已签收任务 → 生成**结算单**（草稿） |
| 明细 | 每单挂：任务编号、签收时间、计费规则版本、费用构成 |
| 确认 | 人工复核/调整（补扣）→ 确认 |
| 推送 | 确认后推 ERP（**幂等**：同一结算单只推一次） |
| 对账 | 与渠道账单（外部平台）、与财务收款（客户侧）双向核对差异 |

### 3.5 业务规范与注意事项（**重点**）

1. **计费时点**：以**签收时间**（而非创建/派遣时间）归入结算周期，避免跨期争议；未签收/拒收单**不计费或按规则扣减**。
2. **规则版本留痕**：结算单必须记录**当时生效的规则版本**，事后调价不影响历史单。
3. **部分签收计费**：按**实际签收数量/金额**计费（依赖《签收管理》补"部分签收数量"字段），否则会按全量多算。
4. **推 ERP 幂等**：以结算单号做幂等键，重复推送不得重复生成凭证/应付。
5. **自有 vs 外部**：自有员工走工资/费用；外部平台走应付账款，**两条链路不混**；外部平台以**平台账单为准**做对账。
6. **代收货款 ≠ 配送费**：代收货款是**代客户收**的钱（进《收款管理》），配送费是**应收客户**的钱；两者在 ERP 中科目不同，严禁混记。
7. **税务合规**：对外支付的结算需可开票（外部运力），保留结算单与账单凭证。
8. **金额精度**：金额字段统一 `DECIMAL(18,2)`，分摊尾差归集到最大项（避免合计对不上）。

**规范落实对照（2026-09-13 二轮）**：

| # | 规范 | 落实 |
|---|------|------|
| 1 | 计费时点=签收时间 | 归期取 `dms_task.completed_time`（缺失回落 `update_time`），统一 `listSettleableTasks` 口径 |
| 2 | 规则版本留痕 | 结算单存 `rule_snapshot`（含规则ID/名称/费率）+ `rule_id`，调价不影响历史单 |
| 3 | 部分签收按实际数量计费 | 读 `dms_sign`（签收类型/应签收/实签收）：**部分签收系数 = min(1, 实/应)**，作用于里程费·重量费·夜间·加急，**起步价全收**；**拒收（系数 0）不计费**；审核驳回视为无效按全量 |
| 4 | 推 ERP 幂等 | 状态位（已推送直接返回原 traceId/凭证号）+ **记账幂等键**（`source_type=DMS_SETTLEMENT` + `source_id`，命中凭证明细则复用不重复记账） |
| 5 | 自有 vs 外部两条链路 | `target_type=1`（配送员）→ 贷 `2241 其他应付款`；`target_type=2`（渠道/外部运力）→ 贷 `2202 应付账款` + 生成**应付单**，链路不混 |
| 6 | 代收货款 ≠ 配送费 | 本页只处理**配送费**（成本侧）；代收货款在《收款管理》独立链路，科目/单据分离 |
| 7 | 税务合规 | 外部运力结算生成应付单（可挂发票/核销），保留结算单 + 凭证 + 应付三方可追溯 |
| 8 | 金额精度 | 全程 `BigDecimal` + `setScale(2, HALF_UP)`；单量/金额由明细逐行累加，保证「结算金额 = 明细合计」 |

## 6. 本系统落地实现（✅ 2026-09-13）

### 6.1 计费规则（配置化，消除硬编码）

| 配置键（`dms_config`，`tenant_id=0` 为全局缺省，租户可覆盖） | 缺省值 | 说明 |
|---|---|---|
| `dms.settlement.base.fee` | 5.00 | 起步价（元） |
| `dms.settlement.free.distance.km` | 0 | 免费里程（超出部分才计里程费） |
| `dms.settlement.per.km.rate` | 2.00 | 每公里单价（元/km） |
| `dms.settlement.time.surcharge.rate` | 1.50 | 夜间附加系数（22:00–06:00，按起步价倍数） |
| `dms.settlement.urgent.surcharge` | 10.00 | 加急附加费（优先级 ≥ 2，元） |

> 算费口径：`起步价 + (里程 − 免费里程) × 每公里单价 + 夜间附加 + 加急附加`；配置缺失时回落内置缺省（不会算不出费）。

**计费规则表（二轮新增，`dms_settlement_rule`）**：按 `结算对象 × 适用渠道 × 适用线路 × 生效期 × 优先级` 差异化计价，未命中回落上表缺省费率。

| 维度 | 字段 |
|------|------|
| 适用 | `target_type`（1 配送员 / 2 渠道）、`channel_id`（空=不限）、`route_id`（空=不限）、`priority`（越小越优先）、`status` |
| 计价 | `billing_type`（1 按单 / 2 按距离 / 3 按重量 / 4 组合）、`base_fee`、`free_distance_km`、`per_km_rate`、`per_kg_rate` |
| 加价 | `time_surcharge_rate`（夜间系数×起步价）、`urgent_surcharge`（优先级≥2） |
| 周期/生效 | `settle_cycle`（日/周/月结）、`effective_start`、`effective_end` |

> 匹配顺序：优先级升序 → 指定渠道者优先 → 指定线路者优先 → 新规则优先；命中即**整体**按规则计费（不做字段级合并，避免歧义）。

### 6.2 结算单闭环

```
生成（草稿 0）──确认──> 已确认（1，锁定金额）──推送 ERP──> 已推送（2，终态，幂等）
      │                        │
      └── 可删除（无留痕）       └── 不可删除（保留审计）
```

- **生成**：按「周期 + 结算对象」聚合**已签收/已完成**（status 5/6）任务；同周期同对象的**草稿会被重建**（幂等），已确认/已推送的拒绝覆盖；**结算对象必填**（配送员 / 渠道），并**排除已被已确认/已推送结算单结算过的任务**（防同一单重复计费）。
- **确认**：仅草稿可确认；重复确认被拒。
- **推送 ERP**：仅已确认可推送；**真实记账** —— 生成记账凭证（借 6602 管理费用 · 贷 2202 应付账款〔外部运力〕或 2241 其他应付款〔自有配送员〕），渠道类型另生成**应付单**；同时写 `dms_event_outbox`（`SETTLEMENT_PUSH_ERP`，payload 含单号/对象/周期/单量/金额/凭证号/应付号）作为事件载体。
- **幂等**：① 状态位——已推送直接返回原 `traceId`/凭证号/应付号；② 记账幂等键——`source_type=DMS_SETTLEMENT` + `source_id`，命中既有凭证明细则复用不重复记账（防"事务回滚但凭证已独立提交"）。
- **留痕**：结算单保存生成时的**计费规则快照**（`rule_snapshot`，命中规则时含规则ID/名称）+ `rule_id` + ERP 回执（`erp_voucher_no` / `erp_payable_id` / `erp_payable_no`），调价后可回溯历史账单。
- **部分签收**：按 `dms_sign` 签收口径折算（见 §3.5 落实对照），明细逐行留存签收类型/应签收/实签收/计费系数。

### 6.6 验收

- 脚本：`tools/e2e-dms-settlement.cjs`（**87/87**，接口 65 + UI 22），后端独立实例（`core-run-5680.jar`）实测。
- 关键断言：
  - **配置化反证**：费率取自 `dms_config`，改配置后算费随之变化（+3 元）并可还原；
  - **规则命中反证**：新增规则（按单 20 元）后算费=20 且返回 `ruleId`；停用后回落缺省（29 元）；编码重复被拒；
  - **部分签收折算**：应签收 10 / 实签收 6 → 系数 0.6，里程费与加急按系数折算、起步价全收；**拒收合计 0**；
  - **真实记账**：推送后 `finance_voucher_item` 落借贷两行（金额=结算金额，借方 6602 / 贷方 2241·2202），渠道单另落 `finance_payable`；重复推送返回同一凭证号（幂等）；
  - **渠道结算**：按 `channel_id` 聚合，对象名取渠道档案；
  - **对账**：行内含凭证号/记账状态/差异（已结 − 结算），`onlyDiff` 过滤生效；
  - **UI**：4 Tab、每 Tab 表头与列配置、按单号查询命中、规则列表中文计价方式、对账汇总卡与状态标签、运行期零接口错误。
- 截图：`tool-results/dms-settlement/{ui-list,ui-rule,ui-reconcile}.png`。
- ⚠️ **E2E 副作用治理**：推送 ERP 会过账并累加 `finance_ledger`（删除凭证不会自动回退），脚本收尾按凭证明细**精确回退分类账**，并在异常路径（`catch`）同样执行清理，保证共享库零残留。
