# 线路列表开发文档

> **对标状态：⚠️ 无对标**——ql361 无「配送」一级菜单，无此页面；本页为本系统实现的**配送路线执行单**列表，按本系统建模。
> 本系统菜单：**配送 → 线路管理 → 线路列表**（菜单ID `80700`，menu_code `dms:route-list`）
> 路由：`dms/route-list` ｜ 组件：`views/dms/route-list/index.vue` ｜ 接口：`/api/delivery/route/*`
> 关联文档：《线路开发文档》（线路**档案**主数据，二者严格区分）、《配送单开发文档》、《配送模块（DMS）开发文档》。
> 通用规范见《对标开发技术参考文档》第 4、5 章。

## 1. 页面概述

- **列表操作页**：配送路线**执行单**台账——记录「谁跑、跑到哪、开始/完成/取消」，行级可执行配送动作。
- 与《线路开发文档》的**红线区分**：

| | 线路（档案，`md:route`） | 线路列表（执行单，`dms:route-list`） |
|---|---|---|
| 表 | `erp_route` + `erp_route_area` | `erp_delivery_route` + `erp_route_point` |
| 语义 | 这条线路"是谁、覆盖哪些区域、自配还是物流" | 某次配送"谁跑、跑到哪、开始/完成/取消" |
| 生命周期 | 档案（长期） | 任务（一次性） |

> ⚠️ 两者**不重复**，但菜单命名「线路」易混淆，建议执行单侧更名为「配送路线单」以区分（见 §5 待完善）。

## 2. 页面结构（现状实测）

### 查询条件

| 查询条件 | 控件 | 说明 |
|---------|------|------|
| 配送员ID | 输入框 | ⚠️ 手输 ID，应改为配送员选择器 |
| 状态 | 下拉 | 规划中 / 待出发 / 配送中 / 已完成 / 已取消 |

### 数据表格列（11 列）

路线编号、配送员、完成进度、起点、终点、总里程、预计时长、状态、开始时间、创建时间、操作。

- **完成进度** = `已完成点位 / 总点位`（`completedPoints / totalPoints`）。
- **总里程** = `totalDistance` km；**预计时长** = `totalDuration` 分钟。
- ⚠️ 路线编号、起点、终点、总里程、预计时长**均为空数据**（无后端字段/无演示数据），需按执行单实体补齐。

### 行级操作

| 操作 | 显示条件 | 说明 |
|------|---------|------|
| 开始配送 | `status ∈ {PLANNING, READY}` | `POST /api/delivery/route/{id}/start` |
| 完成 | `status = IN_PROGRESS` | `POST /api/delivery/route/{id}/complete` |
| 取消 | `status ∉ {COMPLETED, CANCELLED}` | `POST /api/delivery/route/{id}/cancel`（二次确认） |

### 状态枚举（与后端 `RouteStatus` 一致）

`PLANNING 规划中` → `READY 待出发` → `IN_PROGRESS 配送中` → `COMPLETED 已完成` / `CANCELLED 已取消`。

## 3. 业务规范

- **执行单生命周期**：规划中 → 待出发 → 配送中 → 已完成；任意非终态可取消。
- **与配送任务的关系**：配送路线执行单（路线/点位）与配送任务（`DmsTask`，见《配送单开发文档》）是**两条并行模型**——前者面向"路线 + 点位"（`erp_route_point`），后者面向"订单 + 骑手"；本次不做合并，避免影响并行开发。
- **点位明细**：`erp_route_point` 承载路线点位（顺序/状态/到达时间），本页仅显示汇总进度，点位明细视图**待补**。
- **与线路档案的关系**：执行单当前按 `deliveryPersonId` 组织，**未引用**线路档案（`erp_route`）；接线时从 `GET /api/erp/md/route/options` 取启用线路。

## 4. 实现差异说明（本系统现状）

| 项 | 现状 | 差距 |
|----|------|------|
| 页面骨架 | `ARReportPage`（通用报表组件） | 换 `CategoryListLayout` + `BillDetailTable`（序号列齿轮） |
| 列配置 | 无（组件内置显隐） | 补表头齿轮列配置（`storage-key` = `dms-route-list-columns`）+ `PageConfigPanel` |
| 查询条件 | 配送员ID（手输）+ 状态 | 配送员选择器、路线编号、日期范围、线路（档案） |
| 列 | 11 列，含空数据列（起点/终点/里程/时长） | 按执行单实体补真实字段；补点位进度列 |
| 行操作 | 开始/完成/取消 | 补「查看点位明细」「打印路线单」；操作需二次确认 |
| 详情 | 无 | 缺点位明细抽屉/页 |
| 导出/打印 | 组件内置导出 | 导出真实 xlsx；打印接 `PrintDialog` |
| 菜单命名 | 「线路列表」与线路档案「线路」字面重复 | 建议更名「配送路线单/配送路线」 |
| 接口前缀 | `/api/delivery/route/*` | 与 `dms/*` 模块前缀不统一，需确认网关路由 |

5. **菜单更名**：`线路列表` → `配送路线单`（消除与档案「线路」的命名撞车）；父级「线路管理」→「配送路线」。
6. **导出/打印**：导出真实 xlsx；打印接 `PrintDialog`。
7. **状态与配送任务统一**：明确执行单与《配送单》（DmsTask）并存时的业务边界（建议：路线单管多点配送，配送单管单订单配送）。
