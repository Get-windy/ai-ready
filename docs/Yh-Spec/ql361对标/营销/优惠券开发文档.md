## 业务规范说明

### 状态流转与特殊交互（实据归纳）

- **数量守恒口径**（行数据实据）：总数 = 已领取（未使用）+ 已使用 + 未领取（1000 = 48 + 82 + 870）——券的三个存量池此消彼长：发放/领取使"未领取→已领取（未使用）"，核销使"已领取（未使用）→已使用"
- **发放双模式**（列实据）：开放领取=是 → 客户在商城自助领取；开放领取=否 → 仅能通过行级"发优惠券"由后台定向发放（实据行开放领取=否，操作列有"发优惠券"）
- **双使用通道**（列实据）：商城使用 / 线下使用 两列分别标记该券线上商城、线下开单是否可用（实据行券名"在线下单减5元"，通道列横向滚动未读值，待复核）
- **类型与规则**（行实据）：类型=现金券（直接抵面额）；使用规则=无限制（无门槛）；面值 5.00 元——类型枚举（现金券/折扣券/满减券等）与规则形态（满 N 可用/指定商品等）待复核
- **指定客户**（行实据"全部客户"）：券可限定客户范围，配合定向发放实现精准营销
- **生命周期**：新增（制券）→ 发放（开放领取/定向发券）→ 领取 → 使用（核销）→ 到期（按到期时间失效）；行级"作废"强制终止；"显示过期/作废优惠券"默认隐藏历史券
- **领用明细子标签**：逐券逐客户的领取/核销流水台账（子标签实据，列结构待复核）

### 与其他页面关系

- 销售开单联动：订单处理中心全部可配置列含"优惠劵"（对标系统原文用字，销售域抓取实据）；销售订单摘要结账面板含"促销优惠、优惠金额(−)"（销售域实据），优惠金额来源之一即优惠券
- 商城侧：商城营销各玩法（拼团/秒杀/预售）与券在商城下单环节叠加规则待复核；"我要推广"页可直接推广优惠券（推广域 tabs 实据含"优惠券"）
- 效果分析：分析域"营销分析 → 营销活动分析"（菜单树实据）
- 本系统落地：对应 `/api/erp/marketing/coupon`（LoyaltyCouponController，api/marketing.ts 实据）

### 客户来源

指定客户来源通过 ERP 模块的往来单位下的客户分类处理，而非 CRM 模块的客户信息。CRM客户是公海客户，ERP客户是实体客户。

## 验收标准

- 没有桩（Stub）与模拟（Mock）数据：代码中不得出现 TODO、FIXME、stub、模拟、mock、假数据、临时、演示、示例、占位、placeholder，确保使用真实数据
- 16 个默认列真实渲染；总数=已领取（未使用）+已使用+未领取 恒等；合计与分页正确
- 新增制券、行级发优惠券/作废/修改真实落库；开放领取=否的券不可被客户自助领取
- 商城使用/线下使用双通道标记真实控制线上商城与线下开单的用券校验；核销后已领取（未使用）→已使用迁移正确
- 过期券自动失效并默认隐藏，勾选"显示过期/作废优惠券"后可见；领用明细子标签流水与券汇总同源
- 券类型枚举、使用规则形态、"领用明细"列结构待复核后补充细化验收点
