## 1. 页面概述

往来余额表页是**往来域的净额总账**：以「结算单位」为行，把应收、预收、应付、预付**四个账簿**各按「期初 / 本期发生 / 期末」三列平铺（共 15 个叶子列），末组 `往来合计` 给出**债权债务对冲后的净额**；当同一单位既是客户又是供应商时，可执行**清账**（应收与应付互抵），并可从「清账历史」追溯。**单入口、单视图**（本页**无**页内视图 Tab）。

### 口径说明（多级表头归位）

- **3 个固定列**（seq 1–3，不属任何分组）：`操作`（行内 `清账` / `对账`）、`结算单位编号`、`结算单位`。
- **5 个分组表头，各下辖 3 个叶子列（期初 / 本期 / 期末）**：
  - `应收金额`：`期初应收余额`、`本期应收`、`期末应收余额`（seq 4–6）
  - `预收金额`：`期初预收金额`、`本期预收`、`期末预收金额`（seq 7–9）
  - `应付金额`：`期初应付金额`、`本期应付`、`期末应付金额`（seq 10–12）
  - `预付金额`：`期初预付金额`、`本期预付`、`期末预付金额`（seq 13–15）
  - `往来合计`：`期初余额`、`本期发生`、`期末余额`（seq 16–18）
  > 3 + 5×3 = **18**，与 `columnConfig.count` **完全吻合** ✅；基准文档「3 固定 + 5 分组 × 3 叶子 = 18」的归位**已得 JSON 证实**（不再是推算）。
- **四象限口径**：每象限独立滚动，`期末 = 期初 + 本期发生`（应收/预收/应付/预付各自成立，见下验证）。
- **往来合计（净额）**：`往来合计 = （应收金额 + 预付金额） − （预收金额 + 应付金额）` ——债权净额口径（正 = 对方欠我，负 = 我欠对方）。**实测验证见下**。

## 4. 业务规范

### 统计口径（四象限 + 净额）

- **四象限滚动**：`期末 = 期初 + 本期发生`，应收/预收/应付/预付**各自独立滚动**（实测逐行成立 ✅）。
- **往来合计（净额）**：`往来合计 = 应收金额 + 预付金额 − 预收金额 − 应付金额`（实测逐行成立 ✅）；符号方向为**正 = 对方欠我、负 = 我欠对方**（基准文档记「具体符号方向待复核」——本轮实测行 2 为 `175 − 128 = 47` 正数，与「对方欠我」一致，**该方向得证**）。
- **与《查应收》《查应付》的关系**：本页 `应收金额` 组 = 《查应收》口径、`应付金额` 组 = 《查应付》口径的**并集呈现**（同一单位四象限全量视图）；差别是本页把四账簿平铺并直接给出对冲净额，而《查应收/查应付》分别做单侧滚动。
- **清账**：同一单位既是客户又是供应商时，应收与应付可**对冲清账**（查询区勾选 `仅显示既是客户又是供应商` 即为此场景筛查）；清账历史可追溯。**黄色提示条明确「只支持对应收、应付账款清账」——即预收/预付不参与对冲**。
- **预收/预付不参与清账**（提示条实据）：四象限虽并列呈现，但清账动作只作用于 `应收金额` 与 `应付金额` 两组。

### 取数来源与上下游关系

- **取数**：《查应收》 + 《查应付》全量（应收/预收/应付/预付四账簿）；
- **下游**：清账动作回写应收应付余额；对账单输出（打印/导出）；
- **同源页**：《查应收》（客户侧单侧滚动）、《查应付》（供应商侧单侧滚动）、《销售欠款分析》（职员/区域侧欠款口径）。

1. **🔴 四象限期初/本期缺失（最大缺口）**：对标 18 列中 10 列是「期初 / 本期」（5 组 × 2），本页**一列都没有**——无法回答「本期发生了多少往来」。仅有的 4 个余额列亦非同名（对标为 `期末应收余额 / 期末预收金额 / 期末应付金额 / 期末预付金额`）。
2. **🔴 无多级表头与合计行**：对标 5 组分组表头 + 合计行（实测滚动恒等式成立）；`ARReportPage` 的 `a-table` **无分组表头、无 `summary`**。
3. **🔴 无清账能力与清账历史**：清账（应收应付对冲）是本页最核心的业务动作，本页完全缺失；查询区 3 个勾选项（含 `仅显示既是客户又是供应商` 这一清账场景筛查）亦无。基准文档所记「清账动作回写应收应付余额」在本系统**无实现**。
4. **🔴 无行级动作**：对标行内 `清账` / `对账` 均未实现（且 `ARReportPage` **未提供行级操作插槽**，需先扩组件）。
5. **🟡 净额口径未标注符号方向**：本页 `净余额` 列（`netBalance`）未在页面上说明正负含义，而对标经本轮验证为「正 = 对方欠我」（`175 − 128 = 47`）；本页净额公式（是否含预收/预付冲减）**待复核**。
6. **🟡 查询条件缺 5 类**：无查询方案、时间快捷段、日期范围、结算单位选择器、3 个勾选项；`单位类型` 二选一（客户/供应商）**无法表达「既是客户又是供应商」**这一清账场景。
7. **🟡 无打印、无清账历史**：对标两项俱全；本页仅内置 CSV 导出。
8. **🟡 主键口径不同**：本页 `row-key` 为 `${partnerType}-${partnerId}`（`:9`），说明同一单位在客户/供应商两侧**各占一行**；对标以「结算单位」为唯一行并合并四象限——**行粒度口径不同**，这是「四象限并集视图」无法直接成立的结构性原因。
9. **🟡 导出为当前页 CSV**：`ARReportPage.vue:340-371`，非真实 xlsx、仅当前页。
