## 1. 页面概述

查费用页是**费用域的多维归集账表**：四个视图 Tab 共用同一查询区，分别以「部门」「职员」「往来单位」为**矩阵列**、或以「单据」为**明细行**呈现费用归集结果。`按部门`/`按职员` Tab 左侧另有**分类树**（`当前路径:|全部`，JSON `tree` 实据），费用科目按层次展开。**单入口、四视图 Tab，逐 Tab 独立列配置**。

| 页面 | 地址 | 说明 |
|------|------|------|
| 查费用 | `analytics/check-expense` | 单入口复合页（4 个视图 Tab：按部门 / 按职员 / 按明细 / 按往来单位；逐 Tab 独立列配置） |

单入口：分析 → 财务分析 → 查费用。

- 实测实据（2026-09-15）：`按部门` 共 **4 条记录**（管理费用 6602 / 营业外支出 6711 / 销售费用 6601 / 财务费用 6603，合计 **57,272.56**）；`按职员` 共 **4 条记录**（同 4 个费用科目，合计 **57,269.53**）；`按明细` 共 **727 条记录**；`按往来单位` 共 **328 条记录**（`.png` 实据 `第 (1/17) 页`、`每页显示 20 行`）。
- **对标子分组归属**：本页属 ql361「财务分析」组下 **`资金费用`** 子分组（`.popupmenu__list-title`，**分组标题、非页面**）；同分组另有《查资金》《发票统计》。本系统 `sys_menu` **无该层级**，仅保留菜单 80454 直挂 61005。

### 口径说明（多级表头归位与矩阵口径）

- **Tab1/Tab2 为矩阵表**：`费用名称`（科目名，带文件夹图标）为行维度，`费用编号`（6601/6602/6603/6711）为科目编码，`费用金额` 为该科目**全部维度合计**；其后按部门（Tab1）/职员（Tab2）**动态展开的矩阵列**为各维度分摊额。矩阵列**由主数据动态生成、不进列配置弹窗**——这是基准文档误将其计入列数的根因，本文已订正。
- **Tab3 为单据级明细**：`金额` 为费用行金额，`科目`/`科目编号` 为费用归属科目，`记账时间` 为凭证记账日；`单据摘要/单据备注/明细摘要` 3 个文本列构成完整摘要链。
- **Tab4 为往来单位维度**：`占比(%) = 该单位费用金额 ÷ 该单位维度费用总额 × 100`——实测反推分母：`1.66 → 0.04%`（分母≈4,150）、`3.82 → 0.10%`（分母≈3,820）、`4.58 → 0.11%`（分母≈4,164），**分母非 Tab1 的 57,272.56**，故「按往来单位」Tab 的取数范围与「按部门/按职员」**不同源**，精确口径**待复核**。
- **多级表头**：本项目四 Tab **均未见分组表头**（金额为单层叶子列，矩阵列平铺）——与《经营分析》《往来余额表》的多级表头设计不同。

## 4. 业务规范

### 统计口径（费用归集矩阵）

- **费用金额 = 各维度矩阵列之和**（Tab1/Tab2 均已验证 ✅）；部门/职员列的**负值**为该维度费用红冲/退回净额。
- **科目体系实据**：`6601 销售费用`、`6602 管理费用`、`6603 财务费用`、`6711 营业外支出`——与《经营分析》支出组的「三费 + 营业外支出」**同源**（科目编码逐字一致）。
- **层次结构**：费用科目按层级呈现（父科目带子科目展开，文件夹图标）；`按部门`/`按职员` Tab 的 `tree` 字段（`当前路径:|全部`）为该层次树的路径提示。
- **包含红冲**：勾选后红冲费用单并入（负数冲减）。
- **四视图分工**：
  - `按部门`：部门维分摊矩阵（行=费用科目，列=部门）；
  - `按职员`：职员维分摊矩阵（列=职员，含 `Xxx(业务)` 形式的业务职员）；
  - `按明细`：单据级费用流水（含来源单据类型，非仅费用单）；
  - `按往来单位`：费用对象（客户/供应商）维分摊 + 占比。
- **两视图不闭合**：Tab1 销售费用比 Tab2 多 3.03 元（见上），说明**部门维含未分配职员的费用**；跨视图对账时须注意此差。

### 取数来源与上下游关系

- **取数**：费用单 / 其他支出单 + 随单费用（经手部门/经手人归属）+ 收款单/预收款单的优惠金额科目（`按明细` Tab 实测）。
- **下游**：《经营分析》支出组（三费 + 营业外支出汇总口径）。
- **同源**：财务域《费用单》、资料域《费用类型》（费用类会计科目视图）。
- **与本系统关系**：本系统后端仅提供 `/api/erp/expense/statistics/page`（按部门/按类型聚合），**无「按职员」「按往来单位」「按明细」三个维度**，见第 5 节。

- **骨架（路线 A′）**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout(:tabs) > BillDetailTable`（未传 `:max-height`）+ `StandardPagination(variant="classic")`；`PageConfigPanel` 在布局外。
- **视图 Tab**：**4 个**（`按部门 3/3` / `按职员 3/3` / `按明细 15/9` / `按往来单位 4/4`），逐 Tab 独立列配置（`analytics-check-expense-columns-<tabKey>`）。
- **行维度 = 费用科目**（对标口径）：`费用名称` = 科目名（`finance_account_subject.subject_name`，回落明细科目名/费用类型名）、`费用编号` = `item.subject_code`（回落 `expense_code`）。
- **矩阵列（对标实测：不进列配置弹窗）**：`按部门` / `按职员` 两 Tab 的部门列 / 职员列由主数据**动态生成**，
  本系统做法 —— 以 `key='checkbox'` 命中 `BillDetailTable` 的锁定列判定（渲染由 `type:'slot'` 决定，不会渲染成勾选框），
  故**列配置弹窗口径恒为 3 列**，与对标 `columnConfig.count=3 / defCount=3` 完全一致。
- **分类树**：`按部门` / `按职员` 两 Tab 左侧提供**费用科目树**（`CategoryListLayout` 的分类面板，取自当前结果集科目行，非伪造）；
  选中节点即把「科目编号」作为**服务端过滤条件**（`keyword`）重新取数，**合计随之变化**，不做前端假过滤。
- **按明细（15 列 / 默认 9）**：单据日期 / 单据编号 / 单据类型 / 往来单位 / 往来单位编号(隐) / 科目 / 科目编号(隐) / 金额 / 经手人 / 部门(隐) / 制单人 / 单据摘要(隐) / 单据备注(隐) / 明细摘要(隐) / 记账时间。
- **按往来单位（4 列 / 默认 4）**：单位编号 / 单位名称 / 费用金额 / 占比(%)（占比分母 = 本视图费用总额）。

- **状态口径**：排除已取消（`COALESCE(status,0) <> 2`）；红冲单（`red_flag = 1`）由「包含红冲」控制，**默认不并入**（与《分析模块·金标准开发指南》§6「红冲默认不入列」一致），勾选后并入（负数冲减）。
- **工具栏**：刷新 | 打印(F8) | 导出 | 页面配置（`PageConfigPanel`，5 查询项 + 3 功能按钮，默认配置双传）。
- **取数**：`/api/erp/expense/statistics/matrix|detail|partner`（**新端点**，`ExpenseAnalyticsController` + `ExpenseAnalyticsServiceImpl`）；
  既有的 `/statistics/page|summary|by-department|by-type`（费用统计：总额 / 审批状态金额）**保留未动**。
- **旧实现遗留**：原「单视图 3 列（费用类型枚举）+ 4 张审批口径指标卡」**已整体移除**（对标无指标卡、行维度亦非费用类型枚举）。
