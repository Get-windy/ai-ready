# 批次管理模块数据一致性保障方案设计

## 1. 项目概述

### 1.1 背景与目标
批次管理模块（erp-batch-sn）已实现基础功能，包含批次状态流转、序列号管理、追溯记录等核心能力。随着业务复杂度增加，数据一致性问题日益突出，需要设计完善的数据一致性保障方案。

### 1.2 设计目标
- 确保批次数据在不同模块间的一致性
- 防止因数据不一致导致的业务错误
- 提供可靠的数据同步和异常恢复机制
- 支持高并发场景下的数据一致性

## 2. 数据一致性风险分析

### 2.1 数据流分析
批次数据在ERP系统中的关键流动路径：

1. **采购模块** → **批次模块**：采购入库创建批次
2. **批次模块** → **库存模块**：批次状态更新影响库存
3. **销售模块** → **批次模块**：销售出库消耗批次
4. **质量模块** → **批次模块**：质检结果更新批次状态
5. **财务模块** → **批次模块**：成本核算依赖批次数据

### 2.2 一致性风险点识别

| 风险类别 | 风险点 | 影响程度 |
|---------|-------|---------|
| **跨模块事务** | 采购入库成功，批次创建失败 | 高 |
| **数据同步延迟** | 批次状态更新，库存未及时同步 | 中 |
| **并发冲突** | 多个用户同时修改同一批次 | 高 |
| **网络异常** | 分布式事务中断导致部分成功 | 高 |
| **系统故障** | 数据库宕机导致数据丢失 | 高 |
| **业务异常** | 业务流程中断，数据状态不一致 | 中 |

### 2.3 数据同步机制分析
当前系统存在以下同步挑战：
1. 模块间强耦合，直接数据库操作
2. 缺乏统一的事务协调机制
3. 异常处理机制不完善
4. 缺乏数据一致性监控

## 3. 一致性保障方案设计

### 3.1 总体架构

```
┌─────────────────────────────────────────────┐
│           一致性保障层（Consistency Layer）  │
├─────────────────────────────────────────────┤
│ 1. 分布式事务协调器                         │
│ 2. 数据同步中间件                          │
│ 3. 一致性校验服务                          │
│ 4. 异常恢复机制                            │
└─────────────────────────────────────────────┘
                    │
┌─────────────────────────────────────────────┐
│          业务模块层（Business Modules）      │
├─────────────────────────────────────────────┤
│ 采购模块 │ 批次模块 │ 库存模块 │ 销售模块  │
└─────────────────────────────────────────────┘
```

### 3.2 核心机制设计

#### 3.2.1 分布式事务保障
**方案选择：Seata AT模式（推荐）**
- 基于XA协议的二阶段提交
- 支持Spring Cloud Alibaba生态
- 提供全局事务ID追踪

**事务边界设计：**
```java
// 采购入库事务示例
@GlobalTransactional(timeoutMills = 30000, name = "purchase-batch-create")
public PurchaseResult createPurchaseWithBatch(PurchaseDTO purchase) {
    // 阶段1：采购订单创建
    PurchaseOrder order = purchaseService.createOrder(purchase);
    
    // 阶段2：批次创建
    BatchNumber batch = batchService.createBatch(order);
    
    // 阶段3：库存更新
    inventoryService.updateInventory(batch);
    
    return new PurchaseResult(order, batch);
}
```

#### 3.2.2 数据同步机制
**方案设计：事件驱动架构**
1. **发布-订阅模式**：批次状态变更发布事件，相关模块订阅处理
2. **最终一致性保证**：通过事件重试机制确保最终一致
3. **幂等性设计**：事件处理支持重试，避免重复操作

**事件定义示例：**
```java
public class BatchStatusChangedEvent {
    private String batchId;
    private String oldStatus;
    private String newStatus;
    private Long timestamp;
    private String operator;
    // 其他字段...
}

public class InventorySyncEvent {
    private String batchId;
    private Integer quantityChange;
    private String operationType; // IN/OUT/ADJUST
    private String referenceNo;
    // 其他字段...
}
```

#### 3.2.3 并发控制机制
**方案设计：乐观锁+分布式锁**
1. **乐观锁**：批次实体增加version字段，更新时校验
2. **分布式锁**：关键操作使用Redisson分布式锁
3. **请求限流**：高频操作接口限流保护

**乐观锁实现：**
```java
@Entity
@Table(name = "batch_number")
public class BatchNumber {
    @Id
    private String id;
    
    @Version
    private Integer version;
    
    // 其他字段...
    
    public boolean updateStatus(String newStatus) {
        // 更新时自动校验version
        this.status = newStatus;
        return true;
    }
}
```

#### 3.2.4 异常处理与恢复
**方案设计：补偿事务+重试机制**
1. **补偿事务**：正向操作失败时执行反向补偿
2. **重试机制**：网络异常等临时故障自动重试
3. **人工干预接口**：提供管理界面处理异常数据

**补偿事务示例：**
```java
@Service
public class BatchCompensationService {
    
    @Compensable(compensationMethod = "compensateCreateBatch")
    public String createBatchWithCompensation(BatchCreateRequest request) {
        // 创建批次
        return batchService.create(request);
    }
    
    public void compensateCreateBatch(BatchCreateRequest request) {
        // 补偿逻辑：删除已创建的批次
        batchService.deleteByRequest(request);
    }
}
```

### 3.3 技术实现方案

#### 3.3.1 数据库层面
1. **事务隔离级别**：READ_COMMITTED（默认）
2. **索引优化**：批次号、状态、时间字段建立复合索引
3. **数据归档**：历史批次数据定期归档，减少主表压力

#### 3.3.2 应用层面
1. **Spring事务管理**：声明式事务，统一异常处理
2. **Redis缓存**：热点批次数据缓存，减少数据库压力
3. **消息队列**：RabbitMQ/Kafka处理异步事件

#### 3.3.3 监控告警
1. **一致性监控**：定时任务检查数据一致性
2. **异常告警**：关键异常实时告警通知
3. **性能监控**：事务执行时间、成功率监控
