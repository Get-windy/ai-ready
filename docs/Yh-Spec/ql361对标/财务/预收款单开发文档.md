# 预收款单开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`finance/pre-receipt`（表单）+ `finance/pre-receipt`（列表）；另有 advance-receipt 目录，对应关系待复核
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **表单页**：先收客户货款、后抵应收的预收款登记。页面性质 = 表头结算单位字段区 + 收款账户明细表格 + 备注区 + 单据信息 + 底部金额与操作。
- **双入口**：主菜单 → `finance/pre-receipt`（表单）；标签「历史」→ `finance/pre-receipt`（列表，预收登记历史）。
- 单号实据：NO. YSKD-20260723-014（YSKD- 前缀 + YYYYMMDD-序号）。

## 2. 表单页配置

### 表头字段（抓取 JSON filterLabels + 截图确认）

- 必填：结算单位\*、经手人\*（另有单据日期\* 截图确认必填）
- 只读联动：此前预收（选定结算单位后自动带出当前预收余额）
- 赠送：本单赠送金额（充值赠送场景，随预收一并入账）

> 表头一行布局实据：结算单位\*/经手人\*/单据日期\*/此前预收（只读）/本单赠送金额。

### 全部表单字段（16 个，cfg 实据 16 字段 ✅）

编号、结算单位、客户编号、经手人、部门、单据日期、此前预收、本单赠送金额、摘要、单据备注、制单人、制单时间、打印次数、源单、源单未结金额、本单金额

### 字段分组

表头（结算单位/经手人/单据日期/此前预收/本单赠送金额）→ 收款账户明细表格 → 备注区（单据备注）→ 单据信息（制单人/制单时间/打印次数/打印记录/源单）→ 底部本单金额与操作

### 录单默认值 / 打印设置

- 经手人默认当前登录人、单据日期默认当天。
- 打印(F8)按钮及打印次数/打印记录字段存在；打印配置弹窗抓取未覆盖，打印模板配置细节待复核。

### 功能按钮（按抓取 JSON buttons 实据）

打印(F8)、历史、导出、保存草稿 Ctrl+S、记账 Ctrl+Enter

### 明细区查询条件

无（表单页无查询区）。

## 3. 数据表格列配置

### 默认显示列（抓取 JSON columns 实据，5 列）

操作、收款账户编号、收款账户、收款金额、备注

> JSON columns 首项"操作 收款账户编号 收款账户 收款金额 备注"为抓取拼接串（表头整行文本），已剔除，不计入列数。

### 列表页表格列配置（历史标签；对标系统实测 2026-08-14 抓取，29 列）

结算、单据日期、单据类型、单据编号、往来单位、结算单位编号、结算单位、收款期限、部门、仓库、总商品金额、销售金额、优惠金额、费用、运费、本单金额、代收款金额、已结算、待审金额、未结算、本次优惠、本次结算、来源订单、经手人、收货人、联系电话、收货地址、附件、单据备注

> cfg 抓取页签为「收款单」（29 结算列为按单核销网格口径），是否即预收款单列表页列待人工确认；本页表单账户明细列为 5 列（见默认显示列）。

> 双入口「历史」标签打开列表页（预收登记历史）。

## 4. 业务规范

- 保存草稿（Ctrl+S）→ 记账（Ctrl+Enter）：记账后预收款生效，结算单位"预收余额"增加（此前预收字段为记账前余额快照）
- 一单多账户：明细可填多行不同收款账户（现金/银行/微信等），本单金额=Σ收款金额
- 本单赠送金额：充值赠送场景下赠送部分计入预收余额但不计资金账户（赠送是否独立科目核算待复核）
- 预收"收→抵→退"主线之"收"：本页为预收余额的标准入口；收款单"使用预收款"为"抵"；销售退货单"退回预收款"为"退"（销售域实据）
- 下游抵扣：《收款单开发文档》使用预收款区（此前预收/可用预收/使用预收款/预收款余额）；销售出库单/零售单收款区亦可使用预收款（销售域实据）
- 账户主数据：收款账户来自资料 → 财务账户 → 银行账户
- 待确认通道：线上/代收渠道的预收款先入《待确认款项开发文档》"预收款待确认"，确认后入账
- 记账生成会计凭证（KJPZ-），总账科目实据 2203 预收账款
- 本系统前端目录 `finance/pre-receipt`、`finance/advance-receipt`（双目录对应关系待复核）
