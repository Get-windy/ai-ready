## 5. 业务规范

- **科目枚举**：`subjectType` 1 资产 / 2 负债 / 3 所有者权益 / 4 成本 / 5 损益；`direction` 1 借 / 2 贷；`level` 1-4；`isEnabled` 布尔。
- **树形规则**：`parent_id` 建树；新建下级时上级 `isLeaf` 自动转 false，删除最后一个下级后上级恢复 `isLeaf=true`；`level = 上级 level + 1`。
- **科目全名**：留空自动 = `上级科目全名 / 本科目名称`；上级改名/改编号后**自动重算全部下级**，保证链路一致。
- **科目编号**：全局唯一（含软删除外的所有科目），重复返回「科目编号已存在」。
- **删除保护**：有子科目不可删除；已被凭证分录（`finance_voucher_item.subject_id`）引用不可删除，提示改用停用。
- **核算项**：引用 `finance_auxiliary_type`（辅助核算类型：部门/项目/客户/供应商/员工）主数据，**不另建科目字典**。
- **单一口径（红线）**：全部科目数据在 `finance_account_subject`，凭证/总账/明细账/科目余额表/财务报表统一引用。

## 7. 本次修复的真实缺陷（2026-09-11，均在验收中被实测命中）

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| 1 | **新增/停用/按启用过滤全部 500** | `finance_account_subject.is_enabled / is_leaf` 建表为 `integer`，实体映射为 `Boolean` → PG 报「操作符不存在: integer = boolean」 | 迁移 V11.134.0：`DROP DEFAULT` → `TYPE boolean USING (col <> 0)` → `SET DEFAULT true` |
| 2 | **页面「新增会计科目」404** | 前端 `POST /erp/finance/subject`（无尾斜杠），后端 `@PostMapping("/")`；Spring Boot 3 不再自动匹配尾斜杠 | 改为 `@PostMapping({"", "/"})` |
| 3 | **删除科目从不生效** | 逻辑删除用 `entity.setDeletedFlag(1) + updateById`，而 MyBatis-Plus 的 `updateById` 不写 `@TableLogic` 字段 | 改 `accountSubjectMapper.deleteById(id)`；连带修复「删最后一个下级后上级未恢复叶子」 |

附带修复：
- `@OperationLog` 加在导出方法上会尝试序列化 `HttpServletResponse`（告警噪声）→ 导出方法不再打该注解（与其它模块导出一致）。
- 「核算项」清空：`updateById` 默认忽略 null 字段（`!= null` 判断同样吞掉 null）→ 清空核算项改为 `LambdaUpdateWrapper.set(..., null)` 显式置空（已补接口用例）。

## 9. 实现差异说明（本系统 vs 对标）

| 项 | 对标 | 本系统 | 原因 |
|----|------|--------|------|
| 顶层节点 | 科目树顶层 = 科目分类节点（`1 资产类`/`2 负债类`/`4 所有者权益类`/`6 损益类`），顶层行「修改/删除」禁用 | 顶层 = 真实科目；分类由左侧面板过滤 | 对标把分类做成根科目；本系统 `subject_type` 是科目字段，分类树放左侧面板（不伪造分类科目行，符合「不另建重复科目」红线） |

## 14. 本次修复（2026-09-12 · 辅助核算链路 / 核算项数据源）

**背景**：第 10 节 P2 记录 `辅助核算设置`页不可用。核算项是会计科目编辑器的字段之一，其可选项来自
`finance_auxiliary_type`；该链路不通则「核算项」只能读不能维护。本次一次性修掉同链路上的 3 个缺陷，
**未新建表/未改业务数据**，仅对齐 schema 与主键口径。

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| 1 | `/erp/finance/auxiliary/type/{list,page}`、`/item/**` 全部 500（报「字段 created_by 不存在」） | V11.37.0 建表用 `create_by / create_time / update_by / update_time / deleted`，而实体 `FinanceAuxiliaryType`/`FinanceAuxiliaryItem` 继承 finance `BaseEntity`（`created_by / created_at / updated_by / updated_at / deleted_flag`），两个 Mapper 的手写 SQL 也按 `deleted_flag` 过滤 | 迁移 **V11.166.0**：重命名 5 列对齐 `BaseEntity`（以代码口径为准，与 `finance_account_subject` 等一致）；`created_by/updated_by` 由 `bigint` 转 `varchar(64)`（实体中为 `String`） |
| 2 | 类型/项目「新增」报「null value in column "id" violates not-null constraint」 | 两表 `id BIGINT PRIMARY KEY` **无自增**（无 IDENTITY / 无默认值），而 `BaseEntity` 为 `@TableId(type = IdType.AUTO)`；`finance_account_subject`/`finance_account`/`finance_voucher` 等均为 IDENTITY | 迁移 **V11.167.0**：`ADD GENERATED BY DEFAULT AS IDENTITY`，并按 `MAX(id)` 续号（幂等） |

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
