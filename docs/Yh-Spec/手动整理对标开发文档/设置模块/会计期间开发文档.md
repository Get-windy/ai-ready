## 1. 页面概述

会计期间页是**财务日历的维护页**：定义每个会计年度的 **12 个期间**（期间号 / 起始日期 / 结账日期 / 天数），并控制每个期间的**开启 / 关闭**。使用人是**租户的财务主管**。典型使用节奏是：**年初设定 12 期 → 每月月结后关闭当期 → 年末开下一年**。

**本页是本模块内「后端最完整」的对标页**：`AccountingPeriodController`（4 端点）+ `fin_accounting_period` 表（16 列 / **24 行真实数据**）+ **权限码已落库**（`finance:period:view/create/update`，devdb 实测 3 行）。**四个页面的问题在本页都不成立**（不空、不假、有权限）。

**但本页有一个明确的架构违规**：**走「路线 B」（`ARReportPage`）—— 而该路线已在本项目明令「不再新增」**（README §3.1 / §7.2 已登记）。

### 1.1 与相邻页的分工

| | **会计期间（70570，本页）** | **月结（finance/month-closing）** |
|---|---|---|
| 管什么 | **12 期的起止日期 + 开/关** | **期间结转/关账的执行** |
| 表 | `fin_accounting_period`（**24 行**） | 月结相关表（**本文件未取证**） |
| 关系 | 本页的「关闭」状态被月结页消费（或反之） | **两条独立路径，未做联动约束**（见 §5.4） |
| 权限码 | `finance:period:view/create/update` ✅ | `finance:month-closing:execute/reopen/view` ✅（devdb 实测存在） |

> ⚠️ **本页的状态文案把「关闭」直接等同于「已月结」**（`index.vue:22-26`：`text===1 ? '开启' : '关闭（已月结）'`），但**月结模块是另一条独立路径**（`monthClosingApi`，`finance/index.ts:1130-1146`），二者**无联动约束**（§5.4 / §9.2-P1）。

| | **会计期间（70570，本页）** | **会计期间 vs 会计年度** |
|---|---|---|
| 本系统 | 表有 `period_year` + `period_month`，**可按年查询**；**无年度主数据** | 对标顶部有 `当前会计年 2026` / `当前会计期间 8` 的**只读展示** + `会计年 [2026]` **下拉切换** |
| 设计要点 | 本系统**没有「当前会计年/当前会计期间」的概念**（无字段、无页面元素） | 对标把这两个值**显式展示在顶部**（对月结、单据日期范围有直接意义） |

### 1.2 本页不提供的能力（如实登记）

- ❌ **没有「当前会计年 / 当前会计期间」的概念与展示**（对标顶部有 `当前会计年 2026` / `当前会计期间 8`）。
- ❌ **没有「按年切换 + 一次看 12 期」的矩阵视图**（对标是单年 12 行 + 底部 `保存`；本系统是**跨年分页台账**）。
- ❌ **没有「起始日期 / 结账日期 / 天数」的可编辑能力**（对标这 3 列是**可编辑的**，本系统只能由后端算/存，页面**不可改**）。
- ❌ **没有「保存」按钮**（对标底部有一个 `保存`；本系统是**逐行即时启停**）。
- ❌ **没有「天数」列**（对标有）。
- ❌ 无批量生成年度 12 期（只能逐期 `新增期间` 一次一条）。
- ❌ 无期间连续性校验（是否有缺口/重叠）、无「12 期齐备性」校验。
- ❌ 无跨页联动：不阻止「已关闭期间录凭证」（本系统其他财务页**未消费** `status`）。
- ❌ 无失败提示（创建失败与启停失败**都只 `console.warn`**，不给用户提示）。
- ❌ 无 `PageConfigPanel`、无列配置齿轮、无 `storage-key`、无 `StandardPagination`、无 `DEFAULT_QUERY_FIELDS`/`DEFAULT_FUNCTION_BUTTONS` 常量。

### 7.2 实体 `@TableName`

本页通过 `AccountingPeriodService` 间接读写；实体类**未在本次取证中定位到具体文件与行号** → **本文件不写 `@TableName` 位置**（**找不到就写未找到，不编造**）。

### 7.3 「天数」列的处理建议

对标有「天数」列，本系统**无对应列**。**建议在前端派生**：

```
天数 = end_date - start_date + 1
```

**理由**：① 它是**纯派生值**，落库违反《开发技术规范》的冗余字段纪律；② 实测数据验证该公式成立（2026-02-01 ~ 2026-02-28 → **28 天**，与对标一致）。
**本文件不承诺**新增 `days` 列。

## 10. 验收标准

> **优势（必读）**：本页**后端 4 端点全部存在、权限码已落库、库中有 24 行真实数据** → **绝大多数断言当下即可执行**，无需先建后端。
> **验收脚本落位**：`tools/e2e-settings.cjs`（设置模块**目前无任何 E2E**）。
> **写库断言纪律**：**改库 → 回读 → 按原值复原**。本页的写操作（新增期间 / 启停）**必须用专用测试年度（建议 2099）**，并在用例结束**按 id 精确删除**测试行（勿用范围删除）。
> **权限断言账号**：① 超管；② **无 `finance:period:*` 权限的普通账号**（权限码已落库 → 可断言 403）。

### 10.1 接口验收（30 项）

**A. 查询（①–⑩）**

1. `GET /api/erp/finance/period/page?page=1&size=20` → 200；`total` = `SELECT count(*) FROM fin_accounting_period WHERE tenant_id=<当前租户 and deleted_flag=0>`（基线 **24**）。
2. **`periodYear=2026` 过滤** → 断言返回 12 条；与直查 `count(*) where period_year=2026` 一致。
3. **`status=1` 过滤** → 断言返回 24 条（当前全为开启）；`status=0` → 断言 **0 条**（基线）。
4. **组合过滤** `periodYear=2026&status=1` → 断言 12 条。
5. **分页边界**：`size=1` → 1 条；`page=999` → `records=[]` 且 `total` 不变。
6. **参数类型**：`periodYear=2026`（**数字**）→ 200；`periodYear=abc` → 断言 **400**（类型转换失败）。
7. **断言分页参数名是 `page`/`size`**（非 `pageNum`/`pageSize`）→ 与 `ARReportPage` 默认 `pageParamStyle:'page'` 一致。
8. `GET /api/erp/finance/period/list?periodYear=2026`（**后端有、本页未用**）→ 200 且返回 **12 条**（**证明改造为「年度矩阵」无需新增后端**）。
9. **租户隔离**：另一租户 token → 断言看不到本租户的 24 行。
10. **断言 `fin_accounting_period` 对 `(tenant_id, period_code)` 有唯一约束**（`uk_fin_period_tenant_code`）→ 用 SQL 查 `pg_constraint` 验证。

**B. 新增（⑪–⑱）**

11. `POST /api/erp/finance/period/`（**须带尾斜杠**）传 `{periodYear:2099, periodMonth:1}` → 200；**回读 DB** 断言 `period_code='2099-01'`、`start_date='2099-01-01'`、`end_date='2099-01-31'`、`status=1`（**记录 id 以便清理**）。
12. **断言不带尾斜杠的路径 404**：`POST /api/erp/finance/period` → **404**（尾斜杠陷阱的直接证据）。
13. **闰年断言**：`{periodYear:2099, periodMonth:2}` → 断言 `end_date='2099-02-28'`；**再用闰年 `{periodYear:2100, periodMonth:2}` → 断言 `2100-02-28`**（2100 非闰年）；**`{periodYear:2104, periodMonth:2}` → `2104-02-29`**（**验证闰年算法的正确性边界**）。
14. **月份边界**：`periodMonth=1` → `start_date` 为 01-01；`periodMonth=12` → `end_date` 为 12-31。
15. **唯一约束**：重复 `POST {periodYear:2099, periodMonth:1}` → 断言**被拒（500/400）**，且 DB 仍只有 1 行（**幂等的数据库侧保障**）。
16. **非法月份**：`periodMonth=13` → 断言被拒（前端 `monthOptions` 只到 12；**后端 `@Valid` + CHECK 约束**；需实测具体错误码）。
17. **非法年份**：`periodYear=1999` → 断言被拒（若后端有值域校验）；**无校验则登记**。
18. **断言写入后产生操作日志**：`POST` 成功后 `SELECT count(*) FROM sys_oper_log WHERE module='会计期间管理' AND action='CREATE'` **+1**（`@OperationLog` 已注解）。

**C. 启停（⑲–㉔）**

19. `PUT /api/erp/finance/period/{id}/status?status=0`（用测试期间）→ 200；**回读**断言 `status=0`（**记录原值 1 以便复原**）。

21. `PUT .../status?status=1` → 断言 `status=1`（**复原**）。
22. **幂等断言**：对 `status=0` 的期间再 `PUT status=0` → **断言当前返回 200**（无状态机校验，登记 P2）。
23. **断言状态变更不影响其它列**：`period_code`/`start_date`/`end_date` 不变。
24. **断言写入操作日志**：`action='UPDATE'` +1。

**D. 权限（㉕–㉚）**

25. **无 `finance:period:view` 的账号**调 `/page` → 断言 **403**（**权限码已落库，可直接断言**）。

### ② 后端接口清单（`AccountingPeriodController`，前缀 `/api/erp/finance/period`）

| 方法 | 路径 | 权限 | 本轮 |
|---|---|---|---|
| GET | `/api/erp/finance/period/page` | `finance:period:view` | 既有 |
| GET | `/api/erp/finance/period/list` | `finance:period:view` | 既有（年度矩阵改造**无需新增后端**，本页实际走 `/list`） |
| POST | `/api/erp/finance/period/` | `finance:period:create` | 既有（**尾斜杠必需**） |
| PUT | `/api/erp/finance/period/batch-dates` | `finance:period:update` | **本轮新增**：批量保存本年度各期起止日期 |
| PUT | `/api/erp/finance/period/{id}/status` | `finance:period:update` | 既有 |

`saveDates` 服务层校验（逐条对源码）：① `id` 非空 → ② 起止日期非空 → ③ 起始不得晚于结账 → ④ 期间必须存在且属当前租户 → ⑤ **已关闭（`status = 0`）的期间拒绝修改日期**（「期间 xxx 已关闭，不可修改起止日期」）→ ⑥ 值未变化则跳过写库（幂等）。

### ③ 数据库变更

**无迁移**。12 期矩阵完全复用既有表 `fin_accounting_period`；本轮只新增一个**保守写端点**（`batch-dates`），不新增列。

### ④ 仍存在的缺口（如实登记）

1. **「当前会计年 / 当前会计期间」仍未做**：无字段、无配置、无接口（§11 已登记「需先裁定数据来源」——表字段还是从 `status` 派生，**本文件不预设**）。
2. **「关闭后不可录入 / 过账凭证」是否被凭证链路消费**：本页仍看不到消费方，承诺是否兑现**需核实凭证模块**（本文件未取证）。
3. **关闭期间无前置校验**：不检查是否有未过账凭证即允许关闭（业界一律检查）。
4. **`closed_by` / `closed_time` 的写入路径仍未验证**（库中无关闭态数据）。
5. 「关闭（已月结）」与《月结》模块为独立路径，**仍无联动**（文案已按「关闭」口径收敛，但语义歧义未根治）。
6. 表列名口径特例（`deleted_flag` / `created_at` / `updated_at` / `created_by` varchar）**未改**（改列名风险高，按原裁定只登记）。
7. `monthOptions` 仍为前端硬编码 1–12；`updateStatus` 仍无状态机校验（可对已关闭期间重复置 0 而不报错）。
