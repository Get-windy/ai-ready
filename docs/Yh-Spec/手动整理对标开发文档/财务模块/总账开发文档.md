| 页面 | 地址 | 说明 |

## 业务规范说明

- **账簿口径**：期初余额 + 本期借/贷发生 = 期末余额。
- **科目行**：按科目（含核算项）汇总，反映到期末余额。
- **来源**：会计凭证（KJPZ-）记账后入总账。
- **下钻**：选中科目行 →「明细对账」进入《明细账》该科目逐笔明细。

## 实现差异说明

**实现文件**：
- 前端：`views/finance/general-ledger/index.vue`
- API：`api/finance/index.ts`（总账查询）

### 页面对齐（已建成）
- **报表查询页**：查询（会计月起止 / 科目层级）+ 科目汇总表格（科目编码/名称/期间/摘要/借方/贷方/方向/余额）。

### 金标准升级（2026-09-10 已完成）

**前端**（`views/finance/general-ledger/index.vue`）
- 布局：`ErrorBoundary + PageContainer + CategoryListLayout`（无分类树、无底部合计条、无子 Tab）。
- 工具栏：刷新 / 打印(F8) / 导出 / 明细对账（未选行置灰）。
- 查询区（固定布局，非配置弹窗）：查询方案（存/取，localStorage）· 会计月(起) · 会计月(止) · 科目层级 · 无发生额不显示本期合计 · 显示本年累计 · 显示当前总计 · 查询。
- 数据表：`BillTableList`（`storage-key=finance-general-ledger-columns`）→ 表头 `rowNo` 内置列配置齿轮（个人/全局、上移/下移/恢复默认/保存），8 列全部默认显示：科目编码/科目名称/期间/摘要/借方/贷方/方向/余额。
- 下钻：工具栏「明细对账」或点击「科目编码」行内链接 → `/finance/detail-ledger?subjectId&dateStart&dateEnd`（明细账侧已支持读路由参数定位科目与区间）。

**后端**（`erp-finance`）
- `GET /api/erp/finance/ledger/general`：参数 `periodStart`/`periodEnd`（YYYY-MM）、`subjectLevel`（默认 1）、`hideNoAmount`、`showYearAccum`、`showCurrentTotal`、`subjectCode`（编码/名称模糊）。
  - 行结构：每科目「期初余额」行 + 「本期合计」行（跨期时逐期一行，摘要为「本期发生」）；可选「本年累计」行与末尾「当前总计」行。
  - 口径：期初 = 账簿初始期初 + 起始期间之前各期发生净额；期末 = 期初 ± 本期发生（借正贷负，方向由符号判定为 借/贷/平，余额取绝对值）。
  - 科目层级：明细科目沿 `parent_id` 上溯到第 N 级后合并（如 6604 折旧费归并至 6602 管理费用）。
  - 数据源：`finance_ledger`（凭证记账 `postToLedger` 归集），只读，无增删改。
- `GET /api/erp/finance/ledger/levels`：科目层级选项（科目字典 `level` 去重升序）。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 账簿单一口径（红线）**：总账为**只读汇总账簿**，数据唯一来源于《会计凭证》记账（KJPZ-），**严禁直接写总账/明细账**（禁止手工调账绕过凭证）。
- **P1 科目体系**：总账科目与《会计科目》（finance_account_subject）字典一致，按科目（含核算项）汇总期初+发生=期末。
- **P1 穿透**：科目行 →「明细对账」下钻《明细账》，保证凭证级可追溯。
- **P2 验收**：总账不可增删改，仅查询/导出；与明细账、科目余额表、试算平衡数据一致。

## 开发原则（通用）

- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
