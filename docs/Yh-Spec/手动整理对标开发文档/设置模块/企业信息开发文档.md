## 1. 页面概述

企业信息页是设置模块的**租户企业档案表单页**：以一张分区表单（基本信息 / 经营信息 / 联系信息）编辑「本企业」的档案，并直接写回 `sys_tenant`。
**核心事实**：15 个表单项中 **11 项永远为空**（`SysTenant` 实体根本没有那些列），**连必填的「企业名称」也存不上**（页面发 `companyName`，实体收 `tenantName`）→ **整页只有 4 个字段真正可读可写**（README §7.1-13 已登记，本文档 §3.4 / §5.2 / §7 / §9 / §12 逐条取证）。

| 项 | 值 | 证据 |
|----|-----|------|
| 页面 / 组件 | `set/company-info` / `views/set/company-info/index.vue`（**308 行**） | `sys_menu.id=80624`；`component=views/set/company-info/index.vue` |
| 外壳 | `ErrorBoundary > PageContainer`（**未传 `full-height`**）+ 一张 `.content-card` + `a-spin` + `a-form`（3 个 `a-divider` 分区） | `index.vue:2,3,4,5,6-212` |
| 后端 | `TenantController`（前缀 `/api/tenant`，**12 个端点**，类级 `@SaCheckLogin`） | `core/api/core-api/.../tenant/controller/TenantController.java:23,24` |

**1.1 与相邻页的分工**

| | **企业信息（本页，80624）** | **租户管理（系统模块，`system/tenant`）** | **系统参数（80621）** |
|---|---|---|---|
| 域 | 设置模块（`tenant-admin`） | 系统模块（`system-admin`） | 设置模块 |
| 管什么 | **本租户**的企业档案（名称 / 联系人 / 电话 / 邮箱 / 地址） | **平台方**管理所有租户（套餐 / 有效期 / 状态） | 租户的开关与枚举 |

> **分工结论（现状）**：本页与系统模块的「租户管理」**共用同一张表 `sys_tenant` 与同一个控制器**，只是各用其中一部分端点。本页只做「读一条 + 改一条」。
> **红线提示（README §1.1②）**：「两个模块不共用页面组件」—— 本页与租户管理是**不同页面组件**，符合红线；但**共用后端控制器与该表**属既有实现，本页改造时须注意与租户管理的写入口径一致（例如 `PUT /{id}` 与 `PATCH /{id}/status` 的分工）。

**1.2 本页不提供的能力（如实登记）**

- ❌ **无「纳税人信息」分区/ Tab**（ql361 的第 2 个 Tab 完全缺失：公司名称 / 纳税人识别号 / 地址 / 电话 / 开户行地址 / 开户行账号）

- ❌ 无「购买记录」类入口（属应用中心）
- ❌ 无字段级校验规则（**全页无 `a-form :rules`、无 `ref="formRef"`**）；统一社会信用代码 / 邮箱 / 电话格式**一律不校验**
- ❌ 无页面配置弹窗（无 `PageConfigPanel`）、无表头齿轮列配置（本页无表格）、无 `storage-key` / `global-config-key`
- ❌ 无 `StandardPagination`、无 `CategoryListLayout`（本页不是列表页）

- ⚠️ 有「重置」按钮，但语义实为「**重新加载**」（重新 GET），不是「恢复初始值」
- ⚠️ 有「保存」按钮，但**企业名称存不上、11 个字段不落库**（P0）

**提交 `handleSave`（`:280-295`）**

```js
if (!form.companyName) { message.warning('请输入企业名称'); return }   // :281-284（唯一校验）
const tenantId = localStorage.getItem('tenantId') || '1'                // :287

```

- 提交体是 `form` 的**全部 15 个字段**，其中 **12 个字段是 `SysTenant` 不存在的**（`companyName` / `creditCode` / `companyType` / `legalPerson` / `registeredCapital` / `industry` / `companyScale` / `establishDate` / `businessScope` / `contactPersonPhone` / `contactPersonEmail`，以及 `tenantName` 缺失）→ Spring 反序列化时**按实体字段丢弃未知属性**（Spring Boot 默认关闭 `FAIL_ON_UNKNOWN_PROPERTIES`，故**不报错**）
- **🔴 关键缺陷（P0）**：「企业名称」以 `companyName` 提交，而实体收的是 `tenantName` → **企业名称保存不了**；且 `form` 里**根本没有 `tenantName` 字段** → 实体 `tenantName` 永不被写入
- **🔴 连带缺陷（P0/P2）**：`PUT` 走 `tenantMapper.updateById(tenant)`（`TenantController.java:99`）→ MyBatis-Plus `updateById` **忽略 null 字段** → 即便用户把「联系电话」「企业地址」等 4 个可写字段**清空**，也不会写库（清空无效）；反之非空值可写
- **🟡 缺陷（P1）**：「重置」`handleResetForm` → `loadCompanyInfo()`（`:297-299`）→ 语义为「重新加载」，**不是恢复初始值**（P2 级语义偏差）

### 5.3 租户取值口径

```js
const tenantId = localStorage.getItem('tenantId') || '1'   // :252（读）、:287（写）
```

- **硬编码兜底 `1`**；`admin` 账号的 `tenant_id = 1`（devdb 实测）→ 页面加载 `id = 1`（`系统租户`）这一行
- 请求工具**额外注入请求头**：`config.headers.tenantId` 与 `config.headers['X-Tenant-Id']`（同值，`utils/request.ts:127-129`）
- → **路径参数与请求头是两套租户来源**，两者不一致时行为未定义（本次未实测）
- `sys_tenant` 在 `MyBatisPlusConfig.IGNORE_TENANT_TABLES` 中（`:33`，注释「租户表本身」）→ **多租户插件不会注入租户条件** → 本页的 `PUT /{id}` **可以改到任意租户的行**（只要知道 id）—— 结合「`system:tenant:update` 码不存在（非超管 403）」，实际风险由鉴权兜住，但**鉴权本身是缺失的**（码不存在）。

| 层 | 现状 |
|---|---|
