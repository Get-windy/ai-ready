# 账款交账开发文档

> 对标系统：22stable.ql361.com（桌面多标签，无独立路由）｜本系统路由：`finance/account-delivery`（复合页）
> 通用规范见《对标开发技术参考文档》第 4、5 章（价格等级 8 字段 / 客户来源 / 红线 / 验收）。

## 1. 页面概述

- **复合页**：列表查询页 + 统计卡片 + 双视图 Tab（按职员/按单据）+ 交账动作；职员（司机/业务员）经手款项的统一交回工作台。
- **单入口**：财务 → 收入支出 → 账款交账。

## 3. 数据表格列配置

### 默认显示列（8 个数据列 + 1 个分组表头，抓取 JSON columns 实据）

交账职员、部门、待交账单据、待交账金额、待交账收款金额（分组表头，下辖：使用预收、收款合计）、待交账优惠、待交账欠款金额

> JSON columns 首项"交账职员 部门"为抓取拼接串（首两列表头拼接），已剔除，不计入列数。"待交账收款金额"经截图核对为分组表头（跨列居中），下挂"使用预收""收款合计"两个子列，故叶子数据列共 8 个。

> 表格结构实据（截图）：首列行勾选框；底部"合计"行（各金额列合计）；分页第(0/0)页 / 共 0 条记录（抓取时段无待交账数据）。

## 4. 业务规范

### 状态流转与特殊交互

- 交账主线：职员（司机配送代收/业务员上门收款）经手收取客户款项 → 款项挂"待交账" → 财务按职员或按单据核对 → 勾选后"去交账" → 款项交回入账，职员待交账清零
- 统计卡片五档（截图实据）：待交账单据（张数）、待交账金额、待交账收款金额、待交账优惠、待交账欠款金额，与表格口径一致
- 列口径（实据归纳）：待交账金额=职员经手单据应收合计；待交账收款金额拆为 使用预收（单据中以预收抵扣部分）+ 收款合计（实际现金/转账收取部分）；待交账优惠=收款中给予客户的优惠；待交账欠款金额=交账时仍未收齐挂欠部分
- 与按单收款的衔接（页面提示实据）：按单收款页"不可选择的单据在【账款交账】中处理"——职员经手的单据在完成交账前，财务不能在按单收款中选择收款，避免职员与财务双线重复收款
- 时间快捷段含"近两日/近一月/上周"：交账高频对账场景的专用粒度（其他页无此三段）

### 与其他页面关系

- 上游：配送代收（DMS 配送任务/司机）与业务员收款——待确认款项页亦有"配送任务编号"列佐证代收链路
- 下游：交账后款项入收款账户，单据结算状态回写《按单收款开发文档》；资金可再经《提现存现转款开发文档》存行
- 本系统前端目录 `finance/account-delivery`（dynamicRoutes.ts 实据）
