## 页面概述

数据同步是**库存同步记录台账**：展示本系统与各外部渠道之间库存推送（PUSH）/拉取（PULL）/查询（QUERY）的明细与结果（成功/失败/错误信息），用于监控库存同步健康度与排查失败项。**单入口，只读列表页**，单表，无 Tab。

| 页面 | 地址 | 说明 |
|------|------|------|
| 数据同步（库存同步） | `trade/inventory-sync/list` | 只读列表页（分页） |

单入口：交易模块 → 外部平台 → 数据同步（菜单原名「库存同步」，`V9.6.4` 已更名）。

- 实测实据（本系统实现）：服务端分页列表（后端 `GET /api/trade/inventory-sync/page`）；共 **12 列可配置**（默认显示 9 / 默认隐藏 3）+ 固定列「序号」「勾选」「操作」；顶部工具栏含 刷新 / 打印(F8) / 导出 / 失败重试，右侧为「页面配置」齿轮；查询条件 **6 项**（渠道 / SKU编码 / 同步类型 / 状态 / **失败分类** / 同步时间）。
- 同步类型枚举：PUSH 推送（蓝）/ QUERY 查询（绿）/ 其余 拉取（橙）。
- 同步状态枚举：0 待同步（default）/ 1 成功（success）/ 2 失败（error）。

## 业务规范说明

- **库存同步主线**：本系统库存变更 → 推送（PUSH）到外部平台 / 从外部平台拉取（PULL）/ 外部平台查询（QUERY）→ 记录 `inventory_sync_record`。
- **同步类型**：PUSH=推送到外部平台；PULL=从外部平台拉取；QUERY=外部平台查询（`sync_type` 注释另含 PUSH/PULL/QUERY 三态，前端映射 PUSH推送/QUERY查询/其余拉取）。
- **同步状态**：0 待同步 / 1 成功 / 2 失败；实体与前端三态口径已统一（前端 `SYNC_STATUS_MAP` 同三态，原「仅二态映射」问题已修正）。
- **同步数量口径**：internalQty（内部库存）与 externalQty（外部平台库存）差异即推送/拉取的目标量 syncQty。
- **渠道归属**：`channelCode` 来自「渠道配置」页维护的渠道主数据。
- **下游**：库存查询（`queryInventory`/`batchQueryInventory`）供电商平台高频查询（带缓存 `inventory_query_cache`）；推送（`pushToChannel`/`batchPushToChannel`）供库存变更同步。

## 对标判断 / 业界标准 / 跨模块

- **对标判断（ql361 实测）**：ql361 顶栏「商城/销售/设置」菜单均无「库存同步/数据同步/渠道配置/外部订单」相关页，**ql361 未见到独立页**。ql361 的「仓储」库存相关为**进销存入库/出库单据**，与本页「外部平台库存同步记录台账」概念不同，不构成对标。
- **业界标准**：外部平台库存同步业界常采用「channel_code + sku_code + 内部/外部库存 + sync_qty + sync_type(PUSH/PULL/QUERY) + sync_status + error_msg」审计明细表，与本系统 `inventory_sync_record` 表结构一致；配合库存查询缓存表（`inventory_query_cache`）做高频查询优化，为电商平台对接通用设计。
- **跨模块**：本页 `channelCode` 对应「渠道配置」的渠道主数据；`skuCode` 对应本系统商品主数据；推送/查询走 `OpenApiController`（`/api/open/inventory/*`），库存缓存 `inventory_query_cache` 供高频查询。
- **最终裁决**：本页为**本系统独有页**，ql361 无对应，按本系统实现+业界标准描述。存在数据表（列表型），**本轮已升级为金标准列表**：`CategoryListLayout` + `BillDetailTable`（表头 rowNo 列齿轮列配置）+ `StandardPagination` + `PageConfigPanel` 页面配置；字段取自本系统实测源码，未臆造。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
