## 1. 页面概述

线索转化页是**转化工作台**：集中筛选「待转化线索」，按**4 步向导**把线索转成 CRM 客户（并声称可选创建商机）。

| 项 | 内容 |
|----|------|
| 地址 | `crm/lead-convert`（路由映射 `router/dynamicRoutes.ts:488-489`） |
| 组件 | `views/crm/lead-convert/index.vue`（**553 行**） |
| 后端 | 复用线索域端点 `/api/crm/lead/*`（`CustomerLeadController`），**本页没有专属后端** |
| 页面结构 | `PageContainer full-height` → `#header`(面包屑/标题/刷新/快捷键) → `ErrorBoundary` → 4 张统计卡 → 筛选 collapse → `BillTableList` → **4 步转化向导弹窗** |
| 与其他页关系 | 与「线索」页（`80210`）**共用同一实体与同一批端点**，只是筛选口径与转化交互不同 |

### 1.1 与「线索」页的分工

| | 线索（`80210`，双入口） | **线索转化（本页，`70311`，单入口）** |
|---|---|---|
| 定位 | 线索台账维护（含新增/编辑/删除/分配） | **只看待转化线索 + 走向导转化** |
| 统计卡 | 新线索 / 跟进中 / 已转化 / 高分线索（依 `status`+`score`） | 待转化线索 / 已转化 / 预估金额 / 转化率（依 `status`+`estimatedAmount`） |
| 转化交互 | 简易确认弹窗（2 字段只读展示） | **4 步向导**（选择线索 → 客户信息 → 创建商机 → 完成） |
| 行操作 | 查看/编辑/分配/转化/更多 | 转化（link）/ 已转化（tag） |
| 批量转化 | **桩**（不调接口） | **真实调** `leadApi.batchConvert`（但后端端点不存在 → 404） |

> **⚠️ 两页的关键差异（易误判）**：同一个「转化」动作，两页**打的是同一个端点** `POST /api/crm/lead/{id}/convert`，**没有任何客户信息参数**（见 §4.3）。

`handleConvertConfirm`（:393-423）组装了完整 `payload`：

  leadId, customerName, customerGrade, customerPhone, customerEmail,

- **`payload` 从未被使用**（全文件无第二处引用，:393-423 内除构建外无消费）→ 客户名称、客户等级、电话、邮箱、地址、是否建商机、商机名称/金额/概率/日期/阶段 **全部丢弃**。

- 后端**不创建商机**（:94-137 无 `CustomerOpportunity` 写入）。
- Step3 的副标题在勾选时显示「商机已创建」（:267）—— **与实际行为不符**（P1 误导文案）。

> **修法（P0，两端配合）**：① 后端新增 DTO（如 `LeadConvertRequest{customerName, customerGrade, customerPhone, customerEmail, customerAddress, createOpportunity, opportunityName, expectedAmount, winProbability, expectedCloseDate, opportunityStage}`）并新增 `POST /api/crm/lead/{id}/convert` 的**带体重载**（或新路径 `/convert-with-options`）；② Service 内：DTO 有值则覆盖线索取值，`createOpportunity=true` 时在同一事务内 `insert` 一条 `crm_customer_opportunity`（`customer_id/converted` 客户 id、`lead_id`、`opportunity_name`、`estimated_amount`、`probability`、`expected_close_date`、`opportunity_stage` 由 key 映射为数字）；③ 前端把 `payload` 作为请求体下发；④ 未勾选时 Step3 不显示「商机已创建」。
> **⚠️ 阶段值域**：向导用的是字符串 key（`qualification/proposal/negotiation`，:253-255），而后端商机阶段是 **Integer 1-6**（`opportunity/form.vue:44-53` 与 `opportunity-stage/index.vue:137-143` 均为数字）→ 映射表必须显式定义，否则 `opportunity_stage` 会插入字符串导致 500（见《商机开发文档》§5.1 的"三套阶段值域"）。

## 10. 验收标准（目标）

> 本模块**尚无 E2E**（`tools/` 下无 `e2e-crm*.cjs`）。

### 10.1 接口验收（转化部分 ≥ 8 项）

1. 探针：`GET /api/crm/lead/page`（登录态）返回 200（租户列问题见 §9.2 P0）。
   > 2026-09-18 更新：`tenant_id` 已由 `V11.379.0` 补列，登录态探针预期直接 200。
2. `POST /api/crm/lead/{id}/convert`（不带体）：生成 `crm_customer` 行；线索回写 `lead_status`（统一后=2）、`converted_customer_id`、`converted_time`、`actual_close_date`。
3. 同一线索**二次转化**返回 400「线索已转化」，且**不产生第二条客户**。
4. 转化后 `GET /api/customer/{id}` 的 `customer_name` = 线索 `company_name`（当前行为，改造后应 = 向导 `customerName`）。
5. **改造后**：带体转化 `createOpportunity=true` → 同一事务内生成 `crm_customer_opportunity`，其 `customer_id` = 新客户 id、`lead_id` = 线索 id、`estimated_amount`/`probability`/`expected_close_date`/`opportunity_stage`（数字）与请求体一致；线索回写照旧。
   > 2026-09-18 更新：未按此实现。仍是「先 `/{id}/convert`（无请求体）→ 再 `POST /crm/opportunity`」两步，非同一事务；商机失败不回滚客户。断言改为「转化成功且勾选时商机落库、`lead_id` 正确、失败时有如实提示」。
6. **改造后**：`createOpportunity=false` → **不产生**商机行。
   > 2026-09-18 更新：该行为已满足（前端不发起商机创建请求）。
7. `POST /api/crm/lead/batch-convert`（补齐后）：入参含 1 条未转化 + 1 条已转化 + 1 条不存在 → 断言成功 1 条、跳过 1 条、失败 1 条，且**不产生额外客户**。
   > 2026-09-18 更新：端点已补齐（逐条独立事务，返回 `successCount/failCount/failures`），本项可直接执行。
8. 写入回归后清理自产数据（脚本自带）。

### 10.2 UI 验收（≥ 12 项）

1. 菜单 `CRM → 线索管理 → 线索转化` 直达本页（单入口校验）。
2. 面包屑「线索管理」可点，跳回 `crm/lead`。
3. 造 3 条线索（新线索/跟进中/已转化各 1）→ **待转化线索 = 2、已转化 = 1、转化率 = 33%**；预估金额 = 三条之和。
4. 表格 9 列渲染，**来源列显示中文**、**预估金额列显示 `¥` 千分位**（不是 `-`）。
5. 状态列显示中文标签（不是空白）。
6. 行操作：未转化行显示「转化」，已转化行显示绿色「已转化」（当前会失效，见 §9.2）。
   > 2026-09-18 更新：字段名与判据已修，本项由「缺陷复现」转为常规回归断言。
7. 筛选：线索名称 → 生效（`keyword`）；状态 → 生效（`leadStatus`）；来源 → **改造后**生效（当前无效，须断言到具体行数）。
   > 2026-09-18 更新：来源筛选已移除，改为「查询区仅关键字/状态/等级/销售四项且逐项生效」。
8. 点击「转化」→ 向导 Step0 显示该线索的 6 项信息；未选线索时「下一步」禁用。
9. Step1 填入客户名称等 → Step2 勾选「创建商机」并填名称 → 「确认转化」→ Step3 显示成功；**断言网络请求体包含 customerName / createOpportunity 等字段**（当前请求体为空，属 P0 断言）。
   > 2026-09-18 更新：Step1 已改为只读预览（客户字段本就无法下发）；断言改为「转化请求无体 + 勾选时另发 `POST /crm/opportunity` 带商机字段」。
10. **完成后跳回列表**，「批量转化」以外的查询刷新到最新状态；库中 `crm_customer` 新增 1 行、`crm_customer_opportunity`（勾选时）新增 1 行。
