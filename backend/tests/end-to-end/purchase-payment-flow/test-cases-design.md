**前置条件**: 系统管理员登录成功

### 2.2 采购订单测试用例

#### TC-PO-001: 采购订单创建测试
**测试ID**: TC-PO-001  
**优先级**: P0  
**测试类型**: 功能测试  
**前置条件**: 存在已审核的供应商，有采购需求
```
测试步骤：
1. 点击"采购管理"→"采购订单"
2. 点击"新建采购订单"按钮
3. 选择供应商：测试供应商001
4. 添加采购明细：
   - 商品：测试商品A，数量：100，单价：50.00
   - 商品：测试商品B，数量：50，单价：80.00
5. 填写交货日期：2026-05-15
6. 点击"保存并提交审批"按钮
预期结果：
1. 采购订单创建成功，订单号自动生成
2. 订单总金额计算正确：100*50 + 50*80 = 9000.00
3. 订单状态为"待审批"
4. 审批流程自动启动
```

#### TC-PO-002: 采购订单审批流程测试
**测试ID**: TC-PO-002  
**优先级**: P0  
**测试类型**: 审批流程测试  
**前置条件**: 存在状态为"待审批"的采购订单
```
测试步骤：
1. 以审批人身份登录系统
2. 进入"我的待办"页面
3. 找到待审批的采购订单
4. 点击"审批"按钮
5. 选择"通过"选项
6. 填写审批意见："符合采购预算，同意采购"
7. 点击"确认审批"按钮
预期结果：
1. 系统提示"审批操作成功"
2. 采购订单状态更新为"已审批"
3. 审批流程记录完整
4. 订单可以进入执行阶段
```

#### TC-PO-003: 采购订单修改测试
**测试ID**: TC-PO-003  
**优先级**: P1  
**测试类型**: 数据修改测试  
**前置条件**: 存在状态为"已审批"但未执行的采购订单
```
测试步骤：
1. 进入采购订单详情页面
2. 点击"申请修改"按钮
3. 填写修改原因："供应商要求增加采购数量"
4. 修改采购明细：商品A数量从100改为120
5. 点击"提交修改申请"按钮
6. 审批人审批修改申请
预期结果：
1. 修改申请提交成功
2. 审批流程自动启动
3. 审批通过后订单明细更新
4. 订单总金额重新计算：120*50 + 50*80 = 10000.00
5. 修改历史记录完整
```

### 2.3 收货入库测试用例

#### TC-RCV-001: 收货单创建测试
**测试ID**: TC-RCV-001  
**优先级**: P0  
**测试类型**: 功能测试  
**前置条件**: 存在状态为"已发货"的采购订单
```
测试步骤：
1. 仓库管理员登录系统
2. 进入"收货管理"页面
3. 扫描或输入采购订单号
4. 系统自动加载订单明细
5. 录入实际收货数量：
   - 商品A：实际收货100件（与订单一致）
   - 商品B：实际收货50件（与订单一致）
6. 选择收货仓库：主仓库
7. 点击"确认收货"按钮
预期结果：
1. 收货单创建成功，收货单号自动生成
2. 库存数量相应增加：
   - 商品A库存增加100
   - 商品B库存增加50
3. 采购订单状态更新为"已收货"
4. 收货记录保存完整
```

#### TC-RCV-002: 收货数量差异处理测试
**测试ID**: TC-RCV-002  
**优先级**: P1  
**测试类型**: 异常处理测试  
**前置条件**: 存在状态为"已发货"的采购订单
```
测试步骤：
1. 创建收货单时录入差异数量：
   - 商品A：订单100件，实际收货95件（短缺5件）
   - 商品B：订单50件，实际收货52件（超收2件）
2. 系统自动提示数量差异
3. 选择差异处理方式："部分收货，记录差异"
4. 填写差异原因："运输过程中部分商品损坏"
5. 点击"确认收货"按钮
预期结果：
1. 系统创建收货单并记录差异
2. 库存按实际收货数量更新
3. 差异记录保存，可后续处理
4. 采购订单状态更新为"部分收货"
```

#### TC-INV-002: 发票金额不匹配处理测试
**测试ID**: TC-INV-002  
**优先级**: P1  
**测试类型**: 异常处理测试  
**前置条件**: 存在状态为"已收货"的采购订单
```
测试步骤：
1. 录入发票时填写不一致金额：
   - 订单金额：9000.00
   - 录入发票金额：9500.00（差异500元）
2. 系统自动检测金额差异
3. 差异超过阈值（5%），触发异常流程
4. 填写差异原因："包含额外运费"
5. 提交人工审核申请
预期结果：
1. 系统标记发票为"金额异常"
2. 触发人工审核流程
3. 审核人员收到待办任务
4. 审核通过后发票状态更新
```
