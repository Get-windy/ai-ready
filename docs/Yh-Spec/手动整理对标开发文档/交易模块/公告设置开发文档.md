## 业务规范说明

- **公告主线**：商城公告（商家→买家端）发布后展示在商城首页；标题 + 富文本内容。
- **发布人/发布时间**：公告列表展示发布人与发布时间；新增公告默认未发布（草稿），发布后商城端立即可见。
- **状态流转**：金标准侧为「保存草稿 → 发布」二元（发布后下线），本系统已实现 0草稿/1已发布/2已下线 三态 + 发布/下线操作。

## 实现差异说明

> 本节按当前源码回写（本轮金标准升级后）。

### 当前实现
- **实现文件**：`frontend/apps/pc-admin/src/views/mall/notice-config/index.vue`
- **骨架**：`ErrorBoundary > PageContainer(full-height) > CategoryListLayout(:tabs="[]"、:show-category-panel="false"、:show-table-footer="true") > BillDetailTable + StandardPagination(variant="classic")`；列配置齿轮挂在 `BillDetailTable` 表头 rowNo 列；工具栏经 `#toolbar-left` / `#toolbar-right`，查询区经 `#search-fields`，数据表经 `#table`，分页经 `#table-footer`。**本页无独立 `PageConfigPanel` 组件**（列配置由 BillDetailTable 表头齿轮承载）。
- **Tab**：无 Tab（`:tabs="[]"` + 隐藏分类面板；对标为单入口单视图列表页）
- **列**：共 8 列可配置（默认显示 5：公告名称、发布人、发布时间、类型、状态；默认隐藏 3：内容、排序、创建时间）；固定列：序号（`rowNo`，承载列配置齿轮）、操作（宽 200，`fixed: 'left'`）。**无多选勾选列**（源码未定义 checkbox 列）。
- **查询条件**：3 项（公告名称 `a-input`，placeholder「请输入公告名称」；类型 `a-select`，全部类型=1公告/2活动/3系统；状态 `a-select`，全部状态=0草稿/1已发布/2已下线）+「查询」按钮
- **功能按钮**：新增公告（工具栏左，橙色 `.btn-add`）；刷新、打印(F8)、导出（三者均在工具栏右）
- **行级操作**：编辑、发布（`status !== 1` 时，popconfirm）、下线（`status === 1` 时，popconfirm）、删除（popconfirm）；点击「公告名称」单元格链接亦进入编辑弹窗
- **打印(F8) / 导出**：`handlePrint()` 打开新窗口渲染打印模板（列：# / 公告名称 / 发布人 / 发布时间 / 类型 / 状态，页眉含筛选条件、打印时间、记录数）；`window.addEventListener('keydown', handleF8Key)` → F8（无 Ctrl/Alt/Meta 修饰）触发打印；`handleExport()` 为**前端 CSV 导出**（`\uFEFF` BOM 防乱码，文件名 `公告设置_YYYYMMDD.csv`，列：公告名称/发布人/发布时间/类型/状态/排序/创建时间），**无后端 xlsx 导出端点**
- **storage-key**：列配置 `mall-notice-config-table-columns`（`global-config-key` 同值）；页面配置：无（本页无 PageConfigPanel，故无页面配置 storage-key）
- **数据来源**：`apps/pc-admin/src/api/erp/mall.ts` → `mallNoticeApi`
  - `GET /erp/mall/admin/notice/page`（pageNum、pageSize、title、noticeType、status）
  - `POST /erp/mall/admin/notice`（创建，后端默认置草稿）
  - `PUT /erp/mall/admin/notice/{id}`
  - `DELETE /erp/mall/admin/notice/{id}`
  - `PUT /erp/mall/admin/notice/{id}/publish`
  - `PUT /erp/mall/admin/notice/{id}/offline`
  - （API 文件另定义 `GET /erp/mall/admin/notice/{id}` 详情，本页未调用）
- **新增/编辑弹窗字段**：公告标题（必填，限 100）、公告类型（必填，1公告/2活动/3系统）、公告内容（必填，`a-textarea` rows=5、限 500、show-count）、排序（`a-input-number`，min 0）
- **字段语义**：`status` 0草稿/1已发布/2已下线；`noticeType` 1公告/2活动/3系统（与后端 `MallNotice` 常量一致）；发布后 `publishTime` 由「发布时间」列格式化展示（`YYYY-MM-DD HH:mm`）

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
