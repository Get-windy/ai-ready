## 1. 页面概述

短信配置页是**平台运营方的短信服务商接入台账**：**左表单 + 右双卡**的三段布局（左 `a-card title="短信服务商"` 内 4 字段表单；右上方 `a-card title="短信模板"` 内 3 列裸 `a-table`；右下方 `a-card title="发送统计"` 内 **3 个 `a-statistic`**）+ **3 个按钮**（`保存配置` / `测试短信` / 行内 `编辑`）。它属于 `61306 平台设置` 组的第 3 页（`sort=300`）。

> **一句话定性**：**本页整页不可用 + 一半是假数据** —— 后端 `SmsConfigController` 所在包 `cn.aiedge.platform` **不在** `AiReadyScanPackages` → **3 个端点从未装配、运行期全部 404**；前端另加调**两个后端根本不存在**的端点（`GET /api/sms/templates`、`GET /api/sms/stats`）→ **5 个请求 100% 失败、全部被 `catch` 静默吞掉**；而「发送统计」的三张卡片**代码里就写死为 `0 / 0 / 0%`**（`:140-144`）→ 「**看起来有指标、实际全是假数据**」。

### 8.4 明确不借鉴

| 不借鉴 | 理由 |
|--------|------|
| SAP 的「一个 SMTP 节点同时承载邮件/传真/短信 + 地址转换域名」 | 本系统无传真通道；短信已有独立页与独立表；引入地址转换域名会带来一个**本系统无人维护**的抽象层 |
| 阿里云控制台的整套"资质 → 签名 → 模板 → 报备"**申请审批流** | 本系统是**使用方**而非**服务商**；把服务商的审批流搬进自己的系统不现实 → **只做"状态登记 + 提示"**，实际申请仍在云厂商控制台完成 |
| 把「上行短信查询」做进系统 | 官方明确**暂不支持** API / 控制台查询上行短信；本系统不必为此设计 |
| 把"短信 = SMTP 节点的一种通信方式"的模型照搬 | 本系统短信与邮件是完全独立的两个通道，各自有 SDK 与凭据 |

### 11.1 必须写清的「通道判别」事实（《对标开发技术参考文档》§5.6.2 硬规则）

1. **模块自带 yml 不生效**：若把 `notification.sms.*` 写进 `core/notification` 或任何**模块自带**的 `src/main/resources/*.yml`（位于嵌套 jar 内），**core-api 启动时不会加载**（Spring Boot 只读 classpath 根那一份）→ **必须写到 core-api 的 `application.yml`**（或 `application-{profile}.yml` / 启动参数 / 外部化文件）。
   **本页现状**：该键**连 core-api yml 都没进**（§5.6.3 已登记「未在 yml 声明，需补」）→ 只能靠环境变量，**拼写必须严格**（relaxed binding：`notification.sms.enabled` ⇔ `NOTIFICATION_SMS_ENABLED`）。
2. **前端 `VITE_*` 是构建期注入**：本页**未使用** → 无需 CI 注入；代价是**任何前端改动（三卡、按钮接线、校验、loading 缺陷）都属前端改动 → 必须 rebuild 才生效**。
3. **密钥优先不入库**：`sys_sms_config.access_key` / `access_secret` 是明文列 —— 能用环境变量/Secret 的**绝不写进表**；确需页面维护的，按通道 ④ 落库，并遵循「**脱敏展示 + 仅授权角色可见 + 日志不打印**」（本页日志侧**已做到不打印**，其余两项**均未做到**）。
4. **必须有降级**：配置缺失时**不得阻塞业务**。当前 `notification.sms.*` 缺失 → 短信通道不可用（明确失败）；**但本页不可作为兜底**（未接线）→ 表现为「用户在页面上配了也没用」。
   **⚠️ 特别提醒**：**频控缺失属于"看起来降级了、实际会被运营商拦截"** —— 这类"上游硬约束"必须**本地也做**（不能依赖"发出去再说"）。
5. **换配置要能生效**：本页**当前无生效方式**（无消费方）。目标形态有两种，**须先裁定**：
   - **路线 A**：保持 `notification.sms.*` 为唯一真源（**推荐**，与邮件页口径一致）→ 本页应改成**只读诊断页**（显示当前生效的 provider / 签名 / 是否配置，**不回显明文**）；
   - **路线 B**：让 `SmsChannel` 改读 `sys_sms_config`（热生效）→ 需补**缓存失效机制**（保存后发领域事件 + 消费方失效本地缓存，多实例 TTL 兜底），并**显式豁免租户插件**（§11.1-6）。
6. **多租户读全局默认行**：`sys_sms_config` 的 2 行都是 `tenant_id=0` → 读它**必须** `@InterceptorIgnore(tenantLine = "true")`；否则被租户插件注入条件 → **查回 null → `Map.of` NPE → 500**（§7.4）。

### 11.2 平台级参数 vs 租户级参数（**本页的必答项**）

| 维度 | 本页（短信配置 62503） | 归属判定 |
|------|----------------------|---------|
| 菜单 / 路由 / 组件 | `sys_menu`：`client_type='system-admin'`、`tenant_id=0`（实测 62503） | **平台级菜单** |
| 主数据表 | `sys_sms_config`：`tenant_id` 列存在，**2 行全 0**（无租户行） | **平台级表**（当前无租户维度数据） |

   建议：**把三档频控做成默认内置规则**（**本项建议基于 B 级来源：阿里云官方文档，经检索摘要**）。
