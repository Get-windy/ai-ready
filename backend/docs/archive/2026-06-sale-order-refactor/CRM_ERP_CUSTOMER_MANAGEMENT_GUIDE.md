# CRM-ERP客户关系管理实施指南

## 1. 概述

本文档详细介绍了CRM（客户关系管理）模块与ERP（企业资源规划）模块之间客户关系的管理机制。重点解决CRM公海客户（包括潜在客户和实体客户）与ERP实体客户（Partner）之间的转化和映射关系。

## 2. 业务概念澄清

### 2.1 CRM客户概念
- **定义**：包括潜在客户和实体客户的全部客户
- **范围**：针对客户维护及客户关系处理
- **性质**：即"公海客户"，是所有可能成为客户的客户和已经发生业务往来的实体客户在内的全部公海客户
- **用途**：客户开发、客户关系维护、商机跟进等

### 2.2 ERP客户概念（Partner）
- **定义**：特指与企业实际发生业务往来及交易的实体客户
- **范围**：实际的交易对象
- **性质**：在销售订单等实际业务流程中使用的客户
- **用途**：订单处理、交易记录、应收账款等

### 2.3 业务流程
```
CRM模块：线索获取 → 客户培育 → 资格确认 → 客户转化
    ↓
CRM-ERP转化：匹配/创建实体客户 → 建立映射关系
    ↓
ERP模块：实体客户服务 → 订单处理 → 交易执行
```

## 3. 技术实现架构

### 3.1 核心实体模型

#### 3.1.1 Partner实体（erp_partner表）
统一业务伙伴模型，支持客户、供应商等多种角色：
- 基础信息：名称、编码、类型、联系方式
- 法律信息：税号、统一社会信用代码
- 等级信息：客户等级代码、等级名称
- 业务信息：状态、来源、交易统计

#### 3.1.2 映射实体（crm_erp_customer_mapping表）
维护CRM与ERP客户之间的映射关系：
- CRM侧标识：系统、实体类型、实体ID
- ERP侧标识：系统、实体类型、实体ID
- 匹配信息：规则、置信度
- 同步状态：当前同步状态、时间

### 3.2 服务层设计

#### 3.2.1 PartnerService
- 提供基础的Partner CRUD操作
- 增加客户匹配相关方法：按税号、名称、联系方式等查找

#### 3.2.2 CrmErpCustomerMappingService
- 管理CRM-ERP映射关系
- 提供客户匹配算法
- 处理客户转化流程

### 3.3 数据流设计

#### 3.3.1 客户匹配流程
```
输入潜在客户信息
    ↓
按税号精确匹配 (权重1.0)
    ↓
按名称精确匹配 (权重0.95)
    ↓
按联系方式匹配 (权重0.85)
    ↓
按名称+地址匹配 (权重0.80)
    ↓
返回匹配结果或无匹配
```

#### 3.3.2 客户转化流程
```
CRM线索信息输入
    ↓
验证线索信息有效性
    ↓
执行客户匹配算法
    ↓
如有匹配 → 关联到现有Partner
    ↓
如无匹配 → 创建新的Partner实体
    ↓
建立映射关系记录
    ↓
返回转化结果
```

## 4. API接口说明

### 4.1 客户匹配接口
- **URL**: POST /api/crm-erp/match-customer
- **功能**: 根据潜在客户信息进行匹配
- **请求参数**: 公司名称、税号、联系方式、地址
- **返回**: 匹配到的实体客户信息或空

### 4.2 客户转化接口
- **URL**: POST /api/crm-erp/create-entity-customer
- **功能**: 从CRM线索创建实体客户
- **请求参数**: 线索详细信息
- **返回**: 创建的实体客户信息

### 4.3 映射关系接口
- **URL**: GET /api/crm-erp/has-mapping/{crmSystem}/{crmEntityType}/{crmId}
- **功能**: 检查CRM实体是否已有ERP映射
- **返回**: 布尔值表示是否存在映射

## 5. 匹配规则详解

### 5.1 精确匹配规则（高置信度）
- **税号/统一社会信用代码**: 权重1.0，法律唯一标识
- **公司全称**: 权重0.95，名称完全相同

### 5.2 模糊匹配规则（中等置信度）
- **联系方式**: 权重0.85，B2B场景常用验证方式
- **名称+地址**: 权重0.80，考虑同名不同地情况

### 5.3 辅助匹配规则（低置信度）
- **域名/邮箱后缀**: 权重0.70，如@company.com
- **编辑距离匹配**: 权重0.65，容忍轻微名称差异

## 6. 数据一致性保障

### 6.1 事务保证
- 客户转化操作使用事务确保数据一致性
- 映射关系建立与Partner创建原子性操作

### 6.2 同步机制
- 实时同步：转化时立即建立映射关系
- 异步补偿：定期检查未同步数据
- 错误处理：失败时记录日志支持人工干预

### 6.3 去重机制
- 多维度验证防止重复创建
- 映射关系唯一性约束
- 定期数据清理任务

## 11. 常见问题处理

### 11.1 重复客户问题
- 症状：同一个客户在ERP中有多条记录
- 解决：使用合并功能将重复记录关联到一个Partner

### 11.2 匹配失败问题
- 症状：本应匹配的客户未能正确匹配
- 解决：检查匹配规则，适当调整权重配置

### 11.3 数据不一致问题
- 症状：CRM和ERP客户信息不一致
- 解决：建立同步机制，定期校验数据

本指南为CRM-ERP客户关系管理提供了完整的解决方案，解决了客户转化的根本问题，确保了数据一致性，并提供了灵活的扩展能力。
