## 4. 业务规范

- **一行 = 一次分享动作**（`分享时间` + `分享人` + `分享类型` + `分享概要` 四列共同定位）；同一对象被多次分享 → 多行（以 `分享时间` 区分）。
- **效果漏斗口径（基准文档归纳，列实据支撑）**：触达（浏览次数/浏览人数）→ 领取（分享领取数）→ 转化（下单人数/下单笔数）→ 金额（下单金额）；列头带 `?` 注释图标即为该口径的说明入口（**注释原文待复核**）。
- **必填时间窗**：`分享日期*` 强制限定，防止全量扫描（大促/长周期推广下数据量大）。
- **与订单的衔接**：订单处理中心默认列含「推广人」（销售域实据）——买家经推广链接下单后订单记录推广人，实现**订单级业绩归属**；本页是其**汇总查询端**。
- **与其它页面的关系**：
  - **数据上游**：《我要推广开发文档》产生的分享动作及其浏览/领取/下单回流（其 `我的推广` Tab 的 9 列与本页 10 列同源，本页多 `分享人` 列 = 全公司视角）。
  - **分析域**：营销分析 → 营销推广分析为**图形化分析端**，本页为**明细台账端**（同数据两种呈现）。
- **字段实据**：`分享类型`（枚举取值**待复核**）、`分享概要`（文本，实测样本为空——本轮 0 条记录）。

### 剩余缺口

1. **🔴 页面模型完全不同（最大缺口）**：对标 = 分享动作 × 转化漏斗的**查询台账**（10 列 + 合计行 + 8 段时间快捷段 + 查询方案）；本页 = 营销活动（campaign）的**审批执行台账**（11 列 + 行级生命周期动作）。二者不是同一模型，**无一列同名对齐**（最接近的只有「状态」语义，但取值域完全不同）。
2. **🔴 10 列全部缺失**：`分享时间 / 分享人 / 分享类型 / 分享概要 / 浏览次数 / 浏览人数 / 分享领取数 / 下单人数 / 下单笔数 / 下单金额` 在本系统**均无数据来源**（`api/marketing.ts` 无分享/推广效果端点，后端各 Controller 无「分享」实现）。
3. **查询条件不对齐**：对标为 `查询方案` + 8 段时间快捷段 + `分享日期*`（必填）+ `分享类型` + `分享人` + `商品` + `优惠券` + `分享概要` 模糊检索；本页为 `关键字 / 类型 / 状态`（均为活动字段），**且无时间区间、无必填日期**。
4. **无合计行**：对标底部 `合计` 行对 6 个效果列汇总；本页 `ARReportPage` 无合计能力。
5. **未达金标准路线 A**（如实标注）：未使用 `CategoryListLayout` / `BillDetailTable` / `StandardPagination` / `PageConfigPanel`，无 `storage-key`，**无表头齿轮列配置**（也就没有对标的「个人配置 / 全局配置」两 Tab）。
6. **表头能力缺失**：对标效果列列头带**排序箭头**与 **?** 口径注释图标（口径说明入口）；本页仅 `?` 无、排序依赖 `a-table` 默认行为（`handleTableChange` 仅处理分页，未接排序 `sorter`，`ARReportPage.vue:329-333`）。
7. **打印缺失**：对标有 `打印(F8)`；本页无打印按钮（`ARReportPage` 无打印能力）。
8. **导出为当前页 CSV**：本页走 `ARReportPage` 内置「当前页 CSV 导出」（`ARReportPage.vue:340-371`，前端拼字符串生成 `.csv`，**非真实 xlsx、非全量导出**）；对标「导出」为服务端导出（**待复核**）。
9. **失败仅 `console.warn`**：`runAction` / `handleEditOk` / `handleReasonOk` 的 `catch` 均只 `console.warn`（`index.vue:264-266`、`:300-302`、`:353-355`），未做用户可见错误提示。
