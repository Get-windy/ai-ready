### 口径说明

- `商品预售` = **活动 × 商品主数据视图**：`活动名称` 与 `商品名称`（+`商品图片/货号/规格/型号`）并列，同一预售活动可挂多个商品、同一商品可属多个活动；`预售价` 为预售商品独立定价（区别于日常售价与秒杀价/拼团价）；`起始时间/结束时间` 构成活动时间窗；`是否支付订金` 为订金开关（支持「订金 + 尾款」两段式或全额直购）；`活动状态` 枚举（下拉实据）= 待开始 / 进行中 / 已结束；`创建人` 为审计列。
- `预售订单` = **预售成交台账**：`客户名称/商品名称` 定位买家与货品，`单据编号/单据日期` 关联销售单据，`商品金额/订单金额` 双金额（商品金额=商品货款，订单金额=整单应付），`活动名称/活动状态` 回溯归属活动与当前态。
- 「操作」列**不进列配置弹窗**（固定动作列）——基准文档记「默认 13 列」即由此多出的 1 列；弹窗口径为 12 列。

## 4. 业务规范

- **预售模型（列实据归纳）**：
  - 一行 = 活动 × 商品：活动名称与商品名称（+图片/货号/规格/型号）并列，同一预售活动可挂多个商品、同一商品可属多个活动。
  - `预售价`：预售商品独立定价（区别于日常售价与秒杀价/拼团价）。
  - `是否支付订金`（列实据）：订金开关——支持「订金 + 尾款」两段式预售（先付订金锁货，发货前收尾款），也可全额直购；订金比例与尾款期限在新增表单维护（**待复核**）。
  - `活动状态` 枚举（下拉实据）：待开始 / 进行中 / 已结束。
  - **交易侧（基准文档，待复核）**：`预售订单` 承接预售产生的订单台账，订金/尾款支付状态与发货节点**待复核**。
- **与其他页面关系**：商城营销组同域（商城拼团、商城秒杀与预售并列商城三大玩法）；与销售域「预订货单」的关系（销售域实据：预订货单 YDHD- 支持预订金）——商城预售面向线上商城买家、预订货单面向线下开单客户，两者是否归一**待复核**；本系统落地对应 `/api/erp/marketing/presale`。
- **本系统状态轴（实现实据，非对标实据）**：`PRESALE_STATUS_MAP` = 0 未开始 / 1 进行中 / 2 已结束 / 3 已取消（`api/marketing.ts:693-698`），对标为三态（无「已取消」）。
