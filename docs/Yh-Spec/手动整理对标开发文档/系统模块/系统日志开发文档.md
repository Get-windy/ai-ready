## 1. 页面概述

系统日志页是**平台运营方查看"操作流水"的台账页**：分页列出 `sys_oper_log` 的操作记录（模块 / 操作类型 / 请求 URL / 操作人 / IP / 耗时 / 状态），提供模块与操作类型两个筛选下拉、一个操作人输入框与日期范围，支持导出 CSV、清空历史日志，并可点开抽屉看请求/响应详情。30 秒自动刷新 + 每秒倒计时 + F5 快捷键刷新。

**一句话结论：数据源是真的（`sys_oper_log` 实测 13541 行），全链路也是真的，但用户看到的是空表 + 恒定红色报错 —— 一个响应解包判断写错，把整页废掉了。**

本页是**平台级页面**，但 `sys_oper_log` **不在 `IGNORE_TENANT_TABLES`**（`MyBatisPlusConfig.java:32-93` 逐项核对，清单内含 `sys_tenant` / `sys_menu` / `sys_permission` / `sys_login_log` 等，**不含 `sys_oper_log`**）→ 多租户插件会注入 `tenant_id` 条件。

**实测的实际情况（本页因此不受影响）**：`SELECT tenant_id, count(*) FROM sys_oper_log GROUP BY tenant_id;` → **`1 | 13541`**。

**`sys_oper_log` 全部 13541 行的 `tenant_id` 都是 1**，而超管 `admin` 的 `tenant_id` 也是 1（实测 `sys_user` id=1 → `tenant_id=1`）→ **即便插件注入 `tenant_id=1`，本页也不会被过滤掉任何行**。

> **⚠️ 但这不是"对"的**：`SysLogStubController` **另有一层硬编码 `DEFAULT_TENANT_ID = 1L`**（`:37`），在 Service 层显式 `eq(tenantId, 1)` → **两套"只认 1"叠加**。**后果**：平台运营方**永远看不到 `tenant_id ≠ 1` 的日志**（当前库里没有这样的行，**问题被数据掩盖**）。**验收必须专门断言**（§10.1-⑲）。

## 8. 业界对标

> **本页在 ql361 无对应页**（§2）。本章只写**业界能力对标**，逐条标来源与可信度级别。**凡底稿标 D 级的方案，本文件一律写「本系统设计」而非「业界标准」。**

### 8.1 业界叫法

**Actuator `/actuator/logfile` + `/actuator/loggers`**；SAP **安全审计日志（SAL）**，事务码 **SM19（配置）/ SM20（读取）/ SM18（删除旧日志）**，S/4HANA 新版为 **RSAU_CONFIG / RSAU_READ_LOG**；金蝶「调度中心」有独立的**运行日志、错误日志**。

### 8.2 业界做法要点

1. **日志要能在运行时改级别**：Actuator `loggers`「显示并修改应用中日志记录器的配置」—— **这是"生产排障"的关键能力，页面必须做。**
2. **日志文件要能按 Range 读取（大文件不能整读）**：`logfile`「返回日志文件内容（需设置 `logging.file.name` 或 `logging.file.path`）。**支持 HTTP `Range` 头**」。
3. **审计日志与运行日志是两个东西**：SAP 的安全审计日志「记录内容：对话框登录成功/失败、RFC 登录尝试、RFC 调用、用户主记录变更、事务启动、审计配置变更」—— **是安全事件流，不是应用日志**。其存储位置在演进：S/4HANA 中「默认日志存于数据库而非文件系统（`RSAU_CONFIG` → Parameters → Recording Target）」，且「**SM20 只能显示文件系统日志**」，录制目标为数据库时须用 `RSAU_READ_LOG`（SAP_BASIS 755 起 SM19/SM20 分别重定向到 RSAU_CONFIG / RSAU_READ_LOG）。
4. **磁盘配额参数必须配 + 删除要有专用动作**：SAP 侧 `rsau/enable`、`rsau/local/file`、`rsau/max_diskspace_local`、`rsau/selection_slots`、`DIR_AUDIT`、`FN_AUDIT`、`rsau/max_diskspace/per_day`、`rsau/max_diskspace/per_file`（**"审计日志写满磁盘"是这类组件的经典事故**）；SM18 专用于删除旧日志，金蝶也有「日志清理」「调度计划的运行日志默认多久进行清理和归档」条目 —— **保留期是可配的策略，不是硬编码。**
5. **统计分析能力**：SAP 提供 `RSAU_GET_STAT`（统计报表）、`RSAU_GET_WUSL`（检查用户事件记录），且 SM20 可勾选「Statistics data only」。

## 10. 验收标准

> **前置**：本模块**尚无 E2E**。落地脚本建议命名 `tools/e2e-system.cjs`（接口 + 直连 DB 对账 + 写库后复原 + Playwright UI 截屏）。
> **⚠️ 本页验收的特殊性**：本页**端点全部存在（无 404 风险）**，且**表里有 13541 行数据** —— 因此**所有"页面没数据"的现象，都必须归因到前端解包缺陷，而不是后端**。§10.1 的①~④ 是"证明后端是好的+前端是坏的"的关键对照。
> **权限账号**：`admin`（id=1，`tenant_id=1`，SUPER_ADMIN，**持有全部 6 个 `log:audit:*` 码**）作 200 基线；另用一个 `SYSTEM_ADMIN` 账号做权限对账（**该角色一条 `log:audit:*` 都没有** → 预期 403）。
> **⚠️ 写库断言必须"改库 → 回读 → 按原值复原"** —— 本页有**删除类**操作（清空日志），**测试前必须记录原行数并按原值复原**（或使用专用测试数据）。

### 10.1 接口验收（24 项）

**主链路（①–⑦）**

① `GET /api/log/page?pageNum=1&pageSize=10`（带 `admin` Bearer）→ **期望 200**；断言返回结构为 `Result<Page<SysOperLog>>`（含 `code` 包装，拆包后是 `Page`，成员 `records`/`total`）。
② 🔴 **`total` 与直查 DB 对账**：`SELECT count(*) FROM sys_oper_log` = **13541**（2026-09-18 实测）→ 断言接口 `total` 与该值一致（**允许验收期间数据增长，用 `>=` 断言并记录快照值**）。
③ 🔴 **关键对照断言**：`GET /api/log/page` 的 `records` 数组**非空**（至少 10 条）→ **证明后端与数据都是好的**。**这一条与 §10.2-④（表格为空）构成完整证据链：后端有数据、页面不显示。**
④ **断言响应体无顶层 `data` 属性**（`res` 就是 `Page`）→ **这是 P0 解包缺陷的静态证据**（页面却读 `res.data`）。
⑤ `GET /api/log/{id}`（取第 ③ 步第一条的 id）→ 期望 200，返回单条 `SysOperLog`；断言其字段名为 `action` / `username` / `operIp` / `operTime`（**不是** `operationType` / `operatorName` / `ipAddress` / `operationTime`）→ **这是字段错配的接口级证据**。

**查询过滤（⑧–⑫）**

⑧ `GET /page?module=安全审计` → 断言 `total` 与 `SELECT count(*) FROM sys_oper_log WHERE module='安全审计'` 一致（实测该模块 action=顶替下线 **5806** 行）。

## 12. 剩余缺口（P0 / P1 / P2）

> 与《系统模块/README.md》§7 口径一致。README §7.1 P0-8（系统日志解包缺陷致整页恒空）、P0-14（3 处插槽缺陷）、§7.2 P1-2（幽灵文件）在本页的具体化见下。

### P0（6 条）

① **响应解包缺陷 → 整页恒空（README §7.1 P0-8 的具体化）**：`views/system/log/index.vue:382-386` 读 `res.data`，但 `res` 已是 `Page` 对象（`request.ts:207-220` 已拆包）→ **表格 / 2 个下拉（`:400-410`、`:412-421`）/ 3 个统计卡片全部恒空**，而 DB 有 **13541 行**。建议：改读 `res.records` / `res.total`（对照 `admin/monitor/audit/index.vue:294-296`）。
② **3 处插槽列缺陷（README §7.1 P0-14 的具体化）**：第 9/10 列 `slotName` 缺 `type:'slot'`（`:345`、`:346`）→ 状态显示裸 `0/1`、耗时不带颜色；第 11 列 `type:'action'` 无 `slotName`（`:347`）→ **操作列渲染为空白**。建议：前两列补 `type:'slot'`，第三列补 `slotName:'actionCell'`（或页面插槽改名）。
③ **后端 6 端点零权限注解 + `/api/log/*` 未纳入权限注册表**（`SysLogStubController.java:30-31`；`PermissionInitializationConfig.java` grep 零命中）→ **任何已登录用户可读全量日志、可执行 `DELETE /api/log/clear`**。建议：补 `@SaCheckPermission`（6 个 `log:audit:*` 码**已存在**）并纳入注册表。
④ **多租户硬编码 `DEFAULT_TENANT_ID = 1L`**（`:37`、`:131-135`）→ 忽略请求头租户，**`tenant_id ≠ 1` 的日志永远查不到**。建议：改从上下文取租户；平台级读取用 `@InterceptorIgnore(tenantLine="true")`。
⑤ **5 列字段名与实体不一致恒空**（`operationType`←`action`、`description`←**无此字段**、`operatorName`←`username`、`ipAddress`←`operIp`、`operationTime`←`operTime`）→ **数据在 DB 里，页面显示不出来**。建议：统一字段名或后端补 VO 别名。
⑥ **幽灵文件 `views/admin/monitor/log/index.vue`（167 行）永不加载**，且其内唯一接口 `/api/audit-log/page` 后端不存在（`FE/router/dynamicRoutes.ts:248`、`:921-924`）—— README §7.2 P1-2 登记为 P1，本文件按"不可达 + 接口不存在 + 误导后续开发者"实际影响列为 P0。

### P1（7 条）

⑦ **恒定报错提示**：`message.error('加载模块列表失败')` 缩进在 `try/catch` 外（`:409`）→ **每次进页必弹一次**，即使接口成功。
⑧ **日期范围传 `Dayjs` 未格式化**（`:376-379`）→ 后端 `@DateTimeFormat(pattern="yyyy-MM-dd HH:mm:ss")`（`SysLogStubController.java:47-48`）必然解析失败；**对照《操作审计》页做对了**（`audit/index.vue:290-291`）。
⑨ **统计卡口径缩水**：成功/失败/慢请求三卡**仅统计当前页 10 条**（`:317-319`），无「本页」限定文案；**后端无统计端点**。
⑩ **「清空日志」语义与文案不符**：文案「清空所有操作日志」，实际只删 90 天前 + `tenant_id=1`（`:473-487` vs 后端 `:124-137`）；删除条数被丢弃。
⑪ **导出无权限码**：任何登录用户可导出最多 10000 条日志（页面 `:117` 未传 `export-permission`；组件 `:63` 判断恒真）。
⑫ **跨页列配置污染**：未传 `:storage-key` → 落到默认键 `product-unit-columns-config`（`:103`；`BillDetailTable/index.vue:941-942`），与商品单位表等页面共用。
⑬ **无 `PageConfigPanel`**；且**同仓 4 套日志后端重复**（`/api/log` 6 + `/api/logs` 10 + `/api/system/log` 13 + `/api/system/log/advanced` 13 = **42 端点**，§6.3）→ 违反《功能/模块不重复开发》原则。
