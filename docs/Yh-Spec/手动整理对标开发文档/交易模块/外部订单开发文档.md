## 页面概述

外部订单是**外部平台订单接入台账**：记录外部渠道推送/拉取到的订单原始 JSON（用于审计与重试），跟踪其处理状态（待处理/已转换/已入库/失败），支持查看原始数据、失败重试、已入库跳转。**单入口，只读列表页**，单表，无 Tab。

| 页面 | 地址 | 说明 |
|------|------|------|
| 外部订单 | `trade/external-order/list` | 只读列表页（分页） |

单入口：交易模块 → 外部平台 → 外部订单。

- 实测实据（本系统实现）：服务端分页列表（后端 `GET /api/trade/external-order/page`）；共 **8 列可配置**（默认显示 8 / 默认隐藏 0）+ 固定列「序号」「操作」；顶部工具栏含 刷新 / 打印(F8) / 导出 与「待处理 N 笔」标签，右侧为「页面配置」齿轮；查询条件 4 项（渠道 / 处理状态 / 外部订单号 / 接收时间）。
- 处理状态枚举：0 待处理（warning）/ 1 已转换（processing）/ 2 已入库（success）/ 3 失败（error）。
- 渠道显示：`CHANNEL_CODE_MAP` 名称 + 按类型着色标签。

### 顶部按钮区
| 按钮 | 说明 |
|------|------|
| 刷新 | 重新加载当前页数据 |
| 打印(F8) | 前端拼装 HTML 打印窗口（F8 全局快捷键触发） |

### 数据表列（8 列可配置：默认显示 8 / 默认隐藏 0）
| 序号 | 列名 | 字段 | 说明 |
|------|------|------|------|
| 1 | 渠道 | channelCode | `<a-tag>` 按类型着色（电商蓝/社交绿/ERP橙/其余紫），显示渠道名称 |
| 2 | 外部订单号 | externalOrderId | 外部平台订单号 |
| 3 | 接收时间 | receiveTime | 时间 |
| 4 | 处理状态 | processStatus | `<a-tag>`：0待处理/1已转换/2已入库/3失败 |
| 5 | 内部订单ID | internalOrderId | 转换后内部订单ID |
| 6 | 重试次数 | retryCount | 数字 |
| 7 | 错误信息 | errorMsg | 失败原因 |
| 8 | 原始数据 | rawData | 行级操作「查看原始数据」按钮 |
| 9 | 操作 | action | 行级：**重试**（processStatus===3 失败）/ **查看订单**（processStatus===2 已入库） |

上表 1~8 列为**可配置列且默认全部显示**（默认隐藏 0 列）；第 9 行「操作」为固定列，不参与列配置。

固定列：序号（`rowNo`，fixed left）、操作（`action`，fixed left）。

固定操作列：操作（**重试 / 查看订单**）。另每行「原始数据」列有「查看原始数据」按钮 → 弹窗展示 `rawData` 格式化 JSON。

### 查看原始数据弹窗
- 标题「原始订单数据」（`a-modal`，无底部按钮）：上方 `a-descriptions` 展示 渠道 / 外部订单号 / 接收时间 / 处理状态 / 错误信息，下方 `<pre>` 展示 `JSON.stringify(JSON.parse(rawData), null, 2)` 格式化 JSON。

## 业务规范说明

- **外部订单主线**：外部平台回调/推送 → `/api/open/order/callback/{channelCode}` 写入 `external_order_raw`（异步）→ 转换（`convertAndSave` 生成内部订单）→ 入库 → 处理状态逐步演进（0待处理 → 1已转换 → 2已入库 / 3失败）。
- **处理状态枚举**：0 待处理，1 已转换（已转内部订单），2 已入库（已落内部订单），3 失败（转内部单失败，可重试）。
- **原始数据留存**：`rawData` 保存外部订单原始 JSON，用于审计与失败重试；重试次数 `retryCount` 记录失败重试次数。
- **重试**：失败（3）订单可点「重试」，调 `/api/trade/external-order/{id}/retry` 重新加入处理队列。
- **下游**：外部订单转换后联动本系统内部订单（商城订单/销售订单）入库；`internalOrderId` 指向内部订单。
- **渠道归属**：`channelCode` 来自「渠道配置」页维护的渠道主数据。

## 对标判断 / 业界标准 / 跨模块

- **对标判断（ql361 实测）**：ql361 顶栏「商城/销售/设置」菜单均无「外部订单/渠道配置/库存同步」相关页，**ql361 未见到独立页**。ql361 的商城「订单处理」为**自有商城订单**（微商城 `XSDD-`）处理中心，与本页「外部平台（电商/社交/ERP）订单接入台账」概念不同，不构成对标。
- **业界标准**：外部平台订单接入业界常采用「channel_code + external_order_id + raw_data + process_status」审计台账（保留外部原始数据、处理状态机、失败重试），与本系统 `external_order_raw` 表结构一致；处理状态机 待处理/已转换/已入库/失败 为电商平台订单接入通用设计。
- **跨模块**：本页 `rawData`/`channelCode` 对应「渠道配置」的渠道主数据；转换入库后联动本系统内部订单（商城/销售订单）；`pending-count` 供 API监控/渠道同步任务读取待处理量。
- **最终裁决**：本页为**本系统独有页**，ql361 无对应，按本系统实现+业界标准描述。存在数据表（列表型），**本轮已升级为金标准列表**：`CategoryListLayout` + `BillDetailTable`（表头 rowNo 列齿轮列配置）+ `StandardPagination` + `PageConfigPanel` 页面配置；字段取自本系统实测源码，未臆造。

## 开发原则（通用）
- **页面组件优先复用**、**功能/模块不重复开发**、**阶段结束前回写开发文档**。
- **【金标准】模块级 E2E 脚本统一放 `tools/`**：新增模块级端到端验收脚本命名 `tools/e2e-<模块>.cjs`，用 `NODE_PATH` 加载依赖、**不依赖脚本自身所在位置**；历史散落在项目根目录的脚本已统一归置到 `tools/acceptance/`，**该目录不可再移动**（脚本用 `__dirname` 定位项目根，见其 README）。
- **【金标准】启动进程随手关**：任何人 / 每个 AI 会话在结束工作前，必须关闭**自己启动**的实例 —— 后端 `java -jar ...core-api-*.jar`（含为验证临时复制的 `<模块>-run.jar`）与前端 `vite` dev server，并清理自己产生的临时产物（临时 fat jar、日志、截图）；**不得清理他人产物**（尤其刚打包好的 `target/*.jar`）。详见 `AI_DEVELOPER_RULES.md` **7.3 会话收尾纪律**。
