# 分析模块 · 金标准页面开发指南

> 用途：分析模块 31 个页面升级到金标准的统一施工手册。开发前必读。
> 通用规范见《对标开发技术参考文档》第 4、5 章与《交易模块/_开发指南-金标准.md》，本文只写**分析模块特有**的内容。
> 立此文件的直接原因：本模块 2026-09-15 复核时**整体未达金标准**（14 页 `ARReportPage` 只读壳 + 12 页自建骨架，且普遍缺「多视图 Tab + 逐 Tab 列配置」）。

## 一、三条路线

| 路线 | 构成 | 列配置 | 页面配置 | 适用 |
|---|---|---|---|---|
| **A（列表/账表页）** | `ErrorBoundary > PageContainer(full-height) > CategoryListLayout > BillDetailTable` | 表头序号列**齿轮**（BillDetailTable 内置） | 对标有「页面配置」弹窗才接 `PageConfigPanel` | 绝大多数 |
| **A′（多视图工作台）** | 同上，但 `CategoryListLayout` 带 `:tabs` | 逐 Tab **独立** `storage-key` | 同上 | 销售分析/查库存/查批次等 16 个多 Tab 页 |
| **B（纯报表壳 `ARReportPage`）** | — | ❌ | ❌ | **本模块不再使用**，存量 14 页**必须**升级到 A/A′ |

**判定「要不要接 `PageConfigPanel`」的唯一依据 = 该页对标实测有没有「页面配置」弹窗**：
- 证据在 `tool-results/ql361/分析-live/<页名>.json` 的 `pageConfig.found`，以及 `shots/` 下**是否**存在 `<页名>[-<Tab>]-页面配置弹窗.png`。
- 有 → 接；没有（如《待审批单据》）→ **禁止**加，查询区做成固定项。

## 三、列定义（`DetailColumnConfig[]`）

```ts
const columns: DetailColumnConfig[] = [
  { key: 'rowNo',  title: '', type: 'rowNo',  width: 44, fixed: 'left' },   // 承载列配置齿轮（锁定列）
  { key: 'checkbox', title: '', type: 'checkbox', width: 40, fixed: 'left' }, // 仅对标表头有勾选框的页才有
  { key: 'action', title: '操作', type: 'action', slotName: 'actionCell', width: 120, fixed: 'left' },
  { key: 'xxx',    title: '列名', width: 160 },                              // 只读文本列（默认 type）
  { key: 'yyy',    title: '列名', type: 'slot', slotName: 'yyyCell', width: 120 },
  { key: 'zzz',    title: '列名', width: 160, defaultHidden: true },          // 对标「默认不勾选」的列
]
```

规则（**均有踩坑先例**）：
1. **插槽列必须写 `type: 'slot'`**，只写 `slotName` 会静默直出原值（true/2 之类）。插槽模板**必须**接 `{ record, column }`，漏传 `column` 时 `record[column.key]` 恒 undefined。
2. **锁定列**（`rowNo` / `checkbox` / `action`）不进列配置弹窗，其余列才计入「全部可配置列」。
3. 列数口径：**`全部可配置列 / 默认显示列`**，取自对标 `columnConfig.count` / `defCount`。`defaultHidden: true` 的个数必须等于 `count - defCount`。
4. 分组表头用 `children`（仅一层，见进销存分析/销售分析的多级表头）。
5. **不要传 `:max-height`**（高度由 flex 链驱动）；**不要手 push 空行**（`min-rows` 默认 20）。

## 四、多视图 Tab 页（本模块 16 页，是全仓库最密集）

- 每 Tab **独立一套**：列定义 + 查询条件 + 功能按钮 + `storage-key`。
- `:storage-key="\`xxx-columns-${activeTab}\`"`、`:global-config-key` **同值**；切 Tab 必须换 key，否则沿用上一 Tab 的列配置（组件级已修「切 Tab 列显隐串用」，但页面仍须换 key）。
- `PageConfigPanel` 放布局**外面**，`:storage-key="\`xxx-page-config-${activeTab}\`"`（与列配置 key **不同值**）。
- 对标页签顺序逐字取自 `.dijitTabChecked` / `tabs` 实测，**不要自拟**。

## 五、两类配置严格分开

| | 数据表列配置弹窗 | 页面配置弹窗 |
|---|---|---|
| 载体 | `BillDetailTable` **内置齿轮**（rowNo 列表头） | 独立 `<PageConfigPanel>` |
| 管什么 | 列显隐 / 宽度 / 顺序拖拽 / 全局显示名 | 查询条件显隐+排序 / 功能按钮启用 / 打印配置 |
| 持久化 | `storage-key`（个人 localStorage）+ `global-config-key`（全局，后端 user-config） | `storage-key` |
| prop 名 | `storage-key` / `global-config-key` | `storage-key`（**必须与列配置 key 不同值**）、`fields-only`、`hide-print-config`、`print-config-items` |

## 六、口径约定（本模块成立、且必须在下游页面保持一致）

1. **`bizDate` = 单据自身的「单据日期」列**（`order_date`/`outbound_date`/`receipt_date`…），**不是** `create_time`。制单时间另有 `createTime` 列。历史实现一律取 `create_time`，已订正。
2. **单据编号是蓝色链接**，跳 `docTypes.ts` 的 `formPath` + `?id=<docId>`（`useBillForm` 读 `route.params.id || route.query.id`）。
3. **`docId` 是雪花 BIGINT**：前端一律按 **字符串** 透传，**严禁** `Number(id)` 或拿它做 Map key（超 `MAX_SAFE_INTEGER` 会舍入撞键）。
4. **行键 = `${docTypeCode}:${docId}`**（跨表 UNION，单凭 docId 不足以表达「哪个域的哪张单」）。
5. **底部合计行取后端 `summary.amount`**（按当前过滤范围 SUM），**不是**当前页求和。红冲/负数单据以负数参与合计。
6. **「显示红冲」**：后端 `includeReversed=false`（默认）时排除各表「已取消」状态的行；勾选后全量显示。这是本系统对「红冲默认不入列」的落地口径（13 张单据表本身没有 red_flag 列）。
7. **账期（`accountPeriodDays`）= 收/付款截止日 − 单据日期**。仅销售订单/销售出库/销售预订单/采购订单/采购退货/费用申请单有对应列，其余类型为 NULL 且不参与比较。
8. **动作能力按 `docTypes.ts` 的能力矩阵来**：某类型没有的动作**不渲染按钮**（例如报损单无 submit/approve/reject；销售预订单无 reject/cancel；只有销售出库单有 `copy`）。批量操作前先 `canDo()` 过滤并**如实提示跳过张数**，不要让整批静默失败。
9. **审批/过账一律调各业务域既有端点**（`/{id}/submit|approve|reject|cancel`、`DELETE /{id}`），**严禁直改状态列** —— 各域在这些端点里还承担库存事件、凭证生成、核销等副作用。
10. **费用申请单是异类**：审批走 `POST /erp/expense/approval/process`（入参 `applicationId` + `action`），其余走 `/erp/expense/application/{id}/...`。

## 七、查询区必须横向网格

**即使对标页是单列/两列排布，本系统也用横向自适应网格**（`.search-grid` + `flex-wrap`），并把样式写在页面自己的 `<style scoped>` 里 —— **插槽内容不受宿主的 scoped 样式影响**，布局组件里的类名对页面注入的插槽内容无效。

## 八、运行期陷阱（编译期查不出来，交付前必须真机验）

1. **`/api` 双前缀 → 整页 404**：`utils/request.ts` 的 axios 实例已是 `baseURL: '/api'`，api 文件里**一律写相对路径**（`/docquery/...`）。
2. **SQL 列别名**：`DocQueryService` 用 `SELECT 'CODE', '名称', sub.*` 的**位置对齐** UNION，**首分支的列别名就是结果集列名**。首分支未写 `AS` 的表达式会被 PG 命名成 `case` 之类（曾导致外层 `t.status_text` 报「字段不存在」→ 整个端点 500）。改 SQL 时首分支**必须逐个显式 `AS`**。
3. **UNION 各分支列数必须一致**：加列要 13 个分支一起加，缺列用 `NULL::类型` 占位。
4. **某表没有某列时不要硬写**：`attachment` 列在 `erp_sale_outbound`/`erp_purchase_order`/`erp_receipt`/`erp_payment` **不存在**；写之前先查 `information_schema.columns`。
5. **改 `DocQueryService` 后必须重启后端**：`mvn -o -q -pl core/api/core-api package -DskipTests` → 重启（先停进程再打 jar，否则运行中覆盖 fat jar 会随机 `NoClassDefFoundError`）。
6. **`updateById` 忽略 null**：备注等「只改一个字段」的写路径依赖 `FieldStrategy.NOT_NULL`，回传 `{id, remark}` 不会覆盖其余列。
7. **接口响应经拦截器解包**：`code===200` 时直接返回 `data`，页面上拿到的就是 `{list,total,page,size,summary}`。

## 九、金标准自检清单（改完必过）

| # | 检查项 | 判定 |
|---|---|---|
| 1 | 外壳 | 含 `ErrorBoundary` + `PageContainer`（静态属性 `full-height`，**不是** `:full-height`） |
| 2 | 布局 | 含 `CategoryListLayout` |
| 3 | 表格 | 含 `BillDetailTable`，且**未**传 `:max-height` |
| 4 | 分页 | 含 `StandardPagination`（`variant="classic"`） |
| 5 | 页面配置 | 对标有才接 `PageConfigPanel`，且同时传 `:default-query-fields-config` 与 `:default-function-buttons-config` |
| 6 | 列配置 | `storage-key` 与 `global-config-key` **同值**；与页面配置 `storage-key` **不同值** |
| 7 | 打印 | 对标有「打印(F8)」才写 `handlePrint()` + `handleF8Key()`（本模块**只有经营历程**有） |
| 8 | 导出 | 对标有「导出」才写（本模块**只有经营历程**有） |
| 9 | 列数口径 | 与对标 `columnConfig.count / defCount` 逐列对齐，`defaultHidden` 个数 = `count - defCount` |
| 10 | 查询区 | 与对标查询项逐项对齐，且**横向网格**排布 |

- **⚠️ 并行会话必读：E2E 要用独立账号，不要用 `admin`。**
  本仓库的 sa-token 是单端登录，多个会话都用 `admin` 时会**互相踢下线**，表现为「页面突然空白/未渲染」「E2E 反复重登仍 401」——**会被误判成页面缺陷**（2026-09-18 实测踩到：一整轮 E2E 因互踢把已验收页判成"未改造"）。
  ```bash
  # 建一次独立验收账号（幂等；用完 node analytics-e2e-user.cjs drop 删除）
  cd I:/AI-Ready/tool-results && NODE_PATH=I:/AI-Ready/frontend/node_modules node analytics-e2e-user.cjs create
  # 用它跑验收
  ANALYTICS_USER=e2e_analytics ANALYTICS_PASSWORD=admin123 node tools/e2e-analytics.cjs
  ```
  同理：并行会话**重启后端/前端**期间，E2E 会出现 `ERR_CONNECTION_REFUSED` 与「等待后端就绪」超时——这是环境噪声，**等对方起来后重跑**即可，不要据此改代码。共享环境里前端 5656 也可能被别人停掉，自己起一个换端口跑：`FE=http://localhost:5657 ANALYTICS_USER=… node tools/e2e-analytics.cjs`（`npx vite --port 5657 --strictPort`）。
- **收尾纪律**：只关**自己**启动的实例（按端口/PID 精确 kill，勿 `grep` 文件名批量匹配，同名 jar 会误杀并行会话）；清理自己在 `tool-results/` 下产生的临时产物。
- 每个模块级脚本放 `tools/`，命名 `tools/e2e-analytics.cjs`。
- **每页验收口径必须回写到该页开发文档的「实现差异说明 → 当前实现」与「金标准落地记录」**。
