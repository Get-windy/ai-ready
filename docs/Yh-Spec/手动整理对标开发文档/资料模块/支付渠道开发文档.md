| 页面 | 地址 | 说明 |
|------|------|------|
| 支付渠道 | `md/payment-channel` | 支付渠道列表 + 新增/编辑弹窗 |

菜单（本系统）：资料 → 支付管理 → 支付渠道。

- ⚠️ **当前实现说明**：本页为 `ARReportPage` + `a-modal` 弹窗（无独立表单页），已接入列配置能力。

## 业务规范说明

- **渠道语义**：渠道是「支付方式」的具体落地（同一方式可有多个渠道/商户号），服务于收付款单的资金路由。
- **支付方式下拉**：`methodId` 关联 `md_payment_method`，label 显示 `[编码] 名称`。
- **渠道配置**：`configJson` 字段可存渠道扩展配置（如 API 密钥等）。
- **默认值**：新增默认 status=1。
- **排序**：列表 orderBy sort ASC + createTime DESC；`GET /list` 仅返回 status=1（供收付款下拉）。

## 最终裁决方案（2026-09-07 · 严格按此执行）

- **P0 支付渠道单一口径（红线）**：本页支付渠道为全局基础数据，收付款单资金路由统一引用，**严禁另建重复渠道表**。
- **P1 关联一致性**：渠道商户号/状态变更后实时反映到收付款单；`configJson` 预留渠道扩展配置并接入支付 SDK。
- **P2 验收**：无桩/无模拟；渠道增删改、启停、导出闭环真实生效；与收付款单数据一致。
- **⭐ 对标空缺裁决**：ql361 无「支付渠道主数据」对照页（以第三方支付供应商配置替代），本页金标准按本页自定 + 业界标准，不强行挂靠对立标。
