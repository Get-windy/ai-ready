## 1. 页面概述

采购准备页是**「分析 → 执行」合一的补货工作台**：四个策略 Tab 各出一张**建议清单**（库存预警 / 缺货 / 智能 / 以销定购），清单首列为勾选框，工具栏 `采购` 按钮把勾选商品**一键生成采购单**。它既是分析页（哪个商品该补、补多少），也是操作页（把建议变成采购单据）。**单入口、四视图 Tab**，逐 Tab 独立列配置。

| 页面 | 地址 | 说明 |
|------|------|------|
| 采购准备 | `analytics/purchase-prep` | 单入口复合页（4 个策略 Tab：库存预警补货 / 缺货补货 / 智能补货 / 以销定购；逐 Tab 独立列配置；首列勾选 + 采购按钮） |

单入口：分析 → 采销分析 → 采购分析 → 采购准备。

- **对标子分组归属（重点）**：ql361「采销分析」组下有 **3 个 `.popupmenu__list-title` 子分组**——`销售业绩`、`销售分析`、**`采购分析`**，**均为分组标题、非页面**（`.png` 实测右键菜单展开可见：`采购分析` 标题下正是 `采购分析` + `采购准备` 两项）。本系统 `sys_menu` **有对应层级**：菜单 **80420「采购分析」（menuType 0）** 下挂 80421 采购分析 + 80422 采购/准备（`V6.22.0__Fill_Mega_Menu_All_Columns.sql:188-190`）——**与 ql361 子分组结构一致**。
- 实测实据（2026-09-15）：`库存预警补货` 共 **0** 条、`缺货补货` 共 **0** 条、`智能补货` 共 **2248** 条、`以销定购` 共 **2** 条；`以销定购` 底部分页 `第 (1/1) 页`、`每页显示 20 行`、**合计行实测 `商品数量 5` / `已发数量 0`**。
- ⚠️ **与《采购模块》互为上下游（本页最关键的业务关系）**：本页与「采购模块 → 采购准备（组 60201）」下的四个页面**是同一批能力的两个入口**：
  | 策略 | 《采购模块》页面（菜单） | 《分析模块》本页 Tab |
  |---|---|---|
  | 库存预警补货 | `purchase/alert-replenish`（**70051**，父 60201） | `库存预警补货` |
  | 缺货补货 | `purchase/shortage-replenish`（**70052**） | `缺货补货` |
  | 智能补货 | `purchase/smart-replenish`（**70053**） | `智能补货` |
  | 以销定购 | `purchase/sales-driven`（**70054**） | `以销定购` |
  采购模块四页已是**金标准形态**（`CategoryListLayout` + 分类树 + 勾选 + `采购` 按钮 + 列配置 + 页面配置，见第 5 节证据），本页（分析模块侧）为**同一能力的旧式报表壳实现**——按「**功能/模块不重复开发**」原则，**本页应改为薄壳复用采购模块四页**（对标《配发收域》已采用的「入口直达型」落地方式），而非各自维护两套。

## 4. 业务规范

### 四策略统计口径

- **① 库存预警补货** —— 账面触及**库存下限**的商品，补到**库存上限**；`预警类型` 区分 `缺货 / 下限预警 / 超储 / 正常`（本系统 DTO 注释口径，`api/analytics.ts:191`）。
  - **缺货数量公式**（对标页面公式条实据）：`缺货数量 = 库存上限 + 待发货 − 账面数量 − 待收货`。
  - 本系统后端同口径实据：`StockAlertReplenishVO.shortageQty` 注释「缺货数量 = 库存上限 + 待发货 - 账面库存 - 待收货」（`api/analytics.ts:193`）——**与对标公式逐字一致 ✅**。
- **② 缺货补货** —— 当前**已缺货**（待发货 > 账面库存）的销售订单缺口的商品；本系统后端支持两种口径开关：`shortageMode` = `1`（待发货 − 账面库存）/ `2`（待发货 − 待收货 − 账面库存）（`api/analytics.ts:332`；`StockReportController.java:105` 注释同）。
- **③ 智能补货** —— 按历史销量/周转预测备货：
  - **计划采购数量 = 备货天数 × 日均销量 + 待发货数量 − 待收货数量 − 账面库存**（本系统《采购模块·智能补货》页面公式条实据：`views/purchase/smart-replenish/index.vue:42`；后端字段注释 `api/analytics.ts:276` 同）。
  - **算法口径实测验证（2026-09-15，✅）**：`龙鸟琵琶腿120/140|生鸡腿(73个)`：销售数量 13、日均销量 `0.867`、备货天数 `0`、账面库存 `7` → `0 × 0.867 + 0 − 0 − 7 = −7` → 页面 `计划采购数量 = 0`、`可用库存 = 7`，即**负值截零**；`黑白全脂淡奶`：账面库存 `33` → 计划采购数量 `0`、可用库存 `33`（同规则）✅。**「计划采购数量为负时取 0」这一规则由实测两点证实**。
  - **日均销量 = 销售数量 ÷ 区间天数**（本系统字段注释 `api/analytics.ts:264`；实测 `13 → 0.867` 对应区间约 15 天 ✅ 量级吻合，**精确区间天数待复核**）。
  - 基准文档所记「智能补货算法口径待复核」——**现已由本系统后端字段与页面公式条补全**（对标侧算法是否同式，**仍待复核**）。
- **④ 以销定购** —— 按**未发货的销售订单（含预订货）**反推采购需求：
  - 实测 2 行的 `是否采购 = 否`、`单据状态 = 待发货`、`记账状态 = 未完成`，`发货\已发数量 = 0` —— 即**「未发 + 未采购」的销售订单**进入本 Tab。
  - 行级动作分**两条采购线**：`采购成品`（直接采购可售成品）/ `采购原料`（采购用于生产的原料），对应本系统后端端点 `/erp/purchase/sales-driven/{id}/purchase-finished` 与 `/purchase-material`（`views/purchase/sales-driven/index.vue:790-791`）。
  - 单据编号实测为 **XSDD-**（销售订单号段），`录入方式 = 微商城` —— 即商城订单是「以销定购」的主要来源之一。

### 「一键生成采购单」闭环

- **对标形态**：勾选建议清单中的商品 → 工具栏 `采购` → 按**所属供应商分组**生成采购单（生成规则**待复核**：生成采购订单 CGDD- 还是采购入库单 CGRKD-、是否按供应商拆单、是否带默认价，均无实据）。
- **本系统已具备的等价闭环**（在采购模块四页，非本页）：`库存预警补货`/`智能补货`/`缺货补货` 三页勾选后 `采购` → **带商品跳采购订单表单**（`router.push('/erp/purchase/form?productIds=...')`，`views/purchase/alert-replenish/index.vue:398-405`）；`以销定购` 页为**单据级**采购（按销售订单行生成 `purchase-finished` / `purchase-material`）。
- **与《采购模块·智能补货/缺货补货》的上下游关系**（本页业务关系的关键）：
  - **上游**：库存（账面数量/上下限）＋ 待发货（销售订单未发）＋ 待收货（采购在途）＋ 商品档案（品牌/口味/型号/所属供应商）＋ 历史销量。
  - **本页 = 建议侧**（分析：该不该补、补多少）；
  - **《采购模块》对应页 = 执行侧**（操作：勾选 → 生成采购单）；
  - **下游**：采购订单（CGDD-）/ 采购入库单（CGRKD-）→ 到货后 `待收货` 转 `账面库存`，下一轮预警随之解除（形成闭环）。
  - **同源页**：《查库存》（账面数量口径）、《销售履约分析》（待发货口径）、《采购分析》（采订/采购段结果侧）、《预订货查询》（预订货未发数量）。
